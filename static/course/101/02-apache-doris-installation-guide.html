Section 1

Manual Deployment — Integrated Storage-Compute

Deploy a classic Apache Doris cluster on bare-metal or virtual machines. This four-step workflow covers FE Master, FE Cluster expansion, BE Nodes, and verification.

Architecture Overview

Two process types form a unified, shared-nothing cluster with MySQL-compatible protocol.

🧠 Frontend (FE)
  • ✅ Metadata management & query planning
  • ✅ MySQL protocol compatible (port 9030)
  • ✅ Master: reads/writes metadata, coordinates
  • ✅ Follower: HA, participates in leader election
  • ✅ Observer: read-only scaling, no voting rights
⚡ Backend (BE)
  • ✅ Data storage & query execution
  • ✅ Columnar storage + vectorized SIMD
  • ✅ Multi-disk: mix HDD and SSD per node
  • ✅ Tablet-based sharding, 3 replicas by default
  • ✅ Horizontal scaling via ADD BACKEND

1 Deploy FE Master Node
# Create metadata directory and symlink
mkdir -p /ssd1/doris-meta
ln -s /ssd1/doris-meta /path/to/doris/fe/doris-meta

# Start FE
bin/start_fe.sh --daemon

# Verify
mysql -uroot -P9030 -h192.168.1.10
show frontends;
2 Deploy FE Cluster (High Availability)
Production requires 3 FE nodes (1 Master + 2 Followers). The number of Followers must be odd for proper leader election.
🔗 Register Follower
ALTER SYSTEM ADD FOLLOWER "192.168.1.11:9010";

bin/start_fe.sh \
  --helper 192.168.1.10:9010 --daemon
👁 Register Observer
ALTER SYSTEM ADD OBSERVER "192.168.1.12:9010";

Observers handle reads without voting — ideal for scaling query capacity.

3 Deploy BE Nodes
# be.conf multi-disk configuration
storage_root_path=/data1/doris,medium:HDD;/ssd1/doris,medium:SSD

# Register BE
ALTER SYSTEM ADD BACKEND "192.168.1.20:9050";

# Start BE
bin/start_be.sh --daemon

# Verify
show backends;
4 Verification & Security
🔒
Security: Change the root password immediately after deployment. The default empty password is for initial setup only.
-- Check cluster health
show frontends;
show backends;

-- Set password (do this first!)
SET PASSWORD = PASSWORD('doris_secure_passwd');

-- Functional test
create database testdb;

CREATE TABLE testdb.table_hash (
    k1 TINYINT,
    k2 DECIMAL(10, 2) DEFAULT "10.5",
    k3 VARCHAR(10),
    k4 INT NOT NULL DEFAULT "1"
) DISTRIBUTED BY HASH(k1) BUCKETS 32;

INSERT INTO testdb.table_hash VALUES (1, 10.1, 'AAA', 10);
SELECT * FROM testdb.table_hash;

1 Prepare FoundationDB
Doris depends on FoundationDB 7.1.x for metadata storage. At least 3 machines with SSDs for production.
💡
If FDB is already installed, confirm its version is in the 7.1.x series; otherwise Meta Service will fail to start.
# Configure fdb_vars.sh
DATA_DIRS=/mnt/foundationdb/data1,/mnt/foundationdb/data2
FDB_CLUSTER_IPS=172.200.0.2,172.200.0.3,172.200.0.4
FDB_HOME=/fdbhome
FDB_CLUSTER_ID=$(mktemp -u XXXXXXXX)
FDB_CLUSTER_DESC=dorisfdb

# Deploy on each node
./fdb_ctl.sh deploy

# Start FDB
./fdb_ctl.sh start
⚠
Warning: The clean command in fdb_ctl.sh removes all FDB metadata. Never use it in production.
2 Install S3 or HDFS Service Optional

If you don't have shared storage, MinIO is the quickest way to get started.

export MINIO_REGION_NAME=us-east-1
export MINIO_ROOT_USER=minio
export MINIO_ROOT_PASSWORD=minioadmin
nohup ./minio server /mnt/data 2>&1 &

./mc config host add myminio http://127.0.0.1:9000 minio minioadmin
./mc mb myminio/doris
./mc mv test_file myminio/doris
3 Deploy Meta Service
Configure doris_cloud.conf with the FDB connection string. At least 3 Meta Service nodes in production.
# doris_cloud.conf
brpc_listen_port = 5000
fdb_cluster = xxx:yyy@127.0.0.1:4500

# Start Meta Service
export JAVA_HOME=${path_to_jdk_17}
bin/start.sh --daemon

# Verify: return code 0 + "doris_cloud start successfully"
4 Standalone Data Recycler Optional
cp -r ms recycler
# Start recycler only
bin/start.sh --recycler --daemon
# Start metadata only
bin/start.sh --meta-service --daemon
5 Start FE Master Node (Cloud Mode)
# fe.conf key parameters
deploy_mode = cloud
cluster_id = $(echo $((($RANDOM << 15)) | $RANDOM))
meta_service_endpoint = 127.0.0.1:5000

# Start FE
bin/start_fe.sh --daemon

# Verify
mysql -h  -P 9030 -u root -e "SHOW FRONTENDS;"
6 Register FE Follower/Observer
ALTER SYSTEM ADD FOLLOWER "host:port";
ALTER SYSTEM ADD OBSERVER "host:port";
7 Add BE Nodes (Cloud Mode)
# be.conf key parameters
deploy_mode = cloud
file_cache_path = [{"path":"/path/to/file_cache","total_size":21474836480}]

bin/start_be.sh --daemon
ALTER SYSTEM ADD BACKEND ":";
SHOW BACKENDS;
8 Add Storage Vault
A Storage Vault represents the shared storage layer. Create using HDFS or S3-compatible object storage.
HDFS Vault
CREATE STORAGE VAULT IF_NOT_EXISTS hdfs_vault
    PROPERTIES (
    "type"="hdfs",
    "fs.defaultFS"=
      "hdfs://127.0.0.1:8020"
);
S3 Vault
CREATE STORAGE VAULT IF_NOT_EXISTS s3_vault
    PROPERTIES (
    "type"="S3",
    "s3.endpoint"="https://s3.us-east-1.amazonaws.com",
    "s3.access_key" = "ak",
    "s3.secret_key" = "sk",
    "s3.region" = "us-east-1",
    "s3.root.path" = "ssb_sf1_p2_s3",
    "s3.bucket" = "doris-build",
    "provider" = "S3"
);
-- Set default
SET s3_vault AS DEFAULT STORAGE VAULT;

-- Verify
SHOW STORAGE VAULTS;

Troubleshooting

⚠
If BE stays in "Starting" state: check be.log, confirm meta_service_endpoint is reachable, verify deploy_mode = cloud. If adding BE returns "backend already exists", run ALTER SYSTEM DROP BACKEND first.

2 Configure the Cluster
The DorisCluster resource defines all settings: images, replicas, compute resources, ConfigMaps, persistent storage, and access mode.
📄

Image Settings

Set spec.feSpec.image and spec.beSpec.image. Operator supports Doris 2.0+.

📈

Replicas

Default FE=3, BE=3. Change via replicas field. Minimum startup: 4c 8Gi.

💻

Resources

Default FE: 6c 12Gi, BE: 8c 16Gi. Recommended for testing: 8c 8Gi.

💡
Tip: For K8s deployments, enable FQDN mode: add enable_fqdn_mode = true to startup ConfigMap. The key for FE must be fe.conf, for BE it must be be.conf.
🛠 FE ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: fe-conf
  labels:
    app.kubernetes.io/component: fe
data:
  fe.conf: |
    query_port = 9030
    sys_log_level = INFO
    enable_fqdn_mode = true
spec:
  feSpec:
    configMapInfo:
      configMapName: fe-conf
      resolveKey: fe.conf
🛠 BE ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: be-conf
  labels:
    app.kubernetes.io/component: be
data:
  be.conf: |
    be_port = 9060
    webserver_port = 8040
    sys_log_level = INFO
spec:
  beSpec:
    configMapInfo:
      configMapName: be-conf
      resolveKey: be.conf

Persistent Storage Configuration

FE Storage
spec:
  feSpec:
    persistentVolumes:
    - mountPath: /opt/apache-doris/fe/doris-meta
      name: meta
      persistentVolumeClaimSpec:
        storageClassName: ${sc}
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 100Gi
    - mountPath: /opt/apache-doris/fe/log
      name: log
      ...
BE Storage
spec:
  beSpec:
    persistentVolumes:
    - mountPath: /opt/apache-doris/be/storage
      name: be-storage
      persistentVolumeClaimSpec:
        storageClassName: ${sc}
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 500Gi

4 Access the Cluster
ClusterIP

Internal K8s access only.

kubectl run mysql-client
  --image=mysql:5.7 -it --rm
  --restart=Never -- /bin/bash

mysql -uroot -P9030
  -h<fe-service>
NodePort

Access via node IP + port.

# 9030:31545/TCP
mysql -h <node-ip>
  -P 31545 -uroot
LoadBalancer

Cloud LB provided by platform.

# EXTERNAL-IP: <elb>
mysql -h <elb> -P 31545 -uroot

Cluster Operations

↕ Scale FE
kubectl patch doriscluster \
  doriscluster-sample --type merge \
  --patch '{"spec":{"feSpec":{"replicas":3}}}'
↕ Scale BE
kubectl patch doriscluster \
  doriscluster-sample --type merge \
  --patch '{"spec":{"beSpec":{"replicas":5}}}'

Rolling Upgrade (BE → FE)

-- Disable balancing before upgrade
admin set frontend config("disable_balance" = "true");
admin set frontend config("disable_colocate_balance" = "true");
admin set frontend config("disable_tablet_scheduler" = "true");

# Edit and change image tags
kubectl edit dcr doriscluster-sample -n doris
# Change spec.beSpec.image then spec.feSpec.image

-- Re-enable after upgrade
admin set frontend config("disable_balance" = "false");
admin set frontend config("disable_colocate_balance" = "false");
admin set frontend config("disable_tablet_scheduler" = "false");

-- Verify
show frontends;  show backends;

Debug Mode (CrashLoopBackOff)

# Enter Debug mode
kubectl annotate pod ${pod_name} \
  --namespace ${namespace} \
  apache.org.doris/runmode=debug

# Enter the pod
kubectl exec -ti ${pod_name} bash
# IMPORTANT: Modify port before manual start
# FE: change query_port in fe.conf
# BE: change heartbeat_service_port in be.conf

# Manual start
/opt/apache-doris/xx/bin/start_xx.sh

# Exit Debug mode (delete the pod)
kubectl delete pod ${pod_name}
⚠
Caution: When scaling BE down, avoid taking single-replica tables offline. Don't arbitrarily remove FE Follower nodes. FE Observer nodes can be safely removed.

5 End-to-End Verification
-- Confirm BEs are alive

-- Write and query test data
CREATE DATABASE IF NOT EXISTS demo;
USE demo;

    id INT,
    msg VARCHAR(64)
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1;

INSERT INTO hello VALUES (1, 'hello doris');
SELECT * FROM hello;
-- Expected: (1, 'hello doris')
