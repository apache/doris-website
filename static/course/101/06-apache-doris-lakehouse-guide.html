Section 1

Lakehouse Overview

The lakehouse combines the low cost and high scalability of data lakes with the high performance and strong data governance of data warehouses.
🔍 Query Accel.

Doris as compute engine: local disk caching (LRU), materialized views with transparent SPJG rewrite.

🔄 Federated SQL

Unified engine connecting Hive, MySQL, Iceberg for cross-source joins without ETL.

📊 Data Proc.

Job Scheduler + materialized views. Write-back to Hive, Iceberg, JDBC.

🔗

Extensible Connectors

Standard Catalog/Database/Table levels. Compatible with Trino Connector plugins.

⚡

High-Performance Engine

MPP + Pipeline + vectorized. TPCDS 1TB Iceberg: 1/3 of Trino time. 20% avg latency reduction.

🛡

Data Cache & IO

Memory + local SSD caching with LRU. Optimized for high-throughput, high-latency network IO.

💡
Architecture: Since 3.0, compute-storage separation is supported. Shared storage (HDFS/Object) is the single source of truth. Compute clusters scale independently.
Section 2

Catalog Overview

A Data Catalog describes a data source property. Doris creates multiple catalogs for different systems, enabling standard SQL and cross-source joins.
📂 Internal
  • Fixed name: internal
  • Stores Doris internal data
  • Immutable
🌐 External
  • User-defined, for any data source
  • Proxy to HMS/storage
  • CREATE/ALTER/DROP supported
CREATE CATALOG iceberg_catalog PROPERTIES (
    'type' = 'iceberg',
    'warehouse' = 's3://bucket/dir',
    's3.endpoint' = 'https://s3.amazonaws.com',
    's3.access_key' = 'ak',
    's3.secret_key' = 'sk'
);

SWITCH iceberg_catalog;
SHOW CATALOGS;

-- Federated query
SELECT * FROM iceberg.db.t1
JOIN mysql.db.t2 ON t1.id = t2.id;

REFRESH CATALOG iceberg_catalog;
DROP CATALOG iceberg_catalog;
ⓘ
Dropping a catalog only removes the mapping in Doris. The actual data is NOT deleted. Catalogs are proxies to external metadata and storage services.
Section 3

Hive Catalog & Federated SQL

Connect to Hive Metastore to access Hive, Iceberg, and Hudi tables. Supports query acceleration, data integration, write-back, DDL management, and HMS event subscription.
FeatureHive MetaStoreAWS GlueDLF
Table QueryYesYesYes
View QueryYesYesYes
DDL OpsYesNoYes
Write-backYesNoYes
-- HDFS catalog (no Kerberos)
CREATE CATALOG hive_hms PROPERTIES (
    'type' = 'hms',
    'hive.metastore.uris' =
        'thrift://host:9083',
    'fs.defaultFS' = 'hdfs://host:8520',
    'hadoop.username' = 'doris'
);

-- S3 catalog
CREATE CATALOG hive_s3 PROPERTIES (
    'type' = 'hms',
    'hive.metastore.uris' =
        'thrift://host:9083',
    's3.region' = 'us-east-1',
    's3.access_key' = 'ak',
    's3.secret_key' = 'sk'
);

-- AWS Glue
CREATE CATALOG hive_glue PROPERTIES (
    'type' = 'hms',
    'hive.metastore.type' = 'glue',
    'aws.region' = 'us-east-1',
    'aws.access_key' = 'ak',
    'aws.secret_key' = 'sk'
);
Type mapping: TINYINT, SMALLINT, INT, BIGINT map directly. TIMESTAMP maps to DATETIME(6). DECIMAL, CHAR, VARCHAR, STRING map directly. ARRAY, MAP, STRUCT map to complex types.

Federated Queries & Write-Back

-- Cross-source: Hive + MySQL
SELECT h.id, h.amount, m.name
FROM hive.orders h
JOIN mysql.customers m
ON h.customer_id = m.id;

-- Import to Doris
INSERT INTO internal.db.t1
SELECT * FROM hive.db.source;

-- Write back to Hive
INSERT INTO hive.db.hive_tbl
SELECT col1, col2 FROM internal.db.orders;

-- INSERT OVERWRITE
INSERT OVERWRITE TABLE hive.db.tbl
VALUES (1, 'a', 100);

-- CTAS from external
CREATE TABLE internal.db.target
AS SELECT * FROM hive.db.source;

DDL & HMS Events

-- Create Hive table via Doris
CREATE TABLE partition_tbl (
    col1 INT,
    col2 STRING,
    pt1 VARCHAR
) ENGINE=hive
PARTITION BY LIST (pt1) ()
PROPERTIES (
    'file_format'='parquet',
    'compression'='zstd'
);

SWITCH hive_ctl;
CREATE DATABASE IF NOT EXISTS hive_db;
SHOW CREATE DATABASE hive_db;
DROP TABLE partition_tbl;

-- Enable HMS event subscription
-- In fe.conf:
-- enable_hms_events_incremental_sync = true
-- Events: CREATE/DROP/ALTER TABLE,
--         ADD/DROP/ALTER PARTITION
⚠
Note: For Hive clusters with ACID on by default, set "transactional" = "false" in table properties. Partition columns must be at the end of the schema. Drop all tables before dropping a Hive database.
