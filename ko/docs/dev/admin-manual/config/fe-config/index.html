FE 설정

이 문서에서는 FE 관련 설정 항목을 설명합니다.

FE 설정 파일 fe.conf는 일반적으로 FE 배포 경로의 conf/ 디렉터리에 있습니다. 버전 0.14부터는 또 다른 설정 파일인 fe_custom.conf가 도입됩니다. 이 파일은 운영 중 사용자가 동적으로 설정하고 영구 저장한 항목을 기록합니다.

FE 프로세스가 시작되면 먼저 fe.conf의 설정 항목을 읽고, 이어서 fe_custom.conf의 설정 항목을 읽습니다. fe_custom.conf의 항목은 fe.conf에 있는 동일한 항목을 덮어씁니다.

fe_custom.conf 파일의 위치는 fe.conf에서 custom_config_dir 설정 항목으로 지정할 수 있습니다.

설정 항목 조회​

FE 설정 항목은 다음 두 가지 방법으로 조회할 수 있습니다.

  1. FE 웹 페이지

    브라우저에서 FE 웹 페이지 http://fe_host:fe_http_port/variable을 엽니다. Configure Info에서 현재 적용 중인 FE 설정 항목을 볼 수 있습니다.

  2. 명령으로 조회

    FE가 시작된 후 MySQL 클라이언트에서 다음 명령으로 FE 설정 항목을 조회할 수 있습니다. 구체적인 구문은 SHOW-CONFIG를 참조하세요.

    SHOW FRONTEND CONFIG;

    결과 열의 의미는 다음과 같습니다.

    • Key: 설정 항목의 이름입니다.
    • Value: 현재 설정 항목의 값입니다.
    • Type: 정수 또는 문자열과 같은 설정 항목 값의 형식입니다.
    • IsMutable: 동적으로 설정할 수 있는지 나타냅니다. true이면 실행 중에 동적으로 설정할 수 있습니다. false이면 fe.conf에서만 설정할 수 있으며 FE를 다시 시작한 후 적용됩니다.
    • MasterOnly: Master FE 노드에만 해당하는 설정 항목인지 나타냅니다. true이면 Master FE 노드에서만 의미가 있고 다른 유형의 FE 노드에는 의미가 없습니다. false이면 모든 유형의 FE 노드에서 의미가 있습니다.
    • Comment: 설정 항목의 설명입니다.

설정 항목 지정​

버전 4.1.5부터 SHOW FRONTEND CONFIG와 설정 내보내기 엔드포인트는 비어 있지 않은 민감한 값을 ********로 마스킹합니다. 여기에는 initial_root_password, TLS 개인 키 비밀번호, HTTPS Key Store 비밀번호, MySQL SSL 인증서 비밀번호가 포함됩니다. 빈 값은 설정되지 않았음을 나타내도록 그대로 비어 있습니다. 마스킹은 실제 적용되는 설정을 변경하지 않습니다.

FE 설정 항목은 다음 두 가지 방법으로 지정할 수 있습니다.

  1. 정적 설정

    conf/fe.conf 파일에 설정 항목을 추가하고 값을 지정합니다. fe.conf의 설정 항목은 FE 프로세스 시작 시 읽힙니다. fe.conf에 없는 항목에는 기본값이 사용됩니다.

  2. MySQL 프로토콜을 통한 동적 설정

    FE 시작 후 다음 명령으로 설정 항목을 동적으로 지정할 수 있습니다. 이 명령에는 관리자 권한이 필요합니다.

    ADMIN SET FRONTEND CONFIG (" fe_config_name "=" fe_config_value ");

    모든 설정 항목이 동적 설정을 지원하는 것은 아닙니다. SHOW FRONTEND CONFIG; 명령 결과의 IsMutable 열에서 지원 여부를 확인할 수 있습니다.

    MasterOnly 설정 항목을 수정하면 명령이 Master FE로 직접 전달되고 Master FE의 해당 항목만 변경됩니다.

    이 방법으로 변경한 설정 항목은 FE 프로세스를 다시 시작하면 적용되지 않습니다.

    이 명령에 관한 자세한 도움말은 HELP ADMIN SET CONFIG; 명령으로 확인할 수 있습니다.

  3. HTTP 프로토콜을 통한 동적 설정

    자세한 내용은 Set Config Action을 참조하세요.

    이 방법을 사용하면 변경한 설정 항목을 영구 저장할 수도 있습니다. 항목은 fe_custom.conf 파일에 저장되므로 FE를 다시 시작한 후에도 적용됩니다.

예시​

  1. async_pending_load_task_pool_size 변경

    SHOW FRONTEND CONFIG;에서 이 항목은 동적으로 설정할 수 없음을 확인할 수 있습니다(IsMutable이 false). fe.conf에 다음 항목을 추가해야 합니다.

    async_pending_load_task_pool_size = 20

    그런 다음 설정을 적용하려면 FE 프로세스를 다시 시작합니다.

  2. dynamic_partition_enable 변경

    SHOW FRONTEND CONFIG;에서 이 항목은 동적으로 설정할 수 있고(IsMutable이 true) Master FE 전용 설정임을 확인할 수 있습니다. 먼저 아무 FE에나 연결하여 다음 명령을 실행하면 설정을 변경할 수 있습니다.

    ADMIN SET FRONTEND CONFIG ("dynamic_partition_enable" = "true"); `

    이후 다음 명령으로 변경된 값을 조회할 수 있습니다.

    set forward_to_master = true;
    SHOW FRONTEND CONFIG;

    이 방법으로 변경한 후 Master FE가 다시 시작되거나 Master 선출이 수행되면 설정이 무효화됩니다. 영구 적용하려면 설정 항목을 fe.conf에 직접 추가하고 FE를 다시 시작합니다.

  3. max_distribution_pruner_recursion_depth 변경

    SHOW FRONTEND CONFIG;에서 이 항목은 동적으로 설정할 수 있고(IsMutable이 true) Master FE 전용이 아님을 확인할 수 있습니다.

    마찬가지로 동적 설정 명령으로 변경할 수 있습니다. Master FE 전용 설정이 아니므로 모든 FE가 변경된 값을 사용하게 하려면 각 FE에 개별적으로 연결하여 설정을 동적으로 변경해야 합니다.

설정 항목​

메타데이터와 클러스터​

meta_dir​

기본값：DORIS_HOME_DIR + "/doris-meta"

형식: string 설명: Doris 메타데이터가 여기에 저장됩니다. 이 디렉터리의 스토리지에는 다음을 강력히 권장합니다.

  • 높은 쓰기 성능(SSD)
  • 안전성(RAID）

catalog_try_lock_timeout_ms​

기본값：5000 （ms）

IsMutable：true

Catalog 잠금의 tryLock 제한 시간 설정입니다. 테스트 목적이 아니라면 일반적으로 변경할 필요가 없습니다.

enable_bdbje_debug_mode​

기본값：false

true로 설정하면 FE가 BDBJE 디버그 모드로 시작됩니다.

max_bdbje_clock_delta_ms​

기본값：5000 （5s）

Master FE 호스트와 Master가 아닌 FE 사이에서 허용되는 최대 시계 오차를 설정합니다. Master가 아닌 FE가 BDBJE를 통해 Master FE에 연결할 때마다 이 값을 검사합니다. 시계 오차가 이 값보다 크면 연결을 포기합니다.

metadata_failure_recovery​

기본값：false

true이면 FE가 bdbje 복제 그룹을 재설정하여 선출 가능한 모든 노드 정보를 제거하고 Master로 시작하도록 시도합니다. 선출 가능한 노드가 모두 시작되지 않는 경우 메타데이터를 다른 노드에 복사하고 이 설정을 true로 지정하여 FE 재시작을 시도할 수 있습니다.

txn_rollback_limit​

기본값：100

그룹에 다시 참여할 때 bdbje가 롤백할 수 있는 최대 트랜잭션 수입니다.

grpc_threadmgr_threads_nums​

기본값: 4096

grpc_threadmgr에서 grpc 이벤트를 처리하는 스레드 수입니다.

bdbje_replica_ack_timeout_second​

기본값：10 (s)

bdbje에 쓸 때 복제본 응답을 기다리는 제한 시간입니다. 비교적 큰 로그를 쓰는 동안 응답 시간이 초과되어 로그 쓰기에 실패할 수 있습니다. 이 경우 값을 적절히 늘릴 수 있습니다.

bdbje_lock_timeout_second​

기본값：5

bdbje 작업의 잠금 제한 시간입니다. FE WARN 로그에 LockTimeoutException이 많이 발생하면 이 값을 늘려 볼 수 있습니다.

bdbje_heartbeat_timeout_second​

기본값：30

Master와 Follower 사이의 bdbje 하트비트 제한 시간입니다. 기본값은 bdbje의 기본값과 같은 30초입니다. 일시적인 네트워크 문제나 예상치 못한 긴 Java GC로 허위 시간 초과가 발생하면 이 값을 늘려 볼 수 있습니다.

replica_ack_policy​

기본값：SIMPLE_MAJORITY

옵션: ALL, NONE, SIMPLE_MAJORITY

bdbje의 복제본 응답 정책입니다. 자세한 내용은 http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.ReplicaAckPolicy.html을 참조하세요.

replica_sync_policy​

기본값：SYNC

옵션：SYNC, NO_SYNC, WRITE_NO_SYNC

bdbje의 Follower FE 동기화 정책입니다.

master_sync_policy​

기본값：SYNC

옵션：SYNC, NO_SYNC, WRITE_NO_SYNC

bdbje의 Master FE 동기화 정책입니다. Follower FE를 1개만 배포한다면 'SYNC'로 설정하세요. Follower FE를 3개보다 많이 배포한다면 이 항목과 아래의 'replica_sync_policy'를 WRITE_NO_SYNC로 설정할 수 있습니다. 자세한 내용은 http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.SyncPolicy.html을 참조하세요.

bdbje_reserved_disk_bytes​

복제된 JE Environment에서 유지할 예약 공간의 바이트 수에 대한 목표 상한입니다.

기본값: 1073741824

동적 설정 가능 여부: false

Master FE 노드 전용 설정 항목 여부: false

ignore_meta_check​

기본값：false

IsMutable：true

true이면 Master가 아닌 FE는 Master FE와 자신의 메타데이터 지연 격차가 meta_delay_toleration_second를 초과해도 이를 무시하고 읽기 서비스를 계속 제공합니다. 어떤 이유로 Master FE를 비교적 오래 중지해야 하지만 Master가 아닌 FE에서 읽기 서비스를 계속 제공하려는 경우 유용합니다.

meta_delay_toleration_second​

기본값: 300 (5 min)

메타데이터 지연 격차가 meta_delay_toleration_second를 초과하면 Master가 아닌 FE는 서비스 제공을 중지합니다.

edit_log_port​

기본값：9010

bdbje 포트입니다.

edit_log_type​

기본값：BDB

Edit Log 유형입니다. BDB: 로그를 bdbje에 씁니다. LOCAL: 더 이상 사용되지 않습니다.

edit_log_roll_num​

기본값：50000

IsMutable：true

MasterOnly：true

Master FE는 메타 저널이 edit_log_roll_num개 쌓일 때마다 이미지를 저장합니다.

force_do_metadata_checkpoint​

기본값：false

IsMutable：true

MasterOnly：true

true로 설정하면 체크포인트 스레드가 JVM 메모리 사용률과 관계없이 체크포인트를 생성합니다.

metadata_checkpoint_memory_threshold​

기본값：60 （60%）

IsMutable：true

MasterOnly：true

JVM 메모리 사용률(힙 또는 old 메모리 풀)이 이 임계값을 초과하면 OOM을 피하기 위해 체크포인트 스레드가 작동하지 않습니다.

max_same_name_catalog_trash_num​

Catalog 휴지통에서 같은 이름의 메타정보를 유지할 최대 개수를 설정합니다. 최대값을 초과하면 가장 먼저 삭제된 메타정보가 완전히 삭제되어 복구할 수 없습니다. 0이면 같은 이름의 객체를 보관하지 않고, 0보다 작으면 제한하지 않습니다.

참고: 같은 이름의 메타데이터인지는 정해진 범위 안에서 판단합니다. 예를 들어 이름이 같은 데이터베이스는 같은 클러스터 안에서, 이름이 같은 테이블은 같은 데이터베이스(데이터베이스 ID가 동일함) 안에서, 이름이 같은 파티션은 같은 데이터베이스(데이터베이스 ID가 동일함)와 같은 테이블(테이블 ID가 동일함) 안에서 판단합니다.

기본값: 3

동적 설정 가능 여부: true

Master FE 노드 전용 설정 항목 여부: true

cluster_id​

heartbeat_mgr_blocking_queue_size​

기본값：1024

MasterOnly：true

heartbeat_mgr에서 하트비트 작업을 저장하는 블로킹 큐의 크기입니다.

heartbeat_mgr_threads_num​

기본값：8

MasterOnly：true

heartbeat_mgr에서 하트비트 이벤트를 처리하는 스레드 수입니다.

IsMutable：true

  3. 클러스터의 Backend 수 변경
  4. 데이터베이스 연결/마이그레이션

enable_token_check​

fe_meta_auth_token​

기본값: "" (빈 문자열)

기본값：2

기본값：4

위 세 매개변수가 제어하는 Jetty 스레드 아키텍처는 acceptors, selectors, workers의 세 스레드 풀로 구성됩니다. Acceptors가 새 연결을 받아 selectors로 넘기면, selectors가 HTTP 메시지 프로토콜을 파싱하고 마지막으로 workers가 요청을 처리합니다. 앞의 두 스레드 풀은 논블로킹 모델을 사용하므로 한 스레드가 여러 소켓의 읽기와 쓰기를 처리할 수 있어 스레드 수가 적어도 됩니다.

대부분의 프로젝트에는 acceptors 스레드 1-2개와 selectors 스레드 2~4개면 충분합니다. Workers는 블로킹 비즈니스 로직을 처리하며 데이터베이스 작업이 많은 경우가 많아 스레드가 많이 필요합니다. 구체적인 수는 애플리케이션의 QPS와 IO 이벤트 비율에 따라 달라집니다. QPS가 높을수록 스레드가 더 필요하고, IO 비율이 높을수록 대기 중인 스레드와 전체 스레드가 더 많이 필요합니다.

Worker 스레드 풀은 기본적으로 설정되지 않으므로 필요에 맞게 설정하세요.

be_exec_version​

Fragment 사이에서 블록을 전달할 때 사용하는 직렬화 형식을 정의합니다.

코드 변경으로 블록의 데이터 형식이 달라지는 경우가 있습니다. 순차 업그레이드 중에도 BE 간 호환성을 유지하려면 FE가 데이터 버전을 내려 보내 어떤 형식으로 데이터를 전송할지 결정해야 합니다.

예를 들어 클러스터에 BE가 2개 있고, 업그레이드된 하나는 최신 v1v_1v1​을 지원하지만 다른 하나는 v0v_0v0​만 지원한다고 가정합니다. 이때 FE는 아직 업그레이드되지 않았으므로 v0을일괄적으로내려보냅니다.v_0을 일괄적으로 내려 보냅니다. v0​을일괄적으로내려보냅니다., BE는 이전 데이터 형식으로 통신합니다. 모든 BE를 업그레이드한 후 FE를 업그레이드하면 새 FE가 v1v_1v1​을 내려 보내고 클러스터 전체가 새 데이터 형식으로 전환됩니다.

기본값은 max_be_exec_version입니다. 특별한 요구가 있으면 형식 버전을 수동으로 낮출 수 있지만 min_be_exec_version보다 낮아서는 안 됩니다.

모든 BE에 대해 이 변수의 값은 항상 BeExecVersionManager::min_be_exec_version과 BeExecVersionManager::max_be_exec_version 사이여야 합니다. 즉, 업그레이드를 마친 클러스터를 다운그레이드하려면 FE를 먼저 다운그레이드한 다음 BE를 다운그레이드하거나, 설정에서 이 변수를 수동으로 낮춘 뒤 BE를 다운그레이드해야 합니다.

Master FE 노드 전용 설정 항목 여부: false

버전 4.1.5부터 지원합니다. meta_service_rpc_rate_limit_enabled=true일 때만 적용됩니다. true이면 요청을 기다리게 하거나 거부하지 않고 속도 제한을 평가하여 메트릭을 기록합니다. false이면 설정된 QPS, 버스트 창, 대기 제한 시간을 적용합니다. dry-run 모드의 대기 메트릭은 예상 대기 시간을 나타냅니다.

meta_service_rpc_rate_limit_default_qps_per_core​

기본값: 50

동적 설정 가능 여부: true

버전 4.1.4에 추가되었습니다. meta_service_rpc_rate_limit_qps_per_core_config에서 개별 설정하지 않은 Meta Service RPC 메서드에 허용하는 CPU 코어당 기본 QPS입니다. 값이 0 이하이면 속도를 제한하지 않습니다.

meta_service_rpc_rate_limit_qps_per_core_config​

기본값: getPartitionVersion:500;getTableVersion:500;getTabletStats:50;beginTxn:50

동적 설정 가능 여부: true

버전 4.1.4에 추가되었습니다. Meta Service RPC 메서드별 코어당 QPS 제한을 method1:qps1;method2:qps2 형식으로 지정합니다. 값이 0 이하이면 해당 메서드의 속도를 제한하지 않습니다.

meta_service_rpc_rate_limit_burst_seconds​

기본값: 2 (s)

동적 설정 가능 여부: true

버전 4.1.4에 추가되었습니다. Meta Service RPC 속도 제한에서 버스트 창의 길이(초)입니다. 장기 평균 QPS는 그대로 유지하면서 이 창 안에서 버스트를 허용합니다.

meta_service_rpc_rate_limit_wait_timeout_ms​

기본값: 1000 (ms)

동적 설정 가능 여부: true

버전 4.1.4에 추가되었습니다. RPC에 속도 제한이 적용될 때 기다리는 최대 시간(밀리초)입니다. 0이면 기다리지 않고 요청이 즉시 실패합니다.
