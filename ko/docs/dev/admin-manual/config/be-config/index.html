BE 구성

이 문서에서는 BE의 주요 구성 항목을 소개합니다.

BE 구성 파일 be.conf는 일반적으로 BE 배포 경로의 conf/ 디렉터리에 저장됩니다. 버전 0.14에서는 별도의 구성 파일인 be_custom.conf가 도입됩니다. 이 파일은 사용자가 운영 중에 동적으로 설정하고 영구 저장한 구성 항목을 기록하는 데 사용됩니다.

BE 프로세스가 시작되면 먼저 be.conf의 구성 항목을 읽은 다음 be_custom.conf의 구성 항목을 읽습니다. be_custom.conf의 구성 항목은 be.conf의 동일한 구성 항목을 덮어씁니다.

be_custom.conf 파일의 위치는 be.conf의 custom_config_dir 구성 항목으로 설정할 수 있습니다.

구성 항목 조회​

BE의 구성 항목은 다음 두 가지 방법으로 조회할 수 있습니다.

  1. BE 웹 페이지

    BE 웹 페이지에 접속하여 현재 구성 항목을 조회할 수 있습니다.

    http://be_host:be_webserver_port/varz

  2. 명령으로 조회

    MySQL 클라이언트에서 다음 명령으로 BE의 구성 항목을 조회할 수 있습니다. 자세한 구문은 SHOW-CONFIG를 참조하세요.

    SHOW BACKEND CONFIG;

    결과에 표시되는 각 컬럼의 의미는 다음과 같습니다.

    1. BackendId: backend의 ID입니다.
    2. Host: backend의 IP입니다.
    3. Key: 구성 항목의 이름입니다.
    4. Value: 구성 항목의 현재 값입니다.
    5. Type: 정수 또는 문자열과 같은 구성 항목 값의 타입입니다.
    6. IsMutable: 동적 구성 가능 여부입니다. true이면 런타임에 동적으로 설정할 수 있습니다. false이면 be.conf에서만 설정할 수 있으며, BE를 재시작한 후에 적용됩니다.

구성 항목 설정​

BE의 구성 항목은 다음 두 가지 방법으로 설정할 수 있습니다.

  1. 정적 구성

    conf/be.conf 파일에 구성 항목을 추가하고 값을 설정합니다. BE가 시작될 때 be.conf의 구성 항목을 읽습니다. be.conf에 없는 구성 항목은 기본값을 사용합니다.

  2. 동적 구성

    BE가 시작된 후 다음 명령으로 구성 항목을 동적으로 설정할 수 있습니다.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}

    버전 0.13 이하에서는 이 방법으로 변경한 구성 항목이 BE 프로세스를 재시작하면 사라집니다. 버전 0.14 이상에서는 다음 명령으로 변경한 구성을 영구 저장할 수 있습니다. 변경한 구성 항목은 be_custom.conf 파일에 저장됩니다.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}\&persist=true

예시​

  1. max_base_compaction_threads 정적 변경

    be.conf 파일에 다음 내용을 추가합니다.

    max_base_compaction_threads=5

    그런 다음 BE 프로세스를 재시작하면 구성이 적용됩니다.

  2. streaming_load_max_mb 동적 변경

    BE가 시작된 후 다음 명령으로 구성 항목 streaming_load_max_mb를 동적으로 설정합니다.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024

    다음과 같은 반환값은 설정이 성공했음을 나타냅니다.

    {
        "status": "OK",
        "msg": ""
    }

    이 구성은 BE를 재시작하면 사라집니다. 변경 결과를 영구 저장하려면 다음 명령을 사용하세요.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024\&persist=true

구성 항목​

서비스​

deploy_mode​

  • 타입: string
  • 설명: BE의 실행 모드입니다. cloud는 컴퓨팅과 스토리지 분리 모드를 나타냅니다.
  • 기본값: ""

bvar_max_dump_multi_dimension_metric_num​

  • 타입: string
  • 설명: 버전 4.1.5부터 지원됩니다. /brpc_metrics에서 내보내는 다차원 bvar 메트릭 샘플의 최대 개수입니다. 0으로 설정하면 이러한 샘플을 비활성화합니다. 변경하려면 BE를 재시작해야 합니다.
  • 기본값: 5000

be_port​

  • 타입: int32
  • 설명: FE의 요청을 수신하는 BE thrift 서버의 포트입니다.
  • 기본값: 9060

heartbeat_service_port​

  • 타입: int32
  • 설명: FE의 heartbeat를 수신하는 BE의 heartbeat 서비스 포트(thrift)입니다.
  • 기본값: 9050

webserver_port​

  • 타입: int32
  • 설명: BE의 http 서버 서비스 포트입니다.
  • 기본값: 8040

brpc_port​

  • 타입: int32
  • 설명: BE 간 통신에 사용하는 BE의 BRPC 포트입니다.
  • 기본값: 8060

arrow_flight_sql_port​

  • 타입: int32
  • 설명: Arrow Flight Client와 BE 간 통신에 사용하는 BE의 Arrow Flight SQL 서버 포트입니다.
  • 기본값: -1

enable_https​

  • 타입: bool
  • 설명: https 지원 여부입니다. 지원하려면 be.conf에서 ssl_certificate_path와 ssl_private_key_path를 설정하세요.
  • 기본값: false

priority_networks​

  • 설명: IP가 여러 개인 서버에서 사용할 IP 선택 전략을 지정합니다. 이 목록과 일치하는 IP는 최대 하나여야 합니다. 10.10.10.0/24와 같은 CIDR 표기법을 사용하며, 항목은 세미콜론으로 구분합니다. 이 규칙과 일치하는 IP가 없으면 임의로 하나를 선택합니다.
  • 기본값: 빈 값

storage_root_path​

  • 타입: string

  • 설명: 데이터 루트 경로이며, ';'로 구분합니다. 각 루트 경로의 스토리지 매체를 HDD 또는 SSD로 지정할 수 있습니다. 각 루트 경로 끝에 ','로 구분하여 용량 제한을 추가할 수 있습니다. SSD와 HDD 디스크를 혼용하지 않는 경우에는 아래 예 1과 예 2의 구성 방법을 사용할 필요 없이 스토리지 디렉터리만 지정하면 됩니다. FE의 기본 스토리지 매체 구성도 변경할 필요가 없습니다.

    예 1: storage_root_path=/home/disk1/doris.HDD;/home/disk2/doris.SSD;/home/disk2/doris

    • 1./home/disk1/doris.HDD는 스토리지 매체가 HDD임을 나타냅니다.
    • 2./home/disk2/doris.SSD는 스토리지 매체가 SSD임을 나타냅니다.
    • 3./home/disk2/doris는 기본 스토리지 매체가 HDD임을 나타냅니다.

    예 2: storage_root_path=/home/disk1/doris,medium:hdd;/home/disk2/doris,medium:ssd

    • 1./home/disk1/doris,medium:hdd는 스토리지 매체가 HDD임을 나타냅니다.
    • 2./home/disk2/doris,medium:ssd는 스토리지 매체가 SSD임을 나타냅니다.

  • 기본값: ${DORIS_HOME}/storage

heartbeat_service_thread_count​

  • 타입: int32
  • 설명: BE에서 heartbeat 서비스를 실행하는 스레드 수입니다. 기본값은 1이며, 변경하지 않는 것이 좋습니다.
  • 기본값: 1

ignore_broken_disk​

  • 타입: bool

  • 설명: BE가 시작될 때 storage_root_path에 구성된 모든 경로를 검사합니다.

    • ignore_broken_disk=true

    경로가 존재하지 않거나 해당 경로에서 파일을 읽거나 쓸 수 없는 경우(디스크 손상), 해당 경로를 무시합니다. 다른 사용 가능한 경로가 있으면 시작을 중단하지 않습니다.

    • ignore_broken_disk=false

    경로가 존재하지 않거나 해당 경로에서 파일을 읽거나 쓸 수 없는 경우(디스크 손상), 시스템은 시작을 중단하고 종료합니다.

  • 기본값: false

mem_limit​

  • 타입: string
  • 설명: BE 프로세스가 사용할 수 있는 서버의 최대 메모리 비율을 제한합니다. BE가 서버 메모리를 과도하게 점유하지 않도록 하는 데 사용됩니다. 이 매개변수는 0보다 커야 합니다. 비율이 100%보다 크면 100%로 처리됩니다.
  • 기본값: 90%

cluster_id​

  • 타입: int32
  • 설명: BE가 속한 클러스터의 ID를 설정합니다.
    • 일반적으로 FE가 heartbeat를 통해 BE에 이 값을 전달하므로 설정할 필요가 없습니다. BE가 특정 Doris 클러스터에 속한다는 것이 확인된 경우 설정할 수 있습니다. 데이터 디렉터리의 cluster_id 파일도 이 매개변수와 값이 일치하도록 수정해야 합니다.
  • 기본값: -1

custom_config_dir​

  • 설명: be_custom.conf 파일의 위치를 설정합니다. 기본 위치는 conf/ 디렉터리입니다.
    • 일부 배포 환경에서는 시스템 업그레이드로 인해 conf/ 디렉터리가 덮어써질 수 있습니다. 이 경우 사용자가 변경한 구성 항목도 덮어써집니다. 구성 파일이 덮어써지지 않도록 be_custom.conf를 별도로 지정한 다른 디렉터리에 저장할 수 있습니다.
  • 기본값: 빈 값

trash_file_expire_time_sec​

  • 설명: 휴지통 정리 간격은 24시간입니다. 디스크 공간이 부족하면 trash 아래의 파일 보존 기간이 이 매개변수를 따르지 않을 수 있습니다.
  • 기본값: 86400

es_http_timeout_ms​

  • 설명: http를 통해 ES에 연결할 때의 타임아웃입니다.
  • 기본값: 5000 (ms)

es_scroll_keepalive​

  • 설명: ES scroll의 keep-alive 유지 시간입니다.
  • 기본값: 5 (m)

external_table_connect_timeout_sec​

  • 타입: int32
  • 설명: ODBC 테이블과 같은 외부 테이블에 연결할 때의 타임아웃입니다.
  • 기본값: 5초

pipeline_status_report_interval​

  • 설명: profile 보고 간격입니다.
  • 기본값: 5초

brpc_max_body_size​

  • 설명: 주로 brpc의 max_body_size 매개변수를 변경하는 데 사용됩니다.

    • 쿼리가 실패하면서 BE 로그에 body_size is too large 오류 메시지가 표시될 수 있습니다. SQL이 "multi distinct + group by 없음 + 1T 초과 데이터" 형태일 때 발생할 수 있습니다. 이 오류는 brpc 패킷 크기가 구성된 값을 초과했음을 나타냅니다. 구성값을 늘리면 이 오류를 방지할 수 있습니다.

brpc_socket_max_unwritten_bytes​

  • 설명: 주로 brpc의 socket_max_unwritten_bytes 매개변수를 변경하는 데 사용됩니다.
    • 쿼리가 실패하면서 BE 로그에 The server is overcrowded 오류 메시지가 표시될 수 있습니다. 이는 송신 측에서 버퍼링해야 하는 메시지가 너무 많다는 뜻으로, SQL에서 큰 bitmap 값을 전송해야 할 때 발생할 수 있습니다. 구성값을 늘리면 이 오류를 방지할 수 있습니다.

transfer_large_data_by_brpc​

  • 타입: bool
  • 설명: Tuple/Block 데이터 길이가 1.8G보다 클 때 protoBuf 요청을 직렬화하고 Tuple/Block 데이터를 controller attachment에 넣어 http brpc로 전송할지 제어합니다. protoBuf 요청 길이가 2G를 초과할 때 발생하는 오류인 Bad request, error_text=[E1003]Fail to compress request를 방지하기 위한 설정입니다. 이전 버전에서는 Tuple/Block 데이터를 attachment에 넣은 후 기본 baidu_std brpc로 전송했지만, attachment가 2G를 초과하면 잘렸습니다. http brpc를 통한 전송에는 2G 제한이 없습니다.
  • 기본값: true

brpc_num_threads​

  • 설명: 주로 brpc의 bthread 수를 변경하는 데 사용됩니다. 기본값은 256입니다.
    • QPS 성능을 높이기 위해 더 큰 값으로 설정할 수 있습니다. 자세한 내용은 https://github.com/apache/incubator-brpc/blob/master/docs/cn/benchmark.md를 참조하세요.
  • 기본값: 256

thrift_rpc_timeout_ms​

  • 설명: thrift의 기본 타임아웃입니다.
  • 기본값: 60000

thrift_client_retry_interval_ms​

  • 타입: int64
  • 설명: FE thrift 서버의 연쇄 과부하를 방지하기 위해 BE의 thrift 클라이언트 재시도 간격을 설정합니다. 단위는 ms입니다.
  • 기본값: 1000

thrift_connect_timeout_seconds​

  • 설명: thrift 클라이언트의 기본 연결 타임아웃입니다.
  • 기본값: 3 (s)

thrift_server_type_of_fe​

  • 타입: string

  • 설명: FE의 Thrift 서비스에서 사용하는 서비스 모델을 지정합니다. 문자열 타입이며 대소문자를 구분하지 않습니다. 이 매개변수는 FE의 thrift_server_type 매개변수 설정과 일치해야 합니다. 현재 지원하는 값은 THREADED와 THREAD_POOL입니다.

    • 매개변수가 THREADED이면 non-blocking I/O 모델을 사용합니다.

    • 매개변수가 THREAD_POOL이면 blocking I/O 모델을 사용합니다.

thrift_max_message_size​

기본값: 100MB

thrift 서버가 수신하는 메시지의 최대 크기이며, 단위는 바이트입니다. 클라이언트가 전송한 메시지 크기가 이 제한을 초과하면 Thrift 서버는 요청을 거부하고 연결을 닫습니다. 이때 클라이언트에는 "connection has been closed by peer." 오류가 발생합니다. 이 경우 이 매개변수 값을 늘려 볼 수 있습니다.

txn_commit_rpc_timeout_ms​

  • 설명: txn 커밋 RPC 타임아웃입니다.
  • 기본값: 60,000 (ms)

txn_map_shard_size​

  • 설명: txn_map_lock의 샤드 크기입니다. 값은 2^n이며, n=0,1,2,3,4입니다. txn 관리 성능을 높이기 위한 설정입니다.
  • 기본값: 128

txn_shard_size​

  • 설명: txn_lock의 샤드 크기입니다. 값은 2^n이며, n=0,1,2,3,4입니다. txn 커밋 및 게시 성능을 높이기 위한 설정입니다.
  • 기본값: 1024

  • 설명: 버전 4.2.0에서 추가되었습니다. 제공 측에서 동시에 수행할 수 있는 최대 캐시 채우기 수입니다. 한도를 초과하는 캐시 채우기 요청은 거부되며, 요청한 BE는 객체 스토리지에서 읽습니다.
  • 기본값: 32

peer_rpc_failure_eviction_threshold​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. peer 후보에서 이 횟수만큼 연속으로 RPC가 실패하면 후보 목록에서 제거합니다.
  • 기본값: 3

peer_all_miss_cooldown_threshold​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. 모든 peer 후보에서 캐시 미스가 발생한 읽기가 이 횟수만큼 연속으로 발생하면 tablet이 cooldown 상태로 전환됩니다. 이 기간에는 객체 스토리지에서 바로 읽습니다.
  • 기본값: 5

peer_all_miss_cooldown_duration_s​

  • 타입: int64
  • 설명: 버전 4.2.0에서 추가되었습니다. peer 읽기의 cooldown 지속 시간이며, 단위는 초입니다.
  • 기본값: 300

peer_candidate_expiry_s​

  • 타입: int64
  • 설명: 버전 4.2.0에서 추가되었습니다. 마지막 사용 시점부터 측정하는 peer 후보 항목의 만료 시간이며, 단위는 초입니다. 만료된 항목은 메모리에서 제거되며, 다음 캐시 미스 때 FE에서 다시 가져옵니다.
  • 기본값: 3600

peer_candidate_cleanup_interval_s​

  • 타입: int64
  • 설명: 버전 4.2.0에서 추가되었습니다. 만료된 peer 후보를 정리하는 백그라운드 작업의 실행 간격이며, 단위는 초입니다.
  • 기본값: 3600

peer_fetch_queue_timeout_ms​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. 제공 측의 처리 큐에서 peer 읽기 요청이 기다릴 수 있는 최대 시간이며, 단위는 밀리초입니다. 이 시간을 초과하여 대기한 요청은 거부하여 요청한 BE가 신속하게 객체 스토리지에서 읽도록 합니다.
  • 기본값: 100

brpc_peer_fetch_pool_threads​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. 제공 측에서 peer 읽기 요청을 처리하는 스레드 풀의 크기입니다. 데이터 적재와 같이 부하가 큰 RPC의 스레드 풀과 분리되어 있습니다. -1은 max(64, 2 × CPU cores)를 의미합니다. 동적으로 변경할 수 없습니다.
  • 기본값: -1

brpc_peer_fetch_pool_max_queue_size​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. 제공 측 peer 읽기 스레드 풀의 큐 길이입니다. -1은 max(4096, 128 × CPU cores)를 의미합니다. 동적으로 변경할 수 없습니다.
  • 기본값: -1

min_peer_race_s3_thread_num / max_peer_race_s3_thread_num​

  • 타입: int32
  • 설명: 버전 4.2.0에서 추가되었습니다. peer 읽기와 객체 스토리지 읽기가 경쟁할 때 요청 측에서 객체 스토리지 읽기를 수행하는 스레드 풀의 최소 / 최대 스레드 수입니다. 동적으로 변경할 수 없습니다.
  • 기본값: 0 / 32

s3_get_requests_per_second_per_core / s3_put_requests_per_second_per_core​

  • 타입: int64
  • 설명: 버전 4.1.4에서 추가되었습니다. CPU 코어당 계산되는 객체 스토리지 GET / PUT 요청의 QPS 한도입니다. 음수는 이 모드를 비활성화하고 기존의 절대 토큰 구성으로 돌아간다는 의미입니다. 0은 QPS를 제한하지 않는다는 의미입니다.
  • 기본값: -1

s3_get_requests_per_second_max / s3_put_requests_per_second_max​

  • 타입: int64
  • 설명: 버전 4.1.4에서 추가되었습니다. CPU 코어 수를 기준으로 계산한 GET / PUT QPS에 적용하는 절대 상한입니다. 0 이하이면 상한이 없습니다.
  • 기본값: 0

s3_get_bytes_per_second_per_core / s3_put_bytes_per_second_per_core​

  • 타입: int64
  • 설명: 버전 4.1.4에서 추가되었습니다. CPU 코어당 계산되는 객체 스토리지 GET / PUT 대역폭 한도입니다(코어당 초당 바이트 수). 0 이하이면 대역폭을 제한하지 않습니다.
  • 기본값: -1

s3_get_bytes_per_second_max / s3_put_bytes_per_second_max​

  • 타입: int64
  • 설명: 버전 4.1.4에서 추가되었습니다. CPU 코어 수를 기준으로 계산한 GET / PUT 대역폭에 적용하는 절대 상한이며, 단위는 초당 바이트입니다. 0 이하이면 상한이 없습니다.
  • 기본값: 0

s3_rate_limiter_cpu_cores_override​

  • 타입: int32
  • 설명: 버전 4.1.4에서 추가되었습니다. 위의 rate limit을 계산하는 데 사용할 CPU 코어 수입니다. 0 이하이면 시스템의 코어 수를 자동으로 감지합니다.
  • 기본값: 0

s3_rate_limiter_log_interval​

  • 타입: int64
  • 설명: 버전 4.1.4에서 추가되었습니다. 객체 스토리지의 rate limiting이 트리거될 때 출력하는 로그 항목 간 최소 간격이며, 단위는 밀리초입니다.
  • 기본값: 1000

file_cache_mem_storage_shard_num​

  • 타입: int32
  • 설명: 버전 4.1.4에서 추가되었습니다. 파일 캐시 메모리 스토리지의 샤드 수입니다. 동시 접근 시 lock 경합을 줄이는 데 사용됩니다.
  • 기본값: 1024

time_series_max_tablet_version_num​

  • 타입: int
  • 설명: time-series compaction 정책에서 단일 tablet의 버전 수를 제한합니다. 데이터 적재가 너무 빈번하거나 compaction이 제때 수행되지 않아 버전이 대량으로 누적되는 문제를 방지합니다. 한도를 초과하면 데이터 적재 작업이 거부됩니다.
  • 기본값: 20000
