SQL 구조는 질문에 맞게 선택하세요.

조인은 엔터티를 연결하고, 서브쿼리와 CTE는 논리를 구성하며, 분석 연산자는 맥락에 따른 값을 계산합니다. 구체화된 뷰는 반복 작업을 줄여 줍니다.

JOIN관계

일치하는 엔터티를 결합하거나, 일치 여부를 검사하거나, 제외합니다.

CTE구성

중간 단계의 논리에 이름을 붙이고 복잡한 쿼리를 구성합니다.

WIN분석

순위, 누적값, 동일 순위 행을 고려한 값을 계산합니다.

MV가속

투명한 쿼리 재작성을 통해 저장된 결과를 재사용합니다.

학습 도움말

힌트보다 올바른 구조가 먼저입니다.

가장 단순하면서도 올바른 관계형 표현식을 작성하고 실행 계획을 살펴본 다음, 비용이 많이 드는 데이터 이동이나 스캔을 최적화하세요. Doris는 불명확한 절차형 논리보다 명확한 SQL을 더 효과적으로 재작성하고 분산 실행할 수 있습니다.

근거를 확인하는 과정

EXPLAIN으로 실행 계획의 구조를 확인하고, 쿼리 프로파일에서 실행 중 수집된 근거를 확인하세요. SQL의 길이만으로 성능을 판단하지 마세요.

조인 의미

어떤 행을 남길지 선택하세요.

내부 조인, 외부 조인, 세미 조인, 안티 조인, 교차 조인은 같은 관계 키를 사용하더라도 서로 다른 질문에 답합니다.

MATCH내부 조인

조인 조건을 만족하는 행 쌍만 남깁니다.

KEEP외부 조인

한쪽 또는 양쪽에서 일치하지 않는 행도 남깁니다.

EXIST세미 조인

일치하는 행이 하나 이상 있으면 지정된 한쪽의 행을 반환합니다.

MISS안티 조인

일치하는 행이 없을 때만 지정된 한쪽의 행을 반환합니다.

PAIR교차 조인

양쪽 입력의 데카르트 곱을 생성합니다.

COND비동등 조인

범위나 부등식 조건으로 조인하며, 중첩 루프를 사용하는 경우가 많습니다.

학습 도움말

어떤 행이 남는지를 기준으로 생각하세요.

INNER는 일치하는 행을 남깁니다. LEFT, RIGHT, FULL은 지정된 쪽에서 일치하지 않는 행도 남깁니다. SEMI는 반대쪽 행을 반환하지 않고 일치 여부만 검사합니다. ANTI는 일치하지 않는 행을 남기고, CROSS는 가능한 모든 행 쌍을 만듭니다.

물리적 구현

동등 조인에는 보통 Hash Join을 사용할 수 있습니다. 비동등 조건이나 데카르트 곱을 만드는 논리에는 Nested Loop Join이 필요할 수 있으므로 결과 행 수를 특히 주의해서 살펴봐야 합니다.

일치하는 주문이 없는 고객을 반환하는 조인은 무엇인가요?

답을 선택하여 이해도를 확인하세요.

조인 데이터 분산

데이터가 네트워크를 통해 이동하는 양을 줄이세요.

Broadcast, Shuffle, Bucket Shuffle, Colocate 전략은 뒤로 갈수록 데이터 배치에 더 엄격한 조건을 요구하는 대신 유연성이 줄어듭니다.

  1. Broadcast작은 오른쪽 입력 복제
  2. Shuffle양쪽 입력 이동
  3. Bucket Shuffle한쪽 입력 이동
  4. Colocate조인을 위한 Shuffle 불필요
학습 도움말

테이블 크기와 데이터 분산 방식에 따라 데이터 이동 방식이 달라집니다.

Broadcast는 작은 빌드 측을 복제합니다. Shuffle은 양쪽을 다시 분할합니다. 조인 키가 다른 테이블의 버킷 키와 맞으면 Bucket Shuffle은 한쪽만 이동할 수 있습니다. 양쪽 테이블의 데이터 배치가 호환되면 Colocate는 데이터 이동을 피할 수 있습니다.

병렬 처리 수준도 중요합니다

버킷 수가 적으면 병렬로 처리할 수 있는 작업이 제한되어, 효율적으로 보이는 Colocate 또는 Bucket Shuffle 실행 계획이 오히려 느려질 수 있습니다.

매우 작은 차원 테이블에는 어떤 전략이 적합한가요?

서브쿼리와 CTE

중간 단계의 논리를 드러내세요.

서브쿼리는 관계형 질의를 다른 쿼리 안에 넣습니다. CTE는 중간 결과 집합에 이름을 붙이며 재귀적인 계층 구조도 표현할 수 있습니다.

서브쿼리

값, 집합 또는 관계를 다른 표현식 안에 넣습니다.

  • 스칼라 또는 여러 행의 결과
  • 상관 또는 독립 실행
  • 존재 여부 검사에 유용
CTE

주요 명령문 앞에서 쿼리 단계에 이름을 붙입니다.

  • 가독성 향상
  • 재사용 가능한 논리 단계
  • 재귀 표현 가능
학습 도움말

상관관계에 따라 실행 방식의 선택 폭이 달라집니다.

비상관 서브쿼리는 독립적으로 실행할 수 있고 폭넓게 지원됩니다. 상관 서브쿼리는 외부 쿼리의 현재 행에 의존하며 구조에 제약이 있습니다. CTE는 각 단계를 명확하게 해 주지만, 그렇다고 반드시 구체화되는 것은 아닙니다.

참조 범위를 가까운 단계로 제한하세요

여러 쿼리 단계를 가로지르는 깊은 상관관계는 피하세요. 명시적인 조인이나 이름을 붙인 단계가 의존 관계를 최적화하고 검토하기 쉽게 만든다면 이를 사용하세요.

서브쿼리가 상관 서브쿼리가 되는 조건은 무엇인가요?

답을 선택하여 이해도를 확인하세요.

다차원 SQL

여러 집계 수준을 하나의 명령문에서 계산하세요.

GROUPING SETS는 원하는 그룹 조합을 정확히 지정하고, ROLLUP은 계층별 합계를 추가하며, CUBE는 모든 조합을 생성합니다.

SETGROUPING SETS

명시적으로 지정한 그룹 조합만 계산합니다.

TREEROLLUP

순서가 있는 차원 계층을 따라 소계를 추가합니다.

ALLCUBE

차원의 가능한 모든 그룹 조합을 계산합니다.

학습 도움말

조합이 많을수록 처리할 작업도 늘어납니다.

필요한 집계 수준이 정해져 있다면 GROUPING SETS를 사용하세요. 연도에서 월, 일로 내려가는 계층에는 ROLLUP을 사용하고, 모든 차원 조합이 필요할 때만 CUBE를 사용하세요.

소계에서 생성된 NULL 구분하기

GROUPING 또는 GROUPING_ID를 사용하면 집계로 생성된 NULL과 원본 데이터에 이미 있던 NULL을 구분할 수 있습니다.

연도 → 월 → 일 계층에는 어떤 연산자가 가장 적합한가요?

윈도우 함수

주변 행을 분석하되 각 행은 그대로 유지하세요.

윈도우 함수는 각 행의 상세 정보를 유지하면서 순위, 오프셋, 누적 집계, 동일한 정렬값을 가진 행을 고려한 계산 결과를 추가합니다.

  1. 파티션계산 그룹 나누기
  2. 정렬행과 동일 정렬값의 순서 정하기
  3. 프레임계산에 포함할 행 선택
  4. 함수순위, 오프셋, 집계
학습 도움말

파티션, 정렬, 프레임은 각각 다른 역할을 합니다.

PARTITION BY는 계산 그룹을 나누고, ORDER BY는 순서와 동일한 정렬값을 가진 행을 정하며, 프레임은 현재 결과의 계산에 포함할 행을 정의합니다.

ROWS와 RANGE

ROWS는 물리적인 행의 상대 위치를 사용합니다. RANGE는 정렬값을 기준으로 동일한 값을 가진 행을 묶으므로 값이 반복되면 예상보다 많은 행이 포함될 수 있습니다.

누적 합계의 계산 순서를 정의하는 절은 무엇인가요?

답을 선택하여 이해도를 확인하세요.

함수와 타입

SQL 확장은 내장 함수로 표현할 수 없는 로직에만 사용하세요.

별칭 함수는 마이그레이션을 간소화하고, Java와 Python UDF는 사용자 정의 계산을 추가하며, 복합 타입은 중첩된 값도 쿼리할 수 있게 합니다.

AKA별칭 함수

호환되는 이름이나 재사용 가능한 표현식을 연결합니다.

JVMJava UDF

스칼라, 집계, 윈도우 또는 테이블 로직을 구현합니다.

PYPython UDF

Python 생태계의 이점이 추가 실행 비용을 상쇄할 때 Python 로직을 사용합니다.

NEST복합 타입

배열, 맵, 구조체, JSON을 먼저 평탄화하지 않고도 쿼리할 수 있습니다.

학습 도움말

확장 기능을 사용하면 관리할 책임도 늘어납니다.

최적화와 이식성을 위해 내장 함수를 우선 사용하세요. 익숙한 함수 시그니처를 연결할 때는 별칭 함수를, 관리되는 사용자 정의 실행에는 Java를, Python 생태계의 이점이 실행 비용을 상쇄할 때는 Python을 사용하세요. ARRAY, MAP, STRUCT, JSON은 용도를 고려해 설계하세요.

프로덕션 환경 점검 목록

사용자 코드는 버전을 관리하고 보안을 확보하며 테스트하고 모니터링하세요. 타입 매핑, NULL 처리 방식, 결정성, 리소스 제한, 관련된 모든 노드에서의 배포 가능 여부를 확인하세요.

구체화된 뷰

쿼리에서 반복되는 작업은 자주 쓰일수록 미리 계산하세요.

동기식 구체화된 뷰는 강한 일관성을 유지하며 단일 테이블 쿼리를 가속합니다. 비동기식 뷰는 갱신을 관리하면서 복잡한 다중 테이블 결과를 지원합니다.

동기식 MV

기본 데이터와 함께 유지되며 단일 테이블 쿼리를 가속합니다.

  • 강한 일관성
  • 투명한 쿼리 재작성
  • 지원되는 쿼리 구조가 제한됨
비동기식 MV

갱신 정책에 따라 업데이트되는 유연한 저장 결과입니다.

  • 다중 테이블 정의
  • 예약 또는 수동 갱신
  • 데이터 최신성을 관리해야 함
학습 도움말

데이터의 최신성 요구사항과 복잡도에 따라 뷰 유형을 선택하세요.

기본 테이블의 쓰기 작업을 즉시 반영해야 하는, 지원되는 프로젝션과 집계에는 동기식 뷰를 사용하세요. 예약 갱신이나 필요 시 갱신을 허용할 수 있다면 조인, 스타 스키마, 비용이 큰 변환에는 비동기식 뷰를 사용하세요.

투명한 쿼리 재작성

애플리케이션은 계속 기본 테이블을 쿼리하고, 옵티마이저는 호환되는 구체화된 뷰를 선택할 수 있습니다. EXPLAIN으로 재작성 여부를 확인하세요.
