构建目标

Agent 的 JSON 结构复杂，也能直接查询。

LLM 调用、工具调用、错误和最终回答各有不同字段，新版本还会加入新字段。Doris 的 VARIANT 会自动将这些 JSON 路径转为有类型的列，让您通过普通 SQL 过滤、搜索和聚合，无需迁移 Schema。

构建链路分析工具，数据包含 1,000 个 AI Agent 会话，约 20,000 个事件:

  • ，提供 会话列表 ，显示事件数、错误数、Token 数和延迟；
  • 一个 会话时间线，点击会话即可逐步查看 Agent 行为；
  • 工具与模型统计，包括 p95 延迟、错误率和 Token 用量；
  • JSON 内部检索，找出所有提到 timeout 的工具错误。

Doris 为何适合这个项目

  • 无需预定义 Schema 的写入时建模。 VARIANT 为每条 JSON 路径推断类型，并将常用路径存为真正的列式子列，因此 payload['latency_ms'] 只需读取一列，无需逐份解析文档。

  • 新字段自动出现。 当 v2 事件新增 cost_usd时，下一次导入就会出现对应子列，无需执行 ALTER TABLE.

  • JSON 内部检索。 VARIANT 列的倒排索引支持对每条文本路径检索，语法为 MATCH_*.

数据表hackathon.agent_events · sql
CREATE TABLE agent_events (  session_id  VARCHAR(40)  NOT NULL,  ts          DATETIME(3)  NOT NULL,  event_id    BIGINT       NOT NULL,  event_type  VARCHAR(32)  NOT NULL,   -- user_message / llm_call / tool_call / error / final_answer  payload     VARIANT      NOT NULL,  INDEX idx_payload (payload) USING INVERTED PROPERTIES ("parser" = "english"))DUPLICATE KEY(session_id, ts)DISTRIBUTED BY HASH(session_id) BUCKETS 1PROPERTIES ("replication_num" = "1", "storage_format" = "V3");

AI 编程助手容易踩到的 Doris 问题

TrapWhat to do instead
未做类型转换就比较 VARIANT 路径CAST(payload['latency_ms'] AS INT)；VARIANT 不能直接用作 Key 列或关联列
期望通过 DESC 列出 JSON 路径请先执行 SET describe_extend_variant_column = true; ，随后 DESC 会显示每个自动推断的子列及其类型
使用 LIKE '%term%' 进行文本检索col MATCH_ANY 'a b' （OR）、 MATCH_ALL （AND）、 MATCH_PHRASE 'a b' ，这些运算符会使用倒排索引
使用 ORM建议使用普通 MySQL 驱动和原生 SQL，ORM 可能生成 Doris 不支持的语句

开始构建

6 个里程碑， M0 → M5。代码面板会跟随您阅读的步骤。

  1. M0

    里程碑 010 分钟

    导入并检查数据

    在入门包目录中执行：

    M0 · 导入bash
    docker exec -i doris mysql -uroot -h127.0.0.1 -P9030 < seed/a4_agent_events.sql

    随后在 SQL Shell 中执行：

    M0 · 检查sql
    USE hackathon;SET describe_extend_variant_column = true;DESC agent_events;     -- see the subcolumns Doris inferred: payload.tool, payload.usage.input_tokens, ...
    检查点

    导入结果应显示 1,000 个会话和 20,401 个事件; DESC 会列出约 20 条 payload.* 路径，每条均有自动推断的类型。

  2. M1

    里程碑 115 分钟

    查询 JSON 路径

    M1 · 查询 JSON 路径sql
    SELECT CAST(payload['tool'] AS STRING) AS tool, COUNT(*) AS callsFROM agent_eventsWHERE event_type = 'tool_call'GROUP BY toolORDER BY calls DESC;
    检查点

    共有五种工具， sql_query 调用最多，共 3,506 次。

  3. M2

    里程碑 215 分钟

    聚合自动推断的子列

    M2 · 聚合自动推断的子列sql
    SELECT CAST(payload['tool'] AS STRING) AS tool,       COUNT(*) AS calls,       percentile_approx(CAST(payload['latency_ms'] AS DOUBLE), 0.95) AS p95_ms,       SUM(CASE WHEN CAST(payload['status'] AS STRING) = 'error' THEN 1 ELSE 0 END) AS errorsFROM agent_eventsWHERE event_type = 'tool_call'GROUP BY toolORDER BY p95_ms DESC;
    检查点

    python_exec 的 p95 最高，约 2.1 秒； http_get 失败次数最多，共 425 次。

  4. M3

    里程碑 310 分钟

    检索 JSON 内部文本

    M3 · 检索 JSON 内部文本sql
    SELECT session_id, ts, CAST(payload['error']['message'] AS STRING) AS error_messageFROM agent_eventsWHERE payload['error']['message'] MATCH_ANY 'timeout'ORDER BY tsLIMIT 20;
    检查点

    共有 398 个事件提到 timeout。按小时统计，这是判断 v2 影响的第一条线索。

  5. M4

    里程碑 420 分钟

    会话时间线

    M4 · 会话时间线sql
    SELECT ts, event_type,       CAST(payload['tool'] AS STRING)      AS tool,       CAST(payload['status'] AS STRING)    AS status,       CAST(payload['latency_ms'] AS INT)   AS latency_ms,       CAST(payload['text'] AS STRING)      AS textFROM agent_eventsWHERE session_id = 's-0042'ORDER BY ts;

    围绕这些查询构建界面：会话列表 → 时间线 → 统计。

    检查点

    会话 s-0042 包含 25 个事件：提问、LLM 与工具调用，其中一次 sql_query调用失败后重试，最后生成回答。

  6. M5

    里程碑 510 分钟

    观察 Schema 演进

    M5 · 导入结构变化批次bash
    docker exec -i doris mysql -uroot -h127.0.0.1 -P9030 < a4/drift_batch.sql   # events with new fields
    M5 · 查询新字段sql
    SELECT CAST(payload['agent_version'] AS STRING) AS version,       COUNT(*) AS llm_calls,       ROUND(SUM(CAST(payload['cost_usd'] AS DOUBLE)), 2) AS cost_usdFROM agent_eventsWHERE event_type = 'llm_call'GROUP BY versionORDER BY version;

    再次运行 DESC agent_events ，新路径已经出现，全程没有执行 ALTER TABLE 。

    检查点

    还会出现第三个版本， v2.1，只有它的 LLM 调用包含 cost_usd，而 DESC 现在会列出 payload.cost_usd 和 payload.retries.

进阶目标

  • 使用自己的链路。 导出您使用的 AI 编程助手本地会话日志（JSONL），导入 Doris，每行一个 CAST('…' AS JSON) 。数据存储在本地 Doris 实例中。

  • Schema Template。 通过 VARIANT<'latency_ms': INT, 'tool': STRING> 在表的副本中固定热点路径，比较 DESC 输出和查询行为。请使用 INSERT … SELECT …, CAST(payload AS JSON)填充数据，普通 VARIANT 不能直接转换为带模板的 VARIANT。

  • 让助手探索数据。 连接 Doris MCP Server，参见任务 A2，让助手找出表现最差的会话。

  • 使用 SQL 对错误分类 ，需自行提供 API Key： AI_CLASSIFY(CAST(payload['error']['message'] AS STRING), ['timeout', 'auth', 'bad input', 'other'])。参阅 LLM SQL 函数.
