湖仓模型

查询开放数据，无需再建 第二个数据孤岛.

Doris 可以使用其 MPP 向量化查询引擎，查询数据仓库表以及通过数据目录接入的外部数据湖数据。

  1. 01
    SQL 与优化器

    规划关联查询，并尽可能将计算下推到已连接的数据源。

  2. 02
    数据目录与元数据

    解析数据库、表、分区、Schema 和快照。

  3. 03
    远程存储与系统

    将权威数据保留在开放表、文件或数据库中。

学习提示

源系统仍是权威数据源。

外部元数据用于定位表和文件，Doris 负责规划和执行 SQL，缓存则减少重复的远程 I/O。数据可以继续保存在 Hive、Iceberg、Hudi、对象存储或其他已连接的系统中。

两种不同的架构

查询外部数据湖表与以计算存储分离模式部署 Doris 是两回事。前者是数据源联邦，后者是 Doris 的集群架构。

数据目录

为每个外部数据源提供熟悉的 SQL 地址.

一个数据目录定义一条连接，并通过 SQL 使用的三级命名空间暴露其中的数据库和表。

  1. 数据目录数据源 + 连接器
  2. 数据库外部命名空间
  3. 表Schema + 文件
  4. 分区可用于裁剪的元数据
学习提示

数据目录属性属于基础设施配置。

数据目录类型决定使用哪个连接器。属性定义端点、身份认证、存储访问方式和连接器行为。随后，Doris 将外部数据类型和元数据映射到自己的 SQL 模型中。

妥善管理凭据

使用受支持的密钥管理方式，并限制权限和网络访问。不要将对象存储或 Metastore 凭据提交到课程示例或应用代码中。

Hive 集成

让元数据与存储形成 统一的访问路径.

Hive 数据目录既需要访问 Metastore，也需要有权限读取元数据所描述的文件。

元数据层

解析数据库、表、Schema 和分区。

  • Hive Metastore 端点
  • 数据目录属性
  • 元数据事件与缓存
数据层

读取或写入表定义所指向的文件。

  • HDFS 或对象存储
  • 网络与凭据
  • 格式与快照支持
学习提示

能够访问元数据，不代表能够访问数据。

Doris 可能能通过 Hive Metastore 列出数据库，但查询 HDFS 或对象存储中的数据时仍会失败。应端到端检查 DNS、端口、身份认证、文件系统配置和委托凭据。

Kerberos 环境

统一分发并妥善保护所需的 krb5 配置和 keytab 文件，然后从实际运行的 Doris 进程验证票据续期和文件访问。

联邦 SQL

关联不同数据源，同时尽量减少 数据传输量.

Doris 可以在一条查询中关联外部数据湖表、外部数据库和内部表，并根据连接器的能力执行裁剪和下推。

  1. 解析数据目录元数据
  2. 裁剪分区 + 列
  3. 下推受支持的谓词
  4. 扫描并行远程 I/O
  5. 关联Doris 执行
学习提示

联邦查询不会消除网络开销。

尽早过滤数据并选择所需列，明确指定外部分区条件，收集有用的统计信息，并查看 EXPLAIN，确认分区裁剪、谓词下推和关联查询的数据分布情况。

生产环境中的使用方式

联邦查询适合探索性分析和有选择性的关联查询。对于频繁复用或对延迟要求严格的结果，可以使用内部表或物化视图。

缓存与 I/O

将重复的远程读取转化为 本地读取.

元数据缓存减少对数据目录的往返请求，数据缓存则将频繁读取的远程数据块保存在本地存储中。

META元数据缓存

复用表、分区、文件和快照的元数据。

DATA数据缓存

将频繁访问的远程数据块保存在计算节点附近的本地磁盘上。

PUSH下推

在传输前减少需要读取的列、分区和行。

学习提示

冷查询和热查询的性能需要分别衡量。

冷查询反映数据源和网络的吞吐能力，热查询反映缓存的收益。应根据工作集确定缓存容量，监控命中率和淘汰情况，并为并发扫描保留足够的本地带宽。

缓存不保证结果正确

根据外部数据的变化规律配置缓存刷新和失效机制。过期结果即使返回得快，仍然是错的。

回写与 DDL

将外部写入视为一项 共享系统变更.

受支持的数据目录可以写入数据或管理外部对象，但目标格式、Metastore、权限配置以及其他引擎都必须能正确处理写入结果。

CAP功能支持

确认连接器、格式和版本是否支持。

AUTH权限控制

只授予必需的 Metastore 和存储权限。

COMMIT提交行为

了解原子性、快照和失败后的清理机制。

READ跨引擎检查

验证其他使用方能否看到预期结果。

学习提示

具体能力取决于连接器和表格式。

执行 INSERT、CTAS 或 DDL 前，先核对当前版本的功能支持矩阵。遵循外部分区约定，验证提交语义，并测试 Hive、Spark 或其他读取方如何识别变更。

Hive Schema 规则

创建 Hive 表时，应遵守连接器对 Schema 和事务表的限制，包括分区列的位置要求。

湖仓回顾

将连接器边界作为 产品来运营.

生产环境中的湖仓访问路径需要具备正确的元数据、安全的存储访问、高效的裁剪、可衡量的缓存效果，以及经过测试的写入语义。

  1. 连接数据目录 + 认证
  2. 查询裁剪 + 下推
  3. 加速缓存 + 物化
  4. 治理写入 + Schema
  5. 运维端到端观测
学习提示

要负责整条访问路径，而不只是 SQL 端点。

监控 Metastore 延迟、缓存行为、远程读取字节数、扫描错误、凭据、Schema 变更和数据源可用性。明确每项依赖及相关故障由哪个团队负责。
