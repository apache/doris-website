Конфигурация BE

В этом документе описаны основные параметры конфигурации BE.

Файл конфигурации BE be.conf обычно находится в каталоге conf/ внутри каталога развертывания BE. В версии 0.14 появится дополнительный файл конфигурации be_custom.conf. Он предназначен для хранения параметров, которые пользователь динамически изменяет и сохраняет во время работы.

После запуска процесс BE сначала считывает параметры из be.conf, а затем из be_custom.conf. Параметры из be_custom.conf переопределяют одноименные параметры из be.conf.

Расположение файла be_custom.conf можно задать в be.conf с помощью параметра custom_config_dir.

Просмотр параметров конфигурации​

Просмотреть параметры конфигурации BE можно двумя способами:

  1. Веб-страница BE

    Текущие параметры конфигурации можно просмотреть на веб-странице BE:

    http://be_host:be_webserver_port/varz

  2. Просмотр с помощью команды

    Параметры конфигурации BE можно просмотреть в клиенте MySQL с помощью следующей команды. Подробное описание синтаксиса см. в разделе SHOW-CONFIG:

    SHOW BACKEND CONFIG;

    Столбцы результата имеют следующие значения:

    1. BackendId: идентификатор backend.
    2. Host: IP-адрес backend.
    3. Key: имя параметра конфигурации.
    4. Value: текущее значение параметра конфигурации.
    5. Type: тип значения параметра, например целое число или строка.
    6. IsMutable: возможность динамического изменения. Если значение равно true, параметр можно изменять во время работы. Если значение равно false, параметр можно задать только в be.conf, и он вступит в силу после перезапуска BE.

Настройка параметров конфигурации​

Настроить параметры конфигурации BE можно двумя способами:

  1. Статическая настройка

    Добавьте параметры и задайте их значения в файле conf/be.conf. При запуске BE считывает параметры из be.conf. Для параметров, отсутствующих в be.conf, используются значения по умолчанию.

  2. Динамическая настройка

    После запуска BE параметры можно изменять динамически с помощью следующих команд.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}

    В версии 0.13 и более ранних версиях изменения, внесенные таким способом, теряются после перезапуска процесса BE. В версии 0.14 и более поздних версиях измененную конфигурацию можно сохранить с помощью следующей команды. Измененные параметры записываются в файл be_custom.conf.

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}\&persist=true

Примеры​

  1. Статическое изменение max_base_compaction_threads

    Добавьте в файл be.conf:

    max_base_compaction_threads=5

    Затем перезапустите процесс BE, чтобы изменение вступило в силу.

  2. Динамическое изменение streaming_load_max_mb

    После запуска BE параметр streaming_load_max_mb можно изменить динамически следующей командой:

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024

    Следующий ответ указывает на успешное изменение параметра.

    {
        "status": "OK",
        "msg": ""
    }

    После перезапуска BE изменение будет потеряно. Чтобы сохранить его, используйте следующую команду:

    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024\&persist=true

Параметры конфигурации​

Службы​

deploy_mode​

  • Тип: string
  • Описание: Режим работы BE. cloud обозначает режим с разделением хранения и вычислений.
  • Значение по умолчанию: ""

bvar_max_dump_multi_dimension_metric_num​

  • Тип: string
  • Описание: Поддерживается начиная с версии 4.1.5. Максимальное количество образцов многомерных метрик bvar, экспортируемых через /brpc_metrics. Значение 0 отключает эти образцы. Для применения изменений требуется перезапуск BE.
  • Значение по умолчанию: 5000

be_port​

  • Тип: int32
  • Описание: Порт сервера thrift на BE для приема запросов от FE.
  • Значение по умолчанию: 9060

heartbeat_service_port​

  • Тип: int32
  • Описание: Порт службы heartbeat (thrift) на BE для приема heartbeat от FE.
  • Значение по умолчанию: 9050

webserver_port​

  • Тип: int32
  • Описание: Порт HTTP-сервера на BE.
  • Значение по умолчанию: 8040

brpc_port​

  • Тип: int32
  • Описание: Порт BRPC на BE для взаимодействия между BE.
  • Значение по умолчанию: 8060

arrow_flight_sql_port​

  • Тип: int32
  • Описание: Порт сервера Arrow Flight SQL на BE для взаимодействия между Arrow Flight Client и BE.
  • Значение по умолчанию: -1

enable_https​

  • Тип: bool
  • Описание: Определяет, поддерживается ли HTTPS. Если поддержка включена, задайте ssl_certificate_path и ssl_private_key_path в be.conf.
  • Значение по умолчанию: false

priority_networks​

  • Описание: Задает стратегию выбора IP-адреса для серверов с несколькими IP-адресами. Обратите внимание: этому списку должен соответствовать не более чем один IP-адрес. Список записывается в нотации CIDR с разделителем «точка с запятой», например 10.10.10.0/24. Если ни один IP-адрес не соответствует правилу, адрес выбирается случайным образом.
  • Значение по умолчанию: пусто

storage_root_path​

  • Тип: string

  • Описание: Корневые пути для данных, разделенные символом ';'. Для каждого пути можно указать тип носителя: HDD или SSD. В конце каждого пути можно добавить ограничение емкости через ','. Если пользователь не использует одновременно SSD и HDD, настройка по примеру 1 и примеру 2 ниже не требуется: достаточно указать каталог хранения. Менять тип носителя по умолчанию в конфигурации FE также не требуется.

    Пример 1: storage_root_path=/home/disk1/doris.HDD;/home/disk2/doris.SSD;/home/disk2/doris

    • 1./home/disk1/doris.HDD означает, что используется носитель HDD;
    • 2./home/disk2/doris.SSD означает, что используется носитель SSD;
    • 3./home/disk2/doris означает, что по умолчанию используется носитель HDD.

    Пример 2: storage_root_path=/home/disk1/doris,medium:hdd;/home/disk2/doris,medium:ssd

    • 1./home/disk1/doris,medium:hdd означает, что используется носитель HDD;
    • 2./home/disk2/doris,medium:ssd означает, что используется носитель SSD;

  • Значение по умолчанию: ${DORIS_HOME}/storage

heartbeat_service_thread_count​

  • Тип: int32
  • Описание: Количество потоков службы heartbeat на BE. По умолчанию равно 1; изменять его не рекомендуется.
  • Значение по умолчанию: 1

ignore_broken_disk​

  • Тип: bool

  • Описание: При запуске BE проверяются все пути, заданные в storage_root_path.

    • ignore_broken_disk=true

    Если путь не существует или файлы по этому пути недоступны для чтения или записи из-за неисправности диска, путь игнорируется. Если есть другие доступные пути, запуск продолжается.

    • ignore_broken_disk=false

    Если путь не существует или файлы по этому пути недоступны для чтения или записи из-за неисправности диска, система прерывает запуск и завершает работу.

  • Значение по умолчанию: false

mem_limit​

  • Тип: string
  • Описание: Ограничивает долю общей памяти сервера, которую может использовать процесс BE. Это предотвращает чрезмерное потребление памяти сервера процессом BE. Значение параметра должно быть больше 0. Если задано значение больше 100%, используется 100%.
  • Значение по умолчанию: 90%

cluster_id​

  • Тип: int32
  • Описание: Задает идентификатор кластера, к которому принадлежит BE.
    • Обычно FE передает это значение BE через heartbeat, поэтому задавать его не требуется. Если принадлежность BE к определенному кластеру Doris подтверждена, значение можно задать явно. Значение в файле cluster_id в каталоге данных необходимо привести в соответствие с этим параметром.
  • Значение по умолчанию: -1

custom_config_dir​

  • Описание: Задает расположение файла be_custom.conf. По умолчанию он находится в каталоге conf/.
    • В некоторых средах развертывания каталог conf/ может перезаписываться при обновлении системы. При этом измененные пользователем параметры конфигурации будут потеряны. Чтобы избежать перезаписи файла конфигурации, можно хранить be_custom.conf в другом указанном каталоге.
  • Значение по умолчанию: пусто

trash_file_expire_time_sec​

  • Описание: Интервал очистки корзины составляет 24 часа. При нехватке дискового пространства срок хранения файлов в корзине может не соответствовать этому параметру.
  • Значение по умолчанию: 86400

es_http_timeout_ms​

  • Описание: Время ожидания подключения к ES по HTTP.
  • Значение по умолчанию: 5000 (ms)

es_scroll_keepalive​

  • Описание: Время поддержания активности es scroll.
  • Значение по умолчанию: 5 (m)

external_table_connect_timeout_sec​

  • Тип: int32
  • Описание: Время ожидания при установлении соединения с внешней таблицей, например таблицей ODBC.
  • Значение по умолчанию: 5 секунд

pipeline_status_report_interval​

  • Описание: Интервал отправки отчетов профиля.
  • Значение по умолчанию: 5 секунд

brpc_max_body_size​

  • Описание: Используется главным образом для изменения параметра max_body_size в brpc.

    • Иногда запрос завершается с ошибкой, а в журнале BE появляется сообщение body_size is too large. Это может произойти при SQL вида «multi distinct + без group by + более 1T данных». Ошибка означает, что размер пакета brpc превышает заданное значение. Чтобы избежать этой ошибки, увеличьте значение параметра.

brpc_socket_max_unwritten_bytes​

  • Описание: Используется главным образом для изменения параметра socket_max_unwritten_bytes в brpc.
    • Иногда запрос завершается с ошибкой, а в журнале BE появляется сообщение The server is overcrowded. Это означает, что на стороне отправителя накопилось слишком много сообщений для буферизации. Такое возможно, когда SQL требуется передать большое значение bitmap. Чтобы избежать этой ошибки, увеличьте значение параметра.

transfer_large_data_by_brpc​

  • Тип: bool
  • Описание: Определяет, следует ли при размере данных Tuple/Block больше 1.8G сериализовать запрос protoBuf, помещать данные Tuple/Block во вложение контроллера и отправлять его через HTTP brpc. Это позволяет избежать ошибки при размере запроса protoBuf больше 2G: Bad request, error_text=[E1003]Fail to compress request. В предыдущей версии данные Tuple/Block после помещения во вложение отправлялись через стандартный baidu_std brpc, но при размере вложения больше 2G оно обрезалось. При отправке через HTTP brpc ограничение в 2G отсутствует.
  • Значение по умолчанию: true

brpc_num_threads​

  • Описание: Используется главным образом для изменения количества bthread в brpc. Значение по умолчанию равно 256.
    • Для повышения производительности QPS можно увеличить значение этого параметра. Подробнее см. https://github.com/apache/incubator-brpc/blob/master/docs/cn/benchmark.md.
  • Значение по умолчанию: 256

thrift_rpc_timeout_ms​

  • Описание: Время ожидания thrift по умолчанию.
  • Значение по умолчанию: 60000

thrift_client_retry_interval_ms​

  • Тип: int64
  • Описание: Задает интервал повторных попыток клиента thrift в BE, чтобы предотвратить лавинообразную перегрузку сервера thrift в FE. Единица измерения: ms.
  • Значение по умолчанию: 1000

thrift_connect_timeout_seconds​

  • Описание: Время ожидания подключения клиента thrift по умолчанию.
  • Значение по умолчанию: 3 (s)

thrift_server_type_of_fe​

  • Тип: string

  • Описание: Определяет модель обслуживания, используемую службой Thrift в FE. Значение имеет тип string и не зависит от регистра. Этот параметр должен совпадать со значением параметра thrift_server_type в FE. Сейчас доступны два значения: THREADED и THREAD_POOL.

    • Если задано THREADED, используется модель неблокирующего ввода-вывода.

    • Если задано THREAD_POOL, используется модель блокирующего ввода-вывода.

thrift_max_message_size​

Значение по умолчанию: 100MB

Максимальный размер принимаемого сообщения сервера thrift в байтах. Если размер сообщения клиента превышает этот предел, сервер Thrift отклоняет запрос и закрывает соединение. Клиент при этом получает ошибку: "connection has been closed by peer." В таком случае можно попробовать увеличить значение параметра.

txn_commit_rpc_timeout_ms​

  • Описание: Время ожидания RPC фиксации txn.
  • Значение по умолчанию: 60,000 (ms)

txn_map_shard_size​

  • Описание: Количество частей txn_map_lock. Значение задается как 2^n, n=0,1,2,3,4. Это позволяет повысить производительность управления txn.
  • Значение по умолчанию: 128

txn_shard_size​

  • Описание: Количество шардов txn_lock. Значение задается как 2^n, n=0,1,2,3,4. Это позволяет повысить производительность фиксации и публикации txn.
  • Значение по умолчанию: 1024

unused_rowset_monitor_interval​

  • Описание: Интервал удаления устаревших Rowset.
  • Значение по умолчанию: 30 (s)

max_client_cache_size_per_host​

  • Описание: Максимальный размер клиентского кеша на хост. В BE есть несколько клиентских кешей, но сейчас для них используется общая настройка размера. При необходимости для разных клиентских кешей можно задать разные настройки.
  • Значение по умолчанию: 10

string_type_length_soft_limit_bytes​

  • Тип: int32
  • Описание: Мягкое ограничение максимальной длины значения типа String.
  • Значение по умолчанию: 1,048,576

big_column_size_buffer​

  • Тип: int64
  • Описание: При работе с внешней таблицей ODBC, если тип столбца исходной таблицы ODBC равен HLL, CHAR или VARCHAR и длина значения столбца превышает это значение, запрос завершается с ошибкой 'column value length longer than buffer length'. Значение параметра можно увеличить.
  • Значение по умолчанию: 65535

small_column_size_buffer​

  • Тип: int64
  • Описание: При работе с внешней таблицей ODBC, если тип столбца исходной таблицы ODBC не равен HLL, CHAR или VARCHAR и длина значения столбца превышает это значение, запрос завершается с ошибкой 'column value length longer than buffer length'. Значение параметра можно увеличить.
  • Значение по умолчанию: 100

Запросы​

ignore_not_found_file_in_external_table​

  • Тип: bool
  • Описание: Определяет, могут ли средства чтения внешних таблиц пропускать отсутствующие файлы. Поддерживает динамическую настройку. Начиная с версии 4.1.5 этот параметр не позволяет пропускать отсутствующие файлы данных или удаления в зафиксированных снимках Iceberg: запрос завершается с ошибкой даже при значении true, чтобы избежать незаметного возврата неполного снимка.
  • Значение по умолчанию: true

parquet_metadata_size_limit​

  • Тип: int64
  • Описание: Поддерживается начиная с версии 4.1.5. Максимальный размер сериализованных метаданных в нижнем колонтитуле файла в байтах для встроенного средства чтения Parquet V2. Должен быть больше 0. При превышении возвращается ошибка Parquet v2 footer size ... exceeds metadata limit .... Поддерживает динамическую настройку. Для корректных файлов с большими нижними колонтитулами увеличьте значение в пределах доступной памяти.
  • Значение по умолчанию: 268435456 (256 MiB)

fragment_mgr_asynic_work_pool_queue_size​

  • Описание: Максимальное количество асинхронных задач, обрабатываемых на одном узле.
  • Значение по умолчанию: 4096

fragment_mgr_asynic_work_pool_thread_num_min​

  • Описание: Количество потоков для выполнения асинхронных задач. По умолчанию минимальное количество потоков равно 16.
  • Значение по умолчанию: 16

fragment_mgr_asynic_work_pool_thread_num_max​

  • Описание: Потоки создаются динамически по мере поступления асинхронных задач, максимум 512 потоков.
  • Значение по умолчанию: 512

doris_scanner_row_num​

  • Описание: Максимальное количество строк данных, возвращаемых каждым потоком сканирования за одно выполнение.
  • Значение по умолчанию: 16384

doris_scanner_row_bytes​

  • Описание: Объем строк в байтах, считываемый за одно выполнение фрагмента.

  • Описание: Добавлен в версии 4.1.4. Определяет, следует ли записывать в файловый кеш только файлы индексов. После включения при ограниченном пространстве кеша в нем в первую очередь сохраняются индексы.
  • Значение по умолчанию: false

enable_cache_read_from_peer​

  • Тип: bool
  • Описание: Главный переключатель чтения из кеша других BE. Если включен, при промахе локального File Cache сначала выполняется попытка чтения блока из File Cache другого BE в той же или другой вычислительной группе. Объектное хранилище используется, только если блок отсутствует на всех BE. Этот переключатель одновременно управляет чтением внутри группы и между группами; отдельно отключить чтение между группами нельзя. Чтение из кеша BE другой группы поддерживается начиная с версии 4.2.0, в которой также удален параметр cache_read_from_peer_expired_seconds. См. Чтение из кеша других BE.
  • Значение по умолчанию: false (при необходимости включите явно)

enable_peer_s3_race​

  • Тип: bool
  • Описание: Добавлен в версии 4.2.0. Определяет, следует ли выполнять чтение с другого BE и из объектного хранилища параллельно, используя первый полученный результат. Если выключен, чтение выполняется последовательно: кандидаты BE проверяются по очереди, а чтение из объектного хранилища начинается только после неудачи всех попыток.
  • Значение по умолчанию: true

peer_race_hedge_delay_ms​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Время опережения чтения с другого BE при параллельном чтении, в миллисекундах. Если BE отвечает за это время, запрос чтения из объектного хранилища не отправляется; при значении 0 оба чтения начинаются одновременно.
  • Значение по умолчанию: 20

max_concurrent_peer_races​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Максимальное количество одновременных параллельных чтений с другого BE и из объектного хранилища на одном BE. При промахах сверх этого предела чтение выполняется последовательно.
  • Значение по умолчанию: 64

peer_cache_fill_compute_group_id​

  • Тип: string
  • Описание: Добавлен в версии 4.2.0. Задается на BE, отправляющем запрос чтения. Идентификатор вычислительной группы, отвечающей за заполнение кеша между группами (это compute_group_id в столбце Tag команды SHOW BACKENDS, а не имя вычислительной группы). Если выбранный кандидат BE принадлежит этой вычислительной группе, запрос предписывает ему получить блок из объектного хранилища и записать в собственный File Cache, если блок отсутствует. Пустое значение означает, что заполнение не используется.
  • Значение по умолчанию: ""

enable_peer_server_cache_fill​

  • Тип: bool
  • Описание: Добавлен в версии 4.2.0. Задается на BE, предоставляющем кеш. Определяет, следует ли принимать запросы чтения от других BE с флагом заполнения. Если выключен, для блоков, отсутствующих в локальном кеше, возвращается признак «не найдено», и запрашивающий BE обращается к объектному хранилищу.
  • Значение по умолчанию: true

peer_server_cache_fill_timeout_ms​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Максимальное время ожидания одного заполнения на обслуживающей стороне, в миллисекундах. При превышении времени ожидания запрашивающий BE обращается к объектному хранилищу.
  • Значение по умолчанию: 6000

max_concurrent_peer_server_fills​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Максимальное количество одновременных заполнений на обслуживающей стороне. Запросы заполнения сверх предела отклоняются, и запрашивающий BE обращается к объектному хранилищу.
  • Значение по умолчанию: 32

peer_rpc_failure_eviction_threshold​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. После такого количества последовательных сбоев RPC кандидат BE удаляется из списка кандидатов.
  • Значение по умолчанию: 3

peer_all_miss_cooldown_threshold​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Количество последовательных чтений, при которых все кандидаты BE сообщили об отсутствии данных, после которого tablet переходит в период ожидания. В этот период чтение выполняется непосредственно из объектного хранилища.
  • Значение по умолчанию: 5

peer_all_miss_cooldown_duration_s​

  • Тип: int64
  • Описание: Добавлен в версии 4.2.0. Продолжительность периода ожидания перед возобновлением чтения с других BE, в секундах.
  • Значение по умолчанию: 300

peer_candidate_expiry_s​

  • Тип: int64
  • Описание: Добавлен в версии 4.2.0. Срок действия записей о кандидатах BE в секундах с момента последнего использования. Просроченные записи удаляются из памяти и при следующем промахе снова запрашиваются у FE.
  • Значение по умолчанию: 3600

peer_candidate_cleanup_interval_s​

  • Тип: int64
  • Описание: Добавлен в версии 4.2.0. Интервал фоновой задачи, удаляющей просроченные записи о кандидатах BE, в секундах.
  • Значение по умолчанию: 3600

peer_fetch_queue_timeout_ms​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Максимальное время ожидания запроса чтения с другого BE в очереди обработки на обслуживающей стороне, в миллисекундах. Запросы, ожидающие дольше, отклоняются, чтобы запрашивающий BE мог быстро обратиться к объектному хранилищу.
  • Значение по умолчанию: 100

brpc_peer_fetch_pool_threads​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Размер пула потоков, обрабатывающего запросы чтения от других BE на обслуживающей стороне. Он изолирован от пула потоков ресурсоемких RPC, например загрузок. Значение -1 означает max(64, 2 × CPU cores). Не поддерживает динамическое изменение.
  • Значение по умолчанию: -1

brpc_peer_fetch_pool_max_queue_size​

  • Тип: int32
  • Описание: Добавлен в версии 4.2.0. Длина очереди пула потоков чтения от других BE на обслуживающей стороне. Значение -1 означает max(4096, 128 × CPU cores). Не поддерживает динамическое изменение.
  • Значение по умолчанию: -1

min_peer_race_s3_thread_num / max_peer_race_s3_thread_num​

  • Тип: int32
  • Описание: Добавлены в версии 4.2.0. Минимальное / максимальное количество потоков в пуле, выполняющем чтение из объектного хранилища на запрашивающей стороне при параллельном чтении с другого BE и из объектного хранилища. Не поддерживают динамическое изменение.
  • Значение по умолчанию: 0 / 32

s3_get_requests_per_second_per_core / s3_put_requests_per_second_per_core​

  • Тип: int64
  • Описание: Добавлены в версии 4.1.4. Ограничение QPS для запросов GET / PUT к объектному хранилищу в расчете на ядро CPU. Отрицательное значение отключает этот режим и возвращает к прежней конфигурации с абсолютным количеством токенов; 0 означает отсутствие ограничения QPS.
  • Значение по умолчанию: -1

s3_get_requests_per_second_max / s3_put_requests_per_second_max​

  • Тип: int64
  • Описание: Добавлены в версии 4.1.4. Жесткий верхний предел QPS для GET / PUT, рассчитанного по количеству ядер CPU. Значение меньше или равное 0 означает отсутствие верхнего предела.
  • Значение по умолчанию: 0

s3_get_bytes_per_second_per_core / s3_put_bytes_per_second_per_core​

  • Тип: int64
  • Описание: Добавлены в версии 4.1.4. Ограничение пропускной способности GET / PUT для объектного хранилища в расчете на ядро CPU (байт в секунду на ядро). Значение меньше или равное 0 означает отсутствие ограничения пропускной способности.
  • Значение по умолчанию: -1

s3_get_bytes_per_second_max / s3_put_bytes_per_second_max​

  • Тип: int64
  • Описание: Добавлены в версии 4.1.4. Жесткий верхний предел пропускной способности GET / PUT в байтах в секунду, рассчитанной по количеству ядер CPU. Значение меньше или равное 0 означает отсутствие верхнего предела.
  • Значение по умолчанию: 0

s3_rate_limiter_cpu_cores_override​

  • Тип: int32
  • Описание: Добавлен в версии 4.1.4. Количество ядер CPU, используемое для расчета приведенных выше ограничений частоты и пропускной способности. Значение меньше или равное 0 означает автоматическое определение количества ядер машины.
  • Значение по умолчанию: 0

s3_rate_limiter_log_interval​

  • Тип: int64
  • Описание: Добавлен в версии 4.1.4. Минимальный интервал в миллисекундах между записями в журнале при срабатывании ограничения частоты или пропускной способности объектного хранилища.
  • Значение по умолчанию: 1000

file_cache_mem_storage_shard_num​

  • Тип: int32
  • Описание: Добавлен в версии 4.1.4. Количество шардов хранилища файлового кеша в памяти. Используется для уменьшения конкуренции за блокировки при одновременном доступе.
  • Значение по умолчанию: 1024

time_series_max_tablet_version_num​

  • Тип: int
  • Описание: Ограничивает количество версий одного tablet при политике компактизации временных рядов. Предотвращает накопление большого количества версий из-за слишком частой загрузки или несвоевременной компактизации. При превышении предела задача загрузки отклоняется.
  • Значение по умолчанию: 20000
