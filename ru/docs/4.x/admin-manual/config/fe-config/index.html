Конфигурация FE

В этом документе описаны параметры конфигурации FE.

Файл конфигурации FE fe.conf обычно находится в каталоге conf/ в директории развёртывания FE. В версии 0.14 появится ещё один файл конфигурации — fe_custom.conf. Он предназначен для хранения параметров, которые пользователь динамически настраивает и сохраняет во время работы.

После запуска процесс FE сначала считывает параметры из fe.conf, а затем из fe_custom.conf. Параметры из fe_custom.conf переопределяют одноимённые параметры из fe.conf.

Расположение файла fe_custom.conf можно задать в fe.conf с помощью параметра custom_config_dir.

Просмотр параметров конфигурации​

Просмотреть параметры конфигурации FE можно двумя способами:

  1. Веб-страница FE

    Откройте в браузере веб-страницу FE http://fe_host:fe_http_port/variable. Текущие действующие параметры конфигурации FE отображаются в разделе Configure Info.

  2. Просмотр с помощью команды

    После запуска FE можно просмотреть параметры его конфигурации в клиенте MySQL с помощью следующей команды. Подробное описание синтаксиса приведено в разделе SHOW-CONFIG:

    SHOW FRONTEND CONFIG;

    Столбцы результата имеют следующие значения:

    • Key: имя параметра конфигурации.
    • Value: текущее значение параметра конфигурации.
    • Type: тип значения параметра конфигурации, например целое число или строка.
    • IsMutable: возможность динамической настройки. Если значение равно true, параметр можно динамически настраивать во время работы. Если false, параметр можно задать только в fe.conf, и он вступит в силу после перезапуска FE.
    • MasterOnly: является ли параметр специфичным для узла Master FE. Значение true означает, что параметр имеет смысл только на узле Master FE и не имеет смысла на узлах FE других типов. Значение false означает, что параметр имеет смысл на узлах FE всех типов.
    • Comment: описание параметра конфигурации.

Настройка параметров конфигурации​

Начиная с версии 4.1.5, SHOW FRONTEND CONFIG и конечные точки экспорта конфигурации маскируют непустые конфиденциальные значения как ********. Это относится в том числе к initial_root_password, паролям закрытых ключей TLS, паролям HTTPS Key Store и паролям сертификатов MySQL SSL. Пустые значения остаются пустыми, показывая, что они не заданы. Маскирование не изменяет действующую конфигурацию.

Настроить параметры конфигурации FE можно двумя способами:

  1. Статическая настройка

    Добавьте параметры конфигурации и задайте их значения в файле conf/fe.conf. Параметры из fe.conf считываются при запуске процесса FE. Для параметров, отсутствующих в fe.conf, используются значения по умолчанию.

  2. Динамическая настройка по протоколу MySQL

    После запуска FE можно динамически задавать параметры конфигурации с помощью следующих команд. Для выполнения этой команды требуются права администратора.

    ADMIN SET FRONTEND CONFIG (" fe_config_name "=" fe_config_value ");

    Не все параметры поддерживают динамическую настройку. Проверить её поддержку можно по столбцу IsMutable в результате команды SHOW FRONTEND CONFIG;.

    При изменении параметра с признаком MasterOnly команда напрямую перенаправляется на Master FE, и изменяется только соответствующий параметр на Master FE.

    Изменения параметров, внесённые этим способом, перестают действовать после перезапуска процесса FE.

    Дополнительную справку по этой команде можно получить с помощью команды HELP ADMIN SET CONFIG;.

  3. Динамическая настройка по протоколу HTTP

    Подробности см. в разделе Действие Set Config.

    Этот способ также позволяет сохранять изменённые параметры конфигурации. Они записываются в файл fe_custom.conf и продолжают действовать после перезапуска FE.

Примеры​

  1. Изменение async_pending_load_task_pool_size

    С помощью SHOW FRONTEND CONFIG; можно увидеть, что этот параметр не поддерживает динамическую настройку (IsMutable имеет значение false). Необходимо добавить в fe.conf:

    async_pending_load_task_pool_size = 20

    Затем перезапустите процесс FE, чтобы настройка вступила в силу.

  2. Изменение dynamic_partition_enable

    С помощью SHOW FRONTEND CONFIG; можно увидеть, что этот параметр поддерживает динамическую настройку (IsMutable имеет значение true). Кроме того, он специфичен для Master FE. Для изменения конфигурации сначала подключитесь к любому FE и выполните следующую команду:

    ADMIN SET FRONTEND CONFIG ("dynamic_partition_enable" = "true"); `

    Затем можно просмотреть изменённое значение с помощью следующих команд:

    set forward_to_master = true;
    SHOW FRONTEND CONFIG;

    После изменения указанным способом настройка перестанет действовать при перезапуске Master FE или выборах нового Master. Чтобы сохранить параметр постоянно, добавьте его непосредственно в fe.conf и перезапустите FE.

  3. Изменение max_distribution_pruner_recursion_depth

    С помощью SHOW FRONTEND CONFIG; можно увидеть, что этот параметр поддерживает динамическую настройку (IsMutable имеет значение true). Он не является специфичным для Master FE.

    Аналогичным образом конфигурацию можно изменить командой динамической настройки. Поскольку этот параметр не является специфичным для Master FE, для его динамического изменения необходимо отдельно подключиться к каждому FE, чтобы все FE использовали изменённые значения.

Параметры конфигурации​

Метаданные и кластер​

meta_dir​

По умолчанию：DORIS_HOME_DIR + "/doris-meta"

Тип: string. Описание: здесь сохраняются метаданные Doris. Для хранения этого каталога настоятельно рекомендуется использовать накопители со следующими характеристиками:

  • Высокая производительность записи (SSD)
  • Надёжность (RAID）

catalog_try_lock_timeout_ms​

По умолчанию：5000 （ms）

IsMutable：true

Тайм-аут tryLock для блокировки Catalog. Обычно менять его не требуется, кроме случаев, когда нужно что-либо протестировать.

enable_bdbje_debug_mode​

По умолчанию：false

При значении true FE запускается в режиме отладки BDBJE.

max_bdbje_clock_delta_ms​

По умолчанию：5000 （5s）

Максимально допустимое расхождение часов между хостом FE, не являющегося Master, и хостом Master FE. Это значение проверяется каждый раз, когда FE, не являющийся Master, устанавливает соединение с Master FE через BDBJE. Если расхождение часов превышает это значение, соединение разрывается.

metadata_failure_recovery​

По умолчанию：false

При значении true FE сбрасывает группу репликации bdbje, то есть удаляет сведения обо всех узлах, участвующих в выборах, и должен запуститься как Master. Если ни один из узлов, участвующих в выборах, не может запуститься, можно скопировать метаданные на другой узел и установить для этого параметра значение true, чтобы попытаться перезапустить FE.

txn_rollback_limit​

По умолчанию：100

Максимальное число транзакций, которые bdbje может откатить при попытке повторно присоединиться к группе.

grpc_threadmgr_threads_nums​

По умолчанию: 4096

Число потоков для обработки событий grpc в grpc_threadmgr.

bdbje_replica_ack_timeout_second​

По умолчанию：10 (s)

Тайм-аут подтверждения реплики при записи в bdbje. При записи относительно больших журналов время ожидания подтверждения может истечь, что приводит к сбою записи журнала. В таком случае можно увеличить это значение.

bdbje_lock_timeout_second​

По умолчанию：5

Тайм-аут блокировки для операций bdbje. Если в журнале FE уровня WARN часто встречается LockTimeoutException, попробуйте увеличить это значение.

bdbje_heartbeat_timeout_second​

По умолчанию：30

Тайм-аут heartbeat bdbje между Master и Follower. По умолчанию составляет 30 секунд, что совпадает со значением по умолчанию в bdbje. При кратковременных сетевых проблемах или неожиданно длительных паузах Java GC можно увеличить это значение, чтобы снизить вероятность ложных тайм-аутов.

replica_ack_policy​

По умолчанию：SIMPLE_MAJORITY

Варианты: ALL, NONE, SIMPLE_MAJORITY

Политика подтверждения реплик bdbje. Подробнее см.: http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.ReplicaAckPolicy.html

replica_sync_policy​

По умолчанию：SYNC

Варианты：SYNC, NO_SYNC, WRITE_NO_SYNC

Политика синхронизации bdbje для Follower FE.

master_sync_policy​

По умолчанию：SYNC

Варианты：SYNC, NO_SYNC, WRITE_NO_SYNC

Политика синхронизации bdbje для Master FE. Если развёрнут только один Follower FE, установите значение 'SYNC'. Если развёрнуто более 3 Follower FE, для этого параметра и параметра 'replica_sync_policy' можно установить WRITE_NO_SYNC. Подробнее см.: http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.SyncPolicy.html

bdbje_reserved_disk_bytes​

Желаемый верхний предел объёма зарезервированного пространства, сохраняемого в реплицируемой среде JE, в байтах.

По умолчанию: 1073741824

Динамическая настройка: false

Только для узла Master FE: false

ignore_meta_check​

По умолчанию：false

IsMutable：true

При значении true FE, не являющийся Master, игнорирует отставание своих метаданных от Master FE, даже если оно превышает meta_delay_toleration_second. Такой FE продолжает обслуживать запросы на чтение. Это полезно, если по какой-либо причине нужно остановить Master FE на относительно длительное время, сохранив возможность чтения через остальные FE.

meta_delay_toleration_second​

По умолчанию: 300 (5 мин)

FE, не являющийся Master, прекращает обслуживание, если отставание метаданных превышает meta_delay_toleration_second.

edit_log_port​

По умолчанию：9010

Порт bdbje.

edit_log_type​

По умолчанию：BDB

Тип журнала изменений. BDB: запись журнала в bdbje. LOCAL: устарел.

edit_log_roll_num​

По умолчанию：50000

IsMutable：true

MasterOnly：true

Master FE сохраняет образ после каждых edit_log_roll_num записей журнала метаданных.

force_do_metadata_checkpoint​

По умолчанию：false

IsMutable：true

MasterOnly：true

При значении true поток создания контрольных точек создаёт контрольную точку независимо от процента использования памяти JVM.

metadata_checkpoint_memory_threshold​

По умолчанию：60 （60%）

IsMutable：true

MasterOnly：true

Если процент использования памяти JVM (heap или old mem pool) превышает этот порог, поток создания контрольных точек не выполняет работу, чтобы избежать OOM.

max_same_name_catalog_trash_num​

Задаёт максимальное число одноимённых объектов метаданных в корзине Catalog. При превышении этого значения самый ранее удалённый объект метаданных удаляется окончательно и не подлежит восстановлению. 0 означает, что одноимённые объекты не сохраняются. < 0 означает отсутствие ограничения.

Примечание: одноимённость метаданных проверяется в определённых пределах. Например, базы данных с одинаковыми именами учитываются в пределах одного кластера, таблицы с одинаковыми именами — в пределах одной базы данных (с одинаковым идентификатором базы данных), а секции с одинаковыми именами — в пределах одной базы данных (с одинаковым идентификатором базы данных) и одной таблицы (с одинаковым идентификатором таблицы).

По умолчанию: 3

Динамическая настройка: true

Только для узла Master FE: true

cluster_id​

По умолчанию：-1

Узлы (FE или BE) считаются принадлежащими одному кластеру Doris, если у них одинаковый идентификатор кластера. Обычно это случайное целое число, генерируемое при первом запуске Master FE. Его также можно задать вручную.

heartbeat_mgr_blocking_queue_size​

По умолчанию：1024

MasterOnly：true

Размер блокирующей очереди для хранения задач heartbeat в heartbeat_mgr.

heartbeat_mgr_threads_num​

По умолчанию：8

MasterOnly：true

Число потоков для обработки событий heartbeat в heartbeat_mgr.

disable_cluster_feature​

По умолчанию：true

IsMutable：true

Функция нескольких кластеров будет объявлена устаревшей в версии 0.12. Установка этого параметра в true отключает все связанные с ней операции, включая:

  1. Создание и удаление кластера.
  2. Добавление свободного Backend, добавление Backend в кластер, вывод узлов кластера из эксплуатации и балансировку.
  3. Изменение числа Backend в кластере.
  4. Связывание и миграцию баз данных.

enable_fqdn_mode​

Этот параметр в основном используется в среде кластера k8s. Если enable_fqdn_mode имеет значение true, имя pod, в котором находится BE, остаётся прежним после пересоздания, а IP-адрес может измениться.

По умолчанию: false

Динамическая настройка: false

Только для узла Master FE: true

enable_token_check​

По умолчанию：true

Параметр для совместимости с будущими версиями; позднее будет удалён. Включает проверку токена при скачивании файла образа.

fe_meta_auth_token​

По умолчанию: "" (пустая строка)

IsMutable: false

Токен кластера для аутентификации обращений между узлами FE к HTTP-конечным точкам службы метаданных FE (image, role, check, put, journal_id и т. д.). Добавлен в версии 4.0.8 линейки Doris 4.0 и в версии 4.1.4 линейки 4.1.

Если задано непустое значение, эти конечные точки в дополнение к существующей проверке хоста узла требуют от вызывающей стороны заголовок с совпадающим токеном. Это не позволяет узлам, не входящим в кластер, обращаться к конечным точкам метаданных FE. Пустое значение сохраняет прежнее поведение с проверкой только хоста узла, поэтому существующие кластеры и последовательные обновления не затрагиваются.

Примечание

Эта настройка должна быть одинаковой на всех FE и должна быть записана в fe.conf перед включением. Иначе FE будут отклонять запросы метаданных друг друга, и синхронизация метаданных завершится с ошибкой.

enable_multi_tags​

По умолчанию: false

Динамическая настройка: false

Только для узла Master FE: true

Включает поддержку нескольких тегов для одного BE.

initial_root_password​

Задаёт начальный пароль пользователя root, зашифрованный с помощью 2-этапного SHA-1. Значение по умолчанию — '', что означает отсутствие пароля root. Последующие операции set password для пользователя root переопределяют начальный пароль root.

Пример: если нужно задать пароль в открытом виде root@123, можно выполнить SQL-команду Doris select password('root@123'), чтобы получить зашифрованный пароль *A00C34073A26B40AB4307650BFB9309D6BFA6999.

По умолчанию: пустая строка

Динамическая настройка: false

Только для узла Master FE: true

enable_cooldown_replica_affinity​

Позволяет выбрать, следует ли в первую очередь использовать для сканирования реплику, перенесённую в холодное хранилище. По умолчанию включено.

По умолчанию: true

Динамическая настройка: true

Только для узла Master FE: false

Службы​

arrow_flight_deferred_query_idle_timeout_second​

По умолчанию: 3600 (секунд)

Динамическая настройка: true

Только для узла Master FE: false

Поддерживается с версии 4.1.5. Запрос Arrow Flight SQL, который сканирует внешние таблицы пакетами, должен сохранять свой FE Coordinator после возврата GetFlightInfo, чтобы BE могли продолжать получать части данных, когда клиент читает результаты через DoGet. Эта настройка ограничивает время, в течение которого такой запрос удерживает ресурсы в неактивном сеансе. Отсчёт начинается при запуске запроса, а период никогда не бывает короче тайм-аута выполнения запроса. По истечении срока освобождаются Coordinator, слот очереди Workload Group и запись active_queries, но сеанс остаётся открытым и по-прежнему регулируется wait_timeout. Установите 0, чтобы отключить это ограничение времени.

query_port​

По умолчанию：9030

Порт сервера MySQL на FE.

arrow_flight_sql_port​

По умолчанию：-1

Порт сервера Arrow Flight SQL.

frontend_address​

Статус: устарел, использование не рекомендуется. В дальнейшем параметр может быть удалён.

Тип: string

Описание: позволяет явно задать IP-адрес FE вместо его получения с помощью InetAddress.getByName. Обычно используется, когда InetAddress.getByName не даёт ожидаемого результата. Поддерживается только IP-адрес, имя хоста не поддерживается.

Значение по умолчанию: 0.0.0.0

drop_backend_after_decommission​

По умолчанию：false

IsMutable：true

MasterOnly：true

  1. Этот параметр определяет, удаляет ли система BE после его успешного вывода из эксплуатации. При значении true узел BE удаляется после успешного вывода из эксплуатации. При значении false BE остаётся в состоянии DECOMMISSION, но не удаляется.

    Эта настройка полезна в некоторых сценариях. Предположим, что изначально в кластере Doris у каждого узла BE был один диск. Через некоторое время система была вертикально масштабирована: на каждый узел BE добавили 2 новых диска. Поскольку Doris в настоящее время не поддерживает балансировку данных между дисками внутри BE, объём данных на исходном диске может постоянно оставаться значительно больше, чем на новых дисках. В этом случае можно вручную сбалансировать данные между дисками следующим образом:

    1. Установите для параметра значение false.
    2. Выполните вывод из эксплуатации определённого узла BE. Эта операция перенесёт все данные с BE на другие узлы.
    3. После завершения вывода из эксплуатации BE не будет удалён. Отмените состояние вывода из эксплуатации для этого BE. После этого данные начнут перераспределяться с других узлов BE обратно на этот узел и будут равномерно распределены по всем его дискам.
    4. Последовательно выполните шаги 2 и 3 для всех узлов BE, чтобы сбалансировать данные на дисках всех узлов.

jetty_server_acceptors​

По умолчанию：2

jetty_server_selectors​

По умолчанию：4

jetty_server_workers​

По умолчанию：0

Эти три параметра задают простую модель потоков Jetty, состоящую из трёх пулов: acceptors, selectors и workers. Потоки acceptors принимают новые соединения и передают их потокам selectors для разбора HTTP-сообщений, после чего потоки workers обрабатывают запросы. Первые два пула используют неблокирующую модель: один поток может обслуживать чтение и запись множества сокетов, поэтому число потоков в этих пулах невелико.

Для большинства проектов достаточно 1-2 потоков acceptors и от 2 до 4 потоков selectors. Потоки workers выполняют блокирующую бизнес-логику, часто с большим числом операций с базой данных, поэтому их требуется больше. Конкретное число зависит от QPS и доли операций ввода-вывода в приложении. Чем выше QPS, тем больше нужно потоков; чем выше доля ввода-вывода, тем больше потоков ожидает его завершения и тем больше потоков требуется в целом.

По умолчанию размер пула workers не задан; настройте его по потребности.

be_exec_version​

Определяет формат сериализации блоков, передаваемых между фрагментами.

Иногда изменения кода меняют формат данных блока. Чтобы BE оставались совместимыми друг с другом при последовательном обновлении, FE должен передавать версию данных, определяющую формат их отправки.

Например, в кластере есть 2 BE. Один из них после обновления поддерживает последнюю версию v1v_1v1​, а другой — только v0v_0v0​. Поскольку FE ещё не обновлён, всем передаётся v0.v_0. v0​., и BE обмениваются данными в старом формате. После обновления всех BE обновляется FE. Новый FE передаёт v1v_1v1​, и весь кластер переходит на новый формат данных.

Значение по умолчанию — max_be_exec_version. При особых требованиях можно вручную задать более раннюю версию формата, но она не должна быть ниже min_be_exec_version.

Значение этой переменной всегда должно находиться между BeExecVersionManager::min_be_exec_version и BeExecVersionManager::max_be_exec_version для всех BE. Иными словами, если полностью обновлённый кластер нужно понизить до более ранней версии, сначала следует понизить версию FE, а затем BE, либо вручную уменьшить значение переменной в настройках и затем понизить версию BE.

Механизм одинаково применяется ко всем способам загрузки.

enable_group_commit_streamload_be_forward​

По умолчанию: false

IsMutable: true

Включает перенаправление Stream Load через BE для Group Commit в режиме разделения вычислений и хранения. Действует только в этом режиме и только для запросов, использующих Group Commit.

При включении FE перенаправляет запрос Stream Load на конечную точку _stream_load_forward, а принимающий BE пересылает запрос на целевой BE для этой таблицы. Это предотвращает распределение запросов одной таблицы балансировщиком нагрузки между разными пакетами Group Commit.

Одноимённый параметр должен быть включён и на FE, и на BE. Начиная с версии 4.0.8 линейки Doris 4.0 и версии 4.1.4 линейки 4.1, доступ к конечной точке _stream_load_forward на стороне BE регулируется конфигурацией BE: если она отключена, возвращается 403 Forbidden, а после включения запросы должны проходить аутентификацию и иметь глобальное право LOAD. См. Group Commit и Конфигурация BE.

По умолчанию: true (false до 4.1.5)

Динамическая настройка: true

Добавлен в версии 4.1.4. Включает оценку ограничения QPS для RPC от FE к Meta Service. Начиная с версии 4.1.5 включён по умолчанию вместе с meta_service_rpc_rate_limit_dry_run, поэтому по умолчанию только записываются расчётные ожидания и отклонения, а сами запросы не задерживаются и не отклоняются. Чтобы применять ограничение частоты, оставьте для этого параметра true и установите dry-run в false.

meta_service_rpc_rate_limit_dry_run​

По умолчанию: true

Динамическая настройка: true

Только для узла Master FE: false

Поддерживается с версии 4.1.5. Действует только при meta_service_rpc_rate_limit_enabled=true. При значении true оценивает ограничение частоты и записывает метрики, не заставляя запросы ждать и не отклоняя их. При значении false применяет настроенные QPS, окно всплеска и тайм-аут ожидания. Метрики ожидания в режиме dry-run отражают расчётное время ожидания.

По умолчанию: 50

Динамическая настройка: true

Добавлен в версии 4.1.4. Допустимый QPS на одно ядро CPU по умолчанию для методов RPC Meta Service, которые не настроены отдельно в meta_service_rpc_rate_limit_qps_per_core_config. Значение меньше или равно 0 означает отсутствие ограничения частоты.

По умолчанию: getPartitionVersion:500;getTableVersion:500;getTabletStats:50;beginTxn:50

Динамическая настройка: true

meta_service_rpc_rate_limit_burst_seconds​

По умолчанию: 2 (s)

Динамическая настройка: true

Добавлен в версии 4.1.4. Длительность окна всплеска для ограничения частоты RPC Meta Service, в секундах. Долгосрочный средний QPS не меняется, но в пределах этого окна разрешены всплески нагрузки.

meta_service_rpc_rate_limit_wait_timeout_ms​

По умолчанию: 1000 (ms)

Динамическая настройка: true

Добавлен в версии 4.1.4. Максимальное время ожидания при срабатывании ограничения частоты RPC, в миллисекундах. Значение 0 означает отсутствие ожидания, поэтому запрос сразу завершается с ошибкой.
