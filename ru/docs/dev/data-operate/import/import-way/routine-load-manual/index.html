Routine Load

Routine Load — это предоставляемое Apache Doris задание потоковой загрузки, которое непрерывно получает данные из топика Kafka и записывает их в таблицу Doris. После отправки задания Routine Load Doris поддерживает его непрерывную работу, в реальном времени создаёт задачи загрузки для получения сообщений из указанного топика кластера Kafka и обеспечивает семантику Exactly-Once, гарантирующую отсутствие потерь и дублирования данных.

Сценарии использования​

Routine Load подходит для следующих сценариев:

  • Непрерывная синхронизация данных из топика Kafka в Doris в реальном времени.
  • Обеспечение семантики Exactly-Once для предотвращения потерь и дублирования данных.
  • Сопоставление столбцов, фильтрация, вычисление производных столбцов и другие преобразования загружаемых данных.
  • Динамическое распределение данных из одного топика Kafka по нескольким таблицам Doris (один поток, несколько таблиц).

Поддерживаемые источники и форматы данных​

Routine Load поддерживает получение данных только из кластера Kafka и следующие два формата сообщений:

ФорматОписание
CSVКаждое сообщение представляет собой одну строку, в конце которой нет символа перевода строки.
JSONОдин объект JSON или массив JSON, содержащий несколько объектов.

При загрузке данных в формате CSV важно различать значения NULL и пустые строки:

  • Значение NULL обозначается как \n. Например, a,\n,b означает, что средний столбец содержит значение NULL.
  • Пустая строка задаётся отсутствием данных между разделителями. Например, a,,b означает, что средний столбец содержит пустую строку ('').

Ограничения​

При использовании Routine Load для получения данных из Kafka действуют следующие ограничения:

ОграничениеОписание
Формат сообщенийПоддерживаются только текстовые форматы CSV и JSON. Каждое сообщение CSV представляет собой одну строку, в конце которой нет символа перевода строки.
Версия KafkaПо умолчанию поддерживается Kafka 0.10.0.0 и выше. Чтобы использовать версию Kafka ниже 0.10.0.0 (0.9.0, 0.8.2, 0.8.1, 0.8.0), укажите нужную старую версию в параметре конфигурации BE kafka_broker_version_fallback или задайте property.broker.version.fallback непосредственно при создании задания. При использовании старой версии некоторые новые возможности Routine Load могут быть недоступны, например задание смещений партиций Kafka по времени.

Основные принципы​

Routine Load непрерывно получает данные из топика Kafka и записывает их в Doris. После создания задания Routine Load в Doris формируется длительно выполняющееся задание загрузки, которое содержит несколько задач загрузки:

  • Load Job: задание Routine Load — это длительно выполняющееся задание загрузки, которое непрерывно получает данные из источника.
  • Load Task: для фактического получения данных задание загрузки разделяется на несколько задач. Каждая задача представляет собой независимую транзакцию.

Подробная схема работы Routine Load показана на следующем рисунке:

Общий процесс выглядит следующим образом:

  1. Клиент отправляет в FE запрос на создание задания Routine Load. FE через Routine Load Manager создаёт длительно выполняющееся задание загрузки (Routine Load Job).
  2. FE через Job Scheduler разделяет Routine Load Job на несколько задач Routine Load Task. Затем Task Scheduler распределяет их по узлам BE.
  3. После завершения загрузки на BE задача Routine Load Task фиксирует транзакцию в FE и обновляет метаданные задания.
  4. После фиксации Routine Load Task создаются новые задачи или повторно запускаются задачи с истёкшим временем ожидания.
  5. Task Scheduler непрерывно планирует выполнение вновь созданных задач Routine Load Task.

Механизм автоматического восстановления​

Для обеспечения высокой доступности заданий в Routine Load предусмотрен механизм автоматического восстановления. Если задание неожиданно приостанавливается, поток Routine Load Scheduler пытается автоматически восстановить его работу. При неожиданных сбоях на стороне Kafka и других ситуациях, препятствующих работе, этот механизм позволяет заданию загрузки продолжить нормальную работу после восстановления Kafka без вмешательства пользователя.

В следующей таблице указано, в каких случаях восстановление происходит автоматически, а в каких требуется вмешательство пользователя:

Причина приостановкиАвтоматическое восстановлениеРекомендуемое действие
Временная недоступность брокера Kafka, нестабильность сетиДаScheduler автоматически повторяет попытки с интервалом period_of_auto_resume_min.
Пользователь вручную выполняет PAUSE ROUTINE LOADНетВручную выполните RESUME ROUTINE LOAD.
Проблема с качеством данных (превышен max_filter_ratio или max_error_number)НетИзучите ErrorLogUrls, скорректируйте данные или параметры, затем выполните RESUME.
Неустранимые ошибки метаданных, например удаление базы данных или таблицыНетЗаново создайте таблицу или задание.

Быстрый старт​

В этом разделе приведён минимальный рабочий пример создания задания Routine Load для Kafka, а также основные операции просмотра, приостановки, возобновления, изменения и остановки задания.

Создание задания загрузки​

Создать длительно выполняющееся задание загрузки Routine Load можно с помощью команды CREATE ROUTINE LOAD. Routine Load может получать данные в форматах CSV и JSON.

Загрузка данных CSV​

  1. Подготовьте пример данных в Kafka:

    kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test-routine-load-csv --from-beginning
    1,Emily,25
    2,Benjamin,35
    3,Olivia,28
    4,Alexander,60
    5,Ava,17
    6,William,69
    7,Sophia,32
    8,James,64
    9,Emma,37
    10,Liam,64

  2. Создайте целевую таблицу для загрузки:

    CREATE TABLE testdb.test_routineload_tbl(
        user_id            BIGINT       NOT NULL COMMENT "user id",
        name               VARCHAR(20)           COMMENT "name",
        age                INT                   COMMENT "age"
    )
    DUPLICATE KEY(user_id)
    DISTRIBUTED BY HASH(user_id) BUCKETS 10;

  3. Создайте задание загрузки Routine Load:

    CREATE ROUTINE LOAD testdb.example_routine_load_csv ON test_routineload_tbl
    COLUMNS TERMINATED BY ",",
    COLUMNS(user_id, name, age)
    FROM KAFKA(
        "kafka_broker_list" = "192.168.88.62:9092",
        "kafka_topic" = "test-routine-load-csv",
        "property.kafka_default_offsets" = "OFFSET_BEGINNING"
    );

Загрузка данных JSON​

  1. Подготовьте пример данных в Kafka:

    kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test-routine-load-json --from-beginning

    {"user_id":2,"name":"Benjamin","age":35}

    {"user_id":4,"name":"Alexander","age":60}
    {"user_id":5,"name":"Ava","age":17}
    {"user_id":6,"name":"William","age":69}
    {"user_id":7,"name":"Sophia","age":32}
    {"user_id":8,"name":"James","age":64}
    {"user_id":9,"name":"Emma","age":37}
    {"user_id":10,"name":"Liam","age":64}

  2. Создайте целевую таблицу для загрузки:

    CREATE TABLE testdb.test_routineload_tbl(
        user_id            BIGINT       NOT NULL COMMENT "user id",
        name               VARCHAR(20)           COMMENT "name",
        age                INT                   COMMENT "age"
    )
    DUPLICATE KEY(user_id)
    DISTRIBUTED BY HASH(user_id) BUCKETS 10;

  3. Создайте задание загрузки Routine Load:

    CREATE ROUTINE LOAD testdb.example_routine_load_json ON test_routineload_tbl
    COLUMNS(user_id,name,age)
    PROPERTIES(
        "format"="json",
        "jsonpaths"="[\"$.user_id\",\"$.name\",\"$.age\"]"

    FROM KAFKA(

        "kafka_topic" = "test-routine-load-json",
        "property.kafka_default_offsets" = "OFFSET_BEGINNING"
    );
Примечание

Чтобы загрузить объект JSON из корня файла JSON, задайте для jsonpaths значение $., например: PROPERTIES("jsonpaths"="$.").

Приостановка задания загрузки​

Приостановить задание загрузки можно с помощью команды PAUSE ROUTINE LOAD. После приостановки задание переходит в состояние PAUSED, но не завершается. Возобновить его можно командой RESUME ROUTINE LOAD.

PAUSE ROUTINE LOAD FOR testdb.example_routine_load_csv;

Возобновление задания загрузки​

Возобновить задание загрузки в состоянии PAUSED можно с помощью команды RESUME ROUTINE LOAD.

RESUME ROUTINE LOAD FOR testdb.example_routine_load_csv;

Изменение задания загрузки​

Изменить созданное задание загрузки можно с помощью команды ALTER ROUTINE LOAD. Перед изменением приостановите задание командой PAUSE ROUTINE LOAD. После завершения изменений возобновите его командой RESUME ROUTINE LOAD.

Например, чтобы изменить параметр желаемого параллелизма desired_concurrent_number и сведения о топике Kafka:

ALTER ROUTINE LOAD FOR testdb.example_routine_load_csv
PROPERTIES(
    "desired_concurrent_number" = "3"
)
FROM KAFKA(
    "kafka_broker_list" = "192.168.88.60:9092",
    "kafka_topic" = "test-topic"
);

Отмена задания загрузки​

Остановить и удалить задание загрузки Routine Load можно с помощью команды STOP ROUTINE LOAD. Удалённое задание загрузки невозможно восстановить, и оно недоступно для просмотра командой SHOW ROUTINE LOAD.

STOP ROUTINE LOAD FOR testdb.example_routine_load_csv;

Привязка Compute Group​

В режиме разделения хранения и вычислений выбор Compute Group для Routine Load выполняется в следующем порядке приоритета:

  1. Выбирается Compute Group, указанная в операторе use db@cluster.
  2. Выбирается Compute Group, указанная в свойстве пользователя default_compute_group.
  3. Выбирается одна Compute Group из тех, к которым у текущего пользователя есть доступ.

В режиме совместного хранения и вычислений выбирается Compute Group, указанная в свойстве пользователя resource_tags.location. Если в свойствах пользователя Compute Group не задана, используется Compute Group с именем default.

Примечание

Compute Group для задания Routine Load можно указать только при его создании. После создания задания изменить привязанную Compute Group нельзя.

Справочное руководство​

Синтаксис команды загрузки​

Синтаксис создания длительно выполняющегося задания загрузки Routine Load:

CREATE ROUTINE LOAD [<db_name>.]<job_name> [ON <tbl_name>]
[merge_type]
[load_properties]
[job_properties]
FROM KAFKA [data_source_properties]
[COMMENT "<comment>"]

Описание модулей:

МодульОписание
db_nameУказывает базу данных, в которой создаётся задача загрузки.
job_nameУказывает имя создаваемой задачи загрузки. В одной базе данных не может быть задач с одинаковым именем.
tbl_nameУказывает имя таблицы, в которую загружаются данные. Необязательный параметр. Если он не задан, используется динамический выбор таблицы, при котором данные в Kafka должны содержать имя таблицы.
merge_typeТип слияния данных. Значение по умолчанию — APPEND.

Доступны три варианта:

- APPEND: загрузка с добавлением.

- MERGE: загрузка со слиянием.

- DELETE: все загружаемые данные подлежат удалению.

load_propertiesМодуль описания загрузки, включающий следующие компоненты:

- предложение column_separator

- предложение columns_mapping

- предложение preceding_filter

- предложение where_predicates

- предложение partitions

- предложение delete_on

- предложение order_by

job_propertiesЗадаёт общие параметры загрузки Routine Load.
data_source_propertiesОписывает свойства источника данных Kafka.
commentЗадаёт комментарий к заданию загрузки.

Параметры конфигурации загрузки​

При создании задания Routine Load с помощью команды CREATE ROUTINE LOAD можно указать параметры конфигурации загрузки для различных модулей.

Предложение tbl_name​

Указывает имя таблицы для загрузки. Необязательный параметр.

Если параметр не задан, используется динамический выбор таблицы, при котором данные в Kafka должны содержать имя таблицы. В настоящее время динамическое имя таблицы можно извлечь только из Kafka Value, и данные должны соответствовать следующему формату. Для JSON: table_name|{"col1": "val1", "col2": "val2"}, где tbl_name — имя таблицы, а | — разделитель между именем таблицы и её данными. Для CSV используется аналогичный формат, например: table_name|val1,val2,val3.

Примечание

Указанное здесь table_name должно точно совпадать с именем таблицы в Doris, иначе загрузка завершится ошибкой. При динамическом выборе таблицы column_mapping не поддерживается.

Предложение merge_type​

Тип слияния данных можно задать с помощью модуля merge_type. Доступны три варианта:

  • APPEND: загрузка с добавлением.
  • MERGE: загрузка со слиянием. Применима только к модели Unique Key. Необходимо использовать вместе с модулем [DELETE ON] для установки отметки в столбце Delete Flag.
  • DELETE: все загружаемые данные подлежат удалению.
Предложение load_properties​

Свойства загружаемых данных можно описать с помощью модуля load_properties. Синтаксис:

[COLUMNS TERMINATED BY <column_separator>,]
[COLUMNS (<column1_name>[, <column2_name>, <column_mapping>, ...]),]
[WHERE <where_expr>,]
[PARTITION(<partition1_name>, [<partition2_name>, <partition3_name>, ...]),]
[DELETE ON <delete_expr>,]
[ORDER BY <order_by_column1>[, <order_by_column2>, <order_by_column3>, ...]]

Параметры каждого модуля:

ПодмодульПараметрОписание
COLUMNS TERMINATED BY<column_separator>Задаёт разделитель столбцов. По умолчанию — \t. Например, чтобы задать запятую в качестве разделителя: COLUMN TERMINATED BY ",". Особенности обработки NULL:

- Значение NULL обозначается как \n. a,\n,b означает, что средний столбец содержит значение NULL.

- Пустая строка задаётся отсутствием данных между разделителями. a,,b означает, что средний столбец содержит пустую строку ('').

COLUMNS<column_name>Задаёт имя соответствующего столбца. Например, чтобы указать загружаемые столбцы (k1, k2, k3): COLUMNS(k1, k2, k3). Предложение COLUMNS можно опустить в следующих случаях:

- Столбцы CSV взаимно однозначно соответствуют столбцам таблицы.

- Имена ключей JSON совпадают с именами столбцов таблицы.

 <column_mapping>При загрузке можно фильтровать и преобразовывать столбцы с помощью сопоставления столбцов. Например, целевой столбец k4 вычисляется из столбца k3 по формуле k3+1: COLUMNS(k1, k2, k3, k4 = k3 + 1). Подробнее см. в разделе Преобразование данных.
WHERE<where_expr>Фильтрует исходные загружаемые данные по условию. Например, чтобы загрузить только данные с age > 30: WHERE age > 30.
PARTITION<partition_name>Указывает партиции целевой таблицы, в которые нужно загрузить данные. Если не задано, данные автоматически загружаются в соответствующие партиции. Например, для загрузки в партиции p1 и p2: PARTITION(p1, p2).
DELETE ON<delete_expr>В режиме загрузки MERGE используйте delete_expr, чтобы отметить столбцы, подлежащие удалению. Например, чтобы при MERGE удалить столбцы, для которых age > 30: DELETE ON age > 30.
ORDER BY<order_by_column>Действует только для модели Unique Key. Задаёт Sequence Column в загружаемых данных для обеспечения порядка данных. Например, чтобы указать create_time в качестве Sequence Column: ORDER BY create_time. Подробнее см. в разделе Обновление данных / Sequence Column.
Предложение job_properties​

При создании задания загрузки Routine Load его свойства можно задать с помощью предложения job_properties. Синтаксис:

PROPERTIES ("<key1>" = "<value1>"[, "<key2>" = "<value2>" ...])

Доступные параметры предложения job_properties:

ПараметрОписание
desired_concurrent_number

Значение по умолчанию: 256

Желаемый параллелизм для отдельной задачи загрузки. В процессе загрузки желаемое количество параллельных подзадач может отличаться от фактического. Фактический параллелизм вычисляется следующим образом:

min(topic_partition_num, desired_concurrent_number, max_routine_load_task_concurrent_num), где:

- topic_partition_num: количество партиций топика Kafka.

- desired_concurrent_number: значение этого параметра.

- max_routine_load_task_concurrent_num: максимальный параллелизм задач Routine Load, заданный в FE.

max_batch_intervalМаксимальное время выполнения каждой подзадачи в секундах. Должно быть больше 0. Значение по умолчанию — 60. Параметры max_batch_interval, max_batch_rows и max_batch_size совместно задают порог завершения подзадачи. При достижении любого из них подзадача загрузки завершается и создаётся новая.
max_batch_rowsМаксимальное количество строк, которое может прочитать каждая подзадача. Должно быть больше или равно 200000. Значение по умолчанию — 20000000. Параметры max_batch_interval, max_batch_rows и max_batch_size совместно задают порог завершения подзадачи. При достижении любого из них подзадача загрузки завершается и создаётся новая.
max_batch_sizeМаксимальное количество байтов, которое может прочитать каждая подзадача. Значение задаётся в байтах, диапазон — от 100 MB до 1 GB, значение по умолчанию — 1 GB. Параметры max_batch_interval, max_batch_rows и max_batch_size совместно задают порог завершения подзадачи. При достижении любого из них подзадача загрузки завершается и создаётся новая.
max_error_numberМаксимальное количество ошибочных строк, допустимое в окне выборки. Должно быть больше или равно 0. Значение по умолчанию — 0 (ошибочные строки не допускаются). Размер окна выборки — max_batch_rows * 10. Если количество ошибочных строк в окне выборки превышает max_error_number, задание Routine Load приостанавливается. Для проверки проблем с качеством данных требуется вмешательство пользователя. Выявить эти проблемы можно с помощью поля ErrorLogUrls в выводе команды SHOW ROUTINE LOAD. Строки, отфильтрованные условием where, не считаются ошибочными.
strict_modeОпределяет, включён ли строгий режим. По умолчанию отключён. Строгий режим обеспечивает строгую фильтрацию при преобразовании типов столбцов во время загрузки. Если он включён и исходное значение, отличное от NULL, после преобразования типа столбца становится NULL, оно отфильтровывается.

Правила фильтрации:

- Строгий режим не влияет на производные столбцы (созданные преобразованием с помощью функций).

- Если требуется преобразование типа столбца, данные неверного типа отфильтровываются. Их можно просмотреть через ErrorLogUrls в выводе SHOW ROUTINE LOAD.

- Если тип загружаемого столбца имеет ограничения диапазона и исходные данные проходят преобразование типа, но выходят за пределы диапазона, строгий режим на них не влияет. Например, если тип — decimal(1,0), а исходное значение — 10, данные проходят преобразование типа, но не входят в объявленный диапазон столбца. Подробнее см. в разделе Строгий режим.

timezoneЗадаёт часовой пояс задания загрузки. По умолчанию используется параметр часового пояса сеанса. Этот параметр влияет на результаты всех функций, связанных с часовым поясом, которые используются при загрузке.
formatЗадаёт формат загружаемых данных. По умолчанию — CSV. Поддерживается формат JSON.
jsonpathsЕсли данные загружаются в формате JSON, с помощью jsonpaths можно указать поля, извлекаемые из данных JSON. Например: "jsonpaths" = "[\"$.userid\",\"$.username\",\"$.age\",\"$.city\"]"
json_rootЕсли данные загружаются в формате JSON, с помощью json_root можно указать корневой узел данных JSON. Doris извлекает и разбирает элементы из корневого узла, заданного в json_root. По умолчанию значение пустое. Например: "json_root" = "$.RECORDS"
strip_outer_arrayЕсли данные загружаются в формате JSON, значение true для strip_outer_array означает, что данные JSON представлены массивом, а каждый его элемент обрабатывается как отдельная строка. По умолчанию — false. Данные JSON в Kafka часто представлены массивом, то есть внешний уровень заключён в скобки []. В этом случае можно указать "strip_outer_array" = "true". Например, следующие данные разбираются как две строки: [{"user_id":1,"name":"Emily","age":25},{"user_id":2,"name":"Benjamin","age":35}]
send_batch_parallelismЗадаёт параллелизм отправки пакетов данных. Если значение параллелизма превышает параметр конфигурации BE max_send_batch_parallelism_per_job, BE, выполняющий роль координатора, использует значение max_send_batch_parallelism_per_job.
load_to_single_tabletПозволяет загружать данные задачи только в один tablet соответствующей партиции. По умолчанию — false. Этот параметр можно задать только при загрузке данных в таблицу OLAP со случайным распределением по бакетам.
partial_columnsОпределяет, включено ли частичное обновление столбцов. По умолчанию — false. Этот параметр можно задать только для таблицы модели Unique с Merge on Write. Загрузка из одного потока в несколько таблиц не поддерживает этот параметр. Подробнее см. в разделе Частичное обновление столбцов.
unique_key_update_modeЗадаёт режим обновления таблицы Unique Key. Варианты:
  • UPSERT (по умолчанию): стандартная вставка или обновление строки целиком.
  • UPDATE_FIXED_COLUMNS: частичное обновление столбцов, при котором во всех строках обновляются одни и те же столбцы. Эквивалентно partial_columns=true.
  • UPDATE_FLEXIBLE_COLUMNS: гибкое частичное обновление столбцов, при котором в каждой строке могут обновляться разные столбцы. Требуется формат JSON, и для таблицы должен быть задан параметр enable_unique_key_skip_bitmap_column=true. Нельзя использовать вместе с jsonpaths, fuzzy_parse, предложением COLUMNS или предложением WHERE.
Подробнее см. в разделе Частичное обновление столбцов.
partial_update_new_key_behaviorОпределяет обработку новых строк при частичном обновлении столбцов в таблице Unique Merge on Write. Два варианта: APPEND и ERROR.
- APPEND: разрешить вставку новых строк.
- ERROR: при вставке новой строки загрузка завершается неудачей и возвращается ошибка.
max_filter_ratioМаксимальная допустимая доля отфильтрованных строк в окне выборки. Должна быть больше или равна 0 и меньше или равна 1. Значение по умолчанию — 1.0, что допускает любое количество ошибочных строк. Размер окна выборки — max_batch_rows * 10. Если отношение количества ошибочных строк к общему количеству строк в окне выборки превышает max_filter_ratio, задание Routine Load приостанавливается. Для проверки проблем с качеством данных требуется вмешательство пользователя. Строки, отфильтрованные условием where, не считаются ошибочными.
encloseЗадаёт символ обрамления. Если поля CSV содержат разделители строк или столбцов, можно указать однобайтовый символ обрамления, чтобы предотвратить непреднамеренное разделение данных. Например, если разделитель столбцов — ,, а символ обрамления — ', то в данных a,'b,c' значение b,c разбирается как одно поле.
escapeЗадаёт символ экранирования. Используется для экранирования символов внутри поля, совпадающих с символом обрамления. Например, для данных a,'b,'c' с символом обрамления ', чтобы разобрать b,'c как одно поле, необходимо задать однобайтовый символ экранирования (например, \) и изменить данные на a,'b,\'c'.

Предложение data_source_properties​

При создании задания загрузки Routine Load свойства источника данных Kafka можно задать с помощью предложения data_source_properties. Синтаксис:

FROM KAFKA ("<key1>" = "<value1>"[, "<key2>" = "<value2>" ...])

Доступные параметры предложения data_source_properties:

ПараметрОписание
kafka_broker_listЗадаёт сведения для подключения к брокерам Kafka. Формат — <kafka_broker_ip>:<kafka port>. Несколько брокеров разделяются запятыми. Например: "kafka_broker_list" = "<broker1_ip>:9092,<broker2_ip>:9092"
kafka_topicЗадаёт топик Kafka для подписки. Одно задание загрузки может получать данные только из одного топика Kafka.
kafka_partitionsЗадаёт партиции Kafka для подписки. Если не указано, по умолчанию данные получаются из всех партиций.
kafka_offsetsНачальное смещение для получения данных из партиции Kafka. Если указано время, получение данных начинается с самого позднего смещения, время которого больше или равно указанному. Можно задать конкретное значение смещения, большее или равное 0, либо использовать один из следующих форматов:

- OFFSET_BEGINNING: подписка с позиции, с которой доступны данные.

- OFFSET_END: подписка с конца.

- Формат времени, например: "2021-05-22 11:00:00".

Если не задано, по умолчанию подписка на все партиции топика начинается с OFFSET_END. Можно указать несколько начальных смещений, разделённых запятыми, например: "kafka_offsets" = "101,0,OFFSET_BEGINNING,OFFSET_END" или "kafka_offsets" = "2021-05-22 11:00:00,2021-05-22 11:00:00".

Примечание: формат времени нельзя смешивать с форматом OFFSET.

propertyЗадаёт пользовательские параметры Kafka, аналогичные параметру --property командной оболочки Kafka. Если значение параметра является файлом, добавьте к значению префикс FILE:. Для создания файла см. команду CREATE FILE. Дополнительные поддерживаемые пользовательские параметры описаны в настройках клиента в официальном документе librdkafka CONFIGURATION. Например: "property.client.id" = "12345", "property.group.id" = "group_id_0", "property.ssl.ca.location" = "FILE:ca.pem".

С помощью параметров свойств Kafka в data_source_properties можно настроить защищённый доступ. В настоящее время Doris поддерживает несколько протоколов безопасности Kafka, включая plaintext (по умолчанию), SSL, PLAIN и Kerberos.

ProgressХод выполнения задания. Для источников данных Kafka отображает текущее обработанное смещение каждой партиции. Например, {"0":"2"} означает, что получение данных из партиции Kafka 0 достигло смещения 2.

ReasonOfStateChangedПричина изменения состояния задания.

Загрузка из одного потока в несколько таблиц​

Создайте задачу Routine Load для Kafka с динамическим выбором нескольких таблиц, задав имя test1 для базы данных example_db. Укажите group.id и client.id; по умолчанию данные автоматически получаются из всех партиций, а подписка начинается с позиции, с которой доступны данные (OFFSET_BEGINNING).

Предположим, вам нужно загрузить данные из Kafka в таблицы tbl1 и tbl2 базы данных example_db. Можно создать задачу Routine Load с именем test1 для загрузки данных топика Kafka my_topic в обе таблицы: tbl1 и tbl2:

CREATE ROUTINE LOAD example_db.test1
FROM KAFKA
(
    "kafka_broker_list" = "broker1:9092,broker2:9092,broker3:9092",
    "kafka_topic" = "my_topic",
    "property.kafka_default_offsets" = "OFFSET_BEGINNING"
);

В этом случае данные в Kafka должны содержать имя таблицы. В настоящее время динамическое имя таблицы можно извлечь только из Kafka Value, и данные должны соответствовать следующему формату. Для JSON: table_name|{"col1": "val1", "col2": "val2"}, где tbl_name — имя таблицы, а | — разделитель между именем таблицы и её данными. Для CSV используется аналогичный формат, например: table_name|val1,val2,val3.

Примечание

Указанное здесь table_name должно точно совпадать с именем таблицы в Doris, иначе загрузка завершится ошибкой. При динамическом выборе таблицы column_mapping не поддерживается.

Загрузка в строгом режиме​

Создайте задачу Routine Load для Kafka с именем test1 для таблицы example_tbl в базе данных example_db, включив строгий режим:

CREATE ROUTINE LOAD example_db.test1 ON example_tbl
COLUMNS(k1, k2, k3, v1, v2, v3 = k1 * 100),
PRECEDING FILTER k1 = 1,
WHERE k1 < 100 and k2 like "%doris%"
PROPERTIES
(
    "strict_mode" = "true"
)
FROM KAFKA
(
    "kafka_broker_list" = "broker1:9092,broker2:9092,broker3:9092",
    "kafka_topic" = "my_topic"
);

Часто задаваемые вопросы (FAQ)​

Что делать, если задание Routine Load автоматически переходит в состояние PAUSED?​

Обычно это вызвано проблемами с качеством данных или ошибками на стороне Kafka:

  1. Выполните SHOW ROUTINE LOAD FOR <job_name>, чтобы просмотреть ReasonOfStateChanged и ErrorLogUrls.
  2. При наличии некорректных данных при необходимости увеличьте max_filter_ratio и max_error_number.
  3. При ошибках Kafka убедитесь, что брокер и топик доступны, затем выполните RESUME ROUTINE LOAD для восстановления работы.

Как устранить ошибку Offset out of range или out of range?​

Обычно это означает, что данные по сохранённому смещению уже удалены из Kafka (по истечении срока хранения):

  1. Приостановите задание: PAUSE ROUTINE LOAD FOR <job_name>.
  2. С помощью ALTER ROUTINE LOAD задайте для kafka_offsets допустимую позицию (например, OFFSET_BEGINNING или конкретное смещение).
  3. Выполните RESUME ROUTINE LOAD, чтобы возобновить задание.

Что делать при ошибке Server kafka/xxx@EXAMPLE.COM not found in Kerberos database?​

При использовании аутентификации Kerberos задайте rdnbs=true в krb5.conf.

Что делать при ошибке Server certificate verification failed или других ошибках SSL?​

Если на стороне BE не настроен доверенный сертификат CA, задайте "property.enable.ssl.certificate.verification" = "false" или явно укажите "property.ssl.ca.location" = "/path/to/ca-cert.pem".

Почему желаемый параллелизм (desired_concurrent_number) не применяется?​

Фактический параллелизм определяется минимальным из следующих трёх значений:

min(topic_partition_num, desired_concurrent_number, max_routine_load_task_concurrent_num)

Проверьте количество партиций топика Kafka и параметр конфигурации FE max_routine_load_task_concurrent_num.

Как использовать старую версию Kafka (< 0.10.0.0)?​

Задайте kafka_broker_version_fallback в конфигурации BE или укажите совместимую версию с помощью property.broker.version.fallback при создании задания.

Как указать целевую таблицу при загрузке из одного потока в несколько таблиц?​

Значение Value сообщения Kafka должно содержать имя таблицы в формате table_name|<data>, причём имя должно точно совпадать с именем таблицы в Doris. При динамическом выборе таблицы column_mapping не поддерживается.

Как просмотреть некорректные данные, которые не удалось загрузить?​

Выполните SHOW ROUTINE LOAD FOR <job_name> и проверьте поле ErrorLogUrls в результате. Откройте этот URL в браузере или с помощью wget, чтобы получить пример отфильтрованных ошибочных данных и узнать причину ошибки.

Нужно ли приостанавливать задание Routine Load перед изменением?​

Да. Для выполнения команды ALTER ROUTINE LOAD задание должно находиться в состоянии PAUSED. Последовательность изменения: PAUSE ROUTINE LOAD -> ALTER ROUTINE LOAD -> RESUME ROUTINE LOAD.

Дополнительная помощь​

  • Справочник SQL: CREATE ROUTINE LOAD
  • Для получения дополнительной справки выполните HELP ROUTINE LOAD в командной строке клиента.
