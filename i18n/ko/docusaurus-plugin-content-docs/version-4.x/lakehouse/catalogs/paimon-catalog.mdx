Doris는 다양한 메타데이터 서비스를 통한 Paimon 테이블 메타데이터 접근과 Paimon 데이터 읽기 및 쓰기를 지원합니다.

[Apache Doris와 Apache Paimon 빠른 시작](../best-practices/doris-paimon.md).

## 활용 시나리오 {#applicable-scenarios}

| 시나리오     | 설명                                                  |
| ------------ | ------------------------------------------------------------ |
| 쿼리 가속 | Doris의 분산 컴퓨팅 엔진으로 Paimon 데이터에 직접 접근하여 쿼리를 가속합니다. |
| 데이터 통합   | Paimon 데이터를 읽어 Doris 내부 테이블에 기록하거나, Doris 컴퓨팅 엔진으로 ZeroETL 작업을 수행합니다. |
| 데이터 다시 쓰기    | Doris SQL로 Paimon 테이블을 생성하고 수정하며, 데이터를 추가하거나 덮어쓰고, 기본 키 테이블에서 행 단위 변경을 수행합니다. |

## Catalog 구성 {#configuring-catalog}

### 구문 {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = '<paimon_catalog_type>',
    'warehouse' = '<paimon_warehouse>'
    {MetaStoreProperties},
    {StorageProperties},
    {PaimonProperties},
    {CommonProperties}
);
```

* `<paimon_catalog_type>`

  Paimon Catalog의 유형으로, 다음을 지원합니다.

  * `filesystem`: 기본값입니다. 파일 시스템에 저장된 메타데이터에 직접 접근합니다.

  * `hms`: Hive Metastore를 메타데이터 서비스로 사용합니다.

  * `dlf`: Alibaba Cloud DLF를 메타데이터 서비스로 사용합니다.

  * `jdbc`: JDBC 인터페이스로 관계형 데이터베이스에 연결하여 메타데이터 서비스로 사용합니다(4.1.0 버전부터 지원).

* `<paimon_warehouse>`

  Paimon의 웨어하우스 경로입니다. `<paimon_catalog_type>`이 `filesystem`인 경우 이 매개변수를 반드시 지정해야 합니다.

  `warehouse` 경로는 `Database` 경로의 상위 수준을 가리켜야 합니다. 예를 들어 테이블 경로가 `s3://bucket/path/to/db1/table1`이면 `warehouse`는 `s3://bucket/path/to/`여야 합니다.

* `{MetaStoreProperties}`

  MetaStoreProperties에는 Metastore 메타데이터 서비스의 연결 및 인증 정보를 입력합니다. 자세한 내용은 [지원되는 메타데이터 서비스] 절을 참조하세요.

* `{StorageProperties}`

  StorageProperties에는 스토리지 시스템 관련 연결 및 인증 정보를 입력합니다. 자세한 내용은 [지원되는 스토리지 시스템] 절을 참조하세요.

* `{PaimonProperties}`

  PaimonProperties에는 Paimon 관련 속성을 입력합니다.

  Doris는 Paimon 메타데이터에 접근할 때 Paimon Java SDK를 일부 사용하므로, 사용자 지정 매개변수를 Paimon Java SDK에 전달해야 할 수 있습니다. 다음 접두사를 사용할 수 있습니다.

  ```
  paimon.s3.xxx
  paimon.s3a.xxx
  paimon.fs.xxx
  ```

  이러한 매개변수는 자동으로 변환되어 전달됩니다. 다음은 몇 가지 예입니다.

  | 입력 매개변수 | Paimon Java SDK용으로 변환된 매개변수 |
  | --- | --- |
  | "paimon.s3.list.version" = "1" | "fs.s3a.list.version" = "1" |
  | "paimon.s3.paging.maximum" = "100" | "fs.s3a.paging.maximum" = "100" |
  | "paimon.fs.s3.read.ahead.buffer.size" = "1" | "fs.s3a.read.ahead.buffer.size" = "1" |
  | "paimon.s3a.replication.factor" = "3" | "fs.s3a.replication.factor" = "3" |

  **Paimon 읽기 옵션**

  Doris는 다음과 같은 유한 범위의 Paimon 배치 읽기 옵션을 지원합니다. Catalog 전체의 쿼리 기본값은
  `paimon.table-option.<option-key>`로 설정하고, 개별 테이블 참조에서는
  `table@options('<option-key>'='<value>')`로 재정의할 수 있습니다. 이 설정은 Doris의 읽기에만 영향을 미치며, 물리적
  Paimon 테이블 메타데이터를 변경하지 않습니다.

  | Paimon 옵션 | Paimon 기본값 | Doris에서 허용하는 값 | 효과 |
  | --- | --- | --- | --- |
  | `read.batch-size` | `1024` | `1`부터 `65536`까지의 정수 | 각 Paimon JNI 리더 배치에서 요청하는 행 수입니다. 명시적으로 설정한 값은 Doris가 리더를 열 때 유지됩니다. |
  | `file-reader-async-threshold` | `10 MB` | `1 MB`부터 `1 GB`까지의 메모리 크기 | Paimon JNI 리더가 비동기 읽기로 전환하는 파일 크기 임계값입니다. |
  | `file-index.read.enabled` | `true` | 불리언 | 읽기 중 Paimon 파일 인덱스 프루닝을 활성화합니다. |
  | `source.split.target-size` | `128 MB` | 양수 메모리 크기 | Paimon이 데이터 파일을 Doris 스캔 스플릿으로 결합할 때 사용하는 목표 크기입니다. |
  | `source.split.open-file-cost` | `4 MB` | 음수가 아닌 메모리 크기 | Paimon이 파일을 스플릿으로 결합할 때 파일을 여는 데 드는 예상 비용입니다. |
  | `scan.manifest.parallelism` | 사용 가능한 프로세서 수 | `1`부터 `256`까지의 정수 | 요청하는 매니페스트 읽기 병렬 처리 수입니다. 실행 시 Doris는 각 계획 분기에 대해 이 값, `256`, 해당 FE 또는 BE에서 사용 가능한 프로세서 수 중 가장 작은 값을 개별적으로 상한으로 적용합니다. |
  | `scan.plan-sort-partition` | `false` | 불리언 | Paimon 스캔 계획을 수립할 때 파티션을 정렬합니다. |

  예를 들어 다음 Catalog 설정은 물리적 Paimon 테이블에 저장된 값을 재정의하고
  Doris 쿼리의 기본값이 됩니다.

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.table-option.read.batch-size" = "4096",
      "paimon.table-option.file-reader-async-threshold" = "32 MB",
      "paimon.table-option.source.split.target-size" = "64 MB",
      "paimon.table-option.scan.manifest.parallelism" = "1"
  );
  ```

  쿼리는 Catalog나 Paimon 테이블 메타데이터를 수정하지 않고도 이러한 기본값을 재정의할 수 있습니다.

  ```sql
  SELECT *
  FROM paimon_hms.db_name.table_name@options(
      'read.batch-size' = '8192',
      'source.split.target-size' = '32 MB'
  );
  ```

  각 테이블 참조는 독립적인 옵션 집합을 가집니다. 예를 들어 같은 테이블의 두 별칭에 대해 하나의 문에서 서로 다른
  배치 크기를 사용할 수 있습니다.

  ```sql
  SELECT small.id
  FROM paimon_hms.db_name.table_name@options('read.batch-size' = '1') small
  JOIN paimon_hms.db_name.table_name@options('read.batch-size' = '8192') large
    ON small.id = large.id;
  ```

  우선순위는 높은 순서대로 다음과 같습니다.

  ```text
  relation @options > Doris Catalog property > physical Paimon table option > Paimon default
  ```

  Doris는 이 우선순위를 적용한 후 최종 값을 검증합니다. 따라서 안전한 Catalog 또는 관계 수준의 값으로
  유효하지 않은 물리적 테이블 값을 대체할 수 있습니다. 최종 값이 여전히 유효하지 않으면, Doris는 해당 계획 수립 또는
  리더 단계가 시작되기 전에 쿼리를 거부합니다. 매니페스트 제한은 파티션, 행 수/통계,
  폴백 분기 및 시스템 테이블의 매니페스트 계획 수립 전에도 적용됩니다.

  표의 처음 다섯 옵션은 메타데이터에 영향을 미치지 않으므로 캐시된 최신 파티션 프로젝션을 재사용할 수 있습니다.
  `scan.manifest.parallelism`과 `scan.plan-sort-partition`은 메타데이터 계획 수립에 영향을 미치므로, Doris는
  해당 관계에 적용되는 테이블 핸들을 기반으로 계획을 수립합니다. 쿼리별 값은 Paimon의 JVM 전역 실행기 크기를 변경하지 않습니다.

  Doris는 알 수 없거나 유효하지 않은 `paimon.table-option.*` 속성을 `CREATE CATALOG` 및 `ALTER CATALOG` 실행 시 거부합니다.
  `ALTER CATALOG`는 구성을 반영하기 전에 전체 후보 구성을 검증하므로, 변경에 실패하면
  이전 Catalog 구성이 계속 적용됩니다. 이전 Doris 버전에서 영속화한 Catalog도 계속 불러올 수 있지만,
  지원되지 않거나 유효하지 않은 기존 리더 속성은 적용하지 않고 무시합니다. 영속화된 값은
  이미지 및 편집 로그 호환성을 위해 유지됩니다.

  스냅샷 및 시작 위치 옵션은 관계 컨텍스트 선택자이며 반드시 `@options`를 사용해야 합니다. 자세한 내용은
  [Time Travel](#time-travel-with-options)을 참조하세요. 이 옵션은 Catalog 기본값으로 설정할 수 없습니다. 또한 Doris는
  Paimon의 Flink 소스 열거자에 속하는 `scan.max-splits-per-task`, `scan.fallback-branch`, 스트리밍,
  레이아웃, 쓰기 및 컴팩션 옵션을 제외합니다. Bucket, Primary Key, Partition, Merge Engine 및 기타 물리적
  동작은 Paimon 테이블 속성으로 구성하세요. Doris의 `CREATE TABLE ... PROPERTIES`로도 구성할 수 있습니다.

  :::info 문 일관성
  하나의 문 안에서 Doris는 스키마 바인딩, 파티션 불러오기, 행 수/통계 수집, 시스템 테이블
  계획 수립 및 데이터 스캔에 동일한 Paimon 스냅샷과 테이블 세대를 사용합니다.
  `@options`로 선택한 스냅샷이나 태그는 중첩된 `STRUCT`, `MAP`, `ARRAY`
  필드를 포함하여 해당 과거 버전의 스키마를 사용합니다. 준비된 문은 실행할 때마다 새로운 문 상태를 가져오므로,
  실행 사이에 발생한 커밋은 새 실행의 선택자와 캐시 설정에 따라 표시됩니다.
  :::

  운영 안전성을 위해 Paimon 스캐너의 DEBUG 구성 메시지에는 배치 크기와 프로젝션 필드 수만
  표시됩니다. Doris는 자격 증명이 포함될 수 있는 원시 스캐너 매개변수 맵을 출력하지 않습니다.
  `PaimonJniAsyncReaderThreadCount` 프로파일 게이지는 스캐너 전체에서 초당 한 번 샘플링되므로, 최대 일
  초 전의 값을 나타낼 수 있습니다. 이 샘플링은 쿼리 실행이나 스케줄링에 영향을 주지 않습니다. 리더와 IOManager 정리는
  서로 독립적이며, 닫기 작업이 일부 실패한 후에도 안전하게 재시도할 수 있습니다.

  **Paimon JNI IOManager**

  > 이 기능은 4.0.8 버전부터 지원됩니다.

  Paimon 기본 키 테이블에서 JNI 병합 읽기는 여러 파일의 데이터를 정렬하고 병합해야 할 수 있습니다. Paimon IOManager를
  활성화하면 이 과정에서 중간 데이터를 BE의 로컬 디스크로 스필할 수 있으므로,
  대용량 데이터의 병합 읽기 시 메모리 부담을 줄일 수 있습니다.

  | 속성 | 필수 여부 | 기본값 | 설명 |
  | --- | --- | --- | --- |
  | `paimon.jni.enable_jni_io_manager` | 아니요 | `false` | JNI 읽기에 Paimon IOManager를 활성화할지 여부입니다. 다른 IOManager 속성은 이 속성이 `true`일 때만 적용됩니다. |
  | `paimon.jni.io_manager.tmp_dir` | 아니요 | `<storage_root_path>/paimon_jni_scanner_io_tmp` | Paimon IOManager가 임시 스필 파일에 사용하는 로컬 디렉터리입니다. 여러 디렉터리는 쉼표나 콜론으로 구분할 수 있습니다. 이 속성을 생략하면 Doris는 각 BE 스토리지 경로 아래에 디렉터리를 하나씩 생성합니다. |
  | `paimon.jni.io_manager.impl_class` | 아니요 | Paimon 기본 구현 | 사용자 지정 `org.apache.paimon.disk.IOManager` 구현의 정규화된 클래스 이름입니다. 모든 BE의 Paimon JNI Scanner 클래스 경로에서 이 클래스를 사용할 수 있어야 합니다. |

  다음 예는 IOManager를 활성화하고 Doris가 BE 스토리지 경로에서 임시 디렉터리를 선택하도록 합니다.

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.jni.enable_jni_io_manager" = "true"
  );
  ```

  IOManager를 활성화해도 모든 병합 읽기가 스필되는 것은 아닙니다. Paimon은 병합 리더 수가
  `sort-spill-threshold`를 초과할 때만 스필합니다. 이는 Doris의 동적 리더 옵션이 아니므로, 다른 스필 동작이 필요하면 물리적 Paimon
  테이블에서 구성하세요.

  전용 스필 디스크를 사용하려면 모든 BE에 존재하거나 생성할 수 있는 로컬 경로를 구성하세요.

  ```sql
  "paimon.jni.io_manager.tmp_dir" = "/mnt/ssd1/paimon_io:/mnt/ssd2/paimon_io"
  ```

  Doris는 JNI 스캐너마다 IOManager를 생성하고 스캐너와 함께 닫습니다. 구성한
  디렉터리에 쓰기 권한이 있고 동시 쿼리를 처리할 충분한 용량이 있는지 확인하세요. 사용자 지정 구현 클래스를
  구성하는 경우, 이 클래스는 `String[]`을 받는 public 생성자, `String`을 받는 public 생성자
  또는 인수가 없는 public 생성자를 제공해야 합니다. 클래스를 불러오거나 인스턴스화하지 못하면 쿼리가 실패합니다.

  이 속성은 JNI 경로를 사용하는 Paimon 데이터 테이블 읽기에만 영향을 줍니다. 네이티브 읽기에는 영향을 주지 않습니다.
  `paimon.table-option.file-reader-async-threshold` 옵션은 독립적입니다. 이 옵션은 비동기
  Paimon 파일 읽기의 임계값을 제어하며, IOManager를 활성화하거나 스필 디렉터리를 구성하지 않습니다.

* `{CommonProperties}`

  CommonProperties에는 공통 속성을 입력합니다. [Catalog 개요](../catalog-overview.md)의 [공통 속성] 절을 참조하세요.
  
## 메타데이터 캐시 {#meta-cache}

외부 데이터 소스에 접근하는 성능을 개선하기 위해 Apache Doris는 Paimon 메타데이터를 캐시합니다. 메타데이터에는 테이블 구조(Schema), 테이블 객체, 스냅샷 및 파티션 프로젝션이 포함됩니다.

:::tip
Doris 4.1.x 이전 버전에서는 주로 FE 구성 항목으로 메타데이터 캐시를 전역 제어합니다. 자세한 내용은 [메타데이터 캐시](../meta-cache.md)를 참조하세요.
Doris 4.1.x부터 Paimon Catalog의 외부 메타데이터 캐시는 통합 `meta.cache.*` 키로 구성합니다.
:::

### 캐시 속성 구성(4.1.x+) {#meta-cache-unified-model}

각 엔진의 캐시 항목은 통합 구성 키 형식인 `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}`를 사용합니다. 메모리 제한은 추정기를 사용하는 `table` 및 `snapshot` 항목에 적용됩니다. [외부 메타데이터 캐시 메모리 관리](../external-meta-cache-memory-management)를 참조하세요.

| 속성 | 예 | 의미 |
|---|---|---|
| `enable` | `true/false` | 이 캐시 모듈을 활성화할지 여부입니다. |
| `ttl-second` | `600`, `0`, `-1` | `0`은 캐시 비활성화를 의미합니다(즉시 적용되며 최신 데이터를 확인하는 데 사용할 수 있음). `-1`은 만료되지 않음을 의미합니다. 그 외 양의 정수는 접근 시간을 기준으로 하는 초 단위 TTL을 의미합니다. |
| `capacity` | `10000` | 개수를 기준으로 한 최대 캐시 항목 수입니다. `max-weight`가 활성화되면 개수 제한이 동시에 적용되지는 않지만, `0`은 여전히 캐시를 비활성화합니다. |
| `max-weight` | `1GB` | Doris 4.1.4부터 지원됩니다. 추정 보유 메모리의 선택적 제한입니다. Paimon의 `table` 및 `snapshot`에서 지원하며, `0`은 해당 항목을 비활성화합니다. |

**적용 조건:** `enable=true`, `ttl-second != 0`, `capacity > 0`이고, `max-weight`가 없거나 `0`이 아닌 경우 모듈 캐시가 적용됩니다.

### 캐시 모듈 {#meta-cache-unified-modules}

Paimon Catalog에는 다음 캐시 모듈이 포함됩니다.

| 모듈(`<entry>`) | 속성 키 접두사 | 캐시되는 내용 및 영향 |
|---|---|---|
| `schema` | `meta.cache.paimon.schema.` | 테이블 구조를 캐시합니다. 영향: 테이블 컬럼 정보의 가시성입니다. 비활성화하면 쿼리마다 최신 Schema를 가져옵니다. |
| `table` | `meta.cache.paimon.table.` | Paimon 테이블 메타데이터 객체를 캐시합니다. 영향: 쿼리 계획 수립 중 메타데이터를 불러오는 오버헤드를 줄입니다. |
| `snapshot` | `meta.cache.paimon.snapshot.` | 스냅샷 메타데이터, 스키마 세대 및 파티션 프로젝션을 캐시합니다. 이 항목은 `max-weight`를 지원합니다. |

### 기존 매개변수 매핑 및 변환 {#meta-cache-mapping}

4.1.x 이상 버전에서는 통합 키를 권장합니다. 다음은 기존 Catalog 속성과 4.1.x+ 통합 키 간의 매핑입니다.

| 기존 속성 키 | 4.1.x+ 통합 키 | 설명 |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.paimon.schema.ttl-second` | 테이블 구조 캐시의 만료 시간 |

### 모범 사례 {#meta-cache-best-practices}

* **최신 데이터에 실시간 접근**: 각 쿼리에서 Paimon 테이블의 최신 데이터 변경이나 스키마 변경을 확인하려면 `ttl-second`를 `schema` 또는 `table`에 대해 `0`으로 설정할 수 있습니다.
  ```sql
  -- Disable table object cache to detect the latest snapshots of Paimon tables
  ALTER CATALOG paimon_ctl SET PROPERTIES ("meta.cache.paimon.table.ttl-second" = "0");
  ```
* **성능 최적화**: Doris 4.1.4부터 Catalog 속성 변경이 성공하면 Catalog 실행 컨텍스트가 재설정되고 해당 Catalog가 라우팅하는 모든 메타데이터 캐시 엔진의 초기화된 항목이 지워집니다. Doris는 다음 접근 시 새 컨텍스트와 구성으로 이를 다시 생성합니다. 실행 중인 쿼리에는 영향을 주지 않습니다. Doris 메모리 거버넌스가 활성화되면 Paimon SDK의 `CachingCatalog`는 기본적으로 비활성화됩니다. 명시적인 `paimon.cache-enabled` 설정이 우선 적용됩니다.

### 관측 가능성 {#meta-cache-unified-observability}

캐시 지표는 `information_schema.catalog_meta_cache_statistics` 시스템 테이블에서 확인할 수 있습니다.

```sql
SELECT catalog_name, engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, load_failure_count, last_error
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'paimon_ctl' AND engine_name = 'paimon'
ORDER BY entry_name;
```

이 시스템 테이블의 문서를 참조하세요: [catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md).

## 컬럼 타입 매핑 {#column-type-mapping}

| Paimon 타입                        | Doris 타입    | 설명                                                                 |
| ---------------------------------- | ------------- | ----------------------------------------------------------------------- |
| boolean                            | boolean       |                                                                         |
| tinyint                            | tinyint       |                                                                         |
| smallint                           | smallint      |                                                                         |
| integer                            | int           |                                                                         |
| bigint                             | bigint        |                                                                         |
| float                              | float         |                                                                         |
| double                             | double        |                                                                         |
| decimal(P, S)                      | decimal(P, S) |                                                                         |
| varchar                            | string        |                                                                         |
| char                               | string        |                                                                         |
| binary, varbinary | VARBINARY | 4.1.5부터 이 타입은 항상 `VARBINARY`로 매핑됩니다. `enable.mapping.varbinary` 속성은 호환성을 위해 유지되며, `false`로 설정해도 더 이상 `STRING` 매핑으로 복원되지 않습니다. 이전 버전에서는 이 속성으로 기존 매핑을 선택할 수 있습니다. |
| date                               | date          |                                                                         |
| timestamp\_without\_time\_zone     | datetime(N)   | 정밀도에 따라 매핑됩니다. 정밀도가 6보다 크면 최대 6으로 매핑됩니다(정밀도 손실이 발생할 수 있음). |
| timestamp\_with\_local\_time\_zone | TIMESTAMPTZ(N) | 4.1.5부터 이 타입은 항상 `TIMESTAMPTZ(N)`으로 매핑됩니다. `enable.mapping.timestamp_tz` 속성은 호환성을 위해 유지되며, `false`로 설정해도 더 이상 `DATETIME` 매핑으로 복원되지 않습니다. 정밀도는 6으로 제한되므로 그보다 높은 정밀도는 손실됩니다. 이전 버전에서는 이 속성으로 기존 매핑을 선택할 수 있습니다. |
| array                              | array         |                                                                         |
| map                                | map           |                                                                         |
| row                                | struct        |                                                                         |
| other                              | UNSUPPORTED   |                                                                         |

Doris는 두 Paimon JNI 스캐너 경로 모두에서 따옴표로 묶인 최상위 컬럼과 중첩된 `STRUCT` 필드의
철자를 정확히 보존합니다. 쉼표(`region,code`), 해시 기호(`nested#value`), 콜론(`colon:name`),
공백 또는 Unicode 문자가 포함된 이름도 일반적인 SQL 식별자 인용 외에 별도로 이스케이프할 필요가 없습니다. 읽기 시 컬럼은
대소문자를 구분하지 않고 일치 여부를 확인하므로, 대문자나 대소문자가 혼합된 컬럼 이름(예: `UserId`)도
정상적으로 쿼리할 수 있습니다.

:::info 버전 참고 사항

4.0.8 이전 버전에서는 읽기 시 정확한 일치로 컬럼을 찾았으므로, 대소문자가 혼합된 컬럼 이름을 사용하는 Paimon 및 Iceberg 테이블에서 잘못된 컬럼을 읽거나 쿼리가 실패할 수 있었습니다. 이 문제는 4.0.8에서 수정되었습니다.

:::

4.1.5부터 명시적인 `REFRESH TABLE`, `REFRESH DATABASE`, `REFRESH CATALOG` 명령은 해당 Paimon SDK 캐시도 무효화합니다. 외부에서 스키마를 변경하거나 테이블을 삭제하고 다시 생성한 후에는 새로 고침 명령으로 메타데이터를 다시 불러오세요. 이미 시작된 쿼리는 선택한 스냅샷을 유지합니다.

:::info 참고
4.1.5부터 `timestamp_without_time_zone`은 `DATETIME(N)`으로 매핑되고, `timestamp_with_local_time_zone`은 항상 `TIMESTAMPTZ(N)`으로 매핑됩니다. 후자는 세션의 `time_zone`에 따라 표시되는 시점을 나타냅니다. `enable.mapping.timestamp_tz=false`로도 이전 매핑을 복원할 수 없습니다.

소스 타입에 시간대 정보가 포함되어 있는지는 `DESCRIBE table_name` 문의 Extra 컬럼에서 확인할 수 있습니다. `WITH_TIMEZONE`이 표시되면 소스 타입이 시간대 정보를 포함하는 타입임을 의미합니다. (이 기능은 3.0.8부터 지원됩니다.)

4.0.3 버전부터 `timestamp_with_local_time_zone`을 Doris의 `timestamptz` 타입으로 매핑할 수 있습니다.
:::

## 쓰기 작업 {#write-operations}

Doris는 Paimon 테이블을 생성하고 수정하며 데이터를 기록할 수 있습니다. 쓰기가 성공할 때마다 Paimon
스냅샷으로 커밋됩니다. 문이 실패하면 Doris는 부분적인 스냅샷을 게시하지 않습니다.

### 시작하기 전에 {#before-you-begin}

데이터를 기록하기 전에 다음 항목을 확인하세요.

* 모든 FE 및 BE 노드에서 Paimon 쓰기 지원이 포함된 Doris 빌드를 실행해야 합니다. 이전 BE 노드가 아직 실행 중인
  롤링 업그레이드 중에는 Paimon에 데이터를 기록하지 마세요.
* Catalog 자격 증명에는 메타스토어를 업데이트하고 웨어하우스에서 파일을 생성, 쓰기, 이름 변경 및 삭제할 수 있는
  권한이 있어야 합니다. 정확한 권한은 메타스토어와 스토리지 시스템에 따라 다릅니다.
* 쓰기는 일반 Paimon 데이터 테이블에만 적용됩니다. Paimon 시스템 테이블과 브랜치,
  태그, 스냅샷 또는 타임스탬프를 선택하는 테이블 참조는 읽기 전용입니다.

### 지원되는 SQL {#supported-sql}

| 작업 | 지원 여부 및 참고 사항 |
| --- | --- |
| 데이터베이스 DDL | `CREATE DATABASE` 및 `DROP DATABASE` |
| 테이블 DDL | `CREATE TABLE`, `CREATE TABLE AS SELECT` 및 `DROP TABLE` |
| 스키마 변경 | 컬럼 추가, 삭제, 이름 변경, 순서 변경 및 수정 |
| 데이터 추가 | `INSERT INTO ... VALUES` 및 `INSERT INTO ... SELECT` |
| 데이터 덮어쓰기 | 전체 테이블, 정적 파티션 및 동적 파티션 `INSERT OVERWRITE` |
| 행 단위 변경 | 기본 키 테이블의 `DELETE`, `UPDATE` 및 `MERGE INTO`. 아래 제한 사항이 적용됩니다. |

### 빠른 시작 {#quick-start}

다음 예는 기본 키 테이블을 생성하고 데이터를 기록합니다. Paimon 테이블 옵션은
`PROPERTIES`에 지정합니다. Doris의 `DISTRIBUTE BY` 절을 추가하지 마세요.

```sql
SWITCH paimon_ctl;
CREATE DATABASE IF NOT EXISTS sales;
USE sales;

CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    customer STRING NULL,
    amount DECIMAL(12, 2) NULL,
    status STRING NULL
) ENGINE=paimon
PROPERTIES (
    'primary-key' = 'order_id',
    'bucket' = '2',
    'bucket-key' = 'order_id'
);

INSERT INTO orders VALUES
    (1, 'Alice', 99.90, 'NEW'),
    (2, 'Bob', 35.00, 'NEW');

UPDATE orders
SET status = 'PAID'
WHERE order_id = 1;

DELETE FROM orders
WHERE order_id = 2;

SELECT * FROM orders ORDER BY order_id;
```

결과:

```text
+----------+----------+--------+--------+
| order_id | customer | amount | status |
+----------+----------+--------+--------+
|        1 | Alice    |  99.90 | PAID   |
+----------+----------+--------+--------+
```

Doris에서 테이블 스키마를 변경한 다음 새 스키마로 계속 데이터를 기록할 수 있습니다.

```sql
ALTER TABLE orders ADD COLUMN note STRING NULL;
ALTER TABLE orders RENAME COLUMN note order_note;
```

### 데이터 삽입 및 덮어쓰기 {#insert-and-overwrite-data}

`INSERT INTO`는 추가 전용 테이블에 행을 추가하거나 기본 키 테이블의 Paimon
옵션에 따라 행을 병합합니다. 소스로는 `VALUES`, Doris 내부 테이블 또는 다른 외부 테이블을 사용할 수 있습니다.

```sql
INSERT INTO paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.new_orders;
```

파티션이 없는 테이블에서 `INSERT OVERWRITE`는 기존의 모든 행을 대체합니다. 따라서 입력이 비어 있으면 빈
테이블이 생성됩니다.

```sql
INSERT OVERWRITE TABLE paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.orders_snapshot;
```

파티션이 있는 테이블에서는 다음 형식 중 하나를 사용하세요.

```sql
-- Replace only the specified partition. The SELECT list omits the static partition column.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
PARTITION (order_date = '2026-10-08')
SELECT order_id, customer, amount, status
FROM internal.sales.daily_orders_stage;

-- Dynamic overwrite replaces the partitions present in the input and keeps other partitions.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
SELECT order_id, customer, amount, status, order_date
FROM internal.sales.daily_orders_stage;
```

기본 키 테이블은 `merge-engine`이 `partial-update`인 경우에만 키가 아닌 컬럼을 생략한 삽입을 허용합니다.
추가 전용 테이블에서는 생략된 컬럼에 기본값을 사용하거나, 허용되는 경우 `NULL`을 사용합니다.

### 데이터 삭제, 업데이트 및 병합 {#delete-update-and-merge-data}

행 단위 변경에는 Paimon 기본 키 테이블이 필요합니다. 기본 `deduplicate` 병합 엔진을 사용하는 테이블에서 Doris는
다음 작업을 지원합니다.

```sql
DELETE FROM paimon_ctl.sales.orders
WHERE order_id = 10;

UPDATE paimon_ctl.sales.orders
SET amount = amount * 0.9,
    status = 'DISCOUNTED'
WHERE order_id = 20;

MERGE INTO paimon_ctl.sales.orders t
USING internal.sales.order_changes s
ON t.order_id = s.order_id
WHEN MATCHED AND s.action = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
    customer = s.customer,
    amount = s.amount,
    status = s.status
WHEN NOT MATCHED THEN INSERT (order_id, customer, amount, status)
    VALUES (s.order_id, s.customer, s.amount, s.status);
```

Paimon이 행 변경을 적용하는 방식에 따라 다음 제한 사항이 있습니다.

* `UPDATE`는 기본 키 컬럼이나 `sequence.field`로 구성한 컬럼을 수정할 수 없습니다.
* `UPDATE`는 `MERGE`의 업데이트 작업을 포함하여 `deduplicate` 병합 엔진만 지원하며,
  `changelog-producer=input`은 지원하지 않습니다.
* 파티션 컬럼을 업데이트하려면 동적 버킷 테이블(`bucket=-1`)에 `ignore-delete=false`가 설정되어 있어야 합니다.
* `DELETE`는 `MERGE`의 삭제 작업을 포함하여 `ignore-delete=false`가 필요합니다. 기본 `deduplicate` 병합
  엔진은 이를 직접 지원합니다. `partial-update` 테이블은 `partial-update.remove-record-on-delete=true`를 설정해야 하며,
  `aggregation` 테이블은 `aggregation.remove-record-on-delete=true`를 설정해야 합니다.
* `rowkind.field`가 구성된 테이블은 이러한 행 단위 문을 지원하지 않습니다. 동적 버킷 테이블에
  `cross-partition-upsert.index-ttl`이 구성된 경우에도 지원하지 않습니다.
* `MERGE` 문은 포함된 작업에 해당하는 `UPDATE` 및 `DELETE` 제한 사항을 따릅니다.

예측 가능한 결과를 얻으려면 `MERGE`의 소스 측에서 일치 키가 고유하도록 유지하세요. 여러 소스 행이
같은 대상 행과 일치하면 Doris는 해당 문을 거부합니다.

### 운영 참고 사항 {#operational-notes}

* 기본 키, 파티션, 버킷, 병합 엔진, 파일 형식, 컴팩션 및 기타 물리적 동작은
  Paimon 테이블 속성으로 구성하세요. Doris는 Paimon SDK를 통해 이러한 옵션을 검증합니다.
* 현재 Doris는 Paimon 테이블에 일반적인 `ALTER TABLE ... SET TBLPROPERTIES` 작업을 제공하지 않습니다.
  생성 후 테이블 속성을 변경하려면 다른 Paimon 엔진을 사용한 다음, Doris에서 `REFRESH TABLE` 또는 `REFRESH CATALOG`를
  실행하세요.
* 쓰기 스필을 위해 각 BE에 충분한 로컬 디스크 공간을 확보하고, 임시 파일과
  커밋 작업을 위해 충분한 웨어하우스 권한을 부여하세요. BE 설정 `paimon_jni_writer_memory_pool_limit_bytes`는 각
  Paimon JNI 라이터가 사용하는 메모리 풀을 제한하며, 기본값은 512 MB입니다.
* 쓰기 또는 스키마 변경이 성공하면 새 Doris 문은 커밋된 Paimon 스냅샷을 불러옵니다. 기존
  문은 시작할 때 선택한 스냅샷을 계속 사용합니다.

## 쿼리 작업 {#query-operations}

### 기본 쿼리 {#basic-query}

Catalog를 구성한 후 다음과 같이 Catalog의 테이블 데이터를 쿼리할 수 있습니다.

```sql
-- 1. Switch to catalog, use database, and query
SWITCH paimon_ctl;
USE paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 2. Use Paimon database directly
USE paimon_ctl.paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 3. Use fully qualified name to query
SELECT * FROM paimon_ctl.paimon_db.paimon_tbl LIMIT 10;
```

### 배치 증분 쿼리 {#batch-incremental-query}

> 3.1.0 버전부터 지원

Flink와 유사하게 Paimon의 [배치 증분](https://paimon.apache.org/docs/master/flink/sql-query/#batch-incremental) 쿼리를 지원합니다.

지정한 스냅샷 또는 타임스탬프 구간 내의 증분 데이터를 쿼리할 수 있습니다. 구간은 왼쪽 경계를 포함하고 오른쪽 경계를 제외합니다.

```sql
-- between snapshots [0, 5)
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5');

-- between snapshots [0, 5) with specified scan mode
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5', 'incrementalBetweenScanMode'='diff');

-- read from start timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000');

-- read between timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000', 'endTimestamp'='1750944949000');
```

매개변수:

| 매개변수 | 설명 | 예 |
| --- | --- | --- |
| `startSnapshotId` | 시작 스냅샷 ID로, 0보다 커야 합니다. `endSnapshotId`와 함께 지정해야 합니다. | `'startSnapshotId'='3'` |
| `endSnapshotId` | 종료 스냅샷 ID로, `startSnapshotId`보다 커야 합니다. `startSnapshotId`와 함께 지정해야 합니다. | `'endSnapshotId'='10'` |
| `incrementalBetweenScanMode` | 증분 읽기 모드를 지정합니다. 기본값은 `auto`이며, `delta`, `changelog`, `diff`를 지원합니다. |  `'incrementalBetweenScanMode'='delta'` |
| `startTimestamp` | 시작 스냅샷 타임스탬프로, 0보다 크거나 같아야 합니다. 단위는 밀리초입니다. | `'startTimestamp'='1750844949000'` |
| `endTimestamp` | 종료 스냅샷 타임스탬프로, `startTimestamp`보다 커야 합니다. 선택 사항이며, 지정하지 않으면 `startTimestamp`부터 최신 스냅샷까지 읽습니다. 단위는 밀리초입니다. | `'endTimestamp'='1750944949000'` |

:::tip 참고 사항
`startSnapshotId`와 `endSnapshotId`는 Paimon 매개변수 `'incremental-between'='3,10'`을 구성합니다.

`startTimestamp`와 `endTimestamp`는 Paimon 매개변수 `'incremental-between-timestamp'='1750844949000,1750944949000'`을 구성합니다.

`incrementalBetweenScanMode`는 Paimon 매개변수 `incremental-between-scan-mode`에 해당합니다.
:::

이 매개변수에 대한 자세한 내용은 [Paimon 문서](https://paimon.apache.org/docs/master/maintenance/configurations/)를 참조하세요.

### Time Travel {#time-travel}

> 3.1.0 버전부터 지원

Paimon 테이블의 지정된 스냅샷 읽기를 지원합니다.

기본적으로 읽기 요청은 최신 버전의 스냅샷만 읽습니다.

`$snapshots` 테이블 함수를 통해 지정한 Paimon 테이블의 스냅샷을 쿼리할 수 있습니다.

```sql
Doris > SELECT snapshot_id,commit_time FROM paimon_tbl$snapshots;
+-------------+-------------------------+
| snapshot_id | commit_time             |
+-------------+-------------------------+
|           1 | 2025-08-17 06:05:52.740 |
|           2 | 2025-08-17 06:05:52.979 |
|           3 | 2025-08-17 06:05:53.240 |
|           4 | 2025-08-17 06:05:53.561 |
+-------------+-------------------------+
```

`FOR TIME AS OF` 및 `FOR VERSION AS OF` 문을 사용하여 스냅샷 ID 또는 스냅샷 생성 시각을 기준으로 과거 버전의 데이터를 읽을 수 있습니다. 예:

```sql
-- Notice: Before 3.1.1, only support format like YYYY-MM-DD HH:MM:SS.SSS
-- After 3.1.2, support YYYY-MM-DD HH:MM:SS and YYYY-MM-DD
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52.740";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17";

-- Notice: The timestamp must be precise down to the millisecond.
SELECT * FROM paimon_tbl FOR TIME AS OF 1755381952740;
-- Use snapshot id
SELECT * FROM paimon_tbl FOR VERSION AS OF 1;
```

#### `@options`를 사용하는 Time Travel {#time-travel-with-options}

Paimon 전용 선택자를 사용하려면 쿼리 관계에 `@options`를 적용하세요. Doris는 `scan.snapshot-id`,
`scan.tag-name`, `scan.version`, `scan.timestamp`, `scan.timestamp-millis`, `scan.watermark`,
`scan.file-creation-time-millis`, `scan.creation-time-millis`, `scan.mode`를 허용합니다. 스냅샷이나 태그를 선택하면
해당 시점의 스키마도 선택됩니다. Doris는 과거 데이터에 최신 스키마를 바인딩하지 않습니다.

```sql
-- Read snapshot 1 with the schema stored for snapshot 1.
SELECT id, old_name
FROM paimon_tbl@options('scan.snapshot-id' = '1');

-- A retained tag remains readable even after its ordinary snapshot expires.
SELECT id, old_name
FROM paimon_tbl@options('scan.tag-name' = 'tag1');
```

하나의 테이블 참조에는 시작 위치 옵션을 하나만 지정할 수 있습니다. `scan.mode`는 Paimon에서 해당 조합을
호환 가능하다고 정의한 경우에만 위치와 함께 사용할 수 있습니다. 예를 들어 `scan.mode='from-creation-timestamp'`에는
`scan.creation-time-millis`가 필요합니다. 알 수 없거나 만료된 스냅샷, 브랜치 또는 태그는 최신 테이블로
자동 폴백하지 않고 명시적으로 실패합니다. `@options` 구문은 쿼리 관계에서 지원되며 뷰
정의에 저장할 수 있지만, CTE 참조나 `SHOW`와 같은 쿼리 이외의 명령에는 적용할 수 없습니다.

### 브랜치 및 태그 {#branch-and-tag}

> 3.1.0 버전부터 지원

지정한 Paimon 테이블의 브랜치 및 태그 읽기를 지원합니다.

`$branches` 및 `$tags` 시스템 테이블을 사용하여 Paimon 테이블의 브랜치와 태그를 확인할 수 있습니다.

```
Doris > SELECT * FROM paimon_tbl$branches;
+-------------+-------------------------+
| branch_name | create_time             |
+-------------+-------------------------+
| b_1         | 2025-08-17 06:34:37.294 |
| b_2         | 2025-08-17 06:34:37.297 |
+-------------+-------------------------+

Doris > SELECT * FROM paimon_tbl$tags;
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| tag_name | snapshot_id | schema_id | commit_time             | record_count | create_time | time_retained |

| t_1      |           1 |         0 | 2025-08-17 06:05:52.740 |            3 | NULL        | NULL          |
| t_2      |           2 |         0 | 2025-08-17 06:05:52.979 |            6 | NULL        | NULL          |
| t_3      |           3 |         0 | 2025-08-17 06:05:53.240 |            9 | NULL        | NULL          |

+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
```

Spark/Trino 같은 시스템과 호환되도록 다양한 구문 형식을 지원합니다.

```sql
-- BRANCH
SELECT * FROM paimon_tbl@branch(branch1);

SELECT * FROM paimon_tbl FOR VERSION AS OF 'tag1';
```

`FOR VERSION AS OF` 구문에서 Doris는 매개변수가 타임스탬프인지 자동으로 판단합니다.

## 시스템 테이블 {#system-tables}

> 3.1.0 버전부터 지원

Doris는 Paimon 시스템 테이블을 쿼리하여 테이블 관련 메타데이터를 가져오는 기능을 지원합니다. 시스템 테이블에서 스냅샷 이력, 매니페스트 파일, 데이터 파일, 파티션 등의 정보를 확인할 수 있습니다.

Paimon 테이블의 메타데이터에 접근하려면 테이블 이름 뒤에 `$` 기호를 추가하고 그 뒤에 시스템 테이블 이름을 붙이세요.

```sql
SELECT * FROM my_table$system_table_name;
```

`audit_log`, `binlog`, `manifests`, `partitions`, `ro`, `row_tracking`, `table_indexes` 시스템 테이블은
관계의 `@options`를 허용합니다. 선택한 스냅샷이나 태그는 시스템 테이블의 행에 적용되며, 소스 컬럼을 노출하는
시스템 테이블에는 해당 시점의 소스 테이블 스키마도 적용됩니다.

```sql
SELECT rowkind, id, old_name
FROM paimon_tbl$audit_log@options('scan.tag-name' = 'tag1');
```

다른 시스템 테이블은 행을 생성하는 모든 단계에서 선택한 스냅샷을 사용한다고 보장할 수 없으므로
`@options`를 거부합니다. Paimon 시스템 테이블은 `scan.file-creation-time-millis`도 거부합니다. 이 파일
필터를 알림 없이 무시하면 요청한 범위를 벗어나는 행이 반환될 수 있기 때문입니다.

:::info 참고
Doris는 Paimon 전역 시스템 테이블 읽기를 지원하지 않습니다. 이 기능은 Flink에서만 지원됩니다.
:::

## 부록 {#appendix}

### 자주 묻는 질문 {#faq}

**1. `Could not find a file io implementation for scheme 's3a' in the classpath`**

3.1 이전 버전에서 HMS를 메타데이터 저장소로 사용하고 스토리지 측에서 's3a' 또는 's3' 프로토콜을 사용하면 다음 오류가 발생합니다.

```text
java.io.UncheckedIOException: org.apache.paimon.fs.UnsupportedSchemeException: Could not find a file io implementation for scheme 's3a' in the classpath. Hadoop FileSystem also cannot access this path 's3a://`.
```

**3.1 이전 버전**

3.1 이전 버전은 `s3a` 프로토콜을 지원하지 않습니다. 반드시 사용해야 한다면 임시 해결책으로 `s3a` 관련 매개변수를 추가할 수 있습니다.

**3.1 이상 버전**

3.1 버전부터는 `s3a` 매개변수를 명시적으로 추가할 필요가 없습니다. Paimon 스토리지 매개변수를 재정의하려면 `paimon.fs.` 접두사가 붙은 매개변수를 추가할 수 있습니다. Paimon은 내부적으로 HDFS API를 사용하므로 모든 `fs.s3a.*` 매개변수를 지원합니다.

예:

```sql
CREATE CATALOG `paimon_hms_on_s3a` PROPERTIES (
    "type" = "paimon",
    "paimon.catalog.type" = "hms",
    "hive.metastore.uris" = "thrift://172.20.48.119:9383",
    "warehouse" = "s3a://bucket/paimon_warehouse",
    "s3.access_key" = "<ak>",
    "s3.secret_key" = "<sk>",
    "s3.region" = "ap-east-1",
    "s3.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    -- Explicitly add s3a parameters
    "fs.s3a.access.key" = "<ak>",
    "fs.s3a.secret.key" = "<sk>",
    "fs.s3a.endpoint.region" = "ap-east-1",
    "fs.s3a.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    "fs.s3a.impl" = "org.apache.hadoop.fs.s3a.S3AFileSystem"
);
```

`s3` 프로토콜을 사용할 때는 Paimon S3 관련 매개변수를 명시적으로 추가해야 합니다. 즉, `paimon.` 접두사를 추가해야 합니다. 예:

```sql
CREATE CATALOG test_paimon_on_hms_aws_catalog PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = 'hms',
    'warehouse' = 's3://bucket-hk/paimon_warehouse',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9383',
    's3.region' = 'ap-east-1',
    's3.endpoint' = 'https://s3.ap-east-1.amazonaws.com',
    's3.access_key' = '<ak>',
    's3.secret_key' = '<sk>',
    -- Explicitly add Paimon S3 parameters
    'paimon.s3.region' = 'ap-east-1',
    'paimon.s3.endpoint' = 'ap-east-1',
    'paimon.s3.access-key' = '<ak>',
    'paimon.s3.secret-key' = '<sk>'
);
```
