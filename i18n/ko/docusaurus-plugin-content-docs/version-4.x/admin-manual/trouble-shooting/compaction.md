# 컴팩션 {#compaction}

Doris는 LSM-Tree와 유사한 구조로 데이터를 기록하고, 백그라운드에서 컴팩션을 통해 작은 파일들을 정렬된 큰 파일로 지속적으로 병합합니다. 컴팩션은 삭제와 업데이트 등의 작업을 처리합니다.

컴팩션 전략을 적절히 조정하면 데이터 적재 및 쿼리 효율을 크게 높일 수 있습니다. Doris는 튜닝을 위해 다음과 같은 컴팩션 전략을 제공합니다.


## 수직 컴팩션 {#vertical-compaction}

수직 컴팩션은 Doris 1.2.2에 도입된 새로운 컴팩션 알고리즘으로, 대규모 데이터와 컬럼 수가 많은 테이블을 처리하는 환경에서 컴팩션의 실행 효율과 리소스 사용량을 최적화합니다. 컴팩션의 메모리 사용량을 효과적으로 줄이고 실행 속도를 높일 수 있습니다. 테스트 결과, 수직 컴팩션의 메모리 사용량은 기존 컴팩션 알고리즘의 1/10에 불과하며, 컴팩션 처리 속도는 15% 향상되었습니다.

수직 컴팩션에서는 행 단위 병합을 컬럼 그룹 단위 병합으로 변경합니다. 각 병합의 처리 단위를 컬럼 그룹으로 바꾸면 개별 컴팩션에서 처리하는 데이터양이 줄어들어 컴팩션 중 메모리 사용량이 감소합니다.

BE 설정:
- `enable_vertical_compaction = true`는 수직 컴팩션을 활성화합니다.
- `vertical_compaction_num_columns_per_group = 5`는 각 컬럼 그룹에 포함되는 컬럼 수입니다. 테스트 결과, 기본값인 그룹당 5개 컬럼이 효율성과 메모리 사용량 측면에서 더 유리한 것으로 나타났습니다.
- `vertical_compaction_max_segment_size`는 수직 컴팩션 후 생성되는 디스크 파일의 크기를 설정하며, 기본값은 268435456(바이트)입니다.


## 세그먼트 컴팩션 {#segment-compaction}

세그먼트 컴팩션은 주로 대규모 데이터 적재를 처리합니다. 세그먼트 컴팩션은 데이터 적재 과정에서 작업 내부의 세그먼트를 병합하며, 이 점에서 일반 컴팩션 및 수직 컴팩션과 다릅니다. 이 메커니즘은 생성되는 세그먼트 수를 효과적으로 줄여 -238 (OLAP_ERR_TOO_MANY_SEGMENTS) 오류를 방지합니다.

세그먼트 컴팩션은 다음과 같은 기능과 이점을 제공합니다.
- 데이터 적재로 생성되는 세그먼트 수를 줄입니다.
- 컴팩션이 데이터 적재와 병렬로 진행되므로 데이터 적재 시간이 늘어나지 않습니다.
- 데이터 적재 중 메모리 및 컴퓨팅 리소스 사용량이 증가하지만, 긴 데이터 적재 과정 전반에 걸쳐 고르게 분산되므로 증가량은 비교적 적습니다.
- 세그먼트 컴팩션을 거친 데이터는 이후 쿼리와 일반 컴팩션에서 리소스 사용량 및 성능 측면의 이점을 제공합니다.

BE 설정:
- `enable_segcompaction=true`는 세그먼트 컴팩션을 활성화합니다.
- `segcompaction_batch_size`는 병합 간격을 설정합니다. 기본값인 10은 세그먼트 파일이 10개 생성될 때마다 세그먼트 컴팩션을 트리거한다는 의미입니다. 10 - 30 사이의 값으로 설정하는 것을 권장합니다. 값이 클수록 세그먼트 컴팩션의 메모리 사용량이 증가합니다.

세그먼트 컴팩션을 권장하는 상황:

- 대량의 데이터를 적재할 때 OLAP_ ERR_ TOO_ MANY_ SEGMENTS (errcode - 238) 오류로 실패하는 경우. 데이터 적재 중 세그먼트 수를 줄이기 위해 세그먼트 컴팩션을 활성화하는 것을 권장합니다.
- 데이터 적재 중 작은 파일이 너무 많이 생성되는 경우: 적재하는 데이터양이 적절하더라도, 낮은 카디널리티나 메모리 제약으로 인해 memtable이 조기에 플러시되면서 작은 세그먼트 파일이 대량으로 생성되면 데이터 적재 작업이 실패할 수 있습니다. 이 경우 이 기능을 활성화하는 것을 권장합니다.
- 데이터 적재 직후 쿼리를 실행하는 경우. 데이터 적재가 막 완료되고 일반 컴팩션이 아직 끝나지 않은 상태에서는 많은 세그먼트 파일이 이후 쿼리의 효율에 영향을 줍니다. 데이터 적재 직후 쿼리를 실행해야 한다면 이 기능을 활성화하는 것을 권장합니다.
- 데이터 적재 후 일반 컴팩션의 부하가 높은 경우: 세그먼트 컴팩션은 일반 컴팩션 부하의 일부를 데이터 적재 과정에 고르게 분산합니다. 이 경우 이 기능을 활성화하는 것을 권장합니다.

세그먼트 컴팩션을 권장하지 않는 상황:
- 데이터 적재 작업 자체가 이미 메모리 리소스를 모두 사용하는 경우, 메모리 부하가 더 커져 데이터 적재 작업이 실패하지 않도록 세그먼트 컴팩션을 사용하지 않는 것을 권장합니다.

구현 및 테스트 결과에 대한 자세한 내용은 이 [링크](https://github.com/apache/doris/pull/12866)를 참조하세요.

## 컴팩션 전략 {#compaction-strategy}

컴팩션 전략은 어떤 작은 파일들을 언제 큰 파일로 병합할지 결정합니다. Doris는 현재 두 가지 컴팩션 전략을 제공하며, 테이블 속성의 `compaction_policy` 매개변수로 지정합니다.

### 크기 기반 컴팩션 전략 {#size-based-compaction-strategy}

크기 기반 컴팩션 전략은 기본 전략이며 대부분의 상황에 적합합니다.
```
"compaction_policy" = "size_based"
```

### 시계열 컴팩션 전략 {#time-series-compaction-strategy}

시계열 컴팩션 전략은 로그 및 시계열 데이터와 같은 사용 사례에 최적화되어 있습니다. 시계열 데이터의 시간 지역성을 활용하여 비슷한 시점에 기록된 작은 파일들을 큰 파일로 병합합니다. 각 파일은 컴팩션에 한 번만 참여하므로 반복적인 컴팩션으로 인한 쓰기 증폭이 줄어듭니다.

```
"compaction_policy" = "time_series"
```

시계열 컴팩션 전략은 다음 조건 중 하나라도 충족되면 트리거됩니다.
- 병합되지 않은 파일의 크기가 `time_series_compaction_goal_size_mbytes`를 초과하는 경우(기본값 1 GB).
- 병합되지 않은 파일 수가 `time_series_compaction_file_count_threshold`를 초과하는 경우(기본값 2000).
- 마지막 컴팩션 이후 경과 시간이 `time_series_compaction_time_threshold_seconds`를 초과하는 경우(기본값 1시간).

이 매개변수들은 테이블의 PROPERTIES에 설정합니다. 테이블 생성 시 지정하거나 나중에 다음 구문으로 수정할 수 있습니다.
```
ALTER TABLE table_name SET("name" = "value");
```

## 컴팩션 동시 실행 제어 {#compaction-concurrency-control}

컴팩션은 백그라운드에서 실행되며 CPU 및 IO 리소스를 사용합니다. 동시에 실행되는 컴팩션 스레드 수를 조정하여 리소스 사용량을 제어할 수 있습니다.

동시에 실행되는 컴팩션 스레드 수는 BE 설정 파일에서 다음 매개변수로 설정합니다.
- `max_base_compaction_threads`: base compaction 스레드 수이며, 기본값은 4입니다.
- `max_cumu_compaction_threads`: cumulative compaction 스레드 수이며, 기본값은 -1입니다. 이는 디스크당 1개의 스레드를 의미합니다.
