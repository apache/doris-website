## 빠른 선택 가이드 {#quick-selection}

비즈니스 시나리오에 따라 배포 방안을 빠르게 결정할 수 있습니다.

| 시나리오 | 권장 방안 |
|------|----------|
| 탄력적 확장이 필요하고 클라우드에 배포하는 경우 | 스토리지-컴퓨팅 분리형 + 클라우드 플랫폼 배포 |
| 규모가 고정된 온프레미스 환경 | 스토리지-컴퓨팅 통합형 + 수동 배포 |
| 자동화된 관리가 필요한 대규모 클러스터 | 스토리지-컴퓨팅 분리형 + Kubernetes 배포 |

## 스토리지-컴퓨팅 통합형과 스토리지-컴퓨팅 분리형 비교 {#storage-compute-integrated-vs-storage-compute-decoupled}

| 항목 | 스토리지-컴퓨팅 통합형 | 스토리지-컴퓨팅 분리형 |
|--------|----------|----------|
| 아키텍처 | 데이터와 컴퓨팅이 긴밀하게 결합되어 있으며, BE 노드가 스토리지와 쿼리를 모두 처리 | 컴퓨팅 계층(BE)과 스토리지 계층(Shared Storage)이 분리됨 |
| 사용 사례 | 비즈니스 규모가 고정된 경우, 높은 쿼리 성능이 필요한 경우, 공유 스토리지가 없는 환경 | 탄력적 확장이 필요한 경우, 클라우드 배포, 빅데이터 분석 |
| 장점 | 단순한 아키텍처, 낮은 지연 시간, 외부 공유 스토리지 불필요 | 컴퓨팅 리소스를 독립적으로 확장 가능, 낮은 스토리지 비용, 유연한 리소스 격리 |
| 단점 | 컴퓨팅 리소스를 독립적으로 확장할 수 없음 | 구성 요소가 더 많으며, 안정적인 공유 스토리지 서비스가 필요함 |

## 배포 방식 {#deployment-methods}

### 수동 배포 {#manual-deployment}

스크립트와 구성 파일을 사용하여 수동으로 배포합니다. 중소규모 클러스터와 초기 검증에 적합합니다.

- 적합한 경우: 빠른 검증, 최소 구성 배포, 클러스터 아키텍처 학습
- 적합하지 않은 경우: 대규모 클러스터, 잦은 변경이 필요한 환경

자세한 절차는 [스토리지-컴퓨팅 통합형 클러스터 수동 배포](./deploy-manually/integrated-storage-compute-deploy-manually) 또는 [스토리지-컴퓨팅 분리형 클러스터 수동 배포](./deploy-manually/separating-storage-compute-deploy-manually)를 참조하세요.

### Kubernetes 배포 {#kubernetes-deployment}

Doris Operator를 사용하여 Kubernetes에서 클러스터를 관리합니다. 대규모 프로덕션 환경과 자동화가 필요한 시나리오에 적합합니다.

- 적합한 경우: 대규모 클러스터, 선언적 관리가 필요한 시나리오, 하이브리드 클라우드 배포
- 요구 사항: Kubernetes 클러스터, Doris Operator

자세한 절차는 [Kubernetes 배포](./deploy-on-kubernetes/intro)를 참조하세요.

### 클라우드 플랫폼 배포 {#cloud-platform-deployment}

클라우드 네이티브 인프라를 활용하여 Alibaba Cloud, AWS 등의 클라우드 플랫폼에 배포합니다.

- 적합한 경우: 클라우드 기반 워크로드, 신속한 프로비저닝이 필요한 시나리오, 환경 격리
- 지원 플랫폼: Alibaba Cloud ECI, AWS EKS 등

자세한 절차는 [클라우드 플랫폼 배포](./deploy-on-cloud/doris-on-aws)를 참조하세요.

## 선택 시 권장 사항 {#decision-recommendations}

1. **Doris를 처음 사용하는 경우**: 스토리지-컴퓨팅 통합형 + 수동 배포로 시작하세요. 아키텍처가 단순하여 쉽게 시작할 수 있습니다.
2. **중소규모 프로덕션 환경**: 스토리지-컴퓨팅 통합형 + 수동 배포 또는 Kubernetes 배포를 권장합니다.
3. **탄력성이 필요한 클라우드 배포**: 스토리지-컴퓨팅 분리형 + 클라우드 플랫폼 배포 또는 Kubernetes 배포를 권장합니다.
4. **대규모 프로덕션 클러스터**: 스토리지-컴퓨팅 분리형 + Kubernetes 배포를 사용하면 운영 자동화가 간편해집니다.

## 자주 묻는 질문 {#faq}

### 질문: 스토리지-컴퓨팅 분리형 아키텍처가 쿼리 성능에 큰 영향을 미치나요? {#q-does-the-storage-compute-decoupled-architecture-significantly-affect-query-performance}

스토리지-컴퓨팅 분리형 아키텍처는 컴퓨팅 계층과 스토리지 계층이 분리되어 있어 일반적으로 추가적인 네트워크 오버헤드가 발생하지만, 대부분의 시나리오에서는 그 영향이 제한적입니다. 이유는 다음과 같습니다.
- Shared Storage는 일반적으로 고속 네트워크 환경(예: 25Gbps RDMA)에 배포됩니다.
- 데이터 캐싱 메커니즘으로 원격 읽기 빈도를 효과적으로 줄일 수 있습니다.
- 매우 낮은 지연 시간이 필요한 일부 시나리오에서는 스토리지-컴퓨팅 통합형이 더 적합할 수 있습니다.

### 질문: 기존 클러스터를 스토리지-컴퓨팅 통합형에서 스토리지-컴퓨팅 분리형으로 어떻게 마이그레이션하나요? {#q-how-do-i-migrate-an-existing-cluster-from-storage-compute-integrated-to-storage-compute-decoupled}

마이그레이션 절차는 대략 다음과 같습니다.
1. 새 환경에 스토리지-컴퓨팅 분리형 클러스터를 배포합니다.
2. Broker Load 또는 Stream Load를 사용하여 데이터를 마이그레이션합니다.
3. 데이터 일관성과 쿼리 성능을 검증합니다.
4. 기존 클러스터의 운영을 종료합니다.

### 질문: Kubernetes 배포에는 전담 운영팀이 필요한가요? {#q-does-kubernetes-deployment-require-a-dedicated-operations-team}

클러스터 규모에 따라 다릅니다.
- 소규모 클러스터(10개 노드 이내): Kubernetes 배포로 늘어나는 복잡성에 비해 얻는 이점이 크지 않을 수 있습니다.
- 중대규모 클러스터(10+개 노드): Kubernetes의 자동화 기능으로 운영 비용을 크게 줄일 수 있습니다.

### 질문: 클라우드 플랫폼 배포와 Kubernetes 배포 중 어떤 방식을 선택해야 하나요? {#q-how-do-i-choose-between-cloud-platform-deployment-and-kubernetes-deployment}

| 항목 | 클라우드 플랫폼 배포 | Kubernetes 배포 |
|--------|------------|------------------|
| 사용 사례 | 빠른 배포, 탄력적인 리소스 | 하이브리드 클라우드, 멀티 클라우드 환경 |
| 관리 복잡성 | 낮음 | 중간 |
| 유연성 | 클라우드 플랫폼의 기능에 의해 제한됨 | 높음, 맞춤 설정 가능 |
| 비용 | 추가 클라우드 서비스 요금이 발생할 수 있음 | 비용을 더 쉽게 통제할 수 있음 |
