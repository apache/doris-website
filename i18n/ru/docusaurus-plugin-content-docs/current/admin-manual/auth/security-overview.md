Apache Doris предоставляет возможности безопасности для корпоративных платформ данных: аутентификацию, авторизацию, защиту данных, шифрование передачи данных и аудит. В этом документе рассматриваются сценарии применения, общая архитектура безопасности Doris, основные понятия и схема аутентификации и авторизации. Здесь также приведены ссылки на документацию по каждой возможности, чтобы администраторы могли составить комплексный план защиты.

## Обзор возможностей безопасности {#security-capability-overview}

<!-- Knowledge type: Capability list -->

Doris обеспечивает безопасность данных с помощью следующих механизмов, охватывающих пять аспектов: идентификацию, авторизацию, данные, передачу данных и аудит.

| Аспект безопасности | Возможность | Описание |
| --- | --- | --- |
| Аутентификация | Встроенная аутентификация | Doris предоставляет встроенную аутентификацию по имени пользователя и паролю с настраиваемыми политиками паролей. |
| Аутентификация | Аутентификация через LDAP | Позволяет централизованно управлять учётными данными пользователей через службу LDAP, упрощая управление доступом и повышая безопасность системы. |
| Авторизация | Управление доступом на основе ролей (RBAC) | Ограничивает доступ к ресурсам базы данных и операции с ними в зависимости от ролей и привилегий пользователя. |
| Авторизация | Авторизация через Ranger | Интеграция с Apache Ranger обеспечивает централизованную авторизацию с детальными политиками управления доступом. |
| Защита данных | Шифрование и маскирование данных | Шифрует и маскирует данные в таблицах, предотвращая утечку конфиденциальных данных при несанкционированном доступе. |
| Защита данных | Детальное управление доступом | Позволяет настраивать права доступа на уровне строк и столбцов на основе правил. |
| Безопасность передачи данных | Протокол шифрования SSL | Защищает передачу данных между клиентом и сервером Doris от перехвата и изменения. |
| Аудит | Журнал аудита | Регистрирует все операции, включая вход пользователей, запросы и изменения данных, для последующего аудита и расследования проблем. |
| Дополнительная безопасность | Безопасность Java UDF | Администратор root должен проверять реализацию пользовательских UDF, чтобы обеспечить безопасность работы и предотвратить опасные операции, например удаление данных или повреждение системы. |
| Дополнительная безопасность | Контроль сторонних пакетов | При добавлении сторонних пакетов с помощью таких возможностей, как JDBC Catalog и UDF, администраторы должны убедиться в безопасности и надёжности их источника. Используйте только официальные каналы или зависимости из доверенных сообществ. |

## Основные понятия {#core-concepts}

<!-- Knowledge type: Concept overview -->

Система авторизации Doris построена по образцу механизма авторизации MySQL. Она поддерживает детальное управление доступом на уровне строк, управление доступом на основе ролей и механизм белого списка. Следующие четыре понятия помогут разобраться в модели аутентификации и авторизации Doris.

### Идентификатор пользователя (User Identity) {#user-identity}

В системе авторизации пользователь определяется идентификатором User Identity. Он состоит из двух частей: `username` и `host`.

- `username`: имя пользователя, состоящее из прописных и строчных английских букв.
- `host`: IP-адрес, с которого подключается пользователь.

User Identity записывается как `username@'host'` и означает пользователя `username`, подключающегося с `host`.

Другая форма записи User Identity — `username@['domain']`, где `domain` — доменное имя, которое DNS может разрешить в набор IP-адресов. В итоге оно представляется набором записей `username@'host'`. Далее используется единая форма записи `username@'host'`.

### Привилегия (Privilege) {#privilege}

Привилегия действует в отношении узла, каталога данных, базы данных или таблицы. Разные привилегии разрешают разные операции.

### Роль (Role) {#role}

Doris позволяет создавать роли с произвольными именами. Роль представляет собой набор привилегий. Новому пользователю можно назначить роль, и он автоматически получит её привилегии. Последующие изменения привилегий роли также отразятся на привилегиях всех пользователей с этой ролью.

### Свойства пользователя (User Property) {#user-property}

Свойства привязаны непосредственно к пользователю, а не к User Identity. Поэтому `user@'192.%'` и `user@['domain']` используют один и тот же набор свойств. Эти свойства принадлежат пользователю `user`, а не отдельным идентификаторам `user@'192.%'` или `user@['domain']`.

Свойства пользователя включают, в частности, максимальное число соединений и настройки кластера загрузки.

## Схема аутентификации и авторизации {#authentication-and-authorization-framework}

<!-- Knowledge type: Architecture selection decision -->
<!-- Applicable scenarios: Authentication and authorization solution selection -->

Процесс входа в Apache Doris состоит из двух этапов: **аутентификации** и **авторизации**.

- **Аутентификация**: проверяет личность пользователя по предоставленным учётным данным, таким как имя пользователя, IP-адрес клиента и пароль. После успешной проверки пользователь сопоставляется с User Identity в системе.
- **Авторизация**: на основе полученного User Identity и соответствующих ему привилегий проверяет, разрешено ли пользователю выполнять запрошенную операцию.

Doris поддерживает два варианта аутентификации: **встроенную аутентификацию** и **аутентификацию через LDAP**. Для авторизации также доступны два варианта: **встроенная авторизация на основе RBAC** и **внешняя авторизация через Apache Ranger**. Варианты аутентификации и авторизации можно свободно сочетать. Например, для аутентификации можно использовать LDAP, а для авторизации — Ranger.

В следующей таблице приведены распространённые сочетания и сценарии их применения:

| Способ аутентификации | Способ авторизации | Сценарий применения |
| --- | --- | --- |
| Встроенная аутентификация | Встроенная RBAC | Небольшой или средний кластер, автономное развёртывание без внешних зависимостей. |
| Аутентификация через LDAP | Встроенная RBAC | Интеграция с корпоративной LDAP/AD при сохранении управления моделью авторизации в Doris. |
| Встроенная аутентификация | Apache Ranger | Существующая система Ranger, используемая для единого управления авторизацией в экосистеме больших данных. |
| Аутентификация через LDAP | Apache Ranger | Рекомендуемый подход для корпоративной среды: единое управление идентификацией, централизованная авторизация и возможность аудита. |
