В этом документе описан контракт конфигурации фреймворка TLS в Apache Doris.

:::note
Фреймворк доступен начиная с Apache Doris 4.1.4. В версии 4.0 этих единых настроек TLS нет.
:::

Пакет Doris с открытым исходным кодом содержит фреймворк, параметры конфигурации, поддержку разбора и точки расширения для TLS и аутентификации на основе сертификатов. Он не содержит полной реализации TLS для каждого протокола. В стандартной сборке с открытым исходным кодом попытка включить TLS для протокола, для которого нет реализации модуля TLS, завершается ошибкой с сообщением о том, что требуется модуль TLS.

Начиная с Apache Doris 5.0, сборка с открытым исходным кодом предоставляет встроенный взаимный TLS для внутренних gRPC/BRPC и блокирующего Thrift. Сведения о подготовке сертификатов, необходимых изменениях конфигурации, согласованном включении и ограничениях протоколов см. в разделе [Шифрование внутренних RPC с помощью взаимного TLS](./private-rpc-tls.md).

Имена параметров конфигурации, значения по умолчанию и их значения, перечисленные ниже, закреплены фреймворком. Если вы предоставляете собственную реализацию модуля TLS, используйте этот фреймворк и эти параметры конфигурации для обеспечения совместимости. Загрузку сертификатов, создание контекста TLS, поведение при установлении соединения, повторную загрузку сертификатов и проверку сертификатов удалённой стороны с учётом протокола может реализовывать модуль TLS.

## Справочник по параметрам конфигурации {#configuration-reference}

Все перечисленные ниже параметры необязательны и используют указанные значения по умолчанию. Задавайте их в `fe.conf` для FE, `be.conf` для BE или конфигурации компонента Cloud Meta Service/Recycler. Считайте их настройками запуска и перезапускайте соответствующий процесс; исключение составляет параметр FE `tls_cert_based_auth_ignore_password`, который можно изменять во время работы. Разверните и проверьте модуль перед включением TLS для поддерживаемых им протоколов.

| Параметр конфигурации | Тип | Компоненты | Значение по умолчанию | Описание | Примечания |
| --- | --- | --- | --- | --- | --- |
| `enable_tls` | Boolean | FE, BE, Cloud | `false` | Включает единый фреймворк TLS для процесса. | При значении `true` протоколы, не исключённые через `tls_excluded_protocols`, должны использовать реализацию TLS, предоставляемую модулем. Все связанные компоненты Doris должны использовать совместимые настройки TLS. |
| `tls_verify_mode` | String | FE, BE, Cloud | `verify_peer` | Управляет проверкой сертификатов. Поддерживаемые значения: `verify_none`, `verify_peer` и `verify_fail_if_no_peer_cert`. | См. [Режимы проверки TLS](#tls-verification-modes). |
| `tls_certificate_path` | String | FE, BE, Cloud | Пусто | Путь к сертификату, который компонент использует в роли сервера или клиента TLS. | Контракт фреймворка предполагает сертификаты в формате PEM. Модуль TLS может поддерживать файл PEM с конечным сертификатом или полной цепочкой сертификатов. |
| `tls_private_key_path` | String | FE, BE, Cloud | Пусто | Путь к закрытому ключу, используемому вместе с `tls_certificate_path`. | Контракт фреймворка предполагает закрытый ключ в формате PEM. |
| `tls_private_key_password` | String | FE, BE, Cloud | Пусто | Пароль для файла закрытого ключа. | Это строка пароля в открытом виде, а не значение в кодировке Base64. |
| `tls_ca_certificate_path` | String | FE, BE, Cloud | Пусто | Путь к сертификату CA или набору сертификатов CA, используемому для проверки сертификата удалённой стороны. | Контракт фреймворка предполагает сертификаты CA в формате PEM. Если значение пусто и условия использования это допускают, модуль TLS также может использовать системные хранилища доверенных сертификатов или хранилища JDK по умолчанию. |
| `tls_cert_refresh_interval_seconds` | Integer | FE, BE, Cloud | `3600` | Интервал в секундах между проверками того, требуется ли повторная загрузка файлов сертификатов. | Фреймворк предоставляет этот интервал. Фактическое поведение при повторной загрузке сертификатов реализует модуль TLS. |
| `tls_excluded_protocols` | String | FE, BE, Cloud | Пусто | Список имён протоколов, которые не должны использовать TLS, разделённых запятыми. Регистр букв при сопоставлении не учитывается. | Доступные имена протоколов зависят от компонента и модуля TLS. Фреймворк с открытым исходным кодом резервирует такие селекторы, как `thrift`, `mysql`, `http`, `arrowflight`, `brpc` и `bdbje`; используйте только селекторы, поддерживаемые вашей реализацией. |
| `tls_peer_cert_required_san_dns` | String | FE, BE, Cloud | Пусто | Список разрешённых DNS-имён из поля DNS Subject Alternative Name сертификата удалённой стороны для отдельных внутренних протоколов. | Синтаксис: `<protocol>=<dns1>,<dns2>;...`. Фреймворк резервирует этот контракт для реализаций модулей, которым требуется контроль допуска по сертификату удалённой стороны. |
| `tls_cert_based_auth_ignore_password` | Boolean | FE | `false` | Позволяет пропустить проверку пароля после успешной аутентификации на основе сертификата. | Влияет только на процессы аутентификации пользователей FE. Включение ослабляет защиту на основе пароля, поэтому этот параметр следует использовать только в развёртываниях, где модуль TLS обеспечивает необходимую аутентификацию по сертификатам. |

## Режимы проверки TLS {#tls-verification-modes}

| Режим | Роль клиента | Роль сервера | Применение |
| --- | --- | --- | --- |
| `verify_none` | Не проверяет сертификат сервера. | Не проверяет сертификат клиента. | Для развёртываний, которым требуется шифрование TLS без проверки сертификатов. |
| `verify_peer` | Проверяет сертификат сервера. | Не требует сертификат клиента. | Для односторонней проверки при TLS. Это значение не требует mTLS. |
| `verify_fail_if_no_peer_cert` | Проверяет сертификат сервера. | Требует сертификат клиента и проверяет его. | Для развёртываний с mTLS, которым требуется взаимная проверка сертификатов. |

## Поведение фреймворка в сборке с открытым исходным кодом {#framework-behavior-in-the-open-source-build}

Фреймворк с открытым исходным кодом предоставляет определения параметров конфигурации и точки расширения. При значении `enable_tls`, равном `false`, провайдеры по умолчанию сохраняют существующее поведение с передачей данных без шифрования.

При значении `enable_tls`, равном `true`, запуск протокола или создание канала проходит через фреймворк TLS. Сборка со встроенным провайдером внутренних RPC может обслуживать поддерживаемые им внутренние протоколы. Если для выбранного протокола нет соответствующей реализации TLS, реализация по умолчанию в сборке с открытым исходным кодом отклоняет запуск TLS для этого протокола и сообщает, что требуется модуль TLS.

Таким образом, приведённая выше таблица задаёт контракт совместимости, а не полное руководство по включению TLS в стандартном пакете с открытым исходным кодом.

## Рекомендации по реализации {#implementation-guidance}

Если вы реализуете собственный модуль TLS, соблюдайте следующие правила:

- Используйте имена параметров конфигурации и их семантику, описанные в этом документе. Не вводите другие имена параметров для одного и того же поведения TLS.
- Обеспечивайте одинаковое поведение общих параметров конфигурации в компонентах FE, BE и Cloud.
- Учитывайте `tls_excluded_protocols`, чтобы пользователи могли выбирать, какие протоколы обрабатывает модуль TLS.
- Реализуйте `tls_verify_mode` согласованно для ролей сервера и клиента.
- Если поддерживается повторная загрузка сертификатов, используйте `tls_cert_refresh_interval_seconds` как интервал проверки.
- Если поддерживается контроль допуска по DNS SAN сертификата удалённой стороны, используйте синтаксис `tls_peer_cert_required_san_dns`, описанный в таблице.
- Для аутентификации на основе сертификатов предоставьте реализацию аутентификации во время работы через точку расширения фреймворка. Без собственной реализации служба по умолчанию в сборке с открытым исходным кодом работает как no-op.
