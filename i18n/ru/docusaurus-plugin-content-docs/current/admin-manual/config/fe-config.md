# Конфигурация FE {#fe-configuration}

В этом документе описаны параметры конфигурации FE.

Файл конфигурации FE `fe.conf` обычно находится в каталоге `conf/` по пути развёртывания FE. В версии 0.14 вводится ещё один файл конфигурации — `fe_custom.conf`. В нём хранятся параметры, которые пользователь динамически изменил и сохранил во время работы системы.

При запуске процесс FE сначала читает параметры из `fe.conf`, затем — из `fe_custom.conf`. Значения из `fe_custom.conf` переопределяют одноимённые значения в `fe.conf`.

Расположение файла `fe_custom.conf` можно задать в `fe.conf` с помощью параметра `custom_config_dir`.

## Просмотр параметров конфигурации {#view-configuration-items}

Просмотреть параметры FE можно двумя способами:

1. Через веб-страницу FE

    Откройте в браузере страницу `http://fe_host:fe_http_port/variable`. Действующие параметры конфигурации FE отображаются в разделе `Configure Info`.

2. Через команду

    После запуска FE параметры можно просмотреть в клиенте MySQL следующей командой. Синтаксис описан в разделе [SHOW-CONFIG](../../sql-manual/sql-statements/cluster-management/instance-management/SHOW-FRONTEND-CONFIG):

    `SHOW FRONTEND CONFIG;`

    Столбцы результата имеют следующий смысл:

    * Key: имя параметра конфигурации.
    * Value: текущее значение параметра.
    * Type: тип значения, например целое число или строка.
    * IsMutable: возможность динамического изменения. Если значение равно true, параметр можно изменить во время работы. Если оно равно false, параметр можно задать только в `fe.conf`; изменение вступит в силу после перезапуска FE.
    * MasterOnly: применяется ли параметр только к узлу Master FE. Значение true означает, что он имеет смысл только на Master FE; значение false — что он имеет смысл на FE любого типа.
    * Comment: описание параметра.

## Настройка параметров {#set-configuration-items}

Начиная с версии 4.1.5 команда `SHOW FRONTEND CONFIG` и интерфейсы экспорта конфигурации заменяют непустые конфиденциальные значения на `********`. Это касается `initial_root_password`, паролей закрытых ключей TLS, паролей HTTPS Key Store и паролей сертификатов MySQL SSL. Пустые значения остаются пустыми, показывая, что параметр не задан. Маскирование не меняет действующую конфигурацию.

Параметры FE можно настроить следующими способами:

1. Статическая настройка

    Добавьте параметры и их значения в файл `conf/fe.conf`. FE считывает их при запуске. Для параметров, отсутствующих в `fe.conf`, используются значения по умолчанию.

2. Динамическая настройка через протокол MySQL

    После запуска FE параметры можно динамически задать следующей командой. Для неё требуются права администратора.

    `ADMIN SET FRONTEND CONFIG (" fe_config_name "=" fe_config_value ");`

    Динамическое изменение поддерживают не все параметры. Проверить его доступность можно по столбцу `IsMutable` в результате команды ` SHOW FRONTEND CONFIG; `.

    Если изменяется параметр `MasterOnly`, команда непосредственно перенаправляется на Master FE и меняет соответствующее значение только на этом узле.

    **Изменения, внесённые таким способом, теряют силу после перезапуска процесса FE.**

    Дополнительную справку по команде можно получить командой `HELP ADMIN SET CONFIG;`.

3. Динамическая настройка через протокол HTTP

    Подробнее см. [Set Config Action](../open-api/fe-http/set-config-action).

    Этот способ также позволяет сохранять изменения. Параметры записываются в файл `fe_custom.conf` и продолжают действовать после перезапуска FE.

## Примеры {#examples}

1. Изменение `async_pending_load_task_pool_size`

    Команда `SHOW FRONTEND CONFIG;` показывает, что этот параметр нельзя изменить динамически (`IsMutable` равно false). Добавьте в `fe.conf`:

    `async_pending_load_task_pool_size = 20`

    Затем перезапустите процесс FE, чтобы изменение вступило в силу.

2. Изменение `dynamic_partition_enable`

    Команда `SHOW FRONTEND CONFIG;` показывает, что параметр можно изменить динамически (`IsMutable` равно true) и что он относится только к Master FE. Подключитесь к любому FE и выполните:

    ```
    ADMIN SET FRONTEND CONFIG ("dynamic_partition_enable" = "true"); `
    ```

    Затем проверьте новое значение:

    ```
    set forward_to_master = true;
    SHOW FRONTEND CONFIG;
    ```

    Если после такого изменения Master FE перезапустится или будут проведены выборы Master, настройка утратит силу. Чтобы сохранить её постоянно, добавьте параметр непосредственно в `fe.conf` и перезапустите FE.

3. Изменение `max_distribution_pruner_recursion_depth`

    Команда `SHOW FRONTEND CONFIG;` показывает, что параметр можно изменить динамически (`IsMutable` равно true) и что он не относится исключительно к Master FE.

    Его также можно изменить командой динамической настройки. Поскольку параметр действует не только на Master FE, для изменения значения на всех FE нужно подключиться к каждому из них отдельно.

## Параметры конфигурации {#configurations}

### Метаданные и кластер {#metadata-and-cluster}

#### `meta_dir` {#meta_dir}

По умолчанию: DORIS_HOME_DIR + "/doris-meta"

Тип: string. Описание: здесь хранятся метаданные Doris. Для этого каталога настоятельно рекомендуется использовать хранилище с:

* высокой скоростью записи (SSD);
* защитой данных (RAID).

#### `catalog_try_lock_timeout_ms` {#catalog_try_lock_timeout_ms}

По умолчанию: 5000 (мс)

IsMutable: true

Время ожидания tryLock для блокировки каталога. Обычно менять его не требуется, кроме случаев тестирования.

#### `datasource_sensitive_property_pattern` {#datasource_sensitive_property_pattern}

Поддержка запланирована для Doris 4.2.0, версии 5.0 и более поздних выпусков. В версиях 4.0, 4.1 и 3.x параметр не поддерживается.

- Тип: string
- IsMutable: true
- MasterOnly: false (локальный параметр FE)
- По умолчанию:

```text
password|passwd|secret|token|credential|access[._-]?key|api[._-]?key
```

Регулярное выражение без учёта регистра для поиска по именам свойств источников данных и параметров запросов URL при маскировании поддерживаемого вывода. Его совпадения объединяются со встроенными и зарегистрированными правилами защиты секретов. Значение `(?!)` отключает только это дополнительное выражение; пустое выражение совпадает с любым именем. Некорректные выражения отклоняются при запуске, загрузке пользовательской конфигурации и изменении параметра во время работы.

Задайте одинаковое значение на каждом FE, обслуживающем запросы. Изменения через SQL во время работы не сохраняются; для сохранения при перезапуске и добавлении новых FE используйте `fe.conf` или документированный механизм постоянной настройки. Примеры, область действия и правила для URI см. в разделе [Маскирование свойств Catalog](../../lakehouse/catalog-property-masking.md#configure-additional-names).

#### `enable_bdbje_debug_mode` {#enable_bdbje_debug_mode}

По умолчанию: false

Если значение равно true, FE запускается в режиме отладки BDBJE.

#### `max_bdbje_clock_delta_ms` {#max_bdbje_clock_delta_ms}

По умолчанию: 5000 (5 с)

Максимально допустимое расхождение часов между узлом FE, не являющимся Master, и хостом Master FE. Проверка выполняется каждый раз, когда такой FE устанавливает соединение с Master FE через BDBJE. Если расхождение превышает это значение, соединение разрывается.

#### `metadata_failure_recovery` {#metadata_failure_recovery}

По умолчанию: false

Если значение равно true, FE сбрасывает группу репликации bdbje, то есть удаляет сведения обо всех узлах, имеющих право участвовать в выборах, и пытается запуститься как Master. Если ни один такой узел не запускается, можно скопировать метаданные на другой узел, установить этот параметр в true и попробовать перезапустить FE.

#### `txn_rollback_limit` {#txn_rollback_limit}

По умолчанию: 100

Максимальное число транзакций, которое bdbje может откатить при попытке повторно присоединиться к группе.

#### `grpc_threadmgr_threads_nums` {#grpc_threadmgr_threads_nums}

По умолчанию: 4096

Число потоков для обработки событий grpc в grpc_threadmgr.

#### `bdbje_replica_ack_timeout_second` {#bdbje_replica_ack_timeout_second}

По умолчанию: 10 (с)

Время ожидания подтверждения от реплики при записи в bdbje. При записи сравнительно больших журналов подтверждение может не поступить вовремя, что приведёт к ошибке записи. В таком случае значение можно увеличить.

#### `bdbje_lock_timeout_second` {#bdbje_lock_timeout_second}

По умолчанию: 5

Время ожидания блокировки при операциях bdbje. Если в журнале FE уровня WARN много записей LockTimeoutException, попробуйте увеличить значение.

#### `bdbje_heartbeat_timeout_second` {#bdbje_heartbeat_timeout_second}

По умолчанию: 30

Время ожидания сигнала активности bdbje между Master и Follower. Значение по умолчанию — 30 секунд, как и в bdbje. При кратковременных проблемах сети или неожиданно долгой сборке мусора Java увеличение значения может снизить частоту ложных срабатываний тайм-аута.

#### `replica_ack_policy` {#replica_ack_policy}

По умолчанию: SIMPLE_MAJORITY

Варианты: ALL, NONE, SIMPLE_MAJORITY

Политика подтверждения реплик в bdbje. Подробнее: <http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.ReplicaAckPolicy.html>

#### `replica_sync_policy` {#replica_sync_policy}

По умолчанию: SYNC

Варианты: SYNC, NO_SYNC, WRITE_NO_SYNC

Политика синхронизации Follower FE в bdbje.

#### `master_sync_policy` {#master_sync_policy}

По умолчанию: SYNC

Варианты: SYNC, NO_SYNC, WRITE_NO_SYNC

Политика синхронизации Master FE в bdbje. Если развёрнут только один Follower FE, установите значение 'SYNC'. Если развёрнуто более 3 Follower FE, можно задать этому и следующему параметру 'replica_sync_policy' значение WRITE_NO_SYNC. Подробнее: <http://docs.oracle.com/cd/E17277_02/html/java/com/sleepycat/je/Durability.SyncPolicy.html>

#### `bdbje_reserved_disk_bytes` {#bdbje_reserved_disk_bytes}

Желаемый верхний предел зарезервированного пространства в байтах, сохраняемого в реплицируемом окружении JE.

По умолчанию: 1073741824

Можно ли изменить динамически: false

Только для узла Master FE: false

#### `ignore_meta_check` {#ignore_meta_check}

По умолчанию: false

IsMutable: true

Если значение равно true, FE, не являющийся Master, игнорирует отставание своих метаданных от Master FE, даже если оно превышает *meta_delay_toleration_second*, и продолжает обслуживать запросы на чтение. Это полезно, когда Master FE требуется остановить на сравнительно долгое время, сохранив чтение через остальные FE.

#### `meta_delay_toleration_second` {#meta_delay_toleration_second}

По умолчанию: 300 (5 мин)

FE, не являющийся Master, прекращает обслуживать запросы, если отставание метаданных превышает *meta_delay_toleration_second*.

#### `edit_log_port` {#edit_log_port}

По умолчанию: 9010

Порт bdbje.

#### `edit_log_type` {#edit_log_type}

По умолчанию: BDB

Тип журнала изменений.
BDB: запись журнала в bdbje.
LOCAL: устаревший вариант.

#### `edit_log_roll_num` {#edit_log_roll_num}

По умолчанию: 50000

IsMutable: true

MasterOnly: true

Master FE сохраняет образ метаданных через каждые *edit_log_roll_num* записей журнала метаданных.

#### `force_do_metadata_checkpoint` {#force_do_metadata_checkpoint}

По умолчанию: false

IsMutable: true

MasterOnly: true

Если значение равно true, поток контрольных точек создаёт их независимо от доли используемой памяти JVM.

#### `metadata_checkpoint_memory_threshold` {#metadata_checkpoint_memory_threshold}

По умолчанию: 60 (60%)

IsMutable: true

MasterOnly: true

Если доля используемой памяти JVM (кучи или области старого поколения) превышает этот порог, поток контрольных точек приостанавливает работу во избежание OOM.

#### `max_same_name_catalog_trash_num` {#max_same_name_catalog_trash_num}

Максимальное число одноимённых объектов метаданных в корзине каталога. При превышении предела самый ранний удалённый объект стирается без возможности восстановления. Значение 0 означает, что одноимённые объекты не сохраняются; значение < 0 снимает ограничение.

Примечание: одинаковые имена сравниваются в определённой области. Для баз данных — в одном кластере; для таблиц — в одной базе данных с тем же идентификатором; для разделов — в одной базе данных и одной таблице с теми же идентификаторами.

По умолчанию: 3

Можно ли изменить динамически: true

Только для узла Master FE: true

#### `cluster_id` {#cluster_id}

По умолчанию: -1

Узлы (FE или BE) с одинаковым идентификатором кластера считаются принадлежащими одному кластеру Doris. Обычно идентификатор — случайное целое число, созданное при первом запуске Master FE. Его также можно задать вручную.

#### `heartbeat_mgr_blocking_queue_size` {#heartbeat_mgr_blocking_queue_size}

По умолчанию: 1024

MasterOnly: true

Размер блокирующей очереди задач проверки активности в heartbeat_mgr.

#### `heartbeat_mgr_threads_num` {#heartbeat_mgr_threads_num}

По умолчанию: 8

MasterOnly: true

Число потоков обработки событий проверки активности в heartbeat_mgr.

#### `disable_cluster_feature` {#disable_cluster_feature}

По умолчанию: true

IsMutable: true

Поддержка нескольких кластеров будет объявлена устаревшей в версии 0.12. Значение true отключает все связанные с ней операции, включая:

1. создание и удаление кластера;
2. добавление свободного BE, добавление BE в кластер и балансировку при выводе кластера из эксплуатации;
3. изменение числа BE в кластере;
4. связывание и миграцию баз данных.

#### `enable_fqdn_mode` {#enable_fqdn_mode}

Параметр предназначен прежде всего для кластеров k8s. При значении true имя pod, в котором находится BE, остаётся прежним после пересоздания, а IP-адрес может измениться.

По умолчанию: false

Можно ли изменить динамически: false

Только для узла Master FE: true

#### `enable_token_check` {#enable_token_check}

По умолчанию: true

Сохраняется для прямой совместимости и впоследствии будет удалён. Проверяет токен при скачивании файла образа.

#### `fe_meta_auth_token` {#fe_meta_auth_token}

По умолчанию: "" (пустая строка)

IsMutable: false

Токен кластера для аутентификации между узлами FE при обращении к HTTP-интерфейсам метаданных FE (`image`, `role`, `check`, `put`, `journal_id` и другим). Добавлен в версии 4.0.8 ветки Doris 4.0 и версии 4.1.4 ветки 4.1.

Если задано непустое значение, помимо существующей проверки хоста узла вызывающая сторона должна передать совпадающий токен в заголовке запроса. Это предотвращает доступ к интерфейсам метаданных FE со стороны узлов вне кластера. Пустое значение сохраняет прежнее поведение — проверку только хоста узла, поэтому существующие кластеры и последовательные обновления не затрагиваются.

:::caution Примечание

Этот параметр должен иметь одинаковое значение на **всех FE** и быть записан в `fe.conf` до включения. Иначе FE будут отклонять запросы метаданных друг от друга, и синхронизация метаданных перестанет работать.

:::

#### `enable_multi_tags` {#enable_multi_tags}

По умолчанию: false

Можно ли изменить динамически: false

Только для узла Master FE: true

Включает несколько тегов для одного BE.

#### `initial_root_password` {#initial_root_password}

Начальный пароль пользователя root в виде двухэтапного SHA-1-хеша. По умолчанию используется пустая строка, то есть пароль root отсутствует. Последующие операции `set password` для root заменяют начальный пароль.

Пример: чтобы задать пароль `root@123` в открытом виде, выполните SQL-запрос Doris `select password('root@123')`. Он создаст хеш `*A00C34073A26B40AB4307650BFB9309D6BFA6999`.

По умолчанию: пустая строка

Можно ли изменить динамически: false

Только для узла Master FE: true

#### `enable_cooldown_replica_affinity` {#enable_cooldown_replica_affinity}

Определяет, следует ли сначала использовать охлаждённую реплику при сканировании. По умолчанию — true.

По умолчанию: true

Можно ли изменить динамически: true

Только для узла Master FE: false

### Службы {#service}

#### `arrow_flight_deferred_query_idle_timeout_second` {#arrow_flight_deferred_query_idle_timeout_second}

По умолчанию: 3600 (секунд)

Можно ли изменить динамически: true

Только для узла Master FE: false

Поддерживается с версии 4.1.5. Запрос Arrow Flight SQL, сканирующий внешние таблицы пакетами, должен сохранять FE Coordinator после возврата `GetFlightInfo`, чтобы BE могли продолжать получать части данных, пока клиент читает результаты через `DoGet`. Параметр ограничивает срок удержания ресурсов таким запросом в неактивном сеансе. Срок отсчитывается от начала запроса и не бывает короче тайм-аута выполнения этого запроса. По истечении срока освобождаются Coordinator, слот очереди Workload Group и запись `active_queries`, но сеанс остаётся открытым и по-прежнему регулируется `wait_timeout`. Значение `0` отключает этот срок.

#### `thrift_server_type` {#thrift_server_type}

Модель обслуживания, используемая службой Thrift в FE. Параметр имеет строковый тип и не зависит от регистра.

При значении 'SIMPLE' используется модель 'TSimpleServer', которая обычно не подходит для рабочей среды и предназначена только для тестирования.

При значении 'THREADED' используется 'TThreadedSelectorServer' — неблокирующая модель ввода-вывода с ведущим и ведомыми Reactor. Она своевременно обрабатывает большое число одновременных запросов на соединение и хорошо работает в большинстве случаев.

При значении `THREAD_POOL` используется `TThreadPoolServer` — блокирующая модель ввода-вывода с пулом потоков для обработки соединений. Число одновременных соединений ограничено размером пула. Если число параллельных запросов можно оценить заранее и допустимы затраты на потоки, модель может работать лучше. Она используется по умолчанию.

#### `drop_backend_after_decommission` {#drop_backend_after_decommission}

По умолчанию: false

IsMutable: true

MasterOnly: true

1. Управляет удалением BE после успешного вывода из эксплуатации. При true узел удаляется после отключения. При false он остаётся в состоянии DECOMMISSION, но не удаляется.

   Это полезно, например, если изначально у каждого BE был один диск, а затем к каждому добавили 2 новых. Поскольку Doris пока не балансирует данные между дисками внутри BE, исходный диск может оставаться значительно более заполненным. Данные можно перераспределить вручную:

   1. Установите параметр в false.
   2. Выведите один BE из эксплуатации: все его данные будут перенесены на другие узлы.
   3. После завершения отмените состояние вывода BE из эксплуатации. Данные начнут возвращаться с других BE и будут равномерно распределяться по его дискам.
   4. Последовательно повторите шаги 2 и 3 для всех BE, чтобы сбалансировать диски на всех узлах.

#### `jetty_server_acceptors` {#jetty_server_acceptors}

По умолчанию: 2

#### `jetty_server_selectors` {#jetty_server_selectors}

По умолчанию: 4

#### `jetty_server_workers` {#jetty_server_workers}

По умолчанию: 0

Эти три параметра задают модель потоков Jetty: пулы acceptors, selectors и workers. Acceptors принимают новые соединения и передают их selectors, которые разбирают сообщения HTTP. Затем workers обрабатывают запросы. Первые два пула работают без блокировок: один поток обслуживает чтение и запись множества сокетов, поэтому потоков требуется немного.

Для большинства проектов достаточно 1–2 потоков acceptors и от 2 до 4 потоков selectors. Workers выполняют блокирующую прикладную логику, часто обращаются к базе данных и требуют больше потоков. Их число зависит от QPS и доли операций ввода-вывода: чем выше QPS, тем больше нужно потоков; чем выше доля ввода-вывода, тем больше потоков ждут и тем больше требуется всего.

Пул рабочих потоков по умолчанию не задан; настройте его при необходимости.

#### `be_exec_version` {#be_exec_version}

Определяет формат сериализации блоков, передаваемых между фрагментами.

Изменения кода иногда меняют формат блока. Для совместимости BE во время последовательного обновления FE передаёт версию данных, определяющую формат передачи.

Например, из 2 BE один после обновления поддерживает последнюю версию $v_1$, а другой — только $v_0$. Пока FE не обновлён, он задаёт всем $v_0, и BE обмениваются данными в старом формате. $ После обновления всех BE обновляют FE: новый FE задаёт $v_1$, и кластер целиком переходит на новый формат данных.

Значение по умолчанию — `max_be_exec_version`. При особой необходимости версию формата можно понизить вручную, но не ниже `min_be_exec_version`.

Значение всегда должно находиться между `BeExecVersionManager::min_be_exec_version` и `BeExecVersionManager::max_be_exec_version` для всех BE. Если обновлённый кластер нужно откатить, сначала понизьте версию FE, затем BE, либо вручную понизьте этот параметр перед понижением версии BE.

#### `max_be_exec_version` {#max_be_exec_version}

#### `min_be_exec_version` {#min_be_exec_version}

#### `resource_group_load_success_quorum` {#resource_group_load_success_quorum}

По умолчанию: пустое значение

Можно ли изменить динамически: true

Только для узла Master FE: true

Добавлен в версии 4.1.4. Задаёт для каждой группы ресурсов (Location Tag узлов BE) **минимальное число реплик, которые должны быть успешно записаны** в этой группе при подтверждении транзакции загрузки.

Значение — список с разделителем-запятой. Каждый элемент имеет формат `<resource_group>:<min_success_replicas>`, где `<min_success_replicas>` — неотрицательное целое число. Например:

```properties
resource_group_load_success_quorum=group_a:2,group_b:1
```

Если при подтверждении транзакции число успешно записанных реплик в настроенной группе меньше заданного значения, подтвердить транзакцию не удаётся. Группы, отсутствующие в настройке, не проверяются. Элементы с неправильным форматом игнорируются, а предупреждение записывается в `fe.log`.

Используйте параметр при размещении в нескольких центрах обработки данных или зонах доступности, чтобы загрузка считалась успешной только после записи нужного числа реплик в указанном центре.

#### `enable_adaptive_random_bucket_load` {#enable_adaptive_random_bucket_load}

По умолчанию: true

Можно ли изменить динамически: true

Только для узла Master FE: true

Добавлен в версии 4.1.4. Включает адаптивную загрузку с произвольным распределением по корзинам.

При включении FE передаёт BE сведения о расположении tablet, а каждый BE определяет набор локальных корзин, для которых он держит основную реплику. Когда объём записи в один tablet превышает порог (по умолчанию 200 MB), запись начинает чередоваться между локальными корзинами. Это снижает расход памяти при загрузке и повышает пропускную способность загрузки таблиц с произвольным распределением (`DISTRIBUTED BY RANDOM`). Правило одинаково применяется ко всем способам загрузки.

Работу также ограничивают параметры BE `enable_table_memtable_flush_backpressure` и `table_memtable_flush_pending_count_limit`. См. [Конфигурация BE](./be-config).

#### `enable_forward_group_commit_stream_load_to_follower` {#enable_forward_group_commit_stream_load_to_follower}

По умолчанию: false

Можно ли изменить динамически: true

Только для узла Master FE: true

     2. Верхний уровень: (AUC * (1 + clone_capacity_balance_threshold)).

     3. Нижний уровень: (AUC * (1 - clone_capacity_balance_threshold)).

     4. Проверяющий компонент клонирования пытается переместить реплики с BE выше верхнего уровня на BE ниже нижнего.

### Режим разделения вычислений и хранения {#compute-and-storage-disaggregated-mode}

#### `cloud_edit_log_roll_interval_second` {#cloud_edit_log_roll_interval_second}

По умолчанию: 3600 (секунд)

Можно ли изменить динамически: true

Поддерживается с версии 4.1.5. Интервал ротации Edit Log по времени в режиме разделения вычислений и хранения. По умолчанию: false

Одноимённый параметр нужно включить и на FE, и на BE. **Начиная с версии 4.0.8 ветки Doris 4.0 и версии 4.1.4 ветки 4.1 интерфейс `_stream_load_forward` на стороне BE управляется параметром BE: когда он отключён, возвращается `403 Forbidden`; когда включён, запросы должны пройти аутентификацию и иметь глобальное право `LOAD`.** См. [Group Commit](../../data-operate/import/load-best-practices/group-commit-manual) и [Конфигурация BE](./be-config).
