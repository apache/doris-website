# Конфигурация BE {#be-configuration}

В этом документе описаны параметры конфигурации BE.

Файл конфигурации BE `be.conf` обычно находится в каталоге `conf/` по пути установки BE. В версии 0.14 появится ещё один файл конфигурации — `be_custom.conf`. В нём сохраняются параметры, которые пользователь изменил динамически во время работы и сделал постоянными.

При запуске процесс BE сначала считывает параметры из `be.conf`, а затем из `be_custom.conf`. Значения из `be_custom.conf` переопределяют одноимённые параметры в `be.conf`.

Расположение файла `be_custom.conf` можно задать в `be.conf` с помощью параметра `custom_config_dir`.

## Просмотр параметров конфигурации {#view-configuration-items}

Параметры конфигурации BE можно просмотреть двумя способами:

1. Веб-страница BE

    Текущие параметры доступны на веб-странице BE:

    `http://be_host:be_webserver_port/varz`

2. Команда

   В клиенте MySQL параметры конфигурации BE можно просмотреть следующей командой. Подробный синтаксис описан в [SHOW-CONFIG](../../sql-manual/sql-statements/cluster-management/instance-management/SHOW-FRONTEND-CONFIG):

    `SHOW BACKEND CONFIG;`

    Столбцы результата имеют следующий смысл:

    1. BackendId: идентификатор backend.
    2. Host: IP-адрес backend.
    3. Key: имя параметра конфигурации.
    4. Value: текущее значение параметра.
    5. Type: тип значения параметра, например целое число или строка.
    6. IsMutable: возможность динамического изменения. Если значение равно true, параметр можно менять во время работы. Если значение равно false, параметр можно задать только в be.conf; он вступит в силу после перезапуска BE.

## Настройка параметров конфигурации {#set-configuration-items}

Параметры конфигурации BE можно задать двумя способами:

1. Статическая настройка

   Добавьте и задайте параметры в файле `conf/be.conf`. При запуске BE считывает параметры из `be.conf`. Для параметров, отсутствующих в `be.conf`, используются значения по умолчанию.

2. Динамическая настройка

   После запуска BE параметры можно динамически задать следующей командой.

    ```
    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}
    ```

   В версии 0.13 и более ранних версиях параметры, изменённые таким способом, перестают действовать после перезапуска процесса BE. В версии 0.14 и более поздних версиях изменения можно сохранить следующей командой. Изменённые параметры сохраняются в файле `be_custom.conf`.

    ```
    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?{key}={value}\&persist=true
    ```

## Примеры {#examples}

1. Статическое изменение `max_base_compaction_threads`

   Добавьте в файл `be.conf`:

   ```max_base_compaction_threads=5```

   Затем перезапустите процесс BE, чтобы настройка вступила в силу.

2. Динамическое изменение `streaming_load_max_mb`

   После запуска BE динамически задайте параметр `streaming_load_max_mb` следующей командой:

    ```
    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024
    ```

   Следующий ответ означает, что настройка выполнена успешно.

    ```
    {
        "status": "OK",
        "msg": ""
    }
    ```

   После перезапуска BE эта настройка перестанет действовать. Чтобы сохранить изменение, используйте следующую команду:

    ```
    curl -X POST http://{be_ip}:{be_http_port}/api/update_config?streaming_load_max_mb=1024\&persist=true
    ```

## Параметры конфигурации {#configurations}

### Службы {#services}

#### `deploy_mode` {#deploy_mode}

* Тип: string
* Описание: Режим работы BE. Значение `cloud` обозначает режим разделения вычислений и хранения.
* Значение по умолчанию: ""

#### `bvar_max_dump_multi_dimension_metric_num` {#bvar_max_dump_multi_dimension_metric_num}

* Тип: string
* Описание: Поддерживается с версии 4.1.5. Максимальное число образцов многомерных метрик bvar, экспортируемых через `/brpc_metrics`. Значение `0` отключает экспорт этих образцов. Для применения изменений требуется перезапуск BE.
* Значение по умолчанию: 5000

#### `be_port` {#be_port}

* Тип: int32
* Описание: Порт сервера Thrift на BE для приёма запросов от FE.
* Значение по умолчанию: 9060

#### `heartbeat_service_port` {#heartbeat_service_port}

* Тип: int32
* Описание: Порт службы heartbeat (Thrift) на BE для приёма сигналов от FE.
* Значение по умолчанию: 9050

#### `webserver_port` {#webserver_port}

* Тип: int32
* Описание: Служебный порт HTTP-сервера на BE.
* Значение по умолчанию: 8040

#### `brpc_port` {#brpc_port}

* Тип: int32
* Описание: Порт BRPC на BE для обмена данными между узлами BE.
* Значение по умолчанию: 8060

#### `arrow_flight_sql_port` {#arrow_flight_sql_port}

* Тип: int32
* Описание: Порт сервера Arrow Flight SQL на BE для обмена данными между Arrow Flight Client и BE.
* Значение по умолчанию: -1

#### `enable_https` {#enable_https}

* Тип: bool
* Описание: Включает поддержку HTTPS. Если она включена, задайте в be.conf параметры `ssl_certificate_path` и `ssl_private_key_path`.
* Значение по умолчанию: false

#### `priority_networks` {#priority_networks}

* Описание: Задаёт правило выбора адреса для серверов с несколькими IP-адресами. Список должен соответствовать не более чем одному IP-адресу. Это разделённый точками с запятой список сетей в нотации CIDR, например 10.10.10.0/24. Если ни один IP-адрес не подходит, адрес выбирается случайно.
* Значение по умолчанию: пустое

#### `storage_root_path` {#storage_root_path}

* Тип: string

* Описание: Корневые каталоги данных, разделённые символом `;`. Для каждого пути можно указать тип носителя HDD или SSD. В конце каждого пути также можно указать ограничение ёмкости, отделив его запятой `,`. Если пользователь не сочетает диски SSD и HDD, способы настройки из примеров 1 и 2 не нужны: достаточно указать каталог хранения. Менять настройку носителя по умолчанию на FE также не требуется.

  Пример 1: `storage_root_path=/home/disk1/doris.HDD;/home/disk2/doris.SSD;/home/disk2/doris`

    - 1./home/disk1/doris.HDD — носитель HDD;
    - 2./home/disk2/doris.SSD — носитель SSD;
    - 3./home/disk2/doris — по умолчанию носитель HDD.

  Пример 2: `storage_root_path=/home/disk1/doris,medium:hdd;/home/disk2/doris,medium:ssd`

    - 1./home/disk1/doris,medium:hdd — носитель HDD;
    - 2./home/disk2/doris,medium:ssd — носитель SSD.

* Значение по умолчанию: ${DORIS_HOME}/storage

#### `heartbeat_service_thread_count` {#heartbeat_service_thread_count}

* Тип: int32
* Описание: Число потоков службы heartbeat на BE. Значение по умолчанию — 1; менять его не рекомендуется.
* Значение по умолчанию: 1

#### `ignore_broken_disk` {#ignore_broken_disk}

* Тип: bool
* Описание: При запуске BE проверяет все пути, заданные в ``storage_root_path``.

    -  `ignore_broken_disk=true`

  Если путь не существует либо файлы по нему нельзя прочитать или записать из-за неисправного диска, путь игнорируется. При наличии других доступных путей запуск продолжается.

    -  `ignore_broken_disk=false`

  Если путь не существует либо файлы по нему нельзя прочитать или записать из-за неисправного диска, запуск прерывается и процесс завершается.

* Значение по умолчанию: false

#### `mem_limit` {#mem_limit}

* Тип: string
* Описание: Ограничивает долю максимальной памяти сервера, которую может использовать процесс BE. Параметр предотвращает чрезмерное потребление памяти BE и должен быть больше 0. Если указано более 100%, используется 100%.
* Значение по умолчанию: 90%

#### `cluster_id` {#cluster_id}

* Тип: int32
* Описание: Идентификатор кластера, к которому принадлежит BE.
    - Обычно FE передаёт это значение BE через heartbeat, поэтому задавать его вручную не нужно. Если принадлежность BE конкретному кластеру Doris подтверждена, значение можно настроить. При этом файл cluster_id в каталоге данных необходимо изменить так, чтобы его значение совпадало с параметром.
* Значение по умолчанию: -1

#### `custom_config_dir` {#custom_config_dir}

* Описание: Расположение файла `be_custom.conf`. По умолчанию он находится в каталоге `conf/`.
    - В некоторых средах развёртывания каталог `conf/` может быть перезаписан при обновлении системы. Тогда сохранённые пользователем изменения конфигурации тоже будут потеряны. Чтобы этого избежать, разместите `be_custom.conf` в другом каталоге.
* Значение по умолчанию: пустое

#### `trash_file_expire_time_sec` {#trash_file_expire_time_sec}

* Описание: Интервал очистки корзины составляет 24 часа. При недостатке места на диске файлы в trash могут храниться меньше срока, заданного этим параметром.
* Значение по умолчанию: 86400

#### `es_http_timeout_ms` {#es_http_timeout_ms}

* Описание: Время ожидания подключения к ES по HTTP.
* Значение по умолчанию: 5000 (ms)

#### `es_scroll_keepalive` {#es_scroll_keepalive}

* Описание: Время удержания es scroll keep-alive.
* Значение по умолчанию: 5 (m)

#### `external_table_connect_timeout_sec` {#external_table_connect_timeout_sec}

* Тип: int32
* Описание: Время ожидания при установлении соединения с внешней таблицей, например таблицей ODBC.
* Значение по умолчанию: 5 секунд

#### `pipeline_status_report_interval` {#pipeline_status_report_interval}

* Описание: Интервал между отчётами профиля.
* Значение по умолчанию: 5 секунд

#### `brpc_max_body_size` {#brpc_max_body_size}

* Описание: Задаёт значение параметра brpc `max_body_size`.

  - Иногда запрос завершается ошибкой, а в журнале BE появляется сообщение `body_size is too large`. Такое возможно при SQL с «multi distinct + no group by + more than 1T of data». Ошибка означает, что размер пакета brpc превышает заданный предел. Увеличение параметра позволяет избежать этой ошибки.

#### `brpc_socket_max_unwritten_bytes` {#brpc_socket_max_unwritten_bytes}

* Описание: Задаёт значение параметра brpc `socket_max_unwritten_bytes`.
  - Иногда запрос завершается ошибкой, а в журнале BE появляется сообщение `The server is overcrowded`. Это означает, что на стороне отправителя накопилось слишком много сообщений в буфере, например когда SQL должен передать большое значение bitmap. Увеличение параметра позволяет избежать этой ошибки.

#### `transfer_large_data_by_brpc` {#transfer_large_data_by_brpc}

* Тип: bool
* Описание: Определяет, следует ли при размере данных Tuple/Block более 1.8G сериализовать запрос protoBuf, поместить данные Tuple/Block во вложение controller и отправить их через HTTP brpc. Это позволяет избежать ошибки при размере запроса protoBuf более 2G: Bad request, error_text=[E1003]Fail to compress request. В прежних версиях данные Tuple/Block во вложении передавались через стандартный baidu_std brpc, но вложения более 2G усекались. При отправке через HTTP brpc ограничения 2G нет.
* Значение по умолчанию: true

#### `brpc_num_threads` {#brpc_num_threads}

* Описание: Задаёт число bthreads для brpc. Значение по умолчанию — 256.
  - Для повышения QPS можно задать большее значение. Дополнительные сведения: `https://github.com/apache/incubator-brpc/blob/master/docs/cn/benchmark.md`
* Значение по умолчанию: 256

#### `thrift_rpc_timeout_ms` {#thrift_rpc_timeout_ms}

* Описание: Время ожидания Thrift по умолчанию.
* Значение по умолчанию: 60000

#### `thrift_client_retry_interval_ms` {#thrift_client_retry_interval_ms}

* Тип: int64
* Описание: Интервал повторных попыток клиента Thrift в BE, позволяющий избежать лавинообразной нагрузки на сервер Thrift в FE; единица измерения — ms.
* Значение по умолчанию: 1000

#### `thrift_connect_timeout_seconds` {#thrift_connect_timeout_seconds}

* Описание: Время ожидания подключения клиента Thrift по умолчанию.
* Значение по умолчанию: 3 (s)

#### `thrift_server_type_of_fe` {#thrift_server_type_of_fe}

* Тип: string
* Описание: Модель обслуживания, используемая службой Thrift на FE. Значение строковое и не зависит от регистра. Оно должно совпадать со значением параметра thrift_server_type на FE. Возможны два значения: `THREADED` и `THREAD_POOL`.

    - `THREADED` обозначает модель неблокирующего ввода-вывода.

    - `THREAD_POOL` обозначает модель блокирующего ввода-вывода.

#### `thrift_max_message_size` {#thrift_max_message_size}

По умолчанию: 100MB

Максимальный размер сообщения, принимаемого сервером Thrift, в байтах. Если сообщение клиента превышает этот предел, сервер Thrift отклоняет запрос и закрывает соединение. Клиент при этом получает ошибку "connection has been closed by peer." В таком случае можно попробовать увеличить этот параметр.

#### `txn_commit_rpc_timeout_ms` {#txn_commit_rpc_timeout_ms}

* Описание: Время ожидания RPC при отправке txn.
* Значение по умолчанию: 60,000 (ms)

#### `txn_map_shard_size` {#txn_map_shard_size}

* Описание: Размер фрагмента txn_map_lock; значение имеет вид 2^n, где n=0,1,2,3,4. Это улучшение повышает производительность управления txn.
* Значение по умолчанию: 128

#### `txn_shard_size` {#txn_shard_size}

* Описание: Размер шарда txn_lock; значение имеет вид 2^n, где n=0,1,2,3,4. Это улучшение повышает производительность отправки и публикации txn.
* Значение по умолчанию: 1024

#### `unused_rowset_monitor_interval` {#unused_rowset_monitor_interval}

* Описание: Интервал очистки устаревших Rowset.
* Значение по умолчанию: 30 (s)

#### `max_client_cache_size_per_host` {#max_client_cache_size_per_host}

* Описание: Максимальное число элементов клиентского кеша на один хост. В BE есть несколько клиентских кешей, но сейчас для них используется единая настройка размера. При необходимости можно задать разные настройки для разных клиентских кешей.
* Значение по умолчанию: 10

#### `string_type_length_soft_limit_bytes` {#string_type_length_soft_limit_bytes}

* Тип: int32
* Описание: Мягкий предел максимальной длины типа String.
* Значение по умолчанию: 1,048,576

#### `big_column_size_buffer` {#big_column_size_buffer}

* Тип: int64
* Описание: При использовании внешней таблицы odbc, если тип столбца исходной таблицы odbc — HLL, CHAR или VARCHAR, а длина значения превышает этот параметр, запрос завершается ошибкой 'column value length longer than buffer length'. Значение параметра можно увеличить.
* Значение по умолчанию: 65535

#### `small_column_size_buffer` {#small_column_size_buffer}

* Тип: int64
* Описание: При использовании внешней таблицы odbc, если тип столбца исходной таблицы odbc отличается от HLL, CHAR и VARCHAR, а длина значения превышает этот параметр, запрос завершается ошибкой 'column value length longer than buffer length'. Значение параметра можно увеличить.
* Значение по умолчанию: 100

### Запросы {#query}

#### `ignore_not_found_file_in_external_table` {#ignore_not_found_file_in_external_table}

* Тип: bool
* Описание: Разрешает считывателям внешних таблиц пропускать отсутствующие файлы. Поддерживает динамическую настройку. Начиная с версии 4.1.5 этот параметр никогда не разрешает отсутствие файлов данных или файлов удаления в зафиксированных снимках Iceberg: даже при значении `true` запрос завершается ошибкой, чтобы не возвращать незаметно неполный снимок.
* Значение по умолчанию: true

#### `parquet_metadata_size_limit` {#parquet_metadata_size_limit}

* Тип: int64
* Описание: Поддерживается с версии 4.1.5. Максимальный размер сериализованных метаданных нижнего колонтитула файла, в байтах, для нативного считывателя Parquet V2. Значение должно быть больше `0`. При превышении возвращается `Parquet v2 footer size ... exceeds metadata limit ...`. Поддерживает динамическую настройку. Для корректных файлов с большими нижними колонтитулами предел можно увеличить с учётом доступной памяти.
* Значение по умолчанию: 268435456 (256 MiB)

#### `fragment_mgr_asynic_work_pool_queue_size` {#fragment_mgr_asynic_work_pool_queue_size}

* Описание: Максимальное число асинхронных задач, обрабатываемых на одном узле.
* Значение по умолчанию: 4096

#### `fragment_mgr_asynic_work_pool_thread_num_min` {#fragment_mgr_asynic_work_pool_thread_num_min}

* Описание: Число потоков для выполнения асинхронных задач. По умолчанию минимальное число потоков — 16.
* Значение по умолчанию: 16

#### `fragment_mgr_asynic_work_pool_thread_num_max` {#fragment_mgr_asynic_work_pool_thread_num_max}

* Описание: Потоки для последующих асинхронных задач создаются динамически; максимум — 512 потоков.
* Значение по умолчанию: 512

#### `doris_scanner_row_num` {#doris_scanner_row_num}

* Описание: Максимальное число строк данных, возвращаемых каждым потоком сканирования за одно выполнение.
* Значение по умолчанию: 16384

#### `doris_scanner_row_bytes` {#doris_scanner_row_bytes}

* Описание: Объём строк, считываемых за одно выполнение фрагмента.
    - Примечание: если в таблице слишком много столбцов и `select *` зависает, можно изменить этот параметр.
* Значение по умолчанию: 10485760

#### `doris_scanner_thread_pool_queue_size` {#doris_scanner_thread_pool_queue_size}

* Тип: int32
* Описание: Длина очереди пула потоков Scanner. При сканировании в Doris каждый Scanner отправляется в пул как задача потока и ожидает выполнения. Когда число отправленных задач превышает длину очереди пула, последующие задачи блокируются до появления свободного места.
* Значение по умолчанию: 102400

#### `doris_scanner_thread_pool_thread_num` {#doris_scanner_thread_pool_thread_num}

* Тип: int32

При очистке исторических Delete Bitmaps в агрегированном диапазоне в режиме разделения вычислений и хранения удаляет записи по ключам от начальной версии включительно до конечной версии не включительно. Значение `false` включает удаление по диапазону. Существующие переключатели и предварительные условия очистки сохраняются.

#### `file_cache_path` {#file_cache_path}

По умолчанию: [{"path":"${DORIS_HOME}/file_cache"}]

#### `async_file_cache_write_max_pending_bytes` {#async_file_cache_write_max_pending_bytes}

* Тип: int64
* Описание: Добавлен в версии 4.1.4. Максимальный общий объём данных, ожидающих асинхронной записи в кеш файлов, в байтах. Запросы записи сверх этого предела отбрасываются: корректность запросов сохраняется, но данные не кешируются. `-1` означает отсутствие ограничения.

#### `enable_cache_read_from_peer` {#enable_cache_read_from_peer}

* Тип: bool
* Описание: Главный переключатель чтения из кеша соседних BE. При промахе локального File Cache сначала выполняется попытка прочитать блок из File Cache другого BE в той же или другой вычислительной группе; чтение из объектного хранилища выполняется, только если блока нет ни на одном BE. Один переключатель управляет чтением внутри группы и между группами; отдельно отключить чтение между группами нельзя. Чтение между группами поддерживается с версии 4.2.0, в которой также удалён параметр `cache_read_from_peer_expired_seconds`. См. [Чтение из кеша соседних узлов](../../compute-storage-decoupled/file-cache/file-cache-peer-read).
* Значение по умолчанию: false (при необходимости включите явно)

#### `enable_peer_s3_race` {#enable_peer_s3_race}

* Тип: bool
* Описание: Добавлен в версии 4.2.0. Определяет, выполняется ли чтение с соседнего узла параллельно с чтением из объектного хранилища; используется результат, полученный первым. Если параметр отключён, чтение последовательное: кандидаты проверяются по одному, а к объектному хранилищу обращаются только после неудачи всех попыток.
* Значение по умолчанию: true
