# ORC {#orc}

В этом документе описана поддержка чтения и записи файлов формата ORC в Doris. Она распространяется на следующие возможности:

* Чтение и запись данных в Catalog.
* Чтение данных с помощью Table Valued Functions.
* Чтение данных с помощью Broker Load.
* Запись данных при выполнении Export.
* Запись данных с помощью Outfile.

## Точность дробной части секунды во временных метках {#timestamp-fractional-second-precision}

Временные метки ORC могут хранить наносекунды, тогда как Doris `DATETIMEV2` и `TIMESTAMPTZ` поддерживают точность до микросекунд. При сканировании Catalog, использовании Table Valued Functions и Broker Load компонент FileScannerV2 округляет дробную часть секунды в ORC до ближайшей микросекунды, округляя значения ровно посередине вверх:

| Значение ORC | Значение Doris |
|---|---|
| `2024-01-01 00:00:00.123456499` | `2024-01-01 00:00:00.123456` |
| `2024-01-01 00:00:00.123456500` | `2024-01-01 00:00:00.123457` |
| `2024-01-01 00:00:00.999999500` | `2024-01-01 00:00:01.000000` |

Это правило применяется при сопоставлении как с `DATETIMEV2`, так и с `TIMESTAMPTZ`, в том числе при переносе в следующую секунду. При декодировании строк, преобразовании статистики и проталкивании предикатов используются согласованные границы. Если точности статистики ORC недостаточно для точного представления границы округления, Doris консервативно расширяет границу отсечения. Если предикат для временной метки, например `!=`, нельзя безопасно представить, Doris пропускает соответствующее условие поиска и вычисляет предикат для декодированных строк. Это может снизить эффективность отсечения для данного предиката, но предотвращает ошибочный пропуск подходящих строк.

## Сопоставление типа UUID {#uuid-type-mapping}

Doris записывает столбец `UUID`, включая элементы UUID, вложенные в ARRAY, MAP или STRUCT, как `BINARY`, содержащий каноническое 16-байтовое значение с порядком байтов от старшего к младшему, и добавляет атрибут `doris.logical_type=uuid`, обозначающий нативный UUID. В ORC нет стандартного типа UUID, поэтому инструменты, отличные от Doris, видят обычный двоичный столбец без семантики UUID. Если свойство ORC `schema` явно задано для OUTFILE, объявляйте столбцы UUID как `binary`: другой тип, например `string`, будет отклонён.

При чтении столбца `BINARY` с атрибутом `doris.logical_type=uuid` восстанавливается нативный тип UUID, в том числе для вложенных элементов и в обоих средствах чтения файлов. Поэтому Table Valued Function сообщает для таких столбцов тип `uuid`, `array<uuid>` или `struct<k:uuid>`. В версии dev тип `BINARY` без этого атрибута сопоставляется с `VARBINARY`, а `STRING` остаётся `STRING`.

Полное описание сопоставления типов при выводе UUID через OUTFILE и EXPORT см. в разделе [Сопоставление типов столбцов в экспортируемых файлах](../../data-operate/export/export-overview.md#column-type-mapping-for-exported-files).

## Поддерживаемые форматы сжатия {#supported-compression-formats}

### Чтение {#reading}

При чтении существующих файлов поддерживаются следующие кодеки:

* uncompressed
* snappy
* lz4
* zstd
* lzo
* zlib

### Запись {#writing}

| Способ записи | Поддерживаемые кодеки |
| --- | --- |
| Hive / Iceberg Catalog | `plain`, `snappy`, `zlib`, `zstd`, `lz4` (начиная с 4.1.3) |
| OUTFILE / EXPORT | `plain`, `snappy`, `zlib`, `zstd` |

`plain` означает отсутствие сжатия. Настройки и значения по умолчанию для записи через Catalog описаны в разделах [Hive Catalog](../catalogs/hive-catalog.mdx) и [Iceberg Catalog](../catalogs/iceberg-catalog.mdx). В OUTFILE / EXPORT кодек выбирается свойством `compress_type`.

## Параметры {#parameters}

### Совместимость временных меток и дат (начиная с 4.1.5) {#timestamp-and-date-compatibility-since-415}

Начиная с версии 4.1.5, ORC `TIMESTAMP` представляет локальное время без часового пояса, а `TIMESTAMP_INSTANT` представляет момент времени и сопоставляется с `TIMESTAMPTZ`. При чтении наносекунды округляются до микросекунд. Значения вне допустимого диапазона и некорректные значения наносекунд вызывают ошибки.

При записи ORC некоторые отрицательные временные метки с дробной частью секунды непосредственно перед эпохой Unix невозможно представить без потери данных. Doris возвращает сообщение `ORC cannot represent pre-epoch timestamp fractions in [-0.999, 0) seconds without data loss; use Parquet for these values`. Для данных, содержащих такие значения, используйте Parquet.

Файлы DATE, записанные с использованием старой кодировки Doris и содержащие даты от `0000-01-01` до `0000-02-28`, требуют явной миграции. См. раздел [Миграция файлов DATE с нулевым годом](../../admin-manual/cluster-management/upgrade.md#year-zero-date-file-migration).

### Переменные сеанса {#session-variables}

* `enable_orc_lazy_mat` (2.1+, 3.0+)

    Определяет, включает ли ORC Reader отложенную материализацию. Значение по умолчанию — true.

* `hive_orc_use_column_names` (2.1.6+, 3.0.3+)

    При чтении типов данных ORC из таблиц Hive Doris по умолчанию считывает данные из столбцов файла ORC, имена которых совпадают с именами столбцов таблицы Hive. Если для этой переменной задано значение `false`, Doris считывает данные из файла ORC в соответствии с порядком столбцов в таблице Hive, независимо от их имён. Это похоже на переменную `orc.force.positional.evolution` в Hive. Параметр применяется только к именам столбцов верхнего уровня и не действует на столбцы внутри Struct.

* `orc_tiny_stripe_threshold_bytes` (2.1.8+, 3.0.3+)

    Если размер Stripe в файле ORC меньше `orc_tiny_stripe_threshold` байт, он считается Tiny Stripe. Для нескольких последовательных Tiny Stripe применяется оптимизация чтения: они считываются за один раз, чтобы сократить число операций ввода-вывода. Чтобы отключить эту оптимизацию, установите значение 0. Значение по умолчанию — 8M.

* `orc_once_max_read_bytes` (2.1.8+, 3.0.3+)

    При оптимизации чтения Tiny Stripe несколько Tiny Stripe объединяются в одну операцию ввода-вывода. Этот параметр задаёт максимальное число байт для каждого запроса ввода-вывода. Не устанавливайте значение меньше `orc_tiny_stripe_threshold`. Значение по умолчанию — 8M.

* `orc_max_merge_distance_bytes` (2.1.8+, 3.0.3+)

    При оптимизации чтения Tiny Stripe два считываемых Tiny Stripe могут располагаться не подряд. Если расстояние между ними превышает значение этого параметра, они не объединяются в одну операцию ввода-вывода. Значение по умолчанию — 1M.

* `orc_tiny_stripe_amplification_factor` (3.1.0+)

    Если в файле ORC много столбцов, а в запросе используется лишь несколько, оптимизация Tiny Stripe может привести к значительному увеличению объёма чтения. Оптимизация чтения Tiny Stripe применяется, когда отношение числа фактически считываемых байт к размеру всего Stripe превышает значение этого параметра. Значение по умолчанию — 0.4, минимальное значение — 0.

* `check_orc_init_sargs_success` (3.1.0+)

    Проверяет успешность проталкивания предикатов ORC; используется для отладки. Значение по умолчанию — false.

### Конфигурация BE {#be-configuration}

* `orc_natural_read_size_mb` (2.1+, 3.0+)

    Максимальное число байт, которое ORC Reader считывает за один раз. Значение по умолчанию — 8 MB.
