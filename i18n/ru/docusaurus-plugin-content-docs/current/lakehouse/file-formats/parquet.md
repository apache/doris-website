# Parquet {#parquet}

В этом документе описана поддержка чтения и записи файлов формата Parquet в Doris. Документ относится к следующим возможностям:

* Чтение и запись данных в Catalog.
* Чтение данных с помощью Table Valued Functions.
* Чтение данных с помощью Broker Load.
* Запись данных при экспорте с помощью Export.
* Запись данных с помощью Outfile.

## Декодирование временных меток INT96 {#int96-timestamp-decoding}

Parquet `INT96` хранит поля даты и времени без указания часового пояса. Поэтому FileScannerV2 по умолчанию сохраняет исходное значение локального времени, не смещая его в соответствии с часовым поясом сеанса SQL. Например, исходное значение `2021-01-01 10:11:00` сохраняется как `10:11:00` при сопоставлении с `DATETIMEV2`, в том числе при сканировании через Catalog, использовании табличных функций и Broker Load.

Это поведение относится только к `INT96`. Значения Parquet `INT64` с логическим типом временной метки по-прежнему обрабатываются в соответствии с семантикой этого типа. Если устаревшие средства записи Hive нормализовали значения `INT96` с учётом известного часового пояса, настройте `hive.parquet.time-zone` в [Hive Catalog](../catalogs/hive-catalog.mdx#timestamp-compatibility). Табличные функции для внешних файлов также принимают это свойство. Другие точки входа FileScannerV2 сохраняют исходное локальное время `INT96`. Исключение составляет Hudi: при сканировании как в нативном режиме, так и через JNI он намеренно сохраняет прежнюю обработку с учётом часового пояса сеанса SQL и игнорирует `hive.parquet.time-zone`.

Когда столбец `INT96` сопоставляется с `TIMESTAMPTZ`, Doris сохраняет момент времени в UTC без применения часового пояса совместимости.

## Сопоставление типа UUID {#uuid-type-mapping}

Поддерживается чтение `FIXED_LEN_BYTE_ARRAY(16)` с логической аннотацией UUID, обычным или словарным кодированием и каноническим порядком байтов от старшего к младшему. В версии dev обычные Parquet TVF и Iceberg Catalog напрямую сопоставляют столбцы с аннотацией UUID с нативным типом `UUID` независимо от прежних настроек сопоставления двоичных типов. В Doris 4.1.5 Parquet TVF по-прежнему возвращают канонические строки UUID или VARBINARY в зависимости от `enable_mapping_varbinary`; в этом выпуске UUID в Iceberg сопоставляется с `VARBINARY(16)`.

При записи столбца Doris типа `UUID`, включая элемент UUID, вложенный в ARRAY, MAP или STRUCT, создаётся `FIXED_LEN_BYTE_ARRAY(16)` с логической аннотацией UUID. Поэтому другие системы, понимающие эту аннотацию, могут восстановить значение как UUID. Версия dev восстанавливает нативный UUID при чтении таких файлов, включая вложенные элементы UUID.

Полное описание сопоставления типов UUID при выводе через OUTFILE и EXPORT см. в разделе [Сопоставление типов столбцов в экспортируемых файлах](../../data-operate/export/export-overview.md#column-type-mapping-for-exported-files).

## Поддерживаемые форматы сжатия {#supported-compression-formats}

### Чтение {#reading}

При чтении существующих файлов поддерживаются следующие кодеки.

* uncompressed
* snappy
* lz4
* zstd
* gzip
* lzo
* brotli

### Запись {#writing}

| Способ записи | Поддерживаемые кодеки |
| --- | --- |
| Hive / Iceberg Catalog | `plain`, `snappy`, `zstd`, `lz4` (начиная с 4.1.3), `gzip` (начиная с 4.2.0) |
| OUTFILE / EXPORT | `plain`, `snappy`, `gzip`, `brotli`, `zstd`, `lz4` |

`plain` означает отсутствие сжатия. Настройки и значения по умолчанию для записи через Catalog описаны в разделах [Hive Catalog](../catalogs/hive-catalog.mdx) и [Iceberg Catalog](../catalogs/iceberg-catalog.mdx). При записи через OUTFILE / EXPORT кодек выбирается с помощью свойства `compress_type`.

## Запись индексов страниц (версия dev) {#writing-page-indexes-dev-version}

Doris может дополнительно записывать метаданные Parquet `ColumnIndex` и `OffsetIndex` при экспорте через OUTFILE или EXPORT, а также при вставке данных в таблицы Hive и Iceberg, хранящиеся в формате Parquet. Средство чтения, поддерживающее эти индексы, может находить подходящие страницы по значению и сохранять соответствие строк между столбцами. Существующие файлы не изменяются.

Перед выполнением оператора записи задайте следующие переменные сеанса. Они действуют только при выводе в Parquet и не включают фильтрацию по индексам страниц при чтении.

| Переменная | Тип | Значение по умолчанию | Поведение |
| --- | --- | --- | --- |
| `enable_parquet_write_page_index` | Boolean | `true` | Записывает индексы страниц в новые файлы Parquet. Для `ColumnIndex` требуется наличие статистики по столбцу; `OffsetIndex` фиксирует расположение страниц данных и позиции строк. |
| `parquet_write_data_page_size` | Integer, байты | `1048576` (1 MiB) | Целевой размер несжатой страницы данных в диапазоне от `1` до `2147483647`. Действует независимо от того, включена ли запись индексов. Не задаёт размер группы строк или страницы словаря. |

Размер страницы является целевым: отдельное значение или пакет записи могут его превысить. Для LZ4 в формате фреймов Hadoop, используемого при выводе `lz4` через Hive/Iceberg, Doris ограничивает этот целевой размер значением `131072` байт (128 KiB), чтобы сохранить совместимость со средствами чтения Hadoop. На вывод Raw LZ4 это ограничение, связанное с кодеком, не распространяется.

Например, подготовив доступный для записи бакет S3 и учётные данные согласно разделу [OUTFILE](../../data-operate/export/outfile.md), можно экспортировать результат запроса с индексами и целевым размером страницы 256 KiB. Замените заполнители параметров хранилища своими значениями:

```sql
SET enable_parquet_write_page_index = true;
SET parquet_write_data_page_size = 262144;

SELECT 1 AS id, 'example' AS label
INTO OUTFILE 's3://example-bucket/export/result_'
FORMAT AS PARQUET
PROPERTIES (
    "s3.endpoint" = "https://s3.example.com",
    "s3.region" = "us-east-1",
    "s3.access_key" = "<access_key>",
    "s3.secret_key" = "<secret_key>"
);
```

Полученные файлы содержат метаданные индексов страниц для столбцов, удовлетворяющих условиям их записи. Для Hive или Iceberg задайте те же переменные в сеансе перед выполнением `INSERT INTO` или `INSERT OVERWRITE`; целевая таблица должна быть заранее настроена для записи в Parquet. Для EXPORT задайте их перед отправкой задания.

По умолчанию запись индексов включена (`true`), что сохраняет существующее поведение средства записи версии dev. Чтобы не включать индексы страниц в последующие выходные файлы, задайте параметр перед записью:

```sql
SET enable_parquet_write_page_index = false;
```

Чтобы восстановить значения по умолчанию в текущем сеансе:

```sql
SET enable_parquet_write_page_index = true;
SET parquet_write_data_page_size = 1048576;
```

Индексы увеличивают объём метаданных и затраты при записи. Страницы меньшего размера могут улучшить выборочное чтение, особенно если значения сгруппированы, но при этом создают больше записей индекса и заголовков страниц. Эффект зависит от средства чтения и распределения данных; включение индексов не гарантирует ускорения запросов. Файлы остаются доступными для чтения и без использования необязательных индексов. Эти настройки не меняют версию формата Parquet или версию страниц данных.

## Параметры {#parameters}

### Совместимость временных меток и дат (начиная с 4.1.5) {#timestamp-and-date-compatibility}

Начиная с 4.1.5, при чтении и записи Parquet сохраняется различие между локальным временем и моментом времени. Логическая временная метка без часового пояса сопоставляется с `DATETIME`, а логическая временная метка с `isAdjustedToUTC=true` — с `TIMESTAMPTZ`. Ни свойство совместимости Catalog, ни `enable_mapping_timestamp_tz=false` в файловой TVF не могут восстановить сопоставление последней с `DATETIME`.

У Parquet INT96 нет аннотации часового пояса, поэтому он определяется как `DATETIME(6)`. Hive Catalog и файловые TVF принимают необязательное свойство `hive.parquet.time-zone` для указания часового пояса средства записи INT96. По умолчанию используется пустая строка, при которой сохраняется локальное время. Укажите часовой пояс IANA или смещение относительно UTC от `-12:00` до `+14:00`. Значения `UTC` и `GMT` принимаются, а короткие обозначения, такие как `CST` и `PRC`, отклоняются. Задавайте это свойство только тогда, когда часовой пояс средства записи известен, например `"hive.parquet.time-zone" = "Asia/Shanghai"`.

Начиная с 4.1.5, значение `enable_int96_timestamps` по умолчанию для Outfile и Export — `false`; при этом записываются логические временные метки INT64. Задавайте `true` только для систем, которым необходим INT96. Для записи в таблицы Hive применяется другой вариант обеспечения совместимости; см. [Hive Catalog](../catalogs/hive-catalog.mdx).

Файлы DATE, записанные с использованием старого кодирования Doris и содержащие даты от `0000-01-01` до `0000-02-28`, требуют миграции с учётом средства, которым они были записаны. Одно лишь обновление средства чтения не может их исправить. См. [Миграция файлов DATE с нулевым годом](../../admin-manual/cluster-management/upgrade.md#year-zero-date-file-migration).

### Переменные сеанса {#session-variables}

* `enable_parquet_lazy_mat` (2.1+, 3.0+)

    Управляет включением отложенной материализации в Parquet Reader. Значение по умолчанию — true.

* `hive_parquet_use_column_names` (2.1.6+, 3.0.3+)

    При чтении данных Parquet из таблиц Hive Doris по умолчанию читает данные из столбцов файла Parquet, имена которых совпадают с именами столбцов таблицы Hive. Если для этой переменной задано `false`, Doris читает данные из файла Parquet в соответствии с порядком столбцов в таблице Hive независимо от их имён. Это аналогично переменной Hive `parquet.column.index.access`. Параметр действует только для имён столбцов верхнего уровня и не влияет на столбцы внутри Struct.

### Конфигурация BE {#be-configuration}

* `parquet_metadata_size_limit` (начиная с 4.1.5)

    Максимальный размер сериализованных метаданных в конце файла для нативного Parquet V2 Reader. По умолчанию составляет `268435456` байт (256 MiB), должен быть больше `0` и допускает изменение без перезапуска. Это ограничение отличается от ограничения размера заголовка страницы. При его превышении возвращается сообщение `Parquet v2 footer size ... exceeds metadata limit ...`. См. [Конфигурация BE](../../admin-manual/config/be-config.md#parquet_metadata_size_limit).

* `enable_parquet_page_index` (2.1.5+, 3.0+)

    Определяет, использует ли Parquet Reader индекс страниц для фильтрации данных. Предназначен только для отладки на случай, если индекс страниц иногда ошибочно отфильтровывает данные. Значение по умолчанию — false.

* `parquet_header_max_size_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении заголовка страницы Parquet. Значение по умолчанию — 1M.

* `parquet_rowgroup_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении группы строк Parquet. Значение по умолчанию — 128M.

* `parquet_column_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении столбца внутри группы строк Parquet. Значение по умолчанию — 8M.
