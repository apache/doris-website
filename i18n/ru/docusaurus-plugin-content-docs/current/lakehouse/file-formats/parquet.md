# Parquet {#parquet}

В этом документе описана поддержка чтения и записи файлов формата Parquet в Doris. Она распространяется на следующие возможности:

* Чтение и запись данных в Catalog.
* Чтение данных с помощью табличных функций.
* Чтение данных с помощью Broker Load.
* Запись данных при выполнении Export.
* Запись данных с помощью Outfile.

## Декодирование меток времени INT96 {#int96-timestamp-decoding}

В Parquet тип `INT96` хранит поля даты и времени без аннотации часового пояса. Поэтому FileScannerV2 по умолчанию сохраняет исходное значение локального времени, не сдвигая его с учётом часового пояса сеанса SQL. Например, исходное значение `2021-01-01 10:11:00` сохраняет время `10:11:00` при сопоставлении с `DATETIMEV2`, в том числе при сканировании Catalog, использовании табличных функций и Broker Load.

Такое поведение применяется только к `INT96`. Значения Parquet `INT64` с логическим типом timestamp по-прежнему обрабатываются в соответствии с семантикой этого логического типа. Если старые средства записи Hive нормализовали значения `INT96` с учётом известного часового пояса, настройте `hive.parquet.time-zone` в [Hive Catalog](../catalogs/hive-catalog.mdx#timestamp-compatibility). Табличные функции для внешних файлов также поддерживают это свойство. Другие точки входа FileScannerV2 сохраняют исходное значение локального времени `INT96`, за исключением Hudi, который намеренно сохраняет прежнее поведение с учётом часового пояса сеанса SQL как при нативном сканировании, так и при сканировании через JNI, и игнорирует `hive.parquet.time-zone`.

Если столбец `INT96` сопоставляется с `TIMESTAMPTZ`, Doris сохраняет момент времени в UTC, не применяя часовой пояс совместимости.

## Сопоставление типа UUID {#uuid-type-mapping}

При чтении поддерживается тип `FIXED_LEN_BYTE_ARRAY(16)` с аннотацией UUID, простым или словарным кодированием и каноническим порядком байтов big-endian. В версии для разработки обычные Parquet TVF и Iceberg Catalog сопоставляют столбцы с аннотацией UUID напрямую с нативным типом `UUID` независимо от устаревших параметров сопоставления двоичных данных. В Doris 4.1.5 Parquet TVF по-прежнему возвращают канонические строки UUID или VARBINARY в зависимости от `enable_mapping_varbinary`; UUID в Iceberg в этой версии сопоставляется с `VARBINARY(16)`.

При записи столбца Doris типа `UUID`, в том числе элемента UUID, вложенного в ARRAY, MAP или STRUCT, используется тип `FIXED_LEN_BYTE_ARRAY(16)` с логической аннотацией UUID, поэтому другие движки, поддерживающие эту аннотацию, восстанавливают значение как UUID. Версия для разработки восстанавливает нативный тип UUID при чтении этих файлов, в том числе для вложенных элементов UUID.

Полное описание сопоставлений UUID при выводе через OUTFILE и EXPORT см. в разделе [Сопоставление типов столбцов для экспортируемых файлов](../../data-operate/export/export-overview.md#column-type-mapping-for-exported-files).

## Параметры {#parameters}

### Совместимость меток времени и дат (начиная с 4.1.5) {#timestamp-and-date-compatibility}

Начиная с 4.1.5, при чтении и записи Parquet сохраняется различие между локальным временем и моментами времени. Логическая метка времени без часового пояса сопоставляется с `DATETIME`; логическая метка времени с `isAdjustedToUTC=true` сопоставляется с `TIMESTAMPTZ`. Ни свойство совместимости Catalog, ни `enable_mapping_timestamp_tz=false` в файловой TVF не позволяют вернуть сопоставление с `DATETIME` для последнего случая.

Тип Parquet INT96 не имеет аннотации часового пояса и определяется как `DATETIME(6)`. Hive Catalog и файловые TVF поддерживают необязательное свойство `hive.parquet.time-zone`, позволяющее указать часовой пояс средства записи INT96. По умолчанию используется пустая строка, что сохраняет локальное время. Используйте часовой пояс IANA или смещение UTC от `-12:00` до `+14:00`. Значения `UTC` и `GMT` принимаются; короткие псевдонимы, такие как `CST` и `PRC`, отклоняются. Задавайте это свойство только в том случае, если часовой пояс средства записи известен, например: `"hive.parquet.time-zone" = "Asia/Shanghai"`.

Начиная с 4.1.5, значение `enable_int96_timestamps` по умолчанию равно `false` для Outfile и Export, которые записывают логические метки времени INT64. Устанавливайте значение `true` только для потребителей, которым требуется INT96. При записи в таблицы Hive используется другой подход к совместимости; см. [Hive Catalog](../catalogs/hive-catalog.mdx).

Файлы DATE, записанные с использованием старого кодирования Doris и содержащие значения от `0000-01-01` до `0000-02-28`, требуют миграции с учётом средства, которым они были записаны. Одно лишь обновление средства чтения не исправит эти файлы. См. [Миграция файлов DATE с нулевым годом](../../admin-manual/cluster-management/upgrade.md#year-zero-date-file-migration).

### Переменные сеанса {#session-variables}

* `enable_parquet_lazy_mat` (2.1+, 3.0+)

    Определяет, включает ли Parquet Reader ленивую материализацию. Значение по умолчанию: true.

* `hive_parquet_use_column_names` (2.1.6+, 3.0.3+)

    При чтении данных Parquet из таблиц Hive Doris по умолчанию читает данные из столбцов файла Parquet, имена которых совпадают с именами столбцов таблицы Hive. Если эта переменная установлена в `false`, Doris читает данные из файла Parquet в соответствии с порядком столбцов в таблице Hive независимо от их имён. Аналогичным образом работает переменная `parquet.column.index.access` в Hive. Этот параметр применяется только к именам столбцов верхнего уровня и не действует на столбцы внутри структур Struct.

### Конфигурация BE {#be-configuration}

* `parquet_metadata_size_limit` (начиная с 4.1.5)

    Максимальный размер сериализованных метаданных footer для нативного Parquet V2 Reader. Значение по умолчанию: `268435456` байт (256 MiB); оно должно быть больше `0` и может обновляться динамически. Это ограничение задаётся отдельно от ограничения Page Header. При его превышении возвращается сообщение `Parquet v2 footer size ... exceeds metadata limit ...`. См. [Конфигурация BE](../../admin-manual/config/be-config.md#parquet_metadata_size_limit).

* `enable_parquet_page_index` (2.1.5+, 3.0+)

    Определяет, использует ли Parquet Reader Page Index для фильтрации данных. Параметр предназначен только для отладки на случай, если индекс страниц иногда фильтрует данные некорректно. Значение по умолчанию: false.

* `parquet_header_max_size_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении заголовка страницы Parquet. Значение по умолчанию: 1M.

* `parquet_rowgroup_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении группы строк Parquet. Значение по умолчанию: 128M.

* `parquet_column_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении столбца в группе строк Parquet. Значение по умолчанию: 8M.
