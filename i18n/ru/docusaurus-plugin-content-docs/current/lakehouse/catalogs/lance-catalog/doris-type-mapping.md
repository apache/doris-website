В следующей таблице описано сопоставление типов при чтении для Lance Catalog и табличных функций (TVF) для файлов Lance в Doris 4.2 (`branch-4.2`). Doris не поддерживает запись в Lance.

| Тип Lance / Arrow | Тип Doris | Описание |
|---|---|---|
| `null` (поле, допускающее NULL) | `NULL` | Все значения равны SQL NULL; поля типа Null, не допускающие NULL, не поддерживаются |
| `duration(s/ms/us/ns)` | `BIGINT` | Сохраняет числовое значение со знаком в указанной единице измерения; не приводит его к секундам |
| `bool` | `BOOLEAN` | |
| `int8` | `TINYINT` | |
| `uint8` | `SMALLINT` | Целое число без знака, расширенное без потерь |
| `int16` | `SMALLINT` | |
| `uint16` | `INT` | Целое число без знака, расширенное без потерь |
| `int32` | `INT` | |
| `uint32` | `BIGINT` | Целое число без знака, расширенное без потерь |
| `int64` | `BIGINT` | |
| `uint64` | `LARGEINT` | Целое число без знака, расширенное без потерь |
| `float16` | `FLOAT` | Расширяется до 32-битного значения с плавающей точкой |
| `float32` | `FLOAT` | |
| `float64` | `DOUBLE` | |
| `decimal128(P,S)` | `DECIMAL(P,S)` | Максимальная точность: 38 |
| `decimal256(P,S)` | `DECIMAL(P,S)` | Максимальная точность: 76 |
| `utf8`, `large_utf8` | `STRING` | |
| Расширение `arrow.json` | `JSON` | Требует хранения в формате `utf8` или `large_utf8` |
| Расширение `lance.json` | `JSON` | Требует хранения в формате `large_binary`; считывается как логический тип JSON |
| Расширение `lance.bfloat16` | `FLOAT` | Требует хранения в формате `fixed_size_binary(2)`; расширяется до Float32 без потери точности |
| `binary`, `large_binary` | `VARBINARY(2147483647)` | |
| `fixed_size_binary(N)` | `VARBINARY(N)` | Сохраняет фиксированную длину в байтах |
| `date32(day)`, `date64(ms)` | `DATE` | Значение `date64` должно соответствовать полному календарному дню |
| `time32(s)` | `TIME(0)` | |
| `time32(ms)` | `TIME(3)` | |
| `time64(us)`, `time64(ns)` | `TIME(6)` | Наносекундная точность усекается до микросекунд |
| Без часового пояса: `timestamp(s)` | `DATETIME(0)` | Не преобразуется с учётом часового пояса сеанса |
| Без часового пояса: `timestamp(ms)` | `DATETIME(3)` | Не преобразуется с учётом часового пояса сеанса |
| Без часового пояса: `timestamp(us)`, `timestamp(ns)` | `DATETIME(6)` | Наносекундная точность усекается до микросекунд |
| С часовым поясом: `timestamp` | `TIMESTAMPTZ(P)` | Сохраняет момент времени и отображает его в часовом поясе сеанса Doris |
| `struct` | `STRUCT` | Дочерние поля сопоставляются рекурсивно |
| `list`, `large_list`, `fixed_size_list` | `ARRAY` | Типы элементов сопоставляются рекурсивно |
| `map` | `MAP` | Типы ключей и значений сопоставляются рекурсивно |

## Примечания по использованию {#usage-notes}

Точность временных меток `P` составляет 0 для секунд, 3 для миллисекунд и 6 для микросекунд или наносекунд. В отличие от сопоставлений наносекундных временных меток Iceberg/Paimon, наносекундные временные метки Lance по-прежнему сопоставляются с `DATETIME(6)` или `TIMESTAMPTZ(6)` и усекаются до микросекунд. Для десятичных типов должны выполняться условия `1 <= P <= 76` и `0 <= S <= P`; отрицательные значения масштаба не поддерживаются.

Doris распознаёт эти расширения по метаданным `ARROW:extension:name` и проверяет их типы хранения. Расширения JSON сопоставляются с типом Doris `JSON` (внутреннее представление: `JSONB`). Обычный столбец `utf8`/`large_utf8`, содержащий текст JSON, по-прежнему сопоставляется с `STRING`; его содержимое не меняет его тип автоматически. Поддержка чтения JSON не подразумевает проталкивания произвольных выражений пути JSON; поддерживаемые формы предикатов необходимо проверять отдельно.

Для чтения JSON, Duration, Null и BFloat16 требуется поддержка соответствующих типов как в FE, так и в BE, обслуживающих запрос. Более старые сборки могут по-прежнему сообщать, что эти типы не поддерживаются; при обновлении проверяйте определение схемы и фактическое чтение данных.

В настоящее время следующие типы не поддерживаются:

- Поля Arrow `null`, не допускающие NULL.
- Типы расширений Arrow/Lance, не указанные как поддерживаемые, например Lance Blob v2; известные расширения с несовместимыми типами хранения также не поддерживаются.
- Сложные типы, дочерние типы которых невозможно сопоставить рекурсивно.
- Типы Arrow Dictionary, сохраняющие маркер Dictionary.

Для неподдерживаемого столбца верхнего уровня и `DESC` для таблицы Catalog, и `DESC FUNCTION` для табличной функции файла Lance сохраняют столбец и отображают `unknown type: UNSUPPORTED_TYPE`. Если любой дочерний тип сложного типа невозможно сопоставить, весь сложный столбец верхнего уровня помечается как неподдерживаемый. В запросах по-прежнему можно выбирать только поддерживаемые столбцы. Doris сообщает об ошибке на этапе анализа, если SQL-запрос выбирает неподдерживаемый столбец. Например:

```sql
SELECT * EXCEPT(blob_col)
FROM lance_catalog.default.all_types;
```

:::note
Некоторые версии Lance Java SDK могут терять маркер Dictionary при чтении Schema и представлять столбец Dictionary как его физический тип индекса. Такое поведение не означает, что Doris поддерживает логические значения Dictionary, и полагаться на него нельзя.
:::
