Doris поддерживает доступ к метаданным таблиц Paimon через различные службы метаданных, а также чтение и запись данных Paimon.

[Быстрый старт с Apache Doris и Apache Paimon](../best-practices/doris-paimon.md).

## Сценарии применения {#applicable-scenarios}

| Сценарий     | Описание                                                  |
| ------------ | ------------------------------------------------------------ |
| Ускорение запросов | Используйте распределённый вычислительный движок Doris для прямого доступа к данным Paimon и ускорения запросов. |
| Интеграция данных   | Читайте данные Paimon и записывайте их во внутренние таблицы Doris или выполняйте операции ZeroETL с помощью вычислительного движка Doris. |
| Обратная запись данных    | Используйте Doris SQL для создания и изменения таблиц Paimon, добавления или перезаписи данных, а также изменений на уровне строк в таблицах с первичным ключом. |

## Настройка Catalog {#configuring-catalog}

### Синтаксис {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = '<paimon_catalog_type>',
    'warehouse' = '<paimon_warehouse>'
    {MetaStoreProperties},
    {StorageProperties},
    {PaimonProperties},
    {CommonProperties}
);
```

* `<paimon_catalog_type>`

  Тип Paimon Catalog. Поддерживаются следующие варианты:

  * `filesystem`: По умолчанию. Прямой доступ к метаданным, хранящимся в файловой системе.

  * `hms`: Использование Hive Metastore в качестве службы метаданных.

  * `dlf`: Использование Alibaba Cloud DLF в качестве службы метаданных.

  * `jdbc`: Подключение к реляционной базе данных через интерфейс JDBC для использования в качестве службы метаданных (поддерживается начиная с версии 4.1.0).

* `<paimon_warehouse>`

  Путь к хранилищу Paimon. Этот параметр обязателен, когда `<paimon_catalog_type>` имеет значение `filesystem`.

  Путь `warehouse` должен указывать на уровень выше пути `Database`. Например, если путь к таблице: `s3://bucket/path/to/db1/table1`, то значение `warehouse` должно быть: `s3://bucket/path/to/`.

* `{MetaStoreProperties}`

  В разделе MetaStoreProperties указываются сведения для подключения и аутентификации в службе метаданных Metastore. Подробности см. в разделе [Поддерживаемые службы метаданных].

* `{StorageProperties}`

  В разделе StorageProperties указываются сведения для подключения и аутентификации в системе хранения. Подробности см. в разделе [Поддерживаемые системы хранения].

* `{PaimonProperties}`

  В разделе PaimonProperties указываются свойства, относящиеся к Paimon.

  При доступе к метаданным Paimon Doris частично использует Paimon Java SDK, поэтому некоторые пользовательские параметры может потребоваться передать в Paimon Java SDK. Для этого можно использовать следующие префиксы:

  ```
  paimon.s3.xxx
  paimon.s3a.xxx
  paimon.fs.xxx
  ```

  Эти параметры будут автоматически преобразованы и переданы далее. Несколько примеров:

  | Входной параметр | Преобразованный параметр для Paimon Java SDK |
  | --- | --- |
  | "paimon.s3.list.version" = "1" | "fs.s3a.list.version" = "1" |
  | "paimon.s3.paging.maximum" = "100" | "fs.s3a.paging.maximum" = "100" |
  | "paimon.fs.s3.read.ahead.buffer.size" = "1" | "fs.s3a.read.ahead.buffer.size" = "1" |
  | "paimon.s3a.replication.factor" = "3" | "fs.s3a.replication.factor" = "3" |

  **Параметры чтения Paimon**

  Doris поддерживает следующие параметры пакетного чтения ограниченного набора данных Paimon. Задавайте значения по умолчанию для запросов во всём Catalog с помощью
  `paimon.table-option.<option-key>` или переопределяйте их для отдельной ссылки на таблицу с помощью
  `table@options('<option-key>'='<value>')`. Эти настройки влияют только на чтение в Doris и никогда не изменяют физические
  метаданные таблицы Paimon.

  | Параметр Paimon | Значение по умолчанию в Paimon | Значения, принимаемые Doris | Действие |
  | --- | --- | --- | --- |
  | `read.batch-size` | `1024` | Целое число от `1` до `65536` | Число строк, запрашиваемых в каждом пакете средства чтения Paimon JNI. Явно заданное значение сохраняется при открытии средства чтения в Doris. |
  | `file-reader-async-threshold` | `10 MB` | Размер памяти от `1 MB` до `1 GB` | Порог размера файла, при котором средство чтения Paimon JNI переключается на асинхронное чтение. |
  | `file-index.read.enabled` | `true` | Логическое значение | Включает отсечение данных по файловым индексам Paimon при чтении. |
  | `source.split.target-size` | `128 MB` | Положительный размер памяти | Целевой размер, используемый Paimon при объединении файлов данных в блоки сканирования Doris. |
  | `source.split.open-file-cost` | `4 MB` | Неотрицательный размер памяти | Оценка стоимости открытия файла при объединении файлов Paimon в блоки сканирования. |
  | `scan.manifest.parallelism` | Число доступных процессоров | Целое число от `1` до `256` | Запрашиваемый параллелизм чтения манифестов. Во время выполнения Doris независимо ограничивает каждую ветвь планирования наименьшим из следующих значений: это значение, `256` и число процессоров, доступных соответствующему FE или BE. |
  | `scan.plan-sort-partition` | `false` | Логическое значение | Сортирует разделы при планировании сканирования Paimon. |

  Например, следующие настройки Catalog переопределяют значения, хранящиеся в физической таблице Paimon, и становятся
  значениями по умолчанию для запросов Doris:

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.table-option.read.batch-size" = "4096",
      "paimon.table-option.file-reader-async-threshold" = "32 MB",
      "paimon.table-option.source.split.target-size" = "64 MB",
      "paimon.table-option.scan.manifest.parallelism" = "1"
  );
  ```

  Запрос может переопределить эти значения по умолчанию без изменения Catalog или метаданных таблицы Paimon:

  ```sql
  SELECT *
  FROM paimon_hms.db_name.table_name@options(
      'read.batch-size' = '8192',
      'source.split.target-size' = '32 MB'
  );
  ```

  У каждой ссылки на таблицу есть независимый набор параметров. Например, два псевдонима одной таблицы могут использовать разные
  размеры пакета в одном операторе:

  ```sql
  SELECT small.id
  FROM paimon_hms.db_name.table_name@options('read.batch-size' = '1') small
  JOIN paimon_hms.db_name.table_name@options('read.batch-size' = '8192') large
    ON small.id = large.id;
  ```

  Приоритет от высшего к низшему:

  ```text
  relation @options > Doris Catalog property > physical Paimon table option > Paimon default
  ```

  Doris проверяет итоговое значение после применения этого порядка приоритетов. Поэтому допустимое значение в Catalog или ссылке на таблицу может
  заменить недопустимое значение физической таблицы. Если итоговое значение по-прежнему недопустимо, Doris отклоняет запрос до начала
  соответствующего этапа планирования или чтения. Ограничения для манифестов также применяются до планирования манифестов для разделов, сбора числа строк и статистики,
  резервных ветвей и системных таблиц.

  Первые пять параметров в таблице не влияют на метаданные и позволяют повторно использовать кэшированную проекцию разделов для последнего снимка.
  `scan.manifest.parallelism` и `scan.plan-sort-partition` влияют на планирование метаданных, поэтому Doris выполняет планирование с учётом
  действующего дескриптора таблицы для конкретной ссылки на неё. Значения, заданные для отдельного запроса, не изменяют размер глобального для JVM исполнителя Paimon.

  Doris отклоняет неизвестные или недопустимые свойства `paimon.table-option.*` при выполнении `CREATE CATALOG` и `ALTER CATALOG`.
  `ALTER CATALOG` проверяет всю предлагаемую конфигурацию перед её применением, поэтому при неудачном изменении
  продолжает действовать прежняя конфигурация Catalog. Catalog, сохранённые более ранней версией Doris, по-прежнему можно загрузить, но
  неподдерживаемые или недопустимые устаревшие свойства чтения игнорируются и не применяются. Их сохранённые значения
  сохраняются для совместимости с образами состояния и журналом изменений.

  Параметры снимка и начальной позиции выбирают контекст ссылки на таблицу и должны задаваться через `@options`, как описано в разделе
  [Time Travel](#time-travel-with-options); их нельзя использовать как значения по умолчанию для Catalog. Doris также исключает
  `scan.max-splits-per-task`, который относится к перечислителю источника Flink в Paimon, `scan.fallback-branch`, а также параметры потоковой обработки,
  размещения данных, записи и компактации. Настраивайте Bucket, Primary Key, Partition, Merge Engine и другие физические
  характеристики через свойства таблицы Paimon, в том числе с помощью Doris `CREATE TABLE ... PROPERTIES`.

  :::info Согласованность в пределах оператора
  В пределах одного оператора Doris использует один и тот же снимок и одно поколение таблицы Paimon для привязки схемы, загрузки разделов, сбора числа строк и статистики, планирования системных таблиц
  и сканирования данных. Снимок или тег, выбранный через
  `@options`, использует схему, соответствующую этой исторической версии, включая вложенные поля `STRUCT`, `MAP` и `ARRAY`.
  Каждое выполнение подготовленного оператора получает новое состояние оператора, поэтому изменения, зафиксированные между выполнениями,
  видны в соответствии с селекторами и настройками кэша нового выполнения.
  :::

  Для безопасной эксплуатации сообщения DEBUG о конфигурации сканера Paimon содержат только размер пакета и число проецируемых
  полей. Doris не выводит полную карту параметров сканера, которая может содержать учётные данные. Показатель профиля
  `PaimonJniAsyncReaderThreadCount` опрашивается раз в секунду для всех сканеров, поэтому его значение может отставать на одну
  секунду. Этот опрос не влияет на выполнение или планирование запросов. Очистка ресурсов средства чтения и IOManager
  выполняется независимо и допускает безопасное повторение после частичного сбоя закрытия.

  **Paimon JNI IOManager**

  Для таблиц Paimon с первичным ключом чтение со слиянием через JNI может требовать сортировки и слияния данных из нескольких файлов. Можно включить
  Paimon IOManager, чтобы этот процесс мог выгружать промежуточные данные на локальный диск BE. Это снижает
  нагрузку на память при чтении со слиянием больших объёмов данных.

  | Свойство | Обязательно | По умолчанию | Описание |
  | --- | --- | --- | --- |
  | `paimon.jni.enable_jni_io_manager` | Нет | `false` | Включает Paimon IOManager для чтения через JNI. Остальные свойства IOManager действуют только тогда, когда это свойство имеет значение `true`. |
  | `paimon.jni.io_manager.tmp_dir` | Нет | `<storage_root_path>/paimon_jni_scanner_io_tmp` | Локальные каталоги, используемые Paimon IOManager для временных файлов выгрузки. Несколько каталогов можно разделять запятыми или двоеточиями. Если свойство не задано, Doris создаёт по одному каталогу в каждом пути хранения BE. |
  | `paimon.jni.io_manager.impl_class` | Нет | Реализация Paimon по умолчанию | Полное имя класса пользовательской реализации `org.apache.paimon.disk.IOManager`. Класс должен быть доступен в classpath сканера Paimon JNI на каждом BE. |

  Следующий пример включает IOManager и позволяет Doris выбрать временные каталоги на основе путей хранения BE:

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.jni.enable_jni_io_manager" = "true"
  );
  ```

  Включение IOManager не приводит к выгрузке на диск при каждом чтении со слиянием. Paimon выгружает данные только тогда, когда число средств чтения для слияния
  превышает его `sort-spill-threshold`. Это не динамический параметр чтения Doris. Настраивайте его в физической таблице Paimon,
  если требуется изменить поведение выгрузки.

  Чтобы использовать выделенные диски для выгрузки, задайте локальные пути, которые существуют или могут быть созданы на каждом BE:

  ```sql
  "paimon.jni.io_manager.tmp_dir" = "/mnt/ssd1/paimon_io:/mnt/ssd2/paimon_io"
  ```

  Doris создаёт IOManager для каждого сканера JNI и закрывает его вместе со сканером. Убедитесь, что настроенные
  каталоги доступны для записи и имеют достаточно места для параллельных запросов. Если настроен класс пользовательской реализации,
  он должен предоставлять открытый конструктор, принимающий `String[]`, открытый конструктор, принимающий
  `String`, или открытый конструктор без аргументов. Ошибка загрузки класса или создания его экземпляра приводит к сбою запроса.

  Эти свойства влияют только на чтение таблиц данных Paimon через JNI. На нативное чтение они не влияют. Параметр
  `paimon.table-option.file-reader-async-threshold` действует независимо: он управляет порогом асинхронного
  чтения файлов Paimon и не включает IOManager и не настраивает каталоги выгрузки.

* `{CommonProperties}`

  В разделе CommonProperties указываются общие свойства. См. раздел [Общие свойства] в [Обзоре Catalog](../catalog-overview.md).
  
## Кэш метаданных {#meta-cache}

Для повышения производительности доступа к внешним источникам данных Apache Doris кэширует метаданные Paimon. К метаданным относятся схемы таблиц для определённых снимков, идентификатор последнего снимка и производные проекции разделов.

:::tip
В версиях до Doris 4.1.x кэширование метаданных в основном управляется глобальными параметрами конфигурации FE. Подробности см. в разделе [Кэш метаданных](../meta-cache.md).
Начиная с Doris 4.1.x внешний кэш метаданных Paimon Catalog настраивается с помощью унифицированных ключей `meta.cache.*`. Ниже описаны компоненты кэша текущей версии; в Doris 4.1.x и 4.2.x используется другой набор компонентов, описанный в версии 4.x этой страницы.
:::

### Настройка свойств кэша {#meta-cache-unified-model}

Каждый компонент кэша использует унифицированный формат ключа конфигурации: `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}`. Для Paimon значение `<engine>` равно `paimon`. Параметр `meta.cache.paimon.table.ttl-second` управляет TTL кэша последнего снимка и кэша схем таблиц.

| Свойство | Пример | Значение |
|---|---|---|
| `enable` | `true/false` | Включает этот компонент кэша. |
| `ttl-second` | `600`, `0`, `-1` | `0` отключает компонент (вступает в силу немедленно, можно использовать для просмотра последних данных); `-1` означает отсутствие срока действия; другие положительные целые числа задают TTL в секундах с момента обращения. |
| `capacity` | `10000` | Максимальное число записей в кэше. `0` отключает компонент. |
| `max-weight` | `1GB` | Поддерживается начиная с Doris 4.1.4. Необязательное ограничение оценочного объёма памяти, удерживаемой компонентом кэша. Должно быть положительным; `0` отклоняется. Принимается только компонентами, отмеченными ниже. |

**Условия действия:** Компонент действует при `enable=true`, `ttl-second != 0` и `capacity > 0`. Ограничение памяти на уровне всего FE, Catalog или отдельного компонента дополнительно регулирует добавление записей по оценочному объёму памяти; см. [Управление памятью внешнего кэша метаданных](../external-meta-cache-memory-management).

### Модули кэша {#meta-cache-unified-modules}

Следующий компонент имеет собственные ключи конфигурации и принимает `max-weight`:

| Компонент (`<entry>`) | Префикс ключа свойства | `ENTRY_NAME` | Кэшируемое содержимое и влияние | Включение / TTL / ёмкость по умолчанию |
|---|---|---|---|---|
| `partition_view` | `meta.cache.paimon.partition_view.` | `paimon.partition-view` | Проекции разделов, полученные из снимка таблицы. Влияние: сокращает повторное сканирование разделов при планировании. | `true` / 86400 с / 1000 |

Следующие кэши не имеют токена `<entry>` и подчиняются только ограничениям памяти на уровне Catalog и всего FE:

| `ENTRY_NAME` | Кэшируемое содержимое | TTL / ёмкость |
|---|---|---|
| `paimon-schema-at` | Схема таблицы для определённого снимка | Без срока действия / 10000 |
| `paimon-latest-snapshot` | Идентификатор последнего снимка таблицы | `meta.cache.paimon.table.ttl-second` (86400 с) / 1000 |

Схема столбцов таблиц Paimon кэшируется общим движком `default` (`meta.cache.default.schema.*`).

### Сопоставление и преобразование устаревших параметров {#meta-cache-mapping}

| Устаревший ключ свойства | Унифицированный ключ | Описание |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.default.schema.ttl-second` | Срок действия кэша схем таблиц |

### Рекомендации {#meta-cache-best-practices}

* **Доступ к последним данным в реальном времени**: Чтобы каждый запрос видел последний снимок таблиц Paimon, установите `meta.cache.paimon.table.ttl-second` в `0`.
  ```sql
  -- Disable the latest-snapshot cache to detect the latest snapshots of Paimon tables
  ALTER CATALOG paimon_ctl SET PROPERTIES ("meta.cache.paimon.table.ttl-second" = "0");
  ```
* **Оптимизация производительности**: Успешное изменение свойств Catalog удаляет затронутые кэши метаданных и пересоздаёт их с новой конфигурацией при следующем обращении. Изменение `meta.cache.max-weight` или `schema.cache.ttl-second` удаляет все кэши Catalog; изменение `meta.cache.<engine>.<entry>.*` удаляет кэши соответствующего движка. Уже выполняющиеся запросы не затрагиваются. Когда действует ограничение памяти на уровне всего FE или Catalog, собственный `CachingCatalog` SDK Paimon по умолчанию отключается, чтобы избежать второго, неучтённого кэша метаданных; явно заданное свойство `paimon.cache-enabled` имеет приоритет.

### Наблюдаемость {#meta-cache-unified-observability}

Метрики кэша доступны в системной таблице `information_schema.catalog_meta_cache_statistics`. В `ENTRY_NAME` отображаются имена, перечисленные в таблице выше, а строка движка `default` представляет общий кэш схем таблиц:

```sql
SELECT engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, max_weight, estimated_weight
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'paimon_ctl'
ORDER BY engine_name, entry_name;
```

См. документацию этой системной таблицы: [catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md).

## Сопоставление типов столбцов {#column-type-mapping}

Полную таблицу сопоставления для Doris 4.2, правила точности и неподдерживаемые типы см. в разделе [Сопоставление типов данных Paimon и Doris](paimon-catalog/doris-type-mapping.md).

Doris сохраняет точное написание заключённых в кавычки имён столбцов верхнего уровня и вложенных полей `STRUCT` в обоих вариантах работы сканера Paimon JNI.
Имена, содержащие разделители, такие как запятые (`region,code`), знаки решётки (`nested#value`), двоеточия (`colon:name`),
пробелы или символы Unicode, не требуют дополнительного экранирования помимо обычного заключения идентификаторов SQL в кавычки. При чтении столбцы сопоставляются
без учёта регистра, поэтому запросы к столбцам, имена которых содержат прописные буквы или смешанный регистр (например, `UserId`),
работают обычным образом.

:::info Примечание о версиях

В версиях ветки 4.0 до 4.0.8 столбцы при чтении определялись по точному совпадению имён, поэтому таблицы Paimon и Iceberg с именами столбцов в смешанном регистре могли возвращать данные неверного столбца или приводить к сбою запроса. Это исправлено в 4.0.8.

:::

Начиная с 4.1.5 явные команды `REFRESH TABLE`, `REFRESH DATABASE` и `REFRESH CATALOG` также инвалидируют соответствующие кэши метаданных Paimon. После внешних изменений схемы или удаления и повторного создания таблицы используйте команду обновления для повторной загрузки метаданных. Уже запущенные запросы сохраняют выбранный снимок.

## Операции записи {#write-operations}

Doris может создавать и изменять таблицы Paimon и записывать в них данные. Каждая успешная запись фиксируется как снимок
Paimon. Если оператор завершается с ошибкой, Doris не публикует частичный снимок.

### Перед началом работы {#before-you-begin}

Перед записью данных проверьте следующее:

* На всех узлах FE и BE должна работать сборка Doris с поддержкой записи в Paimon. Не записывайте данные в Paimon во время
  поэтапного обновления, пока продолжают работать узлы BE со старой версией.
* Учётные данные Catalog должны давать права на обновление хранилища метаданных, а также на создание, запись, переименование и удаление файлов
  в хранилище данных. Конкретные права зависят от хранилища метаданных и системы хранения.
* Запись применима только к обычным таблицам данных Paimon. Системные таблицы Paimon и ссылки на таблицы с выбором ветви,
  тега, снимка или временной метки доступны только для чтения.

### Поддерживаемый SQL {#supported-sql}

| Операция | Поддержка и примечания |
| --- | --- |
| DDL баз данных | `CREATE DATABASE` и `DROP DATABASE` |
| DDL таблиц | `CREATE TABLE`, `CREATE TABLE AS SELECT` и `DROP TABLE` |
| Изменения схемы | Добавление, удаление, переименование, изменение порядка и модификация столбцов |
| Добавление данных | `INSERT INTO ... VALUES` и `INSERT INTO ... SELECT` |
| Перезапись данных | `INSERT OVERWRITE` для всей таблицы, статических и динамических разделов |
| Изменения на уровне строк | `DELETE`, `UPDATE` и `MERGE INTO` для таблиц с первичным ключом с учётом приведённых ниже ограничений |

### Быстрый старт {#quick-start}

Следующий пример создаёт таблицу с первичным ключом и записывает в неё данные. Параметры таблицы Paimon задаются в
`PROPERTIES`; не добавляйте предложение Doris `DISTRIBUTE BY`.

```sql
SWITCH paimon_ctl;
CREATE DATABASE IF NOT EXISTS sales;
USE sales;

CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    customer STRING NULL,
    amount DECIMAL(12, 2) NULL,
    status STRING NULL
) ENGINE=paimon
PROPERTIES (
    'primary-key' = 'order_id',
    'bucket' = '2',
    'bucket-key' = 'order_id'
);

INSERT INTO orders VALUES
    (1, 'Alice', 99.90, 'NEW'),
    (2, 'Bob', 35.00, 'NEW');

UPDATE orders
SET status = 'PAID'
WHERE order_id = 1;

DELETE FROM orders
WHERE order_id = 2;

SELECT * FROM orders ORDER BY order_id;
```

Результат:

```text
+----------+----------+--------+--------+
| order_id | customer | amount | status |
+----------+----------+--------+--------+
|        1 | Alice    |  99.90 | PAID   |
+----------+----------+--------+--------+
```

Можно изменить схему таблицы через Doris, а затем продолжить запись с новой схемой:

```sql
ALTER TABLE orders ADD COLUMN note STRING NULL;
ALTER TABLE orders RENAME COLUMN note order_note;
```

### Вставка и перезапись данных {#insert-and-overwrite-data}

`INSERT INTO` добавляет строки в таблицу, поддерживающую только добавление, или объединяет строки в соответствии с параметрами Paimon
таблицы с первичным ключом. Источником могут быть `VALUES`, внутренняя таблица Doris или другая внешняя таблица.

```sql
INSERT INTO paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.new_orders;
```

Для несекционированной таблицы `INSERT OVERWRITE` заменяет все существующие строки. Поэтому пустые входные данные приводят к пустой
таблице.

```sql
INSERT OVERWRITE TABLE paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.orders_snapshot;
```

Для секционированной таблицы используйте одну из следующих форм:

```sql
-- Replace only the specified partition. The SELECT list omits the static partition column.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
PARTITION (order_date = '2026-10-08')
SELECT order_id, customer, amount, status
FROM internal.sales.daily_orders_stage;

-- Dynamic overwrite replaces the partitions present in the input and keeps other partitions.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
SELECT order_id, customer, amount, status, order_date
FROM internal.sales.daily_orders_stage;
```

Таблица с первичным ключом допускает вставку с пропуском неключевых столбцов только тогда, когда её `merge-engine` имеет значение `partial-update`.
Для таблицы, поддерживающей только добавление, пропущенные столбцы получают значение по умолчанию или `NULL`, если это разрешено.

### Удаление, обновление и слияние данных {#delete-update-and-merge-data}

Изменения на уровне строк требуют таблицы Paimon с первичным ключом. Для таблицы с механизмом слияния `deduplicate`, используемым по умолчанию, Doris
поддерживает следующие операции:

```sql
DELETE FROM paimon_ctl.sales.orders
WHERE order_id = 10;

UPDATE paimon_ctl.sales.orders
SET amount = amount * 0.9,
    status = 'DISCOUNTED'
WHERE order_id = 20;

MERGE INTO paimon_ctl.sales.orders t
USING internal.sales.order_changes s
ON t.order_id = s.order_id
WHEN MATCHED AND s.action = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
    customer = s.customer,
    amount = s.amount,
    status = s.status
WHEN NOT MATCHED THEN INSERT (order_id, customer, amount, status)
    VALUES (s.order_id, s.customer, s.amount, s.status);
```

Следующие ограничения обусловлены тем, как Paimon применяет изменения строк:

* `UPDATE` не может изменять столбец первичного ключа или столбец, настроенный через `sequence.field`.
* `UPDATE`, включая действие обновления в `MERGE`, поддерживает только механизм слияния `deduplicate` и не поддерживает
  `changelog-producer=input`.
* Обновление столбца секционирования требует таблицы с динамическими бакетами (`bucket=-1`) и `ignore-delete=false`.
* `DELETE`, включая действие удаления в `MERGE`, требует `ignore-delete=false`. Механизм слияния `deduplicate`, используемый по умолчанию,
  поддерживает это напрямую. Для таблицы `partial-update` необходимо задать `partial-update.remove-record-on-delete=true`, а для
  таблицы `aggregation` необходимо задать `aggregation.remove-record-on-delete=true`.
* Таблицы с настроенным `rowkind.field` не поддерживают эти операторы изменения на уровне строк. Таблица с динамическими бакетами и настроенным
  `cross-partition-upsert.index-ttl` также их не поддерживает.
* Оператор `MERGE` подчиняется соответствующим ограничениям `UPDATE` и `DELETE` для содержащихся в нём действий.

Для предсказуемых результатов обеспечьте уникальность строк источника `MERGE` по ключу сопоставления. Doris отклоняет оператор, если
несколько строк источника соответствуют одной строке целевой таблицы.

### Примечания по эксплуатации {#operational-notes}

* Настраивайте первичные ключи, разделы, бакеты, механизмы слияния, форматы файлов, компактацию и другие физические характеристики через
  свойства таблицы Paimon. Doris проверяет эти параметры через Paimon SDK.
* В настоящее время Doris не предоставляет универсальную операцию `ALTER TABLE ... SET TBLPROPERTIES` для таблиц Paimon. Чтобы
  изменить свойства таблицы после создания, используйте другой движок Paimon, а затем выполните `REFRESH TABLE` или `REFRESH CATALOG`
  в Doris.
* Обеспечьте достаточно места на локальном диске каждого BE для выгрузки при записи и достаточные права в хранилище для работы с временными файлами и
  фиксации изменений. Параметр BE `paimon_jni_writer_memory_pool_limit_bytes` ограничивает пул памяти, используемый каждым
  средством записи Paimon JNI; его значение по умолчанию составляет 512 MB.
* После успешной записи или изменения схемы новые операторы Doris загружают зафиксированный снимок Paimon. Уже выполняющиеся
  операторы продолжают использовать снимок, выбранный при их запуске.

## Операции запросов {#query-operations}

### Базовый запрос {#basic-query}

После настройки Catalog можно выполнять запросы к данным таблиц в Catalog следующим образом:

```sql
-- 1. Switch to catalog, use database, and query
SWITCH paimon_ctl;
USE paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 2. Use Paimon database directly
USE paimon_ctl.paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 3. Use fully qualified name to query
SELECT * FROM paimon_ctl.paimon_db.paimon_tbl LIMIT 10;
```

### Столбцы метаданных файлов {#file-metadata-columns}

> Поддерживается начиная с версии 4.2.0.

Doris предоставляет два скрытых столбца метаданных для таблиц данных Paimon. С их помощью можно определить физический файл данных и строку, из которых получена каждая строка результата запроса.

| Столбец | Тип | Описание |
| --- | --- | --- |
| `__paimon_file_path` | `STRING NOT NULL` | Исходный путь к файлу необработанных данных, возвращаемый Paimon. |
| `__paimon_row_index` | `BIGINT NOT NULL` | Физическая позиция строки в полном файле данных, отсчитываемая от нуля. |

Предварительные условия: настройте Paimon Catalog, как описано в предыдущих примерах, и создайте таблицу данных Paimon со столбцом `id`, использующую файлы Parquet или ORC. Следующий запрос предполагает, что `paimon_tbl` уже содержит строки со значениями `id`, равными `1` и `2`:

```sql
SELECT id, `__paimon_file_path`, `__paimon_row_index`
FROM paimon_ctl.paimon_db.paimon_tbl
ORDER BY `__paimon_file_path`, `__paimon_row_index`;
```

Пример результата (путь к файлу зависит от расположения таблицы):

```text
+----+------------------------------------------+--------------------+
| id | __paimon_file_path                       | __paimon_row_index |
+----+------------------------------------------+--------------------+
|  1 | s3://bucket/warehouse/db/table/a.parquet |                  0 |
|  2 | s3://bucket/warehouse/db/table/a.parquet |                  1 |
+----+------------------------------------------+--------------------+
```

По умолчанию эти столбцы не отображаются в `SELECT *` и `DESC`.

Чтобы включить скрытые столбцы в `SELECT *` и `DESC`, включите `show_hidden_columns` для сеанса:

```sql
SET show_hidden_columns = true;
```

Связанные переменные сеанса:

| Переменная | Тип | По умолчанию | Обязательно | Действие |
| --- | --- | --- | --- | --- |
| `show_hidden_columns` | `BOOLEAN` | `false` | Нет | Включает скрытые столбцы в `SELECT *` и `DESC`. Не требуется при явном обращении к этим столбцам. |
| `enable_file_scanner_v2` | `BOOLEAN` | `true` | Нет | Должна оставаться включённой, если запрос обращается к этим столбцам метаданных. |
| `force_jni_scanner` | `BOOLEAN` | `false` | Нет | Должна оставаться отключённой, поскольку средство чтения JNI не может формировать эти столбцы метаданных. |

Позиция строки определяется относительно полного физического файла. Фильтрация по предикатам, обработка векторов удаления и разбиение сканирования не изменяют нумерацию оставшихся строк. Поэтому сочетание `__paimon_file_path` и `__paimon_row_index` позволяет найти физическую запись в текущем снимке таблицы. Перезапись файлов данных или компактация могут изменить оба значения, поэтому их нельзя использовать как стабильный логический идентификатор строки.

:::caution
Эти столбцы доступны только тогда, когда каждый блок сканирования Paimon, участвующий в запросе, может быть прочитан как файл необработанных данных нативным средством чтения Parquet или ORC в FileScannerV2. Запрос, обращающийся к ним, завершается с ошибкой при сканировании через JNI или смешанном нативном/JNI-сканировании, при отключённом `enable_file_scanner_v2`, при включённом `force_jni_scanner` или когда выбранные файлы данных нельзя прочитать нативным средством чтения Parquet/ORC.

`__paimon_file_path` и `__paimon_row_index` являются зарезервированными именами, сравниваемыми без учёта регистра. Не используйте их как имена физических столбцов в таблице Paimon.
:::

### Пакетный инкрементальный запрос {#batch-incremental-query}

> Начиная с версии 3.1.0

Поддерживаются [пакетные инкрементальные](https://paimon.apache.org/docs/master/flink/sql-query/#batch-incremental) запросы к Paimon, аналогично Flink.

Поддерживаются запросы инкрементальных данных в заданных интервалах снимков или временных меток. Левая граница интервала включается, правая исключается.

```sql
-- between snapshots [0, 5)
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5');

-- between snapshots [0, 5) with specified scan mode
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5', 'incrementalBetweenScanMode'='diff');

-- read from start timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000');

-- read between timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000', 'endTimestamp'='1750944949000');
```

Параметры:

| Параметр | Описание | Пример |
| --- | --- | --- |
| `startSnapshotId` | Идентификатор начального снимка, должен быть больше 0. Необходимо задавать вместе с `endSnapshotId`. | `'startSnapshotId'='3'` |
| `endSnapshotId` | Идентификатор конечного снимка, должен быть больше `startSnapshotId`. Необходимо задавать вместе с `startSnapshotId`. | `'endSnapshotId'='10'` |
| `incrementalBetweenScanMode` | Задаёт режим инкрементального чтения, по умолчанию `auto`; поддерживаются `delta`, `changelog` и `diff` |  `'incrementalBetweenScanMode'='delta'` |
| `startTimestamp` | Временная метка начального снимка, должна быть больше или равна 0. Единица измерения: миллисекунда. | `'startTimestamp'='1750844949000'` |
| `endTimestamp` | Временная метка конечного снимка, должна быть больше `startTimestamp`. Необязательный параметр; если не задан, чтение выполняется от `startTimestamp` до последнего снимка. Единица измерения: миллисекунда. | `'endTimestamp'='1750944949000'` |

:::tip Примечание
`startSnapshotId` и `endSnapshotId` образуют параметр Paimon `'incremental-between'='3,10'`

`startTimestamp` и `endTimestamp` образуют параметр Paimon `'incremental-between-timestamp'='1750844949000,1750944949000'`

`incrementalBetweenScanMode` соответствует параметру Paimon `incremental-between-scan-mode`.
:::

### Time Travel {#time-travel}

> Начиная с версии 3.1.0

Поддерживается чтение указанных снимков таблиц Paimon.

По умолчанию запросы чтения обращаются только к последней версии снимков.

Просмотреть снимки указанной таблицы Paimon можно через табличную функцию `$snapshots`:

```sql
Doris > SELECT snapshot_id,commit_time FROM paimon_tbl$snapshots;
+-------------+-------------------------+
| snapshot_id | commit_time             |
+-------------+-------------------------+
|           1 | 2025-08-17 06:05:52.740 |
|           2 | 2025-08-17 06:05:52.979 |
|           3 | 2025-08-17 06:05:53.240 |
|           4 | 2025-08-17 06:05:53.561 |
+-------------+-------------------------+
```

Можно использовать конструкции `FOR TIME AS OF` и `FOR VERSION AS OF` для чтения данных исторической версии по идентификатору снимка или времени его создания. Примеры:

```sql
-- Notice: Before 3.1.1, only support format like YYYY-MM-DD HH:MM:SS.SSS
-- After 3.1.2, support YYYY-MM-DD HH:MM:SS and YYYY-MM-DD
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52.740";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17";

-- Notice: The timestamp must be precise down to the millisecond.
SELECT * FROM paimon_tbl FOR TIME AS OF 1755381952740;
-- Use snapshot id
SELECT * FROM paimon_tbl FOR VERSION AS OF 1;
```

#### Time Travel с `@options` {#time-travel-with-options}

Для селекторов, специфичных для Paimon, используйте `@options` в ссылке на таблицу в запросе. Doris принимает `scan.snapshot-id`,
`scan.tag-name`, `scan.version`, `scan.timestamp`, `scan.timestamp-millis`, `scan.watermark`,
`scan.file-creation-time-millis`, `scan.creation-time-millis` и `scan.mode`. Выбранный снимок или тег также
определяет историческую схему; Doris не привязывает последнюю схему к историческим данным.

```sql
-- Read snapshot 1 with the schema stored for snapshot 1.
SELECT id, old_name
FROM paimon_tbl@options('scan.snapshot-id' = '1');

-- A retained tag remains readable even after its ordinary snapshot expires.
SELECT id, old_name
FROM paimon_tbl@options('scan.tag-name' = 'tag1');
```

В ссылке на таблицу можно задать только один параметр начальной позиции. `scan.mode` можно сочетать с позицией
только тогда, когда Paimon определяет эту пару как совместимую; например, `scan.mode='from-creation-timestamp'` требует
`scan.creation-time-millis`. Неизвестный или просроченный снимок, ветвь или тег приводят к явной ошибке, а не к незаметному
переходу на последнюю версию таблицы. Синтаксис `@options` поддерживается для ссылок на таблицы в запросах и может сохраняться в определении
представления, но его нельзя применять к ссылке на CTE или командам, не являющимся запросами, таким как `SHOW`.

### Ветви и теги {#branch-and-tag}

> Начиная с версии 3.1.0

## Системные таблицы {#system-tables}

> Начиная с версии 3.1.0

Doris поддерживает запросы к системным таблицам Paimon для получения метаданных таблиц. Системные таблицы позволяют просматривать историю снимков, файлы манифестов, файлы данных, разделы и другую информацию.

Для доступа к метаданным таблицы Paimon добавьте символ `$` после имени таблицы, а затем имя системной таблицы:

```sql
SELECT * FROM my_table$system_table_name;
```

Системные таблицы `audit_log`, `binlog`, `manifests`, `partitions`, `ro`, `row_tracking` и `table_indexes` принимают
`@options` в ссылке на таблицу. Выбранный снимок или тег применяется к строкам системной таблицы, а для системных таблиц, предоставляющих
столбцы исходной таблицы, также используется соответствующая историческая схема исходной таблицы:

```sql
SELECT rowkind, id, old_name
FROM paimon_tbl$audit_log@options('scan.tag-name' = 'tag1');
```

Другие системные таблицы отклоняют `@options`, поскольку не могут гарантировать, что каждый этап, формирующий строки, использует
выбранный снимок. Системные таблицы Paimon также отклоняют `scan.file-creation-time-millis`: незаметное игнорирование этого фильтра
файлов могло бы вернуть строки за пределами запрошенного диапазона.

:::info Примечание
Doris не поддерживает чтение глобальных системных таблиц Paimon; они поддерживаются только во Flink.
:::

## Приложение {#appendix}

### Часто задаваемые вопросы {#faq}

**1. `Could not find a file io implementation for scheme 's3a' in the classpath`**

В версиях до 3.1 при использовании HMS для хранения метаданных и протокола 's3a' или 's3' на стороне хранилища возникает следующая ошибка:

```text
java.io.UncheckedIOException: org.apache.paimon.fs.UnsupportedSchemeException: Could not find a file io implementation for scheme 's3a' in the classpath. Hadoop FileSystem also cannot access this path 's3a://`.
```

**Версии до 3.1**

Версии до 3.1 не поддерживают протокол `s3a`. Если его использование необходимо, в качестве временного обходного решения можно добавить параметры, связанные с `s3a`.

**Версия 3.1 и выше**

Начиная с версии 3.1 явно добавлять параметры `s3a` больше не требуется. Если нужно переопределить параметры хранилища Paimon, можно добавить параметры с префиксом `paimon.fs.`. Поскольку Paimon внутри использует HDFS API, поддерживаются все параметры `fs.s3a.*`.

Например:

```sql
CREATE CATALOG `paimon_hms_on_s3a` PROPERTIES (
    "type" = "paimon",
    "paimon.catalog.type" = "hms",
    "hive.metastore.uris" = "thrift://172.20.48.119:9383",
    "warehouse" = "s3a://bucket/paimon_warehouse",
    "s3.access_key" = "<ak>",
    "s3.secret_key" = "<sk>",
    "s3.region" = "ap-east-1",
    "s3.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    -- Explicitly add s3a parameters
    "fs.s3a.access.key" = "<ak>",
    "fs.s3a.secret.key" = "<sk>",
    "fs.s3a.endpoint.region" = "ap-east-1",
    "fs.s3a.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    "fs.s3a.impl" = "org.apache.hadoop.fs.s3a.S3AFileSystem"
);
```

При использовании протокола `s3` необходимо явно добавить параметры Paimon, связанные с S3, то есть добавить префикс `paimon.`. Например:

```sql
CREATE CATALOG test_paimon_on_hms_aws_catalog PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = 'hms',
    'warehouse' = 's3://bucket-hk/paimon_warehouse',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9383',
    's3.region' = 'ap-east-1',
    's3.endpoint' = 'https://s3.ap-east-1.amazonaws.com',
    's3.access_key' = '<ak>',
    's3.secret_key' = '<sk>',
    -- Explicitly add Paimon S3 parameters
    'paimon.s3.region' = 'ap-east-1',
    'paimon.s3.endpoint' = 'ap-east-1',
    'paimon.s3.access-key' = '<ak>',
    'paimon.s3.secret-key' = '<sk>'
);
```
