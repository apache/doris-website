## Описание {#description}

Эта инструкция позволяет вручную задать версию, последнюю успешную версию и последнюю неуспешную версию указанной реплики. В основном она используется для восстановления реплик, находящихся в некорректном состоянии, при возникновении проблем в системе.

## Синтаксис {#syntax}

```sql
ADMIN SET REPLICA VERSION PROPERTIES ("<key>"="<value>" [,...])
```

## Обязательные параметры {#required-parameters}

** 1. `"<key>"="<value>"`**

| Ключ         | Тип значения | Примечания                                                       |
|--------------|------------|------------------------------------------------------------------|
| `tablet_id`  | Int        | ID tablet, версию реплики которого необходимо изменить. |
| `backend_id` | Int        | ID узла BE, на котором расположена реплика.              |


## Необязательные параметры {#optional-parameters}

** 1. `"<key>"="<value>"`**

| Ключ                   | Тип значения | Примечания                                       |
|------------------------|------------|--------------------------------------------------|
| `version`              | Int        | Задаёт версию реплики.                            |
| `last_success_version` | Int        | Задаёт последнюю успешную версию реплики.         |
| `last_failed_version`  | Int        | Задаёт последнюю неуспешную версию реплики.       |


**Примечания**

- Если указанная реплика не существует, операция будет проигнорирована.
-
- Изменение этих значений может вызвать последующие сбои при чтении и записи данных и привести к несогласованности данных. Действуйте осторожно!

- Запишите исходные значения перед внесением изменений. После внесения изменений проверьте операции чтения и записи таблицы. Если они завершаются ошибкой, восстановите исходные значения. Однако восстановление также может завершиться ошибкой.

- Не выполняйте эту операцию для tablet, в который в данный момент записываются данные!


## Требования к правам доступа {#access-control-requirements}

Пользователь, выполняющий эту команду SQL, должен обладать как минимум следующими привилегиями:

| Привилегия | Объект   | Примечания                                                                                                                       |
|:-----------|:---------|:---------------------------------------------------------------------------------------------------------------------------------|
| Admin_priv | База данных | Требуется для выполнения административных операций с базой данных, включая управление таблицами и разделами, а также выполнение команд системного уровня. |

## Примеры {#examples}

- Сбросить флаг ошибки для реплики tablet 10003 на BE 10001

  ```sql
  ADMIN SET REPLICA VERSION PROPERTIES("tablet_id" = "10003", "backend_id" = "10001", "last_failed_version" = "-1");
  ```

- Установить для реплики tablet 10003 на BE 10001 версию 1004

  ```sql
  ADMIN SET REPLICA VERSION PROPERTIES("tablet_id" = "10003", "backend_id" = "10001", "version" = "1004");
  ```
