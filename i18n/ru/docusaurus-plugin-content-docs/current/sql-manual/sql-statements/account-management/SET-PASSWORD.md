## Описание {#description}

Оператор `SET PASSWORD` используется для изменения пароля пользователя для входа.

Начиная с версии 4.2.1, Doris поддерживает два пароля для встроенной аутентификации по паролю с помощью `RETAIN CURRENT PASSWORD` и `DISCARD OLD PASSWORD`.

## Синтаксис {#syntax}

```sql
SET PASSWORD [FOR <user_identity>] =
    { PASSWORD(<plain_password>) | <hashed_password> }
    [RETAIN CURRENT PASSWORD]
```

## Обязательные параметры {#required-parameters}

**1. `<plain_password>`**

> Пароль передаётся в открытом виде. Например, для пароля `123456` используйте строку `123456`.

**2. `<hashed_password>`**

> Передаётся зашифрованный пароль. Например, для пароля 123456 используйте строку `*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9` — результат функции `PASSWORD('123456')`.

## Необязательные параметры {#optional-parameters}

**1. `<user_identity>`**

> Если указано `FOR`, идентификатор учётной записи должен в точности совпадать с идентификатором, заданным при `CREATE USER`, включая часть с хостом. Если `FOR` опущено, Doris использует аутентифицированную учётную запись, которую возвращает `CURRENT_USER()`, а не идентификатор с IP-адресом клиента, который возвращает `USER()`. Текущую учётную запись можно посмотреть с помощью `SHOW GRANTS`.

**2. `RETAIN CURRENT PASSWORD` (начиная с версии 4.2.1)**

> Сохраняет прежний основной пароль как дополнительный и устанавливает указанный новый пароль как основной. Для аутентификации можно использовать любой из них; ранее сохранённый дополнительный пароль заменяется. Требуется глобальная привилегия `GRANT_PRIV` или `ADMIN_PRIV`, в том числе при изменении собственного пароля.

## Требования к правам доступа {#access-control-requirements}

Пользователь, выполняющий эту команду SQL, должен обладать как минимум следующими привилегиями:

| Привилегия | Объект | Примечания |
|:--------------|:----------|:------|
| Нет | Текущий пользователь | Для обычного изменения собственного пароля без RETAIN дополнительные привилегии не требуются. |
| GRANT_PRIV или ADMIN_PRIV | Глобальный уровень | Требуется для изменения пароля другого пользователя или использования RETAIN CURRENT PASSWORD, в том числе для собственной учётной записи. |

## Примечания по использованию {#usage-notes}

Начиная с версии 4.1.5, особым идентификатором root является только `'root'@'%'`. Идентификатор вида `'root'@'localhost'` остаётся идентификатором обычного пользователя: само имя root не даёт ему права изменять настоящую учётную запись root. Защита настоящей учётной записи root также не распространяется на других пользователей с именем root.

- Если поле `FOR user_identity` отсутствует, изменяется пароль текущего пользователя.

### Два пароля (начиная с версии 4.2.1) {#dual-passwords-since-421}

- При обычном изменении пароля на непустой без RETAIN существующий дополнительный пароль сохраняется.
- RETAIN не сработает, если текущий основной пароль пуст. Новый пустой пароль очищает оба пароля, даже если указан RETAIN.
- Для пароля в открытом виде используйте `PASSWORD('<new_password>')`; строка без вызова функции должна содержать уже вычисленный хеш пароля.
- Чтобы отозвать дополнительный пароль, используйте `ALTER USER ... DISCARD OLD PASSWORD`. У SET PASSWORD нет предложения DISCARD.

Полный порядок действий и ограничения при обновлении описаны в разделе [Два пароля](../../../admin-manual/auth/authentication/internal#dual-passwords). Эти предложения применяются к встроенной аутентификации по паролю.

## Пример {#example}

- Изменение пароля текущего пользователя

```sql
SET PASSWORD = PASSWORD('123456')
SET PASSWORD = '*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9'
```

- Изменение пароля указанного пользователя

```sql
SET PASSWORD FOR 'jack'@'192.%' = PASSWORD('123456')
SET PASSWORD FOR 'jack'@['domain'] = '*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9'
```

- Смена пароля учётной записи с периодом одновременного действия старого и нового паролей (начиная с версии 4.2.1)

Выполните от имени администратора с глобальной привилегией `GRANT_PRIV` или `ADMIN_PRIV`:

```sql
CREATE USER 'rotation_user'@'%' IDENTIFIED BY 'OldPwd_2026!';
SET PASSWORD FOR 'rotation_user'@'%' = PASSWORD('NewPwd_2026!') RETAIN CURRENT PASSWORD;
```

Для аутентификации подходят и `OldPwd_2026!`, и `NewPwd_2026!`. После перевода клиентов на новый пароль удалите старые учётные данные:

```sql
ALTER USER 'rotation_user'@'%' DISCARD OLD PASSWORD;
```

После этого для аутентификации подходит только `NewPwd_2026!`.
