## Описание {#description}

Оператор `ALTER USER` используется для изменения атрибутов учётной записи пользователя, включая пароль и политики паролей.

Начиная с версии 4.2.1, Doris поддерживает два пароля для встроенной аутентификации по паролю с помощью `RETAIN CURRENT PASSWORD` и `DISCARD OLD PASSWORD`.

## Синтаксис {#syntax}

```sql
ALTER USER [IF EXISTS] <user_identity>
    [IDENTIFIED BY <password> [RETAIN CURRENT PASSWORD] | DISCARD OLD PASSWORD]
[<password_policy>]
[<comment>]

password_policy:
    1. PASSWORD_HISTORY { <n> | DEFAULT }
    2. PASSWORD_EXPIRE { DEFAULT | NEVER | INTERVAL <n> { DAY | HOUR | SECOND }}
    3. FAILED_LOGIN_ATTEMPTS <n>
    4. PASSWORD_LOCK_TIME { UNBOUNDED | <n> { DAY | HOUR | SECOND }}
    5. ACCOUNT_UNLOCK
```

## Обязательные параметры {#required-parameters}

**1. `<user_identity`>**

> user_identity однозначно определяет пользователя. Синтаксис: 'user_name'@'host'.
> `user_identity` состоит из двух частей: user_name и host. user_name — имя пользователя, а host указывает адрес хоста, с которого подключается клиент. В части host можно использовать % для сопоставления по шаблону. Если host не указан, по умолчанию используется '%': пользователь может подключаться к Doris с любого хоста.
> В качестве host также можно указать домен. Синтаксис: 'user_name'@['domain']. Если домен заключён в квадратные скобки, Doris распознаёт его как домен и пытается разрешить его IP-адрес.

## Необязательные параметры {#optional-parameters}

**1. `<password>`**

> Задаёт пароль пользователя.

**2. `<password_policy>`**

> `password_policy` — часть оператора, задающая политики входа с аутентификацией по паролю. Сейчас поддерживаются следующие политики:
>
> `PASSWORD_HISTORY { <n> | DEFAULT}`
>
> Определяет, можно ли повторно использовать прежние пароли при смене пароля. Например, `PASSWORD_HISTORY 10` запрещает устанавливать новый пароль, совпадающий с одним из паролей, заданных за последние 10 смен. При значении `PASSWORD_HISTORY DEFAULT` используется значение глобальной переменной `password_history`. Значение `0` отключает эту функцию. Значение по умолчанию — 0.
>
> `PASSWORD_EXPIRE { DEFAULT | NEVER | INTERVAL <n> { DAY | HOUR | SECOND }}`
>
> Задаёт срок действия пароля пользователя. Например, `PASSWORD_EXPIRE INTERVAL 10 DAY` означает, что срок действия пароля истечёт через 10 дней. `PASSWORD_EXPIRE NEVER` означает, что срок действия пароля не ограничен. При значении `PASSWORD_EXPIRE DEFAULT` используется значение глобальной переменной `default_password_lifetime`. По умолчанию используется NEVER (или 0): срок действия пароля не ограничен.
>
> `FAILED_LOGIN_ATTEMPTS <n>`
>
> Если пользователь введёт неверный пароль n раз при попытке входа, учётная запись будет заблокирована. Например, `FAILED_LOGIN_ATTEMPTS 3` означает блокировку учётной записи после 3 неудачных попыток входа.
>
> `PASSWORD_LOCK_TIME { UNBOUNDED | <n> { DAY | HOUR | SECOND }}`
>
> Задаёт продолжительность блокировки учётной записи. Например, `PASSWORD_LOCK_TIME 1 DAY` означает блокировку на один день.
>
> `ACCOUNT_UNLOCK`
>
> `ACCOUNT_UNLOCK` снимает блокировку с учётной записи пользователя.

**3. `<comment>`**

> Задаёт комментарий к учётной записи пользователя.

**4. `RETAIN CURRENT PASSWORD` (начиная с версии 4.2.1)**

> Используется вместе с `IDENTIFIED BY`: прежний основной пароль сохраняется как дополнительный, а новый становится основным. Для аутентификации можно использовать любой из них. Если дополнительный пароль уже существовал, он заменяется.

**5. `DISCARD OLD PASSWORD` (начиная с версии 4.2.1)**

> Удаляет сохранённый дополнительный пароль, не изменяя основной. Это отдельная операция: её нельзя совмещать со сменой пароля, изменением политики паролей или комментария либо с другими операциями над учётной записью. Если дополнительного пароля нет, операция ничего не меняет.

## Требования к правам доступа {#access-control-requirements}

Пользователь, выполняющий эту команду SQL, должен иметь как минимум следующие права:

| Право | Объект | Примечание |
|:------|:-------|:-----------|
| GRANT_PRIV или ADMIN_PRIV | Глобальный | Требуется для ALTER USER, в том числе с RETAIN CURRENT PASSWORD и DISCARD OLD PASSWORD. |

## Примечания по использованию {#usage-notes}

Начиная с версии 4.1.5, особой учётной записью root является только `'root'@'%'`. Учётная запись с идентификатором, например, `'root'@'localhost'` остаётся обычной и не получает права изменять настоящую учётную запись root только благодаря имени пользователя. Защита настоящей учётной записи root также не распространяется на других пользователей с именем root.

1. Начиная с версии 2.0, эта команда больше не поддерживает изменение ролей пользователей. Для связанных операций используйте [GRANT](./GRANT-TO.md) и [REVOKE](./REVOKE-FROM.md).

2. Одной командой ALTER USER можно изменить только один из следующих атрибутов учётной записи:
- Изменить пароль, при необходимости с RETAIN CURRENT PASSWORD
- Удалить сохранённый дополнительный пароль
- Изменить `PASSWORD_HISTORY`
- Изменить `PASSWORD_EXPIRE`
- Изменить `FAILED_LOGIN_ATTEMPTS` и `PASSWORD_LOCK_TIME`
- Снять блокировку с пользователя

### Два пароля (начиная с версии 4.2.1) {#dual-passwords-since-421}

- Для `RETAIN CURRENT PASSWORD` требуется сменить пароль; текущий основной пароль должен быть непустым. Если новый пароль пуст, оба пароля удаляются даже при использовании RETAIN.
- Обычная смена пароля на непустой без RETAIN сохраняет существующий дополнительный пароль: эти учётные данные продолжают действовать.
- Проверки блокировки учётной записи и срока действия пароля применяются к обоим паролям. DISCARD не изменяет историю паролей и не запускает отсчёт срока действия пароля заново.

Порядок ротации, сведения о наблюдении за состоянием паролей, поведение доменных учётных записей и ограничения при обновлении описаны в разделе [Два пароля](../../../admin-manual/auth/authentication/internal#dual-passwords). Эти части оператора управляют встроенными паролями, а не учётными данными LDAP или внешней системы аутентификации.

## Примеры {#example}

Подготовка: создайте пользователя `jack`, для которого будут выполняться примеры ниже:

```sql
CREATE USER jack@'%' IDENTIFIED BY "12345";
```

- Изменить пароль пользователя

```sql
ALTER USER jack@'%' IDENTIFIED BY "12345";
```

- Изменить политику паролей пользователя

```sql
ALTER USER jack@'%' FAILED_LOGIN_ATTEMPTS 3 PASSWORD_LOCK_TIME 1 DAY;
```

- Снять блокировку с пользователя

```sql
ALTER USER jack@'%' ACCOUNT_UNLOCK
```

- Изменить комментарий к учётной записи пользователя

```sql
ALTER USER jack@'%' COMMENT "this is my first user"
```

- Сменить пароль, сохранив возможность использовать прежний (начиная с версии 4.2.1)

```sql
ALTER USER jack@'%' IDENTIFIED BY 'NewPwd_2026!' RETAIN CURRENT PASSWORD;
```

Для аутентификации подходят и прежний пароль, и `NewPwd_2026!`. После того как все клиенты перейдут на новый пароль, удалите сохранённый прежний пароль:

```sql
ALTER USER jack@'%' DISCARD OLD PASSWORD;
```

После этого для аутентификации подходит только `NewPwd_2026!`.
