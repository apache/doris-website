## Описание {#description}

Команда ADD BACKEND используется для добавления одного или нескольких узлов BE в кластер Doris. Она позволяет администраторам указать хост и порт новых узлов BE, а также дополнительные свойства для настройки их поведения.

## Синтаксис {#syntax}

```sql
ALTER SYSTEM ADD BACKEND "<host>:<heartbeat_port>"[,"<host>:<heartbeat_port>" [, ...]] [PROPERTIES ("<key>"="<value>" [, ...] )]
```

## Обязательные параметры {#required-parameters}

**1. <host>**

> Имя хоста или IP-адрес узла BE.

**2. <heartbeat_port>**

> Порт heartbeat узла BE. Значение по умолчанию — 9050.

## Необязательные параметры {#optional-parameters}

**1. `PROPERTIES ("<key>"="<value>" [, ... ] )`**

> Набор пар «ключ — значение», определяющих дополнительные свойства узла BE. Эти свойства позволяют настроить добавляемый узел BE. Доступны следующие свойства:
> - `tag.location`: задаёт Resource Group, к которой принадлежит узел BE в режиме совмещённого хранения и вычислений.
> - `tag.compute_group_name`: задаёт вычислительную группу, к которой принадлежит узел BE в режиме разделения хранения и вычислений.
> - `tag.public_endpoint`: задаёт публичную конечную точку узла BE для внешнего доступа (например, `11.10.20.12:8010`). Обычно это доменное имя балансировщика нагрузки или публичный IP-адрес для доступа внешних пользователей.
> - `tag.private_endpoint`: задаёт приватную конечную точку узла BE для доступа по частной сети (например, `10.10.10.9:8020`). Обычно используется для доступа внутри VPC или через IP-адрес Kubernetes Service внутри кластера.

## Примечания по использованию {#usage-notes}

1. Перед добавлением нового узла BE убедитесь, что он правильно настроен и запущен.
2. Использование [Resource Group](../../../../admin-manual/workload-management/resource-group.md) помогает эффективнее управлять узлами BE в кластере и организовывать их.
3. При добавлении нескольких узлов BE можно указать их в одной команде для повышения эффективности.
4. После добавления узлов BE используйте команду [`SHOW BACKENDS`](./SHOW-BACKENDS.md), чтобы проверить, что они успешно добавлены и находятся в нормальном состоянии.
5. Рассмотрите возможность размещения узлов BE в разных физических местоположениях или стойках, чтобы повысить доступность и отказоустойчивость кластера.
6. Регулярно проверяйте и балансируйте нагрузку в кластере, чтобы обеспечить эффективное использование добавленных узлов BE.

## Примеры {#examples}

1. Добавление узлов BE без дополнительных свойств
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.0.1:9050,192.168.0.2:9050";
   ```
   Эта команда добавляет в кластер два узла BE:
   * 192.168.0.1, порт 9050
   * 192.168.0.2, порт 9050
   Дополнительные свойства не указаны, поэтому будут применены настройки по умолчанию.

2. Добавление узла BE в указанную Resource Group в режиме совмещённого хранения и вычислений
   ```sql
   ALTER SYSTEM ADD BACKEND "doris-be01:9050" PROPERTIES ("tag.location" = "groupb");
   ```
   Эта команда добавляет один узел BE (имя хоста doris-be01, порт 9050) в Resource Group `groupb` в кластере.

3. Добавление узла BE в указанную вычислительную группу в режиме разделения хранения и вычислений
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.0.3:9050" PROPERTIES ("tag.compute_group_name" = "cloud_groupc");
   ```
   Эта команда добавляет один узел BE (IP-адрес 192.168.0.3, порт 9050) в вычислительную группу `cloud_groupc` в кластере.

4. Добавление узла BE с настроенными публичной и приватной конечными точками для сложных сетевых сред
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.1.1:9050" PROPERTIES (
       "tag.public_endpoint" = "11.10.20.12:8010",
       "tag.private_endpoint" = "10.10.10.9:8020"
   );
   ```
   Эта команда добавляет узел BE с несколькими сетевыми конечными точками:
   * `192.168.1.1:9050`: внутренний адрес (be_host) для взаимодействия внутри кластера
   * `11.10.20.12:8010`: публичная конечная точка для доступа внешних пользователей через балансировщик нагрузки
   * `10.10.10.9:8020`: приватная конечная точка для доступа внутри VPC или между кластерами Kubernetes

   Такая конфигурация полезна в облачных средах или кластерах Kubernetes, где узлы BE должны быть доступны из разных сетевых сред. Подробнее см. в разделе [Stream Load в сложных сетевых средах](../../../../data-operate/import/load-best-practices/stream-load-in-complex-network.md).
