## Описание {#description}

Этот оператор предназначен для вставки данных.

```sql
INSERT INTO table_name
    [ PARTITION (p1, ...) ]
    [ WITH LABEL label]
    [ (column [, ...]) ]
    [ [ hint [, ...] ] ]
    { VALUES ( { expression | DEFAULT } [, ...] ) [, ...] | query }
```

 Параметры

> tablet_name: Целевая таблица для загрузки данных. Можно указать в форме `db_name.table_name`.
>
> partitions: Разделы, в которые нужно загрузить данные. Они должны существовать в `table_name`. Имена нескольких разделов разделяются запятыми.
>
> label: Метка для задачи Insert.
>
> column_name: Целевой столбец, который должен существовать в `table_name`.
>
> expression: Выражение, значение которого нужно присвоить соответствующему столбцу.
>
> DEFAULT: Использовать для соответствующего столбца значение по умолчанию.
>
> query: Обычный запрос, результат которого будет записан в целевую таблицу.
>
> hint: Подсказка, определяющая поведение `INSERT`. Допустимые значения: `/*+ STREAMING */`, `/*+ SHUFFLE */` или `/*+ NOSHUFFLE */`.
> 1. STREAMING: Сейчас не оказывает практического влияния и сохранена только для совместимости с предыдущими версиями. Раньше при указании этой подсказки возвращалась метка; теперь метка возвращается по умолчанию.
> 2. SHUFFLE: Если целевая таблица секционирована, эта подсказка включает перераспределение данных.
> 3. NOSHUFFLE: Перераспределение данных не выполняется даже для секционированной целевой таблицы. При этом выполняются другие операции, обеспечивающие правильное размещение данных по разделам.

Для таблицы Unique с включённым merge-on-write оператор insert также позволяет частично обновлять столбцы. Для этого нужно установить значение переменной сеанса enable_unique_key_partial_update в true. По умолчанию её значение равно false, то есть частичное обновление столбцов с помощью insert запрещено. При частичном обновлении среди вставляемых столбцов должны быть как минимум все столбцы Key, а также столбцы, которые требуется обновить. Если значения столбцов Key вставляемой строки уже есть в исходной таблице, строка с такими значениями будет обновлена. Если таких значений в исходной таблице нет, будет вставлена новая строка. В этом случае столбцы, не указанные в операторе insert, должны иметь значения по умолчанию или допускать null. Для отсутствующих столбцов сначала используются значения по умолчанию; если у столбца нет значения по умолчанию, в него записывается null. Если столбец не допускает null, вставка завершится ошибкой.

Обратите внимание: значение по умолчанию для переменной сеанса `enable_insert_strict`, управляющей строгим режимом оператора insert, равно true. Таким образом, строгий режим включён по умолчанию и при частичном обновлении столбцов не допускает вставку отсутствующих ключей. Чтобы при частичном обновлении столбцов можно было вставлять отсутствующие ключи, установите `enable_unique_key_partial_update` в true и одновременно установите `enable_insert_strict` в false.

Примечание:

При выполнении оператора `INSERT` данные, не соответствующие формату целевой таблицы, например слишком длинные строки, по умолчанию отфильтровываются. Если в вашем сценарии фильтрация данных недопустима, установите для переменной сеанса `enable_insert_strict` значение `true`: тогда при фильтрации данных выполнение `INSERT` завершится ошибкой.

## Примеры {#example}

Таблица `test` содержит два столбца: `c1` и `c2`.

1. Загрузка одной строки в таблицу `test`

```sql
INSERT INTO test VALUES (1, 2);
INSERT INTO test (c1, c2) VALUES (1, 2);
INSERT INTO test (c1, c2) VALUES (1, DEFAULT);
INSERT INTO test (c1) VALUES (1);
```

Первый и второй операторы дают одинаковый результат. Если целевые столбцы не указаны, используется порядок столбцов в таблице.
Третий и четвёртый операторы также равнозначны: для загрузки данных используется значение по умолчанию столбца `c2`.

2. Загрузка нескольких строк в таблицу `test` за один раз

```sql
INSERT INTO test VALUES (1, 2), (3, 2 + 2);
INSERT INTO test (c1, c2) VALUES (1, 2), (3, 2 * 2);
INSERT INTO test (c1) VALUES (1), (3);
INSERT INTO test (c1, c2) VALUES (1, DEFAULT), (3, DEFAULT);
```

Первый и второй операторы дают одинаковый результат: за один раз в таблицу `test` загружаются две строки.
Третий и четвёртый операторы также дают одинаковый результат: две строки загружаются в таблицу `test` с использованием значения по умолчанию для столбца `c2`.

3. Загрузка результата запроса в таблицу `test`

```sql
INSERT INTO test SELECT * FROM test2;
INSERT INTO test (c1, c2) SELECT * from test2;
```

4. Загрузка результата запроса в таблицу `test` с указанием раздела и метки

```sql
INSERT INTO test PARTITION(p1, p2) WITH LABEL `label1` SELECT * FROM test2;
INSERT INTO test WITH LABEL `label1` (c1, c2) SELECT * from test2;
```

## Рекомендации {#best-practice}

1. Просмотр возвращаемого результата

   Операция INSERT выполняется синхронно: получение результата означает её завершение. Дальнейшие действия зависят от возвращённого результата.

   1. Выполнение успешно, результирующий набор пуст

      Если результат запроса select, используемого в операторе insert, пуст, возвращается следующий ответ:

      ```sql
      mysql> insert into tbl1 select * from empty_tbl;
      Query OK, 0 rows affected (0.02 sec)
      ```

      `Query OK` означает успешное выполнение. `0 rows affected` означает, что данные не были загружены.

   2. Выполнение успешно, результирующий набор не пуст

      Если результирующий набор не пуст, возможны следующие варианты ответа:

      1. Оператор Insert выполнен успешно, данные видны:

         ```sql
         mysql> insert into tbl1 select * from tbl2;
         Query OK, 4 rows affected (0.38 sec)
         {'label':'insert_8510c568-9eda-4173-9e36-6adc7d35291c', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 with label my_label1 select * from tbl2;
         Query OK, 4 rows affected (0.38 sec)
         {'label':'my_label1', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 select * from tbl2;
         Query OK, 2 rows affected, 2 warnings (0.31 sec)
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 select * from tbl2;
         Query OK, 2 rows affected, 2 warnings (0.31 sec)
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'committed', 'txnId':'4005'}
         ```

         `Query OK` означает успешное выполнение. `4 rows affected` означает, что всего загружено 4 строки данных. `2 warnings` указывает количество отфильтрованных строк.

         Также возвращается строка JSON:

         ```json
         {'label':'my_label1', 'status':'visible', 'txnId':'4005'}
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'committed', 'txnId':'4005'}
         {'label':'my_label1', 'status':'visible', 'txnId':'4005', 'err':'some other error'}
         ```

         `label` — заданная пользователем или автоматически созданная метка. Метка служит идентификатором задачи загрузки Insert Into. В пределах одной базы данных каждая задача загрузки имеет уникальную метку.

         `status` показывает, видны ли загруженные данные: `visible` означает, что данные видны, а `committed` — что они ещё не видны.

         `txnId` — идентификатор транзакции загрузки, соответствующей этому оператору insert.

         Поле `err` содержит сведения о других непредвиденных ошибках.

         Чтобы просмотреть отфильтрованные строки, выполните следующий оператор:

         ```sql
         show load where label="xxx";
         ```

         URL в возвращённом результате позволяет просмотреть ошибочные данные. Подробности приведены ниже в разделе **«Просмотр ошибочных строк»**.

         **Невидимость данных — временное состояние; в конечном итоге эта партия данных станет видимой.**

         Проверить, видна ли эта партия данных, можно следующим оператором:

         ```sql
         show transaction where id=4005;
         ```

         Если в возвращённом результате значение столбца `TransactionStatus` равно `visible`, данные видны.

   3. Ошибка выполнения

      Ошибка выполнения означает, что данные не были загружены. Возвращается следующий ответ:

      ```sql
      mysql> insert into tbl1 select * from tbl2 where k1 = "a";
      ERROR 1064 (HY000): all partitions have no load data. url: http://10.74.167.16:8042/api/_load_error_log?file=__shard_2/error_log_insert_stmt_ba8bb9e158e4879-ae8de8507c0bf8a2_ba8bb9e158e4879_ae8de8507c0
      ```

      Фрагмент `ERROR 1064 (HY000): all partitions have no load data` указывает причину ошибки. Следующий за ним URL позволяет просмотреть ошибочные данные:

      ```sql
      show load warnings on "url";
      ```

      Так можно просмотреть конкретную строку с ошибкой.

2. Время ожидания

   Время ожидания операции INSERT определяется выражением max(insert_timeout, query_timeout). Обе переменные относятся к переменным окружения: значение insert_timeout по умолчанию составляет 4 часа, а query_timeout — 5 минут. Если время ожидания превышено, задача отменяется. Переменная insert_timeout обеспечивает операторам INSERT более длительное время ожидания по умолчанию, чтобы задачи загрузки не ограничивались более коротким временем ожидания, обычно применяемым к обычным запросам.

3. Метки и атомарность

   Операция INSERT также гарантирует атомарность загрузки. Подробнее см. документацию [«Транзакции загрузки и атомарность»](../../../../data-operate/transaction.md).

   При использовании `CTE(Common Table Expressions)` в качестве части запроса в операции insert необходимо указать части `WITH LABEL` и `column`.

4. Порог фильтрации

   INSERT использует для управления порогом фильтрации переменную сеанса `insert_max_filter_ratio`, а не свойство загрузки `max_filter_ratio`. Переменная `insert_max_filter_ratio` поддерживается начиная с версии 2.1.5, принимает значения от 0 до 1, по умолчанию равна 1.0 и действует только при `enable_insert_strict = false`. Она применяется к `INSERT INTO ... VALUES` и `INSERT INTO ... SELECT`, в том числе при работе с таблицами Doris, внешними таблицами и файловыми TVF. Если отношение `filtered_rows / (loaded_rows + filtered_rows)` превышает заданное значение, INSERT завершается ошибкой.

   Чтобы отклонять любые отфильтрованные данные, установите [переменную сеанса](../../session/variable/SET-VARIABLE) `enable_insert_strict` в `true` (значение по умолчанию). Тогда INSERT завершится ошибкой, если будет отфильтрована хотя бы одна строка. Порог фильтрации не подавляет другие ошибки выполнения, например ошибки анализа SQL или ошибки доступа к источнику данных.

5. Вопросы производительности

   Не рекомендуется вставлять строки по одной с помощью `VALUES`. Если такой способ необходим, объединяйте несколько строк данных в одном операторе INSERT для пакетной фиксации.
