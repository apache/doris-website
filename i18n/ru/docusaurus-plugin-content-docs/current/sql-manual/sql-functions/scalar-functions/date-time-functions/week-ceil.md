## Описание {#description}


Функция week_ceil округляет входное значение даты и времени вверх до ближайшего начала интервала заданной длительности в неделях. Если указан origin, он используется как точка отсчёта; в противном случае по умолчанию используется 0001-01-01 00:00:00.

Формула расчёта даты:
$$
\begin{aligned}
&\text{week\_ceil}(\langle\text{date\_or\_time\_expr}\rangle, \langle\text{period}\rangle, \langle\text{origin}\rangle) = \\
&\min\{\langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{week} \mid \\
&k \in \mathbb{Z} \land \langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{week} \geq \langle\text{date\_or\_time\_expr}\rangle\}
\end{aligned}
$$
$k$ обозначает количество периодов, необходимых для перехода от опорного времени к целевому.

## Синтаксис {#syntax}

```sql
WEEK_CEIL(<date_or_time_expr>)
WEEK_CEIL(<date_or_time_expr>, <origin>)
WEEK_CEIL(<date_or_time_expr>, <period>)
WEEK_CEIL(<date_or_time_expr>, <period>, <origin>)
```

## Параметры {#parameters}

| Параметр | Описание |
|-----------|-------------|
| `<date_or_time_expr>` | Округляемое вверх значение даты и времени; поддерживаются типы DATE/DATETIME/TIMESTAMP_NS/TIMESTAMPTZ. Значение типа даты преобразуется в начало соответствующей даты со временем 00:00:00. Подробные сведения о форматах см. в разделе [преобразование timestamptz](../../../../sql-manual/basic-element/sql-data-types/conversion/timestamptz-conversion), а о форматах datetime/date см. в разделах [преобразование datetime](../../../../sql-manual/basic-element/sql-data-types/conversion/datetime-conversion) и [преобразование date](../../../../sql-manual/basic-element/sql-data-types/conversion/date-conversion) |
| `<period>` | Длительность недельного интервала, тип INT; задаёт число недель в каждом интервале |
| `<origin>` | Начальная точка интервала; поддерживаются типы DATE/DATETIME/TIMESTAMP_NS; по умолчанию используется 0001-01-01 00:00:00 |

## Возвращаемое значение {#return-value}

При входном значении типа `TIMESTAMP_NS` возвращается `TIMESTAMP_NS` с фиксированной точностью дробной части секунды до девяти знаков. Результаты проверяются на соответствие диапазону возвращаемого типа; для `TIMESTAMP_NS` используется диапазон `[1677-09-21 00:12:43.145224192, 2262-04-11 23:47:16.854775807]`.

Если `<origin>` не указан для входного значения типа `TIMESTAMP_NS`, документированная точка отсчёта по умолчанию используется только для внутреннего выравнивания; она может находиться за пределами диапазона значений, представимых типом `TIMESTAMP_NS`.

Возвращает округлённое вверх значение даты и времени в типе, выбранном на основе входных аргументов.

- Если входное значение не равно NULL, а `<period>` неположительный (≤0), функция возвращает ошибку;
- Если любой из параметров равен NULL, возвращается NULL;
- Если `<datetime>` в точности совпадает с началом интервала (определяемого по `<period>` и `<origin>`), возвращается это начало интервала;
- Если входное значение имеет тип date, возвращается значение типа date
- Если входное значение имеет тип datetime, возвращается значение типа datetime с той же временной частью, что и у точки отсчёта.
- Если результат вычисления превышает максимальное значение даты и времени 9999-12-31 23:59:59, возвращается ошибка.
- Если дата и время `<origin>` находятся после `<date_or_time_expr>`, вычисление всё равно выполняется по приведённой выше формуле, но число периодов k будет отрицательным.
- Если у `date_or_time_expr` задан масштаб, результат сохраняет соответствующую точность. Если `origin` содержит дробную часть секунды, границы интервалов сохраняют эту дробную часть. В серии Doris 4.1 начиная с 4.1.5 при сравнении с границами недель учитываются микросекунды, что исправляет округление, когда входное значение и `origin` различаются только дробной частью секунды.
- Если входное значение имеет тип TIMESTAMPTZ, оно сначала преобразуется в local_time (например, `2025-12-31 23:59:59+05:00` соответствует local_time `2026-01-01 02:59:59`, когда значение переменной сеанса равно `+08:00`), после чего выполняется вычисление CEIL.
- Если среди входных значений времени (`<date_or_time_expr>` и `<origin>`) есть значения обоих типов TIMESTAMPTZ и DATETIME, результат имеет тип DATETIME.

## Пример {#example}

```sql
-- 2023-07-13 is Thursday, rounds up to next interval start (1-week interval starts on Monday, so rounds to 2023-07-17 (Monday))
SELECT WEEK_CEIL(cast('2023-07-13 22:28:18' as datetime)) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-17 00:00:00 |
+---------------------+
```

```sql
-- Specify 2-week interval
SELECT WEEK_CEIL('2023-07-13 22:28:18', 2) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-24 00:00:00 |
+---------------------+
```

```sql
-- Input date type returns date type, date string returns datetime
SELECT WEEK_CEIL(cast('2023-07-13' as date));
```

```text
+---------------------------------------+
| WEEK_CEIL(cast('2023-07-13' as date)) |
+---------------------------------------+
| 2023-07-17                            |
+---------------------------------------+
```

```sql
--input with decimal part 
SELECT WEEK_CEIL('2023-07-13 22:28:18.123', 2) AS result;
```

```text
+-------------------------+
| result                  |
+-------------------------+
| 2023-07-24 00:00:00.000 |
+-------------------------+
```

```sql
-- Only with origin date and specified date
select week_ceil("2023-07-13 22:28:18", "2021-05-01 12:00:00");
```

```text
+---------------------------------------------------------+
| week_ceil("2023-07-13 22:28:18", "2021-05-01 12:00:00") |
+---------------------------------------------------------+
| 2023-07-15 12:00:00                                     |
+---------------------------------------------------------+
```

```sql
-- Specify origin date
SELECT WEEK_CEIL('2023-07-13', 1, '2023-07-03') AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-17 00:00:00 |
+---------------------+
```

```sql
-- TimeStampTz sample, SET time_zone = '+08:00'
-- Convert to local_time (2026-01-01 02:59:59) and then perform WEEK_CEIL
SELECT WEEK_CEIL('2025-12-31 23:59:59+05:00');
```

```text
+----------------------------------------+
| WEEK_CEIL('2025-12-31 23:59:59+05:00') |
+----------------------------------------+
| 2026-01-05 00:00:00+08:00              |
+----------------------------------------+
```

```sql
-- If parameters contain both TimeStampTz and Datetime types, output DateTime type
SELECT WEEK_CEIL('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123');
```

```text
+-------------------------------------------------------------------+
| WEEK_CEIL('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123') |
+-------------------------------------------------------------------+
| 2026-01-05 00:00:00.123                                           |
+-------------------------------------------------------------------+
```

```sql
-- Invalid period (non-positive integer)
SELECT WEEK_CEIL('2023-07-13', 0) AS result;
```

```text
ERROR 1105 (HY000): errCode = 2, detailMessage = (10.16.10.3)[E-218]Operation week_ceil of 2023-07-13 00:00:00, 0 out of range
```

```sql
-- Parameter is NULL
SELECT WEEK_CEIL(NULL, 1) AS result;
```

```text
+--------+
| result |
+--------+
| NULL   |
+--------+
```

Входное значение, точно совпадающее с границей интервала, остаётся без изменений:

```sql
SELECT WEEK_CEIL('2023-07-24 00:00:00', 2);
```

```text
2023-07-24 00:00:00
```

Границы недель при точке отсчёта с микросекундной точностью (исправлено в серии Doris 4.1 начиная с 4.1.5):

```sql
SELECT WEEK_CEIL(CAST('2024-01-08 00:00:00.600000' AS DATETIME(6)),
                   1, CAST('2024-01-01 00:00:00.500000' AS DATETIME(6)));
```

```text
2024-01-15 00:00:00.500000
```
