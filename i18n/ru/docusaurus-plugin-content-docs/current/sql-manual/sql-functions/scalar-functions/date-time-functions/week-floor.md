## Описание {#description}

Функция WEEK_FLOOR округляет входное значение даты и времени вниз до начала ближайшего интервала заданной длительности в неделях (WEEK). Если указана начальная точка отсчёта (origin), интервалы рассчитываются относительно неё; в противном случае по умолчанию используется точка отсчёта 0001-01-01 00:00:00.

Формула расчёта даты:
$$
\text{WEEK\_FLOOR}(\langle\text{date\_or\_time\_expr}\rangle, \langle\text{period}\rangle, \langle\text{origin}\rangle) = \max\{\langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{WEEK} \mid k \in \mathbb{Z} \land \langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{WEEK} \leq \langle\text{date\_or\_time\_expr}\rangle\}
$$
$k$ обозначает количество периодов от точки отсчёта до целевого времени.

## Синтаксис {#syntax}

```sql
WEEK_FLOOR(<date_or_time_expr>)
WEEK_FLOOR(<date_or_time_expr>, <origin>)
WEEK_FLOOR(<date_or_time_expr>, <period>)
WEEK_FLOOR(<date_or_time_expr>, <period>, <origin>)
```

## Параметры {#parameters}

| Параметр | Описание |
|-----------|-------------|
| `<date_or_time_expr>` | Значение даты и времени для округления вниз; поддерживаются типы DATE/DATETIME/TIMESTAMP_NS/TIMESTAMPTZ. Значение типа Date преобразуется во время начала соответствующей даты — 00:00:00. Подробности о форматах см. в разделе [преобразование timestamptz](../../../../sql-manual/basic-element/sql-data-types/conversion/timestamptz-conversion), а о форматах datetime/date — в разделах [преобразование datetime](../../../../sql-manual/basic-element/sql-data-types/conversion/datetime-conversion) и [преобразование date](../../../../sql-manual/basic-element/sql-data-types/conversion/date-conversion)|
| `<period>` | Длительность интервала в неделях, тип INT; задаёт количество недель в каждом интервале |
| `<origin>` | Начальная точка отсчёта для интервалов; поддерживаются типы DATE/DATETIME/TIMESTAMP_NS; значение по умолчанию — 0001-01-01 00:00:00 |

## Возвращаемое значение {#return-value}

Для входного значения типа `TIMESTAMP_NS` возвращается `TIMESTAMP_NS` с фиксированной точностью дробной части секунды до девяти знаков. Результаты проверяются на соответствие диапазону возвращаемого типа; для `TIMESTAMP_NS` используется диапазон `[1677-09-21 00:12:43.145224192, 2262-04-11 23:47:16.854775807]`.

Если `<origin>` не указан для входного значения типа `TIMESTAMP_NS`, документированная точка отсчёта по умолчанию используется только как внутренний ориентир для выравнивания интервалов; она не обязана находиться в диапазоне значений, допускаемых типом `TIMESTAMP_NS`.

Возвращается значение даты и времени, округлённое вниз, с типом, выбранным на основе входных аргументов. Временная часть результата устанавливается равной времени точки отсчёта.

- Если входное значение не равно NULL, а `<period>` неположителен (≤0), функция возвращает ошибку;
- Если любой из параметров равен NULL, возвращается NULL;
- Если `<datetime>` точно совпадает с началом интервала (определяемым по `<period>` и `<origin>`), возвращается начало этого интервала;
- Если входное значение имеет тип date, возвращается тип date
- Если входное значение имеет тип datetime, возвращается тип datetime с той же временной частью, что и у точки отсчёта.
- Если дата и время `<origin>` позже `<date_or_time_expr>`, расчёт по-прежнему выполняется по приведённой выше формуле, но число периодов k будет отрицательным.
- Если `date_or_time_expr` имеет дробную часть секунды, результат сохраняет соответствующую точность. Если `origin` содержит дробную часть секунды, границы интервалов сохраняют эту дробную часть. В серии Doris 4.1 начиная с версии 4.1.5 при сравнении с границами недель учитываются микросекунды, что исправляет округление в случаях, когда входное значение и `origin` различаются только дробной частью секунды.
- Если входное значение имеет тип TIMESTAMPTZ, оно сначала преобразуется в local_time (например, `2025-12-31 23:59:59+05:00` соответствует local_time `2026-01-01 02:59:59`, когда переменная сеанса равна `+08:00`), а затем выполняется вычисление FLOOR.
- Если входные значения времени (`<date_or_time_expr>` и `<origin>`) содержат одновременно типы TIMESTAMPTZ и DATETIME, результат имеет тип DATETIME.

## Пример {#example}

```sql
-- 2023-07-13 is Thursday, default 1-week interval (starting Monday), rounds down to nearest Monday (2023-07-10)
SELECT WEEK_FLOOR(cast('2023-07-13 22:28:18' as datetime)) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-10 00:00:00 |
+---------------------+
```

```sql
-- Specify 2-week interval, rounds down to nearest 2-week interval start
SELECT WEEK_FLOOR('2023-07-13 22:28:18', 2) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-10 00:00:00 |
+---------------------+
```

```sql
-- input with decimal part
SELECT WEEK_FLOOR('2023-07-13 22:28:18.123', 2) AS result;
```

```text
+-------------------------+
| result                  |
+-------------------------+
| 2023-07-10 00:00:00.000 |
+-------------------------+
```

```sql
-- Input date type, returns date type
SELECT WEEK_FLOOR(cast('2023-07-13' as date)) AS result;
```

```text
+------------+
| result     |
+------------+
| 2023-07-10 |
+------------+
```

```sql
-- Only with origin date and specified date
select week_floor("2023-07-13 22:28:18", "2021-05-01 12:00:00");
```

```text
+----------------------------------------------------------+
| week_floor("2023-07-13 22:28:18", "2021-05-01 12:00:00") |
+----------------------------------------------------------+
| 2023-07-08 12:00:00                                      |
+----------------------------------------------------------+
```

```sql
-- Specify origin='2023-07-03' (Monday), 1-week interval
SELECT WEEK_FLOOR('2023-07-13', 1, '2023-07-03') AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-10 00:00:00 |
+---------------------+
```

```sql
-- TimeStampTz sample, SET time_zone = '+08:00'
-- Convert to local_time (2026-01-01 02:59:59) and then perform WEEK_FLOOR
SELECT WEEK_FLOOR('2025-12-31 23:59:59+05:00');
```

```text
+-----------------------------------------+
| WEEK_FLOOR('2025-12-31 23:59:59+05:00') |
+-----------------------------------------+
| 2025-12-29 00:00:00+08:00               |
+-----------------------------------------+
```

```sql
-- If parameters contain both TimeStampTz and Datetime types, output DateTime type
SELECT WEEK_FLOOR('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123');
```

```text
+--------------------------------------------------------------------+
| WEEK_FLOOR('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123') |
+--------------------------------------------------------------------+
| 2025-12-29 00:00:00.123                                            |
+--------------------------------------------------------------------+
```

```sql
-- Invalid period, returns error
SELECT WEEK_FLOOR('2023-07-13', 0) AS result;
```

```text
ERROR 1105 (HY000): errCode = 2, detailMessage = (10.16.10.3)[E-218]Operation week_floor of 2023-07-13 00:00:00, 0 out of range
```

```sql
-- Parameter is NULL
SELECT WEEK_FLOOR(NULL, 1) AS result;
```

```text
+--------+
| result |
+--------+
| NULL   |
+--------+
```

Входное значение, точно совпадающее с границей интервала, остаётся без изменений:

```sql
SELECT WEEK_FLOOR('2023-07-10 00:00:00', 2);
```

```text
2023-07-10 00:00:00
```

Границы недель при точке отсчёта с микросекундной точностью (исправлено в серии Doris 4.1 начиная с версии 4.1.5):

```sql
SELECT WEEK_FLOOR(CAST('2024-01-08 00:00:00.400000' AS DATETIME(6)),
                   1, CAST('2024-01-01 00:00:00.500000' AS DATETIME(6)));
```

```text
2024-01-01 00:00:00.500000
```
