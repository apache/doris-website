## Обзор {#overview}

<!-- Knowledge type: concept -->
<!-- Applicable scenarios: understand the full picture of the Doris index system -->

Индексы Doris — это структуры данных, которые ускоряют фильтрацию при выполнении запросов. Правильное использование индексов позволяет значительно повысить производительность запросов.

В настоящее время Doris поддерживает две категории индексов:

| Категория индексов | Типы индексов                                                           | Особенности                                                |
| ----------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------- |
| Встроенные индексы | Префиксный индекс, индекс ZoneMap                                        | Автоматически формируются при создании таблицы и не требуют дополнительного обслуживания |
| Вторичные индексы  | Инвертированный индекс, индекс Bloomfilter, индекс N-Gram Bloomfilter, индекс Bitmap | Создаются пользователями по мере необходимости и управляются независимо |

При оптимизации рабочих нагрузок использование индексов с учётом особенностей задач позволяет значительно повысить производительность запросов и анализа данных. Это один из основных приёмов настройки производительности.

Подробное описание каждого типа индексов приведено в разделе [Индексы таблиц](../../../table-design/index/index-overview.md). В этой статье на реальных примерах рассматриваются приёмы использования индексов и рекомендации по оптимизации для нескольких типичных сценариев.

### Контрольный список перед чтением {#pre-reading-self-check-checklist}

- Вы знаете, как определены и в каком порядке расположены столбцы Key в текущей таблице
- Вы определили поля, которые чаще всего используются для фильтрации в прикладных запросах
- Вы оценили, можно ли пересоздать таблицу или доступно только добавление вторичных индексов
- Вы понимаете, в каких сценариях применяются разные типы индексов

## Пример 1: изменение порядка столбцов Key для ускорения запросов с помощью префиксных индексов {#case-1-adjust-key-column-order-to-accelerate-queries-with-prefix-indexes}

<!-- Knowledge type: case + operation -->
<!-- Applicable scenarios: high-frequency filter fields miss the prefix index, leading to slow queries -->

В статье [Оптимизация схемы таблицы](optimizing-table-schema.md) описано, как выбрать подходящие поля Key и использовать сортировку по столбцам Key в Doris для ускорения запросов. Этот пример развивает рассмотренный там сценарий.

### Исходные сведения {#background}

В Doris есть встроенный префиксный индекс: при создании таблицы он автоматически формируется из первых 36 байт столбцов Key таблицы. Если условие запроса соответствует префиксу этого индекса, скорость выполнения запроса может значительно возрасти.

### Проблема: порядок столбцов Key не соответствует характеру запросов {#problem-key-column-order-does-not-match-the-query-pattern}

Исходный оператор CREATE TABLE:

```sql
CREATE TABLE `t1` (
  `c1` VARCHAR(10) NULL,
  `c2` VARCHAR(10) NULL
) ENGINE=OLAP
DUPLICATE KEY(`c1`)
DISTRIBUTED BY HASH(`c2`) BUCKETS 10
PROPERTIES (
"replication_allocation" = "tag.location.default: 1"
);
```

При этом в приложении используются следующие типичные SQL-запросы:

```sql
select * from t1 where t1.c2 = '1';
select * from t1 where t1.c2 in ('1', '2', '3');
```

В приведённой схеме сначала идёт `c1`, а за ним — `c2`, но запросы выполняют фильтрацию по полю `c2`. В таком случае префиксный индекс не может ускорить запросы.

### Оптимизация: изменение порядка столбцов {#optimization-adjust-column-order}

Разместите столбец `c2` первым, чтобы префиксный индекс охватывал условие фильтрации прикладных запросов:

```sql
CREATE TABLE `t1` (
  `c2` VARCHAR(10) NULL,
  `c1` VARCHAR(10) NULL
) ENGINE=OLAP
DUPLICATE KEY(`c2`)
DISTRIBUTED BY HASH(`c1`) BUCKETS 10
PROPERTIES (
"replication_allocation" = "tag.location.default: 1"
);
```

:::tip Совет по оптимизации

Определяя порядок столбцов в схеме, учитывайте столбцы, которые часто используются в условиях фильтрации прикладных запросов и имеют высокий приоритет. Это позволит в полной мере использовать префиксный индекс Doris для ускорения запросов.

:::

## Пример 2: использование инвертированных индексов для ускорения запросов {#case-2-use-inverted-indexes-to-accelerate-queries}

<!-- Knowledge type: case + operation -->
<!-- Applicable scenarios: table structure is inconvenient to adjust, text retrieval, equality / range queries -->

### Сценарии применения {#applicable-scenarios}

Doris поддерживает инвертированные индексы в качестве вторичных индексов для ускорения следующих задач:

- Полнотекстовый поиск по текстовым полям;
- Запросы с проверкой равенства по строковым, числовым полям или полям даты и времени;
- Диапазонные запросы по строковым, числовым полям или полям даты и времени.

### Преимущества {#advantages}

Инвертированные индексы создаются и управляются независимо: с их помощью удобно повышать производительность прикладных запросов без изменения исходной схемы таблицы и повторной загрузки данных.

Типичные сценарии использования, синтаксис и примеры приведены в разделе [Инвертированный индекс](../../../table-design/index/inverted-index/overview). Здесь они не повторяются.

:::tip Рекомендация по оптимизации

Если исходную структуру таблицы и определения Key сложно изменить или повторная загрузка данных требует больших затрат, инвертированные индексы предоставляют гибкий способ ускорения прикладных запросов.

:::

## Сравнение индексов для выбора {#index-selection-comparison}

<!-- Knowledge type: comparison -->
<!-- Applicable scenarios: quickly select among multiple indexes -->

| Тип индекса           | Подходящие запросы                | Требуется пересоздание таблицы | Требуется повторная загрузка данных | Типичные поля                |
| --------------------- | --------------------------------- | ---------------------- | ---------------------------- | ---------------------------- |
| Префиксный индекс     | Проверка равенства, диапазонные запросы, поиск по префиксу | Да (изменение Key) | Да                           | Столбцы Key в начале порядка сортировки |
| Индекс ZoneMap        | Фильтрация по диапазону           | Нет (автоматически)    | Нет                          | Все столбцы                  |
| Инвертированный индекс | Полнотекстовый поиск, проверка равенства, диапазонные запросы | Нет | Нет                  | Строковые, числовые, дата и время |
| Индекс Bloomfilter    | Фильтрация по равенству для полей с высокой кардинальностью | Нет | Нет (применяется по мере поступления данных) | Строковые, числовые |
| N-Gram Bloomfilter    | Поиск по шаблону LIKE             | Нет                    | Нет (применяется по мере поступления данных) | Строковые          |
| Индекс Bitmap         | Фильтрация по равенству для полей с низкой кардинальностью | Нет | Нет (применяется по мере поступления данных) | Поля с перечислимым набором значений |

## Часто задаваемые вопросы и типичные проблемы {#faq-and-common-issues}

<!-- Knowledge type: FAQ -->

### Вопрос 1: почему запросы по-прежнему выполняются медленно после создания индекса? {#q1-why-are-my-queries-still-slow-after-creating-an-index}

Возможные причины:

- Условие запроса не использует ни один из индексированных столбцов;
- Порядок столбцов Key не соответствует условию фильтрации, поэтому префиксный индекс не задействуется;
- Объём данных мал, и индекс не даёт заметного выигрыша;
- Индекс ещё не применяется к ранее записанным данным (некоторые вторичные индексы сразу начинают действовать только для новых записываемых данных).

### Вопрос 2: нужно ли создавать префиксный индекс вручную? {#q2-does-the-prefix-index-need-to-be-created-manually}

Нет. При создании таблицы Doris автоматически формирует префиксный индекс из первых 36 байт столбцов Key. Чтобы префиксный индекс работал эффективно, размещайте поля, часто используемые для фильтрации в прикладных запросах, в начале списка столбцов Key.

### Вопрос 3: как выбрать между инвертированным индексом и индексом Bloomfilter? {#q3-how-to-choose-between-an-inverted-index-and-a-bloomfilter-index}

- Для полнотекстового поиска, поиска по шаблону и диапазонных запросов предпочтительны инвертированные индексы;
- Для точных запросов на равенство по полям с высокой кардинальностью выбирайте индексы Bloomfilter: они требуют меньше ресурсов.

### Вопрос 4: требуется ли пересоздавать таблицу при изменении порядка столбцов Key? {#q4-does-adjusting-the-key-column-order-require-rebuilding-the-table}

Да. Порядок столбцов Key является частью определения схемы таблицы. После его изменения необходимо пересоздать таблицу и повторно загрузить данные.

## Итоги {#summary}

<!-- Knowledge type: summary -->
<!-- Applicable scenarios: review key points of index tuning -->

При настройке схемы оптимизация индексов так же важна, как и оптимизация схемы на уровне таблицы. Doris предоставляет несколько типов индексов:

- Встроенные индексы: префиксный индекс, индекс ZoneMap;
- Вторичные индексы: инвертированный индекс, Bloomfilter, N-Gram Bloomfilter, Bitmap.

Правильное использование этих индексов позволяет значительно ускорить прикладные запросы и анализ данных в различных сценариях. Рекомендуется сначала определить поля, которые часто используются для фильтрации в прикладных запросах, а затем выбрать подходящий тип индекса с учётом возможности пересоздания таблицы, объёма данных и других факторов.
