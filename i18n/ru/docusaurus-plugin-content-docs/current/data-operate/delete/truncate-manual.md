`TRUNCATE` за одну операцию очищает все данные указанной таблицы или раздела, сохраняя только структуру таблицы и определение раздела. В отличие от `DELETE`, эта операция не создаёт версий удаления и поэтому не влияет на производительность последующих запросов. Это делает её предпочтительным выбором для очистки больших объёмов данных.

## Когда выбирать TRUNCATE {#when-to-choose-truncate}

`TRUNCATE` подходит для сценариев, в которых требуется очистить большой объём данных за одну операцию:

- **Сброс тестовой среды**: Очистка тестовых данных перед повторной загрузкой.
- **Пересоздание данных разделов**: Очистка указанных разделов с последующей записью исправленных данных.
- **Очистка больших объёмов данных**: В отличие от `DELETE`, версии не накапливаются и производительность запросов не снижается.
- **Очистка после архивирования исторических данных**: Очистка исходной таблицы или раздела после завершения архивирования.

## Синтаксис и параметры {#syntax-and-parameters}

### Формат команды {#command-format}

```sql
TRUNCATE TABLE [db.]tbl [PARTITION(p1, p2, ...)] [FORCE];
```

### Описание параметров {#parameter-description}

| Параметр        | Обязательный | Описание                                                                          |
| --------------- | -------- | ------------------------------------------------------------------------------------ |
| `db.`           | Нет      | Имя базы данных. Если не указано, используется текущая база данных.                   |
| `tbl`           | Да       | Имя таблицы, данные которой нужно очистить.                                          |
| `PARTITION(..)` | Нет      | Задаёт список имён разделов; очищаются только эти разделы. Если не указан, очищается вся таблица. |
| `FORCE`         | Нет      | Сразу физически удаляет данные. **Восстановление с помощью RECOVER невозможно.** Используйте с осторожностью. |

## Примеры использования {#usage-examples}

### 1. Очистка всей таблицы {#1-clear-an-entire-table}

Очистить все данные таблицы `tbl` в базе данных `example_db`:

```sql
TRUNCATE TABLE example_db.tbl;
```

### 2. Очистка указанных разделов {#2-clear-specified-partitions}

Очистить только разделы `p1` и `p2` таблицы `tbl`:

```sql
TRUNCATE TABLE tbl PARTITION(p1, p2);
```

### 3. Принудительная очистка без возможности восстановления {#3-force-clear-non-recoverable}

Сразу физически удалить данные `example_db.tbl`, минуя корзину:

```sql
TRUNCATE TABLE example_db.tbl FORCE;
```

:::caution
После использования `FORCE` данные нельзя восстановить с помощью `RECOVER`. Убедитесь в правильности операции перед выполнением.
:::

## Ограничения использования {#usage-constraints}

Перед выполнением `TRUNCATE` убедитесь, что учтены следующие условия:

- **Очищаются только данные, структура сохраняется**: Структура таблицы и определения разделов сохраняются; очищаются только данные.
- **Условия фильтрации не поддерживаются**: Можно очистить только всю таблицу или указанные разделы. Добавлять условия `WHERE` нельзя.
- **Таблица должна находиться в состоянии NORMAL**: Нельзя очистить таблицу, для которой выполняется `SCHEMA CHANGE`.
- **Влияние на текущие загрузки**: Операция может привести к сбою выполняющихся заданий загрузки. Выполняйте её в периоды, когда загрузка не ведётся.
- **По умолчанию данные можно восстановить**: Если `FORCE` не используется, данные можно восстановить в течение срока хранения с помощью [RECOVER](../../sql-manual/sql-statements/recycle/RECOVER).

## Восстановление данных {#data-recovery}

При выполнении `TRUNCATE` без `FORCE` очищенные данные попадают в корзину и могут быть восстановлены в течение срока хранения:

```sql
RECOVER TABLE [db_name.]table_name;
```

Подробнее см. в [описании оператора RECOVER](../../sql-manual/sql-statements/recycle/RECOVER).

:::tip
Срок хранения данных в корзине задаётся параметром конфигурации FE `catalog_trash_expire_second`. По истечении этого срока данные удаляются безвозвратно.
:::

## Сравнение TRUNCATE и DELETE {#truncate-vs-delete}

Обе операции позволяют удалять данные, но сценарии их применения существенно различаются:

| Критерий сравнения           | TRUNCATE                              | DELETE                                                          |
| ---------------------------- | ------------------------------------- | --------------------------------------------------------------- |
| Гранулярность удаления       | Вся таблица или весь раздел           | Отдельные строки с необязательными условиями `WHERE`             |
| Поддержка фильтрации         | Нет                                   | Да                                                              |
| Влияние на производительность запросов | Отсутствует                  | Создаёт версии удаления, что влияет на производительность запросов |
| Скорость выполнения          | Очень высокая (операция на уровне метаданных) | Зависит от числа строк, соответствующих условию           |
| Возможность восстановления по умолчанию | Восстановление с помощью `RECOVER` (без FORCE) | Непосредственное восстановление невозможно            |
| Типичные сценарии            | Очистка больших объёмов данных, пересоздание данных разделов | Точное удаление небольших объёмов данных          |

**Рекомендации по выбору**:

- Для очистки всей таблицы или всего раздела предпочтительнее `TRUNCATE`.
- Для удаления части данных по условиям используйте `DELETE`.

## Часто задаваемые вопросы {#faq}

### Удаляет ли TRUNCATE структуру таблицы? {#does-truncate-delete-the-table-structure}

Нет. `TRUNCATE` очищает только данные. Структура таблицы, определения разделов, индексы и другие метаданные сохраняются.

### Можно ли восстановить данные после TRUNCATE? {#can-data-be-recovered-after-truncate}

- **Без `FORCE`**: Данные можно восстановить с помощью `RECOVER` в течение срока хранения.
- **С `FORCE`**: Данные физически удаляются без возможности восстановления.

### Можно ли выполнить TRUNCATE, пока для таблицы выполняется SCHEMA CHANGE? {#can-truncate-be-performed-while-a-table-is-undergoing-schema-change}

Нет. Таблица должна находиться в состоянии `NORMAL`; в противном случае команда завершится с ошибкой. Перед выполнением дождитесь завершения SCHEMA CHANGE.

### Влияет ли TRUNCATE на выполняющиеся задания загрузки? {#does-truncate-affect-ongoing-import-tasks}

Операция может привести к сбою выполняющихся заданий загрузки. Выполняйте её в периоды, когда загрузка не ведётся, или предварительно приостановите соответствующие загрузки.

### В чём разница между TRUNCATE и DROP TABLE? {#what-is-the-difference-between-truncate-and-drop-table}

- `TRUNCATE`: Сохраняет структуру таблицы и очищает только данные.
- `DROP TABLE`: Удаляет саму таблицу, включая её структуру и данные.

### Можно ли очистить только часть данных в разделе? {#can-only-part-of-the-data-in-a-partition-be-cleared}

Нет. `TRUNCATE` может очистить только всю таблицу или указанные разделы; фильтрация на уровне строк не поддерживается. Для удаления по условию используйте [DELETE](./delete-manual).
