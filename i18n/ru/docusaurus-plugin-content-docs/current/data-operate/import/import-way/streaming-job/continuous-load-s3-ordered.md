Упорядоченная загрузка использует `ORDERED_LIST` для непрерывного обнаружения новых объектов S3 в **лексикографическом порядке ключей**, включающих путь и имя файла. Этот режим подходит для журналов и файлов ETL, имена которых содержат возрастающие временные метки или порядковые номера. Этот порядок определяет последовательность обнаружения файлов и не гарантирует порядок строк в целевой таблице.

Это режим загрузки из S3 по умолчанию, для которого не требуется очередь. Для файлов, поступающих в произвольном порядке, используйте [загрузку по уведомлениям](./continuous-load-s3-notification.md). Для заранее подготовленного статического набора файлов используйте [однократную загрузку](./continuous-load-s3-one-time.md).

## Как это работает {#how-it-works}

Doris ищет подходящие файлы после последнего зафиксированного ключа. Новый ключ должен быть лексикографически больше зафиксированного ключа. После загрузки `file1`, `file2` и `file3` вновь добавленный файл `file0` не будет прочитан. Если новых файлов нет, задание проверяет их наличие с интервалом `max_interval`.

## Быстрый старт {#quick-start}

### Шаг 1: Подготовьте целевую таблицу и файлы {#step-1-prepare-the-target-table-and-files}

Учётной записи, от имени которой выполняется задание, требуется привилегия `LOAD` для целевой таблицы и соответствующие привилегии для создания базы данных и таблицы. Для учётных данных S3 требуются разрешения `s3:ListBucket` и `s3:GetObject`. Узлы Doris должны иметь доступ к конечной точке S3.

```sql
CREATE DATABASE IF NOT EXISTS db1;
CREATE TABLE db1.tbl1 (
    id INT,
    name STRING
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ("replication_num" = "1");
```

В этом примере используется одна реплика для кластера с одним BE. Задайте число реплик с учётом конфигурации вашего производственного кластера. Загрузите приведённые ниже данные как `s3://bucket/001.csv` и замените в SQL имя бакета, конечную точку, регион и учётные данные своими значениями:

```text
1,Alice
2,Bob
```

### Шаг 2: Создайте задание {#step-2-create-the-job}

Не указывайте `s3.ingestion_mode`, чтобы использовать режим по умолчанию, или явно задайте значение `ORDERED_LIST` в `PROPERTIES` задания.

```SQL
CREATE JOB my_job
ON STREAMING
DO
INSERT INTO db1.tbl1
select * from S3(
    "uri" = "s3://bucket/*.csv",
    "s3.access_key" = "<s3_access_key>",
    "s3.secret_key" = "<s3_secret_key>",
    "s3.region" = "<s3_region>",
    "s3.endpoint" = "<s3_endpoint>",
    "format" = "csv",
    "column_separator" = ","
);
```

После загрузки выполните `SELECT * FROM db1.tbl1 ORDER BY id;`. Ожидаемый результат:

```text
+----+-------+
| id | name  |
+----+-------+
|  1 | Alice |
|  2 | Bob   |
+----+-------+
```

### Шаг 3: Отслеживайте ход выполнения {#step-3-monitor-progress}

```sql
SELECT Name, Status, CurrentOffset, EndOffset, ErrorMsg
FROM jobs("type" = "insert")
WHERE Name = 'my_job';
```

После фиксации загрузки `001.csv` ожидается, что `Status` будет иметь значение `RUNNING`, а `CurrentOffset` примет значение `{"fileName":"001.csv"}`. Для продолжения загрузки добавьте файл с большим ключом, например `002.csv`. При отсутствии новых файлов задание продолжает работать.

## Параметры {#parameters}

Задайте следующие параметры в `PROPERTIES` задания. Параметры подключения к S3, учётные данные и параметры формата файлов указываются в `S3(...)`.

| Параметр | Тип | По умолчанию | Обязательный | Описание |
| --- | --- | --- | --- | --- |
| `s3.ingestion_mode` | Строка | `ORDERED_LIST` | Нет | Задайте значение `ORDERED_LIST`. Нельзя изменить после создания. |
| `offset` | Строка JSON | Нет | Нет | Читать строго после этого ключа, например `'{"fileName":"data/001.csv"}'`. Если параметр не указан, чтение начинается с начала пути, соответствующего шаблону. |
| `s3.max_batch_files` | Положительное целое число | `256` | Нет | Порог числа файлов в пакете. |
| `s3.max_batch_bytes` | Целое число | `10737418240` | Нет | Порог объёма данных в пакете в байтах, от `104857600` до `10737418240`. Суффиксы единиц измерения не допускаются. |
| `max_interval` | Положительное целое число | `10` | Нет | Интервал планирования при отсутствии новых файлов, в секундах. |

Пороговые значения пакета не требуют, чтобы задание дожидалось полного пакета перед вставкой данных.

### Начало чтения после определённого файла {#start-after-a-specific-file}

Если `data/001.csv` и предшествующие файлы уже обработаны, начните чтение с `data/002.csv` следующим образом:

```sql
CREATE JOB s3_after_offset_job
PROPERTIES (
    "s3.ingestion_mode" = "ORDERED_LIST",
    "offset" = "{\"fileName\":\"data/001.csv\"}"
)
ON STREAMING DO
INSERT INTO db1.tbl1
SELECT * FROM S3(
    "uri" = "s3://bucket/data/*.csv",
    "format" = "csv",
    "column_separator" = ",",
    "s3.region" = "<s3_region>",
    "s3.endpoint" = "<s3_endpoint>",
    "s3.access_key" = "<s3_access_key>",
    "s3.secret_key" = "<s3_secret_key>"
);
```

При этом `data/001.csv` и все меньшие ключи пропускаются, а загружаются только соответствующие шаблону ключи, следующие за ним. Используйте отдельную целевую таблицу для этого примера, чтобы избежать повторной загрузки данных из примера быстрого старта.

Режим загрузки и URI S3 нельзя изменить после создания задания. Для изменения режима или пути создайте другое задание.

## Устранение неполадок и ограничения {#troubleshooting-and-limitations}

- **Новые файлы не загружаются:** убедитесь, что ключи соответствуют URI и больше `CurrentOffset`. Файлы, добавленные до текущей позиции курсора, автоматически не загружаются. Для дозагрузки используйте отдельный префикс и задание однократной загрузки либо настройте загрузку по уведомлениям перед добавлением файлов.
- **Неожиданный порядок:** используйте временные метки фиксированной ширины или счётчики с ведущими нулями, например `000001.csv`. В противном случае `file10` окажется перед `file2` при сортировке.
- **Объекты перезаписываются или удаляются:** каждый ключ должен быть уникальным, а его содержимое должно оставаться неизменным и доступным для чтения во время загрузки. Перезапись уже зафиксированного объекта не приводит к повторной загрузке.
- **Не удаётся создать задание для пустого пути:** при создании задания S3 TVF требуется соответствующий шаблону, доступный для чтения непустой файл, чтобы определить схему.

О приостановке, возобновлении и просмотре задач см. [Обзор непрерывной загрузки](./continuous-load-overview.md). Об изменении задания см. [ALTER JOB](../../../../sql-manual/sql-statements/job/ALTER-JOB.md).
