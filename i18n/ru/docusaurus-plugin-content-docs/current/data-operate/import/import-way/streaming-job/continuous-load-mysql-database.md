Синхронизация с автоматическим созданием таблиц реализована с помощью встроенного DDL `FROM MYSQL (...) TO DATABASE (...)`. Приёмником служит база данных Doris, а соответствующие целевые таблицы Doris создаёт автоматически на основе схем исходных таблиц. С помощью `include_tables` можно выбрать синхронизацию одной таблицы, нескольких таблиц или всех таблиц. При первой синхронизации Doris автоматически создаёт целевые таблицы с первичными ключами и поддерживает соответствие этих ключей первичным ключам источника. Этот режим подходит для зеркальной репликации, когда обработка с помощью SQL не требуется, а схема целевой таблицы должна автоматически следовать схеме исходной.

Используя возможности [Flink CDC](https://github.com/apache/flink-cdc), Doris читает журналы изменений MySQL и непрерывно записывает полные и инкрементальные данные группы таблиц в Doris через Stream Load. Синхронизация с автоматическим созданием таблиц позволяет задать имя целевой таблицы для отдельной исходной таблицы или исключить столбцы, не входящие в ключ. Если вам нужны выражения SQL, фильтрация строк или преобразование данных, см. [MySQL CDC с сопоставлением через SQL](./continuous-load-mysql-table.md).

### Сценарии применения {#applicable-scenarios}

- Вам нужно зеркально реплицировать группу таблиц или всю базу данных из MySQL в Doris.
- Вы хотите, чтобы схема целевой таблицы и первичные ключи создавались автоматически на основе источника, без ручного создания таблиц.
- Вам нужно только переименовать целевые таблицы или исключить столбцы, без выражений SQL, фильтрации строк или преобразования данных.
- Вам нужны как первоначальная полная инициализация, так и непрерывное получение инкрементальных изменений.

### Возможности и ограничения {#capabilities-and-limitations}

| Параметр              | Описание                                                             |
| --------------------- | -------------------------------------------------------------------- |
| Семантика согласованности | В настоящее время гарантируется только семантика at-least-once     |
| Тип таблицы           | Можно синхронизировать только исходные таблицы с первичными ключами; автоматически создаваемые целевые таблицы используют модель Unique Key |
| Права доступа         | Требуется право Load; если целевая таблица не существует, также требуется право Create |
| Автоматическое создание таблиц | Если целевая таблица уже существует, её создание пропускается; схему таблицы можно настроить по необходимости |
| Обработка данных      | Поддерживаются переименование целевых таблиц и исключение столбцов, не входящих в ключ; выражения SQL, фильтрация строк и преобразование данных не поддерживаются |

## Предварительные требования {#prerequisites}

Перед созданием задания синхронизации с автоматическим созданием таблиц убедитесь в следующем:

1. Кластер Doris развёрнут, и у вас есть право Load (для автоматического создания таблиц также требуется право Create).
2. Загружен jar-файл драйвера JDBC, совместимого с версией MySQL, и на него можно сослаться по имени файла, локальному абсолютному пути или HTTP-адресу. Подробнее см. [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md).
3. В MySQL включён binlog, и у учётной записи есть право на его чтение.
4. Определён объём синхронизации: вся база данных или только таблицы, указанные в `include_tables`.

## Быстрый старт {#quick-start}

<!-- Knowledge type: Procedure -->

### Шаг 1: Создание задания загрузки {#step-1-create-a-load-job}

Создайте задание непрерывной загрузки с помощью [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md):

```sql
CREATE JOB multi_table_sync
ON STREAMING
FROM MYSQL (
        "jdbc_url" = "jdbc:mysql://127.0.0.1:3306",
        "driver_url" = "mysql-connector-java-8.0.25.jar",
        "driver_class" = "com.mysql.cj.jdbc.Driver",
        "user" = "root",
        "password" = "123456",
        "database" = "test",
        "include_tables" = "user_info,order_info",
        "offset" = "initial"
)
TO DATABASE target_test_db (
    "table.create.properties.replication_num" = "1"  -- Set to 1 for single-BE deployment
)
```

Основные моменты приведённого примера:

- `database` задаёт исходную базу данных MySQL. `include_tables` ограничивает набор синхронизируемых таблиц; имена нескольких таблиц разделяются запятыми, а пустое значение означает синхронизацию всей базы данных.
- `offset = "initial"` означает, что сначала выполняется полная инициализация, а затем начинается инкрементальная синхронизация. Чтобы синхронизировать только инкрементальные данные, измените значение на `latest`.
- `TO DATABASE target_test_db` задаёт целевую базу данных Doris. С помощью `table.create.properties.*` можно настроить свойства автоматически создаваемых таблиц, например число реплик.

### Шаг 2: Проверка состояния загрузки {#step-2-check-load-status}

Запросите состояние выполнения Streaming Job с помощью табличной функции `jobs("type"="insert")`:

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING"
             Id: 1765332859199
             Name: mysql_db_sync
          Definer: root
      ExecuteType: STREAMING
RecurringStrategy: \N
           Status: RUNNING
       ExecuteSql: FROM MYSQL('include_tables'='user_info','database'='test','driver_class'='com.mysql.cj.jdbc.Driver','driver_url'='mysql-connector-java-8.0.25.jar','offset'='initial','jdbc_url'='jdbc:mysql://127.0.0.1:3306','user'='root' ) TO DATABASE target_test_db ('table.create.properties.replication_num'='1')
       CreateTime: 2025-12-10 10:19:35
 SucceedTaskCount: 1
  FailedTaskCount: 0
CanceledTaskCount: 0
          Comment: 
       Properties: \N
    CurrentOffset: {"ts_sec":"1765284495","file":"binlog.000002","pos":"9350","kind":"SPECIFIC","splitId":"binlog-split","row":"1","event":"2","server_id":"1"}
        EndOffset: \N
    LoadStatistic: {"scannedRows":24,"loadBytes":1146,"fileNumber":0,"fileSize":0}
         ErrorMsg: \N
```

Обратите внимание на следующие поля:

- `Status`: общее состояние задания, например `RUNNING`.
- `CurrentOffset`: текущая позиция чтения binlog, полезная для отслеживания хода синхронизации.
- `LoadStatistic`: статистика загрузки, например число просмотренных строк и объём записанных данных в байтах.
- `ErrorMsg`: сообщения об ошибках, основной источник информации для диагностики неполадок задания.

### Шаг 3: Изменение задания загрузки {#step-3-modify-the-load-job}

Если нужно обновить сведения о подключении к источнику данных, например при смене учётных данных, используйте `ALTER JOB`:

```sql
ALTER JOB <job_name>
FROM MYSQL (
    "user" = "root",
    "password" = "123456"
)
TO DATABASE target_test_db
```

Общие операции, такие как приостановка, возобновление, удаление и просмотр задач, описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Параметры источника данных {#data-source-parameters}

<!-- Knowledge type: Configuration parameters -->

Источник MySQL (`FROM MYSQL`) поддерживает следующие параметры. Сведения о подключении, имя базы данных и сведения о драйвере обязательны.

| Параметр | Обязательный | По умолчанию | Описание |
| --- | --- | --- | --- |
| `jdbc_url` | Да | - | Строка подключения JDBC к MySQL. |
| `driver_url` | Да | - | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, локальный абсолютный путь или HTTP URL. Подробнее см. [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md). |
| `driver_class` | Да | - | Имя класса драйвера JDBC, например `com.mysql.cj.jdbc.Driver`. |
| `user` | Да | - | Имя пользователя базы данных. |
| `password` | Да | - | Пароль базы данных. |
| `database` | Да | - | Имя базы данных MySQL. |
| `include_tables` | Нет | - | Имена таблиц для синхронизации, разделённые запятыми. Если параметр не задан, синхронизируются все таблицы базы данных. |
| `exclude_tables` | Нет | - | Имена таблиц, которые не нужно синхронизировать, разделённые запятыми. Этот параметр действует, только если `include_tables` не задан. |
| `table.<table_name>.target_table` | Нет | Имя исходной таблицы | Поддерживается начиная с версии 4.1.0. Задаёт имя целевой таблицы Doris для исходной таблицы. `<table_name>` обозначает имя исходной таблицы. |
| `table.<table_name>.exclude_columns` | Нет | - | Поддерживается начиная с версии 4.1.0. Задаёт исходные столбцы, которые не нужно синхронизировать, через запятую. Столбцы должны существовать и не должны входить в первичный ключ. |
| `offset` | Нет | `latest` | Начальное смещение. `initial`: полная и инкрементальная синхронизация; `earliest`: начало с самого раннего доступного смещения Binlog; `latest`: синхронизация только изменений, произошедших после запуска задания. Также можно указать точное смещение в формате JSON, например `{"file":"binlog.000001","pos":"154"}` или `{"gtids":"<gtid_set>"}`. Начиная с версии 4.1.0 также поддерживается `snapshot` для выполнения только полной синхронизации. |
| `snapshot_split_size` | Нет | `40960` (`8096` до версии 4.1.4) | Размер фрагмента в строках. При полной синхронизации таблица делится на несколько фрагментов. Значение должно быть положительным целым числом. |
| `snapshot_parallelism` | Нет | `1` | Степень параллелизма на этапе полной синхронизации, то есть максимальное число фрагментов, которые Task одновременно назначает на выполнение. Значение должно быть положительным целым числом. |
| `server_id` | Нет | Генерируется автоматически | Поддерживается начиная с версии 4.1.0. Идентификатор сервера средства чтения MySQL CDC. Поддерживается отдельное значение, например `5400`, или замкнутый диапазон, например `5400-5408`. Размер диапазона должен быть не меньше `snapshot_parallelism`. |
| `ssl_mode` | Нет | `disable` | Поддерживается начиная с версии 4.1.0. Режим SSL. Допустимые значения: `disable`, `require` и `verify-ca`. |
| `ssl_rootcert` | Обязателен при определённых условиях | - | Поддерживается начиная с версии 4.1.0. Файл сертификата CA в формате `FILE:<file_name>`. Обязателен, если `ssl_mode` имеет значение `verify-ca`. Сначала загрузите файл с помощью [CREATE FILE](../../../../sql-manual/sql-statements/security/CREATE-FILE.md). |

Если заданы и `include_tables`, и `exclude_tables`, приоритет имеет `include_tables`. Следующий фрагмент параметров `FROM MYSQL` синхронизирует `orders` и `customers`, записывает данные из `orders` в `ods_orders`, исключает столбец `internal_note`, не входящий в ключ, и включает проверку CA:

```sql
"include_tables" = "orders,customers",
"table.orders.target_table" = "ods_orders",
"table.orders.exclude_columns" = "internal_note",
"server_id" = "5400-5403",
"ssl_mode" = "verify-ca",
"ssl_rootcert" = "FILE:ca.pem"
```

## Справочное руководство {#reference-manual}

### Оператор загрузки {#load-statement}

<!-- Knowledge type: Syntax reference -->

Синтаксис создания задания синхронизации с автоматическим созданием таблиц:

```sql
CREATE JOB <job_name>
[job_properties]
ON STREAMING
[ COMMENT <comment> ]
FROM MYSQL (
    [source_properties]
)
TO DATABASE <target_db> (
    [target_properties]
)
```

Описание каждого элемента:

| Элемент           | Описание                                             |
| ----------------- | ---------------------------------------------------- |
| job_name          | Имя задания                                          |
| job_properties    | Общие параметры загрузки для задания                 |
| comment           | Комментарий с описанием задания                      |
| source_properties | Параметры источника MySQL                             |
| target_properties | Параметры целевой базы данных Doris                   |

В `job_properties` поддерживаются `max_interval` и `compute_group`. Подробнее см. [Общие параметры настройки загрузки заданий](./continuous-load-overview.md#job-common-load-configuration-parameters). В режиме автоматического создания таблиц `session.*` не используется.

### Параметры настройки целевой базы данных Doris {#doris-target-database-configuration-parameters}

<!-- Knowledge type: Configuration parameters -->

`TO DATABASE` поддерживает следующие необязательные параметры:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `table.create.properties.*` | - | Добавляет свойства таблицы при её создании в Doris, например `table.create.properties.replication_num`. |
| `load.strict_mode` | `false` | Определяет, включён ли строгий режим для записи через Stream Load. Допустимые значения: `true` и `false`. |
| `load.max_filter_ratio` | `0` | Максимально допустимая доля отфильтрованных строк в окне выборки, в диапазоне `[0, 1]`. Значение `0` означает, что строки с ошибками нельзя отфильтровывать. Окно выборки составляет `max_interval * 10` секунд. Задание приостанавливается, когда отношение числа строк с ошибками к общему числу строк в окне превышает это значение. |

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: Поддерживает ли синхронизация с автоматическим созданием таблиц таблицы без первичного ключа?**

Нет. В настоящее время синхронизация с автоматическим созданием таблиц поддерживает только таблицы с первичными ключами (Unique Key). При первой синхронизации Doris автоматически создаёт целевые таблицы с первичными ключами на основе первичных ключей источника.

**Вопрос 2: Будет ли перезаписана целевая таблица, если она уже существует?**

Нет. На этапе автоматического создания таблиц создание пропускается, если целевая таблица уже существует. Схему таблицы можно настроить в соответствии с вашим сценарием.

**Вопрос 3: Как синхронизировать только инкрементальные данные без полной инициализации?**

Задайте для параметра `offset` значение `latest`. Задание пропустит этап полной синхронизации и начнёт чтение непосредственно с последней позиции binlog.

**Вопрос 4: Как выбрать между синхронизацией с автоматическим созданием таблиц и синхронизацией с сопоставлением через SQL?**

- Для зеркальной репликации, автоматического создания таблиц и поддержания соответствия схемы таблицы источнику используйте синхронизацию с автоматическим созданием таблиц.
- Если нужно только переименовать целевые таблицы или исключить столбцы, не входящие в ключ, используйте синхронизацию с автоматическим созданием таблиц.
- Если нужны выражения SQL, фильтрация строк или преобразование данных, используйте [MySQL CDC с сопоставлением через SQL](./continuous-load-mysql-table.md).

**Вопрос 5: Что делать, если создание таблицы завершается ошибкой при развёртывании с одним BE?**

Явно укажите число реплик 1 в `TO DATABASE`: `"table.create.properties.replication_num" = "1"`.
