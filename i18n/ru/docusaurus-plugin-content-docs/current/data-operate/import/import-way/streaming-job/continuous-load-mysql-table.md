Синхронизация с сопоставлением SQL реализована с помощью задания и [CDC Stream TVF](../../../../sql-manual/sql-functions/table-valued-functions/cdc-stream.md) и выполняется в **существующую** таблицу Doris (`INSERT INTO tbl SELECT * FROM cdc_stream(...)`). Выразительные возможности SQL в Doris позволяют сопоставлять столбцы, фильтровать и преобразовывать данные в конвейере синхронизации. Этот подход подходит для сценариев синхронизации в реальном времени, требующих обработки данных.

> Синхронизация с сопоставлением SQL поддерживается начиная с версии 4.1.0.

Благодаря интеграции с механизмом чтения [Flink CDC](https://github.com/apache/flink-cdc) Doris считывает журнал изменений (Binlog) из MySQL и выполняет **полную + инкрементальную** синхронизацию исходной таблицы с целевой. Если нужно, чтобы Doris автоматически создавал целевые таблицы и синхронизировал группу таблиц на уровне базы данных, см. раздел [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md).

### Сценарии использования {#applicable-scenarios}

- Непрерывная синхронизация одной таблицы MySQL с Doris, когда схема целевой таблицы уже спроектирована
- Необходимость исключать ненужные столбцы, сопоставлять столбцы, переименовывать поля или преобразовывать данные при синхронизации
- Интеграция данных в реальном времени, требующая сквозной семантики exactly-once

### Предварительные требования {#prerequisites}

| Пункт | Описание |
| ------ | ---- |
| Версия Doris | 4.1.0 и выше |
| Тип таблицы | Исходная таблица должна иметь первичный ключ; целевая таблица Doris должна использовать модель Unique Key |
| Права пользователя | Требуется право `Load` |
| Настройка MySQL | На стороне MySQL должен быть включён Binlog. См. [руководство по настройке](./continuous-load-overview.md#supported-data-sources-and-sync-modes) |
| Гарантии семантики | Поддерживается семантика exactly-once |

## Быстрый старт {#quick-start}

Следующий минимальный рабочий пример демонстрирует весь процесс: создание задания и проверку его состояния.

### Шаг 1: создание задания загрузки {#step-1-create-the-import-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки:

```sql
CREATE JOB mysql_single_sync
ON STREAMING
DO
INSERT INTO db1.tbl1
SELECT * FROM cdc_stream(
    "type" = "mysql",
    "jdbc_url" = "jdbc:mysql://127.0.0.1:3306",
    "driver_url" = "mysql-connector-java-8.0.25.jar",
    "driver_class" = "com.mysql.cj.jdbc.Driver",
    "user" = "root",
    "password" = "123456",
    "database" = "source_db",
    "table" = "source_table",
    "offset" = "initial"
)
```

### Шаг 2: проверка состояния загрузки {#step-2-check-the-import-status}

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING";
```

### Шаг 3: управление заданием {#step-3-job-operations}

Подробнее об общих операциях (приостановке, возобновлении, удалении, просмотре задач и т. д.) см. в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Справочник параметров {#parameter-reference}

### Параметры источника данных {#data-source-parameters}

CDC Stream TVF поддерживает следующие параметры источника данных MySQL.

| Параметр | Обязательный | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `type` | Да | - | Тип источника данных. Установите `mysql`. |
| `jdbc_url` | Да | - | Строка подключения JDBC к MySQL. |
| `driver_url` | Да | - | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, локальный абсолютный путь и HTTP URL. Подробнее см. в разделе [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md). |
| `driver_class` | Да | - | Имя класса драйвера JDBC, например `com.mysql.cj.jdbc.Driver`. |
| `user` | Да | - | Имя пользователя базы данных. |
| `password` | Да | - | Пароль базы данных. |
| `database` | Да | - | Имя базы данных MySQL. |
| `table` | Да | - | Имя синхронизируемой таблицы. Каждое задание с сопоставлением SQL поддерживает одну исходную таблицу. |
| `offset` | Да | - | Начальная позиция. `initial`: полная и инкрементальная синхронизация; `snapshot`: только полная синхронизация; `earliest`: запуск с самой ранней доступной позиции Binlog; `latest`: синхронизация только тех изменений, которые произошли после запуска задания. Также можно указать точную позицию в формате JSON, например `{"file":"binlog.000001","pos":"154"}` или `{"gtids":"<gtid_set>"}`. |
| `snapshot_split_size` | Нет | `40960` (`8096` до 4.1.4) | Размер фрагмента в строках. При полной синхронизации таблица разбивается на несколько фрагментов. Значение должно быть положительным целым числом. |
| `snapshot_parallelism` | Нет | `1` | Степень параллелизма на этапе полной синхронизации, то есть максимальное число фрагментов, которые Task может запланировать одновременно. Значение должно быть положительным целым числом. |
| `skip_snapshot_backfill` | Нет | `false` | Пропускать ли дозагрузку изменений из Binlog при создании снимка. При значении `true` используется семантика at-least-once. |
| `server_id` | Нет | Генерируется автоматически | Идентификатор сервера для компонента чтения MySQL CDC. Поддерживается отдельное значение, например `5400`, или диапазон с включёнными границами, например `5400-5408`. Размер диапазона должен быть не меньше `snapshot_parallelism`. |
| `ssl_mode` | Нет | `disable` | Режим SSL. Допустимые значения: `disable`, `require` и `verify-ca`. |
| `ssl_rootcert` | Обязательный при определённом условии | - | Файл сертификата CA в формате `FILE:<file_name>`. Обязателен, если `ssl_mode` имеет значение `verify-ca`. Сначала загрузите файл с помощью [CREATE FILE](../../../../sql-manual/sql-statements/security/CREATE-FILE.md). |
| `include_delete_sign` | Нет | `false` | Должна ли TVF дополнительно возвращать столбец `__DORIS_DELETE_SIGN__`. Установите `true`, чтобы операции DELETE в источнике приводили к удалению данных в таблице Doris с первичным ключом. |

Если включён `include_delete_sign`, целевая таблица должна использовать модель Unique Key с Merge-on-Write, а столбец `__DORIS_DELETE_SIGN__` необходимо явно сопоставить как в списке целевых столбцов INSERT, так и в списке SELECT:

```sql
CREATE JOB mysql_cdc_with_delete
ON STREAMING
DO
INSERT INTO db1.target_table (id, value, __DORIS_DELETE_SIGN__)
SELECT id, value, __DORIS_DELETE_SIGN__
FROM cdc_stream(
    "type" = "mysql",
    "jdbc_url" = "jdbc:mysql://127.0.0.1:3306",
    "driver_url" = "mysql-connector-java-8.0.25.jar",
    "driver_class" = "com.mysql.cj.jdbc.Driver",
    "user" = "root",
    "password" = "123456",
    "database" = "source_db",
    "table" = "source_table",
    "offset" = "initial",
    "include_delete_sign" = "true"
);
```

### Параметры настройки задания {#job-configuration-parameters}

Задайте следующие параметры через `CREATE JOB ... PROPERTIES (...)`:

| Параметр | Значение по умолчанию | Описание |
| --- | --- | --- |
| `max_interval` | `10` | Интервал планирования в секундах при отсутствии новых данных в источнике. Значение должно быть целым числом не меньше 1. |
| `compute_group` | Группа вычислений, заданная для текущего сеанса или по умолчанию для пользователя | Поддерживается только в режиме разделения вычислений и хранения. Задаёт группу вычислений, в которой выполняется задание. Пользователь должен иметь право USAGE для этой группы вычислений. |
| `session.<variable_name>` | Значение соответствующей переменной сеанса по умолчанию | Задаёт переменную сеанса для задачи INSERT. Сведения о переменных загрузки см. в разделе [Insert Into Select](../../../../data-operate/import/import-way/insert-into-manual.md#import-configuration-parameters). |

Сведения о свойстве задания `offset`, которое используется для сброса позиции CDC через `ALTER JOB`, и полный список ограничений см. в разделе [Общие параметры настройки загрузки для заданий](./continuous-load-overview.md#job-common-load-configuration-parameters). Начальную позицию нового задания необходимо задавать в `cdc_stream(...)`.

## Часто задаваемые вопросы {#faq}

**Вопрос 1: чем синхронизация с сопоставлением SQL отличается от синхронизации с автоматическим созданием таблиц?**

- Синхронизация с сопоставлением SQL: целевая таблица Doris должна быть **создана заранее**. Поддерживаются сопоставление столбцов и преобразование данных; этот подход подходит для сценариев, требующих детальной настройки обработки.
- Синхронизация с автоматическим созданием таблиц: Doris **автоматически создаёт** целевые таблицы и синхронизирует их целиком на уровне базы данных. Подробнее см. в разделе [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md).

**Вопрос 2: можно ли использовать в качестве целевой таблицу без первичного ключа?**

Исходная таблица должна иметь первичный ключ, а целевая таблица Doris в настоящее время должна использовать модель Unique Key.

**Вопрос 3: как синхронизировать только инкрементальные данные без полной загрузки исторических данных?**

Установите для параметра `offset` значение `latest`. Задание пропустит этап полной синхронизации и будет синхронизировать только инкрементальные данные из Binlog.

**Вопрос 4: как ускорить полную синхронизацию?**

Чтобы повысить пропускную способность на этапе полной синхронизации, можно настроить следующие два параметра:

- `snapshot_split_size`: увеличьте число строк в каждом фрагменте.
- `snapshot_parallelism`: увеличьте число фрагментов, которые Task планирует параллельно.

Если при настройке `snapshot_parallelism` также задан диапазон `server_id`, убедитесь, что число идентификаторов в диапазоне не меньше степени параллелизма.
