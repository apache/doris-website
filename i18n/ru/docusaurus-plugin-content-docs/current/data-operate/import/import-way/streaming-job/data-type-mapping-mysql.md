В таблице ниже показано, как тип каждого столбца исходной таблицы MySQL сопоставляется с типом столбца Doris. Для обоих способов синхронизации используется одно и то же сопоставление. Различается только то, кто создаёт целевую таблицу:

- **Синхронизация с автоматическим созданием таблиц**: Doris считывает исходную схему и автоматически создаёт целевую таблицу с указанными типами столбцов Doris.
- **Синхронизация с SQL-сопоставлением**: вы самостоятельно создаёте целевую таблицу, выбирая совместимый тип Doris для каждого столбца.

В обоих случаях значения записываются в соответствии с одним и тем же сопоставлением. Информацию о неподдерживаемых типах см. в разделе [Ограничения](./continuous-load-overview.md#limitations).

## Нормализация параметров JDBC URL {#jdbc-url-parameter-normalization}

> Поддерживается начиная с версии 4.1.4.

При создании Streaming Job с источником данных MySQL (или использовании табличной функции `cdc_stream()`) Doris автоматически добавляет следующие параметры в `jdbc_url`, если вы не задали их явно:

| Параметр | Добавляемое значение | Действие |
| --- | --- | --- |
| `tinyInt1isBit` | `false` | `TINYINT(1)` считывается как `TINYINT` (`1` / `0`), а не как `BOOLEAN` (`true` / `false`) |
| `yearIsDateType` | `false` | `YEAR` считывается как целочисленное значение года, а не как дата |
| `useUnicode` | `true` | Используется кодировка Unicode |
| `characterEncoding` | `utf-8` | В качестве набора символов используется UTF-8 |

Если какой-либо из этих параметров явно задан в `jdbc_url`, Doris сохраняет указанное вами значение и не переопределяет его. Для PostgreSQL нормализация `jdbc_url` не выполняется.

:::caution Влияние обновления

После обновления с версии 4.1.3 или более ранней значения столбцов `TINYINT(1)` в существующих заданиях MySQL CDC представляются как `1` / `0` вместо `true` / `false`, а значения столбцов `YEAR` — как целочисленные значения года вместо дат. Чтобы сохранить прежнее поведение, явно задайте `tinyInt1isBit=true` и `yearIsDateType=true` в `jdbc_url`.

:::

## Из MySQL в Doris {#mysql-to-doris}

| Тип MySQL | Тип Doris | Примечания |
| --- | --- | --- |
| `BOOLEAN` / `TINYINT(1)` | `TINYINT` | **Начиная с версии 4.1.4** сопоставляется с `TINYINT` (значения `1` / `0`); до версии 4.1.4 сопоставлялся с `BOOLEAN` (`true` / `false`). Причина описана в разделе [Нормализация параметров JDBC URL](#jdbc-url-parameter-normalization) |
| `TINYINT` | `TINYINT` | `UNSIGNED` → `SMALLINT` |
| `SMALLINT` | `SMALLINT` | `UNSIGNED` → `INT` |
| `MEDIUMINT` | `INT` | `UNSIGNED` → `INT` |
| `INT` | `INT` | `UNSIGNED` → `BIGINT` |
| `BIGINT` | `BIGINT` | `UNSIGNED` → `LARGEINT` |
| `YEAR` | `SMALLINT` | **Начиная с версии 4.1.4** значение считывается как целочисленное значение года, а не как дата; нулевой год MySQL (`0000`) сохраняется как `0` |
| `FLOAT` | `FLOAT` | |
| `DOUBLE` | `DOUBLE` | |
| `DECIMAL(p,s)` | `DECIMAL(p,s)` | При очень высокой точности используется `STRING` |
| `DATE` | `DATE` | |
| `DATETIME` | `DATETIME(s)` | Сохраняется точность дробной части секунды до микросекунд (0–6) |
| `TIMESTAMP` | `DATETIME(s)` | Приводится к часовому поясу сервера |
| `TIME` | `STRING` | Сериализуется в строку, например `12:34:56.000000` |
| `CHAR` | `CHAR` | |
| `VARCHAR` | `VARCHAR` | |
| `TINYTEXT` / `TEXT` / `MEDIUMTEXT` / `LONGTEXT` | `STRING` | |
| `BINARY` / `VARBINARY` / `TINYBLOB` / `BLOB` / `MEDIUMBLOB` / `LONGBLOB` | `STRING` | Строка в кодировке Base64 |
| `BIT(1)` | `BOOLEAN` | |
| `BIT(n>1)` | `STRING` | Строка в кодировке Base64 |
| `JSON` | `STRING` | Хранится в виде текста JSON |
| `ENUM` | `STRING` | Преобразуется в значение метки |
| `SET` | `STRING` | Преобразуется в список меток, разделённых запятыми |
| Пространственные типы (`GEOMETRY`, `POINT`, …) и другие типы | Не поддерживаются | Автоматическое создание таблиц завершается ошибкой для таблиц с такими столбцами; используйте синхронизацию с SQL-сопоставлением (с приведением типа в `SELECT`) или исключите столбец |
