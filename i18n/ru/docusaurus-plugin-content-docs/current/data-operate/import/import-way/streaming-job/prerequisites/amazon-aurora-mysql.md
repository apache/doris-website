:::caution Экспериментальная функция

Непрерывная загрузка Doris является экспериментальной функцией и поддерживается начиная с Doris 4.1.5.

:::

<!-- Applicable scenario: Pre-deployment check / Data source onboarding prerequisite configuration -->

Потоковая загрузка Doris поддерживает Amazon Aurora MySQL-Compatible Edition версий **5.6, 5.7 и 8.0.x**. Поскольку Aurora MySQL по умолчанию не включает Binlog, перед синхронизацией данных необходимо выполнить предварительную настройку кластера Aurora: включить и настроить Binlog, создать пользователя синхронизации и задать срок хранения Binlog.

Этот документ предназначен для пользователей, которые планируют подключить данные Aurora MySQL к потоковой загрузке Doris. В нём описан полный рабочий процесс настройки.

### Список предварительных проверок {#prerequisite-checklist}

Перед подключением к Doris убедитесь, что кластер Aurora соответствует следующим условиям:

| Проверяемый параметр | Ожидаемое значение | Способ проверки |
| :--- | :--- | :--- |
| Включён ли Binlog | `log_bin = ON` | `SHOW VARIABLES LIKE 'log_bin';` |
| Формат Binlog | `binlog_format = ROW` | `SHOW VARIABLES LIKE 'binlog_format';` |
| Образ строк Binlog | `binlog_row_image = FULL` | `SHOW VARIABLES LIKE 'binlog_row_image';` |
| Пользователь синхронизации | Существует выделенная учётная запись с правами репликации | Выполните `SHOW GRANTS FOR ...;` |
| Срок хранения Binlog | Не менее 72 часов | `CALL mysql.rds_show_configuration;` |

Если выполнены все условия, можно сразу перейти к настройке потоковой загрузки Doris. Если какое-либо условие не выполнено, завершите настройку, следуя приведённым ниже шагам.

## Шаг 1. Проверка текущей конфигурации Binlog {#step-1-check-the-current-binlog-configuration}

Подключитесь к **экземпляру записи Aurora** и выполните следующий SQL, чтобы проверить состояние Binlog:

```sql
-- Check if binlog is enabled
SHOW VARIABLES LIKE 'log_bin';

-- Check binlog format
SHOW VARIABLES LIKE 'binlog_format';

-- Check binlog row image
SHOW VARIABLES LIKE 'binlog_row_image';
```

Выберите дальнейший путь на основе результатов:

- Если выполнены все три условия (`log_bin = ON`, `binlog_format = ROW` и `binlog_row_image = FULL`), можно **сразу перейти к** [шагу 4. Создание пользователя синхронизации](#step-4-create-a-sync-user).
- В противном случае перейдите к [шагу 2](#step-2-configure-the-cluster-parameter-group), чтобы включить Binlog через группу параметров кластера.

## Шаг 2. Настройка группы параметров кластера {#step-2-configure-the-cluster-parameter-group}

Aurora MySQL не позволяет напрямую изменять параметры времени выполнения; их необходимо изменять через **DB Cluster Parameter Group**.

Действия:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. На левой панели навигации выберите **Parameter groups** и нажмите **Create parameter group**.
3. В качестве типа выберите **DB Cluster Parameter Group**, затем выберите семейство версий Aurora MySQL, соответствующее целевому кластеру.
4. Отредактируйте созданную группу параметров кластера, найдите `binlog_format` и задайте значение `ROW`:

    ![Настройка формата Binlog MySQL](/images/next/data-operate/streaming-job/mysql-binlog-setting.png)

5. Найдите `binlog_row_image` и задайте значение `FULL`.
6. Нажмите **Save Changes**, чтобы сохранить изменения.

Основные параметры, которые необходимо изменить:

| Параметр | Рекомендуемое значение | Описание |
| :--- | :--- | :--- |
| `binlog_format` | `ROW` | Для синхронизации CDC требуется журналирование на уровне строк |
| `binlog_row_image` | `FULL` | Обеспечивает наличие в Binlog полного образа всех столбцов |

## Шаг 3. Применение группы параметров кластера и перезапуск {#step-3-apply-the-cluster-parameter-group-and-restart}

Созданную группу параметров необходимо привязать к целевому кластеру и перезапустить экземпляр записи, прежде чем изменения вступят в силу.

1. В консоли RDS выберите целевой кластер Aurora и нажмите **Modify**.
2. В разделе **DB cluster parameter group** выберите группу параметров кластера, созданную в [шаге 2](#step-2-configure-the-cluster-parameter-group).
3. Установите флажок **Apply immediately**, чтобы применить изменения немедленно.
4. Перезапустите **экземпляр записи** Aurora, чтобы конфигурация вступила в силу.

:::caution
Для применения параметра `binlog_format` требуется перезапуск экземпляра записи Aurora. Выполняйте эту операцию в период низкой нагрузки.
:::

После перезапуска снова выполните SQL из [шага 1](#step-1-check-the-current-binlog-configuration), чтобы подтвердить изменения. Все три параметра должны соответствовать ожидаемым значениям.

## Шаг 4. Создание пользователя синхронизации {#step-4-create-a-sync-user}

Создайте отдельную учётную запись для потоковой загрузки Doris, чтобы упростить управление правами и аудит.

1. Создайте пользователя:

    ```sql
    CREATE USER 'doris_sync'@'%' IDENTIFIED BY '<password>';
    ```

2. Предоставьте права, необходимые для синхронизации:

    ```sql
    GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'doris_sync'@'%';
    ```

Описание необходимых прав:

| Право | Назначение |
| :--- | :--- |
| `SELECT` | Чтение данных бизнес-таблиц на этапе полной загрузки |
| `REPLICATION SLAVE` | Чтение потока Binlog в качестве клиента репликации |
| `REPLICATION CLIENT` | Запрос метаданных, таких как позиции в файлах Binlog |

## Шаг 5. Настройка срока хранения Binlog {#step-5-configure-the-binlog-retention-period}

Aurora по умолчанию довольно быстро удаляет Binlog, из-за чего после прерывания репликации может быть невозможно продолжить её. Рекомендуется установить срок хранения Binlog **не менее 72 часов**, чтобы бинарные журналы оставались доступными при сбоях.

Для настройки используйте хранимую процедуру `mysql.rds_set_configuration`:

```sql
CALL mysql.rds_set_configuration('binlog retention hours', 72);
```

Текущую конфигурацию можно проверить с помощью следующего SQL:

```sql
CALL mysql.rds_show_configuration;
```

:::caution
Если этот параметр не задан или задан слишком короткий интервал, в бинарных журналах могут появиться пропуски, что повлияет на способность Doris возобновить репликацию.
:::

## Часто задаваемые вопросы {#faq}

**Вопрос 1. Почему после изменения `binlog_format` его значение по-прежнему не равно `ROW`?**

Ответ: Aurora MySQL не позволяет напрямую изменять параметры времени выполнения. Необходимо создать и привязать **DB Cluster Parameter Group**, как описано в [шаге 2](#step-2-configure-the-cluster-parameter-group), а затем перезапустить **экземпляр записи**, чтобы изменения вступили в силу. Изменение группы параметров по умолчанию не поможет.

**Вопрос 2. Нужно ли выполнять проверки и настройку на экземпляре записи?**

Ответ: Да. Binlog создаётся только на экземпляре записи Aurora, поэтому все проверки SQL и создание пользователя синхронизации следует выполнять на экземпляре записи.

**Вопрос 3. Каковы последствия слишком большого значения `binlog retention hours`?**

Ответ: Это потребляет больше места в хранилище. Рекомендуется задавать значение с учётом фактического окна восстановления после сбоев, но не менее 72 часов.

## Устранение неполадок {#troubleshooting}

| Симптом | Возможная причина | Решение |
| :--- | :--- | :--- |
| `log_bin` по-прежнему имеет значение `OFF` | Пользовательская группа параметров кластера не привязана или экземпляр записи не перезапущен | Выполните [шаг 3](#step-3-apply-the-cluster-parameter-group-and-restart), чтобы привязать группу параметров и перезапустить экземпляр записи |
| `binlog_format` не равен `ROW` | Изменена группа параметров экземпляра, а не группы параметров кластера | Задайте `binlog_format = ROW` в **DB Cluster Parameter Group** |
| При синхронизации Doris сообщается, что файл Binlog не найден | Значение `binlog retention hours` слишком мало, и Binlog уже удалён | С помощью `mysql.rds_set_configuration` увеличьте срок хранения минимум до 72 часов |
| Не удаётся выполнить аутентификацию пользователя синхронизации | Ограничение хоста пользователя или недостаточные права | Убедитесь, что хост пользователя указан как `'%'` или как IP-адрес исходящего трафика Doris BE, и что предоставлены права `REPLICATION SLAVE, REPLICATION CLIENT` |
