:::caution Экспериментальная функция

Потоковая загрузка Doris является экспериментальной функцией и поддерживается начиная с Doris 4.1.5.

:::

<!-- Knowledge type: Procedure / Configuration parameters -->
<!-- Applicable scenario: Pre-deployment check / Environment preparation -->

Потоковая загрузка Doris поддерживает синхронизацию данных из **Amazon RDS PostgreSQL 14 и выше**. Перед запуском задачи синхронизации необходимо включить **логическую репликацию (Logical Replication)** в экземпляре RDS и завершить настройку пользователя синхронизации, разрешений и Publication.

Документ предназначен для администраторов экземпляров RDS PostgreSQL и описывает предварительные шаги, необходимые для потоковой загрузки Doris.

### Предварительный контрольный список {#pre-check-checklist}

Перед началом настройки подтвердите выполнение следующих условий:

| Пункт проверки | Требование |
| --- | --- |
| Версия RDS PostgreSQL | 14 и выше |
| Операционные разрешения | Разрешения AWS на изменение групп параметров и перезапуск экземпляра |
| Разрешения базы данных | Разрешения на создание пользователей, выдачу прав и создание Publication |
| Окно обслуживания | Запланировано непиковое окно (изменение параметров логической репликации требует перезапуска экземпляра) |

### Обзор процесса настройки {#configuration-flow-overview}

Общий процесс настройки выглядит следующим образом:

1. Проверить текущее состояние `rds.logical_replication`
2. Создать и настроить пользовательскую группу параметров (если параметр не включен)
3. Применить группу параметров к экземпляру и перезапустить его
4. Создать пользователя синхронизации Doris и выдать ему права
5. Настроить Publication в соответствии с версией Doris

## Шаг 1: Проверка текущей конфигурации {#step-1-check-the-current-configuration}

<!-- Knowledge type: Procedure -->

**Цель**: проверить, включена ли логическая репликация в экземпляре RDS, и определить, требуется ли изменять группу параметров.

После подключения к экземпляру RDS выполните следующий SQL-запрос:

```sql
SHOW rds.logical_replication;
```

Выберите дальнейший путь в зависимости от результата:

| Возвращаемое значение | Значение | Следующий шаг |
| --- | --- | --- |
| `on` | Логическая репликация включена | Перейдите к [Шагу 4: Создание пользователя синхронизации](#step-4-create-the-sync-user) |
| `off` | Логическая репликация не включена | Перейдите к [Шагу 2](#step-2-configure-the-parameter-group) |

---

## Шаг 2: Настройка группы параметров {#step-2-configure-the-parameter-group}

<!-- Knowledge type: Procedure / Configuration parameters -->

**Цель**: создать пользовательскую группу параметров и включить `rds.logical_replication`.

Действия:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. В левой панели навигации выберите **Parameter groups** и нажмите **Create parameter group**.
3. Выберите семейство версий PostgreSQL, соответствующее целевому экземпляру, и создайте новую группу параметров.
4. Измените группу параметров, найдите `rds.logical_replication` и установите для него значение `1`:

    ![PostgreSQL WAL Setting](/images/next/data-operate/streaming-job/pgwalsetting.png)

5. Нажмите **Save Changes**, чтобы сохранить изменения.

Описание ключевого параметра:

| Параметр | Значение | Описание |
| --- | --- | --- |
| `rds.logical_replication` | `1` | Включает логическую репликацию; эквивалентно установке `wal_level` в значение `logical` |

---

## Шаг 3: Применение группы параметров и перезапуск {#step-3-apply-the-parameter-group-and-restart}

<!-- Knowledge type: Procedure -->

**Цель**: привязать новую группу параметров к экземпляру RDS и перезапустить его, чтобы конфигурация вступила в силу.

Действия:

1. В консоли RDS выберите целевой экземпляр и нажмите **Modify**.
2. В разделе **DB parameter group** выберите группу параметров, созданную на [Шаге 2](#step-2-configure-the-parameter-group).
3. Выберите **Apply immediately**, чтобы немедленно применить изменение.
4. Перезапустите экземпляр RDS, чтобы конфигурация вступила в силу.

:::caution
Для применения изменения параметра `rds.logical_replication` требуется перезапустить экземпляр RDS. Выполняйте эту операцию в непиковое время.
:::

## Шаг 4: Создание пользователя синхронизации {#step-4-create-the-sync-user}

<!-- Knowledge type: Procedure / Configuration parameters -->

**Цель**: создать учетную запись базы данных, предназначенную для потоковой загрузки Doris, и выдать необходимые права на чтение и репликацию.

### 1. Создание пользователя {#1-create-the-user}

```sql
CREATE USER doris_sync PASSWORD '<password>';
```

### 2. Предоставление прав доступа к схеме {#2-grant-schema-access-privileges}

Ниже в качестве примера используется схема `public`. При необходимости замените ее целевой схемой:

```sql
GRANT USAGE ON SCHEMA "public" TO doris_sync;
GRANT SELECT ON ALL TABLES IN SCHEMA "public" TO doris_sync;
ALTER DEFAULT PRIVILEGES IN SCHEMA "public" GRANT SELECT ON TABLES TO doris_sync;
```

### 3. Предоставление прав на репликацию {#3-grant-replication-privileges}

```sql
GRANT rds_replication TO doris_sync;
```

:::tip
Amazon RDS PostgreSQL использует роль `rds_replication` для выдачи прав на репликацию, а не стандартный атрибут PostgreSQL `REPLICATION`.
:::

Обзор прав:

| Право | Назначение |
| --- | --- |
| `USAGE ON SCHEMA` | Разрешает доступ к указанной схеме |
| `SELECT ON ALL TABLES` | Разрешает чтение всех существующих таблиц в схеме |
| `ALTER DEFAULT PRIVILEGES ... SELECT` | Автоматически предоставляет право `SELECT` для таблиц, добавленных в будущем |
| `rds_replication` | Роль, необходимая для выполнения логической репликации в RDS |

## Шаг 5: Настройка Publication {#step-5-configure-the-publication}

<!-- Knowledge type: Procedure / Configuration parameters -->

По умолчанию создавать Publication вручную не требуется. Если `publication_name` не задан, Doris с помощью учетной записи синхронизации создает Publication с именем `doris_pub_<job_id>` и удаляет его при удалении задания. Поэтому учетной записи синхронизации необходимо разрешение на создание Publication.

Если при создании Streaming Job явно задан `publication_name`, предварительно создайте Publication с тем же именем. Пользовательский Publication должен включать все исходные таблицы, синхронизируемые заданием, а его сопровождение и удаление выполняет пользователь. Например:

```sql
CREATE PUBLICATION doris_pub_custom
FOR TABLE public.orders, public.customers;
```

При создании задания задайте `"publication_name" = "doris_pub_custom"`. Имя может содержать только строчные буквы, цифры и символы подчеркивания, не может начинаться с цифры и ограничено 63 символами.

## FAQ {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: Если `SHOW rds.logical_replication;` возвращает `on`, нужно ли перезапускать экземпляр?**

Нет. Значение `on` означает, что логическая репликация уже действует, поэтому можно сразу перейти к [Шагу 4: Создание пользователя синхронизации](#step-4-create-the-sync-user).

**Вопрос 2: Можно ли использовать Publication с другим именем?**

Можно указать пользовательское имя через `publication_name`, но Publication необходимо создать до создания задания и убедиться, что она включает все синхронизируемые таблицы.

**Вопрос 3: Обязательно ли использовать роль `rds_replication`?**

Да. По соображениям безопасности RDS PostgreSQL не разрешает использовать стандартный атрибут PostgreSQL `REPLICATION`. Необходимо выдать права с помощью `GRANT rds_replication`.

**Вопрос 4: Обязательно ли создавать Publication вручную?**

Если `publication_name` не указан, Doris автоматически создает и управляет Publication по умолчанию. Предварительно создавать Publication требуется только при использовании пользовательской Publication. Подробнее см. [Шаг 5](#step-5-configure-the-publication).

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->

| Симптом | Возможная причина | Решение |
| --- | --- | --- |
| `SHOW rds.logical_replication;` по-прежнему возвращает `off` | Группа параметров не привязана к экземпляру или экземпляр не был перезапущен | Проверьте, использует ли экземпляр новую группу параметров, и перезапустите его |
| Ошибка разрешений при создании пользователя | У текущей учетной записи недостаточно прав | Используйте учетную запись администратора с правом создания пользователей |
| `GRANT rds_replication` возвращает ошибку | У текущей учетной записи нет права выдавать эту роль | Используйте учетную запись `rds_superuser` или другую учетную запись с правом выдачи этой роли |
| Не удается создать Publication по умолчанию | У учетной записи синхронизации нет права создавать Publication | Выдайте учетной записи синхронизации необходимые права или попросите администратора заранее создать пользовательскую Publication и настроить `publication_name` |
| Пользовательская Publication не существует | Настроен `publication_name`, но Publication с таким именем не создана | Создайте Publication согласно инструкциям в [Шаге 5](#step-5-configure-the-publication) или удалите `publication_name`, чтобы использовать Publication по умолчанию, управляемую Doris |
| Изменения параметров не вступили в силу | Не выбран параметр **Apply immediately** или экземпляр не был перезапущен | Повторно выполните [Шаг 3](#step-3-apply-the-parameter-group-and-restart) |
