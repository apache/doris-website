<!-- Knowledge type: Procedure / Configuration parameters -->
<!-- Applicable scenario: Pre-deployment check / Environment preparation -->

Для потоковой загрузки данных в Doris поддерживается синхронизация с **Amazon RDS PostgreSQL версии 14 и выше**. Перед запуском задания синхронизации необходимо включить **Logical Replication** на экземпляре RDS и настроить пользователя синхронизации, права доступа и Publication.

Этот документ предназначен для администраторов экземпляров RDS PostgreSQL и описывает подготовительные действия, необходимые для потоковой загрузки данных в Doris.

### Контрольный список перед настройкой {#pre-check-checklist}

Перед началом настройки убедитесь, что выполнены следующие условия:

| Что проверить | Требование |
| --- | --- |
| Версия RDS PostgreSQL | 14 и выше |
| Права на выполнение операций | Права AWS на изменение групп параметров и перезапуск экземпляра |
| Права в базе данных | Права на создание пользователей, предоставление привилегий и создание Publication |
| Окно обслуживания | Запланировано окно в период низкой нагрузки (изменение параметров логической репликации требует перезапуска экземпляра) |

### Обзор процесса настройки {#configuration-flow-overview}

Общий порядок настройки:

1. Проверить текущее состояние `rds.logical_replication`
2. Создать и настроить пользовательскую группу параметров (если логическая репликация не включена)
3. Применить группу параметров к экземпляру и перезапустить его
4. Создать пользователя синхронизации Doris и предоставить ему права
5. Настроить Publication в зависимости от версии Doris

---

## Шаг 1: Проверка текущей конфигурации {#step-1-check-the-current-configuration}

<!-- Knowledge type: Procedure -->

**Цель**: Проверить, включена ли логическая репликация на экземпляре RDS, и определить, нужно ли изменять группу параметров.

После подключения к экземпляру RDS выполните следующий SQL-запрос:

```sql
SHOW rds.logical_replication;
```

Выберите дальнейшие действия в зависимости от результата:

| Возвращённое значение | Значение | Следующий шаг |
| --- | --- | --- |
| `on` | Логическая репликация включена | Перейдите к [шагу 4: Создание пользователя синхронизации](#step-4-create-the-sync-user) |
| `off` | Логическая репликация не включена | Продолжите с [шага 2](#step-2-configure-the-parameter-group) |

---

## Шаг 2: Настройка группы параметров {#step-2-configure-the-parameter-group}

<!-- Knowledge type: Procedure / Configuration parameters -->

**Цель**: Создать пользовательскую группу параметров и включить `rds.logical_replication`.

Порядок действий:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. На панели навигации слева выберите **Группы параметров** и нажмите **Создать группу параметров**.
3. Выберите семейство версий PostgreSQL, соответствующее целевому экземпляру, и создайте новую группу параметров.
4. Откройте группу параметров для редактирования, найдите `rds.logical_replication` и установите значение `1`:

    ![Настройка WAL в PostgreSQL](/images/next/data-operate/streaming-job/pgwalsetting.png)

5. Нажмите **Сохранить изменения**.

Описание основного параметра:

| Параметр | Значение | Описание |
| --- | --- | --- |
| `rds.logical_replication` | `1` | Включает логическую репликацию; эквивалентно установке `wal_level` в `logical` |

---

## Шаг 3: Применение группы параметров и перезапуск {#step-3-apply-the-parameter-group-and-restart}

<!-- Knowledge type: Procedure -->

**Цель**: Привязать новую группу параметров к экземпляру RDS и перезапустить его, чтобы конфигурация вступила в силу.

Порядок действий:

1. В консоли RDS выберите целевой экземпляр и нажмите **Изменить**.
2. В поле **Группа параметров БД** выберите группу параметров, созданную на [шаге 2](#step-2-configure-the-parameter-group).
3. Выберите **Применить немедленно**, чтобы сразу применить изменение.
4. Перезапустите экземпляр RDS, чтобы конфигурация вступила в силу.

:::caution
Чтобы изменение параметра `rds.logical_replication` вступило в силу, необходимо перезапустить экземпляр RDS. Выполняйте эту операцию в период низкой нагрузки.
:::

## Шаг 4: Создание пользователя синхронизации {#step-4-create-the-sync-user}

<!-- Knowledge type: Procedure / Configuration parameters -->

**Цель**: Создать отдельную учётную запись базы данных для потоковой загрузки данных в Doris и предоставить необходимые права на чтение и репликацию.

### 1. Создание пользователя {#1-create-the-user}

```sql
CREATE USER doris_sync PASSWORD '<password>';
```

### 2. Предоставление прав доступа к схеме {#2-grant-schema-access-privileges}

В следующем примере используется схема `public`. При необходимости замените её на целевую схему:

```sql
GRANT USAGE ON SCHEMA "public" TO doris_sync;
GRANT SELECT ON ALL TABLES IN SCHEMA "public" TO doris_sync;
ALTER DEFAULT PRIVILEGES IN SCHEMA "public" GRANT SELECT ON TABLES TO doris_sync;
```

### 3. Предоставление прав на репликацию {#3-grant-replication-privileges}

```sql
GRANT rds_replication TO doris_sync;
```

:::tip
Для предоставления прав на репликацию Amazon RDS PostgreSQL использует роль `rds_replication` вместо стандартного атрибута PostgreSQL `REPLICATION`.
:::

Обзор прав:

| Право | Назначение |
| --- | --- |
| `USAGE ON SCHEMA` | Разрешает доступ к указанной схеме |
| `SELECT ON ALL TABLES` | Разрешает чтение всех существующих таблиц в схеме |
| `ALTER DEFAULT PRIVILEGES ... SELECT` | Автоматически предоставляет право `SELECT` на таблицы, добавленные в будущем |
| `rds_replication` | Роль, необходимая для выполнения логической репликации в RDS |

## Шаг 5: Настройка Publication {#step-5-configure-the-publication}

<!-- Knowledge type: Procedure / Configuration parameters -->

### Doris 4.0 {#doris-40}

Необходимо заранее создать Publication с именем `dbz_publication`, используя `FOR ALL TABLES`:

```sql
CREATE PUBLICATION dbz_publication FOR ALL TABLES;
```

Если пользователь синхронизации обладает правами суперпользователя, например ролью `rds_superuser`, Doris может автоматически создать `dbz_publication` при запуске задания, и выполнять эту команду вручную не требуется. Doris 4.0 не поддерживает пользовательские имена Publication и Publication, содержащие только часть таблиц.

### Doris 4.1.0 и новее {#doris-410-and-later}

По умолчанию создавать Publication вручную не требуется. Если `publication_name` не задан, Doris использует учётную запись синхронизации для создания Publication с именем `doris_pub_<job_id>` и удаляет её при удалении задания. Поэтому учётная запись синхронизации должна иметь право на создание Publication.

Если при создании Streaming Job явно задан `publication_name`, заранее создайте Publication с таким же именем. Пользовательская Publication должна включать все исходные таблицы, синхронизируемые заданием; за её сопровождение и удаление отвечает пользователь. Например:

```sql
CREATE PUBLICATION doris_pub_custom
FOR TABLE public.orders, public.customers;
```

При создании задания укажите `"publication_name" = "doris_pub_custom"`. Имя может содержать только строчные латинские буквы, цифры и символы подчёркивания, не может начинаться с цифры и ограничено 63 символами.

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: Если `SHOW rds.logical_replication;` возвращает `on`, нужно ли перезапускать экземпляр?**

Нет. Значение `on` означает, что логическая репликация уже действует, и можно сразу перейти к [шагу 4: Создание пользователя синхронизации](#step-4-create-the-sync-user).

**Вопрос 2: Можно ли использовать Publication с другим именем?**

Doris 4.0 не поддерживает пользовательские имена и поддерживает только `dbz_publication FOR ALL TABLES`. Начиная с версии 4.1.0, можно указать пользовательское имя через `publication_name`, но необходимо создать Publication до создания задания и убедиться, что она включает все синхронизируемые таблицы.

**Вопрос 3: Обязательно ли использовать роль `rds_replication`?**

Да. По соображениям безопасности RDS PostgreSQL не разрешает использовать стандартный атрибут PostgreSQL `REPLICATION`. Права необходимо предоставить через `GRANT rds_replication`.

**Вопрос 4: Обязательно ли создавать Publication вручную?**

В Doris 4.0 обычный пользователь синхронизации должен создать `dbz_publication` вручную, а если пользователь обладает правами суперпользователя, Doris может создать её автоматически. Начиная с версии 4.1.0, если `publication_name` не указан, Doris автоматически создаёт Publication по умолчанию и управляет ею. Заранее создавать нужно только пользовательскую Publication. Подробнее см. [шаг 5](#step-5-configure-the-publication).

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->

| Проблема | Возможная причина | Решение |
| --- | --- | --- |
| `SHOW rds.logical_replication;` по-прежнему возвращает `off` | Группа параметров не привязана к экземпляру или экземпляр не был перезапущен | Проверьте, использует ли экземпляр новую группу параметров, и перезапустите его |
| Ошибка прав доступа при создании пользователя | У текущей учётной записи недостаточно прав | Используйте учётную запись администратора с правом создания пользователей |
| `GRANT rds_replication` возвращает ошибку | У текущей учётной записи нет права предоставлять эту роль | Используйте учётную запись с ролью `rds_superuser` или другую учётную запись с правом предоставления этой роли |
| Doris 4.0 сообщает, что `dbz_publication` не существует | `dbz_publication` не создана, а учётная запись синхронизации не обладает правами суперпользователя | Выполните `CREATE PUBLICATION dbz_publication FOR ALL TABLES;` или используйте учётную запись с необходимыми правами |
| Doris 4.1.0 или новее не удаётся создать Publication по умолчанию | У учётной записи синхронизации нет права на создание Publication | Предоставьте учётной записи синхронизации необходимые права или попросите администратора заранее создать пользовательскую Publication и настройте `publication_name` |
| Doris 4.1.0 или новее сообщает, что пользовательская Publication не существует | Параметр `publication_name` настроен, но Publication с таким именем не создана | Создайте Publication, как описано на [шаге 5](#step-5-configure-the-publication), или удалите `publication_name`, чтобы использовать Publication по умолчанию, которой управляет Doris |
| Изменения параметров не вступают в силу | Не выбран вариант **Применить немедленно** или экземпляр не был перезапущен | Повторите [шаг 3](#step-3-apply-the-parameter-group-and-restart) |
