Загрузка по уведомлениям использует `NOTIFICATION` для получения из SQS событий создания объектов S3 и непрерывной загрузки новых файлов в Doris. Этот режим подходит для файлов с именами в формате UUID и файлов, поступающих в произвольном порядке, поскольку не зависит от упорядоченности имён файлов.

Поддерживаются только **уведомления AWS S3, отправляемые напрямую в SQS Standard Queue в том же регионе**. Для каждого задания нужна выделенная очередь. Существующие объекты не сканируются и не загружаются задним числом. Сквозная доставка имеет семантику at-least-once: объект может быть загружен несколько раз, а порядок загрузки файлов не гарантируется.

## Быстрый старт {#quick-start}

В примере используется `s3://example-bucket/data/*.csv` в регионе `us-east-1`. Замените бакет, учётную запись, очередь и учётные данные своими значениями.

### Подготовьте целевую таблицу Doris {#prepare-the-doris-target-table}

Учётной записи нужны привилегия `LOAD` для целевой таблицы и соответствующие привилегии на создание базы данных и таблицы. Используйте отдельную пустую таблицу, чтобы избежать пересечения с другими примерами.

```sql
CREATE DATABASE IF NOT EXISTS db1;
CREATE TABLE db1.tbl1 (
    id INT,
    name STRING
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ("replication_num" = "1");
```

В этом примере с одним BE используется одна реплика. Для промышленной эксплуатации скорректируйте количество реплик.

### Шаг 1: Создайте SQS Standard Queue {#step-1-create-an-sqs-standard-queue}

Создайте Standard Queue в **том же регионе**, что и бакет S3, и сохраните её URL и ARN. Рекомендуется установить срок хранения сообщений в 14 дней, чтобы учесть приостановки и сбои. SQS удаляет сообщения по истечении срока хранения.

### Шаг 2: Разрешите S3 отправлять уведомления {#step-2-allow-s3-to-send-notifications}

Добавьте следующий блок в политику доступа к очереди, заменив идентификаторы учётной записи, бакета и очереди:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3ToSendMessage",
      "Effect": "Allow",
      "Principal": {"Service": "s3.amazonaws.com"},
      "Action": "sqs:SendMessage",
      "Resource": "arn:aws:sqs:us-east-1:<account-id>:<queue-name>",
      "Condition": {
        "ArnEquals": {"aws:SourceArn": "arn:aws:s3:::example-bucket"},
        "StringEquals": {"aws:SourceAccount": "<account-id>"}
      }
    }
  ]
}
```

### Шаг 3: Предоставьте Doris доступ {#step-3-grant-doris-access}

Предоставьте пользователю или роли IAM, используемым заданием, следующие разрешения. FE нужен доступ к SQS и S3; BE должен иметь возможность читать объекты S3. Для AssumeRole также требуется подключение к STS.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::example-bucket"
    },
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::example-bucket/data/*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "sqs:ReceiveMessage",
        "sqs:DeleteMessage",
        "sqs:GetQueueAttributes",
        "sqs:ChangeMessageVisibility"
      ],
      "Resource": "arn:aws:sqs:us-east-1:<account-id>:<queue-name>"
    }
  ]
}
```

### Шаг 4: Настройте уведомления о событиях S3 {#step-4-configure-s3-event-notifications}

Создайте правило в разделе «Уведомления о событиях» бакета:

- Выберите **Все события создания объектов** (`s3:ObjectCreated:*`).
- Задайте префикс `data/` и суффикс `.csv` без подстановочных знаков. Правило должно охватывать шаблон URI задания.
- Выберите очередь SQS в качестве назначения. Отправляйте сообщения S3 напрямую, без оболочки SNS.

Включите правило перед отправкой файлов, которые нужно загрузить. Создание правила уведомлений не генерирует события для существующих объектов.

### Шаг 5: Создайте Streaming Job {#step-5-create-the-streaming-job}

Для определения схемы при создании задания функции S3 TVF нужны файлы, соответствующие шаблону. После включения уведомлений отправьте непустой файл `data/001.csv` со следующим содержимым:

```text
1,Alice
2,Bob
```

Затем создайте задание:

```sql
CREATE JOB s3_event_job
PROPERTIES (
    "s3.ingestion_mode" = "NOTIFICATION",
    "s3.event.source" = "SQS",
    "s3.sqs.queue_url" = "https://sqs.us-east-1.amazonaws.com/<account-id>/<queue-name>",
    "max_interval" = "10"
)
ON STREAMING DO
INSERT INTO db1.tbl1
SELECT * FROM S3(
    "uri" = "s3://example-bucket/data/*.csv",
    "format" = "csv",
    "column_separator" = ",",
    "provider" = "S3",
    "s3.region" = "us-east-1",
    "s3.endpoint" = "https://s3.us-east-1.amazonaws.com",
    "s3.access_key" = "<access-key>",
    "s3.secret_key" = "<secret-key>"
);
```

Этот файл генерирует уведомление SQS. Объекты, отправленные до настройки уведомлений, могут использоваться для определения схемы, но не загружаются автоматически задним числом. При создании задания хотя бы один файл, соответствующий шаблону, должен оставаться доступным для чтения.

Чтобы использовать роль IAM, замените параметры ключа доступа и секретного ключа следующими; необходимость указания `s3.external_id` зависит от политики доверия:

```sql
"s3.role_arn" = "arn:aws:iam::<account-id>:role/<role-name>",
"s3.external_id" = "<external-id>"
```

FE вызывает AssumeRole, используя настроенные для него учётные данные AWS. Роли нужны разрешения S3 и SQS, вызывающей стороне нужно разрешение `sts:AssumeRole`, а политика доверия роли должна разрешать доступ этой стороне.

После обработки уведомления для `data/001.csv` таблица содержит соответствующие две строки. Последующие файлы загружаются по уведомлениям, даже если их ключи меньше ранее обработанных ключей. Повторные уведомления могут влиять на количество строк в зависимости от модели целевой таблицы.

### Шаг 6: Отслеживайте накопление сообщений в очереди {#step-6-monitor-the-queue-backlog}

```sql
SELECT Name, Status, CurrentOffset, EndOffset, LagBytes,
       LastSourceEventTimestamp, LastTaskSuccessTime
FROM jobs("type" = "insert")
WHERE Name = 's3_event_job';
```

Пример `CurrentOffset`: `{"fileName":"data/a.csv"}`. Пример `EndOffset`: `{"fileName":"data/b.csv","lagMessages":12}`. Эти ключи описывают позиции пакетов, а не лексикографические отметки прогресса, и по ним нельзя определить, загружены ли все поступившие данные.

| Поле | Значение в режиме уведомлений |
| --- | --- |
| `LagBytes` | `-1`: размер объектов в очереди в байтах недоступен. |
| `EndOffset.lagMessages` | Приблизительное количество видимых сообщений SQS без учёта сообщений в обработке и отложенных сообщений. Это не количество файлов. |
| `LastSourceEventTimestamp` | Максимальная временная метка события S3 в последнем зафиксированном пакете, в секундах Unix. Она не подтверждает, что все более ранние события обработаны. |

FE также предоставляет метрики для каждого задания:

```text
doris_fe_streaming_job_per_job_lag_messages
doris_fe_streaming_job_per_job_last_source_event_timestamp_seconds
```

## Подтверждение обработки и ограничения {#acknowledgment-and-limitations}

- Обрабатываются только уведомления, которые ещё хранятся в SQS. Существующие объекты не сканируются.
- Для создания задания нужен доступный для чтения непустой файл, соответствующий шаблону, чтобы S3 TVF могла определить схему.
- Каждая очередь должна использоваться исключительно одним заданием. Doris пропускает и подтверждает записи, не соответствующие области загрузки, некорректные или неподдерживаемые уведомления и тестовые события S3. Задания с разными шаблонами URI не должны использовать одну очередь.
- Для корректных файлов сообщения удаляются после фиксации транзакции INSERT. Во время обработки период невидимости продлевается, а пакеты, обработка которых завершилась с ошибкой, могут обрабатываться повторно. При восстановлении FE может использовать сохранённые ключи из последнего зафиксированного пакета для обработки его повторной доставки; Doris не сохраняет все ключи за всё время для глобальной дедупликации.
- S3 и SQS могут доставлять дубликаты. Сквозная доставка имеет семантику at-least-once, а порядок загрузки файлов не гарантируется. При необходимости используйте таблицу Unique Key для дедупликации по бизнес-ключам и столбец Sequence для обновлений, чувствительных к порядку.
- Обеспечьте уникальность ключей объектов, неизменность их содержимого и доступность для чтения. Doris читает содержимое на момент обработки, которое может отличаться от версии на момент создания события. Преждевременное удаление объектов приводит к ошибкам и повторным попыткам.

## Параметры {#parameters}

Настройте следующие параметры в `PROPERTIES` задания. Параметры подключения к S3, учётных данных и формата файлов указываются в `S3(...)`.

| Параметр | Тип | Значение по умолчанию | Обязательный | Описание |
| --- | --- | --- | --- | --- |
| `s3.ingestion_mode` | String | `ORDERED_LIST` | Да | Установите значение `NOTIFICATION`. Нельзя изменить после создания. |
| `s3.event.source` | String | Нет | Да | Значение должно быть `SQS`. Нельзя изменить после создания. |
| `s3.sqs.queue_url` | String | Нет | Да | URL выделенной очереди SQS. Нельзя изменить после создания. |
| `s3.max_batch_files` | Положительное целое число | `256` | Нет | Порог количества файлов в пакете. |
| `s3.max_batch_bytes` | Целое число | `10737418240` | Нет | Порог размера пакета в байтах, от `104857600` до `10737418240`. Суффиксы единиц измерения не поддерживаются. |
| `max_interval` | Положительное целое число | `10` | Нет | Интервал планирования при отсутствии данных в секундах. Должен быть меньше `7200`. |

Пороговые значения пакета не являются жёсткими ограничениями: ждать заполнения пакета не требуется. Уже полученные сообщения остаются в том же пакете; после достижения порога дальнейшее получение сообщений прекращается, поэтому пакет может превысить любой из порогов. Параметр `offset` запрещён при создании и в `ALTER JOB`. URI S3 нельзя изменить. Чтобы изменить путь или очередь, создайте другое задание.

## Устранение неполадок и рекомендации {#troubleshooting-and-best-practices}

| Проблема | Проверки и действия |
| --- | --- |
| Не удаётся создать задание | Проверьте наличие непустых файлов, соответствующих шаблону, разрешения S3/SQS и сетевое подключение. |
| Задание работает, но не загружает файлы | Убедитесь, что уведомления были настроены до отправки файлов, выбрано событие `s3:ObjectCreated:*`, фильтры охватывают URI и никакой другой потребитель не читает очередь. |
| Отсутствуют ранее существовавшие файлы | Правила уведомлений не воспроизводят события за прошлое время. Используйте отдельный префикс и [однократную загрузку](./continuous-load-s3-one-time.md). |
| После приостановки отсутствуют файлы | Проверьте срок хранения сообщений SQS и при необходимости отдельно загрузите недостающие файлы. |
| Повторяющиеся ошибки чтения | Изучите `ErrorMsg` и ошибки задач. Проверьте доступность объектов, неизменность их содержимого и совместимость формата. |
| Дублирующиеся строки | Проверьте бизнес-ключи и модель целевой таблицы. Не полагайтесь на глобальную дедупликацию всех ранее обработанных файлов. |

Установите достаточный срок хранения сообщений, обеспечьте неизменность содержимого объектов и их доступность для чтения, отслеживайте приблизительное количество накопившихся сообщений, время последнего успешного выполнения и ошибки задач. Сведения об управлении заданиями см. в разделах [Обзор непрерывной загрузки](./continuous-load-overview.md) и [ALTER JOB](../../../../sql-manual/sql-statements/job/ALTER-JOB.md).
