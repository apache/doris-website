Синхронизация с автоматическим созданием таблиц реализована с помощью встроенной DDL-команды `FROM POSTGRES (...) TO DATABASE (...)`. В качестве назначения используется база данных Doris, в которой Doris автоматически создаёт соответствующие целевые таблицы на основе схем исходных таблиц. С помощью `include_tables` можно указать, какие таблицы синхронизировать: одну, несколько или все. При первой синхронизации Doris автоматически создаёт целевые таблицы с первичными ключами, соответствующими ключам исходных таблиц. Этот подход подходит для зеркальной репликации, когда обработка данных средствами SQL не требуется, а схемы целевых таблиц должны автоматически следовать схемам исходных.

Благодаря интеграции с [Flink CDC](https://github.com/apache/flink-cdc) Doris считывает журналы изменений PostgreSQL и непрерывно записывает полные данные и инкрементальные изменения группы таблиц в Doris через Stream Load. Синхронизация с автоматическим созданием таблиц позволяет задать имя целевой таблицы для отдельной исходной таблицы или исключить столбцы, не входящие в первичный ключ. Если нужны выражения SQL, фильтрация строк или преобразование данных, см. [PostgreSQL CDC с сопоставлением на SQL](./continuous-load-postgresql-table.md).

### Сценарии использования {#use-cases}

-   Зеркальная репликация всей базы данных PostgreSQL или нескольких таблиц в Doris
-   Поддержание соответствия схем целевых таблиц исходным без ручного создания таблиц
-   Требуется только переименование целевых таблиц или исключение столбцов, без выражений SQL, фильтрации строк и преобразования данных
-   Нужны как полная инициализация, так и непрерывный захват инкрементальных изменений

### Примечания {#notes}

1.  В настоящее время гарантируется только семантика at-least-once.
2.  Синхронизировать можно только исходные таблицы с первичными ключами; автоматически создаваемые целевые таблицы используют модель Unique Key.
3.  Требуется привилегия Load. Если целевая таблица не существует, также требуется привилегия Create.
4.  При автоматическом создании таблиц уже существующие целевые таблицы пропускаются, поэтому пользователи могут заранее настроить таблицы под свои сценарии.

## Быстрый старт {#quick-start}

<!-- Knowledge type: Operating procedure -->

Выполните следующие шаги, чтобы создать задание синхронизации PostgreSQL с автоматическим созданием таблиц и проверить его состояние.

### Шаг 1: создайте задание загрузки {#step-1-create-a-load-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки:

```sql
CREATE JOB test_postgres_job
ON STREAMING
FROM POSTGRES (
    "jdbc_url" = "jdbc:postgresql://127.0.0.1:5432/postgres",
    "driver_url" = "postgresql-42.5.1.jar",
    "driver_class" = "org.postgresql.Driver",
    "user" = "postgres",
    "password" = "postgres",
    "database" = "postgres",
    "schema" = "public",
    "include_tables" = "test_tbls",
    "offset" = "latest"
)
TO DATABASE target_test_db (
  "table.create.properties.replication_num" = "1"  -- Set to 1 for single-BE deployments
)
```

### Шаг 2: проверьте состояние загрузки {#step-2-check-load-status}

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING";
```

Подробнее об общих операциях (приостановке, возобновлении, удалении, просмотре задач и т. д.) см. в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Справочник параметров {#parameter-reference}

<!-- Knowledge type: Configuration parameters -->

### Параметры источника (на стороне PostgreSQL) {#source-parameters-postgresql-side}

Параметры источника PostgreSQL задают подключение JDBC, область синхронизации и разбиение полного снимка на части. Сведения о подключении и драйвере, а также `database` и `schema` обязательны.

| Параметр | Обязательный | По умолчанию | Описание |
| --- | --- | --- | --- |
| `jdbc_url` | Да | - | Строка подключения JDBC к PostgreSQL. |
| `driver_url` | Да | - | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, локальный абсолютный путь или HTTP URL. Подробнее см. в разделе [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md). |
| `driver_class` | Да | - | Имя класса драйвера JDBC, например `org.postgresql.Driver`. |
| `user` | Да | - | Имя пользователя базы данных. |
| `password` | Да | - | Пароль базы данных. |
| `database` | Да | - | Имя базы данных PostgreSQL. Должно совпадать с именем базы данных в JDBC URL и не превышать 63 байт после кодирования в UTF-8. |
| `schema` | Да | - | Имя схемы. |
| `include_tables` | Нет | - | Имена таблиц для синхронизации, разделённые запятыми. Если параметр не задан, синхронизируются все таблицы схемы. |
| `exclude_tables` | Нет | - | Имена таблиц, которые не нужно синхронизировать, разделённые запятыми. Этот параметр действует только в том случае, если `include_tables` не задан. |
| `table.<table_name>.target_table` | Нет | Имя исходной таблицы | Поддерживается начиная с версии 4.1.0. Задаёт имя целевой таблицы Doris для исходной таблицы. `<table_name>` — имя исходной таблицы. |
| `table.<table_name>.exclude_columns` | Нет | - | Поддерживается начиная с версии 4.1.0. Указывает исходные столбцы, которые не нужно синхронизировать, через запятую. Столбцы должны существовать и не могут входить в первичный ключ. |
| `offset` | Нет | `latest` | Начальное смещение. `initial`: полная и инкрементальная синхронизация; `latest`: синхронизация только изменений, появившихся после запуска задания. Также можно указать точное смещение в JSON, например `{"lsn":"12345678"}`. Начиная с версии 4.1.0 также поддерживается `snapshot` для выполнения только полной синхронизации. PostgreSQL не поддерживает `earliest`. |
| `snapshot_split_size` | Нет | `40960` (`8096` до 4.1.4) | Размер части в строках. При полной синхронизации таблица разбивается на несколько частей. Значение должно быть положительным целым числом. |
| `snapshot_parallelism` | Нет | `1` | Параллелизм этапа полной синхронизации, то есть максимальное количество частей, одновременно обрабатываемых одной задачей. Значение должно быть положительным целым числом. |
| `slot_name` | Нет | `doris_cdc_<job_id>` | Поддерживается начиная с версии 4.1.0. Имя слота логической репликации. Может содержать только строчные буквы, цифры и знаки подчёркивания, не может начинаться с цифры и ограничено 63 символами. Пользовательский слот необходимо создать заранее; Doris его не удаляет. |
| `publication_name` | Нет | `doris_pub_<job_id>` | Поддерживается начиная с версии 4.1.0. Имя публикации. Правила именования такие же, как для `slot_name`. Пользовательскую публикацию необходимо создать заранее и включить в неё все синхронизируемые таблицы; Doris её не удаляет. |
| `ssl_mode` | Нет | `disable` | Поддерживается начиная с версии 4.1.0. Режим SSL. Допустимые значения: `disable`, `require` и `verify-ca`. |
| `ssl_rootcert` | Обязателен при определённых условиях | - | Поддерживается начиная с версии 4.1.0. Файл сертификата CA в формате `FILE:<file_name>`. Обязателен, если для `ssl_mode` задано значение `verify-ca`. Сначала загрузите файл с помощью [CREATE FILE](../../../../sql-manual/sql-statements/security/CREATE-FILE.md). |

Если заданы и `include_tables`, и `exclude_tables`, приоритет имеет `include_tables`. Следующий фрагмент параметров `FROM POSTGRES` синхронизирует `orders` и `customers`, записывает данные из `orders` в `ods_orders`, исключает не входящий в первичный ключ столбец `internal_note` и использует заранее созданные ресурсы логической репликации с проверкой CA:

```sql
"include_tables" = "orders,customers",
"table.orders.target_table" = "ods_orders",
"table.orders.exclude_columns" = "internal_note",
"slot_name" = "orders_slot",
"publication_name" = "orders_publication",
"ssl_mode" = "verify-ca",
"ssl_rootcert" = "FILE:ca.pem"
```

Пользовательские слоты репликации и публикации управляются пользователем и сохраняются при удалении задания Streaming Job. Если `slot_name` или `publication_name` не задан, Doris создаёт соответствующий ресурс для задания и удаляет созданные им ресурсы при удалении задания.

### Параметры целевой базы данных Doris {#doris-target-database-parameters}

Параметры на стороне назначения задают свойства автоматически создаваемых таблиц и стратегию записи через Stream Load. Все перечисленные ниже параметры необязательны.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `table.create.properties.*` | - | Добавляет свойства таблицы при её создании в Doris, например `table.create.properties.replication_num`. |
| `load.strict_mode` | `false` | Включает строгий режим записи через Stream Load. Допустимые значения: `true` и `false`. |
| `load.max_filter_ratio` | `0` | Максимально допустимая доля отфильтрованных строк в окне выборки, в диапазоне `[0, 1]`. `0` означает, что строки с ошибками нельзя отфильтровывать. Длительность окна выборки составляет `max_interval * 10` секунд. Задание приостанавливается, если отношение количества строк с ошибками к общему количеству строк в окне превышает это значение. |

## Справочная информация {#reference}

<!-- Knowledge type: Syntax reference -->

### Синтаксис команды загрузки {#load-command-syntax}

Синтаксис создания задания синхронизации с автоматическим созданием таблиц:

```sql
CREATE JOB <job_name>
[job_properties]
ON STREAMING
[ COMMENT <comment> ]
FROM POSTGRES (
    [source_properties]
)
TO DATABASE <target_db> (
    [target_properties]
)
```

Описание элементов команды:

| Элемент           | Описание                                          |
| ----------------- | ------------------------------------------------- |
| job_name          | Имя задания                                       |
| job_properties    | Общие параметры загрузки задания                  |
| comment           | Комментарий с описанием задания                   |
| source_properties | Параметры источника PostgreSQL                    |
| target_properties | Параметры целевой базы данных Doris                |

`job_properties` поддерживает `max_interval` и `compute_group`. Подробнее см. в разделе [Общие параметры загрузки для заданий](./continuous-load-overview.md#job-common-load-configuration-parameters). Режим автоматического создания таблиц не использует `session.*`.

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: Frequently asked questions -->

**Вопрос 1: как выбрать между синхронизацией с автоматическим созданием таблиц и синхронизацией с сопоставлением на SQL?**

-   Если нужна зеркальная репликация, автоматическое создание таблиц или только переименование целевых таблиц и исключение столбцов, не входящих в первичный ключ, используйте синхронизацию с автоматическим созданием таблиц.
-   Если в процессе синхронизации нужны выражения SQL, фильтрация строк или преобразование данных, используйте [PostgreSQL CDC с сопоставлением на SQL](./continuous-load-postgresql-table.md).

**Вопрос 2: поддерживаются ли таблицы без первичного ключа?**

В настоящее время поддерживается синхронизация только таблиц с первичным ключом. Таблицы без первичного ключа пока не поддерживаются.

**Вопрос 3: что делать, если не удаётся создать таблицу в развёртывании с одним BE?**

Необходимо явно задать `"table.create.properties.replication_num" = "1"` в предложении `TO DATABASE`, чтобы избежать несоответствия между количеством реплик по умолчанию и количеством доступных BE.

**Вопрос 4: будет ли перезаписана целевая таблица, если она уже существует?**

Нет. На этапе автоматического создания таблиц уже существующие целевые таблицы пропускаются. При необходимости можно заранее настроить схему таблицы.

**Вопрос 5: как синхронизировать только инкрементальные данные, пропустив этап полной синхронизации?**

Задайте для `offset` значение `latest`. Задание будет получать только последние инкрементальные изменения и не будет выполнять полную инициализацию.
