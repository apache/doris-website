<!-- Applicable scenario: Upstream schema changes during MySQL Auto Table Creation Sync -->

Синхронизация изменений схемы MySQL автоматически применяет к Doris изменения столбцов в исходной базе данных MySQL во время непрерывной загрузки. Эта возможность доступна только для [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md). Она не поддерживается для [MySQL CDC с SQL Mapping](./continuous-load-mysql-table.md).

:::tip

Синхронизация изменений схемы MySQL поддерживается начиная с Doris 4.1.4.

:::

## Поддерживаемые изменения схемы {#supported-schema-changes}

| Операция MySQL | Поведение Doris |
| --- | --- |
| `ADD COLUMN` | Добавляет столбец с тем же именем и типом, определяемым [сопоставлением типов данных MySQL](./data-type-mapping-mysql.md), и копирует комментарий к столбцу. Ограничения DEFAULT и `NOT NULL` не копируются, а ранее загруженные строки не заполняются значениями нового столбца. В последующих строках используются фактические значения, которые MySQL записывает в binlog. |
| `DROP COLUMN` | Удаляет столбец с тем же именем. |

## Что следует учитывать {#considerations}

- Если добавляемый столбец уже существует или удаляемый столбец отсутствует, Doris пропускает операцию, чтобы повторная попытка не приводила к сбою задания.
- Позиции столбцов, заданные с помощью `FIRST` и `AFTER`, не синхронизируются с Doris. Новые столбцы добавляются после существующих столбцов Doris.
- Операции `CHANGE COLUMN`, `MODIFY COLUMN`, `RENAME COLUMN`, изменения DEFAULT и изменения ограничений `NULL` / `NOT NULL` не синхронизируются автоматически. Перед выполнением этих операций приостановите задание непрерывной загрузки, вручную измените целевую таблицу Doris, убедитесь, что обе схемы совместимы, а затем возобновите задание.
- Изменения первичного ключа, индексов, партиций, имени таблицы и другие изменения схемы на уровне таблицы не синхронизируются автоматически.
- При синхронизации с автоматическим созданием таблиц синхронизация изменений схемы включена по умолчанию. В настоящее время Doris не предоставляет SQL-свойство для её отключения. Табличная функция `cdc_stream()` (синхронизация с SQL Mapping) отключает синхронизацию изменений схемы внутри своей реализации.
