Потоковая загрузка в Doris поддерживает синхронизацию данных из Amazon RDS MySQL. Совместимые версии: **MySQL 5.6, 5.7 и 8.0.x**. Перед запуском задачи синхронизации необходимо убедиться, что для экземпляра RDS включён Binlog и журналы изменений записываются в правильном формате.

Этот документ предназначен для пользователей, которым нужно синхронизировать данные из Amazon RDS MySQL в Doris с помощью потоковой загрузки (CDC). В нём последовательно описаны все необходимые предварительные настройки.

## Контрольный список предварительных условий {#prerequisite-checklist}

Перед началом убедитесь, что выполнены следующие условия:

| Проверяемый пункт | Ожидаемое значение | Описание |
| --- | --- | --- |
| `log_bin` | `ON` | Binlog включён |
| `binlog_format` | `ROW` | Изменения записываются в построчном режиме |
| `binlog_row_image` | `FULL` | Записывается полный образ строки |
| Пользователь синхронизации | Создан | Имеет привилегии `SELECT`, `REPLICATION SLAVE` и `REPLICATION CLIENT` |
| Срок хранения Binlog | Не менее 72 часов | Предотвращает преждевременное удаление журналов, которое может прервать синхронизацию |

Если какое-либо из условий не выполнено, последовательно выполните описанные ниже шаги настройки.

## Шаг 1: Проверка текущей конфигурации Binlog {#step-1-check-the-current-binlog-configuration}

**Цель**: проверить текущее состояние Binlog на экземпляре RDS и определить, нужно ли изменять группу параметров.

После подключения к экземпляру RDS выполните следующий SQL:

```sql
-- Check if binlog is enabled
SHOW VARIABLES LIKE 'log_bin';

-- Check binlog format
SHOW VARIABLES LIKE 'binlog_format';

-- Check binlog row image
SHOW VARIABLES LIKE 'binlog_row_image';
```

**Как интерпретировать результаты**:

-   Если `log_bin = ON`, `binlog_format = ROW` и `binlog_row_image = FULL`, дополнительная настройка не требуется. Можно сразу перейти к [шагу 4: Создание пользователя синхронизации](#step-4-create-a-sync-user).
-   Если какое-либо из этих условий не выполнено, выполните шаг 2 и шаг 3.

## Шаг 2: Создание и настройка группы параметров {#step-2-create-and-configure-a-parameter-group}

**Цель**: создать пользовательскую группу параметров в консоли AWS и задать для параметров Binlog значения, необходимые для потоковой загрузки в Doris.

Порядок действий:

1.  Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2.  В левой панели навигации выберите **Группы параметров** и нажмите **Создать группу параметров**.
3.  Выберите соответствующее семейство версий MySQL и создайте новую группу параметров.
4.  Откройте группу параметров для редактирования, найдите `binlog_format` и установите значение `ROW`:

    ![Настройка формата Binlog в MySQL](/images/next/data-operate/streaming-job/mysql-binlog-setting.png)

5.  Аналогично найдите `binlog_row_image` и установите значение `FULL`.
6.  Нажмите **Сохранить изменения**.

Параметры, которые необходимо изменить, приведены в таблице ниже:

| Параметр | Требуемое значение | Назначение |
| --- | --- | --- |
| `binlog_format` | `ROW` | Записывает изменения данных на уровне строк, что необходимо для синхронизации CDC |
| `binlog_row_image` | `FULL` | Записывает полные данные строки до и после каждого изменения |

## Шаг 3: Применение группы параметров и перезапуск экземпляра {#step-3-apply-the-parameter-group-and-restart-the-instance}

**Цель**: привязать новую группу параметров к целевому экземпляру RDS и перезапустить его, чтобы настройки вступили в силу.

Порядок действий:

1.  В консоли RDS выберите целевой экземпляр и нажмите **Изменить**.
2.  В поле **Группа параметров БД** выберите созданную группу параметров.
3.  Выберите **Применить немедленно**, чтобы сразу применить изменение.
4.  Перезапустите экземпляр RDS, чтобы настройки вступили в силу.

:::caution
Изменение параметра `binlog_format` вступает в силу только после перезапуска экземпляра RDS. Выполняйте эту операцию в часы низкой нагрузки.
:::

## Шаг 4: Создание пользователя синхронизации {#step-4-create-a-sync-user}

**Цель**: создать отдельную учётную запись для потоковой загрузки в Doris, следуя принципу минимальных привилегий.

1.  Создайте отдельного пользователя:

    ```sql
    CREATE USER 'doris_sync'@'%' IDENTIFIED BY '<password>';
    ```

2.  Предоставьте привилегии, необходимые для синхронизации:

    ```sql
    GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'doris_sync'@'%';
    ```

Описание необходимых привилегий:

| Привилегия | Назначение |
| --- | --- |
| `SELECT` | Чтение существующих данных на этапе полной загрузки |
| `REPLICATION SLAVE` | Получение Binlog в качестве реплики |
| `REPLICATION CLIENT` | Запрос состояния Binlog на основном сервере |

## Шаг 5: Настройка срока хранения Binlog {#step-5-configure-binlog-retention}

**Цель**: по умолчанию Amazon RDS MySQL удаляет двоичные журналы при первой возможности. Рекомендуется установить срок хранения Binlog не менее **72 часов**, чтобы файлы Binlog, используемые для репликации, оставались доступными при сбоях.

Используйте хранимую процедуру `mysql.rds_set_configuration`, чтобы задать срок хранения:

```sql
CALL mysql.rds_set_configuration('binlog retention hours', 72);
```

:::caution
Если этот параметр не задан или установлен слишком короткий срок хранения, в двоичном журнале могут возникнуть пропуски, из-за которых Doris не сможет возобновить репликацию.
:::

## Часто задаваемые вопросы (FAQ) {#frequently-asked-questions-faq}

**Вопрос 1: Обязательно ли перезапускать экземпляр после изменения `binlog_format`?**

Да. `binlog_format` является статическим параметром, и для вступления изменения в силу требуется перезапуск экземпляра RDS. Выполняйте эту операцию в часы низкой нагрузки.

**Вопрос 2: Почему для `binlog_row_image` необходимо установить значение `FULL`?**

Для потоковой загрузки в Doris необходимы полные данные строки до и после каждого изменения, чтобы корректно восстановить операции `UPDATE` и `DELETE`. Установка значения `MINIMAL` или `NOBLOB` приведёт к ошибкам синхронизации или неполным данным.

**Вопрос 3: Можно ли использовать одну группу параметров для нескольких экземпляров RDS?**

Да. Несколько экземпляров RDS одного семейства версий могут использовать общую группу параметров, если всем им требуется одинаковая конфигурация Binlog.

**Вопрос 4: Можно ли увеличить срок хранения Binlog?**

Да. `binlog retention hours` поддерживает значения от 1 до 168 часов (до 7 дней). Более длительное хранение даёт больше времени для восстановления, но требует больше места в хранилище.

## Устранение неполадок {#troubleshooting}

| Симптом | Возможная причина | Решение |
| --- | --- | --- |
| `SHOW VARIABLES LIKE 'log_bin'` возвращает `OFF` | Для экземпляра не включено автоматическое резервное копирование, поэтому Binlog не включён | Включите автоматическое резервное копирование для экземпляра в консоли RDS; после этого Binlog включится автоматически |
| После изменения `binlog_format` сохраняет значение `MIXED` или `STATEMENT` | Экземпляр не был перезапущен или к нему привязана неверная группа параметров | Убедитесь, что новая группа параметров привязана к экземпляру, затем перезапустите его |
| При синхронизации Doris сообщает об ошибке `binary log not found` | Binlog был удалён | Увеличьте `binlog retention hours` и перезапустите задачу синхронизации Doris |
| Пользователь синхронизации не может подключиться | Неверно настроен список разрешённых хостов или указан неправильный пароль | Проверьте, соответствует ли хост, указанный в `'doris_sync'@'%'`, исходящему IP-адресу узла Doris |
| Ошибки из-за недостаточных привилегий | Отсутствуют необходимые привилегии, например `REPLICATION SLAVE` | Повторно выполните инструкцию `GRANT` из шага 4 |
