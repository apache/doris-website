Синхронизация изменений схемы PostgreSQL автоматически применяет изменения столбцов в исходной базе данных PostgreSQL к Doris во время непрерывной загрузки. Эта возможность доступна только для [PostgreSQL CDC с автоматическим созданием таблиц](./continuous-load-postgresql-database.md). Она не поддерживается для [PostgreSQL CDC с SQL Mapping](./continuous-load-postgresql-table.md).

:::tip

Синхронизация изменений схемы PostgreSQL поддерживается начиная с Doris 4.1.0.

:::

## Поддерживаемые изменения схемы {#supported-schema-changes}

| Операция PostgreSQL | Поведение Doris |
| --- | --- |
| `ADD COLUMN` | Добавляет столбец с тем же именем и типом, определяемым [сопоставлением типов данных PostgreSQL](./data-type-mapping-postgresql.md). Ограничения DEFAULT и `NOT NULL` не копируются, а существующие строки не заполняются значениями нового столбца. Для последующих строк используются фактические значения, которые PostgreSQL записывает в WAL. |
| `DROP COLUMN` | Удаляет столбец с тем же именем. |

## Особенности использования {#considerations}

- Изменение схемы PostgreSQL не передаётся сразу после выполнения только DDL. Doris обнаруживает и применяет новую схему после следующей операции INSERT, UPDATE или DELETE в изменённой таблице.
- Автоматическая синхронизация изменений схемы не поддерживается на этапе полного снимка. Изменяйте схему в источнике после завершения полного снимка и перехода задания на инкрементальный этап.
- Если добавляемый столбец уже существует или удаляемый столбец отсутствует, Doris пропускает операцию, чтобы повторная попытка не приводила к сбою задания.
- Если в рамках одного изменения схемы столбцы одновременно добавляются и удаляются, Doris рассматривает это как возможное переименование столбца и не изменяет целевую таблицу автоматически. Это предотвращает случайную потерю данных.
- Переименование столбцов, изменение их типов, изменения DEFAULT и ограничений `NULL` / `NOT NULL` не синхронизируются автоматически. Приостановите задание непрерывной загрузки, вручную измените целевую таблицу Doris, убедитесь в совместимости обеих схем и затем возобновите задание.
- При синхронизации с автоматическим созданием таблиц синхронизация изменений схемы включена по умолчанию. В настоящее время Doris не предоставляет свойства SQL для её отключения. Табличная функция `cdc_stream()` (синхронизация с SQL Mapping) отключает синхронизацию изменений схемы во внутренней логике.

:::caution Изменение поведения (4.1.4)

Начиная с версии 4.1.4 обнаружение изменений схемы PostgreSQL основано на событиях Relation:

- Распознаются только `ADD COLUMN` и `DROP COLUMN`.
- Изменение, при котором столбцы одновременно добавляются и удаляются (возможно, `RENAME`), пропускается, а целевая таблица остаётся без изменений.
- Изменения типов столбцов пропускаются.
- Добавленный столбец **больше не получает значение `DEFAULT` исходного столбца**.
- Эта возможность доступна только в режиме синхронизации с автоматическим созданием таблиц (at-least-once). Режим SQL Mapping (TVF / exactly-once) её не поддерживает.

:::
