<!-- Knowledge type: Procedure -->
<!-- Applicable scenario: Pre-deployment check / Environment preparation -->

Потоковая загрузка в Doris поддерживает синхронизацию данных из **Amazon Aurora PostgreSQL-Compatible Edition 14 или более поздних версий**. Перед синхронизацией необходимо включить логическую репликацию на стороне кластера Aurora и предоставить необходимые права. Этот документ предназначен для администраторов баз данных и инженеров данных и содержит все шаги предварительной настройки.

### Контрольный список предварительных требований {#prerequisite-checklist}

Перед началом настройки проверьте следующее:

| Что проверить | Требование |
| --- | --- |
| Версия Aurora PostgreSQL | 14 или более поздняя |
| Права на выполнение операций | Права на изменение групп параметров кластера в консоли AWS RDS |
| Права в базе данных | Права на создание пользователей, предоставление привилегий и создание Publication |
| Окно обслуживания | Допускается перезапуск экземпляра Aurora для записи (перезапуск необходим после изменения параметров логической репликации) |

### Порядок настройки {#configuration-workflow}

Полный процесс настройки состоит из 5 шагов:

1. Проверить текущее состояние настройки логической репликации
2. Настроить группу параметров кластера
3. Применить группу параметров кластера и перезапустить экземпляр
4. Создать пользователя синхронизации Doris и предоставить ему права
5. Настроить Publication в зависимости от версии Doris

Если на шаге 1 выяснится, что логическая репликация уже включена, можно сразу перейти к **шагу 4**, чтобы создать пользователя синхронизации.

## Шаг 1: проверка текущей конфигурации {#step-1-check-the-current-configuration}

<!-- Knowledge type: Procedure -->

**Цель:** определить, включена ли логическая репликация в кластере Aurora и нужно ли изменять группу параметров.

Подключитесь к экземпляру Aurora для записи и выполните следующий SQL:

```sql
SHOW rds.logical_replication;
```

Выберите следующее действие в зависимости от возвращённого значения:

| Возвращённое значение | Значение | Следующее действие |
| --- | --- | --- |
| `on` | Логическая репликация включена | Перейдите к [шагу 4: создание пользователя синхронизации](#step-4-create-the-sync-user) |
| `off` | Логическая репликация не включена | Перейдите к [шагу 2: настройка группы параметров кластера](#step-2-configure-the-cluster-parameter-group) |

## Шаг 2: настройка группы параметров кластера {#step-2-configure-the-cluster-parameter-group}

<!-- Knowledge type: Configuration parameters -->

**Цель:** создать группу параметров кластера БД с включённой логической репликацией для использования в кластере Aurora.

Порядок действий:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. В левой панели навигации выберите **Группы параметров** и нажмите **Создать группу параметров**.
3. Выберите тип **Группа параметров кластера БД** и семейство, соответствующее версии Aurora PostgreSQL.
4. Откройте созданную группу параметров кластера для редактирования, найдите `rds.logical_replication` и установите значение `1`:

    ![Настройка WAL в PostgreSQL](/images/next/data-operate/streaming-job/pgwalsetting.png)

5. Нажмите **Сохранить изменения**.

Описание основного параметра:

| Параметр | Рекомендуемое значение | Описание |
| --- | --- | --- |
| `rds.logical_replication` | `1` | Включает логическую репликацию; `0` означает, что она отключена |

## Шаг 3: применение группы параметров кластера и перезапуск {#step-3-apply-the-cluster-parameter-group-and-restart}

<!-- Knowledge type: Procedure -->

**Цель:** привязать созданную группу параметров к целевому кластеру Aurora и перезапустить экземпляр для записи, чтобы настройки вступили в силу.

Порядок действий:

1. В консоли RDS выберите целевой кластер Aurora и нажмите **Изменить**.
2. В поле **Группа параметров кластера БД** выберите группу параметров кластера, созданную на шаге 2.
3. Выберите **Применить немедленно**.
4. Перезапустите экземпляр Aurora для записи, чтобы настройки вступили в силу.

:::caution
Чтобы изменение параметра `rds.logical_replication` вступило в силу, необходимо перезапустить экземпляр Aurora для записи. Выполняйте эту операцию в период низкой нагрузки.
:::

## Шаг 4: создание пользователя синхронизации {#step-4-create-the-sync-user}

<!-- Knowledge type: Procedure -->

**Цель:** создать отдельную учётную запись для потоковой загрузки в Doris и предоставить минимальные права, необходимые для чтения данных и выполнения репликации.

1. Создайте отдельного пользователя:

    ```sql
    CREATE USER doris_sync PASSWORD '<password>';
    ```

2. Предоставьте права на чтение схемы и таблиц (в примере используется схема `public`; при необходимости замените её):

    ```sql
    GRANT USAGE ON SCHEMA "public" TO doris_sync;
    GRANT SELECT ON ALL TABLES IN SCHEMA "public" TO doris_sync;
    ALTER DEFAULT PRIVILEGES IN SCHEMA "public" GRANT SELECT ON TABLES TO doris_sync;
    ```

3. Предоставьте право на репликацию:

    ```sql
    GRANT rds_replication TO doris_sync;
    ```

Описание прав:

| Право | Назначение |
| --- | --- |
| `USAGE ON SCHEMA` | Разрешает доступ к указанной схеме |
| `SELECT ON ALL TABLES` | Разрешает чтение данных из всех существующих таблиц в схеме |
| `ALTER DEFAULT PRIVILEGES ... GRANT SELECT` | Автоматически предоставляет права на чтение таблиц, создаваемых в этой схеме в дальнейшем |
| `rds_replication` | Роль, необходимая для выполнения логической репликации в Aurora PostgreSQL |

## Шаг 5: настройка Publication {#step-5-configure-the-publication}

<!-- Knowledge type: Procedure -->

### Doris 4.0 {#doris-40}

Необходимо заранее создать Publication с именем `dbz_publication`, используя `FOR ALL TABLES`:

```sql
CREATE PUBLICATION dbz_publication FOR ALL TABLES;
```

Если у пользователя синхронизации есть права суперпользователя, например роль `rds_superuser`, Doris может автоматически создать `dbz_publication` при запуске задания, и выполнять эту инструкцию вручную не требуется. Doris 4.0 не поддерживает пользовательские имена Publication и объекты Publication, содержащие только часть таблиц.

### Doris 4.1.0 и более поздние версии {#doris-410-and-later}

По умолчанию создавать Publication вручную не требуется. Если `publication_name` не задан, Doris использует учётную запись синхронизации для создания Publication с именем `doris_pub_<job_id>` и удаляет этот объект при удалении задания. Поэтому учётной записи синхронизации необходимы права на создание Publication.

Если при создании Streaming Job явно задан параметр `publication_name`, заранее создайте Publication с таким же именем. Пользовательский объект Publication должен включать все исходные таблицы, синхронизируемые заданием; поддерживать и удалять его должен пользователь. Например:

```sql
CREATE PUBLICATION doris_pub_custom
FOR TABLE public.orders, public.customers;
```

При создании задания задайте `"publication_name" = "doris_pub_custom"`. Имя может содержать только строчные латинские буквы, цифры и символы подчёркивания, не может начинаться с цифры и ограничено 63 символами.

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: `SHOW rds.logical_replication;` возвращает `on`. Что ещё нужно сделать?**

Изменять группу параметров кластера и перезапускать экземпляр не требуется. Начните сразу с [шага 4: создание пользователя синхронизации](#step-4-create-the-sync-user).

**Вопрос 2: поддерживается ли Aurora PostgreSQL 13 или более ранних версий?**

Нет. Для потоковой загрузки в Doris требуется Aurora PostgreSQL 14 или более поздней версии.

**Вопрос 3: можно ли использовать Publication с пользовательским именем?**

Doris 4.0 не поддерживает пользовательские имена и поддерживает только `dbz_publication FOR ALL TABLES`. Начиная с версии 4.1.0 можно указать пользовательское имя через `publication_name`, но необходимо создать Publication до создания задания и убедиться, что этот объект включает все синхронизируемые таблицы.

**Вопрос 4: обязательно ли использовать учётную запись суперпользователя для синхронизации?**

Нет. В Doris 4.0 при использовании обычного пользователя синхронизации необходимо вручную создать `dbz_publication`, а если у пользователя есть права суперпользователя, Doris может создать этот объект автоматически. Начиная с версии 4.1.0, если `publication_name` не указан, Doris автоматически создаёт Publication по умолчанию и управляет им. Заранее создавать Publication нужно только при использовании пользовательского объекта Publication.

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->
<!-- Applicable scenario: Pre-sync prerequisite check failure -->

| Проблема | Возможная причина | Решение |
| --- | --- | --- |
| `SHOW rds.logical_replication;` по-прежнему возвращает `off` | Новая группа параметров не привязана к кластеру или экземпляр для записи не был перезапущен | Убедитесь, что в поле **Группа параметров кластера БД** выбрана новая группа параметров, и перезапустите экземпляр для записи |
| Не удаётся создать пользователя или предоставить права | У текущей учётной записи недостаточно прав | Войдите с учётной записью, имеющей права `rds_superuser` или эквивалентные, и выполните операцию |
| `GRANT rds_replication` возвращает ошибку | Версия Aurora слишком старая или кластер не использует Aurora PostgreSQL | Обновите Aurora PostgreSQL до версии 14 или более поздней |
| Doris 4.0 сообщает, что `dbz_publication` не существует | `dbz_publication` не создан, а у учётной записи синхронизации нет прав суперпользователя | Выполните `CREATE PUBLICATION dbz_publication FOR ALL TABLES;` или используйте учётную запись с необходимыми правами |
| Doris 4.1.0 или более поздней версии не удаётся создать Publication по умолчанию | У учётной записи синхронизации нет прав на создание Publication | Предоставьте учётной записи синхронизации необходимые права или попросите администратора заранее создать пользовательский объект Publication и настройте `publication_name` |
| Doris 4.1.0 или более поздней версии сообщает, что пользовательский объект Publication не существует | Параметр `publication_name` настроен, но Publication с таким же именем не создан | Создайте Publication, как описано в [шаге 5](#step-5-configure-the-publication), или удалите настройку `publication_name` |
