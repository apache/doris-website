Разовая загрузка использует `ONE_TIME` для пакетной загрузки подходящих файлов S3 в существующую таблицу Doris. После фиксации последнего пакета задание переходит в состояние `FINISHED`. Этот режим подходит для первоначальной загрузки исторических данных, разовой офлайн-загрузки или дозагрузки данных, размещённых под отдельным префиксом.

Подготовьте все файлы до создания задания и не меняйте содержимое исходного пути во время загрузки. Завершённое задание не ожидает новых файлов. Для непрерывной загрузки выберите [упорядоченную загрузку](./continuous-load-s3-ordered.md) или [загрузку по уведомлениям](./continuous-load-s3-notification.md).

## Быстрый старт {#quick-start}

### Шаг 1: Подготовьте целевую таблицу и файлы {#step-1-prepare-the-target-table-and-files}

Учётной записи, от имени которой выполняется задание, требуется право `LOAD` на целевую таблицу и соответствующие права на создание базы данных и таблицы. Учётные данные S3 должны предоставлять разрешения `s3:ListBucket` и `s3:GetObject`. Узлы Doris должны иметь доступ к endpoint S3.

```sql
CREATE DATABASE IF NOT EXISTS db1;
CREATE TABLE db1.tbl1 (
    id INT,
    name STRING
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ("replication_num" = "1");
```

В этом примере используется одна реплика для кластера с одним BE. Установите количество реплик в соответствии с конфигурацией вашего рабочего кластера. Загрузите следующие данные в `s3://bucket/001.csv` и замените в SQL имя бакета, endpoint, регион и учётные данные своими значениями:

```text
1,Alice
2,Bob
```

### Шаг 2: Создайте задание {#step-2-create-the-job}

```sql
CREATE JOB s3_one_time_job
PROPERTIES (
    "s3.ingestion_mode" = "ONE_TIME",
    "s3.max_batch_files" = "256",
    "s3.max_batch_bytes" = "10737418240"
)
ON STREAMING DO
INSERT INTO db1.tbl1
SELECT * FROM S3(
    "uri" = "s3://bucket/*.csv",
    "format" = "csv",
    "column_separator" = ",",
    "s3.region" = "<s3_region>",
    "s3.endpoint" = "<s3_endpoint>",
    "s3.access_key" = "<s3_access_key>",
    "s3.secret_key" = "<s3_secret_key>"
);
```

## Проверка завершения {#check-completion}

Получите статус задания с помощью запроса:

```sql
SELECT Name, ExecuteType, Status
FROM jobs("type" = "insert")
WHERE Name = 's3_one_time_job';
```

Ожидаемый результат:

```text
Name             ExecuteType  Status
s3_one_time_job  STREAMING    FINISHED
```

Выполните `SELECT * FROM db1.tbl1 ORDER BY id;`. Ожидаемый результат:

```text
id  name
1   Alice
2   Bob
```

## Ограничения и восстановление {#limitations-and-recovery}

`ONE_TIME` не создаёт снимок каталога при создании задания. Этот режим получает списки файлов пакетами и прекращает работу после фиксации последнего пакета. Файлы, добавленные до зафиксированной позиции курсора, не дозагружаются. Подготовьте все исходные файлы до создания задания и на время загрузки прекратите запись и перезапись объектов по этому пути. После перезапуска FE задание продолжает работу с сохранённого прогресса и переходит в состояние `FINISHED`, когда все данные обработаны.

## Параметры {#parameters}

Укажите следующие параметры в `PROPERTIES` задания. Параметры подключения к S3, учётные данные и настройки формата файлов задаются в `S3(...)`.

| Параметр | Тип | По умолчанию | Обязательный | Описание |
| --- | --- | --- | --- | --- |
| `s3.ingestion_mode` | Строка | `ORDERED_LIST` | Да | Установите значение `ONE_TIME`. Нельзя изменить после создания. |
| `s3.max_batch_files` | Положительное целое число | `256` | Нет | Порог количества файлов в пакете. |
| `s3.max_batch_bytes` | Целое число | `10737418240` | Нет | Порог объёма пакета в байтах, от `104857600` до `10737418240`. Суффиксы единиц измерения не допускаются. |
| `max_interval` | Положительное целое число | `10` | Нет | Интервал планирования при отсутствии данных, в секундах. |

Не задавайте `offset`, `s3.event.source` или `s3.sqs.queue_url`. Параметр `max_interval` не заставляет завершённое задание ожидать новых файлов. Настройки сеанса описаны в разделе [INSERT INTO SELECT](../insert-into-manual.md#import-configuration-parameters).

Режим загрузки и URI S3 нельзя изменить после создания задания. Чтобы изменить режим или путь, создайте другое задание.

## Устранение неполадок и рекомендации {#troubleshooting-and-best-practices}

- **Не удаётся создать задание:** убедитесь, что существует подходящий непустой файл, доступный для чтения, по которому S3 TVF может определить схему.
- **Задание не завершается:** проверьте `Status`, `ErrorMsg` и задачи, завершившиеся с ошибкой. Недоступные для чтения объекты и ошибки формата могут препятствовать фиксации пакета.
- **Новые файлы не читаются после завершения:** состояние `FINISHED` является конечным. Поместите следующий пакет файлов под отдельный префикс и создайте новое задание, чтобы избежать повторной загрузки старых данных.
- **Совместное использование с загрузкой по уведомлениям:** используйте непересекающиеся префиксы для исторических и поступающих данных либо обрабатывайте пересечения и дубликаты в своём приложении.

Приостановка, возобновление и просмотр задач описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md). Изменение задания описано в разделе [ALTER JOB](../../../../sql-manual/sql-statements/job/ALTER-JOB.md).
