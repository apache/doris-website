<!-- Knowledge type: Operation guide + Configuration parameter reference -->
<!-- Applicable scenario: Data import / Local file import / Streaming data write -->

Stream Load позволяет загружать локальные файлы и потоки данных в Doris по HTTP. Stream Load выполняет загрузку синхронно: после выполнения он возвращает результат, по которому можно определить, прошла ли загрузка успешно. Обычно Stream Load используют для файлов размером менее 10 GB. Файлы большего размера сначала следует разбить на части, а затем загрузить каждую часть с помощью Stream Load. Stream Load гарантирует атомарность пакета задач загрузки: либо все строки загружаются успешно, либо не загружается ни одна.

:::tip

Для загрузки вместо прямого использования `curl` с одним параллельным потоком рекомендуется специализированный инструмент Doris Streamloader. Этот клиент для загрузки данных в Doris поддерживает **параллельную загрузку в несколько потоков** и сокращает время загрузки больших объёмов данных. Инструкции и практические рекомендации приведены в [документации Doris Streamloader](../../../connection-integration/data-integration/doris-streamloader).

:::

## Сценарии использования {#use-cases}

Stream Load подходит для следующих типичных сценариев:

- Загрузка локальных или удалённых файлов CSV, JSON, Parquet и ORC в Doris.
- Непрерывная запись данных программами на Java, Go, Python и других языках через потоки HTTP.
- Случаи, когда требуется атомарность одной задачи загрузки: все строки загружаются успешно либо вся задача завершается неудачей.
- Загрузка отдельных файлов, размер которых обычно меньше 10 GB. Файлы большего размера следует разбить перед загрузкой или использовать Doris Streamloader.

При загрузке файлов CSV важно различать значения null и пустые строки:

- Значение null: обозначается как `\N`. Например, в записи `a,\N,b` значение среднего столбца равно null.
- Пустая строка: если между двумя разделителями нет символов, значение представляет собой пустую строку. Например, в записи `a,,b` между двумя запятыми нет символов, поэтому значение среднего столбца — пустая строка.

## Основные принципы {#basic-principles}

<!-- Knowledge type: Architecture principles -->

При использовании Stream Load запрос на выполнение задачи загрузки отправляется узлу FE по HTTP. Для распределения нагрузки FE циклически перенаправляет запрос на один из узлов BE. HTTP-запрос также можно отправить напрямую определённому узлу BE. В Stream Load Doris назначает один узел координатором — Coordinator. Он принимает данные и распределяет их между другими узлами.

На следующей схеме показан основной процесс работы Stream Load:

![Основные принципы Stream Load](/images/stream-load.png)

Загрузка выполняется следующим образом:

1. Клиент отправляет запрос на выполнение задачи загрузки Stream Load узлу FE.
2. FE выбирает узел BE в циклическом порядке, назначает его координатором для планирования задачи загрузки и возвращает клиенту HTTP-перенаправление.
3. Клиент подключается к узлу BE, назначенному координатором, и отправляет запрос на загрузку.
4. Узел BE, назначенный координатором, распределяет данные между соответствующими узлами BE. После завершения загрузки он возвращает результат клиенту.
5. Клиент также может напрямую назначить узел BE координатором, который распределит задачу загрузки.

## Быстрый старт {#quick-start}

<!-- Knowledge type: Operational steps -->

Задача Stream Load отправляется, а данные передаются по HTTP. Следующие примеры показывают, как отправить задачу загрузки Stream Load с помощью `curl`.

### Предварительные требования {#prerequisites}

Для Stream Load требуется право INSERT на целевую таблицу. Если у пользователя нет этого права, предоставьте его командой [GRANT](../../../sql-manual/sql-statements/account-management/GRANT-TO).

### Создание задачи загрузки {#create-an-import-job}

#### Загрузка данных CSV {#import-csv-data}

1. Подготовьте данные для загрузки

    Создайте файл CSV `streamload_example.csv` со следующим содержимым:

    ```sql
    1,Emily,25
    2,Benjamin,35
    3,Olivia,28
    4,Alexander,60
    5,Ava,17
    6,William,69
    7,Sophia,32
    8,James,64
    9,Emma,37
    10,Liam,64
    ```

2. Создайте целевую таблицу Doris

    Создайте в Doris таблицу для загрузки данных следующей инструкцией:

    ```sql
    CREATE TABLE testdb.test_streamload(
        user_id            BIGINT       NOT NULL COMMENT "user id",
        name               VARCHAR(20)           COMMENT "name",
        age                INT                   COMMENT "age"
    )
    DUPLICATE KEY(user_id)
    DISTRIBUTED BY HASH(user_id) BUCKETS 10;
    ```

3. Запустите задачу загрузки

    Задачу загрузки Stream Load можно отправить командой `curl`.

    ```shell
    curl --location-trusted -u <doris_user>:<doris_password> \
        -H "Expect:100-continue" \
        -H "column_separator:," \
        -H "columns:user_id,name,age" \
        -T streamload_example.csv \
        -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
    ```

    Stream Load выполняет загрузку синхронно и возвращает результат непосредственно пользователю.

    ```sql
    {
        "TxnId": 3,
        "Label": "123",
        "Comment": "",
        "TwoPhaseCommit": "false",
        "Status": "Success",
        "Message": "OK",
        "NumberTotalRows": 10,
        "NumberLoadedRows": 10,
        "NumberFilteredRows": 0,
        "NumberUnselectedRows": 0,
        "LoadBytes": 118,
        "LoadTimeMs": 173,
        "BeginTxnTimeMs": 1,
        "StreamLoadPutTimeMs": 70,
        "ReadDataTimeMs": 2,
        "WriteDataTimeMs": 48,
        "CommitAndPublishTimeMs": 52
    }
    ```

4. Просмотрите загруженные данные

    ```sql
    mysql> select count(*) from testdb.test_streamload;
    +----------+
    | count(*) |
    +----------+
    |       10 |
    +----------+
    ```

    ```sql
    {"userid":2,"username":"Benjamin","userage":35},
    {"userid":3,"username":"Olivia","userage":28},

    {"userid":6,"username":"William","userage":69},
    {"userid":7,"username":"Sophia","userage":32},
    {"userid":8,"username":"James","userage":64},
    {"userid":9,"username":"Emma","userage":37},
    {"userid":10,"username":"Liam","userage":64}
    ]
    ```

2. Создайте целевую таблицу Doris

    Создайте в Doris таблицу для загрузки данных следующей инструкцией:

    ```sql
    CREATE TABLE testdb.test_streamload(
        user_id            BIGINT       NOT NULL COMMENT "user id",
        name               VARCHAR(20)           COMMENT "name",
        age                INT                   COMMENT "age"
    )
    DUPLICATE KEY(user_id)
    DISTRIBUTED BY HASH(user_id) BUCKETS 10;
    ```

3. Запустите задачу загрузки

    Задачу загрузки Stream Load можно отправить командой `curl`.

    ```shell
    curl --location-trusted -u <doris_user>:<doris_password> \
        -H "label:124" \
        -H "Expect:100-continue" \
        -H "format:json" -H "strip_outer_array:true" \
        -H "jsonpaths:[\"$.userid\", \"$.username\", \"$.userage\"]" \
        -H "columns:user_id,name,age" \
        -T streamload_example.json \
        -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
    ```

    :::info Примечание

    Если файл JSON содержит по одному объекту JSON в каждой строке, а не массив JSON, добавьте заголовки `-H "strip_outer_array:false"` и `-H "read_json_by_line:true"`.
    Чтобы загрузить объект JSON из корневого узла файла JSON, задайте для `jsonpaths` значение `$.`, например: `-H "jsonpaths:[\"$.\"]"`.

    :::

    Stream Load выполняет загрузку синхронно и возвращает результат непосредственно пользователю.

### Просмотр задач загрузки {#view-import-jobs}

По умолчанию Stream Load синхронно возвращает результат клиенту, поэтому система не сохраняет историю задач Stream Load. Чтобы включить её запись, добавьте параметр `enable_stream_load_record=true` в `be.conf`. Подробнее см. в разделе [Конфигурация BE](../../../admin-manual/config/be-config).

После настройки завершённые задачи Stream Load можно просматривать командой `show stream load`.

### Отмена задачи загрузки {#cancel-an-import-job}

Пользователи не могут отменить Stream Load вручную. При превышении времени ожидания или ошибке загрузки система отменяет задачу Stream Load автоматически.

### Привязка Compute Group {#bind-a-compute-group}

Можно указать Compute Group, в которой выполняется Stream Load.

**Режим разделения хранения и вычислений**

В режиме разделения хранения и вычислений Compute Group можно указать следующими способами:

1. С помощью параметра HTTP-заголовка.

    ```text
    -H "cloud_cluster:cluster1"
    ```

    Начиная с Doris 4.0.0, также можно использовать параметр `compute_group`:

    ```text
    -H "compute_group:cluster1"
    ```

    Если заданы и `compute_group`, и `cloud_cluster`, приоритет имеет `compute_group`.

2. В свойствах пользователя, связанного со Stream Load. Если Compute Group указана и в свойствах пользователя, и в HTTP-заголовке, приоритет имеет значение из заголовка.

    ```text
    set property for user1 'default_compute_group'='cluster1';
    ```

3. Если Compute Group не указана ни в свойствах пользователя, ни в HTTP-заголовке, она выбирается из Compute Group, доступных пользователю, связанному со Stream Load. Если у пользователя нет доступа ни к одной Compute Group, загрузка завершается ошибкой.

:::info Примечание о версиях (4.0.8 / 4.1.4)

В Doris 4.0.8 и более поздних версиях серии 4.0, а также в Doris 4.1.4 и более поздних версиях серии 4.1 исправлено несоответствие между маршрутизацией Compute Group и планом выполнения Stream Load в режиме разделения вычислений и хранения:

- Заголовок `compute_group` имеет приоритет над `cloud_cluster`. Ранее FE распознавал только `cloud_cluster`.
- При построении плана выполнения используется Compute Group **узла BE, который фактически получил запрос**. Поэтому план больше не назначается Compute Group, отличной от той, где он выполняется.
- На этом этапе также проверяются доступ учётной записи загрузки к целевой Compute Group, существование этой группы и её состояние. Поэтому, если у учётной записи загрузки нет доступа к Compute Group, которая фактически обслуживает запрос, после обновления загрузка завершится ошибкой прав доступа. Учётной записи потребуется предоставить соответствующее право.

:::

:::info Примечание о версии (4.1.4)

Начиная с версии 4.1.4, конечные точки Stream Load на BE (`PUT /api/{db}/{table}/_stream_load`, `PUT /api/_http_stream` и `PUT /api/{db}/_stream_load_2pc`) больше не выполняют предварительную проверку глобального права `LOAD`. Авторизация единообразно выполняется на FE для базы данных и таблицы, в которые фактически записываются данные.

Поэтому учётная запись, имеющая только право `LOAD_PRIV` на уровне базы данных или таблицы, без глобального права `LOAD`, теперь может выполнять Stream Load, а также подтверждать и отменять транзакции 2PC.

:::

**Режим совместного размещения хранения и вычислений**

В режиме совместного размещения хранения и вычислений Compute Group можно указать только через свойства пользователя, связанного со Stream Load. Если Compute Group в свойствах пользователя не указана, выбирается группа с именем `default`.

```text
set property for user1 'resource_tags.location'='group_1';
```

## Справочник {#reference}

<!-- Knowledge type: Configuration parameter reference -->

### Команда загрузки {#import-command}

Синтаксис загрузки Stream Load:

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
  -H "Expect:100-continue" [-H ""...] \
  -T <file_path> \
  -XPUT http://fe_host:http_port/api/{db}/{table}/_stream_load
```

Stream Load поддерживает загрузку по HTTP как с передачей данных частями (chunked), так и без неё. При загрузке без передачи частями необходимо указать `Content-Length` с длиной загружаемого содержимого, чтобы обеспечить целостность данных.

### Параметры настройки загрузки {#import-configuration-parameters}

#### Конфигурация FE {#fe-configuration}

**1. stream_load_default_timeout_second**

| Параметр | Описание |
| -------------------------- | ----------------------------------- |
| Значение по умолчанию | 259200 (s) |
| Динамическая настройка | Да |
| Настройка только для FE Master | Да |

Описание: время ожидания Stream Load по умолчанию, в секундах. Если задача загрузки не завершается за время, заданное параметром `timeout`, система отменяет её, и она переходит в состояние CANCELLED. Если исходный файл не удаётся загрузить за указанное время, можно задать отдельное время ожидания в запросе Stream Load или изменить параметр FE `stream_load_default_timeout_second`, задающий глобальное время ожидания по умолчанию.

#### Конфигурация BE {#be-configuration}

**1. streaming_load_max_mb**

| Параметр | Описание |
| --------------------- | -------------- |
| Значение по умолчанию | 102400 (MB) |
| Динамическая настройка | Да |

Описание: максимальный размер тела запроса Stream Load. Значение по умолчанию в исходном коде — 102400 MB (100 GB); фактическое ограничение зависит от конфигурации BE в вашей среде. На загрузку JSON без `read_json_by_line=true` также распространяется ограничение `streaming_load_json_max_mb`.

Если размер запроса превышает действующее ограничение, разбейте данные на меньшие пакеты или попросите администратора изменить конфигурацию.

Для управляемых облачных сервисов используйте предоставленный сервисом механизм настройки или обратитесь к его администратору; прямой доступ к узлам BE не требуется.

**История изменений по версиям:**

- В серии 3.x значение `streaming_load_max_mb` по умолчанию увеличено с 10240 MB (10 GB) до 102400 MB (100 GB) начиная с Doris 3.0.2. В Doris 3.0.0 и 3.0.1 значение по умолчанию составляет 10 GB.
- В серии 2.1 такое же изменение вступило в силу в версии 2.1.7.
- В Doris 4.x и dev сохраняется значение по умолчанию 100 GB. Фактическое значение зависит от конфигурации вашей среды.

#### Параметры заголовка {#header-parameters}

Параметры загрузки можно передать через HTTP-заголовки. Их описание приведено ниже:

| Параметр | Описание |
| ------------------------------- | ------------------------------------------------------------ |
| label | Задаёт метку загрузки. Данные с одной и той же меткой нельзя загрузить более одного раза. Если метка не указана, Doris создаёт её автоматически. Указав метку, можно избежать повторной загрузки одних и тех же данных. По умолчанию Doris хранит метки задач загрузки три дня; срок хранения можно изменить параметром `label_keep_max_second`. Например, чтобы назначить этой загрузке метку `123`, используйте `-H "label:123"`. Использование меток предотвращает повторную загрузку тех же данных. Настоятельно рекомендуется использовать одну и ту же метку для одного пакета данных: тогда повторные запросы для этого пакета будут приняты только один раз, что обеспечивает семантику At-Most-Once. Когда задача загрузки с данной меткой находится в состоянии CANCELLED, метку можно использовать повторно. |
| column_separator | Задаёт разделитель столбцов в загружаемом файле. По умолчанию используется `\t`. Для невидимых символов используйте префикс `\x` и шестнадцатеричную запись разделителя. Разделителем также может служить сочетание нескольких символов. Например, разделитель файла Hive `\x01` задаётся командой `-H "column_separator:\x01"`. |
| line_delimiter | Задаёт разделитель строк в загружаемом файле. По умолчанию используется `\n`. Разделителем строк также может служить сочетание нескольких символов. Например, чтобы указать `\n` как разделитель строк, используйте `-H "line_delimiter:\n"`. |
| columns | Задаёт соответствие между столбцами загружаемого файла и таблицы. Если столбцы исходного файла точно соответствуют столбцам таблицы, указывать этот параметр не нужно. Если структура исходного файла отличается от схемы таблицы, параметр необходим для некоторых преобразований данных. Столбец может напрямую соответствовать полю загружаемого файла и указываться по имени либо быть производным столбцом с синтаксисом `column_name = expression`. Подробные примеры см. в разделе [Преобразование данных при загрузке](../../../data-operate/import/load-data-convert). |
| where | Позволяет отобрать часть данных. Используйте параметр для исключения ненужных данных. Например, чтобы загрузить только строки, в которых столбец k1 равен 20180601, укажите `-H "where: k1 = 20180601"`. |
| max_filter_ratio | Максимально допустимая доля отфильтрованных данных, например из-за неверного формата. По умолчанию ошибки не допускаются. Диапазон значений — от 0 до 1. Если доля ошибочных строк превышает это значение, загрузка завершается неудачей. Строки, отфильтрованные условием `where`, не считаются некорректными данными. Например, чтобы загрузить как можно больше корректных данных при допустимой доле ошибок 100%, укажите `-H "max_filter_ratio:1"`. |
| partitions | Задаёт разделы, участвующие в этой загрузке. Если известно, каким разделам соответствуют данные, рекомендуется указать этот параметр. Данные, не соответствующие указанным разделам, отфильтровываются. Например, для загрузки в разделы p1 и p2 укажите `-H "partitions: p1, p2"`. |
| timeout | Задаёт время ожидания загрузки в секундах. По умолчанию — 600 секунд. Допустимый диапазон — от 1 до 259200 секунд. Например, чтобы установить время ожидания 1200 s, укажите `-H "timeout:1200"`. |
| strict_mode | Определяет, включён ли строгий режим для этой загрузки. По умолчанию он выключен. Чтобы включить его, укажите `-H "strict_mode:true"`. |
| timezone | Задаёт часовой пояс для этой загрузки. По умолчанию используется текущий часовой пояс кластера. Параметр влияет на результаты всех функций, связанных с часовыми поясами, которые используются при загрузке. Например, чтобы задать часовой пояс Africa/Abidjan, укажите `-H "timezone:Africa/Abidjan"`. |
| exec_mem_limit | Ограничение памяти для загрузки. По умолчанию — 2 GB. Единица измерения — байты. |
| format | Задаёт формат загружаемых данных. По умолчанию — CSV. Сейчас поддерживаются CSV, JSON, arrow, csv_with_names (позволяет пропустить первую строку файла CSV), csv_with_names_and_types (позволяет пропустить первые две строки файла CSV), Parquet и ORC. Например, чтобы указать формат JSON, используйте `-H "format:json"`. |
| jsonpaths | Данные JSON можно загружать двумя способами. Простой режим используется, если `jsonpaths` не указан; в нём данные JSON должны быть объектами. Режим сопоставления используется для более сложных данных JSON, когда соответствующие значения нужно найти с помощью параметра `jsonpaths`. В простом режиме ключи JSON должны один к одному соответствовать именам столбцов таблицы. Например, для данных JSON `{"k1":1, "k2":2, "k3":"hello"}` ключи k1, k2 и k3 должны соответствовать столбцам таблицы. |
| strip_outer_array | Если для `strip_outer_array` установлено значение true, данные JSON начинаются с массива, элементы которого разворачиваются в строки. По умолчанию значение равно false. Если самый внешний уровень данных JSON представляет собой массив `[]`, задайте для `strip_outer_array` значение true. Например, при загрузке `[{"k1" : 1, "v1" : 2},{"k1" : 3, "v1" : 4}]` с таким значением в Doris будут созданы две строки. |
| json_root | `json_root` — допустимая строка `jsonpath`, задающая корневой узел документа JSON. Значение по умолчанию — "". |
| merge_type | Тип объединения данных. Поддерживаются три типа:<br/>- APPEND (по умолчанию): все данные этого пакета добавляются к существующим.<br/>- DELETE: удаляются все строки, ключи которых совпадают с ключами строк этого пакета.<br/>- MERGE: используется вместе с условием `delete`. Данные, соответствующие условию `delete`, обрабатываются по семантике DELETE, остальные — по семантике APPEND.<br/>Например, режим MERGE задаётся так: `-H "merge_type: MERGE" -H "delete: flag=1"`. |
| delete | Имеет значение только при MERGE; задаёт условие удаления данных. |
| function_column.sequence_col | Применяется только к модели UNIQUE KEYS. Для одинаковых ключевых столбцов обеспечивает замену значения столбца в порядке, определяемом столбцом `source_sequence`. `source_sequence` может быть столбцом источника данных или схемы таблицы. |
| fuzzy_parse | Булев параметр. При значении true для разбора JSON первая строка используется как схема. Это может повысить эффективность загрузки JSON, но порядок ключей во всех объектах JSON должен совпадать с порядком в первой строке. По умолчанию — false. Используется только для формата JSON. |
| num_as_string | Булев параметр. При значении true числовые типы при разборе данных JSON преобразуются в строки, что позволяет избежать потери точности при загрузке. |
| read_json_by_line | Булев параметр. При значении true позволяет читать по одному объекту JSON на строку. По умолчанию — false. |
| send_batch_parallelism | Целочисленный параметр. Задаёт степень параллелизма при отправке пакетов данных. Если она превышает параметр BE `max_send_batch_parallelism_per_job`, узел BE, выступающий координатором, использует значение `max_send_batch_parallelism_per_job`. |
| hidden_columns | Задаёт скрытые столбцы, включённые в загружаемые данные. Действует, если в заголовке не указан `Columns`. Несколько скрытых столбцов разделяются запятыми. Система загружает данные согласно указанным пользователем параметрам. В примере ниже последний столбец загружаемых данных — `__DORIS_SEQUENCE_COL__`. `hidden_columns: __DORIS_DELETE_SIGN__,__DORIS_SEQUENCE_COL__` |
| load_to_single_tablet | Булев параметр. При значении true позволяет загружать данные одной задачи только в один таблет соответствующего раздела. По умолчанию — false. Параметр можно задать только при загрузке в таблицу OLAP со случайным распределением по бакетам. |
| compress_type | Задаёт формат сжатия файла. Сейчас поддерживается сжатие только файлов CSV. Поддерживаемые форматы: gz, lzo, bz2, lz4, lzop и deflate. |
| trim_double_quotes | Булев параметр. По умолчанию — false. При значении true удаляет внешние двойные кавычки каждого поля файла CSV. |
| skip_lines | Целочисленный параметр. По умолчанию — 0. Пропускает несколько первых строк файла CSV. Параметр не действует, если для `format` задано `csv_with_names` или `csv_with_names_and_types`. |
| comment | Строка. По умолчанию пустая. Добавляет к задаче дополнительную информацию. |
| enclose | Задаёт символ обрамления. Если поля CSV содержат разделители строк или столбцов, для предотвращения нежелательного разбиения можно указать однобайтовый символ обрамления. Например, при разделителе столбцов `,` и символе обрамления `'` в данных `"a,'b,c'"` значение `b,c` разбирается как одно поле. Примечание: если для `enclose` задано `"`, для `trim_double_quotes` необходимо задать true. |
| escape | Задаёт символ экранирования. Он нужен для экранирования символов внутри поля, совпадающих с символом обрамления. Например, чтобы при данных `"a,'b,'c'"` и символе обрамления `'` значение `b,'c` разбиралось как одно поле, задайте однобайтовый символ экранирования, например `\`, и измените данные на `"a,'b,\'c'"`. |
| memtable_on_sink_node | Определяет, включена ли передача MemTable вперёд при загрузке данных. По умолчанию — false. |
| unique_key_update_mode | Режим обновления таблицы Unique. Сейчас действует только для таблиц Merge-On-Write Unique. Поддерживаются три типа: `UPSERT`, `UPDATE_FIXED_COLUMNS` и `UPDATE_FLEXIBLE_COLUMNS`. `UPSERT` загружает данные с семантикой upsert. `UPDATE_FIXED_COLUMNS` загружает данные с [частичным обновлением столбцов](../../../data-operate/update/partial-column-update.md#column-update-on-the-unique-key-model). `UPDATE_FLEXIBLE_COLUMNS` загружает данные с [гибким частичным обновлением столбцов](../../../data-operate/update/partial-column-update.md#flexible-column-update). |
| partial_update_new_key_behavior | Определяет, как обрабатываются новые строки при частичном или гибком обновлении столбцов таблицы Unique. Доступны два типа: `APPEND` и `ERROR`.<br/>- `APPEND`: разрешает вставку новых строк.<br/>- `ERROR`: при вставке новой строки загрузка завершается ошибкой. |

```sql
    "Label": "b6f3bc78-0d2c-45d9-9e4c-faa0a0149bee",
    "Status": "Success",
    "ExistingJobStatus": "FINISHED", // optional
    "Message": "OK",
    "NumberTotalRows": 1000000,
    "NumberLoadedRows": 1000000,
    "NumberFilteredRows": 1,
    "NumberUnselectedRows": 0,
    "LoadBytes": 40888898,
    "LoadTimeMs": 2144,
    "BeginTxnTimeMs": 1,
    "StreamLoadPutTimeMs": 2,
    "ReadDataTimeMs": 325,
    "WriteDataTimeMs": 1933,
    "CommitAndPublishTimeMs": 106,
    "ErrorURL": "http://192.168.1.1:8042/api/_load_error_log?file=__shard_0/error_log_insert_stmt_db18266d4d9b4ee5-abb00ddd64bdf005_db18266d4d9b4ee5_abb00ddd64bdf005"
}
```

Поля ответа описаны в следующей таблице:

| Параметр | Описание |
| ---------------------- | ------------------------------------------------------------ |
| TxnId | Идентификатор транзакции загрузки. |
| Label | Метка задачи загрузки, заданная через `-H "label:<label_id>"`. |
| Status | Конечное состояние загрузки:<br/>- Success: загрузка прошла успешно.<br/>- Publish Timeout: загрузка завершена, но данные могут стать видимыми с задержкой; повторять загрузку не нужно.<br/>- Label Already Exists: метка уже существует; требуется новая метка.<br/>- Fail: загрузка завершилась ошибкой. |
| ExistingJobStatus | Состояние существующей задачи загрузки с этой меткой. Поле отображается, только если `Status` имеет значение `Label Already Exists`. По нему можно определить состояние задачи с существующей меткой: `RUNNING` означает, что она ещё выполняется, а `FINISHED` — что она успешно завершилась. |
| Message | Сообщение об ошибке загрузки. |
| NumberTotalRows | Общее число строк, обработанных при загрузке. |
| NumberLoadedRows | Число успешно загруженных строк. |
| NumberFilteredRows | Число строк, не прошедших проверку качества данных. |
| NumberUnselectedRows | Число строк, отфильтрованных условием `where`. |
| LoadBytes | Число загруженных байтов. |
| LoadTimeMs | Время завершения загрузки в миллисекундах. |
| BeginTxnTimeMs | Время, затраченное на запрос к FE для начала транзакции, в миллисекундах. |
| StreamLoadPutTimeMs | Время, затраченное на запрос к FE для получения плана выполнения загрузки данных, в миллисекундах. |
| ReadDataTimeMs | Время чтения данных в миллисекундах. |
| WriteDataTimeMs | Время записи данных в миллисекундах. |
| CommitAndPublishTimeMs | Время, затраченное на запрос к FE для подтверждения и публикации транзакции, в миллисекундах. |
| ErrorURL | Если обнаружены проблемы с качеством данных, по этому URL можно просмотреть конкретные строки с ошибками. |

С помощью `ErrorURL` можно просмотреть данные, не загруженные из-за проблем с качеством. Чтобы получить сведения об ошибочных данных напрямую, выполните `curl "<ErrorURL>"`.

### Настройка времени ожидания и максимального размера загрузки {#set-the-import-timeout-and-maximum-import-size}

Время ожидания задачи загрузки задаётся в секундах. Если задача не завершается за время, заданное параметром `timeout`, система отменяет её, и она переходит в состояние CANCELLED. Изменить время ожидания Stream Load можно параметром `timeout` или параметром `stream_load_default_timeout_second` в `fe.conf`.

Перед загрузкой рассчитайте время ожидания исходя из размера файла. Например, для файла размером 100 GB при предполагаемой скорости загрузки 50 MB/s:

```sql
Import time ~= 100GB / 50MB/s ~= 2048s
```

Следующая команда создаёт задачу загрузки Stream Load с `timeout`, равным 3000 s:

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "timeout:3000" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

### Настройка максимально допустимой доли ошибок {#set-the-maximum-tolerated-error-ratio}

Задачи загрузки Doris допускают некоторую долю некорректно сформированных данных. Допустимая доля задаётся параметром `max_filter_ratio`. По умолчанию он равен 0: даже одна некорректная строка приводит к ошибке всей задачи загрузки. Если нужно пропускать часть проблемных строк, задайте значение от 0 до 1, и Doris автоматически пропустит строки с неверным форматом данных. Подробнее о расчёте допустимой доли см. в документации [Преобразование данных](../../../data-operate/import/load-data-convert).

Следующая команда создаёт задачу загрузки Stream Load со значением `max_filter_ratio` 0.4:

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "max_filter_ratio:0.4" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

### Настройка условий фильтрации при загрузке {#set-import-filter-conditions}

Во время загрузки данные можно отбирать по условию с помощью параметра `WHERE`. Отфильтрованные таким образом данные не учитываются при расчёте доли ошибок и не влияют на настройку `max_filter_ratio`. После завершения загрузки число отфильтрованных строк можно узнать по значению `num_rows_unselected`.

Следующая команда создаёт задачу загрузки Stream Load с условием фильтрации `WHERE`:

```sql
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "where:age>=35" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

### Загрузка данных в указанные разделы {#import-data-into-specified-partitions}

Загрузите данные из локального файла в разделы p1 и p2 таблицы, допустив долю ошибок 20%.

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "label:123" \
    -H "Expect:100-continue" \
    -H "max_filter_ratio:0.2" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -H "partitions: p1, p2" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

### Указание часового пояса при загрузке {#specify-the-import-time-zone}

Типы без часового пояса, такие как `DATETIME` и `TIMESTAMP_NS`, не содержат сведений о часовом поясе, а хранимые значения не меняются при смене системного часового пояса Doris. Поэтому входные значения с часовым поясом при загрузке преобразуются к заданному целевому часовому поясу, после чего сохраняются без часового пояса. В Doris целевой часовой пояс представлен переменной сеанса `time_zone`.

При загрузке целевой часовой пояс задаётся параметром `timezone`. При преобразовании часовых поясов и вычислении функций, зависящих от часового пояса, этот параметр заменяет переменную сеанса `time_zone`. Поэтому, если нет особых причин выбрать другой пояс, значение `timezone` в транзакции загрузки должно совпадать с текущим значением `time_zone` кластера Doris. Тогда все временные данные с часовыми поясами преобразуются к этому поясу.

Например, если системный часовой пояс Doris — `+08:00`, а столбец времени в загружаемых данных содержит две строки, `2012-01-01 01:00:00+00:00` и `2015-12-12 12:12:12-08:00`, то указание `-H "timezone: +08:00"` преобразует обе строки к этому часовому поясу. Результатами будут `2012-01-01 09:00:00` и `2015-12-13 04:12:12`.

Подробнее см. документацию [Часовой пояс](../../../admin-manual/cluster-management/time-zone).

### Потоковая загрузка {#import-using-streaming}

Stream Load работает по протоколу HTTP, поэтому программы на Java, Go, Python и других языках могут записывать в него данные потоком. Отсюда и название Stream Load.

Следующий пример с конвейером команд `bash` показывает такой способ загрузки: данные создаёт программа, а не считывает из локального файла.

```shell
seq 1 10 | awk '{OFS="\t"}{print $1, $1 * 10}' | curl --location-trusted -u root -T - http://host:port/api/testDb/testTbl/_stream_load
```

### Пропуск первой строки CSV при загрузке {#skip-the-first-line-of-a-csv-during-import}

Данные файла:

```Plain
 id,name,age
 1,doris,20
 2,flink,10
```

Чтобы пропустить первую строку при загрузке, укажите `format=csv_with_names`:

```Plain
curl --location-trusted -u root -T test.csv  -H "label:1" -H "format:csv_with_names" -H "column_separator:," http://host:port/api/testDb/testTbl/_stream_load
```

### Операция Delete с помощью merge_type {#use-merge_type-to-perform-a-delete-operation}

В Stream Load есть три типа загрузки: APPEND, DELETE и MERGE. Тип выбирается параметром `merge_type`. Чтобы удалить все строки, ключи которых совпадают с ключами загружаемых данных, используйте следующую команду:

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "merge_type: DELETE" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

Допустим, до загрузки таблица содержит следующие данные:

```sql
+--------+----------+----------+------+
| siteid | citycode | username | pv   |
+--------+----------+----------+------+
|      3 |        2 | tom      |    2 |
|      4 |        3 | bush     |    3 |
|      5 |        3 | helen    |    3 |
+--------+----------+----------+------+
```

Загружаемые данные:

```sql
3,2,tom,0
```

После загрузки совпадающая строка удаляется из таблицы, и результат выглядит так:

```sql
+--------+----------+----------+------+
| siteid | citycode | username | pv   |
+--------+----------+----------+------+
|      4 |        3 | bush     |    3 |
|      5 |        3 | helen    |    3 |
+--------+----------+----------+------+
```

### Операция Merge с помощью merge_type {#use-merge_type-to-perform-a-merge-operation}

Если задать для `merge_type` значение MERGE, загружаемые данные объединяются с данными таблицы. Семантика MERGE требует условия `DELETE`: строки, соответствующие этому условию, обрабатываются по семантике DELETE, а остальные добавляются в таблицу по семантике APPEND. Например, следующая операция удаляет строку, у которой `siteid` равен 1, и добавляет остальные данные в таблицу:

```shell
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "merge_type: MERGE" \
    -H "delete: siteid=1" \
    -H "column_separator:," \
    -H "columns:user_id,name,age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

Допустим, до загрузки имеются следующие данные:

```sql
+--------+----------+----------+------+
| siteid | citycode | username | pv   |
+--------+----------+----------+------+
|      4 |        3 | bush     |    3 |
|      5 |        3 | helen    |    3 |
|      1 |        1 | jim      |    2 |
+--------+----------+----------+------+
```

Загружаемые данные:

```sql
2,1,grace,2
3,2,tom,2
1,1,jim,2
```

После загрузки строка с `siteid = 1` удаляется, а строки с `siteid` 2 и 3 добавляются в таблицу:

```sql
+--------+----------+----------+------+
| siteid | citycode | username | pv   |
+--------+----------+----------+------+
|      4 |        3 | bush     |    3 |
|      2 |        1 | grace    |    2 |
|      3 |        2 | tom      |    2 |
|      5 |        3 | helen    |    3 |
+--------+----------+----------+------+
```

### Указание столбца Sequence для Merge при загрузке {#specify-the-sequence-column-for-merge-during-import}

Если в таблице Unique Key задан столбец Sequence, для строк с одинаковыми ключевыми столбцами значение Sequence определяет порядок замены агрегатной функцией REPLACE: большее значение может заменить меньшее. При пометке таких строк для удаления на основе `DORIS_DELETE_SIGN` необходимо обеспечить совпадение ключа и значение Sequence не меньше текущего. Чтобы выполнить удаление, укажите параметр `function_column.sequence_col` вместе с `merge_type: DELETE`:

```sql
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "merge_type: DELETE" \
    -H "function_column.sequence_col: age" \
    -H "column_separator:," \
    -H "columns: name, gender, age" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

Допустим, структура таблицы следующая:

```sql
mysql> SET show_hidden_columns=true;
Query OK, 0 rows affected (0.00 sec)

mysql> DESC table1;
+------------------------+--------------+------+-------+---------+---------+
| Field                  | Type         | Null | Key   | Default | Extra   |
+------------------------+--------------+------+-------+---------+---------+
| name                   | VARCHAR(100) | No   | true  | NULL    |         |
| gender                 | VARCHAR(10)  | Yes  | false | NULL    | REPLACE |
| age                    | INT          | Yes  | false | NULL    | REPLACE |
| __DORIS_DELETE_SIGN__  | TINYINT      | No   | false | 0       | REPLACE |
| __DORIS_SEQUENCE_COL__ | INT          | Yes  | false | NULL    | REPLACE |
+------------------------+--------------+------+-------+---------+---------+
4 rows in set (0.00 sec)
```

Допустим, исходные данные таблицы:

```sql
+-------+--------+------+
| name  | gender | age  |
+-------+--------+------+
| li    | male   |   10 |
| wang  | male   |   14 |
| zhang | male   |   12 |
+-------+--------+------+
```

**1. Параметр Sequence действует: значение загружаемого столбца Sequence больше или равно существующему значению в таблице**

Загружаемые данные:

```sql
li,male,10
```

Поскольку задано `function_column.sequence_col: age`, а значение `age` больше или равно существующему значению столбца в таблице, исходная строка удаляется. После этого таблица содержит:

```sql
+-------+--------+------+
| name  | gender | age  |
+-------+--------+------+
| wang  | male   |   14 |
| zhang | male   |   12 |
+-------+--------+------+
```

**2. Параметр Sequence не действует: значение загружаемого столбца Sequence меньше или равно существующему значению в таблице**

Загружаемые данные:

```sql
li,male,9
```

Хотя задано `function_column.sequence_col: age`, значение `age` меньше существующего значения столбца в таблице, поэтому операция DELETE не действует. Данные таблицы остаются без изменений, а строка с первичным ключом `li` по-прежнему видна:

```sql
+-------+--------+------+
| name  | gender | age  |
+-------+--------+------+
| li    | male   |   10 |
| wang  | male   |   14 |
| zhang | male   |   12 |
+-------+--------+------+
```

Строка не удаляется, поскольку на нижнем уровне система сначала сопоставляет строки с одинаковым ключом и предоставляет извне строку с большим значением столбца Sequence. Затем она проверяет значение `DORIS_DELETE_SIGN` этой строки. При значении 1 строка скрывается, а при значении 0 остаётся доступной для чтения.

### Загрузка данных с символами обрамления {#import-data-containing-enclosing-characters}

Если данные CSV содержат разделители строк или столбцов, можно задать однобайтовый символ обрамления, чтобы избежать разбиения поля.

В следующих данных поле содержит разделитель `,`:

```sql
Zhang San,30,'Shanghai City, Huangpu District, Dagu Road'
```

Если указать символ обрамления `'`, значение «Shanghai City, Huangpu District, Dagu Road» будет считаться одним полем:

```sql
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "column_separator:," \
    -H "enclose:'" \
    -H "columns:username,age,address" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

Если символ обрамления встречается и внутри поля, например значение «Shanghai City, Huangpu District, 'Dagu Road» нужно считать одним полем, сначала экранируйте этот символ в данных:

```sql
Zhang San,30,'Shanghai City, Huangpu District, \'Dagu Road'
```

Параметр `escape` позволяет указать однобайтовый символ экранирования, например `\` в следующем примере:

```sql
curl --location-trusted -u <doris_user>:<doris_password> \
    -H "Expect:100-continue" \
    -H "column_separator:," \
    -H "enclose:'" \
    -H "escape:\\" \
    -H "columns:username,age,address" \
    -T streamload_example.csv \
    -XPUT http://<fe_ip>:<fe_http_port>/api/testdb/test_streamload/_stream_load
```

### Загрузка данных в таблицу с полями DEFAULT CURRENT_TIMESTAMP {#import-data-into-a-table-with-default-current_timestamp-fields}

Следующий пример показывает загрузку данных в таблицу с полями, для которых задано `DEFAULT CURRENT_TIMESTAMP`.

Схема таблицы:

```sql
CREATE TABLE testDb.testTbl (
    `id` BIGINT(30) NOT NULL,
    `order_code` VARCHAR(30) DEFAULT NULL COMMENT '',
    `create_time` DATETIMEv2(3) DEFAULT CURRENT_TIMESTAMP
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 10;
```

Формат данных JSON:

```Plain

```

Команда загрузки:

```shell
curl --location-trusted -u root -T test.json -H "label:1" -H "format:json" -H 'columns: id, order_code, create_time=CURRENT_TIMESTAMP()' http://host:port/api/testDb/testTbl/_stream_load
```

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: Troubleshooting -->

### Можно ли отменить Stream Load вручную? {#does-stream-load-support-manual-cancellation}

Нет. При превышении времени ожидания или ошибке загрузки система автоматически отменяет Stream Load; пользователи не могут вручную отменить выполняющуюся задачу.

### Есть ли ограничение на размер одного файла Stream Load? {#is-there-a-size-limit-for-a-single-stream-load-file}

Рекомендуется, чтобы размер одного загружаемого файла не превышал 10 GB. Файлы большего размера следует разбить перед загрузкой. Можно также увеличить ограничение на размер одной загрузки, изменив параметр BE `streaming_load_max_mb`, или повысить производительность за счёт параллельной загрузки с помощью [Doris Streamloader](../../../connection-integration/data-integration/doris-streamloader).

### Как просмотреть историю задач Stream Load? {#how-do-i-query-historical-stream-load-jobs}

По умолчанию система не сохраняет историю задач Stream Load. Установите `enable_stream_load_record=true` в `be.conf`, выполните перезапуск и просматривайте историю командой `show stream load from <db>`.

### Что делать при ошибке «Label Already Exists»? {#how-do-i-handle-the-label-already-exists-error}

Ошибка означает, что указанная метка уже использовалась. Состояние существующей задачи можно определить по полю `ExistingJobStatus` в ответе:

- `RUNNING`: задача ещё выполняется; дождитесь её завершения.
- `FINISHED`: задача успешно завершена; повторная загрузка не нужна.
- Если задача находится в состоянии CANCELLED, ту же метку можно использовать для новой загрузки.

Для одного и того же пакета данных рекомендуется всегда использовать одну метку: это обеспечивает семантику At-Most-Once и предотвращает повторную загрузку.

### Что делать, если загрузка завершилась ошибкой из-за формата данных? {#what-if-an-import-fails-because-of-data-format-errors}

Чтобы найти и устранить проблему:

1. Просмотрите конкретные строки с ошибками по полю `ErrorURL` в ответе: `curl "<ErrorURL>"`.
2. При необходимости увеличьте `max_filter_ratio` (диапазон от 0 до 1), чтобы допустить часть некорректных данных.
3. Проверьте, правильно ли в CSV используются значения null (`\N`) и пустые строки (без символов между двумя разделителями).
4. Проверьте, соответствуют ли содержимому файла настройки разделителей столбцов и строк, символа обрамления (`enclose`) и символа экранирования (`escape`).

### Что делать при превышении времени ожидания загрузки (CANCELLED)? {#how-do-i-handle-import-timeouts-cancelled}

Оцените подходящее время ожидания исходя из объёма данных:

```text
Import time ~= File size / Estimated import speed (for example, 50MB/s)
```

Время ожидания можно изменить двумя способами:

- Для одной загрузки: укажите параметр заголовка `-H "timeout:3000"`.
- Глобально: измените параметр FE `stream_load_default_timeout_second`.

### Как различать значения null и пустые строки в CSV? {#how-do-i-distinguish-null-values-from-empty-strings-in-csv}

| Тип | Представление | Пример | Значение среднего столбца |
| ------------- | ----------------------------------------- | -------- | ---------------------------- |
| Значение null | Используйте `\N` | `a,\N,b` | Средний столбец содержит null |
| Пустая строка | Между двумя разделителями нет символов | `a,,b` | Средний столбец содержит пустую строку |
