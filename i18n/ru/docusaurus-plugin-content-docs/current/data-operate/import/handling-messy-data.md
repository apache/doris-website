При импорте типы данных исходных и целевых столбцов могут различаться. Doris преобразует данные при импорте, но в процессе преобразования могут возникнуть проблемы, из-за которых часть данных не удастся корректно загрузить:

- Несоответствие типов полей (например, запись строки `"abc"` в столбец `TinyInt`)
- Слишком длинное поле (например, запись 11 символов в столбец `char(10)`)
- Несоответствие точности или числовое переполнение (например, запись `10` в столбец `Decimal(1,0)`)

Для обработки таких ситуаций Doris предоставляет два основных параметра управления импортом:

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `strict_mode` | Определяет, следует ли отфильтровывать строки, для которых не удалось преобразовать тип столбца | `false` |
| `max_filter_ratio` | Задаёт максимально допустимую долю некорректных данных от общего объёма | `0` |

> Сочетая эти параметры, можно выбрать подходящий баланс между строгим контролем качества данных и допустимостью небольшого количества некорректных данных.

## Строгий режим (strict_mode) {#strict-mode-strict_mode}

<!-- Knowledge type: Configuration parameter description -->

Основное назначение строгого режима (`strict_mode`) — отфильтровывать строки, для которых при импорте **не удалось преобразовать тип столбца**.

### Фильтрация при ошибках преобразования типа столбца {#filtering-strategy-for-column-type-conversion-failures}

Поведение системы зависит от настройки строгого режима:

- **Строгий режим выключен**: значения полей, которые не удалось преобразовать, заменяются на `NULL`. Строки с такими значениями импортируются вместе с корректными строками.
- **Строгий режим включён**: строки с ошибками преобразования отфильтровываются, и импортируются только корректные строки. Под «ошибкой преобразования» здесь понимается конкретный случай: исходное значение не равно `NULL`, но после преобразования типа столбца результат равен `NULL`. Значения `NULL`, полученные в результате вычисления функций, к таким ошибкам не относятся.
- **Обработка значений NULL**: и корректные, и некорректные строки могут содержать `NULL`. Если целевой столбец не допускает `NULL`, строки с такими значениями отфильтровываются.

Следующие три примера показывают различия в поведении при включённом и выключенном строгом режиме.

#### Пример 1: столбец типа TinyInt {#example-1-column-type-tinyint}

| Тип исходных данных | Пример исходного значения | Значение после преобразования в TinyInt | Строгий режим | Результат |
| ------------ | ---------------- | --------------------- | ------------ | ---------------- |
| Значение NULL | `\N` | `NULL` | Включён или выключен | `NULL` |
| Значение не NULL | `"abc"` или `2000` | `NULL` | Включён | Недопустимое значение (отфильтровано) |
| Значение не NULL | `"abc"` или `2000` | `NULL` | Выключен | `NULL` |
| Значение не NULL | `1` | `1` | Включён или выключен | Успешно импортировано |

:::tip
1. Столбцы в таблице допускают импорт значений NULL.
2. После преобразования в `TinyInt` значения `abc` и `2000` становятся `NULL` из-за несоответствия типа или точности. При включённом строгом режиме такие строки отфильтровываются; при выключенном импортируется `NULL`.
:::

#### Пример 2: столбец типа Decimal(1,0) {#example-2-column-type-decimal10}

| Тип исходных данных | Пример исходного значения | Значение после преобразования в Decimal | Строгий режим | Результат |
| ------------ | ------------ | --------------------- | ------------ | ---------------- |
| Значение NULL | `\N` | `NULL` | Включён или выключен | `NULL` |
| Значение не NULL | `aaa` | `NULL` | Включён | Недопустимое значение (отфильтровано) |
| Значение не NULL | `aaa` | `NULL` | Выключен | `NULL` |
| Значение не NULL | `10` | `NULL` (переполнение) | Включён | Отфильтровано |
| Значение не NULL | `10` | `NULL` (переполнение) | Выключен | `NULL` |

:::tip
1. Столбцы в таблице допускают импорт значений NULL.
2. После преобразования в `Decimal` значение `aaa` становится `NULL` из-за несоответствия типа. При включённом строгом режиме такая строка отфильтровывается; при выключенном импортируется `NULL`.
3. Значение `10` выходит за пределы диапазона `Decimal(1, 0)` и преобразуется в `NULL`. При включённом строгом режиме строка отфильтровывается; при выключенном импортируется `NULL`.
:::

#### Пример 3: столбец типа char(10) {#example-3-column-type-char10}

| Тип исходных данных | Пример исходного значения | Значение после преобразования в char(10) | Строгий режим | Результат |
| ------------ | -------------- | ---------------------- | -------- | ------------------- |
| Значение NULL | `\N` | `NULL` | Включён или выключен | `NULL` |
| Значение не NULL | `a1234567890` | `a1234567890` | Включён | Слишком длинное значение, отфильтровано |
| Значение не NULL | `a1234567890` | `a1234567890` | Выключен | `a123456789` (обрезано) |

:::tip
Столбцы в таблице допускают импорт значений NULL.
:::

### Включение строгого режима {#enabling-strict-mode}

По умолчанию `strict_mode` имеет значение `false`. Ниже показано, как включить строгий режим для разных способов импорта:

**Stream Load**

```shell
curl --location-trusted -u user:passwd \
    -H "strict_mode: true" \
    -T data.txt \
    http://host:port/api/example_db/test_table/_stream_load
```

**Broker Load**

```sql
LOAD LABEL example_db.label_1
(
    DATA INFILE("s3://bucket/data.txt")
    INTO TABLE test_table
)
WITH S3 (...)
PROPERTIES
(
    "strict_mode" = "true"
);
```

**Routine Load**

```sql
CREATE ROUTINE LOAD example_db.job1 ON test_table
PROPERTIES
(
    "strict_mode" = "true"
)
FROM KAFKA (...);
```

**MySQL Load**

```sql
LOAD DATA LOCAL INFILE 'data.txt'
INTO TABLE test_table
PROPERTIES
(
    "strict_mode" = "true"
);
```

**Insert Into**

```sql
SET enable_insert_strict = true;
INSERT INTO test_table ...;
```

## Максимальная доля отфильтрованных данных (max_filter_ratio) {#maximum-filter-ratio-max_filter_ratio}

<!-- Knowledge type: Configuration parameter description -->

Параметр `max_filter_ratio` задаёт максимально допустимую долю некорректных данных от общего объёма данных при импорте:

- Если фактическая доля отфильтрованных данных **ниже** заданного максимума, импорт продолжается, а некорректные данные игнорируются.
- Если фактическая доля отфильтрованных данных **превышает** заданный максимум, импорт завершается ошибкой.

### Как рассчитывается доля отфильтрованных данных {#how-the-filter-ratio-is-calculated}

При импорте строки делятся на три категории:

| Категория | Описание |
| --- | --- |
| **Отфильтрованные строки (Filtered Rows)** | Строки, исключённые из-за проблем с качеством данных. К ним относятся ошибки типов и точности, слишком длинные строки, несоответствие числа столбцов в файлах и другие ошибки формата данных, а также строки, для которых не найден соответствующий раздел. |
| **Неотобранные строки (Unselected Rows)** | Строки, исключённые условиями [предварительной фильтрации](./load-data-convert.md#pre-filtering) или [последующей фильтрации](./load-data-convert.md#post-filtering). |
| **Загруженные строки (Loaded Rows)** | Успешно импортированные строки. |

Доля отфильтрованных данных рассчитывается по формуле:

```Plain
#Filtered Rows / (#Filtered Rows + #Loaded Rows)
```

Иными словами, `Unselected Rows` в расчёте не участвуют.

### Настройка максимальной доли отфильтрованных данных {#setting-the-maximum-filter-ratio}

По умолчанию `max_filter_ratio` имеет значение `0`: некорректные данные не допускаются. Ниже приведены примеры для разных способов импорта:

**Stream Load**

```shell
curl --location-trusted -u user:passwd \
    -H "max_filter_ratio: 0.1" \
    -T data.txt \
    http://host:port/api/example_db/my_table/_stream_load
```

**Broker Load**

```sql
LOAD LABEL example_db.label_1
(
    DATA INFILE("s3://bucket/data.txt")
    INTO TABLE test_table
)
WITH S3 (...)
PROPERTIES
(
    "max_filter_ratio" = "0.1"
);
```

**Routine Load**

```sql
CREATE ROUTINE LOAD example_db.job1 ON test_table
PROPERTIES
(
    "max_filter_ratio" = "0.1"
)
FROM KAFKA (...);
```

**MySQL Load**

```sql
LOAD DATA LOCAL INFILE 'data.txt'
INTO TABLE test_table
PROPERTIES
(
    "max_filter_ratio" = "0.1"
);
```

**Insert Into**

```sql
CREATE TABLE insert_filter_ratio_example (id INT NOT NULL)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ("replication_num" = "1");

SET enable_insert_strict = false;
SET insert_max_filter_ratio = 0.5;
INSERT INTO insert_filter_ratio_example VALUES (1), (NULL);
SELECT * FROM insert_filter_ratio_example;
```

```text
+------+
| id   |
+------+
|    1 |
+------+
```

Поскольку столбец `id` не допускает NULL, вторая строка отфильтровывается. Доля отфильтрованных данных составляет `1 / (1 + 1) = 0.5` и не превышает порог, поэтому загрузка завершается успешно.

:::tip
Для инструкций INSERT INTO параметр `insert_max_filter_ratio` действует только при `enable_insert_strict = false`; его значение по умолчанию — `1.0`. Он применяется к VALUES и SELECT, включая данные из таблиц Doris, внешних таблиц и файловых TVF. Если фактическая доля отфильтрованных данных превышает порог, INSERT завершается ошибкой; равенство порогу допускается. Этот параметр не подавляет другие ошибки выполнения.
:::

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: Как использовать `strict_mode` и `max_filter_ratio` вместе?**

- Если требуется **строгий контроль качества данных**, включите `strict_mode = true` и задайте небольшое значение `max_filter_ratio` (например, `0`). Любая ошибка преобразования приведёт к сбою импорта.
- Если допустимо **небольшое количество некорректных данных**, выключите `strict_mode` (или оставьте значение по умолчанию) и задайте приемлемое значение `max_filter_ratio` (например, `0.1`). Некорректные данные будут отфильтрованы, не нарушая импорт в целом.

**Вопрос 2: Отфильтровывает ли строгий режим значения `NULL`, полученные при вычислении функций?**

Нет. Строгий режим применяется только к случаю, когда исходное значение не равно NULL, а после преобразования типа столбца результат равен NULL. Значения `NULL`, полученные при вычислении функций, к этому случаю не относятся.

**Вопрос 3: Учитываются ли в `max_filter_ratio` строки, исключённые условиями предварительной или последующей фильтрации?**

Нет. `Unselected Rows` не участвуют в расчёте. Доля рассчитывается только по `Filtered Rows` и `Loaded Rows`.

**Вопрос 4: Как связаны `enable_insert_strict` и `insert_max_filter_ratio` в Insert Into?**

`insert_max_filter_ratio` действует только при `enable_insert_strict = false`. Его значение по умолчанию — `1.0`, что позволяет отфильтровать все некорректные данные.

**Вопрос 5: Чем различается поведение строгого и нестрогого режимов, если значение для столбца `char(10)` слишком длинное?**

- Строгий режим включён: строка со слишком длинным значением отфильтровывается.
- Строгий режим выключен: значение обрезается, после чего строка импортируется (например, `a1234567890` обрезается до `a123456789`).
