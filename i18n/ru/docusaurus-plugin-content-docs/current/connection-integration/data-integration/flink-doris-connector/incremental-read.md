# Инкрементальное чтение с Doris Changelog {#incremental-reading-with-doris-changelog}

Flink Doris Connector позволяет непрерывно читать изменения на уровне строк из таблицы Doris с включённым changelog (`"changelog.enable" = "true"`). В режиме `initial` коннектор сначала читает текущий снимок таблицы, а затем переключается на инкрементальное чтение. Изменения, необходимые для этого перехода, должны оставаться в пределах окна хранения changelog исходной таблицы.

:::info Требования к версиям
Для этой функции требуются Flink Doris Connector 26.4.0 или более поздней версии и Doris 5.0.0 или более поздней версии. Функция changelog является экспериментальной в Doris 5.0.0, и её необходимо включить, задав `enable_feature_changelog = true` в конфигурации FE. О том, как включить её для таблицы, о поддерживаемых моделях таблиц и ограничениях см. в разделе [Changelog](../../../data-operate/incremental/changelog.md).
:::

## Пример {#example}

Сначала включите changelog при создании исходной таблицы Doris. Параметр `changelog.need_historical_value` необходим, если потребителю нужно предыдущее состояние (before-image) обновлённых строк:

```sql
CREATE DATABASE IF NOT EXISTS test;

CREATE TABLE test.student_changelog_source (
    id INT,
    name VARCHAR(50),
    age INT
)
UNIQUE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES (
    "replication_num" = "1",
    "changelog.enable" = "true",
    "changelog.need_historical_value" = "true",
    "changelog.ttl_seconds" = "86400"
);

INSERT INTO test.student_changelog_source VALUES (1, 'Alice', 18);
```

Затем включите Flink Checkpoint и создайте таблицу с источником Doris:

```sql
SET 'execution.checkpointing.interval' = '10s';

CREATE TABLE student_changelog (
    id INT,
    name STRING,
    age INT,
    PRIMARY KEY (id) NOT ENFORCED
) WITH (
    'connector' = 'doris',
    'fenodes' = '127.0.0.1:8030',
    'table.identifier' = 'test.student_changelog_source',
    'username' = 'root',
    'password' = '',
    'source.scan.mode' = 'initial'
);

SELECT * FROM student_changelog;
```

## Режимы запуска {#scan-mode}

После запуска задания изменения в `test.student_changelog_source` непрерывно выдаются в виде записей changelog Flink. Выберите режим запуска с помощью `source.scan.mode`:

| Режим | Поведение |
| ---- | -------- |
| `snapshot` | Читает текущий снимок и останавливается. Это режим по умолчанию. |
| `initial` | Читает текущий снимок и после завершения его чтения переключается на непрерывное чтение changelog Doris. |
| `latest` | Пропускает снимок и читает изменения, появившиеся после запуска задания. |
| `from-timestamp` | Пропускает снимок и читает изменения начиная со времени, указанного в `source.scan.timestamp` в формате `yyyy-MM-dd HH:mm:ss`, включительно. |

При восстановлении из Flink Checkpoint или Savepoint коннектор возобновляет чтение из сохранённого состояния. Изменение `source.scan.mode` или `source.scan.timestamp` не сбрасывает это состояние. Как восстановленное смещение, так и запуск в режиме `from-timestamp` подчиняются ограничению `changelog.ttl_seconds` исходной таблицы; поведение при истечении срока хранения описано ниже.

## Типы изменений {#increment-type}

По умолчанию коннектор выдаёт изменения с полным содержимым строк в режиме `detail`. Задайте для `source.changelog.increment-type` значение `min_delta`, чтобы получать минимальный набор изменений, или `append_only`, чтобы получать только события добавления.

Коннектор читает изменения через запросы Doris `@incr`. Если срок хранения изменений для запрошенной начальной позиции истёк согласно `changelog.ttl_seconds`, поведение зависит от типа изменений:

| Тип изменений | Поведение при истечении срока хранения для начальной позиции |
| ---- | ---- |
| `detail` (по умолчанию), `append_only` | Doris сдвигает фактическую начальную позицию к первому сохранившемуся TSO и пропускает изменения с истёкшим сроком хранения. Задание может продолжать работу без ошибки истечения срока хранения, но эти изменения будут отсутствовать в его выходных данных. |
| `min_delta` | Чтение завершается ошибкой `Changelog offset has expired according to changelog.ttl_seconds`, чтобы не возвращать неполные итоговые изменения. |

Эти правила действуют при обычном чтении, после начального снимка и при восстановлении из сохранённого состояния. Работающее задание или успешно созданный Checkpoint не гарантируют, что срок хранения каких-либо изменений не истёк. Параметр `source.changelog.visible-wait-timeout` не приводит к повторным попыткам при ошибках истечения срока хранения.

## Примечания {#notes}

- Инкрементальное чтение использует Arrow Flight SQL. Коннектор включает его по умолчанию и автоматически определяет его порт.
- Включите Flink Checkpoint.
- Параметр Doris `changelog.ttl_seconds` по умолчанию равен `86400` секундам (один день) и должен быть больше `0`. Истечение срока хранения не зависит от задания Flink или его Checkpoint. Увеличение TTL не позволяет восстановить физически удалённые записи.
- Задайте TTL с запасом, чтобы он покрывал время чтения начального снимка, накопившийся объём непрочитанных изменений, а также время, необходимое для восстановления после сбоя и устранения отставания. Отслеживайте возраст самых старых изменений, которые ещё нужны заданию, в том числе при восстановлении из более старого Checkpoint или Savepoint.
- Для автоматической физической очистки также включите `enable_feature_changelog = true` на BE и оставьте автоматическую компакцию включённой. Инкрементальные запросы отфильтровывают записи с истёкшим сроком хранения ещё до завершения физической очистки. См. [Хранение и очистка changelog](../../../data-operate/incremental/changelog.md#retention-and-cleanup).
- При инкрементальном чтении Doris ожидает завершения выполняющихся транзакций, затрагивающих исходную таблицу в пределах окна чтения. Если время ожидания истекает, чтение возвращает ошибку. Только при этой ошибке коннектор повторяет чтение того же окна в течение времени, заданного параметром `source.changelog.visible-wait-timeout` (по умолчанию: `5m`). Задайте `0s`, чтобы отключить повторные попытки коннектора; при других ошибках чтение сразу завершается сбоем.

### Восстановление после истечения срока хранения changelog {#changelog-expiration-recovery}

Если срок хранения необходимых изменений истёк, существующее смещение не позволяет выполнить полное инкрементальное восстановление. Если задание должно поддерживать согласованность данных в целевой системе с текущим состоянием исходной таблицы, запустите новую начальную загрузку с `source.scan.mode = 'initial'`, не восстанавливая Checkpoint или Savepoint с истёкшим сроком хранения изменений, и перестройте данные в целевой системе по новому снимку. При восстановлении старого состояния даже с установленным режимом `initial` чтение возобновится из сохранённого состояния вместо создания нового полного снимка.

Новый снимок восстанавливает текущее состояние таблицы; он не может воспроизвести исторические события с истёкшим сроком хранения. Запуск в режиме `latest` или с более поздней начальной позицией `from-timestamp` также пропускает недостающий интервал. Используйте эти режимы, только если пропуск этого интервала допустим или недостающие данные были восстановлены отдельно.

## Семантика доставки и дедупликация {#delivery}

Источник Doris обеспечивает доставку с семантикой at-least-once при инкрементальном чтении, пока все необходимые записи изменений сохраняются в Doris. После сбоя события изменений могут быть выданы повторно и повлиять на результаты запросов Flink. Дедупликация событий CDC во Flink по умолчанию отключена. Чтобы использовать её, задайте следующий параметр перед отправкой запроса:

```sql
SET 'table.exec.source.cdc-events-duplicate' = 'true';
```

Если этот параметр включён, в исходной таблице должен быть объявлен первичный ключ, как в примере выше. Flink использует дополнительный оператор с состоянием для нормализации changelog Flink. Подробнее см. в [справочнике по конфигурации Flink](https://nightlies.apache.org/flink/flink-docs-release-2.3/zh/docs/dev/table/config/#table-exec-source-cdc-events-duplicate).

Checkpoint сохраняют состояние чтения, а дедупликация CDC обрабатывает повторно выданные события. Ни то ни другое не предотвращает истечение срока хранения changelog Doris и не восстанавливает события, уже утраченные по этой причине.

## Публикация прогресса чтения в Doris (необязательно) {#offset-table}

Прогресс чтения хранится в состоянии Flink Checkpoint. Необязательная таблица смещений предназначена только для наблюдения за прогрессом, зафиксированным завершёнными Checkpoint. Коннектор не читает эту таблицу для автоматического возобновления чтения при запуске или перезапуске задания.

Чтобы запрашивать прогресс чтения в Doris, создайте следующую таблицу смещений:

```sql
CREATE DATABASE IF NOT EXISTS ops;

CREATE TABLE ops.flink_source_offsets (
    consumer_id VARCHAR(256) NOT NULL,
    offset_timestamp DATETIME NOT NULL,
    update_time DATETIMEV2(3) NOT NULL
)
UNIQUE KEY(consumer_id)
DISTRIBUTED BY HASH(consumer_id) BUCKETS 1
PROPERTIES (
    "replication_num" = "1"
);
```

```sql
'jdbc-url' = 'jdbc:mysql://127.0.0.1:9030',
'source.changelog.offset-table' = 'ops.flink_source_offsets',
'source.changelog.consumer-id' = 'student-sync'
```

`source.changelog.consumer-id` идентифицирует задание-потребитель в таблице смещений. Сохраняйте его значение при перезапуске того же задания, чтобы отслеживать его прогресс.

Если восстановление из Flink Checkpoint или Savepoint невозможно и все изменения, необходимые начиная с сохранённого `offset_timestamp`, ещё доступны, скопируйте это значение в `source.scan.timestamp` и задайте для `source.scan.mode` значение `from-timestamp`, чтобы вручную возобновить чтение с этого смещения. Если срок хранения истёк, следуйте указаниям в разделе [Восстановление после истечения срока хранения changelog](#changelog-expiration-recovery); копирование временной метки с истёкшим сроком хранения не восстанавливает недостающие изменения. Например, если следующая временная метка всё ещё находится в пределах окна хранения:

```sql
'source.scan.mode' = 'from-timestamp',
'source.scan.timestamp' = '2026-10-09 10:00:00'
```

## Параметры {#options}

Следующие параметры управляют инкрементальным чтением. Остальные параметры Source перечислены в разделе [Чтение данных из Doris](./read.md#options).

| Параметр                         | Значение по умолчанию | Обязательный | Описание                                                                                                                                                |
| --------------------------- | ------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| source.scan.mode            | snapshot      | Нет        | Режим запуска источника. Поддерживаемые значения: `snapshot`, `initial`, `latest` и `from-timestamp`.                                                           |
| source.scan.timestamp       | --            | Нет        | Начальное время включительно в формате `yyyy-MM-dd HH:mm:ss`. Требуется только для `from-timestamp`. Если срок хранения для начальной позиции истёк, применяется поведение, описанное в разделе [Типы изменений](#increment-type); этот параметр не позволяет восстановить изменения с истёкшим сроком хранения. |
| source.changelog.increment-type | detail    | Нет        | Тип изменений: `detail`, `min_delta` или `append_only`. Если срок хранения для начальной позиции истёк, `detail` / `append_only` пропускают изменения с истёкшим сроком хранения, а `min_delta` завершается ошибкой. |
| source.changelog.poll-interval | 10s        | Нет        | Интервал опроса новых изменений. Минимальное значение составляет 1 секунду.                                                                                        |
| source.changelog.visible-wait-timeout | 5m         | Нет        | Максимальное время, в течение которого коннектор повторяет чтение того же окна после того, как Doris возвращает ошибку истечения времени ожидания видимости транзакций. Задайте `0s`, чтобы отключить повторные попытки; отрицательные значения недопустимы. |
| source.changelog.offset-table  | --         | Нет        | Таблица Doris в формате `database.table`, используемая для публикации смещений, зафиксированных завершёнными Checkpoint, только для наблюдения, без автоматического восстановления. Настраивается вместе с `source.changelog.consumer-id` и `jdbc-url`. |
| source.changelog.consumer-id   | --         | Нет        | Постоянный идентификатор потребителя, записываемый в `source.changelog.offset-table`.                                                                                |
