[Doris Streamloader](https://github.com/apache/doris-streamloader) — специализированный клиентский инструмент для загрузки данных в базу данных Apache Doris. По сравнению с загрузкой через `curl` в один поток он позволяет загружать данные параллельно и значительно сокращает время загрузки больших объёмов данных.

## Основные возможности {#core-features}

| Возможность | Описание |
|---|---|
| Параллельная загрузка | Выполняет Stream Load с несколькими параллельными рабочими процессами. Степень параллелизма задаётся параметром `workers` |
| Загрузка нескольких файлов | Загружает несколько файлов и каталогов в рамках одной задачи. Поддерживает шаблоны с подстановочными символами и автоматически рекурсивно обходит все файлы в каталоге |
| Возобновление передачи | Если во время загрузки происходит частичный сбой, инструмент может продолжить передачу с места сбоя |
| Автоматические повторные попытки | После сбоя загрузки ручной повторный запуск не требуется. Инструмент автоматически повторяет попытку заданное по умолчанию число раз. Если загрузка всё равно не удаётся, он выводит команду для ручного повторного запуска |

## Сценарии использования {#use-cases}

- Пакетная загрузка больших объёмов данных (от ГБ до ТБ) в Doris
- Пакетная загрузка нескольких файлов и каталогов
- Сценарии, в которых важна скорость загрузки и требуется повысить пропускную способность за счёт параллелизма
- Надёжные процессы загрузки, которым нужны возобновление передачи и автоматическое восстановление после сбоев

## Использование {#usage}

### Общий вид команды {#basic-command-format}

```shell
doris-streamloader \
    --source_file={FILE_LIST} \
    --url={FE_OR_BE_SERVER_URL}:{PORT} \
    --header={STREAMLOAD_HEADER} \
    --db={TARGET_DATABASE} \
    --table={TARGET_TABLE}
```

### Обязательные параметры {#required-parameters}

| Параметр | Значение |
|---|---|
| `--source_file` | Список файлов данных для загрузки. Поддерживаются отдельный файл, каталог, подстановочные символы и список через запятую |
| `--url` | Адрес сервиса Doris FE или BE в формате `http://host:port` |
| `--header` | Параметры заголовка для Stream Load. Несколько параметров разделяются символом `?` |
| `--db` | Имя целевой базы данных |
| `--table` | Имя целевой таблицы |

### Форматы, поддерживаемые параметром `source_file` {#formats-supported-by-source_file}

Параметр `--source_file` поддерживает следующие пять форматов. Выберите подходящий для вашего сценария.

#### 1. Один файл {#1-a-single-file}

Например, чтобы загрузить один файл `file.csv`:

```shell
doris-streamloader --source_file="file.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 2. Один каталог {#2-a-single-directory}

Например, чтобы загрузить каталог `dir`:

```shell
doris-streamloader --source_file="dir" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 3. Имя файла с подстановочными символами (обязательно в кавычках) {#3-a-file-name-with-wildcards-must-be-quoted}

Например, чтобы загрузить `file0.csv`, `file1.csv` и `file2.csv`:

```shell
doris-streamloader --source_file="file*" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 4. Список имён файлов через запятую {#4-a-comma-separated-list-of-file-names}

Например, чтобы загрузить `file0.csv`, `file1.csv` и `file2.csv`:

```shell
doris-streamloader --source_file="file0.csv,file1.csv,file2.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 5. Список каталогов через запятую {#5-a-comma-separated-list-of-directories}

Например, чтобы загрузить `dir1`, `dir2` и `dir3`:

```shell
doris-streamloader --source_file="dir1,dir2,dir3" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

### Параметр заголовка {#header-parameter}

`--header` поддерживает все параметры Stream Load. Несколько параметров разделяются символом `?`.

Пример:

```shell
doris-streamloader --source_file="data.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

## Необязательные параметры {#optional-parameters}

Помимо перечисленных выше обязательных параметров, инструмент предоставляет необязательные параметры для более точного управления загрузкой. Ниже они сгруппированы по назначению.

### Аутентификация и передача данных {#authentication-and-transport}

| Параметр | Значение | Значение по умолчанию | Рекомендация |
|---|---|---|---|
| `--u` | Имя пользователя базы данных | `root` | —— |
| `--p` | Пароль пользователя базы данных | Пустая строка | —— |
| `--compress` | Сжимать ли данные при передаче по HTTP | `false` | Оставьте значение по умолчанию. Сжатие и распаковка увеличивают нагрузку на CPU как инструмента, так и Doris BE. Включайте сжатие только тогда, когда узким местом становится пропускная способность сети на машине с исходными данными |
| `--timeout` | Время ожидания ответа на HTTP-запросы к Doris, в секундах | `60*60*10` | Оставьте значение по умолчанию |

### Пакетная обработка и параллелизм {#batch-and-concurrency}

| Параметр | Значение | Значение по умолчанию | Рекомендация |
|---|---|---|---|
| `--batch` | Размер порции при чтении и отправке файлов, в строках | `4096` | Оставьте значение по умолчанию |
| `--batch_byte` | Размер порции при чтении и отправке файлов, в байтах | `943718400` (900 MB) | Оставьте значение по умолчанию |
| `--workers` | Степень параллелизма загрузки | `0` | При значении `0` инструмент работает в автоматическом режиме и рассчитывает степень параллелизма с учётом объёма загружаемых данных, пропускной способности диска и скорости загрузки через Stream Load. Значение также можно задать вручную. Для производительных кластеров его можно увеличить, но **рекомендуется не превышать 10**. Если потребление памяти при загрузке слишком велико (что видно по Memtracker или журналам Exceed), значение можно уменьшить |
| `--disk_throughput` | Пропускная способность диска, в MB/s | `800` | Обычно оставляйте значение по умолчанию. Оно участвует в автоматическом расчёте `--workers`. Чтобы инструмент подобрал подходящее число `workers`, можно указать фактическую пропускную способность диска |
| `--streamload_throughput` | Фактическая пропускная способность загрузки через Stream Load, в MB/s | `100` | Обычно оставляйте значение по умолчанию. Оно участвует в автоматическом расчёте `--workers` и получено в среде ежедневного тестирования производительности. Чтобы инструмент подобрал подходящее число `workers`, можно указать измеренную пропускную способность, рассчитанную по формуле `(LoadBytes*1000) / (LoadTimeMs*1024*1024)` |
| `--max_byte_per_task` | Верхний предел объёма данных на одну задачу загрузки. При его превышении данные выделяются в новую задачу | `107374182400` (100 GB) | Рекомендуется использовать большее значение, чтобы сократить число версий, создаваемых при загрузке. Однако если возникает ошибка `body exceed max size` и вы не хотите менять `streaming_load_max_mb` либо возникает ошибка `-238 TOO MANY SEGMENT`, значение можно временно уменьшить |

### Проверка данных и журналы {#data-validation-and-logs}

| Параметр | Значение | Значение по умолчанию | Рекомендация |
|---|---|---|---|
| `--check_utf8` | Проверять ли кодировку загружаемых данных: `false` пропускает проверку и загружает данные без изменений; `true` заменяет символы, не соответствующие UTF-8, на `�` | `true` | Оставьте значение по умолчанию |
| `--debug` | Выводить ли отладочные журналы | `false` | Оставьте значение по умолчанию |
| `--log_filename` | Место хранения журналов | `""` | По умолчанию журналы выводятся в консоль. Чтобы записывать их в файл, укажите путь, например `--log_filename="/var/log"` |

### Повторные попытки после сбоя {#failure-retry}

| Параметр | Значение | Значение по умолчанию | Рекомендация |
|---|---|---|---|
| `--auto_retry` | Список номеров рабочих процессов и задач для автоматического повторного запуска | Пустая строка | Используйте только при сбое загрузки. При обычной загрузке задавать параметр не нужно. В случае сбоя инструмент выводит конкретные значения: их достаточно скопировать и запустить. Например, `--auto_retry="1,1,2,1"` означает, что нужно повторить первую задачу первого рабочего процесса и первую задачу второго рабочего процесса |
| `--auto_retry_times` | Число автоматических повторных попыток | `3` | Оставьте значение по умолчанию. Чтобы отключить повторные попытки, задайте `0` |
| `--auto_retry_interval` | Интервал между автоматическими повторными попытками, в секундах | `60` | Оставьте значение по умолчанию. Если сбой вызван недоступностью Doris, задайте интервал с учётом фактического времени перезапуска |

## Результат {#result}

По завершении работы инструмент выводит итоговый результат независимо от того, прошла загрузка успешно или завершилась сбоем.

### Поля результата {#result-fields}

| Поле | Описание |
|---|---|
| `Status` | Состояние загрузки: `Success` означает успех, `Failed` — сбой |
| `TotalRows` | Общее число строк в файлах, предназначенных для загрузки |
| `FailLoadRows` | Число строк, которые предполагалось загрузить, но загрузить не удалось |
| `LoadedRows` | Число строк, фактически загруженных в Doris |
| `FilteredRows` | Число строк, отфильтрованных Doris при загрузке |
| `UnselectedRows` | Число строк, проигнорированных Doris при загрузке |
| `LoadBytes` | Число фактически загруженных байтов |
| `LoadTimeMs` | Фактическая продолжительность загрузки, в миллисекундах |
| `LoadFiles` | Список фактически загруженных файлов |

### Пример успешной загрузки {#success-example}

При успешной загрузке вывод выглядит так:

```Go
Load Result: {
        "Status": "Success",
        "TotalRows": 120,
        "FailLoadRows": 0,
        "LoadedRows": 120,
        "FilteredRows": 0,
        "UnselectedRows": 0,
        "LoadBytes": 40632,
        "LoadTimeMs": 971,
        "LoadFiles": [
                "basic.csv",
                "basic_data1.csv",
                "basic_data2.csv",
                "dir1/basic_data.csv",
                "dir1/basic_data.csv.1",
                "dir1/basic_data1.csv"
        ]
}
```

### Пример сбоя загрузки {#failure-example}

Если часть данных загрузить не удалось, инструмент сначала выводит команду для повторного запуска:

```Go
load has some error, and auto retry failed, you can retry by :
./doris-streamloader --source_file /mnt/disk1/laihui/doris/tools/tpch-tools/bin/tpch-data/lineitem.tbl.1  --url="http://127.0.0.1:8239" --header="column_separator:|?columns: l_orderkey, l_partkey, l_suppkey, l_linenumber, l_quantity, l_extendedprice, l_discount, l_tax, l_returnflag,l_linestatus, l_shipdate,l_commitdate,l_receiptdate,l_shipinstruct,l_shipmode,l_comment,temp" --db="db" --table="lineitem1" -u root -p "" --compress=false --timeout=36000 --workers=3 --batch=4096 --batch_byte=943718400 --max_byte_per_task=1073741824 --check_utf8=true --report_duration=1 --auto_retry="2,1;1,1;0,1" --auto_retry_times=0 --auto_retry_interval=60
```

Скопируйте и выполните эту команду, чтобы повторить загрузку вручную. Значение параметра `auto_retry` описано выше в разделе параметров. Затем инструмент выводит результат сбоя:

```Go
Load Result: {
      "Status": "Failed",
      "TotalRows": 1,
      "FailLoadRows": 1,
      "LoadedRows": 0,
      "FilteredRows": 0,
      "UnselectedRows": 0,
      "LoadBytes": 0,
      "LoadTimeMs": 104,
      "LoadFiles": [
              "/mnt/disk1/laihui/doris/tools/tpch-tools/bin/tpch-data/lineitem.tbl.1"
      ]
}
```

## Рекомендации по использованию {#best-practices}

### Рекомендуемые параметры {#recommended-parameters}

1. **Обязательные параметры**: необходимо настроить следующие параметры:

    ```text
    --source_file=FILE_LIST
    --url=FE_OR_BE_SERVER_URL_WITH_PORT
    --header=STREAMLOAD_HEADER
    --db=TARGET_DATABASE
    --table=TARGET_TABLE
    ```

    **Для загрузки нескольких файлов используйте параметр `source_file`.**

2. **`workers`**: значение по умолчанию — `0`, что включает автоматический режим (инструмент рассчитывает значение по объёму загружаемых данных, `disk_throughput` и `streamload_throughput`; обычно результатом будет 1, 2, 4 или 8). Значение также можно задать вручную: для производительных кластеров его можно увеличить, но **рекомендуется не превышать 10**. **Распространённое значение при ручной настройке — `8`**.

3. **`max_byte_per_task`**: большее значение сокращает число версий, создаваемых при загрузке. Однако если возникает ошибка `body exceed max size` и вы не хотите менять `streaming_load_max_mb` либо возникает ошибка `-238 TOO MANY SEGMENT`, это значение можно временно уменьшить. **Обычно подходит значение по умолчанию.**

4. **Два ключевых параметра, влияющих на число версий**:

    | Параметр | Влияние | Рекомендация |
    |---|---|---|
    | `workers` | Большее число рабочих процессов означает больше версий и более высокую степень параллелизма | Обычно используйте `8` |
    | `max_byte_per_task` | Чем больше значение, тем больше данных приходится на одну версию и тем меньше версий создаётся; слишком большое значение может вызвать ошибку `-238 TOO MANY SEGMENT` | Обычно используйте значение по умолчанию |

### Рекомендуемая команда {#recommended-command}

Для большинства сценариев достаточно задать обязательные параметры и установить `workers` в `8`:

```shell
./doris-streamloader \
    --source_file="demo.csv,demoFile*.csv,demoDir" \
    --url="http://127.0.0.1:8030" \
    --header="column_separator:," \
    --db="demo" \
    --table="test_load" \
    --u="root" \
    --workers=8
```

## Часто задаваемые вопросы {#faq}

### 1. Что делать, если во время загрузки произошёл сбой в некоторых подзадачах? {#1-what-should-i-do-if-some-subtasks-fail-during-import}

Инструмент автоматически повторяет попытки. Если они также завершаются сбоем, он выводит команду для ручного повторного запуска. Скопируйте и выполните её. Удалять таблицу и загружать данные заново не нужно.

### 2. Что делать, если объём одной загрузки превышает порог `streaming_load_max_mb`, заданный по умолчанию для BE? {#2-what-if-a-single-import-exceeds-the-be-default-streaming_load_max_mb-threshold}

Установленный в инструменте по умолчанию верхний предел для одной задачи составляет 100 GB. Он соответствует исходному значению `streaming_load_max_mb` — 102400 MB — в Doris 3.0.2 и более поздних версиях (начиная с 2.1.7 для серии 2.1). В Doris 3.0.0 и 3.0.1 предел BE по умолчанию составляет 10 GB, а в версиях 4.x и dev — 100 GB. Фактическая конфигурация BE может отличаться. Если задача превышает действующий предел, уменьшите `--max_byte_per_task`, чтобы разделить данные на меньшие порции, или попросите администратора изменить параметр `streaming_load_max_mb`, который поддерживает динамическое изменение. Перезапуск BE не требуется.

Пользователи с правом ADMIN_PRIV могут проверить действующую конфигурацию каждого BE через SQL. Если вы используете управляемый облачный сервис, воспользуйтесь предусмотренным в нём способом настройки или обратитесь к администратору; прямой доступ к узлу BE не требуется:

```sql
SHOW BACKEND CONFIG LIKE 'streaming_load_max_mb';
```

### 3. Что делать при ошибке `-238 TOO MANY SEGMENT`? {#3-what-should-i-do-when-the--238-too-many-segment-error-occurs}

Чтобы уменьшить вероятность этой ошибки, снизьте значение параметра `--max_byte_per_task`.
