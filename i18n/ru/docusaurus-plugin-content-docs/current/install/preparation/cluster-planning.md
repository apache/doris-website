## Планирование архитектуры {#architecture-planning}

<!-- Knowledge type: Architecture selection decision -->

Выберите архитектуру в зависимости от потребностей вашего бизнеса:

| Архитектура | Сценарий применения | Зависимость |
| ----------------- | ------------------- | ---------- |
| [Совместное размещение хранения и вычислений](../../features-architecture/system-architecture#coupled-architecture) | Нет потребности в максимально гибком масштабировании | Общее хранилище не требуется |
| [Раздельное размещение хранения и вычислений](../../features-architecture/system-architecture#decoupled-architecture) | Вычислительные ресурсы необходимо динамически масштабировать | Требуется общее хранилище |

## Планирование портов {#port-planning}

<!-- Knowledge type: Network configuration parameters -->

Экземпляры Doris обмениваются данными по сети. Администраторы могут изменять настройки портов в зависимости от среды:

| Экземпляр | Имя порта | Порт по умолчанию | Направление обмена данными | Описание |
| -------- | --------- | ------------ | ----------------------- | ----------- |
| BE | be_port | 9060 | FE → BE | Thrift Server, принимает запросы от FE |
| BE | webserver_port | 8040 | BE ↔ BE | HTTP Server |
| BE | heartbeat_service_port | 9050 | FE → BE | Служба проверки работоспособности (Thrift) |
| BE | brpc_port | 8060 | FE ↔ BE, BE ↔ BE | Обмен данными по BRPC |
| FE | http_port | 8030 | FE ↔ FE, Клиент ↔ FE | HTTP Server |
| FE | rpc_port | 9020 | BE → FE, FE ↔ FE | Thrift Server, порт должен быть одинаковым на всех узлах FE |
| FE | query_port | 9030 | Клиент ↔ FE | MySQL Server |
| FE | edit_log_port | 9010 | FE ↔ FE | Обмен данными по bdbje |

## Планирование количества узлов {#node-count-planning}

<!-- Knowledge type: Node capacity planning -->

### Количество узлов FE {#fe-node-count}

FE принимает пользовательские запросы, планирует запросы, управляет метаданными и узлами.

| Тип узла | Роль | Рекомендация для промышленной эксплуатации |
| --------- | ---- | ------------------------- |
| Follower | Участвует в выборах; принимает на себя функции Master при его отказе | ≥ 3 |
| Observer | Только синхронизирует метаданные; увеличивает возможности обслуживания запросов на чтение | Добавляйте по мере необходимости |

### Количество узлов BE {#be-node-count}

BE отвечает за хранение данных и вычисления. В промышленных средах для обеспечения надёжности используются 3 реплики.

| Рекомендация | Описание |
| -------------- | ----------- |
| ≥ 3 узлов BE | Обеспечивает надёжное хранение с 3 репликами (при совместном размещении хранения и вычислений. При раздельном размещении хранения и вычислений количество узлов BE может составлять 0 и более.) |
| Поддержка горизонтального масштабирования | Добавление узлов повышает производительность запросов и позволяет обрабатывать больше запросов одновременно |
