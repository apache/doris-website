Таблицы ClickHouse, Greenplum и lakehouse можно скопировать в Doris с помощью соответствующих Catalog. Прежде чем выбирать целевую модель, определите семантику снимков, обновлений и агрегации; в Doris нет полных аналогов движков хранения исходных систем, которые автоматически воспроизводили бы их поведение.

## Способы миграции и предварительные требования {#routes-and-prerequisites}

| Источник | Справочная документация по подключению и параметрам | Проверки перед миграцией |
| --- | --- | --- |
| ClickHouse | [ClickHouse JDBC Catalog](../lakehouse/catalogs/jdbc-clickhouse-catalog.md) | Драйверы, беззнаковые целые числа, сопоставления типов даты и времени и сложных типов |
| Greenplum | [PostgreSQL JDBC Catalog](../lakehouse/catalogs/jdbc-pg-catalog.md) | Совместимый драйвер, фактические метаданные и согласованность распределённого экспорта |
| Hive | [Hive Catalog](../lakehouse/catalogs/hive-catalog.mdx) | Metastore, файловое хранилище, аутентификация и партиции |
| Iceberg | [Iceberg Catalog](../lakehouse/catalogs/iceberg-catalog.mdx) | Сервис метаданных, права доступа к хранилищу и согласованный снимок |
| Hudi | [Hudi Catalog](../lakehouse/catalogs/hudi-catalog.md) | Тип таблицы, доступное для чтения представление, лежащие в основе файлы и ограничения запросов |

Каждый FE/BE должен иметь доступ к необходимым сервисам, драйверам и хранилищам. Настройте Catalog по соответствующей справочной документации и используйте учётную запись Doris с правами на чтение внешней таблицы, а также на создание целевой таблицы и загрузку в неё данных.

## ClickHouse {#clickhouse}

Используйте JDBC Catalog и явно указывайте столбцы в `INSERT INTO ... SELECT`. Сначала выполните `DESC`; рекомендуемые варианты структуры целевой таблицы не отражают фактические сопоставления типов JDBC. Например, Catalog не гарантирует прямого сопоставления с CHAR для типа ClickHouse `FixedString`; проверьте поддержку Map/Tuple и других сложных типов для используемого драйвера и версии Doris.

Для `ReplacingMergeTree`, `CollapsingMergeTree` и таблиц с состояниями агрегатных функций определите итоговый набор видимых строк, столбцы версий, маркеры удаления и правила слияния. Таблица Doris с моделью Unique Key не воспроизводит автоматически всю семантику движка исходной системы. Проверьте различия в SQL, связанные с NULL, совпадающими экстремальными значениями, разворачиванием массивов и извлечением строк из JSON.

## Greenplum {#greenplum}

Следуйте порядку пакетной миграции, описанному в разделе [Миграция из PostgreSQL](./postgresql-to-doris.md), проверяя фактические сопоставления типов Greenplum. Параллельные операции экспорта и пакеты SQL должны работать с одним и тем же согласованным представлением исходных данных; сама по себе параллельность не обеспечивает общий снимок для нескольких таблиц.

## Озеро данных {#data-lake}

Используйте соответствующие Catalog для Hive, Iceberg и Hudi. На время миграции зафиксируйте нужный снимок Iceberg. Для Hudi определите, какое представление читается и какие типы таблиц поддерживает развёрнутая версия. Создание Catalog лишь открывает доступ к внешним данным; копия данных в Doris при этом не создаётся.

## Основы использования {#basic-usage}

Предположим, что `source_catalog` настроен, как описано выше, а таблица `analytics.migration_demo` содержит столбцы `id BIGINT` и `value DECIMAL(12,2)` и используется фиксированный снимок источника. Проверьте эти типы с помощью `DESC`, затем выполните в Doris:

```sql
CREATE DATABASE IF NOT EXISTS migration_target;
CREATE TABLE migration_target.olap_demo (
    id BIGINT,
    `value` DECIMAL(12,2)
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ('replication_num' = '1');

INSERT INTO migration_target.olap_demo (id, `value`)
SELECT id, `value` FROM source_catalog.analytics.migration_demo;

SELECT COUNT(*), SUM(`value`) FROM source_catalog.analytics.migration_demo;
SELECT COUNT(*), SUM(`value`) FROM migration_target.olap_demo;
```

Ожидаемый результат: в пустую целевую таблицу загружаются оба выбранных столбца из снимка источника, а два проверочных запроса возвращают одинаковое количество строк и одинаковые суммы. Одна реплика и один бакет приведены для примера; выбирайте параметры производственных таблиц с учётом ресурсов и требований к надёжности. Полный пример с фиксированными входными данными приведён в разделах [MySQL](./mysql-to-doris.md) и [PostgreSQL](./postgresql-to-doris.md).

## Другие способы загрузки {#other-loading-methods}

Если прямое подключение недоступно, экспортируйте данные в файлы поддерживаемых форматов и используйте [S3 Load](../data-operate/import/data-source/amazon-s3.md) или [Broker Load](../data-operate/import/import-way/broker-load-manual.md). Прежде чем увеличивать объём импорта, определите форматы файлов, кодировку, представление NULL, точность и часовые пояса.

Также можно использовать [Spark Connector](../connection-integration/data-integration/spark-doris-connector.md) или [Flink Connector](../connection-integration/data-integration/flink-doris-connector/overview.md). Сведения о возможностях пакетной и потоковой обработки, совместимых версиях и семантике приведены в справочной документации каждого коннектора.

## Ошибки и рекомендации {#errors-and-best-practices}

Проверяйте выборки ограниченного размера, прежде чем увеличивать размер пакетов или степень параллелизма. Явно преобразуйте неподдерживаемые типы и проверяйте потери точности, не пропуская столбцы. Повторное выполнение INSERT в целевую таблицу с моделью Duplicate Key добавляет дублирующиеся строки; перед возобновлением загрузки определите, какие диапазоны уже обработаны. Перед переключением на новую систему выполните проверки согласованности между системами из раздела [Обзор миграции](./overview.md), а также сохраните исходные данные и возможность отката.
