В Apache Doris проектирование таблиц напрямую определяет производительность записи, эффективность запросов и стоимость хранения. Эта глава построена вокруг типичных сценариев проектирования и поможет вам создать таблицу с нуля или оптимизировать структуру существующей таблицы.

## Порядок проектирования {#design-workflow}

Проектирование таблицы в Doris обычно включает следующие шаги:

1. **Выберите модель таблицы**: определите, как данные будут храниться, дедуплицироваться и агрегироваться.
2. **Определите столбцы и типы данных**: выберите подходящие типы для полей ваших бизнес-данных.
3. **Спланируйте партиционирование и бакетирование**: обеспечьте равномерное распределение данных и возможность отсечения ненужных данных.
4. **Добавьте индексы**: ускорьте точечные запросы, сканирование диапазонов или полнотекстовый поиск.
5. **Оптимизируйте хранение**: сократите затраты за счёт сжатия, гибридного строчно-столбцового хранения или разделения горячих и холодных данных по уровням хранения.
6. **Адаптируйте схему**: изменяйте схему или используйте столбцы с автоинкрементом по мере изменения бизнес-требований.

## Создание таблицы {#creating-a-table}

Для создания таблицы в Doris используйте оператор [CREATE TABLE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE). Чтобы создать новую таблицу на основе существующей, можно использовать:

- [CREATE TABLE ... LIKE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE): повторно использовать структуру существующей таблицы.
- [CREATE TABLE ... AS SELECT (CTAS)](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE): создать таблицу на основе результата запроса.

### Правила именования таблиц {#table-name-rules}

По умолчанию имена таблиц в Doris чувствительны к регистру, а их максимальная длина составляет 64 байта. Это поведение можно настроить с помощью следующих параметров:

| Параметр | Значение по умолчанию | Описание |
| --- | --- | --- |
| [lower_case_table_names](../admin-manual/config/fe-config.md) | С учётом регистра | Задаётся только при первичной инициализации кластера; впоследствии изменить нельзя |
| [table_name_length_limit](../admin-manual/config/fe-config.md) | 64 байта | Не рекомендуется задавать слишком большое значение |

### Основные свойства таблицы {#key-table-properties}

При создании таблицы можно указать часто используемые свойства в PROPERTIES. Подробнее см. [CREATE TABLE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE):

| Свойство | Назначение |
| --- | --- |
| `buckets` | Определяет гранулярность распределения данных внутри таблицы |
| `storage_medium` | Задаёт носитель или тип хранилища, например HDD, SSD или удалённое общее хранилище |
| `replication_num` | Задаёт количество реплик данных для обеспечения избыточности и надёжности |
| `storage_policy` | Настраивает политику миграции горячих и холодных данных между уровнями хранения |

:::tip
Свойства таблицы применяются на уровне партиций. Изменение свойств таблицы действует только на партиции, созданные после изменения; существующие партиции не затрагиваются. Подробнее см. [ALTER TABLE PROPERTY](../sql-manual/sql-statements/table-and-view/table/ALTER-TABLE-PROPERTY) и [ALTER TABLE DISTRIBUTION](../sql-manual/sql-statements/table-and-view/table/ALTER-TABLE-DISTRIBUTION). При [динамическом партиционировании](data-partitioning/dynamic-partitioning.md) эти свойства можно задавать отдельно.
:::

## Что учитывать при проектировании {#design-considerations}

{/* Knowledge type: considerations / design constraints */}

| Аспект проектирования | Описание | Влияние |
| --- | --- | --- |
| Модель данных | **Нельзя изменить** после создания таблицы; заранее выберите подходящую [модель данных](./data-model/intro.mdx) | Определяет дальнейшие способы записи данных и выполнения запросов |
| Количество бакетов | Количество бакетов в уже созданных партициях нельзя изменить напрямую, но его можно скорректировать с помощью [замены партиций](../data-operate/delete/table-temp-partition.md); при динамическом партиционировании можно изменить количество бакетов для будущих партиций | Влияет на равномерность распределения данных и параллелизм запросов |
| Изменения столбцов | Добавление или удаление столбцов VALUE является легковесной операцией (выполняется за секунды); добавление или удаление столбцов KEY либо изменение типов данных является тяжеловесной операцией | По возможности избегайте изменения столбцов KEY в больших наборах данных |
| Политика хранения | Используйте [разделение горячих и холодных данных по уровням хранения](./tiered-storage/overview.md) для переноса холодных данных на HDD, в S3 или HDFS | Значительно снижает стоимость хранения |
