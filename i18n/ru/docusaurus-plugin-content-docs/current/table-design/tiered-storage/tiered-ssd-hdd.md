Doris поддерживает многоуровневое хранение на SSD и HDD. В сочетании с динамическими партициями система может сохранять горячие данные на SSD и автоматически переносить холодные данные на HDD с учётом характера обращений к ним. Это обеспечивает высокую производительность чтения и записи горячих данных и снижает общие затраты на хранение.

## Сценарии применения {#applicable-scenarios}

Этот документ относится к следующим сценариям:

- Данные таблицы разбиты на партиции по времени и имеют выраженные различия по частоте доступа.
- В кластере есть и SSD, и HDD.
- Вы хотите ускорить запросы к недавним горячим данным с помощью SSD, а исторические холодные данные хранить на HDD для снижения затрат.
- Вы хотите автоматически управлять жизненным циклом данных с помощью динамических партиций, без переноса вручную.

## Основные понятия {#core-concepts}

<!-- Knowledge type: Feature introduction -->

Многоуровневое хранение реализовано на основе динамических партиций. Doris автоматически выбирает носитель в зависимости от активности партиции и переносит данные на целевой носитель по достижении времени охлаждения.

### Горячие и холодные партиции {#hot-partitions-and-cold-partitions}

| Тип | Описание | Носитель | Характеристики производительности |
| --- | --- | --- | --- |
| Горячая партиция | Недавно активная партиция, к которой часто обращаются | SSD | Высокий IOPS, низкая задержка |
| Холодная партиция | Исторические данные, к которым обращаются реже | HDD | Большая ёмкость, низкая стоимость |

### Как это работает {#how-it-works}

Многоуровневое хранение работает следующим образом:

1. При создании таблицы включите динамические партиции и задайте `dynamic_partition.storage_medium = HDD`.
2. С помощью `dynamic_partition.hot_partition_num` оставьте на SSD текущую партицию, партиции за предыдущие `N - 1` временных интервалов и все будущие партиции.
3. Система задаёт `storage_cooldown_time` для каждой горячей партиции.
4. По достижении времени охлаждения данные партиции автоматически переносятся с SSD на HDD.

Подробнее о динамических партициях см. в разделе [Разбиение данных на партиции — динамические партиции](../../table-design/data-partitioning/dynamic-partitioning).

## Справочник параметров {#parameter-reference}

<!-- Knowledge type: Configuration parameters -->

Многоуровневое хранение зависит от следующих параметров динамических партиций:

| Параметр | Назначение | Значение по умолчанию | Примечания |
| --- | --- | --- | --- |
| `dynamic_partition.hot_partition_num` | При `N > 0` оставляет на SSD текущую партицию, партиции за предыдущие `N - 1` временных интервалов и все будущие партиции | Нет | Необходимо использовать вместе с `storage_medium = HDD` |
| `dynamic_partition.storage_medium` | Задаёт конечный носитель для динамических партиций | HDD | При значении SSD параметр `hot_partition_num` перестаёт действовать |

### dynamic_partition.hot_partition_num {#dynamic_partitionhot_partition_num}

- **Назначение**: при положительном значении `N` оставляет на SSD текущую партицию, партиции за предыдущие `N - 1` временных интервалов и все будущие партиции. Более старые партиции используют HDD.
- **Условия использования**:
    - Необходимо также задать `dynamic_partition.storage_medium = HDD`. Иначе параметр не действует.
    - По пути хранения должно быть доступно устройство SSD. Иначе создать партицию не удастся.

**Пример**:

Предположим, текущая дата — **2021-05-20**, партиции создаются по дням, а параметры динамических партиций заданы так:

```sql
dynamic_partition.hot_partition_num = 2
dynamic_partition.start = -3
dynamic_partition.end = 3
```

Система автоматически создаёт следующие партиции с указанными носителями и временем охлаждения:

```Plain
p20210517: ["2021-05-17", "2021-05-18") storage_medium=HDD storage_cooldown_time=9999-12-31 23:59:59
p20210518: ["2021-05-18", "2021-05-19") storage_medium=HDD storage_cooldown_time=9999-12-31 23:59:59
p20210519: ["2021-05-19", "2021-05-20") storage_medium=SSD storage_cooldown_time=2021-05-21 00:00:00
p20210520: ["2021-05-20", "2021-05-21") storage_medium=SSD storage_cooldown_time=2021-05-22 00:00:00
p20210521: ["2021-05-21", "2021-05-22") storage_medium=SSD storage_cooldown_time=2021-05-23 00:00:00
p20210522: ["2021-05-22", "2021-05-23") storage_medium=SSD storage_cooldown_time=2021-05-24 00:00:00
p20210523: ["2021-05-23", "2021-05-24") storage_medium=SSD storage_cooldown_time=2021-05-25 00:00:00
```

Для дневных партиций смещение текущего дня равно `0`. При `hot_partition_num = N > 0` и конечном носителе `HDD` партиции со смещением больше `-N` используют SSD. Это включает текущий день, предыдущие `N - 1` дней и все будущие партиции, созданные с помощью `dynamic_partition.end`. Время охлаждения партиции на SSD со смещением `i` приходится на начало дня `i + N` относительно текущего дня.

В этом примере партиции со смещениями `-3` и `-2` используют HDD, а со смещениями от `-1` до `3` — SSD. На **2021-05-20** на SSD находятся 5 партиций, хотя `hot_partition_num = 2`. Для создания исторических партиций также необходимо задать `dynamic_partition.create_history_partition = true`, как показано в полном определении таблицы ниже.

### dynamic_partition.storage_medium {#dynamic_partitionstorage_medium}

- **Назначение**: задаёт конечный носитель для динамических партиций. Допустимые значения — `HDD` (по умолчанию) и `SSD`.
- **Примечания**:
    - При значении `SSD` параметр `hot_partition_num` игнорируется.
    - В этом случае все партиции используют SSD, а время охлаждения для них устанавливается равным `9999-12-31 23:59:59`, то есть перенос не происходит.

## Пример использования {#usage-example}

Следующие шаги показывают, как создать таблицу с многоуровневым хранением и проверить распределение её партиций по носителям.

### Шаг 1: Создайте таблицу с многоуровневым хранением {#step-1-create-a-tiered-storage-table}

Цель: создать таблицу с многоуровневым хранением на SSD и HDD. При `hot_partition_num = 2` текущий день, предыдущий день и все будущие партиции используют SSD. Более старые партиции используют HDD.

```sql
CREATE TABLE tiered_table (k DATE)
PARTITION BY RANGE(k)()
DISTRIBUTED BY HASH (k) BUCKETS 5
PROPERTIES
(
    "dynamic_partition.storage_medium" = "hdd",
    "dynamic_partition.enable" = "true",
    "dynamic_partition.time_unit" = "DAY",
    "dynamic_partition.hot_partition_num" = "2",
    "dynamic_partition.end" = "3",
    "dynamic_partition.prefix" = "p",
    "dynamic_partition.buckets" = "5",
    "dynamic_partition.create_history_partition" = "true",
    "dynamic_partition.start" = "-3"
);
```

### Шаг 2: Проверьте носитель партиций {#step-2-check-the-partition-storage-medium}

Цель: убедиться, что партиции распределены между SSD и HDD ожидаемым образом.

```sql
SHOW PARTITIONS FROM tiered_table;
```

Если таблица создана **2021-05-20**, относящиеся к хранению свойства партиций приведены ниже: всего 7 партиций, из которых 5 используют SSD, а 2 — HDD.

## Частые вопросы {#faq}

<!-- Knowledge type: FAQ -->

### Q1: Что делать, если `hot_partition_num` не действует? {#q1-what-if-hot_partition_num-does-not-take-effect}

Убедитесь, что также задано `dynamic_partition.storage_medium = HDD`. Настройка горячих партиций действует только при конечном носителе HDD.

### Q2: Можно ли использовать только SSD? {#q2-can-i-use-ssd-storage-only}

Да. Установите для `dynamic_partition.storage_medium` значение `SSD`: все партиции будут использовать SSD и перенос по достижении времени охлаждения происходить не будет. В этом случае настраивать `hot_partition_num` не нужно.

### Q3: Как данные переносятся по достижении времени охлаждения? {#q3-how-is-data-migrated-after-the-cooldown-time-is-reached}

Когда для партиции наступает `storage_cooldown_time`, система автоматически переносит её данные с SSD на HDD без ручного вмешательства.

### Q4: Чем многоуровневое хранение отличается от архивирования горячих и холодных данных, например в объектном хранилище? {#q4-what-is-the-difference-between-tiered-storage-and-hot-cold-data-archiving-such-as-object-storage}

Многоуровневое хранение на SSD и HDD перемещает данные между разными типами локальных дисков и подходит для разделения горячих и холодных данных на краткосрочную и среднесрочную перспективу. Об архивировании исторических данных в объектное хранилище (S3, HDFS и другие) см. документацию по многоуровневому хранению горячих и холодных данных.

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->
<!-- Applicable scenarios: Table creation failure / Partition creation failure -->

| Признак ошибки | Возможная причина | Решение |
| --- | --- | --- |
| Не удаётся создать партицию | По пути хранения нет устройства SSD | Настройте путь хранения на SSD на узле BE или перейдите на хранение только на HDD |
| `hot_partition_num` не действует | Не задано `storage_medium = HDD` | Также задайте `dynamic_partition.storage_medium = HDD` |
| Все партиции находятся на SSD, переноса на HDD нет | Для `storage_medium` задано значение `SSD` | Измените `storage_medium` на `HDD` и настройте `hot_partition_num` |
| Данные не переносятся на HDD ожидаемым образом | Время `storage_cooldown_time` ещё не наступило | Дождитесь времени охлаждения или проверьте правильность настройки времени |
