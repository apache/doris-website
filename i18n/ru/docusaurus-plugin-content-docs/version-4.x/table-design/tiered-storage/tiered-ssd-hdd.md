Doris поддерживает многоуровневое хранение на SSD и HDD. В сочетании с динамическими разделами система может хранить горячие данные на SSD и автоматически переносить холодные данные на HDD с учётом характера обращения к ним. Это обеспечивает высокую производительность чтения и записи горячих данных и снижает общую стоимость хранения.

## Сценарии применения {#applicable-scenarios}

Этот документ предназначен для следующих случаев:

- Данные таблицы разделены по времени, и частота обращения к ним заметно снижается со временем.
- В кластере есть накопители SSD и HDD.
- Вы хотите ускорить запросы к недавним горячим данным с помощью SSD и сократить расходы на хранение исторических холодных данных с помощью HDD.
- Вы хотите автоматически управлять жизненным циклом данных с помощью динамических разделов без ручного переноса.

## Основные понятия {#core-concepts}

<!-- Knowledge type: Feature introduction -->

Многоуровневое хранение реализовано на основе динамических разделов. Doris автоматически выбирает носитель в зависимости от активности раздела и переносит данные на целевой носитель по достижении времени охлаждения.

### Горячие и холодные разделы {#hot-partitions-and-cold-partitions}

| Тип | Описание | Носитель | Характеристики производительности |
| --- | --- | --- | --- |
| Горячий раздел | Недавно активный раздел, к которому часто обращаются | SSD | Высокая IOPS, низкая задержка |
| Холодный раздел | Исторические данные, к которым обращаются реже | HDD | Большая ёмкость, низкая стоимость |

### Принцип работы {#how-it-works}

Многоуровневое хранение работает следующим образом:

1. При создании таблицы включите динамические разделы и задайте `dynamic_partition.storage_medium = HDD`.
2. С помощью `dynamic_partition.hot_partition_num` оставьте на SSD текущий раздел, разделы за предыдущие `N - 1` временных интервалов и все будущие разделы.
3. Система задаёт `storage_cooldown_time` для каждого горячего раздела.
4. По достижении времени охлаждения данные раздела автоматически переносятся с SSD на HDD.

Подробнее о динамических разделах см. в разделе [«Разделение данных на разделы — динамические разделы»](../../table-design/data-partitioning/dynamic-partitioning).

## Справочник параметров {#parameter-reference}

<!-- Knowledge type: Configuration parameters -->

Для многоуровневого хранения используются два параметра динамических разделов:

| Параметр | Назначение | Значение по умолчанию | Примечания |
| --- | --- | --- | --- |
| `dynamic_partition.hot_partition_num` | При `N > 0` оставляет на SSD текущий раздел, разделы за предыдущие `N - 1` временных интервалов и все будущие разделы | Не задано | Необходимо использовать вместе с `storage_medium = HDD` |
| `dynamic_partition.storage_medium` | Задаёт конечный носитель для динамических разделов | HDD | При значении SSD параметр `hot_partition_num` не действует |

### dynamic_partition.hot_partition_num {#dynamic_partitionhot_partition_num}

- **Назначение**: при положительном значении `N` оставляет на SSD текущий раздел, разделы за предыдущие `N - 1` временных интервалов и все будущие разделы. Более старые разделы используют HDD.
- **Условия использования**:
    - Необходимо также задать `dynamic_partition.storage_medium = HDD`. Иначе параметр не действует.
    - По пути хранения должно быть доступно устройство SSD. Иначе создать раздел не удастся.

**Пример**:

Предположим, текущая дата — **2021-05-20**, разделы создаются по дням, а параметры динамических разделов заданы так:

```sql
dynamic_partition.hot_partition_num = 2
dynamic_partition.start = -3
dynamic_partition.end = 3
```

Система автоматически создаст следующие разделы с указанными носителями и временем охлаждения:

```Plain
p20210517: ["2021-05-17", "2021-05-18") storage_medium=HDD storage_cooldown_time=9999-12-31 23:59:59
p20210518: ["2021-05-18", "2021-05-19") storage_medium=HDD storage_cooldown_time=9999-12-31 23:59:59
p20210519: ["2021-05-19", "2021-05-20") storage_medium=SSD storage_cooldown_time=2021-05-21 00:00:00
p20210520: ["2021-05-20", "2021-05-21") storage_medium=SSD storage_cooldown_time=2021-05-22 00:00:00
p20210521: ["2021-05-21", "2021-05-22") storage_medium=SSD storage_cooldown_time=2021-05-23 00:00:00
p20210522: ["2021-05-22", "2021-05-23") storage_medium=SSD storage_cooldown_time=2021-05-24 00:00:00
p20210523: ["2021-05-23", "2021-05-24") storage_medium=SSD storage_cooldown_time=2021-05-25 00:00:00
```

При ежедневном создании разделов смещение текущего дня равно `0`. Если `hot_partition_num = N > 0`, а конечный носитель — `HDD`, разделы со смещением больше `-N` используют SSD. К ним относятся текущий день, предыдущие `N - 1` дней и все будущие разделы, создаваемые согласно `dynamic_partition.end`. Время охлаждения раздела на SSD со смещением `i` приходится на начало дня `i + N` относительно текущего дня.

В этом примере разделы со смещениями `-3` и `-2` используют HDD, а разделы со смещениями от `-1` до `3` — SSD. На **2021-05-20** накопитель SSD используют пять разделов, хотя `hot_partition_num = 2`. Для создания исторических разделов также требуется `dynamic_partition.create_history_partition = true`, как показано ниже в полном определении таблицы.

### dynamic_partition.storage_medium {#dynamic_partitionstorage_medium}

- **Назначение**: задаёт конечный носитель для динамических разделов. Допустимые значения: `HDD` (по умолчанию) и `SSD`.
- **Примечания**:
    - Если задано `SSD`, параметр `hot_partition_num` игнорируется.
    - В этом случае все разделы хранятся на SSD, а время охлаждения для них устанавливается в `9999-12-31 23:59:59`: переноса не происходит.

## Пример использования {#usage-example}

Следующие шаги показывают, как создать таблицу с многоуровневым хранением и проверить распределение разделов между носителями.

### Шаг 1. Создайте таблицу с многоуровневым хранением {#step-1-create-a-tiered-storage-table}

Цель: создать таблицу с многоуровневым хранением на SSD и HDD. При `hot_partition_num = 2` текущий день, предыдущий день и все будущие разделы используют SSD. Более старые разделы используют HDD.

```sql
CREATE TABLE tiered_table (k DATE)
PARTITION BY RANGE(k)()
DISTRIBUTED BY HASH (k) BUCKETS 5
PROPERTIES
(
    "dynamic_partition.storage_medium" = "hdd",
    "dynamic_partition.enable" = "true",
    "dynamic_partition.time_unit" = "DAY",
    "dynamic_partition.hot_partition_num" = "2",
    "dynamic_partition.end" = "3",
    "dynamic_partition.prefix" = "p",
    "dynamic_partition.buckets" = "5",
    "dynamic_partition.create_history_partition" = "true",
    "dynamic_partition.start" = "-3"
);
```

### Шаг 2. Проверьте носители разделов {#step-2-check-the-partition-storage-medium}

Цель: убедиться, что разделы распределены между SSD и HDD ожидаемым образом.

```sql
SHOW PARTITIONS FROM tiered_table;
```

Если таблица создана **2021-05-20**, соответствующие свойства разделов приведены ниже: всего 7 разделов, из которых 5 используют SSD, а 2 — HDD.

```Plain

p20210518: ["2021-05-18", "2021-05-19") storage_medium=HDD storage_cooldown_time=9999-12-31 23:59:59
p20210519: ["2021-05-19", "2021-05-20") storage_medium=SSD storage_cooldown_time=2021-05-21 00:00:00
p20210520: ["2021-05-20", "2021-05-21") storage_medium=SSD storage_cooldown_time=2021-05-22 00:00:00
p20210521: ["2021-05-21", "2021-05-22") storage_medium=SSD storage_cooldown_time=2021-05-23 00:00:00
p20210522: ["2021-05-22", "2021-05-23") storage_medium=SSD storage_cooldown_time=2021-05-24 00:00:00
p20210523: ["2021-05-23", "2021-05-24") storage_medium=SSD storage_cooldown_time=2021-05-25 00:00:00
```

## Частые вопросы {#faq}

<!-- Knowledge type: FAQ -->

### Вопрос 1. Что делать, если `hot_partition_num` не действует? {#q1-what-if-hot_partition_num-does-not-take-effect}

Убедитесь, что также задано `dynamic_partition.storage_medium = HDD`. Параметр горячих разделов действует только тогда, когда конечным носителем выбран HDD.

### Вопрос 2. Можно ли использовать только SSD? {#q2-can-i-use-ssd-storage-only}

Да. Задайте для `dynamic_partition.storage_medium` значение `SSD`: все разделы будут использовать SSD без переноса по достижении времени охлаждения. В этом случае настраивать `hot_partition_num` не нужно.

### Вопрос 3. Как данные переносятся по достижении времени охлаждения? {#q3-how-is-data-migrated-after-the-cooldown-time-is-reached}

Когда наступает заданное для раздела `storage_cooldown_time`, система автоматически переносит его данные с SSD на HDD без ручного вмешательства.

### Вопрос 4. Чем многоуровневое хранение отличается от архивации горячих и холодных данных, например в объектном хранилище? {#q4-what-is-the-difference-between-tiered-storage-and-hot-cold-data-archiving-such-as-object-storage}

Многоуровневое хранение на SSD и HDD предназначено для переноса данных между разными локальными дисковыми носителями и подходит для разделения горячих и холодных данных на короткий и средний срок. Об архивации исторических данных в объектное хранилище (S3, HDFS и другие) см. документацию по многоуровневому хранению горячих и холодных данных.

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->
<!-- Applicable scenarios: Table creation failure / Partition creation failure -->

| Признак ошибки | Возможная причина | Решение |
| --- | --- | --- |
| Не удаётся создать раздел | По пути хранения нет устройства SSD | Настройте путь хранения на SSD на узле BE или переключитесь на хранение только на HDD |
| `hot_partition_num` не действует | Не задано `storage_medium = HDD` | Также задайте `dynamic_partition.storage_medium = HDD` |
| Все разделы находятся на SSD и не переносятся на HDD по достижении времени охлаждения | Для `storage_medium` задано значение `SSD` | Измените `storage_medium` на `HDD` и настройте `hot_partition_num` |
| Данные не переносятся на HDD ожидаемым образом | Время `storage_cooldown_time` ещё не наступило | Дождитесь времени охлаждения или проверьте правильность настройки времени |
