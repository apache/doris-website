В модели Unique Key Doris предоставляет средства управления параллельными обновлениями. Они решают три типичные задачи:

| Сценарий | Проблема | Решение Doris |
| --- | --- | --- |
| Многократная загрузка данных с одним первичным ключом | Определить, какая запись останется в результате параллельных загрузок | MVCC (многоверсионное управление параллельным доступом): номер версии определяет порядок перезаписи |
| Данные из нескольких потоков поступают не по порядку | Старые данные поступают позже и ошибочно перезаписывают новые | Столбец Sequence: пользователь задаёт порядок замены, и побеждает строка с большим значением Sequence |
| Параллельные UPDATE в одной таблице | Обновления строк могут привести к некорректным данным, поэтому по умолчанию выполняются последовательно | Блокировка на уровне таблицы обеспечивает уровень изоляции Serializable; ограничение на параллельное выполнение можно снять |

Ниже описаны принципы работы и использование этих механизмов.

## Многоверсионное управление параллельным доступом MVCC {#mvcc-multi-version-concurrency-control}

<!-- Knowledge type: Concept description -->

Doris использует многоверсионное управление параллельным доступом (MVCC) для обработки параллельных обновлений:

- Для каждой операции записи данных создаётся транзакция записи. Она гарантирует атомарность: запись либо полностью завершается успешно, либо полностью завершается с ошибкой.
- При фиксации транзакции записи система присваивает ей номер версии.
- Если данные загружаются в таблицу Unique Key несколько раз и встречаются одинаковые первичные ключи, Doris определяет порядок перезаписи по номеру версии: **данные с большим номером версии перезаписывают данные с меньшим номером версии**.

## Управление параллельным выполнением UPDATE {#update-concurrency-control}

<!-- Knowledge type: Configuration parameter -->
<!-- Applicable scenarios: Concurrent execution of multiple UPDATE statements -->

### Поведение по умолчанию {#default-behavior}

По умолчанию Doris **не допускает** параллельного выполнения нескольких операций `UPDATE` в одной таблице.

Причина в том, что сейчас Doris поддерживает обновление на уровне строки: даже если указать только `SET v2 = 1`, все остальные столбцы Value тоже перезаписываются, хотя их значения не меняются. Если две операции `UPDATE` одновременно обновляют одну строку, поведение не определено и возникает риск некорректных данных.

Поэтому по умолчанию оператор `UPDATE` обеспечивает уровень изоляции Serializable с помощью блокировки на уровне таблицы: несколько операций `UPDATE` могут выполняться только последовательно.

### Снятие ограничения на параллельное выполнение {#lifting-the-concurrency-limit}

Если вы можете гарантировать, что параллельные обновления не затронут одну и ту же строку одновременно, ограничение можно снять, изменив конфигурацию FE:

| Параметр конфигурации | Значение по умолчанию | Описание |
| --- | --- | --- |
| `enable_concurrent_update` | `false` | Значение `true` разрешает параллельное выполнение `UPDATE`, но при этом гарантии транзакционности больше не предоставляются |

## Столбец Sequence {#sequence-column}

<!-- Knowledge type: Feature description -->
<!-- Applicable scenarios: Multi-threaded concurrent synchronization / Out-of-order data ingestion -->

### Зачем нужен столбец Sequence {#why-you-need-a-sequence-column}

Модель Unique предназначена главным образом для сценариев, требующих уникальных первичных ключей, и гарантирует их уникальность. Однако в следующих случаях одного номера версии загрузки недостаточно:

- При параллельной синхронизации данных в Doris из нескольких потоков данные разных потоков могут поступать не по порядку.
- Старые данные могут поступить позже и ошибочно перезаписать новые.
- При загрузке данных с одинаковым первичным ключом в одном пакете или в разных пакетах порядок замены не гарантирован, поэтому итоговый результат недетерминирован.

Для решения этой проблемы Doris позволяет указать при загрузке **столбец Sequence**. Для строк с одинаковыми столбцами Key замена определяется значением столбца Sequence: **большее значение заменяет меньшее**, а меньшее не вызывает замены. Таким образом, порядок задаёте вы.

Для этого Doris добавляет скрытый столбец `__DORIS_SEQUENCE_COL__`. Его тип пользователь указывает при создании таблицы, а значение определяется при загрузке. Затем Doris по этому значению выбирает строку среди строк с одинаковыми столбцами Key.

:::caution Примечание
Столбец Sequence сейчас поддерживается только моделью Unique.
:::

### Включение столбца Sequence {#enabling-the-sequence-column}

Его можно включить следующими способами:

| Сценарий | Действие |
| --- | --- |
| Включить при создании таблицы | Указать `function_column.sequence_col` или `function_column.sequence_type` в `PROPERTIES` оператора `CREATE TABLE` |
| Включить для существующей таблицы | Выполнить `ALTER TABLE example_db.my_table ENABLE FEATURE "SEQUENCE_LOAD" WITH PROPERTIES ("function_column.sequence_type" = "Date")` |
| Проверить, включён ли он | Выполнить `SET show_hidden_columns=true`, затем `desc tablename`. Если результат содержит `__DORIS_SEQUENCE_COL__`, столбец Sequence включён |

Эти два свойства различаются следующим образом:

| Свойство | Значение | Нужен ли соответствующий столбец в схеме |
| --- | --- | --- |
| `function_column.sequence_col` | Сопоставляет столбец Sequence с существующим столбцом таблицы | Да |
| `function_column.sequence_type` | Указывает только тип столбца Sequence, который хранится как скрытый столбец | Нет |

Поддерживаемые типы столбца: целочисленные типы, `DATE` и `DATETIME`. **После создания таблицы тип столбца изменить нельзя.**

### Пример использования {#usage-example}

Следующий пример показывает весь процесс с использованием Stream Load.

#### 1. Создание таблицы с поддержкой столбца Sequence {#1-create-a-table-that-supports-the-sequence-column}

Создайте таблицу `test_table` модели Unique и сопоставьте столбец Sequence со столбцом `modify_date` этой таблицы:

```sql
CREATE TABLE test.test_table
(
    user_id bigint,
    date date,
    group_id bigint,
    modify_date date,
    keyword VARCHAR(128)
)
UNIQUE KEY(user_id, date, group_id)
DISTRIBUTED BY HASH (user_id) BUCKETS 32
PROPERTIES(
    "function_column.sequence_col" = 'modify_date',
    "replication_num" = "1",
    "in_memory" = "false"
);
```

Полученная схема таблицы выглядит так:

```sql
MySQL>  desc test_table;
+-------------+--------------+------+-------+---------+---------+
| Field       | Type         | Null | Key   | Default | Extra   |
+-------------+--------------+------+-------+---------+---------+
| user_id     | BIGINT       | No   | true  | NULL    |         |
| date        | DATE         | No   | true  | NULL    |         |
| group_id    | BIGINT       | No   | true  | NULL    |         |
| modify_date | DATE         | No   | false | NULL    | REPLACE |
| keyword     | VARCHAR(128) | No   | false | NULL    | REPLACE |
+-------------+--------------+------+-------+---------+---------+
```

Если вы не хотите, чтобы этот столбец отображался в схеме таблицы, вместо этого укажите его тип через `function_column.sequence_type`:

```sql
PROPERTIES (
    "function_column.sequence_type" = 'Date'
);
```

#### 2. Загрузка данных и проверка работы столбца Sequence {#2-import-data-and-verify-the-sequence-behavior}

При сопоставлении столбцов через `function_column.sequence_col` дополнительные параметры команды загрузки не нужны. Загрузите следующие данные с помощью Stream Load:

```Plain
1	2020-02-22	1	2020-02-21	a
1	2020-02-22	1	2020-02-22	b
1	2020-02-22	1	2020-03-05	c
1	2020-02-22	1	2020-02-26	d
1	2020-02-22	1	2020-02-23	e
1	2020-02-22	1	2020-02-24	b
```

Команда Stream Load:

```shell
curl --location-trusted -u root: -T testData http://host:port/api/test/test_table/_stream_load
```

Результат запроса:

```sql
MySQL> select * from test_table;
+---------+------------+----------+-------------+---------+
| user_id | date       | group_id | modify_date | keyword |
+---------+------------+----------+-------------+---------+
|       1 | 2020-02-22 |        1 | 2020-03-05  | c       |
+---------+------------+----------+-------------+---------+
```

Поскольку `2020-03-05` — наибольшее значение в столбце Sequence (`modify_date`), в столбце `keyword` в итоге остаётся `c`.

#### 3. Указание столбца Sequence при разных способах загрузки {#3-specifying-the-sequence-column-in-different-import-methods}

Если для таблицы используется `function_column.sequence_type`, столбец Sequence скрыт и при загрузке его нужно сопоставить с входным полем. В следующих примерах используется **отдельная таблица**, а не таблица `test_table`, в которой столбец Sequence сопоставлен с `modify_date`.

```sql
CREATE DATABASE IF NOT EXISTS test;
CREATE TABLE test.test_sequence_hidden
(
    k1 BIGINT NOT NULL,
    k2 DATE NOT NULL,
    v1 BIGINT,
    v2 VARCHAR(128)
)
UNIQUE KEY(k1, k2)
DISTRIBUTED BY HASH(k1) BUCKETS 1
PROPERTIES (
    "function_column.sequence_type" = "DATE",
    "replication_num" = "1"
);
```

Подготовьте файл `sequence_data.tsv` со следующими строками, разделёнными символами табуляции. Четвёртое входное поле, `source_sequence`, задаёт значение скрытого столбца Sequence; оно не является видимым столбцом таблицы.

```text
1	2020-02-22	1	2020-02-22	a
1	2020-02-22	1	2020-03-23	w
```

**Stream Load**

Сопоставьте входные поля в порядке их следования в файле и укажите поле Sequence в заголовке запроса:

```shell
curl --location-trusted -u root: \
    -H "columns: k1,k2,v1,source_sequence,v2" \
    -H "function_column.sequence_col: source_sequence" \
    -T sequence_data.tsv http://host:port/api/test/test_sequence_hidden/_stream_load
```

**Broker Load**

Загрузите тот же файл в HDFS и замените путь и учётные данные Broker ниже. Используйте разделитель табуляции и тот же порядок полей, затем выберите четвёртое входное поле с помощью `ORDER BY source_sequence`:

```sql
LOAD LABEL test.sequence_hidden_broker
(
    DATA INFILE("hdfs://host:port/user/data/sequence_data.tsv")
    INTO TABLE `test_sequence_hidden`
    COLUMNS TERMINATED BY "\t"
    (k1,k2,v1,source_sequence,v2)
    ORDER BY source_sequence
)
WITH BROKER 'broker'
(
    "username" = "user",
    "password" = "pass"
)
PROPERTIES ("timeout" = "3600");
```

**Routine Load**

Создайте задание, указав свой Kafka broker и topic, затем отправьте каждую из приведённых выше строк как отдельное сообщение Kafka с полями, разделёнными табуляцией:

```sql
CREATE ROUTINE LOAD test.sequence_hidden_routine ON test_sequence_hidden
    COLUMNS TERMINATED BY "\t",
    COLUMNS(k1,k2,v1,source_sequence,v2),
    ORDER BY source_sequence
    PROPERTIES
    (
        "desired_concurrent_number" = "1",
        "format" = "csv"
    )
    FROM KAFKA
    (
        "kafka_broker_list" = "broker1:9092",
        "kafka_topic" = "my_topic"
    );
```

После успешной загрузки, когда данные станут видимыми, большее значение Sequence (`2020-03-23`) сохранит строку, у которой `v2` равно `w`. В следующих примерах с `modify_date` снова используется исходная таблица `test_table` и настроенное для неё сопоставление столбцов.

#### 4. Проверка гарантированного порядка замены {#4-verify-the-replacement-order-guarantee}

Продолжая предыдущий пример, загрузите следующие данные (все значения Sequence меньше существующего максимума `2020-03-05`):

```Plain
1	2020-02-22	1	2020-02-22	a
1	2020-02-22	1	2020-02-23	b
```

Результат запроса:

```sql
MySQL [test]> select * from test_table;
+---------+------------+----------+-------------+---------+
| user_id | date       | group_id | modify_date | keyword |
+---------+------------+----------+-------------+---------+
|       1 | 2020-02-22 |        1 | 2020-03-05  | c       |
+---------+------------+----------+-------------+---------+
```

Поскольку все значения Sequence в этой загрузке меньше существующего максимума `2020-03-05`, результат не меняется.

Теперь загрузите данные с большим значением Sequence:

```Plain
1	2020-02-22	1	2020-02-22	a
1	2020-02-22	1	2020-03-23	w
```

Результат запроса:

```sql
MySQL [test]> select * from test_table;
+---------+------------+----------+-------------+---------+
| user_id | date       | group_id | modify_date | keyword |
+---------+------------+----------+-------------+---------+
|       1 | 2020-02-22 |        1 | 2020-03-23  | w       |
+---------+------------+----------+-------------+---------+
```

Поскольку значение Sequence `2020-03-23` у новых данных больше существующего максимума `2020-03-05`, прежние данные заменяются.

**Вывод**: при загрузке Doris сравнивает значения столбца Sequence во всех пакетах и **записывает в таблицу запись с наибольшим значением**.

### Примечания по использованию {#usage-notes}

<!-- Knowledge type: Caveats -->

1. **Требования к столбцу Sequence зависят от определения таблицы**: при использовании `function_column.sequence_col` загружайте сопоставленный обычный столбец по стандартным правилам работы со столбцами; дополнительный параметр сопоставления Sequence при загрузке не нужен. При использовании `function_column.sequence_type` настройте сопоставление исходного столбца для Stream Load или Broker Load, как показано выше. Для `INSERT` полной строки с явно указанным списком целевых столбцов включите в него сопоставленный обычный столбец (если его значение по умолчанию не равно `CURRENT_TIMESTAMP`) либо скрытый `__DORIS_SEQUENCE_COL__`, если сопоставленного столбца нет. `INSERT` без списка целевых столбцов уже включает сопоставленный обычный столбец. Об обновлении отдельных столбцов см. пункт 3 ниже. Если обязательное значение Sequence отсутствует, возникает следующая ошибка:

    ```Plain
    Table test_tbl has sequence column, need to specify the sequence column
    ```

2. **Отключение проверки обязательного наличия столбца Sequence**: например, при репликации таблиц или внутренней миграции данных обязательную проверку столбца Sequence в операторах `INSERT` можно отключить с помощью переменной сеанса:

    ```sql
    set require_sequence_in_insert = false;
    ```

3. **Совместимость с обновлением отдельных столбцов**: начиная с версии 2.0 реализация Merge-on-Write для таблиц Unique Key в Doris поддерживает обновление отдельных столбцов. При такой загрузке каждый раз можно обновлять только часть столбцов, поэтому **столбец Sequence не обязателен**:

    - Если задание загрузки включает столбец Sequence, поведение не меняется.
    - Если задание загрузки не включает столбец Sequence, Doris использует значение столбца Sequence из соответствующих ранее записанных данных как значение Sequence обновлённой строки.
    - Если в ранее записанных данных нет записи с таким же Key, Doris автоматически подставляет `null` или значение по умолчанию.

4. **Гарантия корректности при параллельных загрузках**: при параллельных загрузках Doris использует MVCC для обеспечения корректности данных. Если два пакета загрузки обновляют разные столбцы одного и того же Key, то после успешного завершения задания с меньшим номером версии задание с большим номером версии использует записанные им строки с тем же Key для заполнения недостающих значений.
