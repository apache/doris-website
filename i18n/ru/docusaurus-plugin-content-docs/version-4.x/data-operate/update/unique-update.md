<!-- Knowledge type: How-to guide -->
<!-- Applicable scenarios: Data correction / ETL field batch processing / Business state changes -->

После записи данных в Doris часто возникает необходимость изменить существующие данные: меняются статусы заказов, заданиям ETL нужно дозаполнить определённые поля, а в исторических записях обнаруживаются ошибки, которые требуется исправить. Для таких задач Doris предоставляет стандартный оператор `UPDATE` для модели Unique Key, позволяющий обновлять данные на уровне строк по заданному условию.

В этом документе описаны сценарии применения, основные принципы работы и типичные способы использования команды `UPDATE` в Doris. Примечание: **команда `UPDATE` применима только к таблицам, использующим модель данных Unique**.

## Сценарии применения {#applicable-scenarios}

Команда `UPDATE` предназначена прежде всего для следующих двух типичных сценариев:

| Тип сценария | Описание | Рекомендуемая частота |
| ----------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------ |
| Обновление небольшого объёма данных | Исправление ошибочных полей в небольшом числе записей или обновление статуса небольшого числа записей (например, изменение статусов заказов). | Частота сопоставима с INSERT. |
| Пакетная обработка ETL | Массовое обновление определённого поля, характерное для сценариев ETL, в которых некоторые столбцы нужно дозаполнить или пересчитать. | Подходит только для редких вызовов. |

## Основные принципы {#basic-principles}

<!-- Knowledge type: Principle explanation -->

Команда `UPDATE` выполняется следующим образом:

1. С помощью встроенной в движок запросов логики фильтрации `WHERE` из целевой таблицы выбираются строки, которые требуется обновить.
2. Целевые столбцы этих строк изменяются в памяти.
3. Изменённые строки повторно вставляются в таблицу с использованием механизма модели Unique, при котором новые данные в столбцах Value заменяют старые. Так выполняется обновление на уровне строк.

### Синхронное выполнение {#synchronous-execution}

`UPDATE` в Doris является **синхронным оператором**: когда оператор `UPDATE` возвращает результат об успешном выполнении, обновление уже завершено, а новые данные сразу доступны.

### Характеристики производительности {#performance-characteristics}

Производительность оператора `UPDATE` зависит главным образом от двух факторов:

- **Число обновляемых строк**: чем больше строк нужно обновить, тем медленнее выполняется оператор `UPDATE`.
    - Обновление небольшого объёма данных: Doris поддерживает частоту, сопоставимую с `INSERT INTO`.
    - Обновление большого объёма данных: один вызов `UPDATE` занимает много времени и подходит только для редкого выполнения.

- **Эффективность поиска по условию запроса**: при выполнении `UPDATE` сначала считываются строки, соответствующие условию запроса, поэтому чем эффективнее поиск по условию, тем быстрее выполняется `UPDATE`.
    - Рекомендуется: по возможности использовать в условии столбцы, позволяющие задействовать индексы или отсекать разделы либо бакеты, чтобы избежать полного сканирования таблицы.
    - **Настоятельно не рекомендуется**: включать столбцы Value в условие.

## Пример использования {#usage-example}

<!-- Knowledge type: Operating steps -->
<!-- Applicable scenarios: Financial risk control / Field batch processing -->

Следующий пример на основе сценария управления финансовыми рисками показывает, как с помощью команды `UPDATE` массово заполнить уровни риска в таблице с деталями транзакций.

### 1. Создание таблицы {#1-create-the-table}

Создайте таблицу с деталями транзакций, использующую модель Unique Key, с включённым режимом MOW (Merge-on-Write):

```sql
CREATE TABLE transaction_details (
    transaction_id BIGINT NOT NULL,        -- Unique transaction ID
    user_id BIGINT NOT NULL,               -- User ID
    transaction_date DATE NOT NULL,        -- Transaction date
    transaction_time DATETIME NOT NULL,    -- Transaction time
    transaction_amount DECIMAL(18, 2),     -- Transaction amount
    transaction_device STRING,             -- Transaction device
    transaction_region STRING,             -- Transaction region
    average_daily_amount DECIMAL(18, 2),   -- Average daily transaction amount in the last 3 months
    recent_transaction_count INT,          -- Number of transactions in the last 7 days
    has_dispute_history BOOLEAN,           -- Whether there is a chargeback record
    risk_level STRING                      -- Risk level
)
UNIQUE KEY(transaction_id)
DISTRIBUTED BY HASH(transaction_id) BUCKETS 16
PROPERTIES (
    "replication_num" = "3",                     -- Number of replicas, default 3
    "enable_unique_key_merge_on_write" = "true"  -- Enable MOW mode to support merge updates
);
```

### 3. Правила оценки риска {#3-risk-control-rules}

Обновите уровень риска для всех записей о транзакциях за день в соответствии со следующими правилами оценки риска:

| № | Правило | Уровень риска |
| --- | --------------------------------------------- | ---------- |
| 1   | Есть запись о возврате платежа | высокий |
| 2   | Транзакция в регионе с высоким риском | высокий |
| 3   | Аномальная сумма транзакции (превышает среднедневную более чем в 5 раз) | высокий |
| 4   | Более 50 транзакций за последние 7 дней | высокий |
| 5   | От 20 до 50 транзакций за последние 7 дней | средний |
| 6   | Транзакция в нерабочее время (между 2 и 4 часами утра) | средний |
| 7   | Прочие случаи (по умолчанию) | низкий |

### 4. Выполнение UPDATE {#4-run-update}

Используйте выражение `CASE WHEN`, чтобы применить все приведённые выше правила к записям за день одним оператором:

```sql
UPDATE transaction_details
SET risk_level = CASE
    -- Transactions with a chargeback record or in a high-risk region
    WHEN has_dispute_history = TRUE THEN 'high'
    WHEN transaction_region IN ('high_risk_region1', 'high_risk_region2') THEN 'high'

    -- Sudden abnormal transaction amount
    WHEN transaction_amount > 5 * average_daily_amount THEN 'high'

    -- Very high transaction frequency in the last 7 days
    WHEN recent_transaction_count > 50 THEN 'high'
    WHEN recent_transaction_count BETWEEN 20 AND 50 THEN 'medium'

    -- Off-hours transactions
    WHEN HOUR(transaction_time) BETWEEN 2 AND 4 THEN 'medium'

    -- Default risk
    ELSE 'low'
END
WHERE transaction_date = '2024-11-24';
```

## Дополнительная справка {#more-help}

Полный синтаксис команды `UPDATE` приведён в руководстве по команде [UPDATE](../../sql-manual/sql-statements/data-modification/DML/UPDATE). Дополнительную информацию также можно получить, выполнив `HELP UPDATE` в командной строке клиента MySQL.
