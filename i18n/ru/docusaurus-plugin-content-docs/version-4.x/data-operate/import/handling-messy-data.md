Во время импорта типы данных исходных и целевых столбцов могут не совпадать. Doris преобразует несовпадающие типы при импорте, но в процессе могут возникнуть следующие проблемы, из-за которых часть данных не удастся корректно загрузить:

- Несовпадение типов поля (например, запись строки `"abc"` в столбец `TinyInt`)
- Слишком длинное поле (например, запись 11 символов в столбец `char(10)`)
- Несовпадение точности / переполнение числового значения (например, запись `10` в столбец `Decimal(1,0)`)

Для обработки таких исключений Doris предоставляет два основных параметра управления импортом:

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `strict_mode` | Управляет фильтрацией строк данных, для которых не удалось преобразовать тип столбца | `false` |
| `max_filter_ratio` | Задаёт максимально допустимую долю аномальных данных от общего объёма данных | `0` |

> Совместное использование этих двух параметров позволяет гибко выбирать между «строгим обеспечением качества данных» и «допуском небольшого количества аномальных данных».

## Строгий режим (strict_mode) {#strict-mode-strict_mode}

<!-- Knowledge type: Configuration parameter description -->

Основная функция строгого режима (`strict_mode`) — фильтровать строки данных, для которых **не удалось преобразовать тип столбца** во время импорта.

### Стратегия фильтрации при сбоях преобразования типов столбцов {#filtering-strategy-for-column-type-conversion-failures}

В зависимости от настройки строгого режима система применяет разные стратегии обработки:

- **Строгий режим отключён**: поля, преобразование которых завершилось ошибкой, получают значение `NULL`, а строки с такими значениями `NULL` импортируются вместе с корректными строками.
- **Строгий режим включён**: система фильтрует строки, для которых преобразование завершилось ошибкой, и импортирует только корректные строки. Здесь «сбой преобразования» означает именно ситуацию, когда исходные данные не равны `NULL`, но после преобразования типа столбца результатом становится `NULL`. Обратите внимание, что такое преобразование типа столбца не включает значения `NULL`, полученные в результате вычисления функции.
- **Обработка значений `NULL`**: как корректные, так и аномальные строки могут содержать значения `NULL`. Если целевой столбец объявлен не допускающим значения `NULL`, строки с такими значениями фильтруются.

Ниже приведены три типичных примера типов столбцов, иллюстрирующие различия в поведении при включённом и отключённом строгом режиме.

#### Пример 1: тип столбца TinyInt {#example-1-column-type-tinyint}

| Тип исходных данных | Пример исходных данных | Значение после преобразования в TinyInt | Строгий режим | Результат |
| ------------ | ---------------- | --------------------- | ------------ | ---------------- |
| Пустое значение | `\N` | `NULL` | Включён или отключён | `NULL` |
| Непустое значение | `"abc"` или `2000` | `NULL` | Включён | Недопустимое значение (отфильтровано) |
| Непустое значение | `"abc"` или `2000` | `NULL` | Отключён | `NULL` |
| Непустое значение | `1` | `1` | Включён или отключён | Импортировано корректно |

:::tip
1. Столбцы в таблице допускают импорт значений `NULL`.
2. После преобразования в `TinyInt` значения `abc` и `2000` становятся `NULL` из-за проблем с типом или точностью. При включённом строгом режиме такие данные фильтруются; при отключённом режиме импортируется `NULL`.
:::

#### Пример 2: тип столбца Decimal(1,0) {#example-2-column-type-decimal10}

| Тип исходных данных | Пример исходных данных | Значение после преобразования в Decimal | Строгий режим | Результат |
| ------------ | ------------ | --------------------- | ------------ | ---------------- |
| Пустое значение | `\N` | `NULL` | Включён или отключён | `NULL` |
| Непустое значение | `aaa` | `NULL` | Включён | Недопустимое значение (отфильтровано) |
| Непустое значение | `aaa` | `NULL` | Отключён | `NULL` |
| Непустое значение | `10` | `NULL` (переполнение) | Включён | Отфильтровано |
| Непустое значение | `10` | `NULL` (переполнение) | Отключён | `NULL` |

:::tip
1. Столбцы в таблице допускают импорт значений `NULL`.
2. После преобразования в `Decimal` значение `aaa` становится `NULL` из-за проблем с типом. При включённом строгом режиме такие данные фильтруются; при отключённом режиме импортируется `NULL`.
3. Значение `10` выходит за диапазон `Decimal(1, 0)` и преобразуется в `NULL`. При включённом строгом режиме оно фильтруется; при отключённом режиме импортируется `NULL`.
:::

#### Пример 3: тип столбца char(10) {#example-3-column-type-char10}

| Тип исходных данных | Пример исходных данных | Значение после преобразования в char(10) | Строгий режим | Результат |
| ------------ | -------------- | ---------------------- | -------- | ------------------- |
| Пустое значение | `\N` | `NULL` | Включён или отключён | `NULL` |
| Непустое значение | `a1234567890` | `a1234567890` | Включён | Слишком длинное значение, отфильтровано |
| Непустое значение | `a1234567890` | `a1234567890` | Отключён | `a123456789` (обрезано) |

:::tip
Столбцы в таблице допускают импорт значений `NULL`.
:::

### Включение строгого режима {#enabling-strict-mode}

По умолчанию `strict_mode` имеет значение `false`. Примеры включения строгого режима для различных способов импорта:

**Stream Load**

```shell
curl --location-trusted -u user:passwd \
    -H "strict_mode: true" \
    -T data.txt \
    http://host:port/api/example_db/test_table/_stream_load
```

**Broker Load**

```sql
LOAD LABEL example_db.label_1
(
    DATA INFILE("s3://bucket/data.txt")
    INTO TABLE test_table
)
WITH S3 (...)
PROPERTIES
(
    "strict_mode" = "true"
);
```

**Routine Load**

```sql
CREATE ROUTINE LOAD example_db.job1 ON test_table
PROPERTIES
(
    "strict_mode" = "true"
)
FROM KAFKA (...);
```

**MySQL Load**

```sql
LOAD DATA LOCAL INFILE 'data.txt'
INTO TABLE test_table
PROPERTIES
(
    "strict_mode" = "true"
);
```

**Insert Into**

```sql
SET enable_insert_strict = true;
INSERT INTO test_table ...;
```

## Максимальная доля фильтрации (max_filter_ratio) {#maximum-filter-ratio-max_filter_ratio}

<!-- Knowledge type: Configuration parameter description -->

Максимальная доля фильтрации (`max_filter_ratio`) — это важный параметр управления импортом, который определяет максимально допустимую долю аномальных данных от общего объёма данных во время импорта:

- Если фактическая доля фильтрации **ниже** настроенной максимальной доли фильтрации, задание импорта продолжает выполняться, а аномальные данные игнорируются.
- Если фактическая доля фильтрации **превышает** настроенную максимальную долю фильтрации, задание импорта завершается ошибкой.

### Как рассчитывается доля фильтрации {#how-the-filter-ratio-is-calculated}

Во время импорта строки данных делятся на следующие три категории:

| Категория | Описание |
| --- | --- |
| **Filtered Rows** | Строки, отфильтрованные из-за проблем с качеством данных. К таким проблемам относятся ошибки типов, ошибки точности, превышение длины строк, несовпадение числа столбцов в файлах и другие проблемы формата данных, а также строки, отфильтрованные из-за отсутствия соответствующей партиции. |
| **Unselected Rows** | Строки данных, отфильтрованные условиями [предварительной фильтрации](./load-data-convert.md#pre-filtering) или [последующей фильтрации](./load-data-convert.md#post-filtering). |
| **Loaded Rows** | Строки данных, импортированные корректно. |

Доля фильтрации рассчитывается следующим образом:

```Plain
#Filtered Rows / (#Filtered Rows + #Loaded Rows)
```

Иными словами, `Unselected Rows` не участвуют в расчёте доли фильтрации.

### Настройка максимальной доли фильтрации {#setting-the-maximum-filter-ratio}

По умолчанию `max_filter_ratio` имеет значение `0`, то есть аномальные данные не допускаются. Примеры настройки для различных способов импорта:

**Stream Load**

```shell
curl --location-trusted -u user:passwd \
    -H "max_filter_ratio: 0.1" \
    -T data.txt \
    http://host:port/api/example_db/my_table/_stream_load
```

**Broker Load**

```sql
LOAD LABEL example_db.label_1
(
    DATA INFILE("s3://bucket/data.txt")
    INTO TABLE test_table
)
WITH S3 (...)
PROPERTIES
(
    "max_filter_ratio" = "0.1"
);
```

**Routine Load**

```sql
CREATE ROUTINE LOAD example_db.job1 ON test_table
PROPERTIES
(
    "max_filter_ratio" = "0.1"
)
FROM KAFKA (...);
```

**MySQL Load**

```sql
LOAD DATA LOCAL INFILE 'data.txt'
INTO TABLE test_table
PROPERTIES
(
    "max_filter_ratio" = "0.1"
);
```

**Insert Into**

```sql
CREATE TABLE insert_filter_ratio_example (id INT NOT NULL)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 1
PROPERTIES ("replication_num" = "1");

SET enable_insert_strict = false;
SET insert_max_filter_ratio = 0.5;
INSERT INTO insert_filter_ratio_example VALUES (1), (NULL);
SELECT * FROM insert_filter_ratio_example;
```

```text
+------+
| id   |
+------+
|    1 |
+------+
```

Поскольку `id` не допускает NULL, вторая строка отфильтрована. Доля фильтрации равна `1 / (1 + 1) = 0.5`, что не превышает порог, поэтому загрузка завершается успешно.

:::tip
Для операторов INSERT INTO параметр `insert_max_filter_ratio` действует только при `enable_insert_strict = false` и имеет значение `1.0` по умолчанию. Он применяется к VALUES и SELECT, включая таблицы Doris, внешние таблицы и файловые TVF. Если фактическая доля фильтрации превышает порог, INSERT завершается ошибкой; равенство порогу допускается. Этот параметр не подавляет другие ошибки выполнения.
:::

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Q1: Как следует использовать `strict_mode` и `max_filter_ratio` вместе?**

- Если требуется **строгое качество данных**: включите `strict_mode = true` и задайте небольшое значение `max_filter_ratio` (например, `0`). Любая ошибка преобразования приведёт к сбою импорта.
- Если нужно **допускать небольшое количество аномальных данных**: отключите `strict_mode` (или оставьте значение по умолчанию) и задайте приемлемую долю `max_filter_ratio` (например, `0.1`). Аномальные данные будут отфильтрованы, не влияя на импорт в целом.

**Q2: Фильтруются ли строгим режимом значения `NULL`, полученные в результате вычисления функции?**

Нет. Строгий режим применяется только к случаю, когда «исходные данные не равны NULL, но после преобразования типа столбца результатом становится NULL». Значения `NULL`, полученные в результате вычисления функции, к этой категории не относятся.

**Q3: Учитываются ли в `max_filter_ratio` строки, отфильтрованные условиями предварительной или последующей фильтрации?**

Нет. `Unselected Rows` не участвуют в расчёте доли фильтрации. Доля фильтрации рассчитывается только на основе `Filtered Rows` и `Loaded Rows`.

**Q4: Как связаны `enable_insert_strict` и `insert_max_filter_ratio` в Insert Into?**

`insert_max_filter_ratio` действует только при `enable_insert_strict = false`. Его значение по умолчанию — `1.0`, то есть допускается фильтрация всех аномальных данных.

**Q5: Чем отличается поведение строгого и нестрогого режима, когда в столбец `char(10)` поступают слишком длинные данные?**

- Строгий режим включён: слишком длинные данные фильтруются.
- Строгий режим отключён: слишком длинные данные обрезаются и импортируются (например, `a1234567890` обрезается до `a123456789`).
