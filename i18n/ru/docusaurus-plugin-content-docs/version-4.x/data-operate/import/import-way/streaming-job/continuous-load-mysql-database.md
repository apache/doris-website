<!-- Applicable scenario: Mirror sync of a whole MySQL database to Doris -->

Синхронизация с автоматическим созданием таблиц реализована с помощью встроенной команды DDL `FROM MYSQL (...) TO DATABASE (...)`. **Целевым объектом служит контейнер базы данных Doris, а таблицы на целевой стороне Doris создаёт автоматически.** С помощью `include_tables` можно выбрать синхронизацию одной таблицы, нескольких таблиц или всех таблиц. При первой синхронизации Doris автоматически создаёт на целевой стороне таблицы с первичным ключом, сохраняя первичные ключи источника. Этот способ подходит для зеркальной репликации, когда обработка с помощью SQL не требуется, а структура целевых таблиц должна автоматически соответствовать структуре исходных.

Благодаря интеграции возможностей [Flink CDC](https://github.com/apache/flink-cdc) Doris читает журналы изменений MySQL и непрерывно записывает полный набор данных и инкрементальные изменения группы таблиц в Doris через Stream Load. Если во время синхронизации требуется сопоставление столбцов, фильтрация или преобразование данных, см. [MySQL CDC с сопоставлением через SQL](./continuous-load-mysql-table.md).

### Сценарии использования {#applicable-scenarios}

- Вам нужно зеркально реплицировать группу таблиц или всю базу данных из MySQL в Doris.
- Вы хотите, чтобы структура целевых таблиц и первичные ключи создавались автоматически на основе источника, без ручного создания таблиц.
- Во время синхронизации не требуется сопоставление столбцов, фильтрация или преобразование данных.
- Вам нужна поддержка как начальной полной загрузки, так и непрерывного получения инкрементальных изменений.

### Возможности и ограничения {#capabilities-and-limitations}

| Параметр              | Описание                                                             |
| --------------------- | -------------------------------------------------------------------- |
| Гарантии согласованности | В настоящее время гарантируется только семантика at-least-once     |
| Тип таблицы           | Синхронизация поддерживается только для таблиц с первичным ключом (Unique Key) |
| Права доступа         | Требуется право Load; если целевая таблица не существует, также требуется право Create |
| Автоматическое создание таблиц | Если целевая таблица уже существует, её создание пропускается; структуру таблицы можно настроить по необходимости |
| Обработка данных      | Сопоставление столбцов, фильтрация и преобразование не поддерживаются; при необходимости используйте синхронизацию с сопоставлением через SQL |

## Предварительные требования {#prerequisites}

Перед созданием задания синхронизации с автоматическим созданием таблиц убедитесь в следующем:

1. Кластер Doris развёрнут, и у вас есть право Load. Для автоматического создания таблиц также требуется право Create.
2. JAR-файл драйвера JDBC, совместимого с версией MySQL, загружен и доступен по имени файла, локальному абсолютному пути или HTTP-адресу. Подробности см. в разделе [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md).
3. В MySQL включён binlog, а учётная запись имеет право на его чтение.
4. Определён объём синхронизации: вся база данных или только таблицы, указанные в `include_tables`.

## Быстрый старт {#quick-start}

<!-- Knowledge type: Procedure -->

### Шаг 1: Создайте задание загрузки {#step-1-create-a-load-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки:

```sql
CREATE JOB multi_table_sync
ON STREAMING
FROM MYSQL (
        "jdbc_url" = "jdbc:mysql://127.0.0.1:3306",
        "driver_url" = "mysql-connector-java-8.0.25.jar",
        "driver_class" = "com.mysql.cj.jdbc.Driver",
        "user" = "root",
        "password" = "123456",
        "database" = "test",
        "include_tables" = "user_info,order_info",
        "offset" = "initial"
)
TO DATABASE target_test_db (
    "table.create.properties.replication_num" = "1"  -- Set to 1 for single-BE deployment
)
```

Основные моменты приведённого примера:

- `database` задаёт исходную базу данных MySQL. `include_tables` ограничивает список синхронизируемых таблиц; имена нескольких таблиц разделяются запятыми, а пустое значение означает синхронизацию всей базы данных.
- `offset = "initial"` означает, что сначала выполняется полная загрузка, а затем начинается синхронизация инкрементальных изменений. Чтобы синхронизировать только инкрементальные данные, измените значение на `latest`.
- `TO DATABASE target_test_db` задаёт целевую базу данных Doris. Используйте `table.create.properties.*`, чтобы настроить свойства автоматически создаваемых таблиц, например количество реплик.

### Шаг 2: Проверьте состояние загрузки {#step-2-check-load-status}

Запросите текущее состояние задания Streaming Job с помощью табличной функции `jobs("type"="insert")`:

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING"

             Name: mysql_db_sync

       CreateTime: 2025-12-10 10:19:35

  FailedTaskCount: 0

          Comment: 
       Properties: \N
    CurrentOffset: {"ts_sec":"1765284495","file":"binlog.000002","pos":"9350","kind":"SPECIFIC","splitId":"binlog-split","row":"1","event":"2","server_id":"1"}
        EndOffset: \N
    LoadStatistic: {"scannedRows":24,"loadBytes":1146,"fileNumber":0,"fileSize":0}
         ErrorMsg: \N
```

Поля, на которые следует обратить внимание:

- `Status`: общее состояние задания, например `RUNNING`.
- `CurrentOffset`: текущая обработанная позиция в binlog, позволяющая отслеживать ход синхронизации.
- `LoadStatistic`: статистика загрузки, например количество прочитанных строк и записанных байтов.
- `ErrorMsg`: сообщения об ошибках, основной источник информации для диагностики проблем с заданием.

### Шаг 3: Измените задание загрузки {#step-3-modify-the-load-job}

Если нужно обновить параметры подключения к источнику данных, например сменить учётные данные, используйте `ALTER JOB`:

```sql
ALTER JOB <job_name>
FROM MYSQL (
    "user" = "root",
    "password" = "123456"
)
TO DATABASE target_test_db
```

Другие стандартные операции, такие как приостановка, возобновление, удаление и просмотр задач, описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Параметры источника данных {#data-source-parameters}

<!-- Knowledge type: Configuration parameters -->

Источник MySQL (`FROM MYSQL`) поддерживает следующие параметры:

| Параметр             | По умолчанию | Описание                                                                                                        |
| -------------------- | ------- | -------------------------------------------------------------------------------------------------------------------- |
| jdbc_url             | -       | Строка подключения JDBC к MySQL                                                                                       |
| driver_url           | -       | Путь к JAR-файлу драйвера JDBC. Поддерживаются имя файла, локальный абсолютный путь и HTTP-адрес. Подробности см. в разделе [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md) |
| driver_class         | -       | Имя класса драйвера JDBC                                                                                              |
| user                 | -       | Имя пользователя базы данных                                                                                          |
| password             | -       | Пароль базы данных                                                                                                   |
| database             | -       | Имя базы данных                                                                                                      |
| include_tables       | -       | Имена синхронизируемых таблиц, разделённые запятыми. Если значение не задано, по умолчанию синхронизируются все таблицы |
| offset               | latest  | `latest`: только инкрементальная синхронизация; `initial`: полная и инкрементальная синхронизация                       |
| snapshot_split_size  | 40960 (8096 до 4.1.4)    | Размер фрагмента в строках. При полной синхронизации таблица разделяется на несколько фрагментов для синхронизации |
| snapshot_parallelism | 1       | Степень параллелизма на этапе полной синхронизации, то есть максимальное количество фрагментов, которые одна задача Task может запланировать одновременно |

## Справочник {#reference-manual}

### Оператор загрузки {#load-statement}

<!-- Knowledge type: Syntax reference -->

Синтаксис создания задания синхронизации с автоматическим созданием таблиц:

```sql
CREATE JOB <job_name>
[job_properties]
ON STREAMING
[ COMMENT <comment> ]
FROM MYSQL (
    [source_properties]
)
TO DATABASE <target_db> (
    [target_properties]
)
```

Описание элементов:

| Элемент           | Описание                                             |
| ----------------- | ---------------------------------------------------- |
| job_name          | Имя задания                                          |
| job_properties    | Общие параметры загрузки для задания                 |
| comment           | Комментарий с описанием задания                      |
| source_properties | Параметры источника MySQL                            |
| target_properties | Параметры целевой базы данных Doris                  |

### Параметры настройки целевой базы данных Doris {#doris-target-database-configuration-parameters}

<!-- Knowledge type: Configuration parameters -->

`TO DATABASE` поддерживает следующие параметры:

| Параметр                  | По умолчанию | Описание                                                                                                                                                                                                                                                                                                                       |
| ------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| table.create.properties.* | -       | Свойства таблицы, задаваемые при её создании, например `replication_num`                                                                                                                                                                                                                                                                |
| load.strict_mode          | -       | Включение строгого режима. По умолчанию отключён                                                                                                                                                                                                                                                                                        |
| load.max_filter_ratio     | -       | Максимальная допустимая доля отфильтрованных строк в окне выборки. Должна быть больше или равна 0 и меньше или равна 1. Значение по умолчанию составляет 0, что означает нулевую допустимость ошибок. Окно выборки равно `max_interval * 10`. Если отношение числа строк с ошибками к общему числу строк в окне выборки превышает `load.max_filter_ratio`, периодическое задание приостанавливается и требуется ручное вмешательство для проверки проблемы с качеством данных. |

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: Поддерживает ли синхронизация с автоматическим созданием таблиц таблицы без первичного ключа?**

Нет. В настоящее время синхронизация с автоматическим созданием таблиц поддерживает только таблицы с первичным ключом (Unique Key). При первой синхронизации Doris автоматически создаёт на целевой стороне таблицы с первичным ключом на основе первичных ключей источника.

**Вопрос 2: Будет ли перезаписана целевая таблица, если она уже существует?**

Нет. На этапе автоматического создания таблиц создание пропускается, если целевая таблица уже существует. Вы можете настроить структуру таблицы под свой сценарий.

**Вопрос 3: Как синхронизировать только инкрементальные данные без начальной полной загрузки?**

Задайте для параметра `offset` значение `latest`. Задание пропустит этап полной синхронизации и начнёт чтение непосредственно с последней позиции binlog.

**Вопрос 4: Как выбрать между синхронизацией с автоматическим созданием таблиц и синхронизацией с сопоставлением через SQL?**

- Для зеркальной репликации, автоматического создания таблиц и поддержания соответствия структуры таблиц источнику используйте синхронизацию с автоматическим созданием таблиц.
- Для сопоставления столбцов, фильтрации или преобразования данных используйте [MySQL CDC с сопоставлением через SQL](./continuous-load-mysql-table.md).

**Вопрос 5: Что делать, если создание таблиц завершается ошибкой при развёртывании с одним BE?**

Явно укажите количество реплик 1 в `TO DATABASE`: `"table.create.properties.replication_num" = "1"`.

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->

| Проблема                                 | Возможная причина                                           | Диагностика и решение                                                                                               |
| ---------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Создание задания завершается ошибкой доступа | У текущего пользователя нет права Load или Create        | Предоставьте право Load учётной записи, выполняющей операцию; для автоматического создания таблиц также требуется право Create |
| Медленная полная синхронизация            | Значение `snapshot_parallelism` слишком мало или фрагменты слишком велики | Увеличьте `snapshot_parallelism` до подходящего значения; настройте `snapshot_split_size` с учётом количества строк в таблице |
| Задание приостановлено из-за проблем с качеством данных | Доля строк с ошибками превышает `load.max_filter_ratio` | Проверьте поле `ErrorMsg`, чтобы найти некорректные данные; настройте `load.strict_mode` или `load.max_filter_ratio` |
| Ошибка количества реплик при автоматическом создании таблиц | Используется развёртывание с одним BE, но количество реплик по умолчанию составляет 3 | Задайте `table.create.properties.replication_num = 1` |
| Инкрементальные данные не поступают в Doris | В MySQL не включён binlog или у учётной записи нет права на доступ к binlog | Включите binlog на стороне MySQL и предоставьте учётной записи синхронизации права `REPLICATION SLAVE` и `REPLICATION CLIENT` |
