<!-- Applicable scenario: Pre-deployment check / Environment preparation -->

Потоковая загрузка данных в Doris поддерживает синхронизацию данных из **Amazon Aurora PostgreSQL-Compatible Edition версии 14 или новее**. Перед синхронизацией необходимо включить логическую репликацию в кластере Aurora и предоставить необходимые права. Этот документ предназначен для администраторов баз данных и инженеров данных и содержит полный порядок предварительной настройки.

### Контрольный список предварительных требований {#prerequisite-checklist}

Перед началом настройки убедитесь, что выполнены следующие требования:

| Проверяемый пункт | Требование |
| --- | --- |
| Версия Aurora PostgreSQL | 14 или новее |
| Права на выполнение операций | Права на изменение групп параметров кластера в консоли AWS RDS |
| Права в базе данных | Права на создание пользователей, предоставление прав и создание Publication |
| Окно обслуживания | Допускается перезапуск пишущего экземпляра Aurora (после изменения параметров логической репликации требуется перезапуск) |

### Порядок настройки {#configuration-workflow}

Полный процесс настройки состоит из 5 шагов:

1. Проверить текущее состояние настройки логической репликации
2. Настроить группу параметров кластера
3. Применить группу параметров кластера и перезапустить экземпляр
4. Создать пользователя синхронизации Doris и предоставить права
5. Создать Publication

Если на шаге 1 выяснится, что логическая репликация уже включена, можно сразу перейти к **шагу 4**, чтобы создать пользователя синхронизации.

## Шаг 1: Проверка текущей конфигурации {#step-1-check-the-current-configuration}

<!-- Knowledge type: Procedure -->

**Цель:** Определить, включена ли логическая репликация в кластере Aurora и требуется ли изменение группы параметров.

Подключитесь к пишущему экземпляру Aurora и выполните следующий SQL:

```sql
SHOW rds.logical_replication;
```

Выберите дальнейшее действие в зависимости от возвращённого значения:

| Возвращённое значение | Значение | Дальнейшее действие |
| --- | --- | --- |
| `on` | Логическая репликация включена | Перейдите к [шагу 4: Создание пользователя синхронизации](#step-4-create-the-sync-user) |
| `off` | Логическая репликация не включена | Продолжите с [шага 2: Настройка группы параметров кластера](#step-2-configure-the-cluster-parameter-group) |

## Шаг 2: Настройка группы параметров кластера {#step-2-configure-the-cluster-parameter-group}

<!-- Knowledge type: Configuration parameters -->

**Цель:** Создать группу параметров кластера базы данных с включённой логической репликацией для использования в кластере Aurora.

Порядок действий:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. В левой панели навигации выберите **Группы параметров** и нажмите **Создать группу параметров**.
3. Установите тип **Группа параметров кластера базы данных** и выберите семейство, соответствующее версии Aurora PostgreSQL.
4. Откройте созданную группу параметров кластера для редактирования, найдите `rds.logical_replication` и установите значение `1`:

    ![Настройка WAL в PostgreSQL](/images/next/data-operate/streaming-job/pgwalsetting.png)

5. Нажмите **Сохранить изменения**.

Описание основного параметра:

| Параметр | Рекомендуемое значение | Описание |
| --- | --- | --- |
| `rds.logical_replication` | `1` | Включает логическую репликацию; `0` означает, что она отключена |

## Шаг 3: Применение группы параметров кластера и перезапуск {#step-3-apply-the-cluster-parameter-group-and-restart}

<!-- Knowledge type: Procedure -->

**Цель:** Привязать созданную группу параметров к целевому кластеру Aurora и перезапустить пишущий экземпляр, чтобы настройки вступили в силу.

Порядок действий:

1. В консоли RDS выберите целевой кластер Aurora и нажмите **Изменить**.
2. В поле **Группа параметров кластера базы данных** выберите группу параметров кластера, созданную на шаге 2.
3. Выберите **Применить немедленно**.
4. Перезапустите пишущий экземпляр Aurora, чтобы настройки вступили в силу.

:::caution
Чтобы изменение параметра `rds.logical_replication` вступило в силу, необходимо перезапустить пишущий экземпляр Aurora. Выполняйте эту операцию в часы низкой нагрузки.
:::

## Шаг 4: Создание пользователя синхронизации {#step-4-create-the-sync-user}

<!-- Knowledge type: Procedure -->

**Цель:** Создать отдельную учётную запись для потоковой загрузки данных в Doris и предоставить минимально необходимые права на чтение данных и выполнение репликации.

1. Создайте отдельного пользователя:

    ```sql
    CREATE USER doris_sync PASSWORD '<password>';
    ```

2. Предоставьте права на чтение схемы и таблиц (в примере используется схема `public`; при необходимости замените её):

    ```sql
    GRANT USAGE ON SCHEMA "public" TO doris_sync;
    GRANT SELECT ON ALL TABLES IN SCHEMA "public" TO doris_sync;
    ALTER DEFAULT PRIVILEGES IN SCHEMA "public" GRANT SELECT ON TABLES TO doris_sync;
    ```

3. Предоставьте право на репликацию:

    ```sql
    GRANT rds_replication TO doris_sync;
    ```

Описание прав:

| Право | Назначение |
| --- | --- |
| `USAGE ON SCHEMA` | Разрешает доступ к указанной схеме |
| `SELECT ON ALL TABLES` | Разрешает чтение данных из всех существующих таблиц схемы |
| `ALTER DEFAULT PRIVILEGES ... GRANT SELECT` | Автоматически предоставляет права на чтение таблиц, которые будут созданы в этой схеме позднее |
| `rds_replication` | Роль, необходимая для выполнения логической репликации в Aurora PostgreSQL |

## Шаг 5: Создание Publication {#step-5-create-the-publication}

<!-- Knowledge type: Procedure -->

**Цель:** Создать Publication, на которую будет подписываться Doris.

Выполните следующий SQL:

```sql
CREATE PUBLICATION dbz_publication FOR ALL TABLES;
```

:::caution
В настоящее время Doris поддерживает только Publication с именем `dbz_publication`, причём обязательно требуется `FOR ALL TABLES`. Произвольные имена Publication и выбор только части таблиц пока не поддерживаются.
:::

> **Примечание:** Если пользователь синхронизации обладает правами суперпользователя (например, ролью `rds_superuser`), Doris создаёт Publication автоматически, и выполнять этот шаг вручную не требуется.

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->

**Вопрос 1: `SHOW rds.logical_replication;` возвращает `on`. Что ещё нужно сделать?**

Изменять группу параметров кластера и перезапускать экземпляр не требуется. Начните сразу с [шага 4: Создание пользователя синхронизации](#step-4-create-the-sync-user).

**Вопрос 2: Поддерживается ли Aurora PostgreSQL версии 13 или более ранних версий?**

Нет. Для потоковой загрузки данных в Doris требуется Aurora PostgreSQL версии 14 или новее.

**Вопрос 3: Можно ли использовать Publication с произвольным именем?**

Нет. В настоящее время Doris поддерживает только Publication с именем `dbz_publication` и с указанием `FOR ALL TABLES`.

**Вопрос 4: Обязательно ли использовать учётную запись суперпользователя для синхронизации?**

Нет. Рекомендуется использовать обычного пользователя `doris_sync` и предоставить права, описанные в этом документе. Doris создаёт Publication автоматически только в том случае, если учётная запись обладает правами суперпользователя (например, ролью `rds_superuser`).

## Устранение неполадок {#troubleshooting}

<!-- Knowledge type: Troubleshooting -->
<!-- Applicable scenario: Pre-sync prerequisite check failure -->

| Проблема | Возможная причина | Решение |
| --- | --- | --- |
| `SHOW rds.logical_replication;` по-прежнему возвращает `off` | Новая группа параметров не привязана к кластеру или пишущий экземпляр не был перезапущен | Убедитесь, что в поле **Группа параметров кластера базы данных** выбрана новая группа параметров, и перезапустите пишущий экземпляр |
| Не удаётся создать пользователя или предоставить права | У текущей учётной записи недостаточно прав | Войдите с учётной записью, имеющей права `rds_superuser` или равноценные права, затем выполните операцию |
| `GRANT rds_replication` возвращает ошибку | Версия Aurora слишком старая или кластер не является кластером Aurora PostgreSQL | Обновите Aurora PostgreSQL до версии 14 или новее |
| Ошибка прав доступа при создании Publication | У пользователя `doris_sync` нет права на создание Publication | Используйте учётную запись суперпользователя, чтобы вручную выполнить `CREATE PUBLICATION`, или временно предоставьте необходимые права учётной записи синхронизации |
| При запуске синхронизации Doris сообщает, что `dbz_publication` не найдена | Publication не создана, а у учётной записи синхронизации нет прав суперпользователя, поэтому автоматическое создание невозможно | Вручную выполните `CREATE PUBLICATION dbz_publication FOR ALL TABLES;` из шага 5 |
