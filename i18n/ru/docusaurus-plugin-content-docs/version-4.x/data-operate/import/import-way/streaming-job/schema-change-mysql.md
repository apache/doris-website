<!-- Applicable scenario: Upstream schema changes during MySQL Auto Table Creation Sync -->

Синхронизация изменений схемы MySQL автоматически применяет в Doris изменения столбцов в исходной базе данных MySQL во время непрерывной загрузки. Эта возможность доступна только для [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md). Она не поддерживается для [MySQL CDC с сопоставлением SQL](./continuous-load-mysql-table.md).

:::tip

Синхронизация изменений схемы MySQL поддерживается начиная с Doris 4.1.4.

:::

## Поддерживаемые изменения схемы {#supported-schema-changes}

| Операция MySQL | Поведение Doris |
| --- | --- |
| `ADD COLUMN` | Добавляет столбец с тем же именем и типом, определённым [сопоставлением типов данных MySQL](./data-type-mapping-mysql.md), и копирует комментарий к столбцу. Ограничения DEFAULT и `NOT NULL` не копируются, а ранее загруженные строки не заполняются значениями нового столбца. Для последующих строк используются фактические значения, записанные MySQL в binlog. |
| `DROP COLUMN` | Удаляет столбец с тем же именем. |

## Особенности использования {#considerations}

- Если добавляемый столбец уже существует или удаляемый столбец отсутствует, Doris пропускает операцию, чтобы повторная попытка не привела к сбою задания.
- Позиции столбцов, заданные с помощью `FIRST` и `AFTER`, не синхронизируются с Doris. Новые столбцы добавляются после существующих столбцов Doris.
- Операции `CHANGE COLUMN`, `MODIFY COLUMN`, `RENAME COLUMN`, изменения DEFAULT и ограничения `NULL` / `NOT NULL` не синхронизируются автоматически. Перед выполнением этих операций приостановите задание непрерывной загрузки, вручную измените целевую таблицу Doris, убедитесь в совместимости обеих схем и затем возобновите задание.
- Изменения первичного ключа, индексов, разделов, имени таблицы и другие изменения схемы на уровне таблицы не синхронизируются автоматически.
- При синхронизации с автоматическим созданием таблиц синхронизация изменений схемы включена по умолчанию. В Doris 4.1 нет свойства SQL для её отключения. Табличная функция `cdc_stream()` (синхронизация с сопоставлением SQL) отключает синхронизацию изменений схемы на уровне реализации.
