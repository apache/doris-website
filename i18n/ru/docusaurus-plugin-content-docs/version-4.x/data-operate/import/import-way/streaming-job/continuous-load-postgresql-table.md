Синхронизация с сопоставлением столбцов через SQL реализуется с помощью Job + [CDC Stream TVF](../../../../sql-manual/sql-functions/table-valued-functions/cdc-stream.md). Данные записываются в существующую таблицу Doris (`INSERT INTO tbl SELECT * FROM cdc_stream(...)`). SQL в Doris позволяет задавать сопоставление столбцов, фильтрацию и преобразование данных, гарантируя при этом семантику exactly-once. Такой подход подходит для сценариев синхронизации в реальном времени, в которых данные необходимо обработать перед записью.

Используя возможности чтения [Flink CDC](https://github.com/apache/flink-cdc), Doris считывает журналы изменений (WAL) из PostgreSQL и выполняет полную + инкрементальную синхронизацию исходной таблицы с целевой. Если вы хотите, чтобы Doris автоматически создавала целевые таблицы и синхронизировала группы таблиц на уровне базы данных, см. [PostgreSQL CDC с автоматическим созданием таблиц](./continuous-load-postgresql-database.md).

### Сценарии использования {#use-cases}

-   Загрузка отдельной таблицы в хранилище данных в реальном времени, когда перед записью требуется отбор столбцов, фильтрация или преобразование с помощью выражений.
-   Целевая таблица Doris уже существует, и вы хотите явно задавать сопоставление полей с помощью SQL.
-   Высокие требования к согласованности данных, для которых необходима семантика exactly-once.

### Предварительные требования {#prerequisites}

Перед созданием задания убедитесь в следующем:

1. На стороне PostgreSQL включена логическая репликация. Подробнее см. в [руководстве по настройке](./continuous-load-overview.md).
2. У текущего пользователя есть право `Load`.
3. Исходная таблица имеет первичный ключ (в настоящее время поддерживается синхронизация только таблиц с первичным ключом).
4. Целевая таблица заранее создана в Doris, и её схема совместима с SQL-запросом, задающим сопоставление.

### Примечания {#notes}

-   Поддерживается семантика exactly-once.
-   В настоящее время поддерживается синхронизация только таблиц с первичным ключом.
-   Требуется право `Load`.
-   На стороне PostgreSQL должна быть включена логическая репликация. См. [руководство по настройке](./continuous-load-overview.md).

## Быстрый старт {#quick-start}

Общий процесс состоит из двух шагов: создание задания непрерывной загрузки и проверка его состояния.

### Шаг 1: создание задания загрузки {#step-1-create-the-load-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки, которое синхронизирует `public.source_table` из PostgreSQL с `db1.tbl1` в Doris:

```sql
CREATE JOB pg_single_sync
ON STREAMING
DO
INSERT INTO db1.tbl1
SELECT * FROM cdc_stream(
    "type" = "postgres",
    "jdbc_url" = "jdbc:postgresql://127.0.0.1:5432/postgres",
    "driver_url" = "postgresql-42.5.1.jar",
    "driver_class" = "org.postgresql.Driver",
    "user" = "postgres",
    "password" = "postgres",
    "database" = "postgres",
    "schema" = "public",
    "table" = "source_table",
    "offset" = "initial"
)
```

### Шаг 2: проверка состояния загрузки {#step-2-check-the-load-status}

Используйте табличную функцию `jobs`, чтобы проверить состояние выполнения заданий типа Streaming:

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING";
```

Другие распространённые операции (приостановка, возобновление, удаление, просмотр задач и так далее) описаны в [обзоре непрерывной загрузки](./continuous-load-overview.md).

### Параметры источника данных {#data-source-parameters}

Параметры источника данных задаются через TVF `cdc_stream(...)`. Они описывают таблицу PostgreSQL для синхронизации и определяют поведение при чтении.

| Параметр             | По умолчанию | Описание                                                                                                                                                       |
| -------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| type                 | -            | Тип источника данных. Укажите `postgres`.                                                                                                                       |
| jdbc_url             | -            | Строка подключения JDBC к PostgreSQL.                                                                                                                           |
| driver_url           | -            | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, абсолютный локальный путь или HTTP URL. Подробнее см. в [обзоре JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md). |
| driver_class         | -            | Имя класса драйвера JDBC.                                                                                                                                       |
| user                 | -            | Имя пользователя базы данных.                                                                                                                                  |
| password             | -            | Пароль базы данных.                                                                                                                                            |
| database             | -            | Имя базы данных.                                                                                                                                               |
| schema               | -            | Имя схемы.                                                                                                                                                     |
| table                | -            | Имя таблицы для синхронизации.                                                                                                                                  |
| offset               | latest       | `latest`: только инкрементальная синхронизация. `initial`: полная + инкрементальная синхронизация.                                                                 |
| snapshot_split_size  | 40960 (8096 до 4.1.4) | Размер фрагмента в строках. При полной синхронизации таблица разделяется на несколько фрагментов для синхронизации.                                               |
| snapshot_parallelism | 1            | Параллелизм на этапе полной синхронизации, то есть максимальное число фрагментов, планируемых для каждого Task.                                                   |

### Параметры настройки загрузки {#load-configuration-parameters}

Параметры настройки загрузки задаются через `job_properties` задания. Они управляют поведением загрузки и переменными сеанса.

| Параметр | По умолчанию | Описание                                                                                                                                                                       |
| -------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| session.* | Нет         | Все переменные сеанса можно настроить в `job_properties`. Переменные, связанные с загрузкой, описаны в разделе [Insert Into Select](../../../../data-operate/import/import-way/insert-into-manual.md#import-configuration-parameters). |

Дополнительные общие параметры (например, `max_interval`) описаны в разделе [Общие параметры](./continuous-load-overview.md#common-parameters) обзора непрерывной загрузки.
