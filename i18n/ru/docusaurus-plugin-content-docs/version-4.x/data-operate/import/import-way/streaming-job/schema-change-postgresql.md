Синхронизация изменений схемы PostgreSQL автоматически применяет изменения столбцов в исходной базе PostgreSQL к Doris во время непрерывной загрузки. Эта возможность доступна только для [PostgreSQL CDC с автоматическим созданием таблиц](./continuous-load-postgresql-database.md). Для [PostgreSQL CDC с сопоставлением SQL](./continuous-load-postgresql-table.md) она не поддерживается.

:::tip

Синхронизация изменений схемы PostgreSQL поддерживается начиная с Doris 4.1.0.

:::

## Поддерживаемые изменения схемы {#supported-schema-changes}

| Операция PostgreSQL | Поведение Doris |
| --- | --- |
| `ADD COLUMN` | Добавляет столбец с тем же именем и типом, определяемым [сопоставлением типов данных PostgreSQL](./data-type-mapping-postgresql.md). Ограничения DEFAULT и `NOT NULL` не копируются, а существующие строки не заполняются значениями нового столбца. Для последующих строк используются фактические значения, записанные PostgreSQL в WAL. |
| `DROP COLUMN` | Удаляет столбец с тем же именем. |

## Особенности использования {#considerations}

- Изменение схемы PostgreSQL не передаётся сразу после выполнения DDL. Doris обнаруживает и применяет новую схему после следующей операции INSERT, UPDATE или DELETE в изменённой таблице.
- Автоматическая синхронизация изменений схемы не поддерживается на этапе полного снимка. Изменяйте схему в исходной базе после завершения полного снимка и перехода задания к инкрементальной обработке.
- Если добавляемый столбец уже существует или удаляемый столбец отсутствует, Doris пропускает операцию, чтобы повторная попытка не приводила к сбою задания.
- Если одно изменение схемы одновременно добавляет и удаляет столбцы, Doris рассматривает его как возможное переименование столбца и не изменяет целевую таблицу автоматически. Это предотвращает случайную потерю данных.
- Переименование столбцов, изменение типов столбцов, изменения DEFAULT и ограничений `NULL` / `NOT NULL` не синхронизируются автоматически. Приостановите задание непрерывной загрузки, вручную измените целевую таблицу Doris, убедитесь в совместимости обеих схем, а затем возобновите задание.
- При синхронизации с автоматическим созданием таблиц синхронизация изменений схемы включена по умолчанию. В Doris 4.1 нет свойства SQL для её отключения. Табличная функция `cdc_stream()` (синхронизация с сопоставлением SQL) отключает синхронизацию изменений схемы на внутреннем уровне.

:::caution Изменение поведения (4.1.4)

Начиная с версии 4.1.4, изменения схемы PostgreSQL обнаруживаются на основе событий Relation:

- Распознаются только `ADD COLUMN` и `DROP COLUMN`.
- Изменение, которое одновременно добавляет и удаляет столбцы (возможно, это `RENAME`), пропускается, а целевая таблица остаётся без изменений.
- Изменения типов столбцов пропускаются.
- Добавленный столбец **больше не наследует значение `DEFAULT` исходного столбца**.
- Эта возможность доступна только при синхронизации с автоматическим созданием таблиц (at-least-once). При сопоставлении SQL (TVF / exactly-once) она не поддерживается.

:::
