Синхронизация с автоматическим созданием таблиц реализована с помощью встроенной DDL-команды `FROM POSTGRES (...) TO DATABASE (...)`. **Целевой объект представляет собой контейнер базы данных Doris, а таблицы на стороне получателя Doris создаёт автоматически.** С помощью `include_tables` можно задать синхронизацию одной таблицы, нескольких таблиц или всех таблиц. При первой синхронизации Doris автоматически создаёт таблицы с первичными ключами на стороне получателя и поддерживает соответствие их первичных ключей ключам источника. Этот подход подходит для зеркальной репликации, когда обработка данных с помощью SQL не требуется, а схемы таблиц на стороне получателя должны автоматически следовать схемам источника.

Благодаря интеграции с [Flink CDC](https://github.com/apache/flink-cdc) Doris читает журналы изменений PostgreSQL и непрерывно записывает полные данные и инкрементальные изменения группы таблиц в Doris через Stream Load. Если во время синхронизации требуется сопоставлять столбцы, фильтровать или преобразовывать данные, см. [PostgreSQL CDC с сопоставлением через SQL](./continuous-load-postgresql-table.md).

### Сценарии использования {#use-cases}

-   Зеркальная репликация всей базы данных PostgreSQL или нескольких таблиц в Doris
-   Поддержание соответствия схем таблиц получателя схемам источника без ручного создания таблиц
-   Отсутствие необходимости в отборе столбцов, фильтрации или преобразовании данных в конвейере синхронизации
-   Необходимость как полной начальной загрузки, так и непрерывного захвата инкрементальных изменений

### Примечания {#notes}

1.  В настоящее время гарантируется только семантика at-least-once.
2.  В настоящее время поддерживается только синхронизация таблиц с первичным ключом.
3.  Требуется привилегия Load. Если таблица на стороне получателя не существует, также требуется привилегия Create.
4.  При автоматическом создании таблиц уже существующая целевая таблица пропускается, поэтому пользователи могут настраивать таблицы под разные сценарии.

## Быстрый старт {#quick-start}

<!-- Knowledge type: Operating procedure -->

Выполните следующие шаги, чтобы создать задание синхронизации PostgreSQL с автоматическим созданием таблиц и проверить его состояние.

### Шаг 1: создание задания загрузки {#step-1-create-a-load-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки:

```sql
CREATE JOB test_postgres_job
ON STREAMING
FROM POSTGRES (
    "jdbc_url" = "jdbc:postgresql://127.0.0.1:5432/postgres",
    "driver_url" = "postgresql-42.5.1.jar",
    "driver_class" = "org.postgresql.Driver",
    "user" = "postgres",
    "password" = "postgres",
    "database" = "postgres",
    "schema" = "public",
    "include_tables" = "test_tbls",
    "offset" = "latest"
)
TO DATABASE target_test_db (
  "table.create.properties.replication_num" = "1"  -- Set to 1 for single-BE deployments
)
```

### Шаг 2: проверка состояния загрузки {#step-2-check-load-status}

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING";
```

Другие общие операции (приостановка, возобновление, удаление, просмотр задач и т. д.) описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Справочник параметров {#parameter-reference}

<!-- Knowledge type: Configuration parameters -->

### Параметры источника (сторона PostgreSQL) {#source-parameters-postgresql-side}

Параметры источника PostgreSQL задают подключение JDBC, область синхронизации и способ разбиения полного снимка на фрагменты.

| Параметр             | По умолчанию | Описание                                                                                                                                                                       |
| -------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jdbc_url             | -       | Строка подключения JDBC к PostgreSQL                                                                                                                                               |
| driver_url           | -       | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, локальный абсолютный путь и HTTP URL. Подробнее см. [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md) |
| driver_class         | -       | Имя класса драйвера JDBC                                                                                                                                                           |
| user                 | -       | Имя пользователя базы данных                                                                                                                                                       |
| password             | -       | Пароль базы данных                                                                                                                                                                 |
| database             | -       | Имя базы данных                                                                                                                                                                    |
| schema               | -       | Имя схемы                                                                                                                                                                          |
| include_tables       | -       | Таблицы для синхронизации, разделённые запятыми. Если параметр не задан, по умолчанию синхронизируются все таблицы                                                                     |
| offset               | latest  | latest: только инкрементальная синхронизация; initial: полная и инкрементальная синхронизация                                                                                          |
| snapshot_split_size  | 40960 (8096 до 4.1.4)    | Размер фрагмента (в строках). При полной синхронизации таблица разбивается на несколько фрагментов для синхронизации                                                              |
| snapshot_parallelism | 1       | Параллелизм на этапе полной синхронизации, то есть максимальное число фрагментов, назначаемых одной задаче Task                                                                         |

### Параметры целевой базы данных Doris {#doris-target-database-parameters}

Параметры на стороне получателя управляют свойствами автоматически создаваемых таблиц и стратегией записи через Stream Load.

| Параметр                  | По умолчанию | Описание                                                                                                                                                                                                                                                                                                                                                |
| ------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| table.create.properties.* | -       | Позволяет задавать свойства таблиц при их создании, например replication_num                                                                                                                                                                                                                                                                                 |
| load.strict_mode          | -       | Включать ли строгий режим. По умолчанию отключён                                                                                                                                                                                                                                                                                                             |
| load.max_filter_ratio     | -       | Максимально допустимая доля отфильтрованных строк в окне выборки. Значение должно находиться в диапазоне от 0 до 1 включительно. Значение по умолчанию равно 0, то есть ошибки не допускаются. Окно выборки равно max_interval * 10. Если в пределах окна выборки отношение числа ошибочных строк к общему числу строк превышает max_filter_ratio, регулярное задание приостанавливается, и для проверки проблем с качеством данных требуется вмешательство пользователя. |

## Справочная информация {#reference}

<!-- Knowledge type: Syntax reference -->

### Синтаксис команды загрузки {#load-command-syntax}

Синтаксис создания задания синхронизации с автоматическим созданием таблиц:

```sql
CREATE JOB <job_name>
[job_properties]
ON STREAMING
[ COMMENT <comment> ]
FROM POSTGRES (
    [source_properties]
)
TO DATABASE <target_db> (
    [target_properties]
)
```

Описание элементов команды приведено ниже:

| Элемент           | Описание                                          |
| ----------------- | ------------------------------------------------- |
| job_name          | Имя задания                                       |
| job_properties    | Общие параметры загрузки для задания               |
| comment           | Комментарий с описанием задания                    |
| source_properties | Параметры источника PostgreSQL                     |
| target_properties | Параметры целевой базы данных Doris                |

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: Frequently asked questions -->

**Вопрос 1: как выбрать между синхронизацией с автоматическим созданием таблиц и синхронизацией с сопоставлением через SQL?**

-   Если требуется зеркальная репликация и автоматическое создание таблиц без отбора столбцов и преобразований, используйте синхронизацию с автоматическим созданием таблиц.
-   Если в конвейере синхронизации требуется сопоставлять столбцы, фильтровать или преобразовывать данные, используйте [PostgreSQL CDC с сопоставлением через SQL](./continuous-load-postgresql-table.md).

**Вопрос 2: поддерживаются ли таблицы без первичного ключа?**

В настоящее время поддерживается только синхронизация таблиц с первичным ключом. Таблицы без первичного ключа пока не поддерживаются.

**Вопрос 3: что делать, если не удаётся создать таблицу в развёртывании с одним BE?**

Необходимо явно задать `"table.create.properties.replication_num" = "1"` в предложении `TO DATABASE`, чтобы избежать несоответствия между числом реплик по умолчанию и числом доступных BE.

**Вопрос 4: будет ли перезаписана целевая таблица, если она уже существует?**

Нет. На этапе автоматического создания уже существующие целевые таблицы пропускаются. При необходимости можно заранее настроить схему таблицы.

**Вопрос 5: как синхронизировать только инкрементальные данные и пропустить этап полной синхронизации?**

Установите для `offset` значение `latest`. Задание будет получать только последние инкрементальные изменения и больше не будет выполнять полную начальную загрузку.
