Синхронизация с SQL Mapping реализована с помощью Job + [CDC Stream TVF](../../../../sql-manual/sql-functions/table-valued-functions/cdc-stream.md) и выполняется в **существующую** таблицу Doris (`INSERT INTO tbl SELECT * FROM cdc_stream(...)`). Возможности Doris SQL позволяют выполнять сопоставление столбцов, фильтрацию и преобразование данных в процессе синхронизации с гарантией семантики exactly-once. Этот подход подходит для сценариев синхронизации в реальном времени, требующих обработки данных.

Благодаря интеграции механизмов чтения [Flink CDC](https://github.com/apache/flink-cdc) Doris считывает журнал изменений (Binlog) из MySQL и выполняет **полную и инкрементальную** синхронизацию исходной таблицы с целевой. Если вы хотите, чтобы Doris автоматически создавал целевые таблицы и синхронизировал группу таблиц на уровне базы данных, см. [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md).

### Сценарии применения {#applicable-scenarios}

- Непрерывная синхронизация одной таблицы MySQL с Doris, когда схема целевой таблицы уже спланирована
- Необходимость исключать ненужные столбцы, сопоставлять столбцы, переименовывать поля или преобразовывать данные в процессе синхронизации
- Интеграция данных в реальном времени, требующая сквозной семантики exactly-once

### Предварительные требования {#prerequisites}

| Пункт | Описание |
| ------ | ---- |
| Версия Doris | 4.1.0 и выше |
| Тип таблицы | В настоящее время в качестве целевых поддерживаются только **таблицы с первичным ключом** |
| Права пользователя | Требуется право `Load` |
| Конфигурация MySQL | На стороне MySQL должен быть включён Binlog. См. [Руководство по настройке](./continuous-load-overview.md) |
| Гарантии семантики | Поддерживается семантика exactly-once |

## Быстрый старт {#quick-start}

Следующий минимальный рабочий пример показывает весь процесс: создание задания и последующую проверку его состояния.

### Шаг 1: Создание задания загрузки {#step-1-create-the-import-job}

Используйте [CREATE STREAMING JOB](../../../../sql-manual/sql-statements/job/CREATE-STREAMING-JOB.md), чтобы создать задание непрерывной загрузки:

```sql
CREATE JOB mysql_single_sync
ON STREAMING
DO
INSERT INTO db1.tbl1
SELECT * FROM cdc_stream(
    "type" = "mysql",
    "jdbc_url" = "jdbc:mysql://127.0.0.1:3306",
    "driver_url" = "mysql-connector-java-8.0.25.jar",
    "driver_class" = "com.mysql.cj.jdbc.Driver",
    "user" = "root",
    "password" = "123456",
    "database" = "source_db",
    "table" = "source_table",
    "offset" = "initial"
)
```

### Шаг 2: Проверка состояния загрузки {#step-2-check-the-import-status}

```sql
select * from jobs("type"="insert") where ExecuteType = "STREAMING";
```

Другие общие операции (приостановка, возобновление, удаление, просмотр задач и т. д.) описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md).

## Справочник параметров {#parameter-reference}

### Параметры источника данных {#data-source-parameters}

CDC Stream TVF поддерживает следующие параметры источника данных MySQL:

| Параметр              | По умолчанию | Описание                                                                                                                                     |
| --------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| type                  | -       | Тип источника данных. Укажите `mysql`                                                                                                                |
| jdbc_url              | -       | Строка подключения JDBC к MySQL                                                                                                                    |
| driver_url            | -       | Путь к jar-файлу драйвера JDBC. Поддерживаются имя файла, абсолютный локальный путь и HTTP URL. Подробнее см. [Обзор JDBC Catalog](../../../../lakehouse/catalogs/jdbc-catalog-overview.md) |
| driver_class          | -       | Имя класса драйвера JDBC                                                                                                                          |
| user                  | -       | Имя пользователя базы данных                                                                                                                               |
| password              | -       | Пароль базы данных                                                                                                                               |
| database              | -       | Имя базы данных                                                                                                                                   |
| table                 | -       | Имя таблицы для синхронизации                                                                                                                       |
| offset                | latest  | `latest`: только инкрементальная синхронизация; `initial`: полная и инкрементальная синхронизация                                                                             |
| snapshot_split_size   | 40960 (8096 до 4.1.4)    | Размер сегмента (в строках). При полной синхронизации таблица разбивается на несколько сегментов для синхронизации                                              |
| snapshot_parallelism  | 1       | Степень параллелизма на этапе полной синхронизации, то есть максимальное число сегментов, назначаемых на каждый Task                                                |

### Параметры настройки загрузки {#import-configuration-parameters}

| Параметр | По умолчанию | Описание                                                                                                                                                                  |
| --------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| session.* | Нет    | Все переменные сеанса можно настроить в `job_properties`. Переменные загрузки описаны в разделе [Insert Into Select](../../../../data-operate/import/import-way/insert-into-manual.md#import-configuration-parameters) |

Другие общие параметры (например, `max_interval`) описаны в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md#common-parameters).

## Часто задаваемые вопросы {#faq}

**Вопрос 1: Чем синхронизация с SQL Mapping отличается от синхронизации с автоматическим созданием таблиц?**

- Синхронизация с SQL Mapping: целевая таблица Doris должна быть **создана заранее**. Поддерживает сопоставление столбцов и преобразование данных, подходит для сценариев, требующих детальной обработки.
- Синхронизация с автоматическим созданием таблиц: Doris **автоматически создаёт** целевые таблицы и синхронизирует их совместно на уровне базы данных. Подробнее см. [MySQL CDC с автоматическим созданием таблиц](./continuous-load-mysql-database.md).

**Вопрос 2: Можно ли использовать таблицы без первичного ключа в качестве целевых?**

В настоящее время в качестве целевых поддерживаются **только таблицы с первичным ключом**.

**Вопрос 3: Как синхронизировать только инкрементальные данные без полной загрузки исторических данных?**

Установите для параметра `offset` значение `latest`. Задание пропустит этап полной синхронизации и будет синхронизировать только инкрементальные данные из Binlog.

**Вопрос 4: Как оптимизировать полную синхронизацию, если она выполняется слишком медленно?**

Чтобы повысить пропускную способность на этапе полной синхронизации, можно настроить следующие два параметра:

- `snapshot_split_size`: увеличьте число строк в сегменте.
- `snapshot_parallelism`: увеличьте число сегментов, параллельно назначаемых на каждый Task.
