В таблице ниже показано, как каждый тип столбца вышестоящего MySQL сопоставляется с типом столбца Doris. Существует единое сопоставление, общее для обоих методов синхронизации; различие заключается только в том, кто создает целевую таблицу:

- **Синхронизация с автоматическим созданием таблицы**: Doris считывает схему вышестоящего источника и автоматически создает целевую таблицу с указанными типами столбцов Doris.
- **Синхронизация с отображением SQL**: вы самостоятельно создаете целевую таблицу, используя совместимый тип Doris для каждого столбца.

В обоих случаях значения записываются согласно одному и тому же сопоставлению. Сведения о неподдерживаемых типах см. в разделе [Ограничения](./continuous-load-overview.md#limitations).

## Нормализация параметров JDBC URL {#jdbc-url-parameter-normalization}

При создании Streaming Job с источником данных MySQL (или использовании табличной функции `cdc_stream()`) Doris автоматически добавляет следующие параметры в `jdbc_url`, если они не заданы явно:

| Параметр | Добавляемое значение | Эффект |
| --- | --- | --- |
| `tinyInt1isBit` | `false` | `TINYINT(1)` считывается как `TINYINT` (`1` / `0`), а не как `BOOLEAN` (`true` / `false`) |
| `yearIsDateType` | `false` | `YEAR` считывается как целочисленный год, а не как дата |
| `useUnicode` | `true` | Используется кодировка Unicode |
| `characterEncoding` | `utf-8` | В качестве набора символов используется UTF-8 |

Если какой-либо из этих параметров явно задан в `jdbc_url`, Doris сохраняет указанное вами значение и не переопределяет его. `jdbc_url` для PostgreSQL не нормализуется.

:::caution Влияние обновления

Чтобы считывать `TINYINT(1)` как `BOOLEAN` или `YEAR` как дату, явно задайте в `jdbc_url` соответственно `tinyInt1isBit=true` или `yearIsDateType=true`.

:::

## От MySQL к Doris {#mysql-to-doris}

| Тип MySQL | Тип Doris | Примечания |
| --- | --- | --- |
| `BOOLEAN` / `TINYINT(1)` | `TINYINT` | Сопоставляется с `TINYINT` (значения `1` / `0`). Причину см. в разделе [Нормализация параметров JDBC URL](#jdbc-url-parameter-normalization) |
| `TINYINT` | `TINYINT` | `UNSIGNED` → `SMALLINT` |
| `SMALLINT` | `SMALLINT` | `UNSIGNED` → `INT` |
| `MEDIUMINT` | `INT` | `UNSIGNED` → `INT` |
| `INT` | `INT` | `UNSIGNED` → `BIGINT` |
| `BIGINT` | `BIGINT` | `UNSIGNED` → `LARGEINT` |
| `YEAR` | `SMALLINT` | Считывается как целочисленный год, а не как дата; нулевой год MySQL (`0000`) сохраняется как `0` |
| `FLOAT` | `FLOAT` | |
| `DOUBLE` | `DOUBLE` | |
| `DECIMAL(p,s)` | `DECIMAL(p,s)` | При очень высокой точности используется `STRING` |
| `DATE` | `DATE` | |
| `DATETIME` | `DATETIME(s)` | Микросекундная точность (0–6) сохраняется |
| `TIMESTAMP` | `DATETIME(s)` | Нормализуется по часовому поясу сервера |
| `TIME` | `STRING` | Сериализуется в строку, например `12:34:56.000000` |
| `CHAR` | `CHAR` | |
| `VARCHAR` | `VARCHAR` | |
| `TINYTEXT` / `TEXT` / `MEDIUMTEXT` / `LONGTEXT` | `STRING` | |
| `BINARY` / `VARBINARY` / `TINYBLOB` / `BLOB` / `MEDIUMBLOB` / `LONGBLOB` | `STRING` | Строка в кодировке Base64 |
| `BIT(1)` | `BOOLEAN` | |
| `BIT(n>1)` | `STRING` | Строка в кодировке Base64 |
| `JSON` | `STRING` | Хранится как текст JSON |
| `ENUM` | `STRING` | Преобразуется в значение метки |
| `SET` | `STRING` | Преобразуется в список меток, разделенных запятыми |
| Пространственные типы (`GEOMETRY`, `POINT`, …) и другие типы | Не поддерживается | Автоматическое создание таблицы завершается ошибкой для таблиц с такими столбцами; используйте синхронизацию с отображением SQL (выполните приведение в `SELECT`) или исключите столбец |
