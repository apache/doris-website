OceanBase CDC с автоматическим созданием таблиц использует `FROM OCEANBASE (...) TO DATABASE (...)`. Doris получает данные для полной и инкрементальной синхронизации через службу OBBinlog и автоматически создаёт таблицы Doris с моделью Unique Key на основе схем источника. Используйте `include_tables` для синхронизации одной или нескольких таблиц либо всех таблиц базы данных.

:::caution Экспериментальная функция

Непрерывная загрузка через OceanBase CDC доступна как экспериментальная функция начиная с Doris 4.1.4. В настоящее время поддерживаются только режим совместимости OceanBase с MySQL и синхронизация с автоматическим созданием таблиц. Режим совместимости с Oracle и SQL Mapping Sync не поддерживаются.

:::

### Сценарии использования {#applicable-scenarios}

- Зеркалирование группы таблиц OceanBase или всей базы данных в Doris.
- Автоматическое создание целевых таблиц и первичных ключей в Doris на основе схем источника.
- Первоначальная полная загрузка с последующей непрерывной синхронизацией изменений.
- Переименование целевых таблиц или исключение столбцов без выражений SQL, фильтрации строк и преобразований данных.

### Возможности и ограничения {#capabilities-and-limitations}

| Пункт | Описание |
| --- | --- |
| Режим совместимости | Только режим совместимости OceanBase с MySQL |
| Способ синхронизации | Только синхронизация с автоматическим созданием таблиц; SQL Mapping Sync не поддерживается |
| Гарантии согласованности | At-least-once |
| Тип таблицы | Исходные таблицы должны иметь первичные ключи; автоматически создаваемые таблицы Doris используют модель Unique Key |
| Права доступа | Требуется право Load; если целевая таблица не существует, также требуется право Create |
| Изменение схемы | Синхронизируются `ADD COLUMN` и `DROP COLUMN`; см. [Синхронизация изменений схемы](./schema-change-oceanbase.md) |
| Типы данных | Используется преобразование типов, совместимое с MySQL; см. [Сопоставление типов данных](./data-type-mapping-oceanbase.md) |

## Предварительные требования {#prerequisites}

Перед созданием задания убедитесь в следующем:

1. OceanBase работает в режиме совместимости с MySQL. При создании задания Doris проверяет режим, выполняя `SHOW VARIABLES LIKE 'ob_compatibility_mode'`.
2. Служба OBBinlog развёрнута и доступна. Выполнение `SHOW MASTER STATUS` через её точку подключения по протоколу MySQL возвращает корректные имя файла binlog и позицию.
3. Doris FE, BE и CDC Client имеют доступ к службе OBBinlog.
4. Доступен совместимый драйвер MySQL Connector/J, а `jdbc_url` начинается с `jdbc:mysql://`.
5. Учётная запись источника имеет права на чтение таблиц, схем и binlog в области синхронизации.
6. Каждая исходная таблица, подлежащая синхронизации, имеет первичный ключ.

## Быстрый старт {#quick-start}

### Шаг 1: Создайте задание загрузки {#step-1-create-a-load-job}

Следующий пример синхронизирует таблицы `users` и `orders` из базы данных `source_db`:

```sql
CREATE JOB oceanbase_db_sync
ON STREAMING
FROM OCEANBASE (
    "jdbc_url" = "jdbc:mysql://127.0.0.1:2883",
    "driver_url" = "mysql-connector-j-8.4.0.jar",
    "driver_class" = "com.mysql.cj.jdbc.Driver",
    "user" = "root@test",
    "password" = "123456",
    "database" = "source_db",
    "include_tables" = "users,orders",
    "offset" = "initial"
)
TO DATABASE target_db (
    "table.create.properties.replication_num" = "1"
);
```

- `jdbc_url` указывает на порт службы OBBinlog для протокола MySQL. Используйте порт, настроенный в вашем развёртывании.
- `offset = "initial"` сначала загружает существующие строки, а затем непрерывно синхронизирует изменения из binlog.
- Если `include_tables` не указан, синхронизируются все подходящие таблицы в базе данных `database`.
- Для развёртывания с одним BE задайте для `replication_num` значение `1`. В рабочей среде задавайте число реплик с учётом размера кластера.

### Шаг 2: Проверьте состояние загрузки {#step-2-check-load-status}

```sql
SELECT Name, Status, CurrentOffset, ErrorMsg
FROM jobs("type" = "insert")
WHERE Name = "oceanbase_db_sync";
```

При нормальной работе задания `Status` имеет значение `RUNNING`:

```text
+-------------------+---------+-----------------------------------------------+----------+
| Name              | Status  | CurrentOffset                                 | ErrorMsg |
+-------------------+---------+-----------------------------------------------+----------+
| oceanbase_db_sync | RUNNING | {"file":"binlog.000001","pos":"154", ...} | NULL     |
+-------------------+---------+-----------------------------------------------+----------+
```

### Шаг 3: Проверьте инкрементальную синхронизацию {#step-3-verify-incremental-sync}

После выполнения `INSERT`, `UPDATE` или `DELETE` для исходной таблицы OceanBase выполните запрос к соответствующей таблице Doris и убедитесь, что изменение синхронизировано:

```sql
SELECT * FROM target_db.users ORDER BY id;
```

Сведения о приостановке, возобновлении, удалении и запросах Task см. в разделе [Обзор непрерывной загрузки](./continuous-load-overview.md#common-operations).

## Параметры источника данных {#data-source-parameters}

| Параметр | Обязательный | По умолчанию | Описание |
| --- | --- | --- | --- |
| `jdbc_url` | Да | - | Строка подключения JDBC к службе OBBinlog. Должна начинаться с `jdbc:mysql://`. |
| `driver_url` | Да | - | Путь к JAR-файлу драйвера MySQL Connector/J. Поддерживаются имя файла, абсолютный локальный путь или HTTP URL. |
| `driver_class` | Да | - | Класс драйвера MySQL JDBC, например `com.mysql.cj.jdbc.Driver`. |
| `user` | Да | - | Имя пользователя OceanBase. Укажите сведения об арендаторе в формате имени пользователя, требуемом OceanBase. |
| `password` | Да | - | Пароль пользователя OceanBase. |
| `database` | Да | - | Имя базы данных OceanBase. |
| `include_tables` | Нет | - | Имена таблиц для синхронизации через запятую. Если параметр не указан, синхронизируются все таблицы базы данных. |
| `exclude_tables` | Нет | - | Имена таблиц, которые не нужно синхронизировать, через запятую. Этот параметр действует, только если `include_tables` не задан. |
| `table.<table_name>.target_table` | Нет | Имя исходной таблицы | Задаёт имя целевой таблицы Doris для исходной таблицы. |
| `table.<table_name>.exclude_columns` | Нет | - | Исключает неключевые столбцы исходной таблицы, перечисленные через запятую. Каждый столбец должен существовать и не должен входить в первичный ключ. |
| `offset` | Нет | `latest` | Начальная позиция. `initial`: полная и инкрементальная синхронизация; `snapshot`: только полная синхронизация; `earliest`: начать с самой ранней доступной позиции binlog; `latest`: синхронизировать только изменения после запуска задания. Также поддерживается точная позиция, например `{"file":"binlog.000001","pos":"154"}`. |
| `snapshot_split_size` | Нет | `40960` | Число строк в каждом фрагменте на этапе полной синхронизации. Должно быть положительным целым числом. |
| `snapshot_parallelism` | Нет | `1` | Максимальное число фрагментов, планируемых к одновременному выполнению одной задачей Task на этапе полной синхронизации. Должно быть положительным целым числом. |
| `skip_snapshot_backfill` | Нет | `true` | Пропускать ли дозагрузку изменений из binlog на этапе создания снимка. Синхронизация с автоматическим созданием таблиц обеспечивает семантику at-least-once. |
| `server_id` | Нет | Генерируется автоматически | Идентификатор сервера для компонента чтения CDC. Поддерживается отдельное значение, например `5400`, или диапазон с включёнными границами, например `5400-5408`. Диапазон должен содержать не менее `snapshot_parallelism` идентификаторов. |
| `ssl_mode` | Нет | `disable` | Режим SSL. Допустимые значения: `disable`, `require` и `verify-ca`. |
| `ssl_rootcert` | Обязателен при определённых условиях | - | Требуется, если `ssl_mode` имеет значение `verify-ca`. Используйте формат `FILE:<file_name>` и предварительно загрузите файл с помощью [CREATE FILE](../../../../sql-manual/sql-statements/security/CREATE-FILE.md). |

Параметры `schema`, `slot_name` и `publication_name` не поддерживаются. Если указан любой из них, создание задания завершается ошибкой.

## Справочное руководство {#reference-manual}

### Оператор загрузки {#load-statement}

```sql
CREATE JOB <job_name>
[job_properties]
ON STREAMING
[COMMENT <comment>]
FROM OCEANBASE (
    [source_properties]
)
TO DATABASE <target_db> (
    [target_properties]
);
```

| Элемент | Описание |
| --- | --- |
| `job_name` | Имя задания. |
| `job_properties` | Общие параметры задания, например `max_interval`. |
| `comment` | Комментарий к заданию. |
| `source_properties` | Параметры источника данных OceanBase. |
| `target_properties` | Параметры целевой базы данных Doris. |

### Параметры целевой базы данных Doris {#doris-target-database-parameters}

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `table.create.properties.*` | - | Добавляет свойства таблицы при её создании в Doris, например `table.create.properties.replication_num`. |
| `load.strict_mode` | `false` | Включать ли строгий режим для Stream Load. |
| `load.max_filter_ratio` | `0` | Максимальная допустимая доля отфильтрованных строк в окне выборки, в диапазоне `[0, 1]`. Если доля превышает это значение, задание приостанавливается. |

## Рекомендации и особенности использования {#considerations-and-best-practices}

- Перед расширением области синхронизации в рабочей среде проверьте подключение к OBBinlog, сопоставление типов и задержку инкрементальной синхронизации на небольшом наборе таблиц.
- Явно задавайте область синхронизации с помощью `include_tables`, чтобы посторонние таблицы, добавленные позже, не включались автоматически.
- Исключайте неподдерживаемые неключевые столбцы с помощью `table.<table_name>.exclude_columns`. Столбцы первичного ключа исключить нельзя.
- Перед внесением неподдерживаемого изменения схемы приостановите задание, внесите совместимое изменение в таблицу Doris, а затем возобновите задание.
- Отслеживайте `CurrentOffset`, `LagBytes` и `ErrorMsg`, чтобы убедиться, что задание продолжает выполняться и не было автоматически приостановлено.

## Часто задаваемые вопросы {#faq}

**Вопрос 1: Поддерживается ли режим совместимости OceanBase с Oracle?**

Нет. При создании задания Doris проверяет `ob_compatibility_mode` и отклоняет любой режим, кроме режима совместимости с MySQL.

**Вопрос 2: Поддерживается ли SQL Mapping Sync?**

Нет. В настоящее время OceanBase поддерживает только синхронизацию с автоматическим созданием таблиц через `FROM OCEANBASE (...) TO DATABASE (...)`.

**Вопрос 3: Как синхронизировать только изменения, происходящие после запуска задания?**

Задайте для `offset` значение `latest`. Строки, существующие до перехода задания в состояние `RUNNING`, не загружаются через снимок.

**Вопрос 4: Перезаписывается ли существующая целевая таблица?**

Нет. При автоматическом создании таблиц существующая целевая таблица пропускается. Убедитесь, что её первичный ключ и типы столбцов совместимы с исходной таблицей.
