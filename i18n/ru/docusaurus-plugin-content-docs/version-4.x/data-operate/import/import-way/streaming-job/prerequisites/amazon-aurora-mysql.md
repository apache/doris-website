Потоковая загрузка данных в Doris поддерживает Amazon Aurora MySQL-Compatible Edition версий **5.6, 5.7 и 8.0.x**. Поскольку в Aurora MySQL Binlog по умолчанию отключён, перед синхронизацией данных необходимо подготовить кластер Aurora: включить и настроить Binlog, создать пользователя для синхронизации и задать срок хранения Binlog.

Этот документ предназначен для пользователей, которые планируют подключить Aurora MySQL как источник для потоковой загрузки данных в Doris. В нём описан полный процесс настройки.

### Контрольный список предварительных требований {#prerequisite-checklist}

Перед подключением к Doris убедитесь, что кластер Aurora соответствует следующим требованиям:

| Проверяемый пункт | Ожидаемое значение | Способ проверки |
| :--- | :--- | :--- |
| Включён ли Binlog | `log_bin = ON` | `SHOW VARIABLES LIKE 'log_bin';` |
| Формат Binlog | `binlog_format = ROW` | `SHOW VARIABLES LIKE 'binlog_format';` |
| Образ строки в Binlog | `binlog_row_image = FULL` | `SHOW VARIABLES LIKE 'binlog_row_image';` |
| Пользователь для синхронизации | Создана отдельная учётная запись с правами репликации | Выполните `SHOW GRANTS FOR ...;` |
| Срок хранения Binlog | Не менее 72 часов | `CALL mysql.rds_show_configuration;` |

Если все требования выполнены, можно сразу переходить к настройке потоковой загрузки данных в Doris. Если какое-либо требование не выполнено, настройте кластер, следуя приведённым ниже инструкциям.

## Шаг 1: Проверка текущей конфигурации Binlog {#step-1-check-the-current-binlog-configuration}

Подключитесь к **экземпляру Aurora для записи** и выполните следующий SQL, чтобы проверить состояние Binlog:

```sql
-- Check if binlog is enabled
SHOW VARIABLES LIKE 'log_bin';

-- Check binlog format
SHOW VARIABLES LIKE 'binlog_format';

-- Check binlog row image
SHOW VARIABLES LIKE 'binlog_row_image';
```

Дальнейшие действия зависят от результатов проверки:

- Если выполнены все три условия (`log_bin = ON`, `binlog_format = ROW` и `binlog_row_image = FULL`), можно **сразу перейти к** [шагу 4: Создание пользователя для синхронизации](#step-4-create-a-sync-user).
- В противном случае перейдите к [шагу 2](#step-2-configure-the-cluster-parameter-group), чтобы включить Binlog через группу параметров кластера.

## Шаг 2: Настройка группы параметров кластера {#step-2-configure-the-cluster-parameter-group}

Aurora MySQL не позволяет изменять параметры напрямую во время работы; их необходимо настраивать через **группу параметров кластера БД (DB Cluster Parameter Group)**.

Порядок действий:

1. Войдите в [консоль AWS RDS](https://console.aws.amazon.com/rds/).
2. На панели навигации слева выберите **Группы параметров** и нажмите **Создать группу параметров**.
3. В качестве типа выберите **Группа параметров кластера БД (DB Cluster Parameter Group)** и укажите семейство версий Aurora MySQL, соответствующее целевому кластеру.
4. Откройте созданную группу параметров кластера для редактирования, найдите `binlog_format` и задайте значение `ROW`:

    ![Настройка формата Binlog в MySQL](/images/next/data-operate/streaming-job/mysql-binlog-setting.png)

5. Найдите `binlog_row_image` и задайте значение `FULL`.
6. Нажмите **Сохранить изменения**.

Основные параметры, которые необходимо изменить:

| Параметр | Рекомендуемое значение | Описание |
| :--- | :--- | :--- |
| `binlog_format` | `ROW` | Для синхронизации CDC требуется журналирование на уровне строк |
| `binlog_row_image` | `FULL` | Обеспечивает запись в Binlog полного образа строки со всеми столбцами |

## Шаг 3: Применение группы параметров кластера и перезапуск {#step-3-apply-the-cluster-parameter-group-and-restart}

Созданную группу параметров необходимо привязать к целевому кластеру, а затем перезапустить экземпляр для записи, чтобы изменения вступили в силу.

1. В консоли RDS выберите целевой кластер Aurora и нажмите **Изменить**.
2. В разделе **Группа параметров кластера БД** выберите группу параметров кластера, созданную на [шаге 2](#step-2-configure-the-cluster-parameter-group).
3. Установите флажок **Применить немедленно**, чтобы сразу применить изменения.
4. Перезапустите **экземпляр Aurora для записи**, чтобы настройки вступили в силу.

:::caution
Для вступления в силу изменения параметра `binlog_format` необходимо перезапустить экземпляр Aurora для записи. Выполняйте эту операцию в период низкой нагрузки.
:::

После перезапуска повторно выполните SQL из [шага 1](#step-1-check-the-current-binlog-configuration) для проверки. Все три параметра должны соответствовать ожидаемым значениям.

## Шаг 4: Создание пользователя для синхронизации {#step-4-create-a-sync-user}

Создайте отдельную учётную запись для потоковой загрузки данных в Doris, чтобы упростить управление правами и аудит.

1. Создайте пользователя:

    ```sql
    CREATE USER 'doris_sync'@'%' IDENTIFIED BY '<password>';
    ```

2. Предоставьте права, необходимые для синхронизации:

    ```sql
    GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'doris_sync'@'%';
    ```

Назначение необходимых прав:

| Право | Назначение |
| :--- | :--- |
| `SELECT` | Чтение данных рабочих таблиц на этапе полной загрузки |
| `REPLICATION SLAVE` | Чтение потока Binlog в качестве клиента репликации |
| `REPLICATION CLIENT` | Запрос метаданных, например позиций в файлах Binlog |

## Шаг 5: Настройка срока хранения Binlog {#step-5-configure-the-binlog-retention-period}

По умолчанию Aurora довольно быстро удаляет старые файлы Binlog, что может помешать возобновлению репликации после прерывания. Рекомендуется задать срок хранения Binlog **не менее 72 часов**, чтобы двоичные журналы оставались доступны при сбоях.

Для настройки используйте хранимую процедуру `mysql.rds_set_configuration`:

```sql
CALL mysql.rds_set_configuration('binlog retention hours', 72);
```

Проверить текущую конфигурацию можно с помощью следующего SQL:

```sql
CALL mysql.rds_show_configuration;
```

:::caution
Если этот параметр не задан или установлен слишком короткий срок хранения, в двоичных журналах могут возникать пропуски, что может помешать Doris возобновить репликацию.
:::

## Часто задаваемые вопросы {#faq}

**Вопрос 1: Почему значение по-прежнему не равно `ROW` после изменения `binlog_format`?**

Ответ: Aurora MySQL не позволяет изменять параметры напрямую во время работы. Необходимо создать и привязать **группу параметров кластера БД (DB Cluster Parameter Group)**, как описано на [шаге 2](#step-2-configure-the-cluster-parameter-group), а затем перезапустить **экземпляр для записи**, чтобы изменение вступило в силу. Изменение группы параметров по умолчанию не даст результата.

**Вопрос 2: Обязательно ли выполнять проверки и настройку на экземпляре для записи?**

Ответ: Да. Binlog формируется только на экземпляре Aurora для записи, поэтому все проверки SQL и создание пользователя для синхронизации следует выполнять на этом экземпляре.

**Вопрос 3: На что влияет слишком большое значение `binlog retention hours`?**

Ответ: Оно увеличивает расход дискового пространства. Рекомендуется выбирать значение с учётом фактического времени, необходимого для восстановления после сбоя, но не менее 72 часов.

## Устранение неполадок {#troubleshooting}

| Признак | Возможная причина | Решение |
| :--- | :--- | :--- |
| Значение `log_bin` по-прежнему равно `OFF` | Пользовательская группа параметров кластера не привязана или экземпляр для записи не был перезапущен | Следуйте инструкциям из [шага 3](#step-3-apply-the-cluster-parameter-group-and-restart), чтобы привязать группу параметров и перезапустить экземпляр для записи |
| Значение `binlog_format` не равно `ROW` | Изменена группа параметров экземпляра вместо группы параметров кластера | Задайте `binlog_format = ROW` в **группе параметров кластера БД (DB Cluster Parameter Group)** |
| При синхронизации Doris сообщает, что файл Binlog не найден | Значение `binlog retention hours` слишком мало, и файл Binlog уже удалён | Используйте `mysql.rds_set_configuration`, чтобы увеличить срок хранения как минимум до 72 часов |
| Ошибка аутентификации пользователя для синхронизации | Ограничение по хосту для пользователя или недостаточные права | Убедитесь, что для пользователя в качестве хоста указан `'%'` или исходящий IP-адрес Doris BE и что предоставлены права `REPLICATION SLAVE, REPLICATION CLIENT` |
