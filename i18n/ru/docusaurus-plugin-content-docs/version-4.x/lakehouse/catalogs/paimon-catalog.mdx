Doris поддерживает доступ к метаданным таблиц Paimon через различные службы метаданных, а также чтение и запись данных Paimon.

[Быстрый старт с Apache Doris и Apache Paimon](../best-practices/doris-paimon.md).

## Сценарии применения {#applicable-scenarios}

| Сценарий     | Описание                                                  |
| ------------ | ------------------------------------------------------------ |
| Ускорение запросов | Используйте распределённый вычислительный движок Doris для прямого доступа к данным Paimon и ускорения запросов. |
| Интеграция данных   | Читайте данные Paimon и записывайте их во внутренние таблицы Doris или выполняйте операции ZeroETL с помощью вычислительного движка Doris. |
| Обратная запись данных    | Используйте SQL в Doris для создания и изменения таблиц Paimon, добавления или перезаписи данных, а также изменения отдельных строк в таблицах с первичным ключом. |

## Настройка Catalog {#configuring-catalog}

### Синтаксис {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = '<paimon_catalog_type>',
    'warehouse' = '<paimon_warehouse>'
    {MetaStoreProperties},
    {StorageProperties},
    {PaimonProperties},
    {CommonProperties}
);
```

* `<paimon_catalog_type>`

  Тип Paimon Catalog. Поддерживаются следующие значения:

  * `filesystem`: значение по умолчанию. Прямой доступ к метаданным, хранящимся в файловой системе.

  * `hms`: использование Hive Metastore в качестве службы метаданных.

  * `dlf`: использование Alibaba Cloud DLF в качестве службы метаданных.

  * `jdbc`: подключение через интерфейс JDBC к реляционной базе данных, используемой в качестве службы метаданных (поддерживается с версии 4.1.0).

* `<paimon_warehouse>`

  Путь к хранилищу Paimon. Этот параметр обязателен, если `<paimon_catalog_type>` имеет значение `filesystem`.

  Путь `warehouse` должен указывать на уровень выше пути `Database`. Например, если путь к таблице: `s3://bucket/path/to/db1/table1`, то `warehouse` должен иметь значение: `s3://bucket/path/to/`.

* `{MetaStoreProperties}`

  В разделе MetaStoreProperties указываются параметры подключения и аутентификации для службы метаданных Metastore. Подробнее см. в разделе [Поддерживаемые службы метаданных].

* `{StorageProperties}`

  В разделе StorageProperties указываются параметры подключения и аутентификации для системы хранения. Подробнее см. в разделе [Поддерживаемые системы хранения].

* `{PaimonProperties}`

  В разделе PaimonProperties указываются свойства, связанные с Paimon.

  При доступе к метаданным Paimon Doris частично использует Paimon Java SDK, поэтому некоторые пользовательские параметры может потребоваться передать в Paimon Java SDK. Для этого можно использовать следующие префиксы:

  ```
  paimon.s3.xxx
  paimon.s3a.xxx
  paimon.fs.xxx
  ```

  Эти параметры автоматически преобразуются и передаются в SDK. Примеры:

  | Входной параметр | Преобразованный параметр для Paimon Java SDK |
  | --- | --- |
  | "paimon.s3.list.version" = "1" | "fs.s3a.list.version" = "1" |
  | "paimon.s3.paging.maximum" = "100" | "fs.s3a.paging.maximum" = "100" |
  | "paimon.fs.s3.read.ahead.buffer.size" = "1" | "fs.s3a.read.ahead.buffer.size" = "1" |
  | "paimon.s3a.replication.factor" = "3" | "fs.s3a.replication.factor" = "3" |

  **Параметры чтения Paimon**

  Doris поддерживает следующие параметры пакетного чтения ограниченного набора данных Paimon. Задайте значения по умолчанию для запросов на уровне Catalog с помощью
  `paimon.table-option.<option-key>` или переопределите их для отдельного обращения к таблице с помощью
  `table@options('<option-key>'='<value>')`. Эти настройки влияют только на чтение через Doris и не изменяют физические
  метаданные таблицы Paimon.

  | Параметр Paimon | Значение по умолчанию в Paimon | Значения, принимаемые Doris | Действие |
  | --- | --- | --- | --- |
  | `read.batch-size` | `1024` | Целое число от `1` до `65536` | Количество строк, запрашиваемых в каждом пакете чтения Paimon JNI. Явно заданное значение сохраняется при открытии модуля чтения в Doris. |
  | `file-reader-async-threshold` | `10 MB` | Размер памяти от `1 MB` до `1 GB` | Порог размера файла, при котором модуль чтения Paimon JNI переключается на асинхронное чтение. |
  | `file-index.read.enabled` | `true` | Логическое значение | Включает отсечение по файловому индексу Paimon при чтении. |
  | `source.split.target-size` | `128 MB` | Положительный размер памяти | Целевой размер, используемый при объединении файлов данных Paimon во фрагменты сканирования Doris. |
  | `source.split.open-file-cost` | `4 MB` | Неотрицательный размер памяти | Оценочная стоимость открытия файла при объединении файлов Paimon во фрагменты. |
  | `scan.manifest.parallelism` | Количество доступных процессоров | Целое число от `1` до `256` | Запрашиваемая степень параллелизма чтения манифестов. Во время выполнения Doris независимо ограничивает её для каждой ветви планирования наименьшим из следующих значений: заданное значение, `256` и количество процессоров, доступных соответствующему FE или BE. |
  | `scan.plan-sort-partition` | `false` | Логическое значение | Сортирует разделы при планировании сканирования Paimon. |

  Например, следующие настройки Catalog переопределяют значения, хранящиеся в физической таблице Paimon, и становятся
  значениями по умолчанию для запросов Doris:

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.table-option.read.batch-size" = "4096",
      "paimon.table-option.file-reader-async-threshold" = "32 MB",
      "paimon.table-option.source.split.target-size" = "64 MB",
      "paimon.table-option.scan.manifest.parallelism" = "1"
  );
  ```

  Запрос может переопределить эти значения по умолчанию, не изменяя Catalog или метаданные таблицы Paimon:

  ```sql
  SELECT *
  FROM paimon_hms.db_name.table_name@options(
      'read.batch-size' = '8192',
      'source.split.target-size' = '32 MB'
  );
  ```

  Каждое обращение к таблице имеет независимый набор параметров. Например, два псевдонима одной таблицы могут использовать разные
  размеры пакетов в одном SQL-операторе:

  ```sql
  SELECT small.id
  FROM paimon_hms.db_name.table_name@options('read.batch-size' = '1') small
  JOIN paimon_hms.db_name.table_name@options('read.batch-size' = '8192') large
    ON small.id = large.id;
  ```

  Приоритет от высшего к низшему:

  ```text
  relation @options > Doris Catalog property > physical Paimon table option > Paimon default
  ```

  Doris проверяет итоговое значение после применения этого порядка приоритетов. Поэтому допустимое значение на уровне Catalog или обращения к таблице может
  заменить недопустимое значение физической таблицы. Если итоговое значение по-прежнему недопустимо, Doris отклоняет запрос до начала
  соответствующего этапа планирования или чтения. Ограничения для манифестов также применяются до планирования манифестов для разделов, подсчёта строк и сбора статистики,
  резервной ветви и системных таблиц.

  Первые пять параметров в таблице не влияют на метаданные и позволяют повторно использовать кэшированную проекцию актуальных разделов.
  `scan.manifest.parallelism` и `scan.plan-sort-partition` влияют на планирование метаданных, поэтому Doris планирует их на основе
  действующего дескриптора таблицы для конкретного обращения. Значения, заданные для отдельного запроса, не изменяют размер глобального для JVM пула выполнения Paimon.

  Doris отклоняет неизвестные или недопустимые свойства `paimon.table-option.*` при выполнении `CREATE CATALOG` и `ALTER CATALOG`.
  `ALTER CATALOG` проверяет всю предлагаемую конфигурацию перед её публикацией, поэтому при неудачном изменении
  предыдущая конфигурация Catalog остаётся действующей. Catalog, сохранённые более ранней версией Doris, по-прежнему можно загрузить, но
  неподдерживаемые или недопустимые устаревшие свойства чтения игнорируются, а не применяются. Их сохранённые значения
  сохраняются для совместимости с образом состояния и журналом изменений.

  Параметры снимка и начальной позиции выбирают контекст обращения к таблице и должны задаваться через `@options`, как описано в разделе
  [Time Travel](#time-travel-with-options); их нельзя задавать как значения по умолчанию для Catalog. Doris также исключает
  `scan.max-splits-per-task`, относящийся к перечислителю источника Flink в Paimon, `scan.fallback-branch`, а также параметры потоковой обработки,
  размещения данных, записи и компакции. Настраивайте Bucket, Primary Key, Partition, Merge Engine и другие физические
  характеристики через свойства таблицы Paimon, в том числе с помощью `CREATE TABLE ... PROPERTIES` в Doris.

  :::info Согласованность в рамках SQL-оператора
  В рамках одного SQL-оператора Doris выполняет привязку схемы, загрузку разделов, подсчёт строк и сбор статистики, планирование системных таблиц
  и сканирование данных на одном снимке Paimon и в рамках одного поколения таблицы. Для снимка или тега, выбранного через
  `@options`, используется схема соответствующей исторической версии, включая вложенные поля `STRUCT`, `MAP` и `ARRAY`.
  Каждое выполнение подготовленного SQL-оператора получает новое состояние, поэтому изменения, зафиксированные между выполнениями,
  становятся видимыми в соответствии с селекторами и настройками кэша нового выполнения.
  :::

  Для безопасной эксплуатации сообщения уровня DEBUG о конфигурации сканера Paimon содержат только размер пакета и количество проецируемых
  полей. Doris не выводит полную карту параметров сканера, которая может содержать учётные данные.
  Значение показателя `PaimonJniAsyncReaderThreadCount` в профиле обновляется раз в секунду по всем сканерам, поэтому может отставать на одну
  секунду. Такая частота сбора не влияет на выполнение или планирование запросов. Освобождение ресурсов модуля чтения и IOManager выполняется
  независимо и может безопасно повторяться после частичного сбоя закрытия.

  **Paimon JNI IOManager**

  > Эта функция поддерживается начиная с версии 4.0.8.

  Для таблиц Paimon с первичным ключом чтение со слиянием через JNI может требовать сортировки и слияния данных из нескольких файлов. Можно включить
  Paimon IOManager, чтобы этот процесс мог выгружать промежуточные данные на локальный диск BE. Это снижает
  нагрузку на память при чтении со слиянием больших объёмов данных.

  | Свойство | Обязательное | Значение по умолчанию | Описание |
  | --- | --- | --- | --- |
  | `paimon.jni.enable_jni_io_manager` | Нет | `false` | Включает Paimon IOManager для чтения через JNI. Остальные свойства IOManager действуют только при значении `true` у этого свойства. |
  | `paimon.jni.io_manager.tmp_dir` | Нет | `<storage_root_path>/paimon_jni_scanner_io_tmp` | Локальные каталоги, используемые Paimon IOManager для временных файлов выгрузки на диск. Несколько каталогов можно разделить запятыми или двоеточиями. Если свойство не задано, Doris создаёт по одному каталогу в каждом пути хранения BE. |
  | `paimon.jni.io_manager.impl_class` | Нет | Стандартная реализация Paimon | Полное имя класса пользовательской реализации `org.apache.paimon.disk.IOManager`. Класс должен быть доступен в classpath Paimon JNI Scanner на каждом BE. |

  В следующем примере включается IOManager, а временные каталоги Doris выбирает из путей хранения BE:

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.jni.enable_jni_io_manager" = "true"
  );
  ```

  Включение IOManager не приводит к выгрузке на диск при каждом чтении со слиянием. Paimon выгружает данные только тогда, когда количество модулей чтения со слиянием
  превышает значение `sort-spill-threshold`. Этот параметр не является динамическим параметром чтения Doris. Если требуется другое поведение выгрузки,
  настройте его в физической таблице Paimon.

  Чтобы использовать отдельные диски для выгрузки, укажите локальные пути, которые существуют или могут быть созданы на каждом BE:

  ```sql
  "paimon.jni.io_manager.tmp_dir" = "/mnt/ssd1/paimon_io:/mnt/ssd2/paimon_io"
  ```

  Doris создаёт IOManager для каждого JNI-сканера и закрывает его вместе со сканером. Убедитесь, что в настроенные
  каталоги разрешена запись и в них достаточно места для параллельных запросов. Если задан класс пользовательской реализации,
  он должен предоставлять открытый конструктор, принимающий `String[]`, открытый конструктор, принимающий
  `String`, или открытый конструктор без аргументов. Ошибка загрузки класса или создания его экземпляра приводит к сбою запроса.

  Эти свойства влияют только на чтение таблиц данных Paimon через JNI. На нативное чтение они не влияют.
  Параметр `paimon.table-option.file-reader-async-threshold` независим: он задаёт порог для асинхронного
  чтения файлов Paimon и не включает IOManager и не настраивает каталоги выгрузки на диск.

* `{CommonProperties}`

  В разделе CommonProperties указываются общие свойства. См. раздел [Общие свойства] в [обзоре Catalog](../catalog-overview.md).
  
## Кэш метаданных {#meta-cache}

Для ускорения доступа к внешним источникам данных Apache Doris кэширует метаданные Paimon. Они включают структуру таблиц (Schema), объекты таблиц, снимки и проекции разделов.

:::tip
В версиях до Doris 4.1.x кэширование метаданных в основном управляется глобально через параметры конфигурации FE. Подробнее см. в разделе [Кэш метаданных](../meta-cache.md).
Начиная с Doris 4.1.x, внешний кэш метаданных Paimon Catalog настраивается с помощью унифицированных ключей `meta.cache.*`.
:::

### Настройка свойств кэша (4.1.x+) {#meta-cache-unified-model}

Для каждого элемента кэша движка используется единый формат ключей конфигурации: `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}`. Ограничения памяти применяются к элементам `table` и `snapshot`, для которых поддерживается оценка использования памяти. См. [Управление памятью внешнего кэша метаданных](../external-meta-cache-memory-management).

| Свойство | Пример | Значение |
|---|---|---|
| `enable` | `true/false` | Включает этот модуль кэша. |
| `ttl-second` | `600`, `0`, `-1` | `0` отключает кэш (вступает в силу немедленно и позволяет видеть актуальные данные); `-1` означает неограниченный срок хранения; другие положительные целые числа задают TTL в секундах с момента доступа. |
| `capacity` | `10000` | Максимальное количество записей кэша. Когда действует `max-weight`, этот параметр не ограничивает количество записей одновременно с ним, но `0` по-прежнему отключает кэш. |
| `max-weight` | `1GB` | Поддерживается с Doris 4.1.4. Необязательное ограничение оценочного объёма удерживаемой памяти. Поддерживается для элементов Paimon `table` и `snapshot`; `0` отключает соответствующий элемент. |

**Условия работы:** Кэш модуля действует, если `enable=true`, `ttl-second != 0`, `capacity > 0`, а `max-weight` отсутствует или не равен `0`.

### Модули кэша {#meta-cache-unified-modules}

Paimon Catalog включает следующие модули кэша:

| Модуль (`<entry>`) | Префикс ключа свойства | Кэшируемое содержимое и влияние |
|---|---|---|
| `schema` | `meta.cache.paimon.schema.` | Кэширует структуру таблицы. Влияет на видимость информации о столбцах таблицы. При отключении для каждого запроса загружается актуальная Schema. |
| `table` | `meta.cache.paimon.table.` | Кэширует объекты метаданных таблиц Paimon. Снижает накладные расходы на загрузку метаданных при планировании запросов. |
| `snapshot` | `meta.cache.paimon.snapshot.` | Кэширует метаданные снимков, поколения схем и проекции разделов. Этот элемент поддерживает `max-weight`. |

### Сопоставление и преобразование устаревших параметров {#meta-cache-mapping}

В версии 4.1.x и более поздних рекомендуется использовать унифицированные ключи. Ниже приведено соответствие между устаревшими свойствами Catalog и унифицированными ключами 4.1.x+:

| Устаревший ключ свойства | Унифицированный ключ 4.1.x+ | Описание |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.paimon.schema.ttl-second` | Срок действия кэша структуры таблицы |

### Рекомендации {#meta-cache-best-practices}

* **Доступ к актуальным данным в реальном времени**: Если каждый запрос должен видеть последние изменения данных или схемы таблиц Paimon, можно установить `ttl-second` для `schema` или `table` в `0`.
  ```sql
  -- Disable table object cache to detect the latest snapshots of Paimon tables
  ALTER CATALOG paimon_ctl SET PROPERTIES ("meta.cache.paimon.table.ttl-second" = "0");
  ```
* **Оптимизация производительности**: Начиная с Doris 4.1.4, успешное изменение свойства Catalog сбрасывает контекст выполнения Catalog и очищает инициализированные элементы всех движков кэша метаданных, к которым этот Catalog направляет обращения. При следующем доступе Doris создаёт их заново с новым контекстом и конфигурацией; выполняющиеся запросы не затрагиваются. Если в Doris включено управление памятью, `CachingCatalog` из SDK Paimon по умолчанию отключён; явно заданная настройка `paimon.cache-enabled` имеет приоритет.

### Наблюдаемость {#meta-cache-unified-observability}

Метрики кэша доступны в системной таблице `information_schema.catalog_meta_cache_statistics`:

```sql
SELECT catalog_name, engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, load_failure_count, last_error
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'paimon_ctl' AND engine_name = 'paimon'
ORDER BY entry_name;
```

См. документацию этой системной таблицы: [catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md).

## Сопоставление типов столбцов {#column-type-mapping}

Полная таблица сопоставления для Doris 4.2, правила точности и неподдерживаемые типы приведены в разделе [Сопоставление типов данных Paimon и Doris](paimon-catalog/doris-type-mapping.md).

Doris сохраняет точное написание имён столбцов верхнего уровня и вложенных полей `STRUCT`, заключённых в кавычки, в обоих вариантах работы JNI-сканера Paimon.
Имена, содержащие разделители, например запятые (`region,code`), знаки решётки (`nested#value`), двоеточия (`colon:name`),
пробелы или символы Unicode, не требуют дополнительного экранирования помимо обычного заключения SQL-идентификаторов в кавычки. При чтении столбцы сопоставляются
без учёта регистра, поэтому запросы к столбцам с именами, содержащими заглавные буквы или смешанный регистр (например, `UserId`),
выполняются обычным образом.

:::info Примечание о версиях

В версиях до 4.0.8 столбцы при чтении определялись по точному совпадению имён, поэтому в таблицах Paimon и Iceberg с именами столбцов в смешанном регистре мог считываться неверный столбец или запрос мог завершаться ошибкой. Это исправлено в 4.0.8.

:::

Начиная с 4.1.5, явные команды `REFRESH TABLE`, `REFRESH DATABASE` и `REFRESH CATALOG` также сбрасывают соответствующие кэши Paimon SDK. После внешнего изменения схемы или удаления и повторного создания таблицы выполните команду обновления для повторной загрузки метаданных. Уже запущенные запросы сохраняют выбранный снимок.

## Операции записи {#write-operations}

Doris может создавать и изменять таблицы Paimon, а также записывать в них данные. Каждая успешная запись фиксируется как снимок
Paimon. Если SQL-оператор завершается ошибкой, Doris не публикует частичный снимок.

### Перед началом работы {#before-you-begin}

Перед записью данных проверьте следующее:

* На всех узлах FE и BE должна работать сборка Doris с поддержкой записи в Paimon. Не выполняйте запись в Paimon во время
  последовательного обновления кластера, пока в нём ещё работают узлы BE со старой версией.
* Учётные данные Catalog должны предоставлять права на обновление metastore, а также на создание, запись, переименование и удаление файлов
  в хранилище. Точный набор прав зависит от metastore и системы хранения.
* Запись доступна только для обычных таблиц данных Paimon. Системные таблицы Paimon и обращения к таблицам с выбором ветви,
  тега, снимка или временной метки доступны только для чтения.

### Поддерживаемые SQL-операции {#supported-sql}

| Операция | Поддержка и примечания |
| --- | --- |
| DDL для баз данных | `CREATE DATABASE` и `DROP DATABASE` |
| DDL для таблиц | `CREATE TABLE`, `CREATE TABLE AS SELECT` и `DROP TABLE` |
| Изменения схемы | Добавление, удаление, переименование, изменение порядка и модификация столбцов |
| Добавление данных | `INSERT INTO ... VALUES` и `INSERT INTO ... SELECT` |
| Перезапись данных | `INSERT OVERWRITE` для всей таблицы, статических и динамических разделов |
| Изменения на уровне строк | `DELETE`, `UPDATE` и `MERGE INTO` для таблиц с первичным ключом с учётом приведённых ниже ограничений |

### Быстрый старт {#quick-start}

В следующем примере создаётся таблица с первичным ключом и в неё записываются данные. Параметры таблицы Paimon задаются в
`PROPERTIES`; не добавляйте предложение Doris `DISTRIBUTE BY`.

```sql
SWITCH paimon_ctl;
CREATE DATABASE IF NOT EXISTS sales;
USE sales;

CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    customer STRING NULL,
    amount DECIMAL(12, 2) NULL,
    status STRING NULL
) ENGINE=paimon
PROPERTIES (
    'primary-key' = 'order_id',
    'bucket' = '2',
    'bucket-key' = 'order_id'
);

INSERT INTO orders VALUES
    (1, 'Alice', 99.90, 'NEW'),
    (2, 'Bob', 35.00, 'NEW');

UPDATE orders
SET status = 'PAID'
WHERE order_id = 1;

DELETE FROM orders
WHERE order_id = 2;

SELECT * FROM orders ORDER BY order_id;
```

Результат:

```text
+----------+----------+--------+--------+
| order_id | customer | amount | status |
+----------+----------+--------+--------+
|        1 | Alice    |  99.90 | PAID   |
+----------+----------+--------+--------+
```

Можно изменить схему таблицы через Doris, а затем продолжить запись с новой схемой:

```sql
ALTER TABLE orders ADD COLUMN note STRING NULL;
ALTER TABLE orders RENAME COLUMN note order_note;
```

### Вставка и перезапись данных {#insert-and-overwrite-data}

`INSERT INTO` добавляет строки в таблицу только для добавления или объединяет строки в соответствии с параметрами
Paimon для таблицы с первичным ключом. Источником могут быть `VALUES`, внутренняя таблица Doris или другая внешняя таблица.

```sql
INSERT INTO paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.new_orders;
```

Для таблицы без разделов `INSERT OVERWRITE` заменяет все существующие строки. Поэтому пустые входные данные приводят к получению пустой
таблицы.

```sql
INSERT OVERWRITE TABLE paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.orders_snapshot;
```

Для таблицы с разделами используйте одну из следующих форм:

```sql
-- Replace only the specified partition. The SELECT list omits the static partition column.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
PARTITION (order_date = '2026-10-08')
SELECT order_id, customer, amount, status
FROM internal.sales.daily_orders_stage;

-- Dynamic overwrite replaces the partitions present in the input and keeps other partitions.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
SELECT order_id, customer, amount, status, order_date
FROM internal.sales.daily_orders_stage;
```

Таблица с первичным ключом допускает вставку без указания неключевых столбцов только в том случае, если её `merge-engine` имеет значение `partial-update`.
Для таблицы только для добавления пропущенные столбцы получают значение по умолчанию или `NULL`, если это разрешено.

### Удаление, обновление и слияние данных {#delete-update-and-merge-data}

Изменения на уровне строк требуют таблицы Paimon с первичным ключом. Для таблицы со стандартным движком слияния `deduplicate` Doris
поддерживает следующие операции:

```sql
DELETE FROM paimon_ctl.sales.orders
WHERE order_id = 10;

UPDATE paimon_ctl.sales.orders
SET amount = amount * 0.9,
    status = 'DISCOUNTED'
WHERE order_id = 20;

MERGE INTO paimon_ctl.sales.orders t
USING internal.sales.order_changes s
ON t.order_id = s.order_id
WHEN MATCHED AND s.action = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
    customer = s.customer,
    amount = s.amount,
    status = s.status
WHEN NOT MATCHED THEN INSERT (order_id, customer, amount, status)
    VALUES (s.order_id, s.customer, s.amount, s.status);
```

Следующие ограничения обусловлены способом применения изменений строк в Paimon:

* `UPDATE` не может изменять столбец первичного ключа или столбец, заданный через `sequence.field`.
* `UPDATE`, включая действие обновления в `MERGE`, поддерживает только движок слияния `deduplicate` и не поддерживает
  `changelog-producer=input`.
* Обновление столбца раздела требует таблицы с динамическими бакетами (`bucket=-1`) и настройкой `ignore-delete=false`.
* `DELETE`, включая действие удаления в `MERGE`, требует `ignore-delete=false`. Стандартный движок слияния `deduplicate`
  поддерживает эту операцию напрямую. Для таблицы `partial-update` необходимо задать `partial-update.remove-record-on-delete=true`, а для
  таблицы `aggregation` необходимо задать `aggregation.remove-record-on-delete=true`.
* Таблицы с настройкой `rowkind.field` не поддерживают эти SQL-операторы изменения строк. Таблица с динамическими бакетами и настройкой
  `cross-partition-upsert.index-ttl` также их не поддерживает.
* SQL-оператор `MERGE` подчиняется соответствующим ограничениям `UPDATE` и `DELETE` для содержащихся в нём действий.

Для предсказуемых результатов обеспечьте уникальность строк источника `MERGE` по ключу сопоставления. Doris отклоняет SQL-оператор, если
несколько строк источника соответствуют одной целевой строке.

### Примечания по эксплуатации {#operational-notes}

* Настраивайте первичные ключи, разделы, бакеты, движки слияния, форматы файлов, компакцию и другие физические характеристики через
  свойства таблиц Paimon. Doris проверяет эти параметры с помощью Paimon SDK.
* В настоящее время Doris не предоставляет общую операцию `ALTER TABLE ... SET TBLPROPERTIES` для таблиц Paimon. Чтобы
  изменить свойства таблицы после создания, используйте другой движок Paimon, а затем выполните `REFRESH TABLE` или `REFRESH CATALOG`
  в Doris.
* Обеспечьте достаточно места на локальном диске каждого BE для выгрузки данных при записи, а также необходимые права в хранилище для временных файлов и
  операций фиксации. Настройка BE `paimon_jni_writer_memory_pool_limit_bytes` ограничивает пул памяти, используемый каждым
  модулем записи Paimon JNI; её значение по умолчанию составляет 512 MB.
* После успешной записи или изменения схемы новые SQL-операторы Doris загружают зафиксированный снимок Paimon. Уже выполняющиеся
  SQL-операторы продолжают использовать снимок, выбранный при их запуске.

## Операции запросов {#query-operations}

### Базовый запрос {#basic-query}

После настройки Catalog можно выполнять запросы к данным его таблиц следующим образом:

```sql
-- 1. Switch to catalog, use database, and query
SWITCH paimon_ctl;
USE paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 2. Use Paimon database directly
USE paimon_ctl.paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 3. Use fully qualified name to query
SELECT * FROM paimon_ctl.paimon_db.paimon_tbl LIMIT 10;
```

### Пакетный инкрементальный запрос {#batch-incremental-query}

> Начиная с версии 3.1.0

Поддерживаются [пакетные инкрементальные](https://paimon.apache.org/docs/master/flink/sql-query/#batch-incremental) запросы к Paimon, аналогичные запросам во Flink.

Можно запрашивать инкрементальные данные в заданных интервалах снимков или временных меток. Левая граница интервала включается, правая не включается.

```sql
-- between snapshots [0, 5)
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5');

-- between snapshots [0, 5) with specified scan mode
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5', 'incrementalBetweenScanMode'='diff');

-- read from start timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000');

-- read between timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000', 'endTimestamp'='1750944949000');
```

Параметры:

| Параметр | Описание | Пример |
| --- | --- | --- |
| `startSnapshotId` | ID начального снимка, должен быть больше 0. Необходимо указывать вместе с `endSnapshotId`. | `'startSnapshotId'='3'` |
| `endSnapshotId` | ID конечного снимка, должен быть больше `startSnapshotId`. Необходимо указывать вместе с `startSnapshotId`. | `'endSnapshotId'='10'` |
| `incrementalBetweenScanMode` | Задаёт режим инкрементального чтения. По умолчанию используется `auto`, поддерживаются `delta`, `changelog` и `diff` |  `'incrementalBetweenScanMode'='delta'` |
| `startTimestamp` | Временная метка начального снимка, должна быть больше или равна 0. Единица измерения: миллисекунда. | `'startTimestamp'='1750844949000'` |
| `endTimestamp` | Временная метка конечного снимка, должна быть больше `startTimestamp`. Необязательный параметр: если не задан, чтение выполняется от `startTimestamp` до последнего снимка. Единица измерения: миллисекунда. | `'endTimestamp'='1750944949000'` |

:::tip Обратите внимание
`startSnapshotId` и `endSnapshotId` образуют параметр Paimon `'incremental-between'='3,10'`

`startTimestamp` и `endTimestamp` образуют параметр Paimon `'incremental-between-timestamp'='1750844949000,1750944949000'`

`incrementalBetweenScanMode` соответствует параметру Paimon `incremental-between-scan-mode`.
:::

Подробнее об этих параметрах см. в [документации Paimon](https://paimon.apache.org/docs/master/maintenance/configurations/).

### Time Travel {#time-travel}

> Начиная с версии 3.1.0

Поддерживается чтение указанных снимков таблиц Paimon.

По умолчанию запросы на чтение используют только последнюю версию снимка.

Получить снимки указанной таблицы Paimon можно через табличную функцию `$snapshots`:

```sql
Doris > SELECT snapshot_id,commit_time FROM paimon_tbl$snapshots;
+-------------+-------------------------+
| snapshot_id | commit_time             |
+-------------+-------------------------+
|           1 | 2025-08-17 06:05:52.740 |
|           2 | 2025-08-17 06:05:52.979 |
|           3 | 2025-08-17 06:05:53.240 |
|           4 | 2025-08-17 06:05:53.561 |
+-------------+-------------------------+
```

Можно использовать предложения `FOR TIME AS OF` и `FOR VERSION AS OF` для чтения данных исторических версий по ID снимка или времени его создания. Примеры:

```sql
-- Notice: Before 3.1.1, only support format like YYYY-MM-DD HH:MM:SS.SSS
-- After 3.1.2, support YYYY-MM-DD HH:MM:SS and YYYY-MM-DD
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52.740";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17";

-- Notice: The timestamp must be precise down to the millisecond.
SELECT * FROM paimon_tbl FOR TIME AS OF 1755381952740;
-- Use snapshot id
SELECT * FROM paimon_tbl FOR VERSION AS OF 1;
```

#### Time Travel с `@options` {#time-travel-with-options}

Для селекторов, специфичных для Paimon, используйте `@options` при обращении к таблице в запросе. Doris принимает `scan.snapshot-id`,
`scan.tag-name`, `scan.version`, `scan.timestamp`, `scan.timestamp-millis`, `scan.watermark`,
`scan.file-creation-time-millis`, `scan.creation-time-millis` и `scan.mode`. При выборе снимка или тега также
выбирается его историческая схема; Doris не привязывает актуальную схему к историческим данным.

```sql
-- Read snapshot 1 with the schema stored for snapshot 1.
SELECT id, old_name
FROM paimon_tbl@options('scan.snapshot-id' = '1');

-- A retained tag remains readable even after its ordinary snapshot expires.
SELECT id, old_name
FROM paimon_tbl@options('scan.tag-name' = 'tag1');
```

В одном обращении к таблице можно указать только один параметр начальной позиции. `scan.mode` можно сочетать с позицией,
только если Paimon определяет эту пару как совместимую. Например, `scan.mode='from-creation-timestamp'` требует
`scan.creation-time-millis`. Неизвестный или просроченный снимок, ветвь или тег приводит к явной ошибке, а не к неявному
переходу к актуальной таблице. Синтаксис `@options` поддерживается при обращении к таблицам в запросах и может сохраняться в определении
представления, но его нельзя применять к ссылке на CTE или к командам, не являющимся запросами, например `SHOW`.

### Ветви и теги {#branch-and-tag}

> Начиная с версии 3.1.0

Поддерживается чтение ветвей и тегов указанных таблиц Paimon.

Для просмотра ветвей и тегов таблиц Paimon можно использовать системные таблицы `$branches` и `$tags`:

```
Doris > SELECT * FROM paimon_tbl$branches;
+-------------+-------------------------+
| branch_name | create_time             |
+-------------+-------------------------+
| b_1         | 2025-08-17 06:34:37.294 |
| b_2         | 2025-08-17 06:34:37.297 |
+-------------+-------------------------+

Doris > SELECT * FROM paimon_tbl$tags;
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| tag_name | snapshot_id | schema_id | commit_time             | record_count | create_time | time_retained |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| t_1      |           1 |         0 | 2025-08-17 06:05:52.740 |            3 | NULL        | NULL          |
| t_2      |           2 |         0 | 2025-08-17 06:05:52.979 |            6 | NULL        | NULL          |
| t_3      |           3 |         0 | 2025-08-17 06:05:53.240 |            9 | NULL        | NULL          |
| t_4      |           4 |         0 | 2025-08-17 06:05:53.561 |           12 | NULL        | NULL          |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
```

Для совместимости с такими системами, как Spark/Trino, поддерживаются различные формы синтаксиса:

```sql
-- BRANCH
SELECT * FROM paimon_tbl@branch(branch1);
SELECT * FROM paimon_tbl@branch("name" = "branch1");

-- TAG
SELECT * FROM paimon_tbl@tag(tag1);
SELECT * FROM paimon_tbl@tag("name" = "tag1");
SELECT * FROM paimon_tbl FOR VERSION AS OF 'tag1';
```

При использовании синтаксиса `FOR VERSION AS OF` Doris автоматически определяет, является ли параметр временной меткой

## Системные таблицы {#system-tables}

> Начиная с версии 3.1.0

Doris поддерживает запросы к системным таблицам Paimon для получения метаданных таблиц. Системные таблицы позволяют просматривать историю снимков, файлы манифестов, файлы данных, разделы и другую информацию.

Для доступа к метаданным таблицы Paimon добавьте после её имени символ `$`, а затем имя системной таблицы:

```sql
SELECT * FROM my_table$system_table_name;
```

Системные таблицы `audit_log`, `binlog`, `manifests`, `partitions`, `ro`, `row_tracking` и `table_indexes` принимают
`@options` при обращении к ним. Выбранный снимок или тег применяется к строкам системной таблицы, а для системных таблиц, предоставляющих
столбцы исходной таблицы, также используется соответствующая историческая схема исходной таблицы:

```sql
SELECT rowkind, id, old_name
FROM paimon_tbl$audit_log@options('scan.tag-name' = 'tag1');
```

Остальные системные таблицы отклоняют `@options`, поскольку не могут гарантировать, что каждый этап формирования строк использует
выбранный снимок. Системные таблицы Paimon также отклоняют `scan.file-creation-time-millis`: неявное игнорирование этого
фильтра файлов могло бы привести к возврату строк за пределами запрошенного диапазона.

:::info Примечание
Doris не поддерживает чтение глобальных системных таблиц Paimon; они поддерживаются только во Flink.
:::

## Приложение {#appendix}

### Часто задаваемые вопросы {#faq}

**1. `Could not find a file io implementation for scheme 's3a' in the classpath`**

В версиях до 3.1 при использовании HMS для хранения метаданных и протокола 's3a' или 's3' на стороне хранения данных возникает следующая ошибка:

```text
java.io.UncheckedIOException: org.apache.paimon.fs.UnsupportedSchemeException: Could not find a file io implementation for scheme 's3a' in the classpath. Hadoop FileSystem also cannot access this path 's3a://`.
```

**Версии до 3.1**

Версии до 3.1 не поддерживают протокол `s3a`. Если его использование необходимо, в качестве временного обходного решения можно добавить параметры, связанные с `s3a`.

**Версия 3.1 и выше**

Начиная с версии 3.1, явно добавлять параметры `s3a` больше не требуется. Если нужно переопределить параметры хранения Paimon, можно добавить параметры с префиксом `paimon.fs.`. Поскольку Paimon внутренне использует HDFS API, поддерживаются все параметры `fs.s3a.*`.

Например:

```sql
CREATE CATALOG `paimon_hms_on_s3a` PROPERTIES (
    "type" = "paimon",
    "paimon.catalog.type" = "hms",
    "hive.metastore.uris" = "thrift://172.20.48.119:9383",
    "warehouse" = "s3a://bucket/paimon_warehouse",
    "s3.access_key" = "<ak>",
    "s3.secret_key" = "<sk>",
    "s3.region" = "ap-east-1",
    "s3.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    -- Explicitly add s3a parameters
    "fs.s3a.access.key" = "<ak>",
    "fs.s3a.secret.key" = "<sk>",
    "fs.s3a.endpoint.region" = "ap-east-1",
    "fs.s3a.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    "fs.s3a.impl" = "org.apache.hadoop.fs.s3a.S3AFileSystem"
);
```

При использовании протокола `s3` необходимо явно добавить параметры Paimon, связанные с S3, то есть добавить префикс `paimon.`. Например:

```sql
CREATE CATALOG test_paimon_on_hms_aws_catalog PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = 'hms',
    'warehouse' = 's3://bucket-hk/paimon_warehouse',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9383',
    's3.region' = 'ap-east-1',
    's3.endpoint' = 'https://s3.ap-east-1.amazonaws.com',
    's3.access_key' = '<ak>',
    's3.secret_key' = '<sk>',
    -- Explicitly add Paimon S3 parameters
    'paimon.s3.region' = 'ap-east-1',
    'paimon.s3.endpoint' = 'ap-east-1',
    'paimon.s3.access-key' = '<ak>',
    'paimon.s3.secret-key' = '<sk>'
);
```
