В следующей таблице приведено сопоставление типов при чтении для Lance Catalog и TVF файлов Lance в Doris 4.2 (`branch-4.2`). Doris не поддерживает запись в Lance.

| Тип Lance / Arrow | Тип Doris | Описание |
|---|---|---|
| `null` (поле, допускающее NULL) | `NULL` | Все значения равны SQL NULL; поля Null, не допускающие NULL, не поддерживаются |
| `duration(s/ms/us/ns)` | `BIGINT` | Сохраняет целочисленное значение со знаком в указанной единице измерения; не пересчитывает его в секунды |
| `bool` | `BOOLEAN` | |
| `int8` | `TINYINT` | |
| `uint8` | `SMALLINT` | Беззнаковое целое число с расширением разрядности без потерь |
| `int16` | `SMALLINT` | |
| `uint16` | `INT` | Беззнаковое целое число с расширением разрядности без потерь |
| `int32` | `INT` | |
| `uint32` | `BIGINT` | Беззнаковое целое число с расширением разрядности без потерь |
| `int64` | `BIGINT` | |
| `uint64` | `LARGEINT` | Беззнаковое целое число с расширением разрядности без потерь |
| `float16` | `FLOAT` | Расширяется до 32-битного значения с плавающей точкой |
| `float32` | `FLOAT` | |
| `float64` | `DOUBLE` | |
| `decimal128(P,S)` | `DECIMAL(P,S)` | Максимальная точность: 38 |
| `decimal256(P,S)` | `DECIMAL(P,S)` | Максимальная точность: 76 |
| `utf8`, `large_utf8` | `STRING` | |
| `arrow.json` (расширение) | `JSON` | Требуется хранение в формате `utf8` или `large_utf8` |
| `lance.json` (расширение) | `JSON` | Требуется хранение в формате `large_binary`; читается как логический тип JSON |
| `lance.bfloat16` (расширение) | `FLOAT` | Требуется хранение в формате `fixed_size_binary(2)`; расширяется до Float32 без потери точности |
| `binary`, `large_binary` | `VARBINARY(2147483647)` | |
| `fixed_size_binary(N)` | `VARBINARY(N)` | Сохраняет фиксированную ширину в байтах |
| `date32(day)`, `date64(ms)` | `DATE` | Значение `date64` должно представлять полный календарный день |
| `time32(s)` | `TIME(0)` | |
| `time32(ms)` | `TIME(3)` | |
| `time64(us)`, `time64(ns)` | `TIME(6)` | Наносекундная точность усекается до микросекунд |
| Без часового пояса: `timestamp(s)` | `DATETIME(0)` | Не преобразуется с учётом часового пояса сессии |
| Без часового пояса: `timestamp(ms)` | `DATETIME(3)` | Не преобразуется с учётом часового пояса сессии |
| Без часового пояса: `timestamp(us)`, `timestamp(ns)` | `DATETIME(6)` | Наносекундная точность усекается до микросекунд |
| С часовым поясом: `timestamp` | `TIMESTAMPTZ(P)` | Сохраняет момент времени и отображает его в часовом поясе сессии Doris |
| `struct` | `STRUCT` | Дочерние поля сопоставляются рекурсивно |
| `list`, `large_list`, `fixed_size_list` | `ARRAY` | Типы элементов сопоставляются рекурсивно |
| `map` | `MAP` | Типы ключей и значений сопоставляются рекурсивно |

## Примечания по использованию {#usage-notes}

Точность временных меток `P` равна 0 для секунд, 3 для миллисекунд и 6 для микросекунд или наносекунд. В отличие от сопоставлений наносекундных типов Iceberg/Paimon, наносекундные временные метки Lance по-прежнему сопоставляются с `DATETIME(6)` или `TIMESTAMPTZ(6)` и усекаются до микросекунд. Для десятичных чисел требуется соблюдение условий `1 <= P <= 76` и `0 <= S <= P`; отрицательный масштаб не поддерживается.

Doris распознаёт эти расширения по метаданным `ARROW:extension:name` и проверяет их типы хранения. Расширения JSON сопоставляются с типом Doris `JSON` (внутреннее представление: `JSONB`). Обычный столбец `utf8`/`large_utf8`, содержащий текст JSON, по-прежнему сопоставляется с `STRING`; его содержимое не меняет тип автоматически. Поддержка чтения JSON не означает возможность проталкивания произвольных выражений пути JSON; поддерживаемые возможности описаны в разделе [Проталкивание предикатов](../lance-catalog.mdx#predicate-pushdown).

Для чтения JSON, Duration, Null и BFloat16 требуется поддержка соответствующих типов как в FE, так и в узлах BE, обслуживающих запрос. Старые сборки могут по-прежнему сообщать, что эти типы не поддерживаются; при обновлении проверяйте получение схемы и фактическое чтение данных.

Следующие типы в настоящее время не поддерживаются:

- Поля Arrow `null`, не допускающие NULL.
- Типы расширений Arrow/Lance, не перечисленные как поддерживаемые, например Lance Blob v2; известные расширения с несовместимыми типами хранения также не поддерживаются.
- Сложные типы, дочерние типы которых не удаётся сопоставить рекурсивно.
- Типы Arrow Dictionary, сохраняющие маркер Dictionary.

Если столбец верхнего уровня не поддерживается, `DESC` для таблицы Catalog и `DESC FUNCTION` для TVF файла Lance сохраняют этот столбец и отображают `unknown type: UNSUPPORTED_TYPE`. Если хотя бы один дочерний элемент сложного типа не удаётся сопоставить, весь сложный столбец верхнего уровня помечается как неподдерживаемый. В запросах по-прежнему можно выбирать только поддерживаемые столбцы. Если SQL-запрос выбирает неподдерживаемый столбец, Doris сообщает об ошибке на этапе анализа. Например:

```sql
SELECT * EXCEPT(blob_col)
FROM lance_catalog.default.all_types;
```

:::note
Некоторые версии Lance Java SDK могут терять маркер Dictionary при чтении Schema и представлять столбец Dictionary как его физический тип индекса. Такое поведение не означает, что Doris поддерживает логические значения Dictionary, и на него нельзя полагаться.
:::
