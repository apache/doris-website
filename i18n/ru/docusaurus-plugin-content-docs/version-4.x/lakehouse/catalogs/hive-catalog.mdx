Подключившись к Hive Metastore или совместимой с ним службе метаданных, Doris может автоматически получать сведения о базах данных и таблицах Hive для выполнения запросов.

Помимо Hive, метаданные в Hive Metastore хранят и многие другие системы. Поэтому через Hive Catalog можно обращаться как к таблицам Hive, так и к таблицам других форматов, использующих Hive Metastore для хранения метаданных, например Iceberg и Hudi.

## Сценарии использования {#applicable-scenarios}

| Сценарий     | Описание                                                  |
|--------------|--------------------------------------------------------------|
| Ускорение запросов | Используйте распределённый вычислительный движок Doris для прямого доступа к данным Hive и ускорения запросов. |
| Интеграция данных   | Читайте данные Hive и записывайте их во внутренние таблицы Doris либо выполняйте операции ZeroETL с помощью вычислительного движка Doris. |
| Обратная запись данных   | Обрабатывайте данные из любого источника, поддерживаемого Doris, и записывайте результаты в таблицы Hive. |

## Настройка Catalog {#configuring-catalog}

### Синтаксис {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type'='hms', -- required
    'hive.metastore.type' = '<hive_metastore_type>', -- optional
    'hive.version' = '<hive_version>', -- optional
    'fs.defaultFS' = '<fs_defaultfs>', -- required for write, optional for read-only
    {MetaStoreProperties},
    {StorageProperties},
    {HiveProperties},
    {CommonProperties}
);
```

* `<hive_metastore_type>`

  Указывает тип Hive Metastore.

  * `hms`: стандартная служба Hive Metastore.
  * `glue`: доступ к службе метаданных AWS Glue через интерфейс, совместимый с Hive Metastore.
  * `dlf`: доступ к службе метаданных Alibaba Cloud DLF через интерфейс, совместимый с Hive Metastore.

* `<fs_defaultfs>`

  Этот параметр обязателен при записи данных из Doris в таблицы данного Hive Catalog. Пример:

  `'fs.defaultFS' = 'hdfs://namenode:port'`

* `{MetaStoreProperties}`

  Раздел MetaStoreProperties предназначен для параметров подключения и аутентификации в службе метаданных Metastore. Подробнее см. раздел «Поддерживаемые службы метаданных».

* `{StorageProperties}`

  Раздел StorageProperties предназначен для параметров подключения и аутентификации в системе хранения. Подробнее см. раздел «Поддерживаемые системы хранения».

* `{HiveProperties}`

  Раздел HiveProperties предназначен для свойств Hive Catalog.

  * `get_schema_from_table`: значение по умолчанию — false. Обычно Doris получает схему таблицы из Hive Metastore. Однако иногда возникают проблемы совместимости, например ошибка `Storage schema reading not supported`. В таком случае можно задать для параметра значение true, и схема таблицы будет получена непосредственно из объекта Table. Учтите, что при этом сведения о значениях столбцов по умолчанию игнорируются. Свойство поддерживается начиная с версий 2.1.10 и 3.0.6.

  * `hive.recursive_directories`: определяет, нужно ли рекурсивно обходить подкаталоги при получении списка каталогов разделов. Параметр поддерживается начиная с версии 3.0.2. До версии 4.0 его значением по умолчанию было `false`, в более поздних версиях — `true`. Пути к разделам некоторых таблиц Hive могут не соответствовать сведениям о разделах в схеме таблицы. Чтобы получать файлы данных из подкаталогов, необходимо задать для этого параметра значение true.

  * `hive.ignore_absent_partitions`: определяет, следует ли игнорировать несуществующие разделы. Значение по умолчанию — `true`. Если задано `false`, при обнаружении несуществующего раздела запрос завершится ошибкой. Параметр поддерживается начиная с версии 3.0.2.

  * `hive.staging_dir`: задаёт корневой временный каталог для операций записи в Hive. Во время записи данные сначала помещаются в этот каталог, а после завершения перемещаются в конечный каталог таблицы Hive. Можно указать путь относительно корневого каталога таблицы Hive или абсолютный путь. Значение по умолчанию — `/tmp/.doris_staging`. Иногда каталог `/tmp` и каталог таблицы находятся в разных пространствах имён, из-за чего запись в таблицу Hive завершается ошибкой. В таком случае проблему можно устранить, указав относительный путь. Параметр поддерживается начиная с версии 4.0.3.

* `{CommonProperties}`

  Раздел CommonProperties предназначен для общих свойств. См. раздел «Общие свойства» в [обзоре Catalog](../catalog-overview.md).

## Кеш метаданных {#meta-cache}

Для повышения производительности при обращении к внешним источникам данных Apache Doris кеширует метаданные Hive. К ним относятся структура таблицы (Schema), списки разделов, свойства разделов и списки файлов.

:::tip
В версиях до Doris 4.1.x кеширование метаданных в основном управлялось глобальными параметрами конфигурации FE. Подробнее см. [Кеш метаданных](../meta-cache.md).
Начиная с Doris 4.1.x кеш внешних метаданных Hive Catalog настраивается с помощью унифицированных ключей `meta.cache.*`.
:::

### Настройка свойств кеша (4.1.x+) {#meta-cache-unified-model}

Для записи кеша каждого движка используется единый формат ключей конфигурации: `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}`. Сейчас `max-weight` поддерживается только для отдельных записей с оценкой потребления памяти; см. [Управление памятью кеша внешних метаданных](../external-meta-cache-memory-management).

| Свойство | Пример | Значение |
|---|---|---|
| `enable` | `true/false` | Включает или отключает данный модуль кеша. |
| `ttl-second` | `600`, `0`, `-1` | `0` отключает кеш (изменение вступает в силу сразу; это позволяет видеть актуальные данные); `-1` означает отсутствие срока действия; другие положительные целые числа задают TTL в секундах, отсчитываемый от времени обращения. |
| `capacity` | `10000` | Максимальное количество записей в кеше. Когда действует `max-weight`, одновременное ограничение на количество записей не применяется, но `0` по-прежнему отключает кеш. |
| `max-weight` | `1GB` | Поддерживается начиная с Doris 4.1.4. Необязательный лимит оцениваемого объёма удерживаемой памяти. Сейчас поддерживается для Hive `partition_values`; `0` отключает эту запись. |

**Условия работы:** кеш модуля действует, если `enable=true`, `ttl-second != 0`, `capacity > 0`, а `max-weight` отсутствует или не равен `0`.

### Модули кеша {#meta-cache-unified-modules}

Hive Catalog включает следующие модули кеша:

| Модуль (`<entry>`) | Префикс ключа свойства | Кешируемые данные и влияние |
|---|---|---|
| `schema` | `meta.cache.hive.schema.` | Кеширует структуру таблицы. Влияет на видимость сведений о столбцах таблицы. Если отключить модуль, при каждом запросе будет загружаться актуальная Schema. |
| `partition_values` | `meta.cache.hive.partition_values.` | Кеширует список значений и имён разделов. Влияет на отсечение и перечисление разделов. Если отключить модуль, новые внешние разделы будут видны в реальном времени. |
| `partition` | `meta.cache.hive.partition.` | Кеширует свойства разделов (Location, формат ввода и т. д.). Влияет на доступность конкретных метаданных разделов. |
| `file` | `meta.cache.hive.file.` | Кеширует списки файлов. Снижает затраты на удалённые операции LIST. Если отключить модуль, изменения файлов будут видны в реальном времени. |

### Сопоставление и преобразование прежних параметров {#meta-cache-mapping}

В версиях 4.1.x и новее рекомендуется использовать унифицированные ключи. Ниже показано соответствие прежних свойств Catalog унифицированным ключам 4.1.x+:

| Прежний ключ свойства | Унифицированный ключ 4.1.x+ | Описание |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.hive.schema.ttl-second` | Срок действия кеша структуры таблицы |
| `partition.cache.ttl-second` | `meta.cache.hive.partition_values.ttl-second` | Срок действия кеша значений разделов |
| `file.meta.cache.ttl-second` | `meta.cache.hive.file.ttl-second` | Срок действия кеша списка файлов |

### Рекомендации {#meta-cache-best-practices}

* **Доступ к актуальным данным в реальном времени**: чтобы каждый запрос видел последние изменения разделов или файлов во внешнем источнике данных, задайте для соответствующего `ttl-second` значение `0`.
  ```sql
  -- Disable file list cache to see file changes in real-time
  ALTER CATALOG hive_ctl SET PROPERTIES ("meta.cache.hive.file.ttl-second" = "0");
  -- Disable partition value cache to see new partitions in real-time
  ALTER CATALOG hive_ctl SET PROPERTIES ("meta.cache.hive.partition_values.ttl-second" = "0");
  ```
* **Оптимизация производительности**: если метаданные меняются редко, рекомендуется увеличить `capacity` и `ttl-second` в подходящих пределах, чтобы снизить нагрузку на Hive Metastore и файловые системы.

:::caution
**Примечание о Hive Catalog**: начиная с Doris 4.1.4 успешное изменение свойств Catalog сбрасывает контекст выполнения Catalog и очищает инициализированные записи во всех движках кеша метаданных, к которым обращается этот Catalog. При следующем обращении Doris создаёт их заново с новым контекстом и конфигурацией. Уже выполняющиеся запросы не затрагиваются.
:::

### Наблюдение за кешем {#meta-cache-unified-observability}

Метрики кеша доступны через системную таблицу `information_schema.catalog_meta_cache_statistics`:

```sql
SELECT catalog_name, engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, load_failure_count, last_error
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'hive_ctl' AND engine_name = 'hive'
ORDER BY entry_name;
```

Документацию по этой системной таблице см. в разделе [catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md).

### Часовой пояс записи Parquet INT96 (начиная с 4.1.5) {#parquet-int96-writer-time-zone-since-415}

Необязательное свойство Catalog `hive.parquet.time-zone` задаёт часовой пояс стороны записи при чтении Parquet INT96. По умолчанию оно содержит пустую строку: в этом случае локальное время сохраняется без пересчёта. Непустое значение должно быть часовым поясом IANA либо смещением относительно UTC от `-12:00` до `+14:00`. Значения `UTC` и `GMT` допустимы, а короткие обозначения, например `CST` и `PRC`, отклоняются. Пример: `"hive.parquet.time-zone" = "Asia/Shanghai"`. INT96 не содержит аннотации часового пояса, поэтому не следует определять часовой пояс стороны записи по часовому поясу сеанса чтения. См. [Parquet](../file-formats/parquet.md#timestamp-and-date-compatibility).

## Операции чтения {#query-operations}

### Базовый запрос {#basic-query}

После настройки Catalog можно запрашивать данные его таблиц следующими способами:

```sql
-- 1. switch to catalog, use database and query
SWITCH hive_ctl;
USE hive_db;
SELECT * FROM hive_tbl LIMIT 10;

-- 2. use hive database directly
USE hive_ctl.hive_db;
SELECT * FROM hive_tbl LIMIT 10;

-- 3. use full qualified name to query
SELECT * FROM hive_ctl.hive_db.hive_tbl LIMIT 10;
```

### Запрос сведений о разделах Hive {#querying-hive-partitions}

Сведения о разделах Hive можно получить двумя способами:

* `SHOW PARTITIONS FROM [catalog.][db.]hive_table`

  Эта команда выводит все разделы указанной таблицы Hive и их значения.

  ```sql
  SHOW PARTITIONS FROM hive_table;

  +--------------------------------+
  | Partition                      |
  +--------------------------------+
  | pt1=2024-10-10/pt2=beijing     |
  | pt1=2024-10-10/pt2=shanghai    |
  | pt1=2024-10-11/pt2=beijing     |
  | pt1=2024-10-11/pt2=shanghai    |
  | pt1=2024-10-12/pt2=nanjing     |
  +--------------------------------+
  ```

* Использование таблицы метаданных `table$partitions`

  Начиная с версий 2.1.7 и 3.0.3 сведения о разделах Hive можно запрашивать через таблицу метаданных `table$partitions`. По сути, это реляционная таблица, в которой каждому столбцу раздела соответствует отдельный столбец. Поэтому её можно использовать в любом запросе SELECT.

  ```sql
  SELECT * FROM hive_table$partitions;

  +------------+-------------+
  | pt1        | pt2         |
  +------------+-------------+
  | 2024-10-10 | beijing     |
  | 2024-10-10 | shanghai    |
  | 2024-10-12 | nanjing     |
  | 2024-10-11 | beijing     |
  | 2024-10-11 | shanghai    |
  +------------+-------------+
  ```

:::caution Изменение поведения (4.1.4)

Начиная с версии 4.1.4 маркер раздела по умолчанию `__HIVE_DEFAULT_PARTITION__`, используемый при разбиении Hive на разделы по каталогам, преобразуется в настоящее значение **NULL**, а не кодируется строкой `\N`. При этом буквальное значение `\N`, действительно сохранённое в пути раздела, остаётся данными.

До версии 4.1.4 эти случаи были неразличимы и оба отображались в результатах запросов как `\N`. После обновления условие `WHERE <partition_col> IS NULL` корректно находит раздел Hive по умолчанию.

:::

### Запросы к транзакционным таблицам Hive {#querying-hive-transactional-tables}

Транзакционные таблицы Hive поддерживают семантику ACID. Подробнее см. [Hive Transactions](https://cwiki.apache.org/confluence/display/Hive/Hive+Transactions).

* Поддержка транзакционных таблиц Hive

  | Тип таблицы                      | Поддерживаемые операции в Hive        | Свойства таблицы Hive                                                | Поддерживаемые версии Hive                                          |
  | ------------------------------- | ----------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------- |
  | Транзакционная таблица Full-ACID   | Поддерживает Insert, Update, Delete     | `'transactional'='true'`                                            | 4.x, 3.x, 2.x (для чтения в 2.x требуется Major Compaction в Hive)    |
  | Транзакционная таблица Insert-Only | Поддерживает только Insert                | `'transactional'='true'`, `'transactional_properties'='insert_only'` | 4.x, 3.x, 2.x (при создании Catalog укажите `hive.version`) |

* Текущие ограничения

  Сценарии с Original Files не поддерживаются. При преобразовании таблицы в транзакционную новые файлы данных используют схему транзакционной таблицы Hive, а существующие файлы данных не преобразуются. Такие файлы называются Original Files.

### Запросы к представлениям Hive {#querying-hive-views}

Представления Hive можно запрашивать, но с некоторыми ограничениями:

* Определение представления Hive (HiveQL) должно быть совместимо с инструкциями SQL, поддерживаемыми Doris. Иначе возникнет ошибка синтаксического анализа.

* Некоторые функции HiveQL могут называться так же, как функции Doris, но вести себя иначе. Из-за этого результаты запросов Hive и Doris могут различаться. Если вы столкнулись с такой проблемой, сообщите о ней сообществу.

### Связанные параметры {#related-parameters}

* Переменные сеанса

| Имя параметра | Значение по умолчанию | Описание | Начиная с версии |
| ----------| ---- | ---- | --- |
| `hive_parquet_use_column_names` | `true` | По умолчанию при чтении данных Parquet из таблицы Hive Doris ищет в файле Parquet столбец с тем же именем, что и столбец таблицы Hive. Если переменная равна `false`, Doris читает данные из файла Parquet в порядке столбцов таблицы Hive независимо от их имён. Аналогична переменной Hive `parquet.column.index.access`. Параметр действует только для имён столбцов верхнего уровня и не применяется внутри Struct. | 2.1.6+, 3.0.3+ |
| `hive_orc_use_column_names` | `true` | Аналогичен `hive_parquet_use_column_names`, но применяется к данным ORC таблицы Hive. Аналогичен переменной Hive `orc.force.positional.evolution`. | 2.1.6+, 3.0.3+ |

## Операции записи {#write-operations}

Для записи данных в таблицы Hive используется инструкция INSERT. Поддерживаются таблицы Hive, созданные Doris, и существующие таблицы Hive совместимых форматов.

Для таблиц с разделами данные автоматически записываются в соответствующий раздел либо на основе данных создаётся новый раздел. Начиная с версии 4.1.5 конструкция `PARTITION (column = literal)` поддерживает статические разделы, а также сочетание статических и динамических столбцов разделов. Статические столбцы разделов не следует включать в список целевых столбцов INSERT и вывод SELECT или VALUES; остальные динамические столбцы разделов должны поступать из входных данных.

### INSERT INTO {#insert-into}

Операция INSERT добавляет данные в целевую таблицу.

```sql
INSERT INTO hive_tbl VALUES (val1, val2, val3, val4);
INSERT INTO hive_ctl.hive_db.hive_tbl SELECT col1, col2 FROM internal.db1.tbl1;

INSERT INTO hive_tbl(col1, col2) VALUES (val1, val2);
INSERT INTO hive_tbl(col1, col2, partition_col1, partition_col2) VALUES (1, 2, "beijing", "2023-12-12");
```

Начиная с версии 4.1.5 запись поддерживает статические разделы и сочетание статических и динамических разделов:

```sql
-- Full Static Partition
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
VALUES (val1, val2);
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
SELECT col1, col2 FROM source_table;

-- Hybrid Partition Mode: "partition_col1" is static, "partition_col2" comes from SELECT dynamically
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30')
VALUES (val1, val2, partition_val2);
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30')
SELECT col1, col2, partition_col2 FROM source_table;
```

### INSERT OVERWRITE {#insert-overwrite}

INSERT OVERWRITE полностью заменяет существующие данные таблицы новыми.

```sql
INSERT OVERWRITE TABLE hive_tbl VALUES (val1, val2, val3, val4);
INSERT OVERWRITE TABLE hive_ctl.hive_db.hive_tbl(col1, col2) SELECT col1, col2 FROM internal.db1.tbl1;
```

Начиная с версии 4.1.5 запись поддерживает статические разделы и сочетание статических и динамических разделов:

```sql
-- Full Static Partition
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
VALUES (val1, val2);
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
SELECT col1, col2 FROM source_table;

-- Hybrid Partition Mode: "partition_col1" is static, "partition_col2" comes from SELECT dynamically
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30')
VALUES (val1, val2, partition_val2);
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30')
SELECT col1, col2, partition_col2 FROM source_table;
```

Семантика INSERT OVERWRITE соответствует Hive и предполагает следующее поведение:

* Если целевая таблица разбита на разделы, а исходная таблица пуста, операция ни на что не влияет. Целевая таблица остаётся без изменений.

* Если целевая таблица не разбита на разделы, а исходная таблица пуста, целевая таблица очищается.

* Начиная с версии 4.1.5 можно указывать статические разделы для записи и сочетать статические разделы с динамическими. Однако даже при указании статических разделов они не очищаются, если исходный запрос возвращает пустой результат.

**Полный пример со статическими разделами (начиная с 4.1.5)**

Настройте описанный на этой странице Hive Catalog, подготовьте существующую базу данных `hive_ctl.hive_db` и предоставьте права на создание таблиц, запись и выполнение запросов. В Catalog для записи должно быть настроено свойство `fs.defaultFS`. В этом примере статическая дата сочетается с динамически задаваемыми регионами, после чего один полностью указанный статический раздел перезаписывается:

```sql
CREATE TABLE hive_ctl.hive_db.static_write_demo (
    id INT,
    dt STRING,
    region STRING
)
ENGINE=HIVE
PARTITION BY LIST (dt, region) ()
PROPERTIES ("file_format" = "parquet");

INSERT INTO hive_ctl.hive_db.static_write_demo PARTITION (dt='2026-10-01')
VALUES (1, 'beijing'), (2, 'shanghai');

INSERT OVERWRITE TABLE hive_ctl.hive_db.static_write_demo
PARTITION (dt='2026-10-01', region='beijing') VALUES (3);

SELECT id, dt, region FROM hive_ctl.hive_db.static_write_demo ORDER BY id;
```

```text
+----+------------+----------+
| id | dt         | region   |
+----+------------+----------+
|  2 | 2026-10-01 | shanghai |
|  3 | 2026-10-01 | beijing  |
+----+------------+----------+
```

Значения статических разделов должны быть литералами. Нельзя указывать один ключ раздела несколько раз или повторять статический столбец раздела в явном списке столбцов INSERT. Имена статических ключей сопоставляются без учёта регистра; несуществующий столбец раздела вызывает ошибку.

### CTAS {#ctas}

Создать таблицу Hive и записать в неё данные можно с помощью инструкции `CTAS (CREATE TABLE AS SELECT)`:

```sql
CREATE TABLE hive_ctas ENGINE=hive AS SELECT * FROM other_table;
```

CTAS позволяет указывать формат файлов, способ разбиения на разделы и другие свойства, как показано ниже:

```sql
CREATE TABLE hive_ctas ENGINE=hive
PARTITION BY LIST (pt1, pt2) ()
AS SELECT col1, pt1, pt2 FROM part_ctas_src WHERE col1 > 0;

CREATE TABLE hive_ctl.hive_db.hive_ctas (col1, col2, pt1) ENGINE=hive
PARTITION BY LIST (pt1) ()
PROPERTIES (
    "file_format"="parquet",
    "compression"="zstd"
)
AS SELECT col1, pt1 AS col2, pt2 AS pt1 FROM test_ctas.part_ctas_src WHERE col1 > 0;
```

## Управление базами данных и таблицами {#database-and-table-management}

Пользователи могут создавать и удалять базы данных и таблицы в Hive Metastore через Doris. Учтите, что для этих операций Doris только вызывает API Hive Metastore и сама не хранит метаданные Hive на постоянной основе.

### Создание и удаление баз данных {#creating-and-dropping-databases}

Можно переключиться на нужный Catalog с помощью инструкции `SWITCH`, а затем выполнить `CREATE DATABASE`:

```sql
SWITCH hive_ctl;
CREATE DATABASE [IF NOT EXISTS] hive_db;
```

Базу данных также можно создать по полному имени или указать её расположение, например:

```sql
CREATE DATABASE [IF NOT EXISTS] hive_ctl.hive_db;

CREATE DATABASE [IF NOT EXISTS] hive_ctl.hive_db
PROPERTIES ('location'='hdfs://172.21.16.47:4007/path/to/db/');
```

Расположение базы данных можно посмотреть с помощью команды `SHOW CREATE DATABASE`:

```sql
mysql> SHOW CREATE DATABASE hive_db;
+----------+---------------------------------------------------------------------------------------------+
| Database | Create Database                                                                             |
+----------+---------------------------------------------------------------------------------------------+
| hive_db  | CREATE DATABASE hive_db LOCATION 'hdfs://172.21.16.47:4007/usr/hive/warehouse/hive_db.db'   |
+----------+---------------------------------------------------------------------------------------------+
```

Чтобы удалить базу данных:

```sql
DROP DATABASE [IF EXISTS] hive_ctl.hive_db;
```

:::caution
Перед удалением базы данных Hive необходимо удалить все её таблицы, иначе возникнет ошибка. При этом также удаляется соответствующая база данных в Hive.
:::

### Создание и удаление таблиц {#creating-and-dropping-tables}

- **Создание таблиц**

  Doris поддерживает создание в Hive таблиц как с разделами, так и без разделов.

  ```sql
  -- Create unpartitioned hive table
  CREATE TABLE unpartitioned_table (
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3',
    `col4` CHAR(10) COMMENT 'col4',
    `col5` FLOAT COMMENT 'col5',
    `col6` DOUBLE COMMENT 'col6',
    `col7` DECIMAL(9,4) COMMENT 'col7',
    `col8` VARCHAR(11) COMMENT 'col8',
    `col9` STRING COMMENT 'col9'
  )  ENGINE=hive
  PROPERTIES (
    'file_format'='parquet'
  );

  -- Create partitioned hive table
  -- The partition columns must be in table's column definition list
  CREATE TABLE partition_table (
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3',
    `col4` DECIMAL(2,1) COMMENT 'col4',
    `pt1` VARCHAR COMMENT 'pt1',
    `pt2` VARCHAR COMMENT 'pt2'
  )  ENGINE=hive
  PARTITION BY LIST (pt1, pt2) ()
  PROPERTIES (
    'file_format'='orc',
    'compression'='zlib'
  );

  -- Create text format table(Since 2.1.7 & 3.0.3)
  CREATE TABLE text_table (
      `id` INT,
      `name` STRING
  ) PROPERTIES (
      'file_format'='text',
      'compression'='gzip',
      'field.delim'='\t',
      'line.delim'='\n',
      'collection.delim'=';',
      'mapkey.delim'=':',
      'serialization.null.format'='\\N',
      'escape.delim'='\\'
  );
  ```

  После создания таблицы её инструкцию создания в Hive можно просмотреть с помощью команды `SHOW CREATE TABLE`.

  Учтите, что, в отличие от синтаксиса создания таблиц Hive, при создании таблицы Hive с разделами в Doris столбцы разделов необходимо включить в схему таблицы. Они должны находиться в конце схемы и идти в том же порядке.

  :::tip
  В кластерах Hive, где функции транзакций ACID включены по умолчанию, таблицы, созданные Doris, получают свойство `transactional` со значением `true`. Поскольку Doris поддерживает лишь часть возможностей транзакционных таблиц Hive, она может не суметь прочитать созданные ею таблицы Hive. Чтобы избежать этого, явно укажите `"transactional" = "false"` в свойствах таблицы и создайте нетранзакционную таблицу Hive:

  ```sql
  CREATE TABLE non_acid_table(
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3'
  ) ENGINE=hive
  PROPERTIES (
    'transactional'='false'
  );
  ```
  :::

- **Удаление таблиц**

  Таблицу Hive можно удалить инструкцией `DROP TABLE`. При удалении таблицы удаляются и все её данные, включая данные разделов.

- **Сопоставление типов столбцов**

  Подробнее см. раздел [Сопоставление типов столбцов]. Учитывайте следующие ограничения:

  - Столбцы должны иметь тип, допускающий NULL по умолчанию; `NOT NULL` не поддерживается.
  - Hive 3.0 поддерживает значения по умолчанию. Чтобы задавать такие значения, явно добавьте `"hive.version" = "3.0.0"` в свойства Catalog.
  - Если тип вставляемых данных несовместим с типом столбца (например, строка `'abc'` вставляется в числовой столбец), значение преобразуется в `null`.

- **Разбиение на разделы**

  Разделам Hive соответствуют разделы List в Doris. Поэтому при создании таблицы Hive с разделами в Doris используйте синтаксис разбиения List, но не перечисляйте каждый раздел явно. При вставке данных Doris автоматически создаст соответствующий раздел Hive на основе значений данных. Поддерживаются таблицы с разделами по одному или нескольким столбцам.

- **Форматы файлов**

  - ORC (по умолчанию)
  - Parquet

    При записи значения типа DATETIME в файл Parquet используется физический тип INT96 вместо INT64. Это обеспечивает совместимость с логикой версий Hive до 4.0.

  - Text (поддерживается начиная с версий 2.1.7 и 3.0.3)

      Формат Text поддерживает следующие свойства таблицы:

		  - `field.delim`: разделитель столбцов. По умолчанию — `\1`.
		  - `line.delim`: разделитель строк. По умолчанию — `\n`.
		  - `collection.delim`: разделитель элементов сложных типов. По умолчанию — `\2`.
		  - `mapkey.delim`: разделитель пар «ключ — значение» в Map. По умолчанию — `\3`.
		  - `serialization.null.format`: формат хранения значений `NULL`. По умолчанию — `\N`.
		  - `escape.delim`: символ экранирования. По умолчанию — `\`.

- **Форматы сжатия**

  Следующие кодеки применяются при выборе сжатия для создания таблиц и записи данных через Doris. Значение `plain` означает отсутствие сжатия.

  | Версия Doris | Parquet | ORC |
  | --- | --- | --- |
  | 4.0.x, 4.1.0–4.1.2 | `snappy` (по умолчанию), `zstd`, `plain` | `snappy`, `zlib` (по умолчанию), `zstd`, `plain` |
  | 4.1.3 и более поздние выпуски 4.1 | `snappy` (по умолчанию), `zstd`, `plain`, `lz4` | `snappy`, `zlib` (по умолчанию), `zstd`, `plain`, `lz4` |
  | Начиная с 4.2.0 | `snappy` (по умолчанию), `zstd`, `plain`, `lz4`, `gzip` | `snappy`, `zlib` (по умолчанию), `zstd`, `plain`, `lz4` |

  При записи Hive Text поддерживаются `gzip`, `bzip2`, `zstd`, `lz4`, `snappy` и `plain` (по умолчанию). Поддержку сжатия при чтении существующих файлов см. в разделе [Text/CSV/JSON](../file-formats/text.md).

  Для таблиц, создаваемых через Doris, кодек выбирается свойством `compression`. При записи в существующие таблицы Hive Doris считывает свойства таблицы `parquet.compression`, `orc.compress` и `text.compression` для соответствующих форматов файлов.

- **Носитель данных**

  - HDFS
  - Объектное хранилище

## Подписка на события Hive Metastore {#subscribing-to-hive-metastore-events}

Узлы FE периодически считывают события уведомлений из HMS. Так Doris обнаруживает изменения метаданных таблиц Hive в реальном времени и поддерживает их актуальность. Сейчас поддерживаются следующие события:

| Событие            | Действие и соответствующее поведение                                         |
| ---------------- | ------------------------------------------------------------------------- |
| CREATE DATABASE  | Создаёт базу данных в соответствующем каталоге данных.                   |
| DROP DATABASE    | Удаляет базу данных в соответствующем каталоге данных.                   |
| ALTER DATABASE   | В основном касается изменения свойств базы данных, комментариев и расположения хранилища по умолчанию. Эти изменения не влияют на возможность Doris запрашивать внешние каталоги данных, поэтому событие сейчас игнорируется. |
| CREATE TABLE     | Создаёт таблицу в соответствующей базе данных.                            |
| DROP TABLE       | Удаляет таблицу из соответствующей базы данных и делает кеш таблицы недействительным. |
| ALTER TABLE      | При переименовании удаляет таблицу со старым именем и создаёт таблицу с новым; в остальных случаях делает кеш таблицы недействительным. |
| ADD PARTITION    | Добавляет раздел в кешированный список разделов соответствующей таблицы. |
| DROP PARTITION   | Удаляет раздел из кешированного списка разделов и делает кеш раздела недействительным. |
| ALTER PARTITION  | При переименовании удаляет раздел со старым именем и создаёт раздел с новым; в остальных случаях делает кеш раздела недействительным. |

:::tip
1. Когда загрузка данных приводит к изменению файлов, таблицы с разделами вызывают событие `ALTER PARTITION`, а таблицы без разделов — `ALTER TABLE`.

2. Если изменять файловую систему напрямую, минуя HMS, соответствующие события в HMS не создаются и Doris не обнаруживает изменения метаданных.
:::

С этой функцией связаны следующие параметры в `fe.conf`:

1. `enable_hms_events_incremental_sync`: включает автоматическую инкрементальную синхронизацию метаданных. По умолчанию отключена.

2. `hms_events_polling_interval_ms`: интервал чтения событий; по умолчанию 10000 миллисекунд.

3. `hms_events_batch_size_per_rpc`: максимальное число событий, считываемых за один RPC; по умолчанию 500.

Чтобы использовать эту функцию (кроме Huawei Cloud MRS), измените файл `hive-site.xml` службы HMS и перезапустите HMS и HiveServer2.

```xml
<property>
    <name>hive.metastore.event.db.notification.api.auth</name>
    <value>false</value>
</property>
<property>
    <name>hive.metastore.dml.events</name>
    <value>true</value>
</property>
<property>
    <name>hive.metastore.transactional.event.listeners</name>
    <value>org.apache.hive.hcatalog.listener.DbNotificationListener</value>
</property>
```

Для Huawei Cloud MRS измените файл `hivemetastore-site.xml` и перезапустите HMS и HiveServer2.

```xml
<property>
    <name>metastore.transactional.event.listeners</name>
    <value>org.apache.hive.hcatalog.listener.DbNotificationListener</value>
</property>
```

## Приложение {#appendix}

### Механизм транзакций {#transaction-mechanism}

Операции записи в Hive выполняются в отдельной транзакции. До её фиксации данные недоступны извне. Связанные с таблицей операции становятся видны другим пользователям только после фиксации транзакции.

Транзакции обеспечивают атомарность: все операции внутри транзакции либо выполняются успешно вместе, либо вместе завершаются неудачей.

Транзакции не могут полностью гарантировать изоляцию операций, но стремятся свести несогласованность к минимуму, отделяя операции файловой системы от операций с метаданными Hive Metastore.

Например, если в транзакции нужно изменить несколько разделов таблицы Hive, задачу могут выполнить в два этапа. Первый этап может стать видимым извне до завершения второго: разделы первого этапа уже можно прочитать, а разделы второго — ещё нет.

Если при фиксации транзакции возникает исключение, транзакция полностью откатывается, включая изменения файлов HDFS и метаданных Hive Metastore. Дополнительных действий пользователя не требуется.

### Механизм параллельной записи {#concurrent-writing-mechanism}

Apache Doris сейчас поддерживает параллельную запись с помощью нескольких инструкций вставки. При этом пользователи должны следить, чтобы параллельные операции записи не конфликтовали.

Поскольку обычные нетранзакционные таблицы Hive не имеют полноценного механизма транзакций, механизм транзакций Apache Doris лишь сокращает периоды несогласованности, но не гарантирует полноценные свойства ACID. Поэтому параллельная запись в таблицы Hive через Apache Doris может привести к проблемам с согласованностью данных.

1. **Параллельные операции `INSERT`**

2. Операции `INSERT` добавляют данные и при параллельном выполнении не конфликтуют, давая ожидаемый результат.

3. **Параллельные операции `INSERT OVERWRITE`**

4. Параллельное выполнение `INSERT OVERWRITE` для одной таблицы или одного раздела может привести к потере или повреждению данных с непредсказуемым результатом.

5. Обычно применяют следующие решения:

   * Для таблиц с разделами записывайте данные в разные разделы. Параллельные операции над разными разделами не конфликтуют.

   * Для таблиц без разделов используйте `INSERT` вместо `INSERT OVERWRITE`, чтобы избежать конфликтов.

   * Для операций, которые могут конфликтовать, обеспечьте на уровне приложения выполнение только одной операции записи в каждый момент времени.

### Операции с файлами HDFS {#hdfs-file-operations}

Данные таблицы Hive в HDFS обычно сначала записываются во временный каталог, а затем окончательно размещаются с помощью операций файловой системы, например `rename`. Ниже подробно описаны операции с файлами HDFS для разных способов записи данных.

Формат временного каталога данных: `/tmp/.doris_staging/<username>/<uuid>`

Формат имён записанных файлов данных: `<query-id>_<uuid>-<index>.<compress-type>.<file-type>`

Примеры файловых операций в разных сценариях:

1. **Таблица без разделов**

   * **Добавление данных**

     * Целевой каталог таблицы: `hdfs://ns/usr/hive/warehouse/example.db/table1`

     * Временный файл: `hdfs://ns/tmp/.doris_staging/root/f02247cb662846038baae272af5eeb05/b35fdbcea3a4e39-86d1f36987ef1492_7e3985bf-9de9-4fc7-b84e-adf11aa08756-0.orc`

     * На этапе фиксации все временные файлы перемещаются в целевой каталог таблицы.

   * **Перезапись данных**

     * Целевой каталог таблицы: `hdfs://ns/usr/hive/warehouse/example.db/table1`

     * Временный файл: `hdfs://ns/tmp/.doris_staging/root/f02247cb662846038baae272af5eeb05/b35fdbcea3a4e39-86d1f36987ef1492_7e3985bf-9de9-4fc7-b84e-adf11aa08756-0.orc`

     * Этапы фиксации:

       1. Целевой каталог таблицы переименовывается во временный: `hdfs://ns/usr/hive/warehouse/example.db/_temp_b35fdbcea3a4e39-86d1f36987ef1492_table1`

       2. Временный каталог переименовывается в целевой каталог таблицы.

       3. Временный каталог прежней целевой таблицы удаляется.

2. **Таблица с разделами**

   * **Добавление данных в новый раздел**

     * Целевой каталог таблицы: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * Временный файл: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * На этапе фиксации временный каталог переименовывается в целевой каталог таблицы.

   * **Добавление данных в существующий раздел**

     * Целевой каталог таблицы: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * Временный файл: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * На этапе фиксации файлы из временного каталога перемещаются в целевой каталог таблицы.

   * **Перезапись существующего раздела**

     * Целевой каталог таблицы: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * Временный файл: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * Этапы фиксации:

       1. Целевой каталог раздела переименовывается во временный каталог раздела: `hdfs://ns/usr/hive/warehouse/example.db/table2/_temp_d678a74d232345e0-b659e2fb58e86ffd_part_col=2024-01-01`

       2. Временный каталог раздела переименовывается в целевой каталог раздела.

       3. Временный каталог прежнего целевого раздела удаляется.
