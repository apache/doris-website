# Parquet {#parquet}

В этом документе описывается поддержка чтения и записи файлов формата Parquet в Doris. Она применяется к следующим функциям:

* Чтение и запись данных в Catalog.
* Чтение данных с помощью Table Valued Functions.
* Чтение данных с помощью Broker Load.
* Запись данных при выполнении Export.
* Запись данных с помощью Outfile.

## Поддерживаемые форматы сжатия {#supported-compression-formats}

### Чтение {#reading}

При чтении существующих файлов поддерживаются следующие кодеки.

* uncompressed
* snappy
* lz4
* zstd
* gzip
* lzo
* brotli

### Запись {#writing}

| Точка входа для записи | Поддерживаемые кодеки |
| --- | --- |
| Hive / Iceberg Catalog | `plain`, `snappy`, `zstd`, `lz4` (начиная с версии 4.1.3), `gzip` (начиная с версии 4.2.0) |
| OUTFILE / EXPORT | `plain`, `snappy`, `gzip`, `brotli`, `zstd`, `lz4` |

`plain` означает отсутствие сжатия. Настройки записи в Catalog и значения по умолчанию приведены в разделах [Hive Catalog](../catalogs/hive-catalog.mdx) и [Iceberg Catalog](../catalogs/iceberg-catalog.mdx). OUTFILE / EXPORT выбирает кодек с помощью свойства `compress_type`.

## Параметры {#parameters}

### Совместимость временных меток и дат (начиная с версии 4.1.5) {#timestamp-and-date-compatibility}

Начиная с версии 4.1.5 операции чтения и записи Parquet сохраняют различие между локальным временем и моментами времени. Логическая временная метка без часового пояса сопоставляется с `DATETIME`, а логическая временная метка с `isAdjustedToUTC=true` — с `TIMESTAMPTZ`. Ни свойство совместимости Catalog, ни `enable_mapping_timestamp_tz=false` в файловой TVF не могут восстановить для последней отображение в `DATETIME`.

Parquet INT96 не содержит аннотации часового пояса и при выводе схемы определяется как `DATETIME(6)`. Hive Catalog и файловые TVF поддерживают необязательное свойство `hive.parquet.time-zone` для указания часового пояса, использованного при записи INT96. По умолчанию используется пустая строка, сохраняющая локальное время. Используйте часовой пояс IANA или смещение UTC от `-12:00` до `+14:00`. Значения `UTC` и `GMT` принимаются; короткие псевдонимы, такие как `CST` и `PRC`, отклоняются. Указывайте это свойство только если часовой пояс средства записи известен, например, `"hive.parquet.time-zone" = "Asia/Shanghai"`.

Начиная с версии 4.1.5 в Outfile и Export параметр `enable_int96_timestamps` имеет значение `false` по умолчанию; эти функции записывают логические временные метки INT64. Устанавливайте его в `true` только для потребителей, которым требуется INT96. Запись таблиц Hive использует другой вариант совместимости; см. [Hive Catalog](../catalogs/hive-catalog.mdx).

Файлы DATE, записанные с использованием старой кодировки Doris и содержащие даты от `0000-01-01` до `0000-02-28`, требуют миграции с учётом средства записи. Одного обновления Reader недостаточно для их исправления. См. раздел [Миграция файлов DATE с нулевым годом](../../admin-manual/cluster-management/upgrade.md#year-zero-date-file-migration).

### Переменные сеанса {#session-variables}

* `enable_parquet_lazy_mat` (2.1+, 3.0+)

    Определяет, включает ли Parquet Reader ленивую материализацию. По умолчанию — true.

* `hive_parquet_use_column_names` (2.1.6+, 3.0.3+)

    При чтении типов данных Parquet из таблиц Hive Doris по умолчанию читает данные из столбцов файла Parquet, имена которых совпадают с именами столбцов таблицы Hive. Если для этой переменной задано значение `false`, Doris читает данные из файла Parquet в соответствии с порядком столбцов в таблице Hive, независимо от имён столбцов. Это аналогично переменной `parquet.column.index.access` в Hive. Параметр применяется только к именам столбцов верхнего уровня и не действует для столбцов внутри Struct.

### Конфигурация BE {#be-configuration}

* `parquet_metadata_size_limit` (начиная с версии 4.1.5)

    Максимальный размер сериализованных метаданных Footer для нативного Parquet V2 Reader. По умолчанию — `268435456` байт (256 MiB); значение должно быть больше `0`, поддерживается динамическое изменение. Это ограничение отдельно от ограничения Page Header. При превышении возвращается ошибка `Parquet v2 footer size ... exceeds metadata limit ...`. См. [Конфигурация BE](../../admin-manual/config/be-config.md#parquet_metadata_size_limit).

* `enable_parquet_page_index` (2.1.5+, 3.0+)

    Определяет, использует ли Parquet Reader Page Index для фильтрации данных. Параметр предназначен только для отладки на случай, если индекс страниц иногда ошибочно фильтрует данные. Значение по умолчанию — false.

* `parquet_header_max_size_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении заголовка Page header в Parquet. По умолчанию — 1M.

* `parquet_rowgroup_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении Parquet Row Group. По умолчанию — 128M.

* `parquet_column_max_buffer_mb` (2.1+, 3.0+)

    Максимальный размер буфера, выделяемого при чтении Column в Parquet Row Group. По умолчанию — 8M.
