# ORC {#orc}

В этом документе описывается поддержка чтения и записи файлов формата ORC в Doris. Она применяется к следующим функциям:

* Чтение и запись данных в Catalog.
* Чтение данных с помощью Table Valued Functions.
* Чтение данных с помощью Broker Load.
* Запись данных во время Export.
* Запись данных с помощью Outfile.

## Поддерживаемые форматы сжатия {#supported-compression-formats}

### Чтение {#reading}

При чтении существующих файлов поддерживаются следующие кодеки.

* uncompressed
* snappy
* lz4
* zstd
* lzo
* zlib

### Запись {#writing}

| Точка входа записи | Поддерживаемые кодеки |
| --- | --- |
| Hive / Iceberg Catalog | `plain`, `snappy`, `zlib`, `zstd`, `lz4` (начиная с 4.1.3) |
| OUTFILE / EXPORT | `plain`, `snappy`, `zlib`, `zstd` |

Значение `plain` означает отсутствие сжатия. Конфигурацию и значения по умолчанию для записи в Catalog см. в разделах [Hive Catalog](../catalogs/hive-catalog.mdx) и [Iceberg Catalog](../catalogs/iceberg-catalog.mdx). OUTFILE / EXPORT выбирает кодек с помощью свойства `compress_type`.

## Параметры {#parameters}

### Совместимость временных меток и дат (начиная с 4.1.5) {#timestamp-and-date-compatibility-since-415}

Начиная с версии 4.1.5, ORC `TIMESTAMP` представляет календарное время без часового пояса, а `TIMESTAMP_INSTANT` представляет момент времени и сопоставляется с `TIMESTAMPTZ`. При чтении точность наносекунд округляется до микросекунд. Значения вне допустимого диапазона и некорректные значения наносекунд вызывают ошибки.

При записи ORC некоторые отрицательные дробные значения временных меток непосредственно перед эпохой Unix невозможно представить без потери данных. Doris возвращает сообщение `ORC cannot represent pre-epoch timestamp fractions in [-0.999, 0) seconds without data loss; use Parquet for these values`. Для данных, содержащих такие значения, используйте Parquet.

DATE-файлы, записанные с использованием старой кодировки Doris и содержащие даты от `0000-01-01` до `0000-02-28`, требуют явной миграции. См. раздел [Миграция DATE-файлов нулевого года](../../admin-manual/cluster-management/upgrade.md#year-zero-date-file-migration).

### Переменные сеанса {#session-variables}

* `enable_orc_lazy_mat` (2.1+, 3.0+)

    Определяет, включает ли ORC Reader отложенную материализацию. По умолчанию — true.

* `hive_orc_use_column_names` (2.1.6+, 3.0.3+)

    При чтении типов данных ORC из таблиц Hive Doris по умолчанию читает данные из столбцов ORC-файла, имена которых совпадают с именами столбцов таблицы Hive. Если для этой переменной задано значение `false`, Doris читает данные из ORC-файла в соответствии с порядком столбцов в таблице Hive, независимо от их имен. Это аналогично переменной `orc.force.positional.evolution` в Hive. Этот параметр действует только для имен столбцов верхнего уровня и не работает для столбцов внутри Struct.

* `orc_tiny_stripe_threshold_bytes` (2.1.8+, 3.0.3+)

    В ORC-файлах, если размер Stripe в байтах меньше `orc_tiny_stripe_threshold`, такой Stripe считается Tiny Stripe. Для нескольких идущих подряд Tiny Stripe выполняется оптимизация чтения: несколько Tiny Stripe читаются за один раз, чтобы уменьшить число операций IO. Если эта оптимизация не нужна, установите значение 0. По умолчанию — 8M.

* `orc_once_max_read_bytes` (2.1.8+, 3.0.3+)

    При использовании оптимизации чтения Tiny Stripe несколько Tiny Stripe объединяются в одну операцию IO. Этот параметр задает максимальное число байт для каждого запроса IO. Не следует задавать значение меньше `orc_tiny_stripe_threshold`. По умолчанию — 8M.

* `orc_max_merge_distance_bytes` (2.1.8+, 3.0.3+)

    При оптимизации чтения Tiny Stripe два читаемых Tiny Stripe могут быть расположены не подряд. Если расстояние между ними превышает это значение, они не объединяются в одну операцию IO. По умолчанию — 1M.

* `orc_tiny_stripe_amplification_factor` (3.1.0+)

    При оптимизации Tiny Stripe, если в ORC-файле много столбцов, а в запросе используется лишь несколько, она может привести к значительному усилению чтения. Если доля фактически читаемых байт от общего размера Stripe превышает это значение, используется оптимизация чтения Tiny Stripe. Значение по умолчанию — 0.4, минимальное значение — 0.

* `check_orc_init_sargs_success` (3.1.0+)

    Проверяет, успешно ли выполнено проталкивание предикатов ORC; используется для отладки. По умолчанию — false.

### Конфигурация BE {#be-configuration}

* `orc_natural_read_size_mb` (2.1+, 3.0+)

    Максимальное число байт, которое ORC Reader читает за один раз. По умолчанию — 8 MB.
