[Doris Streamloader](https://github.com/apache/doris-streamloader) — специализированный клиентский инструмент для загрузки данных в базу данных Apache Doris. По сравнению с однопоточным импортом напрямую через `curl` этот инструмент поддерживает параллельный импорт и значительно сокращает время загрузки больших объёмов данных.

## Основные возможности {#core-features}

| Возможность | Описание |
|---|---|
| Параллельный импорт | Выполняет Stream Load с несколькими параллельными рабочими процессами. Уровень параллелизма задаётся параметром `workers` |
| Импорт нескольких файлов | Импортирует несколько файлов и каталогов в рамках одной задачи. Поддерживает сопоставление по шаблону и автоматически рекурсивно обходит все файлы в каталоге |
| Возобновление передачи | Если во время импорта происходит частичный сбой, инструмент может продолжить работу с места сбоя |
| Автоматический повтор | После сбоя импорта повторный запуск вручную не требуется. Инструмент автоматически выполняет повтор до числа раз по умолчанию. Если попытки по-прежнему завершаются ошибкой, он выводит команду для повторного запуска вручную |

## Сценарии использования {#use-cases}

- Пакетная загрузка больших объёмов данных (от GB до TB) в Doris
- Пакетный импорт нескольких файлов и каталогов
- Сценарии, чувствительные к задержке импорта, где для увеличения пропускной способности требуется параллельная обработка
- Стабильные процессы импорта, требующие возобновления передачи и автоматического восстановления после сбоев

## Использование {#usage}

### Основной формат команды {#basic-command-format}

```shell
doris-streamloader \
    --source_file={FILE_LIST} \
    --url={FE_OR_BE_SERVER_URL}:{PORT} \
    --header={STREAMLOAD_HEADER} \
    --db={TARGET_DATABASE} \
    --table={TARGET_TABLE}
```

### Обязательные параметры {#required-parameters}

| Параметр | Значение |
|---|---|
| `--source_file` | Список файлов данных для импорта. Поддерживаются отдельный файл, каталог, шаблоны и список, разделённый запятыми |
| `--url` | Адрес службы Doris FE или BE в формате `http://host:port` |
| `--header` | Параметры заголовка Stream Load. Несколько параметров разделяются символом `?` |
| `--db` | Имя целевой базы данных |
| `--table` | Имя целевой таблицы |

### Форматы, поддерживаемые `source_file` {#formats-supported-by-source_file}

Параметр `--source_file` поддерживает следующие пять форматов. Выберите подходящий вариант в зависимости от сценария.

#### 1. Один файл {#1-a-single-file}

Например, для импорта одного файла `file.csv`:

```shell
doris-streamloader --source_file="file.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 2. Один каталог {#2-a-single-directory}

Например, для импорта каталога `dir`:

```shell
doris-streamloader --source_file="dir" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 3. Имя файла с шаблонами (необходимо заключить в кавычки) {#3-a-file-name-with-wildcards-must-be-quoted}

Например, для импорта `file0.csv`, `file1.csv` и `file2.csv`:

```shell
doris-streamloader --source_file="file*" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 4. Список имён файлов, разделённых запятыми {#4-a-comma-separated-list-of-file-names}

Например, для импорта `file0.csv`, `file1.csv` и `file2.csv`:

```shell
doris-streamloader --source_file="file0.csv,file1.csv,file2.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

#### 5. Список каталогов, разделённых запятыми {#5-a-comma-separated-list-of-directories}

Например, для импорта `dir1`, `dir2` и `dir3`:

```shell
doris-streamloader --source_file="dir1,dir2,dir3" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

### Параметр заголовка {#header-parameter}

`--header` поддерживает все параметры Stream Load. Несколько параметров разделяются символом `?`.

Пример:

```shell
doris-streamloader --source_file="data.csv" --url="http://localhost:8330" --header="column_separator:|?columns:col1,col2" --db="testdb" --table="testtbl"
```

## Необязательные параметры {#optional-parameters}

Помимо обязательных параметров, описанных выше, инструмент предоставляет ряд необязательных параметров для детальной настройки поведения импорта. В таблице ниже они сгруппированы по функциям.

### Аутентификация и передача данных {#authentication-and-transport}

| Параметр | Значение | По умолчанию | Рекомендация |
|---|---|---|---|
| `--u` | Имя пользователя базы данных | `root` | —— |
| `--p` | Пароль пользователя базы данных | Пустая строка | —— |
| `--compress` | Сжимать ли данные при передаче по HTTP | `false` | Сохраните значение по умолчанию. Включение сжатия увеличивает нагрузку на CPU инструмента и Doris BE при сжатии и распаковке. Включайте этот параметр только если узким местом является пропускная способность сети на компьютере с источником данных |
| `--timeout` | Тайм-аут HTTP-запросов, отправляемых в Doris, в секундах | `60*60*10` | Сохраните значение по умолчанию |

### Пакетная обработка и параллелизм {#batch-and-concurrency}

| Параметр | Значение | По умолчанию | Рекомендация |
|---|---|---|---|
| `--batch` | Размер пакета при чтении и отправке файлов, в строках | `4096` | Сохраните значение по умолчанию |
| `--batch_byte` | Размер пакета при чтении и отправке файлов, в байтах | `943718400` (900 MB) | Сохраните значение по умолчанию |
| `--workers` | Уровень параллелизма импорта | `0` | При значении `0` инструмент работает в автоматическом режиме и вычисляет значение на основе размера импортируемых данных, пропускной способности диска и скорости импорта Stream Load. Его также можно задать вручную. Для высокопроизводительных кластеров значение можно увеличить, но **желательно не более 10**. Если объём памяти при импорте слишком велик (это видно по журналам Memtracker или Exceed), значение можно уменьшить |
| `--disk_throughput` | Пропускная способность диска, в MB/s | `800` | Обычно сохраняйте значение по умолчанию. Этот параметр участвует в автоматическом расчёте `--workers`. Если нужно, чтобы инструмент вычислил подходящее число `workers`, задайте значение на основе фактической пропускной способности диска |
| `--streamload_throughput` | Фактическая пропускная способность импорта Stream Load, в MB/s | `100` | Обычно сохраняйте значение по умолчанию. Этот параметр участвует в автоматическом расчёте `--workers`. Значение по умолчанию получено в среде ежедневного тестирования производительности. Если нужно, чтобы инструмент вычислил подходящее число `workers`, задайте значение на основе измеренной пропускной способности, используя формулу: `(LoadBytes*1000) / (LoadTimeMs*1024*1024)` |
| `--max_byte_per_task` | Максимальный объём данных для одной задачи импорта. При превышении этого значения данные разделяются и передаются в новую задачу | `107374182400` (100 GB) | Рекомендуется большое значение, чтобы уменьшить число версий импорта. Однако при ошибке `body exceed max size`, если вы не хотите изменять `streaming_load_max_mb`, или при ошибке `-238 TOO MANY SEGMENT` значение можно временно уменьшить |

### Проверка данных и журналы {#data-validation-and-logs}

| Параметр | Значение | По умолчанию | Рекомендация |
|---|---|---|---|
| `--check_utf8` | Проверять ли кодировку импортируемых данных: `false` пропускает проверку и импортирует исходные данные; `true` заменяет символы, не относящиеся к UTF-8, на `�` | `true` | Сохраните значение по умолчанию |
| `--debug` | Выводить ли отладочные журналы | `false` | Сохраните значение по умолчанию |
| `--log_filename` | Место хранения журналов | `""` | По умолчанию журналы выводятся в консоль. Чтобы записывать их в файл, укажите путь, например `--log_filename="/var/log"` |

### Повтор после сбоя {#failure-retry}

| Параметр | Значение | По умолчанию | Рекомендация |
|---|---|---|---|
| `--auto_retry` | Список номеров worker и task для автоматического повтора | Пустая строка | Используйте этот параметр только при сбое импорта. При обычном импорте задавать его не нужно. При сбое выводятся конкретные значения параметра — просто скопируйте и выполните их. Например, `--auto_retry="1,1,2,1"` означает, что нужно повторить первую задачу первого worker и первую задачу второго worker |
| `--auto_retry_times` | Число автоматических повторов | `3` | Сохраните значение по умолчанию. Чтобы отключить повторы, задайте `0` |
| `--auto_retry_interval` | Интервал между автоматическими повторами, в секундах | `60` | Сохраните значение по умолчанию. Если сбои вызваны недоступностью Doris, задайте интервал с учётом фактического времени перезапуска |

## Результат {#result}

Независимо от успешного или неуспешного завершения импорта инструмент выводит итоговый результат.

### Поля результата {#result-fields}

| Поле | Описание |
|---|---|
| `Status` | Состояние импорта. `Success` означает успешное завершение, `Failed` — сбой |
| `TotalRows` | Общее число строк в файлах, предназначенных для импорта |
| `FailLoadRows` | Число строк, которые планировалось импортировать, но импортировать не удалось |
| `LoadedRows` | Число строк, фактически импортированных в Doris |
| `FilteredRows` | Число строк, отфильтрованных Doris во время импорта |
| `UnselectedRows` | Число строк, проигнорированных Doris во время импорта |
| `LoadBytes` | Число фактически импортированных байтов |
| `LoadTimeMs` | Фактическая длительность импорта, в миллисекундах |
| `LoadFiles` | Список фактически импортированных файлов |

### Пример успешного завершения {#success-example}

При успешном импорте вывод выглядит следующим образом:

```Go
Load Result: {
        "Status": "Success",
        "TotalRows": 120,
        "FailLoadRows": 0,
        "LoadedRows": 120,
        "FilteredRows": 0,
        "UnselectedRows": 0,
        "LoadBytes": 40632,
        "LoadTimeMs": 971,
        "LoadFiles": [
                "basic.csv",
                "basic_data1.csv",
                "basic_data2.csv",
                "dir1/basic_data.csv",
                "dir1/basic_data.csv.1",
                "dir1/basic_data1.csv"
        ]
}
```

### Пример сбоя {#failure-example}

Если часть данных не импортирована, инструмент сначала выводит команду для повтора:

```Go
load has some error, and auto retry failed, you can retry by :
./doris-streamloader --source_file /mnt/disk1/laihui/doris/tools/tpch-tools/bin/tpch-data/lineitem.tbl.1  --url="http://127.0.0.1:8239" --header="column_separator:|?columns: l_orderkey, l_partkey, l_suppkey, l_linenumber, l_quantity, l_extendedprice, l_discount, l_tax, l_returnflag,l_linestatus, l_shipdate,l_commitdate,l_receiptdate,l_shipinstruct,l_shipmode,l_comment,temp" --db="db" --table="lineitem1" -u root -p "" --compress=false --timeout=36000 --workers=3 --batch=4096 --batch_byte=943718400 --max_byte_per_task=1073741824 --check_utf8=true --report_duration=1 --auto_retry="2,1;1,1;0,1" --auto_retry_times=0 --auto_retry_interval=60
```

Скопируйте и выполните эту команду, чтобы повторить импорт вручную. Значение `auto_retry` описано в разделе параметров выше. Затем выводится результат сбоя:

```Go
Load Result: {
      "Status": "Failed",
      "TotalRows": 1,
      "FailLoadRows": 1,
      "LoadedRows": 0,
      "FilteredRows": 0,
      "UnselectedRows": 0,
      "LoadBytes": 0,
      "LoadTimeMs": 104,
      "LoadFiles": [
              "/mnt/disk1/laihui/doris/tools/tpch-tools/bin/tpch-data/lineitem.tbl.1"
      ]
}
```

## Рекомендации по использованию {#best-practices}

### Рекомендуемые параметры {#recommended-parameters}

1. **Обязательные параметры**: необходимо настроить следующие параметры:

    ```text
    --source_file=FILE_LIST
    --url=FE_OR_BE_SERVER_URL_WITH_PORT
    --header=STREAMLOAD_HEADER
    --db=TARGET_DATABASE
    --table=TARGET_TABLE
    ```

    **Для импорта нескольких файлов используйте `source_file`.**

2. **`workers`**: значение по умолчанию равно `0`, что включает автоматический режим (инструмент вычисляет значение на основе размера импорта, `disk_throughput` и `streamload_throughput`; обычно результатом становится 1, 2, 4 или 8). Значение также можно задать вручную — для высокопроизводительных кластеров его можно увеличить, но **рекомендуется не более 10**. **Обычно вручную задают `8`**.

3. **`max_byte_per_task`**: большее значение уменьшает число версий импорта. Однако при ошибке `body exceed max size`, если вы не хотите изменять `streaming_load_max_mb`, или при ошибке `-238 TOO MANY SEGMENT` это значение можно временно уменьшить. **Обычно достаточно значения по умолчанию.**

4. **Два ключевых параметра, влияющих на число версий**:

    | Параметр | Влияние | Рекомендация |
    |---|---|---|
    | `workers` | Чем больше worker, тем больше версий и выше параллелизм | Обычно используйте `8` |
    | `max_byte_per_task` | Чем больше значение, тем больше данных в одной версии и тем меньше версий, но слишком большое значение может вызвать `-238 TOO MANY SEGMENT` | Обычно используйте значение по умолчанию |

### Рекомендуемая команда {#recommended-command}

Для большинства сценариев достаточно задать обязательные параметры и установить `workers` равным `8`:

```shell
./doris-streamloader \
    --source_file="demo.csv,demoFile*.csv,demoDir" \
    --url="http://127.0.0.1:8030" \
    --header="column_separator:," \
    --db="demo" \
    --table="test_load" \
    --u="root" \
    --workers=8
```

## FAQ {#faq}

### 1. Что делать, если во время импорта не удаётся выполнить некоторые подзадачи? {#1-what-should-i-do-if-some-subtasks-fail-during-import}

Инструмент автоматически выполняет повтор. Если повторные попытки также завершаются ошибкой, он выводит команду для повтора вручную. Скопируйте и выполните её. Удалять таблицу и импортировать данные заново не требуется.

### 2. Что делать, если один импорт превышает порог `streaming_load_max_mb` по умолчанию для BE? {#2-what-if-a-single-import-exceeds-the-be-default-streaming_load_max_mb-threshold}

Ограничение инструмента по умолчанию для одной задачи составляет 100 GB, что соответствует значению `streaming_load_max_mb` в исходном коде по умолчанию — 102400 MB — в Doris 3.0.2 и более поздних версиях (в серии 2.1 — в версии 2.1.7 и более поздних). Ограничение BE по умолчанию составляет 10 GB в Doris 3.0.0 и 3.0.1 и 100 GB в версиях 4.x и dev. Фактическая конфигурация BE может отличаться. Если задача превышает действующее ограничение, уменьшите `--max_byte_per_task`, чтобы разделить её на меньшие пакеты, или попросите администратора изменить динамически настраиваемый параметр `streaming_load_max_mb`. Перезапуск BE не требуется.

Пользователи с привилегией ADMIN_PRIV могут проверить фактическую конфигурацию на каждом BE с помощью SQL. В управляемых облачных службах используйте механизм настройки, предоставляемый службой, или обратитесь к администратору; прямой доступ к хосту BE не требуется:

```sql
SHOW BACKEND CONFIG LIKE 'streaming_load_max_mb';
```

### 3. Что делать при ошибке `-238 TOO MANY SEGMENT`? {#3-what-should-i-do-when-the--238-too-many-segment-error-occurs}

Уменьшение параметра `--max_byte_per_task` помогает устранить эту проблему.
