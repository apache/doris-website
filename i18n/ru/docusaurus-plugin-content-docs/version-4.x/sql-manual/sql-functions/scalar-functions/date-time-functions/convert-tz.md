## Описание {#description}

Преобразует значение datetime из заданного часового пояса from_tz в заданный часовой пояс to_tz и возвращает результат. Подробнее о настройках часового пояса см. в документации [Управление часовыми поясами](../../../../admin-manual/cluster-management/time-zone).

Поведение этой функции соответствует поведению [функции convert_tz](https://dev.mysql.com/doc/refman/8.4/en/date-and-time-functions.html#function_convert_tz) в MySQL.

## Синтаксис {#syntax}

```sql
CONVERT_TZ(<dt>, <from_tz>, <to_tz>)
```

## Параметры {#parameters}

| Параметр | Описание |
| -- | -- | 
| `<dt>` | Преобразуемое значение типа datetime или date. Подробнее о форматах datetime и date см. в разделах [Преобразование datetime](../../../../sql-manual/basic-element/sql-data-types/conversion/datetime-conversion) и [Преобразование date](../../../../sql-manual/basic-element/sql-data-types/conversion/date-conversion) |
| `<from_tz>` | Исходный часовой пояс dt. Параметр имеет тип `varchar` |
| `<to_tz>` | Целевой часовой пояс, в который выполняется преобразование. Параметр имеет тип `varchar` |

## Возвращаемое значение {#return-value}

- Преобразованное значение типа datetime
- Точность дробной части результата совпадает с точностью дробной части входного значения
  - Если для входного значения datetime точность дробной части не задана, она не задаётся и для результата
  - Если для входного значения задана точность дробной части, результат имеет ту же точность

Особые случаи:
- Если какой-либо параметр равен NULL, возвращается NULL.
- Если входной часовой пояс недопустим, возвращается ошибка. Подробнее о настройках часового пояса см. в разделе [Управление часовыми поясами](../../../../admin-manual/cluster-management/time-zone).
- Для входного значения типа date временная часть автоматически преобразуется в 00:00:00

## Примеры {#examples}


```sql
-- Convert time from Shanghai, China to Los Angeles, USA
mysql> select CONVERT_TZ(CAST('2019-08-01 13:21:03' AS DATETIME), 'Asia/Shanghai', 'America/Los_Angeles');
+---------------------------------------------------------------------------+
| CONVERT_TZ('2019-08-01 13:21:03', 'Asia/Shanghai', 'America/Los_Angeles') |
+---------------------------------------------------------------------------+
| 2019-07-31 22:21:03                                                       |
+---------------------------------------------------------------------------+

-- Convert the time '2019-08-01 13:21:03' in UTC+8 (+08:00) to Los Angeles, USA
mysql> select CONVERT_TZ(CAST('2019-08-01 13:21:03' AS DATETIME), '+08:00', 'America/Los_Angeles');

+--------------------------------------------------------------------+
| convert_tz('2019-08-01 13:21:03', '+08:00', 'America/Los_Angeles') |
+--------------------------------------------------------------------+
| 2019-07-31 22:21:03                                                |
+--------------------------------------------------------------------+

-- For date type input,return datetime type value, the time part is automatically converted to 00:00:00
mysql> select CONVERT_TZ(CAST('2019-08-01 13:21:03' AS DATE), 'Asia/Shanghai', 'America/Los_Angeles');
+-------------------------------------------------------------------------------------------+
| CONVERT_TZ(CAST('2019-08-01 13:21:03' AS DATE), 'Asia/Shanghai', 'America/Los_Angeles')   |
+-------------------------------------------------------------------------------------------+
| 2019-07-31 09:00:00                                                                       |
+-------------------------------------------------------------------------------------------+

-- When conversion time is NULL, output NULL
mysql> select CONVERT_TZ(NULL, 'Asia/Shanghai', 'America/New_York');
+-------------------------------------------------------+
| CONVERT_TZ(NULL, 'Asia/Shanghai', 'America/New_York') |
+-------------------------------------------------------+
| NULL                                                  |
+-------------------------------------------------------+

-- When any time zone is NULL, return NULL
mysql> select CONVERT_TZ('2019-08-01 13:21:03', NULL, 'America/Los_Angeles');
+----------------------------------------------------------------+
| CONVERT_TZ('2019-08-01 13:21:03', NULL, 'America/Los_Angeles') |
+----------------------------------------------------------------+
| NULL                                                           |
+----------------------------------------------------------------+

mysql> select CONVERT_TZ('2019-08-01 13:21:03', '+08:00', NULL);
+---------------------------------------------------+
| CONVERT_TZ('2019-08-01 13:21:03', '+08:00', NULL) |
+---------------------------------------------------+
| NULL                                              |
+---------------------------------------------------+

-- Time with scale
mysql> select CONVERT_TZ('2019-08-01 13:21:03.636', '+08:00', 'America/Los_Angeles');
+------------------------------------------------------------------------+
| CONVERT_TZ('2019-08-01 13:21:03.636', '+08:00', 'America/Los_Angeles') |
+------------------------------------------------------------------------+
| 2019-07-31 22:21:03.636                                                |
+------------------------------------------------------------------------+

-- When the input time zone is invalid, an error is returned.
select CONVERT_TZ(CAST('2019-08-01 13:21:03' AS DATETIME), '+08:00', 'America/Los_Anges');
ERROR 1105 (HY000): errCode = 2, detailMessage = (10.16.10.3)[INVALID_ARGUMENT][E33] Operation convert_tz invalid timezone: America/Los_Anges
```
