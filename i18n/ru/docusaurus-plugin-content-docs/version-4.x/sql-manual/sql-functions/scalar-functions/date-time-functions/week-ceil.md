## Описание {#description}


Функция week_ceil округляет входное значение даты и времени вверх до ближайшего времени начала заданного недельного интервала. Если указан origin, он используется как точка отсчёта; в противном случае по умолчанию используется 0001-01-01 00:00:00.

Формула расчёта даты:
$$
\begin{aligned}
&\text{week\_ceil}(\langle\text{date\_or\_time\_expr}\rangle, \langle\text{period}\rangle, \langle\text{origin}\rangle) = \\
&\min\{\langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{week} \mid \\
&k \in \mathbb{Z} \land \langle\text{origin}\rangle + k \times \langle\text{period}\rangle \times \text{week} \geq \langle\text{date\_or\_time\_expr}\rangle\}
\end{aligned}
$$
$k$ обозначает количество периодов, необходимых для достижения целевого времени от точки отсчёта.

## Синтаксис {#syntax}

```sql
WEEK_CEIL(<date_or_time_expr>)
WEEK_CEIL(<date_or_time_expr>, <origin>)
WEEK_CEIL(<date_or_time_expr>, <period>)
WEEK_CEIL(<date_or_time_expr>, <period>, <origin>)
```

## Параметры {#parameters}

| Параметр | Описание |
|-----------|-------------|
| `<date_or_time_expr>` | Значение даты и времени для округления вверх; поддерживаются типы date/datetime/timestamptz. Значение типа date преобразуется во время начала соответствующей даты — 00:00:00. Подробную информацию о форматах см. в разделе [преобразование timestamptz](../../../../sql-manual/basic-element/sql-data-types/conversion/timestamptz-conversion), а о форматах datetime/date — в разделах [преобразование datetime](../../../../sql-manual/basic-element/sql-data-types/conversion/datetime-conversion) и [преобразование date](../../../../sql-manual/basic-element/sql-data-types/conversion/date-conversion) |
| `<period>` | Величина недельного интервала типа INT, определяющая количество недель в каждом интервале |
| `<origin>` | Начальная точка отсчёта интервалов; поддерживаются типы date/datetime; значение по умолчанию — 0001-01-01 00:00:00 |

## Возвращаемое значение {#return-value}

Возвращает TIMESTAMPTZ, DATETIME или DATE — округлённое вверх значение даты и времени.

- Если входное значение не равно NULL, а `<period>` неположителен (≤0), функция возвращает ошибку;
- Если какой-либо параметр равен NULL, возвращает NULL;
- Если `<datetime>` точно совпадает с началом интервала (определяемым по `<period>` и `<origin>`), возвращает эту начальную точку;
- Если входное значение имеет тип date, возвращает значение типа date
- Если входное значение имеет тип datetime, возвращает значение типа datetime с той же временной частью, что и у точки отсчёта.
- Если результат вычисления превышает максимальное значение даты и времени 9999-12-31 23:59:59, возвращает ошибку.
- Если дата и время `<origin>` позже `<date_or_time_expr>`, вычисление всё равно выполняется по приведённой выше формуле, но количество периодов k будет отрицательным.
- Если для `date_or_time_expr` задан масштаб, результат сохраняет соответствующую точность. Если `origin` содержит доли секунды, границы интервалов сохраняют эту дробную часть. В ветке Doris 4.1 начиная с 4.1.5 при сравнении границ недель учитываются микросекунды, что исправляет округление в случаях, когда входное значение и `origin` различаются только долями секунды.
- Если входное значение имеет тип TIMESTAMPTZ, оно сначала преобразуется в local_time (например, `2025-12-31 23:59:59+05:00` соответствует local_time `2026-01-01 02:59:59`, когда переменная сеанса равна `+08:00`), после чего выполняется вычисление CEIL.
- Если входные значения времени (`<date_or_time_expr>` и `<origin>`) имеют разные типы — TIMESTAMPTZ и DATETIME, результат имеет тип DATETIME.

## Пример {#example}

```sql
-- 2023-07-13 is Thursday, rounds up to next interval start (1-week interval starts on Monday, so rounds to 2023-07-17 (Monday))
SELECT WEEK_CEIL(cast('2023-07-13 22:28:18' as datetime)) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-17 00:00:00 |
+---------------------+
```

```sql
-- Specify 2-week interval
SELECT WEEK_CEIL('2023-07-13 22:28:18', 2) AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-24 00:00:00 |
+---------------------+
```

```sql
-- Input date type returns date type, date string returns datetime
SELECT WEEK_CEIL(cast('2023-07-13' as date));
```

```text
+---------------------------------------+
| WEEK_CEIL(cast('2023-07-13' as date)) |
+---------------------------------------+
| 2023-07-17                            |
+---------------------------------------+
```

```sql
--input with decimal part 
SELECT WEEK_CEIL('2023-07-13 22:28:18.123', 2) AS result;
```

```text
+-------------------------+
| result                  |
+-------------------------+
| 2023-07-24 00:00:00.000 |
+-------------------------+
```

```sql
-- Only with origin date and specified date
select week_ceil("2023-07-13 22:28:18", "2021-05-01 12:00:00");
```

```text
+---------------------------------------------------------+
| week_ceil("2023-07-13 22:28:18", "2021-05-01 12:00:00") |
+---------------------------------------------------------+
| 2023-07-15 12:00:00                                     |
+---------------------------------------------------------+
```

```sql
-- Specify origin date
SELECT WEEK_CEIL('2023-07-13', 1, '2023-07-03') AS result;
```

```text
+---------------------+
| result              |
+---------------------+
| 2023-07-17 00:00:00 |
+---------------------+
```

```sql
-- TimeStampTz sample, SET time_zone = '+08:00'
-- Convert to local_time (2026-01-01 02:59:59) and then perform WEEK_CEIL
SELECT WEEK_CEIL('2025-12-31 23:59:59+05:00');
```

```text
+----------------------------------------+
| WEEK_CEIL('2025-12-31 23:59:59+05:00') |
+----------------------------------------+
| 2026-01-05 00:00:00+08:00              |
+----------------------------------------+
```

```sql
-- If parameters contain both TimeStampTz and Datetime types, output DateTime type
SELECT WEEK_CEIL('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123');
```

```text
+-------------------------------------------------------------------+
| WEEK_CEIL('2025-12-31 23:59:59+05:00', '2025-12-15 00:00:00.123') |
+-------------------------------------------------------------------+
| 2026-01-05 00:00:00.123                                           |
+-------------------------------------------------------------------+
```

```sql
-- Invalid period (non-positive integer)
SELECT WEEK_CEIL('2023-07-13', 0) AS result;
```

```text
ERROR 1105 (HY000): errCode = 2, detailMessage = (10.16.10.3)[E-218]Operation week_ceil of 2023-07-13 00:00:00, 0 out of range
```

```sql
-- Parameter is NULL
SELECT WEEK_CEIL(NULL, 1) AS result;
```

```text
+--------+
| result |
+--------+
| NULL   |
+--------+
```

Входное значение, точно совпадающее с границей интервала, остаётся без изменений:

```sql
SELECT WEEK_CEIL('2023-07-24 00:00:00', 2);
```

```text
2023-07-24 00:00:00
```

Границы недель при точке отсчёта с микросекундами (исправлено в ветке Doris 4.1 начиная с 4.1.5):

```sql
SELECT WEEK_CEIL(CAST('2024-01-08 00:00:00.600000' AS DATETIME(6)),
                   1, CAST('2024-01-01 00:00:00.500000' AS DATETIME(6)));
```

```text
2024-01-15 00:00:00.500000
```
