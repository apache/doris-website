## Описание {#description}

Система Proc представляет собой уникальную возможность Doris. Тем, кто работал с Linux, эта концепция может быть понятнее. В системах Linux proc представляет собой виртуальную файловую систему, которая обычно монтируется в каталоге /proc. Через эту файловую систему пользователи могут просматривать внутренние структуры данных системы. Например, сведения о процессе с указанным pid можно просмотреть через /proc/pid.

Как и система proc в Linux, система proc в Doris организована в виде структуры каталогов. Это позволяет просматривать различные сведения о системе по указанному пользователем «пути к каталогу (пути proc)».

Система proc предназначена прежде всего для системных администраторов и позволяет удобно просматривать внутреннее состояние работающей системы: состояние tablet таблицы, балансировку кластера, состояние различных заданий и другие сведения. Это очень полезная возможность.

Просматривать систему proc в Doris можно двумя способами.

1. Через веб-интерфейс Doris по адресу: `http://FE_IP:FE_HTTP_PORT`
2. С помощью команды

Все команды, поддерживаемые Doris PROC, можно просмотреть с помощью ` SHOW PROC "/";`

После подключения к Doris через клиент MySQL можно выполнить оператор SHOW PROC, чтобы просмотреть сведения об указанном каталоге proc. Каталог proc задаётся абсолютным путём, начинающимся с "/".

Результаты оператора show proc представлены в виде двумерной таблицы. Обычно первый столбец этой таблицы содержит имена подкаталогов proc следующего уровня.

```none
mysql> show proc "/";
+---------------------------+
| name                      |
+---------------------------+
| auth                      |
| backends                  |
| bdbje                     |
| brokers                   |
| catalogs                  |
| cluster_balance           |
| cluster_health            |
| colocation_group          |
| current_backend_instances |
| current_queries           |
| current_query_stmts       |
| dbs                       |
| diagnose                  |
| frontends                 |
| jobs                      |
| load_error_hub            |
| monitor                   |
| resources                 |
| routine_loads             |
| statistic                 |
| stream_loads              |
| tasks                     |
| transactions              |
| trash                     |
+---------------------------+
23 rows in set (0.00 sec)
```

Пояснения:

1. auth: имя пользователя и сведения о соответствующих правах доступа.
2. backends: отображает список узлов BE в кластере; эквивалентно [SHOW BACKENDS](../cluster-management/instance-management/SHOW-BACKENDS).
3. bdbje: чтобы просмотреть список баз данных bdbje, добавьте в файл `fe.conf` параметр `enable_bdbje_debug_mode=true`, а затем запустите `FE` командой `sh start_fe.sh --daemon`, чтобы перейти в режим `debug`. После перехода в режим `debug` запускаются только `http server` и `MySQLServer` и открывается экземпляр `BDBJE`; загрузка метаданных и последующие этапы запуска не выполняются.
4. binlog: просмотр сведений о binlog, включая количество записей binlog, размер binlog в байтах, временной диапазон binlog и другие сведения.
5. brokers : просмотр сведений об узлах broker кластера; эквивалентно [SHOW BROKER](../cluster-management/instance-management/SHOW-BROKER).
6. catalogs : просмотр созданных объектов Catalog; эквивалентно [SHOW CATALOGS](../catalog/SHOW-CATALOG.md).
7. cluster_balance : проверка балансировки кластера. Подробнее см. в разделе [Управление репликами данных](../../../admin-manual/maint-monitor/tablet-repair-and-balance.md).
8. cluster_health: выполните оператор <code>SHOW PROC '/cluster_health/tablet_health';</code>, чтобы просмотреть состояние реплик во всём кластере.
9. colocation_group : эта команда позволяет просмотреть сведения о существующих группах в кластере. Подробнее см. в разделе [Colocation Join](../../../query-acceleration/colocation-join).
10. current_backend_instances : отображает список узлов be, которые в данный момент выполняют задания.
11. current_queries : просмотр списка выполняемых запросов со статистикой времени выполнения, включая ход выполнения задач и показатели ресурсов (сканирование/CPU/память/shuffle/spill/кэш). Начиная с 4.1.1 здесь представлено то же расширенное представление, что и в `current_query_stmts`.
12. current_query_stmts: возвращает выполняемый запрос с тем же представлением статистики, что и `current_queries`, включая ход выполнения отдельных задач и показатели ресурсов.
13. dbs: используется главным образом для просмотра метаданных каждой базы данных и таблиц в кластере Doris. Эти сведения включают структуру таблиц, разделы, материализованные представления, шарды данных, реплики и многое другое. Этот каталог и его подкаталоги позволяют наглядно просматривать метаданные таблиц кластера и находить такие проблемы, как неравномерное распределение данных, сбои реплик и т. д.
14. diagnose: выявление и диагностика распространённых проблем управления кластером, включая балансировку и перенос реплик, ошибки транзакций и т. д.
15. frontends: отображает сведения обо всех узлах FE в кластере, включая IP-адрес, роль, состояние, признак ведущего узла и т. д.; эквивалентно [SHOW FRONTENDS](../cluster-management/instance-management/SHOW-FRONTENDS).
16. jobs: отображает статистику заданий всех типов. Если задан конкретный `dbId`, возвращается статистика соответствующей базы данных. Если `dbId` равен -1, возвращается суммарная статистика по всем базам данных.
17. load_error_hub: Doris поддерживает централизованное хранение сведений об ошибках заданий загрузки в хранилище ошибок. Затем сообщения об ошибках можно просматривать непосредственно с помощью оператора <code>SHOW LOAD WARNINGS;</code>. Здесь отображаются сведения о конфигурации хранилища ошибок.
18. monitor : отображает использование ресурсов JVM процесса FE.
19. resources : просмотр системных ресурсов. Обычные учётные записи могут видеть только ресурсы, на использование которых у них есть право USAGE_PRIV. Только учётные записи root и admin могут видеть все ресурсы. Эквивалентно [SHOW RESOURCES](../cluster-management/compute-management/SHOW-RESOURCES).
20. routine_loads: отображает сведения обо всех заданиях Routine Load, включая имя задания, состояние и т. д.
21. statistics: используется главным образом для обобщения и просмотра количества баз данных, таблиц, разделов, шардов и реплик в кластере Doris, а также количества неисправных реплик. Эти сведения помогают контролировать общий объём метаданных кластера, дают общее представление о шардировании кластера и позволяют быстро проверить состояние шардов. Это помогает определить проблемные шарды данных.
22. stream_loads: возвращает выполняемую задачу Stream Load.
23. tasks : отображает общее количество задач различных заданий и количество сбоев.
24. transactions : используется для просмотра подробных сведений о транзакции с указанным идентификатором; эквивалентно [SHOW TRANSACTION](../transaction/SHOW-TRANSACTION).
25. trash: этот оператор используется для просмотра объёма пространства, занимаемого мусорными данными в backend. Эквивалентно [SHOW TRASH](../table-and-view/data-and-status-management/SHOW-TRASH).


##   Подробное описание {#detailed-description}
1. /binlog

Binlog регистрирует изменения данных в Doris. С помощью этой команды администраторы могут отслеживать состояние Binlog, обеспечивать его нормальную работу и рационально планировать пространство для хранения.

| Имя поля | Тип данных | Описание |
|------------|-----------|-------------|
| Name | String | Имя базы данных или таблицы. |
| Type | String | Тип объекта данных; значение может быть "db" (база данных) или "table" (таблица). |
| Id | Number | Идентификатор базы данных или таблицы. |
| Dropped | Boolean | Удалена ли база данных или таблица. Значение "true" означает, что объект удалён из Doris, но его записи Binlog ещё сохраняются; значение "false" означает, что объект по-прежнему существует в системе. Даже после удаления базы данных или таблицы система некоторое время сохраняет записи Binlog, пока не истечёт TTL или они не будут очищены вручную. |
| BinlogLength | Number | Общее количество записей бинарного журнала для этой базы данных или таблицы. |
| BinlogSize | Number | Общий размер бинарных журналов (байты). |
| FirstBinlogCommittedTime | Number | Метка времени фиксации первой записи бинарного журнала (метка времени Unix, миллисекунды). |
| ReadableFirstBinlogCommittedTime | String | Время фиксации первой записи бинарного журнала (в удобочитаемом формате). |
| LastBinlogCommittedTime | Number | Метка времени фиксации последней записи бинарного журнала (метка времени Unix, миллисекунды). |
| ReadableLastBinlogCommittedTime | String | Время фиксации последней записи бинарного журнала (в удобочитаемом формате). |
| BinlogTtlSeconds | Number | Срок хранения бинарных журналов (секунды); журналы, превысившие этот срок, могут быть удалены. |
| BinlogMaxBytes | Number | Максимальный размер бинарных журналов (байты); превышение этого размера может запустить очистку. |
| BinlogMaxHistoryNums | Number | Максимальное количество сохраняемых исторических записей бинарного журнала; превышение этого количества может запустить очистку. |

Примечания:
- В результатах этой команды отображаются только базы данных и таблицы, для которых включено ведение бинарного журнала.
- Если ведение бинарного журнала включено на уровне базы данных, отображаются сведения о бинарном журнале базы данных; в противном случае отображаются сведения об отдельных таблицах этой базы данных, для которых включено ведение бинарного журнала.

3. Следующая команда позволяет просмотреть сведения о существующих группах в кластере.

   ```
   SHOW PROC '/colocation_group';
   
   +-------------+--------------+--------------+------------+-------------------+----------+----------+----------+
   | GroupId     | GroupName    | TableIds     | BucketsNum | ReplicaAllocation | DistCols | IsStable | ErrorMsg |
   +-------------+--------------+--------------+------------+-------------------+----------+----------+----------+
   | 10005.10008 | 10005_group1 | 10007, 10040 | 10         | tag.location.default: 3 | int(11)  | true     |          |
   +-------------+--------------+--------------+------------+-------------------+----------+----------+----------+
   ```

   - GroupId: уникальный в пределах кластера идентификатор группы; первая часть представляет собой идентификатор базы данных, а вторая часть представляет собой идентификатор группы.
   - GroupName: полное имя группы.
   - TableIds: список идентификаторов таблиц, входящих в эту группу.
   - BucketsNum: количество бакетов.
   - ReplicaAllocation: политика распределения реплик.
   - DistCols: столбцы распределения, то есть тип столбца бакетирования.
   - IsStable: стабильна ли группа (определение стабильности см. в разделе `Colocation replica balance and repair`).
   - ErrorMsg: текущее сообщение об ошибке группы; пустое, если всё в порядке.

   :::caution Изменение поведения (4.0.8)

   Начиная с версии 4.0.8 столбец `ReplicaAllocation` отображает `null` в режиме с разделением вычислений и хранения. В этой архитектуре репликами управляет слой хранения, поэтому семантика распределения реплик режима с совмещёнными хранением и вычислениями здесь неприменима, а ранее отображавшееся значение вводило в заблуждение.

   :::

4. Используйте следующие команды для более подробного просмотра распределения данных группы:

   ```sql
   SHOW PROC '/colocation_group/10005.10008';
   
   +-------------+---------------------+
   | BucketIndex | BackendIds          |
   +-------------+---------------------+
   | 0           | 10004, 10002, 10001 |
   | 1           | 10003, 10002, 10004 |
   | 2           | 10002, 10004, 10001 |
   | 3           | 10003, 10002, 10004 |
   | 4           | 10002, 10004, 10003 |
   | 5           | 10003, 10002, 10001 |
   | 6           | 10003, 10004, 10001 |
   | 7           | 10003, 10004, 10002 |
   +-------------+---------------------+
   ```

   - BucketIndex: индекс бакета в последовательности.
   - BackendIds: список идентификаторов узлов BE, на которых расположены шарды данных бакета.

   Имена столбцов, кроме `BucketIndex`, зависят от режима развёртывания: в режиме с совмещёнными хранением и вычислениями каждому тегу ресурсов соответствует отдельный столбец, а в режиме с разделением вычислений и хранения отдельный столбец соответствует каждой вычислительной группе. Если такого разбиения нет, используется единственный столбец `BackendIds`.
