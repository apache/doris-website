## Описание {#description}

Оператор изменения предназначен для выполнения операции вставки данных.

```sql
INSERT INTO table_name
    [ PARTITION (p1, ...) ]
    [ WITH LABEL label]
    [ (column [, ...]) ]
    [ [ hint [, ...] ] ]
    { VALUES ( { expression | DEFAULT } [, ...] ) [, ...] | query }
```

 Параметры

> tablet_name: Таблица назначения для импорта данных. Может иметь вид `db_name.table_name`
>
> partitions: Укажите импортируемые разделы. Они должны существовать в `table_name`. Имена нескольких разделов разделяются запятыми
>
> label: Укажите метку для задачи Insert
>
> column_name: Указанный столбец назначения; он должен существовать в `table_name`
>
> expression: Соответствующее выражение, которое необходимо присвоить столбцу
>
> DEFAULT: Позволяет соответствующему столбцу использовать значение по умолчанию
>
> query: Обычный запрос; его результат будет записан в целевую таблицу
>
> hint: Индикатор, задающий поведение выполнения `INSERT`. Можно выбрать одно из следующих значений: `/*+ STREAMING */`, `/*+ SHUFFLE */` или `/*+ NOSHUFFLE */.
> 1. STREAMING: В настоящее время практического эффекта не имеет и сохраняется только для совместимости с предыдущими версиями. (В предыдущей версии добавление этого hint возвращало label, а теперь label возвращается по умолчанию.)
> 2. SHUFFLE: Если целевая таблица является секционированной, включение этого hint выполнит repartiiton.
> 3. NOSHUFFLE: Даже если целевая таблица является секционированной, repartiiton выполняться не будет, но будут выполнены другие операции, гарантирующие правильное распределение данных по разделам.

Для таблицы Unique с включённым merge-on-write также можно выполнять обновление отдельных столбцов с помощью оператора insert. Чтобы выполнять частичное обновление столбцов оператором insert, необходимо установить переменную сеанса enable_unique_key_partial_update в значение true (значение этой переменной по умолчанию — false, то есть частичное обновление столбцов оператором insert по умолчанию запрещено). При частичном обновлении столбцов вставляемые столбцы должны содержать как минимум все столбцы Key и указывать столбцы, которые требуется обновить. Если значения столбцов Key вставляемой строки уже существуют в исходной таблице, будут обновлены данные строки с такими же значениями столбцов Key. Если значения столбцов Key вставляемой строки отсутствуют в исходной таблице, в таблицу будет вставлена новая строка. В этом случае столбцы, не указанные в операторе insert, должны иметь значения по умолчанию или допускать значение null. Для этих отсутствующих столбцов сначала предпринимается попытка использовать значения по умолчанию, а если значение по умолчанию отсутствует, столбцу присваивается null. Если столбец не допускает значение null, операция вставки завершится ошибкой.

Обратите внимание, что значение переменной сеанса `enable_insert_strict`, определяющей, работает ли оператор insert в строгом режиме, по умолчанию равно true. Иными словами, оператор insert по умолчанию работает в строгом режиме, а в этом режиме при частичном обновлении столбцов нельзя обновлять отсутствующие ключи. Поэтому при использовании оператора insert для частичного обновления столбцов, если требуется вставлять отсутствующие ключи, необходимо установить `enable_unique_key_partial_update` в значение true и одновременно установить `enable_insert_strict` в значение false.

Примечание:

При выполнении оператора `INSERT` по умолчанию фильтруются данные, не соответствующие формату целевой таблицы, например слишком длинные строки. Однако в бизнес-сценариях, где фильтрация данных недопустима, можно установить переменную сеанса `enable_insert_strict` в значение `true`, чтобы `INSERT` не завершался успешно при отфильтровывании данных.

## Пример {#example}

Таблица `test` содержит два столбца `c1`, `c2`.

1. Импорт одной строки данных в таблицу `test`

```sql
INSERT INTO test VALUES (1, 2);
INSERT INTO test (c1, c2) VALUES (1, 2);
INSERT INTO test (c1, c2) VALUES (1, DEFAULT);
INSERT INTO test (c1) VALUES (1);
```

Первый и второй операторы имеют одинаковый эффект. Если целевой столбец не указан, в качестве целевых столбцов по умолчанию используется порядок столбцов в таблице.
Третий и четвёртый операторы имеют одинаковый смысл: для завершения импорта данных используется значение по умолчанию столбца `c2`.

2. Одновременный импорт нескольких строк данных в таблицу `test`

```sql
INSERT INTO test VALUES (1, 2), (3, 2 + 2);
INSERT INTO test (c1, c2) VALUES (1, 2), (3, 2 * 2);
INSERT INTO test (c1) VALUES (1), (3);
INSERT INTO test (c1, c2) VALUES (1, DEFAULT), (3, DEFAULT);
```

Первый и второй операторы имеют одинаковый эффект: в таблицу `test` одновременно импортируются две строки данных.
Эффект третьего и четвёртого операторов очевиден: для импорта двух строк данных в таблицу `test` используется значение по умолчанию столбца `c2`.

3. Импорт результата запроса в таблицу `test`

```sql
INSERT INTO test SELECT * FROM test2;
INSERT INTO test (c1, c2) SELECT * from test2;
```

4. Импорт результата запроса в таблицу `test` с указанием раздела и метки

```sql
INSERT INTO test PARTITION(p1, p2) WITH LABEL `label1` SELECT * FROM test2;
INSERT INTO test WITH LABEL `label1` (c1, c2) SELECT * from test2;
```

## Лучшие практики {#best-practice}

1. Просмотр возвращаемых результатов

   Операция INSERT выполняется синхронно, и возврат результата означает завершение операции. Пользователь должен выполнить соответствующую обработку в зависимости от возвращённого результата.

   1. Выполнение успешно, набор результатов пуст

      Если набор результатов оператора select, соответствующего insert, пуст, возвращается следующее:

      ```sql
      mysql> insert into tbl1 select * from empty_tbl;
      Query OK, 0 rows affected (0.02 sec)
      ```

      `Query OK` означает успешное выполнение. `0 rows affected` означает, что данные не были импортированы.

   2. Выполнение успешно, набор результатов не пуст

      Если набор результатов не пуст, возвращаемые результаты делятся на следующие случаи:

      1. Insert выполнен успешно, данные видимы:

         ```sql
         mysql> insert into tbl1 select * from tbl2;
         Query OK, 4 rows affected (0.38 sec)
         {'label':'insert_8510c568-9eda-4173-9e36-6adc7d35291c', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 with label my_label1 select * from tbl2;
         Query OK, 4 rows affected (0.38 sec)
         {'label':'my_label1', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 select * from tbl2;
         Query OK, 2 rows affected, 2 warnings (0.31 sec)
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'visible', 'txnId':'4005'}

         mysql> insert into tbl1 select * from tbl2;
         Query OK, 2 rows affected, 2 warnings (0.31 sec)
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'committed', 'txnId':'4005'}
         ```

         `Query OK` означает успешное выполнение. `4 rows affected` означает, что всего импортировано 4 строки данных. `2 warnings` показывает количество отфильтрованных строк.

         Также возвращается строка json:

         ```json
         {'label':'my_label1', 'status':'visible', 'txnId':'4005'}
         {'label':'insert_f0747f0e-7a35-46e2-affa-13a235f4020d', 'status':'committed', 'txnId':'4005'}
         {'label':'my_label1', 'status':'visible', 'txnId':'4005', 'err':'some other error'}
         ```

         `label` — это заданная пользователем или автоматически сгенерированная метка. Label — идентификатор задания импорта Insert Into. Каждое задание импорта имеет уникальный Label в пределах одной базы данных.

         `status` показывает, видимы ли импортированные данные. Если данные видимы, отображается `visible`, если невидимы — `committed`.

         `txnId` — идентификатор транзакции импорта, соответствующей этому insert.

         Поле `err` содержит другие непредвиденные ошибки.

         Чтобы просмотреть отфильтрованные строки, пользователь может выполнить следующий оператор:

         ```sql
         show load where label="xxx";
         ```

         URL в возвращённом результате можно использовать для запроса ошибочных данных. Подробности приведены далее в разделе **Просмотр строк с ошибками**.

         **Невидимость данных — временное состояние; эта партия данных в конечном итоге станет видимой.**

         Просмотреть состояние видимости этой партии данных можно следующим оператором:

         ```sql
         show transaction where id=4005;
         ```

         Если столбец `TransactionStatus` в возвращённом результате имеет значение `visible`, данные видимы.

   3. Выполнение завершилось ошибкой

      Ошибка выполнения означает, что данные не были успешно импортированы, и возвращается следующее:

      ```sql
      mysql> insert into tbl1 select * from tbl2 where k1 = "a";
      ERROR 1064 (HY000): all partitions have no load data. url: http://10.74.167.16:8042/api/_load_error_log?file=__shard_2/error_log_insert_stmt_ba8bb9e158e4879-ae8de8507c0bf8a2_ba8bb9e158e4879_ae8de8507c0
      ```

      Сообщение `ERROR 1064 (HY000): all partitions have no load data` показывает причину ошибки. Следующий URL можно использовать для запроса ошибочных данных:

      ```sql
      show load warnings on "url";
      ```

      Можно просмотреть конкретную строку с ошибкой.

2. Время ожидания

   Время ожидания операции INSERT определяется выражением `max(insert_timeout, query_timeout)`. Обе величины являются переменными среды: значение insert_timeout по умолчанию составляет 4 часа, а query_timeout — 5 минут. Если операция превышает время ожидания, задание отменяется. Переменная insert_timeout введена, чтобы операторы INSERT имели более длительное время ожидания по умолчанию и чтобы задачи импорта не зависели от более короткого времени ожидания, обычно применяемого к обычным запросам.

3. Метка и атомарность

   Операция INSERT также гарантирует атомарность импорта. См. документацию [Транзакции импорта и атомарность](../../../../data-operate/transaction.md).

   При использовании `CTE(Common Table Expressions)` в качестве части запроса в операции insert необходимо указать части `WITH LABEL` и `column`.

4. Порог фильтрации

   INSERT использует переменную сеанса `insert_max_filter_ratio` для управления порогом фильтрации, а не свойство загрузки `max_filter_ratio`. Переменная `insert_max_filter_ratio` поддерживается начиная с версии 2.1.5, принимает значения от 0 до 1, имеет значение по умолчанию 1.0 и действует только при `enable_insert_strict = false`. Она применяется к `INSERT INTO ... VALUES` и `INSERT INTO ... SELECT`, включая таблицы Doris, внешние таблицы и файловые TVF. INSERT завершается ошибкой, если значение `filtered_rows / (loaded_rows + filtered_rows)` превышает этот порог.

   Чтобы отклонять любые отфильтрованные данные, установите [переменную сеанса](../../session/variable/SET-VARIABLE) `enable_insert_strict` в значение `true` (значение по умолчанию). В этом случае INSERT завершается ошибкой при фильтрации любой строки. Порог фильтрации не подавляет другие ошибки выполнения, например ошибки анализа SQL или сбои доступа к источнику данных.

5. Проблемы производительности

   Метод `VALUES` не предназначен для вставки одной строки. Если необходимо использовать его таким образом, объедините несколько строк данных в один оператор INSERT для пакетной фиксации.
