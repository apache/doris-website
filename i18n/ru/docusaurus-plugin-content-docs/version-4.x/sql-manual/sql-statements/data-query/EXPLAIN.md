## Описание {#description}

Оператор EXPLAIN отображает план выполнения заданного запроса в Doris. Оптимизатор запросов Doris стремится создать эффективный план, используя статистические данные, характеристики данных и такие возможности, как HASH JOIN, партиционирование и бакетирование. Однако из-за теоретических и практических ограничений план иногда оказывается недостаточно эффективным.

Для повышения производительности необходимо проанализировать текущий план. В этой статье объясняется, как использовать оператор EXPLAIN для оптимизации.



## Синтаксис {#syntax}

```plain text
{EXPLAIN | DESC} [VERBOSE] <query_block>
```

## Обязательные параметры {#required-parameters}

**<query_block>**

> Запрос, для которого требуется получить план выполнения.

## Необязательные параметры {#optional-parameters}

**[VERBOSE]**

> Наличие `VERBOSE` определяет, будет ли отображаться подробная информация. При указании `VERBOSE` выводятся полные сведения, включая подробности о каждом операторе, идентификаторы используемых им кортежей и подробные описания каждого кортежа. Без этого параметра выводится краткая информация.


## Результаты выполнения {#return-results}

### Основные понятия {#basic-concepts}

Чтобы лучше понимать информацию, отображаемую командой `EXPLAIN`, рассмотрим несколько основных понятий плана выполнения Doris.

| Название  | Пояснение                                                    |
| :-------- | :----------------------------------------------------------- |
| PLAN      | План выполнения. Планировщик преобразует запрос в план выполнения, который затем выполняется движком исполнения. |
| FRAGMENT  | Фрагмент выполнения. Поскольку Doris является распределённым движком исполнения, полный план выполнения разделяется на несколько фрагментов, каждый из которых выполняется на одном узле. Таблица FRAGMENT представляет полный фрагмент выполнения для одного узла. Несколько FRAGMENTS вместе образуют полный PLAN. |
| PLAN NODE | Оператор. Наименьшая единица плана выполнения. FRAGMENT состоит из нескольких операторов. Каждый оператор отвечает за определённую логику выполнения, например агрегацию или соединение. |

### Структура результата {#return-result-structure}

Результат выполнения оператора `EXPLAIN` в Doris представляет собой полный PLAN. Внутри PLAN фрагменты FRAGMENTS расположены в порядке, обратном последовательности выполнения. Внутри каждого FRAGMENT операторы (PLAN NODES) также расположены в порядке, обратном последовательности выполнения.

Ниже приведён пример:


```sql
+--------------------------------------------------+
| Explain String(Nereids Planner)                  |
+--------------------------------------------------+
| PLAN FRAGMENT 0                                  |
|   OUTPUT EXPRS:                                  |
|     cnt[#10]                                     |
|     cnt[#11]                                     |
|   PARTITION: UNPARTITIONED                       |
|                                                  |
|   HAS_COLO_PLAN_NODE: false                      |
|                                                  |
|   VRESULT SINK                                   |
|      MYSQL_PROTOCAL                              |
|                                                  |
|   7:VEXCHANGE                                    |
|      offset: 0                                   |
|      distribute expr lists:                      |
|                                                  |
| PLAN FRAGMENT 1                                  |
|                                                  |
|   PARTITION: RANDOM                              |
|                                                  |
|   HAS_COLO_PLAN_NODE: false                      |
|                                                  |
|   STREAM DATA SINK                               |
|     EXCHANGE ID: 07                              |
|     UNPARTITIONED                                |
|                                                  |
|   6:VHASH JOIN(354)                              |
|   |  join op: INNER JOIN(BROADCAST)[]            |
|   |  equal join conjunct: cnt[#7] = cnt[#5]      |
|   |  cardinality=1                               |
|   |  vec output tuple id: 8                      |
|   |  vIntermediate tuple ids: 7                  |
|   |  hash output slot ids: 5 7                   |
|   |  distribute expr lists:                      |
|   |  distribute expr lists:                      |
|   |                                              |
|   |----4:VEXCHANGE                               |
|   |       offset: 0                              |
|   |       distribute expr lists:                 |
|   |                                              |
|   5:VEXCHANGE                                    |
|      offset: 0                                   |
|      distribute expr lists:                      |
|                                                  |
| PLAN FRAGMENT 2                                  |
|   ...                                            |
|                                                  |
| PLAN FRAGMENT 3                                  |
|   ...                                            |
+--------------------------------------------------+
```

Операторы связаны со своими дочерними узлами пунктирными линиями. Если у оператора несколько дочерних узлов, они располагаются по вертикали в порядке справа налево. В приведённом выше примере у оператора 6 (VHASH JOIN) левый дочерний узел — оператор 5 (EXCHANGE), а правый — оператор 4 (EXCHANGE).

### Описание информации о кортежах {#tuple-information-description}

В режиме VERBOSE выводится информация о кортежах. Она описывает характеристики SLOT в строке данных, включая тип SLOT, допустимость пустых значений и другие свойства.

Вывод содержит несколько TupleDescriptors, каждый из которых содержит несколько SlotDescriptors. Ниже приведён пример:

```sql
Tuples:
TupleDescriptor{id=0, tbl=t1}
  SlotDescriptor{id=0, col=c1, colUniqueId=0, type=int, nullable=true, isAutoIncrement=false, subColPath=null}
  SlotDescriptor{id=2, col=c3, colUniqueId=2, type=int, nullable=true, isAutoIncrement=false, subColPath=null}
```

#### TupleDescriptor {#tupledescriptor}



| Название | Описание                                                     |
| :--- | :----------------------------------------------------------- |
| id   | Идентификатор дескриптора кортежа                             |
| tbl  | Таблица, соответствующая кортежу, или `null`, если неприменимо |



#### SlotDescriptor {#slotdescriptor}

| Название        | Описание                                                     |
| :-------------- | :----------------------------------------------------------- |
| id              | Идентификатор дескриптора слота                               |
| col             | Столбец, соответствующий слоту; если неприменимо, поле остаётся пустым |
| colUniqueId     | Уникальный идентификатор соответствующего столбца или -1, если неприменимо |
| type            | Тип слота                                                    |
| nullable        | Указывает, могут ли соответствующие данные принимать значение null |
| isAutoIncrement | Указывает, является ли столбец автоинкрементным                |
| subColPath      | Путь к вложенному столбцу внутри столбца; в настоящее время применим только к типам variant |
