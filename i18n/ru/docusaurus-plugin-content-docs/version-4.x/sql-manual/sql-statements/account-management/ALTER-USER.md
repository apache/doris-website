## Описание {#description}

Оператор `ALTER USER` используется для изменения атрибутов учетной записи пользователя, включая пароли и политики паролей и т. д.

Начиная с версии 4.2.1, Doris поддерживает два пароля для встроенной парольной аутентификации с помощью `RETAIN CURRENT PASSWORD` и `DISCARD OLD PASSWORD`.

## Синтаксис {#syntax}

```sql
ALTER USER [IF EXISTS] <user_identity>
    [IDENTIFIED BY <password> [RETAIN CURRENT PASSWORD] | DISCARD OLD PASSWORD]
[<password_policy>]
[<comment>]

password_policy:
    1. PASSWORD_HISTORY { <n> | DEFAULT }
    2. PASSWORD_EXPIRE { DEFAULT | NEVER | INTERVAL <n> { DAY | HOUR | SECOND }}
    3. FAILED_LOGIN_ATTEMPTS <n>
    4. PASSWORD_LOCK_TIME { UNBOUNDED | <n> { DAY | HOUR | SECOND }}
    5. ACCOUNT_UNLOCK
```

## Обязательные параметры {#required-parameters}

**1. `<user_identity`>**

> user_identity однозначно идентифицирует пользователя. Синтаксис: 'user_name'@'host'.
> `user_identity` состоит из двух частей: user_name и host; username — это имя пользователя. Host обозначает адрес хоста, с которого подключается клиент. В части host можно использовать % для нечеткого сопоставления. Если host не указан, по умолчанию используется '%', то есть пользователь может подключаться к Doris с любого хоста.
> В части host также можно указать домен; синтаксис: 'user_name'@['domain']. Даже если значение заключено в квадратные скобки, Doris считает его доменом и пытается разрешить его IP-адрес.

## Необязательные параметры {#optional-parameters}

**1. `<password>`**

> Укажите пароль пользователя.

**2. `<password_policy>`**

> `password_policy` — это конструкция для указания политик, связанных со входом с использованием парольной аутентификации. В настоящее время поддерживаются следующие политики:
>
> `PASSWORD_HISTORY { <n> | DEFAULT}`
>
>    Указывает, разрешено ли текущему пользователю использовать исторические пароли при сбросе пароля. Например, `PASSWORD_HISTORY 10` означает, что нельзя использовать в качестве нового пароль, установленный в ходе последних 10 смен пароля. Если задано `PASSWORD_HISTORY DEFAULT`, используется значение глобальной переменной `password_history`. Значение `0` означает, что функция отключена. По умолчанию — 0.
>
> `PASSWORD_EXPIRE { DEFAULT | NEVER | INTERVAL <n> { DAY | HOUR | SECOND }}`
>
>    Устанавливает срок действия пароля текущего пользователя. Например, `PASSWORD_EXPIRE INTERVAL 10 DAY` означает, что пароль истечет через 10 дней. `PASSWORD_EXPIRE NEVER` означает, что срок действия пароля не истекает. Если задано `PASSWORD_EXPIRE DEFAULT`, используется значение глобальной переменной `default_password_lifetime`. По умолчанию используется NEVER (или 0), то есть срок действия не истекает.
>
> `FAILED_LOGIN_ATTEMPTS <n>`
>
> При входе текущего пользователя учетная запись блокируется, если он n раз вводит неправильный пароль. Например, `FAILED_LOGIN_ATTEMPTS 3` означает, что после 3 неудачных попыток входа учетная запись будет заблокирована.
>
> `PASSWORD_LOCK_TIME { UNBOUNDED | <n> { DAY | HOUR | SECOND }}`
>
> Если учетная запись заблокирована, задается срок блокировки. Например, `PASSWORD_LOCK_TIME 1 DAY` означает, что учетная запись будет заблокирована на один день.
>
> `ACCOUNT_UNLOCK`
>
> `ACCOUNT_UNLOCK` используется для разблокировки заблокированного пользователя.

**3. `<comment>`**

> Укажите комментарий пользователя.

**4. `RETAIN CURRENT PASSWORD` (начиная с 4.2.1)**

> Используйте вместе с `IDENTIFIED BY`, чтобы сохранить предыдущий основной пароль как сохраненный вторичный пароль. Новый пароль становится основным; для аутентификации можно использовать любой из паролей. Любой ранее сохраненный вторичный пароль заменяется.

**5. `DISCARD OLD PASSWORD` (начиная с 4.2.1)**

> Удаляет сохраненный вторичный пароль, оставляя основной пароль без изменений. Это самостоятельная операция: не объединяйте ее со сменой пароля, политикой пароля, комментарием или другой операцией с учетной записью. Если вторичного пароля нет, операция не изменяет состояние.

## Требования к управлению доступом {#access-control-requirements}

Пользователь, выполняющий эту SQL-команду, должен иметь как минимум следующие привилегии:

| Привилегия     | Объект    | Примечания |
|:--------------|:----------|:------|
| GRANT_PRIV или ADMIN_PRIV | Глобальный | Требуется для ALTER USER, включая RETAIN CURRENT PASSWORD и DISCARD OLD PASSWORD. |

## Примечания по использованию {#usage-notes}

Начиная с версии 4.1.5, только `'root'@'%'` является специальным идентификатором root. Учетная запись с идентификатором `'root'@'localhost'` остается обычной учетной записью и не получает права изменять фактическую учетную запись root только из-за имени пользователя. Защита фактической учетной записи root также не распространяется на других пользователей с именем root.

1. Начиная с версии 2.0 эта команда больше не поддерживает изменение ролей пользователей. Для соответствующих операций используйте [GRANT](./GRANT-TO.md) и [REVOKE](./REVOKE-FROM.md).

2. В одной команде ALTER USER одновременно можно изменить только один из следующих атрибутов учетной записи:
- Изменить пароль, при необходимости с RETAIN CURRENT PASSWORD
- Удалить сохраненный вторичный пароль
- Изменить `PASSWORD_HISTORY`
- Изменить `PASSWORD_EXPIRE`
- Изменить `FAILED_LOGIN_ATTEMPTS` и `PASSWORD_LOCK_TIME`
- Разблокировать пользователей

### Двойные пароли (начиная с 4.2.1) {#dual-passwords-since-421}

- `RETAIN CURRENT PASSWORD` требует непустого текущего основного пароля и смены пароля. Пустой новый пароль очищает оба слота паролей, даже при RETAIN.
- Обычная смена непустого пароля без RETAIN сохраняет существующий вторичный пароль; она не аннулирует эти учетные данные.
- Проверки блокировки учетной записи и истечения срока действия пароля применяются к обоим паролям. DISCARD не изменяет историю паролей и не запускает заново отсчет срока действия пароля.

См. [Двойные пароли](../../../admin-manual/auth/authentication/internal#dual-passwords), где описаны процедура ротации, наблюдаемость, поведение доменных учетных записей и ограничения при обновлении. Эти конструкции управляют встроенными паролями, а не учетными данными, хранящимися в LDAP или внешней интеграции аутентификации.

## Пример {#example}

Подготовка — создайте пользователя `jack`, чтобы использовать его в приведенных ниже примерах:

```sql
CREATE USER jack@'%' IDENTIFIED BY "12345";
```

- Изменить пароль пользователя

```sql
ALTER USER jack@'%' IDENTIFIED BY "12345";
```

- Изменить политику пароля пользователя

```sql
ALTER USER jack@'%' FAILED_LOGIN_ATTEMPTS 3 PASSWORD_LOCK_TIME 1 DAY;
```

- Разблокировать пользователя

```sql
ALTER USER jack@'%' ACCOUNT_UNLOCK
```

- Изменить комментарий пользователя

```sql
ALTER USER jack@'%' COMMENT "this is my first user"
```

- Сменить пароль, сохранив возможность использовать предыдущий пароль (начиная с 4.2.1)

```sql
ALTER USER jack@'%' IDENTIFIED BY 'NewPwd_2026!' RETAIN CURRENT PASSWORD;
```

Для аутентификации подходят и предыдущий пароль, и `NewPwd_2026!`. После переключения всех клиентов на новый пароль удалите сохраненный пароль:

```sql
ALTER USER jack@'%' DISCARD OLD PASSWORD;
```

После этого для аутентификации подходит только `NewPwd_2026!`.
