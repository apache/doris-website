## Описание {#description}

Оператор `SET PASSWORD` используется для изменения пароля пользователя для входа.

Начиная с версии 4.2.1 Doris поддерживает два пароля для встроенной аутентификации по паролю с помощью `RETAIN CURRENT PASSWORD` и `DISCARD OLD PASSWORD`.

## Синтаксис {#syntax}

```sql
SET PASSWORD [FOR <user_identity>] =
    { PASSWORD(<plain_password>) | <hashed_password> }
    [RETAIN CURRENT PASSWORD]
```

## Обязательные параметры {#required-parameters}

**1. `<plain_password>`**

> Указывается пароль в открытом виде. Например, для пароля `123456` непосредственно укажите строку `123456`.

**2. `<hashed_password>`**

> Указывается зашифрованный пароль. Например, для пароля 123456 непосредственно укажите строку `*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9`, являющуюся возвращаемым значением функции `PASSWORD('123456')`.

## Необязательные параметры {#optional-parameters}

**1. `<user_identity>`**

> При указании `FOR` точно укажите идентификатор учетной записи, созданный с помощью `CREATE USER`, включая его часть host. Без `FOR` Doris использует аутентифицированную учетную запись, возвращаемую `CURRENT_USER()`, а не идентификатор с IP-адресом клиента, возвращаемый `USER()`. Текущую учетную запись можно просмотреть с помощью `SHOW GRANTS`.

**2. `RETAIN CURRENT PASSWORD` (начиная с 4.2.1)**

> Предыдущий основной пароль сохраняется как вторичный, а указанный новый пароль устанавливается как основной. Для аутентификации можно использовать любой из них; ранее сохраненный вторичный пароль заменяется. Требуется глобальная привилегия `GRANT_PRIV` или `ADMIN_PRIV`, в том числе при изменении собственного пароля.

## Требования к управлению доступом {#access-control-requirements}

Пользователь, выполняющий эту SQL-команду, должен иметь как минимум следующие привилегии:

| Привилегия     | Объект    | Примечания |
|:--------------|:----------|:------|
| Нет | Текущий пользователь | Обычное изменение собственного пароля без RETAIN не требует дополнительных привилегий. |
| GRANT_PRIV или ADMIN_PRIV | Глобальный уровень | Для изменения пароля другого пользователя или использования RETAIN CURRENT PASSWORD, в том числе для собственной учетной записи, требуется эта привилегия. |

## Примечания по использованию {#usage-notes}

Начиная с версии 4.1.5 специальным идентификатором root является только `'root'@'%'`. Идентификатор вроде `'root'@'localhost'` остается обычной учетной записью и не получает права изменять фактическую учетную запись root только из-за имени пользователя. Защита фактической учетной записи root также не распространяется на других пользователей с именем root.

- Если поле `FOR user_identity` отсутствует, изменяется пароль текущего пользователя.

### Два пароля (начиная с 4.2.1) {#dual-passwords-since-421}

- Без RETAIN обычное изменение непустого пароля сохраняет любой существующий вторичный пароль.
- RETAIN завершается ошибкой, если текущий основной пароль пуст. Пустой новый пароль очищает оба слота, даже если указан RETAIN.
- Для пароля в открытом виде используйте `PASSWORD('<new_password>')`; строка без вызова функции должна содержать уже вычисленный хеш пароля.
- Чтобы отозвать вторичный пароль, используйте `ALTER USER ... DISCARD OLD PASSWORD`. В SET PASSWORD нет предложения DISCARD.

Полный рабочий процесс и ограничения при обновлении описаны в разделе [Два пароля](../../../admin-manual/auth/authentication/internal#dual-passwords). Эти предложения применяются к встроенным паролям.

## Пример {#example}

- Изменение пароля текущего пользователя

```sql
SET PASSWORD = PASSWORD('123456')
SET PASSWORD = '*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9'
```

- Изменение пароля указанного пользователя

```sql
SET PASSWORD FOR 'jack'@'192.%' = PASSWORD('123456')
SET PASSWORD FOR 'jack'@['domain'] = '*6BB4837EB74329105EE4568DDA7DC67ED2CA2AD9'
```

- Ротация учетной записи с периодом перекрытия (начиная с 4.2.1)

Выполните команду от имени администратора с глобальной привилегией `GRANT_PRIV` или `ADMIN_PRIV`:

```sql
CREATE USER 'rotation_user'@'%' IDENTIFIED BY 'OldPwd_2026!';
SET PASSWORD FOR 'rotation_user'@'%' = PASSWORD('NewPwd_2026!') RETAIN CURRENT PASSWORD;
```

Оба пароля — `OldPwd_2026!` и `NewPwd_2026!` — позволяют пройти аутентификацию. После переноса клиентов удалите старые учетные данные:

```sql
ALTER USER 'rotation_user'@'%' DISCARD OLD PASSWORD;
```

После этого аутентификацию проходит только `NewPwd_2026!`.
