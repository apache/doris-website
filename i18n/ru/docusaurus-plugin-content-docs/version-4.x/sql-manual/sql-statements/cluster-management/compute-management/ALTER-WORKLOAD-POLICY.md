## Описание {#description}

Изменение свойств политики Workload Policy. В настоящее время поддерживается только изменение свойств; изменение действий и условий не поддерживается.


## Синтаксис {#syntax}

```sql
ALTER WORKLOAD POLICY <workload_policy_name> PROPERTIES( <properties> )
```

## Обязательные параметры {#required-parameters}

`<workload_policy_name>` 

Имя политики Workload Policy


`<properties>`

1. enabled: Может принимать значение true или false. Значение по умолчанию: true, что означает, что текущая политика включена. Значение false означает, что текущая политика отключена.
2. priority: Положительное целое число в диапазоне от 0 до 100 со значением по умолчанию 0. Задаёт приоритет политики. Чем больше значение, тем выше приоритет. Основное назначение этого свойства состоит в выборе политики с наивысшим приоритетом, когда условиям соответствуют несколько политик.
3. workload_group: В настоящее время политику можно привязать к одной группе рабочей нагрузки. Это означает, что политика действует только для определённой группы рабочей нагрузки. По умолчанию значение пустое, и политика действует для всех запросов.

    Поскольку сама группа рабочей нагрузки принадлежит вычислительной группе, значение этого свойства должно соответствовать следующим правилам:

    - **Облачный режим (с разделением хранения и вычислений)**: Требуется полная форма `<compute_group>.<workload_group>`, например `'workload_group'='compute_group_a.wg1'`. Краткая форма `<workload_group>`, наличие более одной `.` или пустых сегментов (например, `.wg1` или `wg1.`) приводят к отклонению значения с сообщением: `workload_group must be '<compute_group>.<workload_group>' in cloud mode`.
    - **Необлачный режим (с совмещением хранения и вычислений)**: Допускаются две формы:
        - `<workload_group>`: по умолчанию привязывает политику к группе рабочей нагрузки с таким же именем в группе ресурсов по умолчанию (`default`).
        - `<resource_group>.<workload_group>`: явно указывает группу ресурсов. Здесь префикс фактически обозначает группу ресурсов (Tag); синтаксис совпадает с облачным режимом исключительно для единообразия.
        
        Наличие более одной `.` или пустых сегментов также приводит к отклонению значения с сообщением: `workload_group must be '<workload_group>' or '<resource_group>.<workload_group>' in non-cloud mode`.

## Требования к правам доступа {#access-control-requirements}

Необходимо иметь как минимум права ADMIN_PRIV.

## Примеры {#examples}

1. Отключение политики Workload Policy

  ```sql
  alter workload policy cancel_big_query properties('enabled'='false')
  ```
