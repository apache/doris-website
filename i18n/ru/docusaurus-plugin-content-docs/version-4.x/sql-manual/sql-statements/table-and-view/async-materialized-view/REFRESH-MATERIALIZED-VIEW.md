## Описание {#description}

Эта инструкция используется для ручного обновления указанного асинхронного материализованного представления

## Синтаксис {#syntax}

```sql
REFRESH MATERIALIZED VIEW <mv_name> <refresh_type>
```

Где:
```sql
refresh_type
  : { <partitionSpec> | COMPLETE | AUTO }
```

```sql
partitionSpec
  : PARTITIONS (<partition_name> [, <partition_name> [, ... ] ])
```

## Обязательные параметры {#required-parameters}
**1. `<mv_name>`**
> Указывает имя материализованного представления.
>
> Имя материализованного представления должно начинаться с буквы (или символа любого языка, если включена поддержка имён в Unicode) и не может содержать пробелы или специальные символы, если только вся строка имени не заключена в обратные кавычки (например, `My Object`).
>
> В качестве имени материализованного представления нельзя использовать зарезервированные ключевые слова.
>
> Подробнее см. раздел «Зарезервированные ключевые слова».

**2. `<refresh_type>`**
> Указывает тип обновления этого материализованного представления.
>
> Тип обновления может принимать одно из следующих значений: partitionSpec, COMPLETE или AUTO.

## Необязательные параметры {#optional-parameters}
**1. `<partition_name>`**
> Указывает имя раздела при его обновлении
>

## Требования к правам доступа {#access-control-requirements}
Пользователи, выполняющие эту команду SQL, должны обладать как минимум следующими правами:

| Право  | Объект | Примечания                                        |
| :--------- | :----- | :------------------------------------------- |
| ALTER_PRIV | Материализованное представление  | REFRESH — это операция ALTER над материализованным представлением |


## Примечания по использованию {#usage-notes}

- AUTO: Вычисляется, какие разделы материализованного представления не синхронизированы с базовой таблицей. (В настоящее время, если базовая таблица является внешней, она считается всегда синхронизированной с материализованным представлением. Поэтому, если базовая таблица является внешней, необходимо указать `COMPLETE` или задать разделы для обновления.) Затем обновляются соответствующие разделы.
- COMPLETE: Принудительно обновляются все разделы материализованного представления без проверки их синхронизации с базовой таблицей.
- partitionSpec: Принудительно обновляются указанные разделы без проверки их синхронизации с базовой таблицей.

## Примеры {#examples}

- Обновление материализованного представления mv1 (с автоматическим определением раздела для обновления)

    ```sql
    REFRESH MATERIALIZED VIEW mv1 AUTO;
    ```


- Обновление разделов с именами p_19950801_19950901 и p_19950901_19951001

    ```sql
    REFRESH MATERIALIZED VIEW mv1 partitions(p_19950801_19950901,p_19950901_19951001);
    ```
 

- Принудительное обновление всех данных материализованного представления

    ```sql
    REFRESH MATERIALIZED VIEW mv1 complete;
    ```
