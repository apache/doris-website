# JSON {#json}

## Введение в JSON {#json-introduction}

JSON (JavaScript Object Notation) представляет собой открытый стандарт формата файлов и обмена данными, в котором для хранения и передачи данных используется удобочитаемый текст. Согласно официальной спецификации [RFC7159](https://datatracker.ietf.org/doc/html/rfc7159), JSON поддерживает следующие базовые типы:
- Bool
- Null
- Number
- String
- Array
- Object

Тип данных JSON эффективно хранит данные [JSON](https://www.rfc-editor.org/rfc/rfc8785) в двоичном формате и позволяет обращаться к внутренним полям с помощью функций JSON.

По умолчанию поддерживается размер до 1048576 байт (1MB), который можно увеличить до 2147483643 байт (2GB). Это ограничение настраивается с помощью параметра `string_type_length_soft_limit_bytes`.

По сравнению с хранением строк JSON в обычном типе STRING тип JSON имеет два основных преимущества:
1. Проверка формата JSON при вставке данных.
2. Более эффективный двоичный формат хранения, который обеспечивает более быстрый доступ к внутренним полям JSON с помощью таких функций, как `json_extract`, по сравнению с функциями `get_json_xx`.

:::caution Примечание
В версии 1.2.x тип JSON назывался JSONB. Для совместимости с MySQL начиная с версии 2.0.0 он был переименован в JSON. В старых таблицах по-прежнему можно использовать прежнее имя.
:::

## Проблемы точности чисел в JSON {#json-number-precision-issues}

При работе с JSON следует уделять особое внимание точности чисел:
- В большинстве систем тип Number реализован на основе 64-разрядных двоичных чисел с плавающей точкой двойной точности по стандарту IEEE 754-2008 (например, тип double в C++)
- Поскольку спецификация JSON не определяет строго базовый тип для Number, а обмен данными JSON между различными системами происходит в текстовом виде, возможна потеря точности

Для строки JSON вида `{"abc": 18446744073709551616}`:

```sql
-- Conversion result in MySQL
cast('{"abc": 18446744073709551616}' as json)
-- Result: {"abc": 1.8446744073709552e19}
```

```javascript
// Conversion result in JavaScript
console.log(JSON.parse('{"abc": 18446744073709551616}'));
// Result: {abc: 18446744073709552000}
```

Чтобы сохранить точность чисел при обмене данными между системами, большие числа следует хранить как строки, например `{"abc": "18446744073709551616"}`.

## Тип JSON в Doris {#json-type-in-doris}

Doris поддерживает типы данных, соответствующие спецификации стандарта JSON, и использует эффективный формат JSONB (JSON Binary) для хранения данных в двоичном представлении.

### Поддерживаемые типы {#supported-types}

JSONB в Doris поддерживает все стандартные типы JSON. Главное отличие заключается в том, что Doris предоставляет более детальные расширения типа Number для более точного сопоставления с внутренними типами Doris.

| Тип JSON | Подтип | Соответствующий тип Doris |
|----------|-------|-----------------|
| Bool | - | BOOLEAN |
| Null | - | (Прямого аналога нет, обозначает значение null в JSON) |
| Number | Int8 | TINYINT |
| | Int16 | SMALLINT |
| | Int32 | INT |
| | Int64 | BIGINT |
| | Int128 | LARGEINT |
| | Double | DOUBLE |
| | Float | FLOAT |
| | Decimal | DECIMAL |
| String | - | STRING |
| Array | - | ARRAY |
| Object | - | STRUCT |

### Важные замечания: {#important-notes}
- Значение Null:
  - Null в JSON является допустимым значением, обозначающим «пустое значение». Оно отличается от NULL в SQL, которое обозначает «неизвестное» или «отсутствующее» значение.
  - CAST('null' AS JSON) возвращает столбец JSONB, содержащий значение null в JSON, которое само по себе не является NULL на уровне SQL.
  - CAST('null' AS JSON) IS NULL возвращает false (0), поскольку столбец содержит известное значение null в JSON, которое не является NULL в SQL.

## Операции и ограничения {#operations-and-limitations}
- Сравнение и арифметические операции:
  - Столбцы JSONB нельзя напрямую сравнивать с другими типами данных (включая другие столбцы JSONB) или использовать в арифметических операциях.
  - Решение: извлеките из JSONB скалярные значения (например, INT, DOUBLE, STRING, BOOLEAN) с помощью функции JSON_EXTRACT, затем преобразуйте их в соответствующие собственные типы Doris для сравнения или вычислений.
- Сортировка:
  - Столбцы JSONB не поддерживают операции ORDER BY.
- Неявное преобразование:
  - Только при вводе: при вводе данных в столбец JSONB тип STRING может неявно преобразовываться в JSONB (при условии, что строка содержит допустимый текст JSON). Другие типы Doris не могут неявно преобразовываться в JSONB.


## Поддержка GROUP BY и DISTINCT для JSON {#group-by-and-distinct-support-for-json}

### Пример 1: GROUP BY для столбцов JSON {#example-1-group-by-on-json-columns}
```sql
mysql> SELECT * FROM test_jsonb_groupby;
+------+---------------+
| id   | j             |
+------+---------------+
|    1 | {"a":1,"b":2} |
|    2 | {"a":1,"b":3} |
|    3 | {"a":2,"b":2} |
|    4 | {"a":2,"b":2} |
|    5 | {"a":1,"b":2} |
|    6 | {"a":2,"b":2} |
+------+---------------+
6 rows in set (0.07 sec)

mysql> SELECT j, COUNT(*) FROM test_jsonb_groupby GROUP BY j;
+---------------+----------+
| j             | COUNT(*) |
+---------------+----------+
| {"a":1,"b":3} |        1 |
| {"a":2,"b":2} |        3 |
| {"a":1,"b":2} |        2 |
+---------------+----------+
```

### Пример 2: запрос DISTINCT для столбцов JSON {#example-2-distinct-query-on-json-columns}
```sql
mysql> SELECT DISTINCT j FROM test_jsonb_groupby;
+---------------+
| j             |
+---------------+
| {"a":1,"b":3} |
| {"a":2,"b":2} |
| {"a":1,"b":2} |
+---------------+
```

### Примечания {#notes}
1. **Двоичное сравнение**: сравнение JSON выполняется на основе двоичного представления. Если два значения JSON семантически одинаковы, но имеют разные двоичные представления, они не могут быть объединены в одну группу. Например:
   ```sql
   mysql> SELECT * FROM test_jsonb;
   +------+------+
   | id   | j    |
   +------+------+
   |    1 | 123  |
   |    2 | 123  |
   +------+------+

   mysql> SELECT j, COUNT(*) FROM test_jsonb GROUP BY j;
   +------+----------+
   | j    | COUNT(*) |
   +------+----------+
   | 123  |        1 |
   | 123  |        1 |
   +------+----------+
   ```

   Это происходит потому, что первое значение `123` хранится внутри как 64-разрядное целое число (`json_type` возвращает `bigint`), а второе значение `123` хранится как целое число меньшей разрядности (`json_type` возвращает `int` для всех целочисленных типов с разрядностью меньше, чем у `bigint`), что приводит к различным двоичным представлениям. Проверить их типы можно следующим запросом:
   ```sql
   mysql> SELECT j, json_type(j, '$') FROM test_jsonb;
   +------+------------------+
   | j    | json_type(j, '$') |
   +------+------------------+
   | 123  | bigint           |
   | 123  | int              |
   +------+------------------+
   ```

   Аналогично, объекты JSON с разным порядком ключей не могут быть объединены в одну группу. Например:
   ```sql
   mysql> SELECT * FROM test_jsonb;
   +------+---------------+
   | id   | j             |
   +------+---------------+
   |    2 | {"b":2,"a":1} |
   |    1 | {"a":1,"b":2} |
   +------+---------------+

   mysql> SELECT j, COUNT(*) FROM test_jsonb GROUP BY j;
   +---------------+----------+
   | j             | COUNT(*) |
   +---------------+----------+
   | {"b":2,"a":1} |        1 |
   | {"a":1,"b":2} |        1 |
   +---------------+----------+
   ```

2. **Единообразие числовых типов**: чтобы не учитывать различия числовых типов, используйте функцию `NORMALIZE_JSON_NUMBERS_TO_DOUBLE` для преобразования всех чисел в JSON в тип `DOUBLE`:
   ```sql
   mysql> SELECT NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j), COUNT(*) 
          FROM test_jsonb 
          GROUP BY NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j);
   +-------------------------------------+----------+
   | NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j) | COUNT(*) |
   +-------------------------------------+----------+
   | 123                                 |        2 |
   +-------------------------------------+----------+
   ```
   При создании объектов JSON путём разбора текста (например, с помощью CAST для преобразования строк в JSON) Doris автоматически выбирает подходящий числовой тип для хранения, поэтому различия числовых типов обычно не вызывают проблем.

3. **Единообразие порядка ключей**:
   Используйте функцию `SORT_JSON_OBJECT_KEYS` для сортировки ключей:
   ```sql
   mysql> SELECT SORT_JSON_OBJECT_KEYS(j), COUNT(*) 
          FROM test_jsonb 
          GROUP BY SORT_JSON_OBJECT_KEYS(j);
   +--------------------------+----------+
   | SORT_JSON_OBJECT_KEYS(j) | COUNT(*) |
   +--------------------------+----------+
   | {"a":1,"b":2}            |        2 |
   +--------------------------+----------+
   ```

   При создании объектов JSON путём разбора текста (например, с помощью CAST для преобразования строк в JSON) Doris сохраняет порядок ключей в тексте. Поэтому, если данные JSONB создаются путём разбора текста, описанные выше проблемы с группировкой не возникнут.

### Рекомендации {#recommendations}
Если вы не можете обеспечить единообразие числовых типов или порядка ключей в данных JSON, рекомендуется предварительно обработать данные с помощью функций `NORMALIZE_JSON_NUMBERS_TO_DOUBLE` и `SORT_JSON_OBJECT_KEYS` перед выполнением операций `GROUP BY`, чтобы получить ожидаемые результаты.

### Синтаксис {#syntax}

**Определение:**
```sql
json_column_name JSON
```

**Вставка:**
- С помощью `INSERT INTO VALUES`: значение передаётся в виде строки в кавычках. Например:
```sql
INSERT INTO table_name(id, json_column_name) VALUES (1, '{"k1": "100"}')
```

- Для STREAM LOAD значение соответствующего столбца передаётся в виде строки без дополнительных кавычек. Например:
```
12	{"k1":"v31", "k2": 300}
13	[]
14	[123, 456]
```

- Если в JSON встречаются специальные символы с `'\'`, такие как `'\r'` и `'\t'`, необходимо использовать функцию replace для замены `"\"` на `"\\"`, например заменить `"\n"` на `"\\n"` 


**Запрос:**
- Выбор всего столбца JSON напрямую:
```sql
SELECT json_column_name FROM table_name;
```

- Извлечение определённых полей или другой информации из JSON с помощью функций JSON. Например:
```sql
SELECT json_extract(json_column_name, '$.k1') FROM table_name;
```

- Тип JSON можно преобразовывать в целые числа, строки, BOOLEAN, ARRAY и MAP, а также выполнять обратное преобразование. Например:
```sql
SELECT CAST('{"k1": "100"}' AS JSON);
SELECT CAST(json_column_name AS STRING) FROM table_name;
SELECT CAST(json_extract(json_column_name, '$.k1') AS INT) FROM table_name;
```

:::tip
В настоящее время тип JSON нельзя использовать в `ORDER BY` или операциях сравнения.
:::

## Ввод JSON {#json-input}

Преобразуйте строку, соответствующую синтаксису JSON, в JSONB с помощью CAST.

```sql
-- Simple scalar/basic values (numeric types, bool, null, string)
mysql> SELECT cast('5' as json);
+-------------------+
| cast('5' as json) |
+-------------------+
| 5                 |
+-------------------+

-- Arrays with zero or more elements (elements don't need to be the same type)
mysql> SELECT cast('[1, 2, "foo", null]' as json);
+-------------------------------------+
| cast('[1, 2, "foo", null]' as json) |
+-------------------------------------+
| [1,2,"foo",null]                    |
+-------------------------------------+

-- Objects containing key-value pairs
-- Note that object keys must always be quoted strings
mysql> SELECT cast('{"bar": "baz", "balance": 7.77, "active": false}' as json);
+------------------------------------------------------------------+
| cast('{"bar": "baz", "balance": 7.77, "active": false}' as json) |
+------------------------------------------------------------------+
| {"bar":"baz","balance":7.77,"active":false}                      |
+------------------------------------------------------------------+

-- Arrays and objects can be nested arbitrarily
mysql> SELECT cast('{"foo": [true, "bar"], "tags": {"a": 1, "b": null}}' as json);
+---------------------------------------------------------------------+
| cast('{"foo": [true, "bar"], "tags": {"a": 1, "b": null}}' as json) |
+---------------------------------------------------------------------+
| {"foo":[true,"bar"],"tags":{"a":1,"b":null}}                        |
+---------------------------------------------------------------------+
```

JSONB в Doris не сохраняет семантически незначимые детали, такие как пробельные символы.

```sql
mysql> -- The input text and JSON output may not look the same
mysql> SELECT cast('[1,                 2]' as json);
+----------------------------------------+
| cast('[1,                 2]' as json) |
+----------------------------------------+
| [1,2]                                  |
+----------------------------------------+
```

### Основные отличия и примечания: {#key-differences-and-notes}
- CAST(string AS JSON): используется для разбора строк, соответствующих синтаксису JSON. Для типа Number поддерживается разбор только типов Int8, Int16, Int32, Int64, Int128 и Double, но не Decimal.
- В отличие от большинства других реализаций JSON, тип JSONB в Doris поддерживает точность вплоть до Int128. Для чисел, превышающих точность Int128, возможно переполнение.
- Если входная строка с числом имеет вид 12.34, она будет разобрана как Double; если десятичной точки нет, она будет разобрана как целое число (если значение выходит за диапазон Int128, оно будет преобразовано в Double с потерей точности)

## Преобразование внутренних типов Doris в тип JSONB с помощью to_json {#using-to_json-to-convert-doris-internal-types-to-jsonb-type}

```sql
mysql> SELECT to_json(1) , to_json(3.14) , to_json("12345");
+------------+---------------+------------------+
| to_json(1) | to_json(3.14) | to_json("12345") |
+------------+---------------+------------------+
| 1          | 3.14          | "12345"          |
+------------+---------------+------------------+

mysql> SELECT to_json(array(array(1,2,3),array(4,5,6)));
+-------------------------------------------+
| to_json(array(array(1,2,3),array(4,5,6))) |
+-------------------------------------------+
| [[1,2,3],[4,5,6]]                         |
+-------------------------------------------+

mysql> SELECT json_extract(to_json(array(array(1,2,3),array(4,5,6))), '$.[1].[2]');
+----------------------------------------------------------------------+
| json_extract(to_json(array(array(1,2,3),array(4,5,6))), '$.[1].[2]') |
+----------------------------------------------------------------------+
| 6                                                                    |
+----------------------------------------------------------------------+

mysql> SELECT to_json(struct(123,array(4,5,6),"789"));
+------------------------------------------+
| to_json(struct(123,array(4,5,6),"789"))  |
+------------------------------------------+
| {"col1":123,"col2":[4,5,6],"col3":"789"} |
+------------------------------------------+

mysql> SELECT json_extract(to_json(struct(123,array(4,5,6),"789")),"$.col2");
+----------------------------------------------------------------+
| json_extract(to_json(struct(123,array(4,5,6),"789")),"$.col2") |
+----------------------------------------------------------------+
| [4,5,6]                                                        |
+----------------------------------------------------------------+
```

to_json поддерживает преобразование только тех типов Doris, которым соответствуют типы JSONB.
Например, DECIMAL можно использовать с to_json.
Однако DATE не поддерживается: сначала его необходимо преобразовать в STRING, а затем использовать to_json.

## Вывод JSONB {#jsonb-output}

При преобразовании в обычный текст для взаимодействия с другими системами тип JSONB в Doris обеспечивает формирование допустимого текста JSON:

1. Значения Null:
   - Выводятся как null (без кавычек)
2. Логические значения:
   - true → выводится true
   - false → выводится false
3. Числовые типы:
   - Все числовые значения выводятся напрямую
   - Пример: 5 → выводится 5, 3.14 → выводится 3.14
4. Строки:
   - Выводятся в двойных кавычках: "<content>"
   - Специальные символы экранируются:
     - " → \"
     - \ → \\
     - / → \/
     - Возврат на одну позицию → \b
     - Перевод страницы → \f
     - Перевод строки → \n
     - Возврат каретки → \r
     - Табуляция → \t
   - Другие управляющие символы (ASCII < 32) преобразуются в escape-последовательности Unicode: \uXXXX
5. Объекты:
   - Формат: {<key-value pairs list>}
   - Формат пары «ключ-значение»: "<key>": <value>
   - Несколько пар «ключ-значение» разделяются запятыми
6. Массивы:
   - Формат: [<element list>]
   - Несколько элементов разделяются запятыми
7. Обработка вложенных структур:
   - Объекты и массивы поддерживают неограниченную глубину вложенности
   - Каждый уровень вложенности обрабатывается рекурсивно по тем же правилам

## Проблемы точности чисел {#number-precision-issues}

При преобразовании внутренних типов Doris в JSONB с помощью to_json потери точности не происходит.
При использовании внутренних функций JSON в Doris, если возвращаемое значение также имеет тип JSONB, потери точности не происходит.
Однако преобразование JSONB в Doris в обычный текст с последующим обратным преобразованием в JSONB может привести к потере точности.

Пример: объект типа JSON в Doris
```
Object{
    "a": (Decimal 18446744073709551616.123)
}
```

После преобразования в обычный текст:
```
{"a": 18446744073709551616.123}
```

При обратном преобразовании обычного текста в тип JSON в Doris:
```
Object{
    "a": (Double 18446744073709552000)  // precision loss
}
```

## Настройка и ограничения {#configuration-and-limitations}
- По умолчанию JSON поддерживает размер 1,048,576 байт (1 MB)
- Ограничение размера можно изменить с помощью параметра конфигурации BE string_type_length_soft_limit_bytes
- Максимальное значение составляет 2,147,483,643 байт (приблизительно 2 GB)
- В объектах типа JSON в Doris длина ключа не может превышать 255 байт

### Часто задаваемые вопросы {#faq}

1. Есть ли разница между null в JSON и NULL в SQL (то есть при проверке IS NULL)?

Да, разница есть. В JSON значение null (например, {"key1": null}) означает, что ключ key1 существует и его значение явно задано как null. Это специальный тип, который кодируется в двоичном представлении JSON.

При этом NULL в SQL (при использовании IS NULL) может указывать на то, что ключ вообще отсутствует в объекте JSON.

Например:

``` sql
mysql> SELECT JSON_EXTRACT_STRING('{"key1" : null}', "$.key1") IS NULL;
+----------------------------------------------------------+
| JSON_EXTRACT_STRING('{"key1" : null}', "$.key1") IS NULL |
+----------------------------------------------------------+
|                                                        0 |
+----------------------------------------------------------+
1 row in set (0.00 sec)

mysql> SELECT JSON_EXTRACT_STRING('{"key1" : null}', "$.key_not_exist") IS NULL;
+-------------------------------------------------------------------+
| JSON_EXTRACT_STRING('{"key1" : null}', "$.key_not_exist") IS NULL |
+-------------------------------------------------------------------+
|                                                                 1 |
+-------------------------------------------------------------------+
1 row in set (0.01 sec)
```

2. Чем отличаются функции `GET_JSON_XXX` и `JSON_EXTRACT_XXX` и как выбрать подходящие?

Функции `GET_JSON_XXX` предназначены для работы со строковыми типами: они извлекают значения непосредственно из исходных строк JSON. Функции `JSON_EXTRACT_XXX` реализованы специально для типа данных JSON и оптимизированы для работы с ним.
