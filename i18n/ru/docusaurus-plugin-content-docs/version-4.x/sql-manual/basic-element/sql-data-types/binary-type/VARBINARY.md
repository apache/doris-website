## VARBINARY {#varbinary}
### Описание {#description}
Двоичная последовательность байтов переменной длины, где M обозначает максимальную длину (в байтах).

В отличие от VARCHAR, этот тип сохраняет исходные байты без интерпретации с учётом набора символов или правил сравнения (collation) и подходит для произвольных двоичных данных (например, фрагментов файлов, хешей, зашифрованных или сжатых данных). Максимальная длина составляет 2,147,483,647.

В настоящее время столбцы VARBINARY не поддерживаются в создаваемых материализованных представлениях, а также в качестве ключей Group By и Join Keys и в предикатах сравнения.

Версия и ограничения: поддерживается начиная с 4.0; в настоящее время не поддерживается в качестве типа столбца при создании таблиц и хранении данных в Doris. Для выполнения запросов можно сопоставлять поля BINARY/VARBINARY из внешних систем с типом VARBINARY в Doris через Catalogs.

### Внешние типы и ограничения начиная с 4.1.5 {#external-types-and-restrictions-since-415}

Начиная с 4.1.5, Catalogs всегда сохраняют внешние двоичные типы как `VARBINARY`; настройка `enable.mapping.varbinary=false` больше не восстанавливает сопоставление с `STRING`. Тип Iceberg `fixed(N)` сопоставляется с `VARBINARY(N)`, а UUID с `VARBINARY(16)`, в том числе при сериализации Block и обмене данными. Параметр файловых TVF `enable_mapping_varbinary` действует независимо, и его значение по умолчанию по-прежнему равно `false`; при необходимости включайте его явно.

Для двоичных полей Hive Text применяются совместимые с Hive кодирование и декодирование Base64. Преобразования с использованием шестнадцатеричных представлений требуют префикса `0x` и чётного количества допустимых шестнадцатеричных цифр; при некорректных входных данных возвращается `Invalid VARBINARY hex representation`.

Эта поддержка не добавляет возможность нативного хранения двоичных столбцов во внутренних таблицах Doris. VARBINARY нельзя использовать в качестве ключа Hash Join или Group By, в предикатах сравнения, в `IN` или `NOT IN`, а также в таких операциях, как `collect_set`, в которых не предусмотрена семантика работы с двоичными данными. Doris 4.1.5 явно отклоняет такие варианты использования.
