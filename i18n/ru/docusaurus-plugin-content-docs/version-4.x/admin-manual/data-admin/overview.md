Doris предоставляет полный набор возможностей аварийного восстановления, которые помогают справляться с рисками потери данных из-за **аппаратных сбоев, программных ошибок и ошибочных действий пользователей**. Сочетая **резервное копирование и восстановление** с **восстановлением из корзины**, можно обеспечить высокую доступность и надёжность данных при сбоях разного масштаба.

## Сценарии применения {#applicable-scenarios}

Разные возможности аварийного восстановления подходят для разных сценариев сбоев. Сочетайте их в зависимости от потребностей вашего бизнеса:

| Возможность | Сценарий применения | Уровень детализации восстановления | Скорость восстановления | Типичный пример использования |
| --- | --- | --- | --- | --- |
| Резервное копирование и восстановление | Повреждение данных, долгосрочное архивирование, миграция | База данных, таблица, раздел | От нескольких минут до нескольких часов (в зависимости от объёма данных) | Периодическое создание снимков, миграция между кластерами, архивирование для соблюдения нормативных требований |
| Восстановление из корзины | Недавние ошибки пользователей, например случайное удаление таблиц или баз данных | Таблица, база данных | Секунды | Восстановление после случайного удаления, краткосрочное хранение |

## Сравнение возможностей {#capability-comparison}

Эти две возможности различаются по степени защиты данных, эксплуатационным затратам и зависимостям:

| Критерий | Резервное копирование и восстановление | Восстановление из корзины |
| --- | --- | --- |
| Актуальность данных | Периодические снимки | Сохраняется состояние на момент удаления |
| Внешние зависимости | Требуется удалённое хранилище, например объектное хранилище или HDFS | Отсутствуют (данные хранятся локально в кластере) |
| Срок хранения | Определяется политикой резервного копирования | Настраиваемый срок хранения, автоматическая очистка по его истечении |
| Эксплуатационные затраты | Средние (периодические задания + стоимость хранения) | Низкие (включено по умолчанию) |

## 1. Резервное копирование и восстановление {#1-backup-and-restore}

Doris предоставляет функции резервного копирования и восстановления для периодического сохранения снимков данных, предотвращения потери данных из-за непредвиденных событий, а также для миграции данных и долгосрочного архивирования.

<!-- Knowledge type: Feature capability definition -->
<!-- Applicable scenarios: Periodic data protection / Cross-cluster migration / Compliance archiving -->

### Основные возможности {#key-features}

- **Резервное копирование**: поддерживает полное резервное копирование указанных баз данных, таблиц или разделов с сохранением полных снимков данных.
- **Восстановление**: поддерживает восстановление баз данных, таблиц или разделов из снимков.

### Пример сценария {#example-scenario}

Компания периодически создаёт резервные копии своих данных и сохраняет файлы резервных копий в сервисе объектного хранения (например, Amazon S3). При случайном удалении важной таблицы функция резервного копирования позволяет быстро восстановить потерянные данные и обеспечить нормальную работу бизнеса.

Подробные инструкции см. в разделах [Резервное копирование данных](./backup-restore/backup) и [Восстановление данных](./backup-restore/restore).

## 2. Восстановление из корзины {#2-recycle-bin-recovery}

Doris предоставляет корзину, которая позволяет быстро восстанавливать недавно удалённые данные и снижать последствия ошибочных действий пользователей.

<!-- Knowledge type: Feature capability definition -->
<!-- Applicable scenarios: Accidental deletion recovery / Short-term data retention -->

### Основные возможности {#key-features-1}

- **Временное удаление**: удаляемые таблицы или базы данных сначала перемещаются в корзину, а не удаляются окончательно сразу.
- **Срок хранения**: удалённые данные сохраняются в корзине в течение настраиваемого срока, пока он не истёк, их можно восстановить.
- **Быстрое восстановление**: случайно удалённые данные легко восстановить из корзины без полного процесса резервного копирования и восстановления.
- **Безопасность данных**: если восстановление не требуется, данные в корзине автоматически удаляются по истечении срока хранения.

### Пример сценария {#example-scenario-1}

Команда случайно удаляет важную таблицу во время повседневной работы. С помощью корзины она быстро восстанавливает удалённые данные, избегает сложного процесса резервного копирования и восстановления и обеспечивает непрерывную работу бизнеса.

Подробные инструкции см. в разделе [Корзина](./recyclebin).

## Часто задаваемые вопросы {#faq}

<!-- Knowledge type: FAQ -->
<!-- Applicable scenarios: Disaster recovery solution selection / Data recovery operations -->

### Вопрос: я случайно удалил таблицу. Какую функцию использовать для её восстановления? {#q-i-accidentally-dropped-a-table-which-feature-should-i-use-to-recover-it}

Сначала воспользуйтесь **восстановлением из корзины**. Оно занимает секунды и не зависит от внешнего хранилища. Если срок хранения уже истёк, используйте **резервное копирование и восстановление**, чтобы восстановить данные из последнего снимка.

### Вопрос: данные остаются в корзине навсегда? {#q-does-data-in-the-recycle-bin-stay-there-forever}

Нет. Удалённые данные сохраняются только в течение настраиваемого срока хранения и автоматически удаляются по его истечении. Для долгосрочного хранения используйте резервное копирование и восстановление.

### Вопрос: где можно хранить файлы резервных копий? {#q-where-can-backup-files-be-stored}

Файлы резервных копий можно хранить в удалённых хранилищах, таких как объектные хранилища (например, Amazon S3) и HDFS. Это позволяет избежать общей точки отказа с исходным кластером.
