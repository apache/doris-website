# Компактация {#compaction}

Doris записывает данные с использованием структуры, похожей на LSM-Tree, и непрерывно объединяет небольшие файлы в крупные упорядоченные файлы с помощью фоновой компактации. Компактация обрабатывает такие операции, как удаление и обновление.

Правильная настройка стратегии компактации позволяет значительно повысить эффективность загрузки и выполнения запросов. В Doris доступны следующие стратегии компактации:


## Вертикальная компактация {#vertical-compaction}

Вертикальная компактация представляет собой новый алгоритм компактации, реализованный в Doris 1.2.2. Он повышает эффективность выполнения компактации и снижает затраты ресурсов при работе с большими объёмами данных и широкими таблицами. Этот алгоритм позволяет существенно сократить потребление памяти и ускорить компактацию. Результаты тестирования показывают, что потребление памяти при вертикальной компактации составляет всего 1/10 от потребления исходного алгоритма, а скорость компактации увеличивается на 15%.

При вертикальной компактации объединение по строкам заменяется объединением по группам столбцов. Единицей каждого объединения становится группа столбцов, что уменьшает объём данных, обрабатываемых за одну операцию компактации, и снижает потребление памяти.

Параметры конфигурации BE:
- `enable_vertical_compaction = true` включает вертикальную компактацию.
- `vertical_compaction_num_columns_per_group = 5` задаёт количество столбцов в каждой группе. По результатам тестирования значение по умолчанию, 5 столбцов в группе, обеспечивает более благоприятное соотношение эффективности и потребления памяти.
- `vertical_compaction_max_segment_size` задаёт размер файла на диске после вертикальной компактации. Значение по умолчанию составляет 268435456 (байт).


## Компактация сегментов {#segment-compaction}

Компактация сегментов предназначена прежде всего для загрузки больших объёмов данных. В отличие от обычной и вертикальной компактации, она выполняется во время загрузки и объединяет сегменты внутри задания. Этот механизм позволяет существенно сократить количество создаваемых сегментов и избежать ошибок -238 (OLAP_ERR_TOO_MANY_SEGMENTS).

Компактация сегментов обеспечивает следующие возможности:
- Сокращает количество сегментов, создаваемых при загрузке.
- Выполняется параллельно с загрузкой, поэтому не увеличивает время загрузки.
- Увеличивает потребление памяти и вычислительных ресурсов во время загрузки, однако это увеличение относительно невелико, поскольку равномерно распределяется по всему длительному процессу загрузки.
- Повышает эффективность использования ресурсов и производительность последующих запросов и обычной компактации для обработанных данных.

Параметры конфигурации BE:
- `enable_segcompaction=true` включает компактацию сегментов.
- `segcompaction_batch_size` задаёт интервал объединения. Значение по умолчанию 10 означает, что компактация сегментов запускается после создания каждых 10 файлов сегментов. Рекомендуется устанавливать значение в диапазоне 10 - 30. Чем больше значение, тем выше потребление памяти при компактации сегментов.

Ситуации, в которых рекомендуется использовать компактацию сегментов:

- Загрузка больших объёмов данных завершается ошибкой OLAP_ ERR_ TOO_ MANY_ SEGMENTS (errcode - 238). В этом случае рекомендуется включить компактацию сегментов, чтобы сократить их количество во время загрузки.
- При загрузке создаётся слишком много небольших файлов: даже при умеренном объёме загружаемых данных большое количество небольших файлов сегментов может привести к сбою задания загрузки из-за низкой кардинальности или ограничений памяти, вызывающих преждевременный сброс memtable. В этом случае рекомендуется включить эту функцию.
- Запросы выполняются сразу после загрузки. Если загрузка только что завершилась, а стандартная компактация ещё не закончилась, большое количество файлов сегментов снижает эффективность последующих запросов. Если пользователю нужно выполнять запросы сразу после загрузки, рекомендуется включить эту функцию.
- Высокая нагрузка от обычной компактации после загрузки: компактация сегментов равномерно распределяет часть этой нагрузки на процесс загрузки. В этом случае рекомендуется включить эту функцию.

Ситуации, в которых компактация сегментов не рекомендуется:
- Если сама операция загрузки уже исчерпала доступную память, использовать компактацию сегментов не рекомендуется, поскольку она может дополнительно увеличить нагрузку на память и привести к сбою задания загрузки.

Дополнительные сведения о реализации и результатах тестирования доступны по этой [ссылке](https://github.com/apache/doris/pull/12866).

## Стратегия компактации {#compaction-strategy}

Стратегия компактации определяет, когда и какие небольшие файлы объединяются в более крупные. В настоящее время Doris предлагает две стратегии компактации, которые задаются параметром `compaction_policy` в свойствах таблицы.

### Стратегия компактации на основе размера {#size-based-compaction-strategy}

Стратегия компактации на основе размера используется по умолчанию и подходит для большинства сценариев.
```
"compaction_policy" = "size_based"
```

### Стратегия компактации временных рядов {#time-series-compaction-strategy}

Стратегия компактации временных рядов оптимизирована для таких сценариев, как работа с журналами и данными временных рядов. Она использует временную локальность данных временных рядов, объединяя небольшие файлы, записанные в близкие моменты времени, в более крупные. Каждый файл участвует в компактации только один раз, что снижает усиление записи, возникающее при повторной компактации.

```
"compaction_policy" = "time_series"
```

Компактация по стратегии временных рядов запускается при выполнении любого из следующих условий:
- Размер необъединённых файлов превышает `time_series_compaction_goal_size_mbytes` (по умолчанию 1 GB).
- Количество необъединённых файлов превышает `time_series_compaction_file_count_threshold` (по умолчанию 2000).
- Время с момента последней компактации превышает `time_series_compaction_time_threshold_seconds` (по умолчанию 1 час).

Эти параметры задаются в PROPERTIES таблицы. Их можно указать при создании таблицы или изменить позже с помощью следующей команды:
```
ALTER TABLE table_name SET("name" = "value");
```

## Управление параллельным выполнением компактации {#compaction-concurrency-control}

Компактация выполняется в фоновом режиме и потребляет ресурсы CPU и IO. Потребление ресурсов можно регулировать, изменяя количество одновременно работающих потоков компактации.

Количество одновременно работающих потоков компактации задаётся в конфигурационном файле BE с помощью следующих параметров:
- `max_base_compaction_threads`: количество потоков базовой компактации, по умолчанию 4.
- `max_cumu_compaction_threads`: количество потоков кумулятивной компактации, по умолчанию -1, что означает 1 поток на диск.
