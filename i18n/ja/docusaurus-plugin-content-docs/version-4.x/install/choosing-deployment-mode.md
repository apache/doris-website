## クイック選択

ビジネスの要件に合わせて、デプロイ構成を選択してください。

| シナリオ | 推奨構成 |
|------|----------|
| クラウド上でデプロイし、柔軟なスケーリングが必要 | ストレージ・コンピュート分離型 + クラウドプラットフォームでのデプロイ |
| 規模が固定されており、オンプレミスで運用する | ストレージ・コンピュート一体型 + 手動デプロイ |
| 大規模クラスターで、自動管理が必要 | ストレージ・コンピュート分離型 + Kubernetes デプロイ |

## ストレージ・コンピュート一体型と分離型の比較

| 項目 | ストレージ・コンピュート一体型 | ストレージ・コンピュート分離型 |
|--------|----------|----------|
| アーキテクチャ | データとコンピュートが密結合され、BE ノードがストレージとクエリ処理の両方を担う | コンピュート層（BE）とストレージ層（共有ストレージ）が分離される |
| 用途 | ビジネスの規模が固定されている場合、高いクエリ性能が求められる場合、共有ストレージを利用できない環境 | 柔軟なスケーリングが必要な場合、クラウドデプロイ、ビッグデータ分析 |
| 利点 | アーキテクチャがシンプルで、レイテンシーが低く、外部の共有ストレージが不要 | コンピュートリソースを独立してスケーリングでき、ストレージコストを抑えられ、リソース分離の柔軟性が高い |
| 欠点 | コンピュートリソースを独立してスケーリングできない | コンポーネントが増え、安定した共有ストレージサービスが必要 |

## デプロイ方法

### 手動デプロイ

スクリプトと設定ファイルを使って手動でデプロイします。小規模から中規模のクラスターや初期検証に適しています。

- 適しているケース：短時間での検証、最小構成のデプロイ、クラスターアーキテクチャの習得
- 適していないケース：大規模クラスター、頻繁な変更が必要な環境

詳しい手順は、[ストレージ・コンピュート一体型クラスターの手動デプロイ](./deploy-manually/integrated-storage-compute-deploy-manually)または[ストレージ・コンピュート分離型クラスターの手動デプロイ](./deploy-manually/separating-storage-compute-deploy-manually)を参照してください。

### Kubernetes デプロイ

Doris Operator を使って Kubernetes 上のクラスターを管理します。大規模な本番環境や自動化が必要な場合に適しています。

- 適しているケース：大規模クラスター、宣言的な管理が必要な場合、ハイブリッドクラウドへのデプロイ
- 必要なもの：Kubernetes クラスター、Doris Operator

詳しい手順は、[Kubernetes デプロイ](./deploy-on-kubernetes/intro)を参照してください。

### クラウドプラットフォームでのデプロイ

Alibaba Cloud や AWS などのクラウドプラットフォームに、クラウドネイティブのインフラストラクチャを活用してデプロイします。

- 適しているケース：クラウド上のワークロード、迅速なプロビジョニングや環境の分離が必要な場合
- 対応例：Alibaba Cloud ECI、AWS EKS など

詳しい手順は、[クラウドプラットフォームでのデプロイ](./deploy-on-cloud/doris-on-aws)を参照してください。

## 選択の目安

1. **Doris を初めて試す場合**：ストレージ・コンピュート一体型 + 手動デプロイから始めてください。アーキテクチャがシンプルで、導入しやすい構成です。
2. **小規模から中規模の本番環境**：ストレージ・コンピュート一体型 + 手動デプロイ、または Kubernetes デプロイを選択します。
3. **柔軟なスケーリングが必要なクラウド環境**：ストレージ・コンピュート分離型 + クラウドプラットフォームでのデプロイ、または Kubernetes デプロイを選択します。
4. **大規模な本番クラスター**：ストレージ・コンピュート分離型 + Kubernetes デプロイを選択します。運用の自動化が容易になります。

## よくある質問

### Q：ストレージ・コンピュート分離型のアーキテクチャはクエリ性能に大きく影響しますか？

コンピュート層とストレージ層が分離されるため、ストレージ・コンピュート分離型ではネットワークのオーバーヘッドが多少増えます。ただし、ほとんどのシナリオで影響は限定的です。理由は次のとおりです。
- 共有ストレージは通常、25Gbps RDMA などの高速ネットワーク環境にデプロイされます。
- データキャッシュにより、リモートからの読み取り頻度を効果的に減らせます。
- レイテンシーを極限まで抑える必要がある場合は、ストレージ・コンピュート一体型の方が適していることがあります。

### Q：既存のクラスターをストレージ・コンピュート一体型から分離型に移行するには、どうすればよいですか？

移行手順の概要は次のとおりです。
1. 新しい環境にストレージ・コンピュート分離型のクラスターをデプロイします。
2. Broker Load または Stream Load を使用してデータを移行します。
3. データの整合性とクエリ性能を検証します。
4. 旧クラスターを廃止します。

### Q：Kubernetes デプロイには専任の運用チームが必要ですか？

クラスターの規模によって異なります。
- 小規模クラスター（10 ノード以内）：Kubernetes デプロイによる複雑さの増加が、得られる利点に見合わない場合があります。
- 中規模から大規模のクラスター（10 ノード以上）：Kubernetes の自動化機能によって運用コストを大幅に削減できます。

### Q：クラウドプラットフォームでのデプロイと Kubernetes デプロイは、どう選べばよいですか？

| 項目 | クラウドプラットフォームでのデプロイ | Kubernetes デプロイ |
|--------|------------|------------------|
| 用途 | 迅速なデプロイ、柔軟なリソース | ハイブリッドクラウド、マルチクラウド環境 |
| 管理の複雑さ | 低い | 中程度 |
| 柔軟性 | クラウドプラットフォームの機能に制約される | 高く、カスタマイズできる |
| コスト | クラウドサービスの追加料金が発生する場合がある | より管理しやすい |
