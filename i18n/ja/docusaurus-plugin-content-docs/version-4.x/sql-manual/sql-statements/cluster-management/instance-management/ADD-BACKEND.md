## 説明

ADD BACKEND は、Doris クラスターに一つ以上の BE ノードを追加するために使用します。このコマンドでは、新しい BE ノードのホストとポートを指定できるほか、ノードの動作を設定するためのプロパティを任意で指定できます。

## 構文

```sql
ALTER SYSTEM ADD BACKEND "<host>:<heartbeat_port>"[,"<host>:<heartbeat_port>" [, ...]] [PROPERTIES ("<key>"="<value>" [, ...] )]
```

## 必須パラメータ

**1. <host>**

> BE ノードのホスト名または IP アドレスを指定します。

**2. <heartbeat_port>**

> BE ノードのハートビートポートを指定します。デフォルトは 9050 です。

## オプションパラメータ

**1. `PROPERTIES ("<key>"="<value>" [, ... ] )`**

> BE ノードの追加プロパティを定義するキーと値のペアです。追加する BE の設定をカスタマイズできます。指定できるプロパティは次のとおりです。
> - `tag.location`: ストレージとコンピュートの統合モードで、BE ノードが属するリソースグループを指定します。
> - `tag.compute_group_name`: ストレージとコンピュートの分離モードで、BE ノードが属するコンピュートグループを指定します。
> - `tag.public_endpoint`: 外部アクセス用の BE ノードのパブリックエンドポイントを指定します（例: `11.10.20.12:8010`）。通常は、外部ユーザーのアクセスに使用するロードバランサーのドメイン名またはパブリック IP です。
> - `tag.private_endpoint`: プライベートネットワークからのアクセスに使用する BE ノードのプライベートエンドポイントを指定します（例: `10.10.10.9:8020`）。通常は、クラスター内の VPC 内部アクセスや Kubernetes Service の IP に使用します。

## アクセス制御要件

この SQL を実行するユーザーには、少なくとも次の権限が必要です。

| 権限 | オブジェクト | 備考 |
|-----------|----|-------|
| NODE_PRIV |    |       |

## 使用上の注意

1. 新しい BE ノードを追加する前に、そのノードが正しく設定され、稼働していることを確認してください。
2. [リソースグループ](../../../../admin-manual/workload-management/resource-group.md)を使用すると、クラスター内の BE ノードを管理、整理しやすくなります。
3. 複数の BE ノードを追加する場合は、一つのコマンドで指定すると効率的です。
4. BE ノードを追加した後は、[`SHOW BACKENDS`](./SHOW-BACKENDS.md) を使用して、追加が成功し、ノードが正常な状態にあることを確認してください。
5. クラスターの可用性と耐障害性を高めるため、異なる物理的な場所やラックに BE ノードを配置することを検討してください。
6. 新しく追加した BE ノードが適切に利用されるように、クラスター内の負荷を定期的に確認し、分散してください。

## 例

1. 追加プロパティを指定せずに BE ノードを追加する
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.0.1:9050,192.168.0.2:9050";
   ```
   このコマンドは、クラスターに次の二つの BE ノードを追加します。
   * 192.168.0.1、ポート 9050
   * 192.168.0.2、ポート 9050
   追加プロパティを指定していないため、デフォルト設定が適用されます。

2. ストレージとコンピュートの統合モードで、指定したリソースグループに BE ノードを追加する
   ```sql
   ALTER SYSTEM ADD BACKEND "doris-be01:9050" PROPERTIES ("tag.location" = "groupb");
   ```
   このコマンドは、クラスター内のリソースグループ `groupb` に一つの BE ノード（ホスト名 doris-be01、ポート 9050）を追加します。

3. ストレージとコンピュートの分離モードで、指定したコンピュートグループに BE ノードを追加する
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.0.3:9050" PROPERTIES ("tag.compute_group_name" = "cloud_groupc");
   ```
   このコマンドは、クラスター内のコンピュートグループ `cloud_groupc` に一つの BE ノード（IP アドレス 192.168.0.3、ポート 9050）を追加します。

4. 複雑なネットワーク環境向けにパブリックエンドポイントとプライベートエンドポイントを設定して BE ノードを追加する
   ```sql
   ALTER SYSTEM ADD BACKEND "192.168.1.1:9050" PROPERTIES (
       "tag.public_endpoint" = "11.10.20.12:8010",
       "tag.private_endpoint" = "10.10.10.9:8020"
   );
   ```
   このコマンドは、複数のネットワークエンドポイントを持つ BE ノードを追加します。
   * `192.168.1.1:9050`: クラスター内の通信に使用する内部アドレス（be_host）
   * `11.10.20.12:8010`: ロードバランサー経由の外部ユーザーアクセスに使用するパブリックエンドポイント
   * `10.10.10.9:8020`: VPC 内部または Kubernetes のクラスター間アクセスに使用するプライベートエンドポイント

   この設定は、BE ノードに異なるネットワーク環境からアクセスする必要があるクラウド環境や Kubernetes クラスターで役立ちます。詳細は、[複雑なネットワーク環境での Stream Load](../../../../data-operate/import/load-best-practices/stream-load-in-complex-network.md)を参照してください。
