# JSON

## JSON の概要

JSON（JavaScript Object Notation）は、人が読めるテキストを使用してデータを保存・転送するためのオープン標準のファイル形式およびデータ交換形式です。公式仕様の [RFC7159](https://datatracker.ietf.org/doc/html/rfc7159) によると、JSON は次の基本型をサポートします。
- Bool
- Null
- Number
- String
- Array
- Object

JSON データ型は [JSON](https://www.rfc-editor.org/rfc/rfc8785) データをバイナリ形式で効率的に保存し、JSON 関数を使用して内部のフィールドにアクセスできます。

デフォルトで最大 1048576 バイト（1MB）をサポートし、最大 2147483643 バイト（2GB）まで拡張できます。この上限は `string_type_length_soft_limit_bytes` 設定で調整できます。

通常の STRING 型に JSON 文字列を保存する場合と比べて、JSON 型には主に次の利点があります。
1. データ挿入時に JSON 形式を検証します。
2. 効率的なバイナリ保存形式により、`json_extract` などの関数を使った JSON 内部フィールドへのアクセスが、`get_json_xx` 関数より高速になります。

:::caution 注意
バージョン 1.2.x では JSON 型は JSONB という名前でした。MySQL との互換性を保つため、バージョン 2.0.0 から JSON に改名されました。既存のテーブルでは以前の名前を引き続き使用できます。
:::

## JSON の数値精度に関する問題

JSON を使用する際は、数値の精度に特に注意が必要です。
- 多くのシステムでは、Number 型は IEEE 754-2008 の 64 ビット倍精度浮動小数点数を基に実装されています（例：C++ の double 型）。
- JSON 仕様は Number 型の内部表現を厳密には定めていません。また、JSON データはシステム間でテキストとして交換されるため、精度が失われることがあります。

たとえば、JSON 文字列 `{"abc": 18446744073709551616}` は次のようになります。

```sql
-- Conversion result in MySQL
cast('{"abc": 18446744073709551616}' as json)
-- Result: {"abc": 1.8446744073709552e19}
```

```javascript
// Conversion result in JavaScript
console.log(JSON.parse('{"abc": 18446744073709551616}'));
// Result: {abc: 18446744073709552000}
```

システム間でデータを交換する際に数値の精度を維持するには、大きな数値を `{"abc": "18446744073709551616"}` のように文字列として保存してください。

## Doris の JSON 型

Doris は JSON 標準仕様に準拠したデータ型をサポートし、保存時のバイナリエンコードには効率的な JSONB（JSON Binary）形式を使用します。

### サポートする型

Doris JSONB はすべての標準 JSON 型をサポートします。主な違いは、Number 型に対してより細かい拡張を提供し、Doris の内部型により正確に対応付けられる点です。

| JSON 型 | サブタイプ | 対応する Doris の型 |
|----------|-------|-----------------|
| Bool | - | BOOLEAN |
| Null | - | （直接対応する型はなく、JSON の null 値を表す） |
| Number | Int8 | TINYINT |
| | Int16 | SMALLINT |
| | Int32 | INT |
| | Int64 | BIGINT |
| | Int128 | LARGEINT |
| | Double | DOUBLE |
| | Float | FLOAT |
| | Decimal | DECIMAL |
| String | - | STRING |
| Array | - | ARRAY |
| Object | - | STRUCT |

### 重要な注意事項：
- Null の意味：
  - JSON の null は「空の値」を表す有効な値です。「不明」または「欠損」を表す SQL の NULL とは異なります。
  - CAST('null' AS JSON) の結果は、JSON の null 値を含む JSONB カラムです。このカラム自体は SQL レベルでは NULL ではありません。
  - CAST('null' AS JSON) IS NULL は false（0）を返します。カラムには既知の JSON の null 値が含まれており、SQL の NULL ではないためです。

## 操作と制限
- 比較と算術演算：
  - JSONB カラムを他のデータ型（別の JSONB カラムを含む）と直接比較したり、算術演算に使用したりすることはできません。
  - 対処方法：JSON_EXTRACT 関数で JSONB からスカラー値（INT、DOUBLE、STRING、BOOLEAN など）を抽出し、対応する Doris のネイティブ型に変換してから比較または計算します。
- ソート：
  - JSONB カラムは ORDER BY 操作をサポートしません。
- 暗黙的な変換：
  - 入力時のみ：JSONB カラムにデータを入力する際、STRING 型は文字列の内容が有効な JSON テキストであれば、暗黙的に JSONB に変換できます。他の Doris 型は JSONB に暗黙的に変換できません。


## JSON での GROUP BY と DISTINCT のサポート

### 例 1：JSON カラムに対する GROUP BY
```sql
mysql> SELECT * FROM test_jsonb_groupby;
+------+---------------+
| id   | j             |
+------+---------------+
|    1 | {"a":1,"b":2} |
|    2 | {"a":1,"b":3} |
|    3 | {"a":2,"b":2} |
|    4 | {"a":2,"b":2} |
|    5 | {"a":1,"b":2} |
|    6 | {"a":2,"b":2} |
+------+---------------+
6 rows in set (0.07 sec)

mysql> SELECT j, COUNT(*) FROM test_jsonb_groupby GROUP BY j;
+---------------+----------+
| j             | COUNT(*) |
+---------------+----------+
| {"a":1,"b":3} |        1 |
| {"a":2,"b":2} |        3 |
| {"a":1,"b":2} |        2 |
+---------------+----------+
```

### 例 2：JSON カラムに対する DISTINCT クエリ
```sql
mysql> SELECT DISTINCT j FROM test_jsonb_groupby;
+---------------+
| j             |
+---------------+
| {"a":1,"b":3} |
| {"a":2,"b":2} |
| {"a":1,"b":2} |
+---------------+
```

### 注意事項
1. **バイナリ比較**：JSON の比較はバイナリ表現に基づきます。JSON データ同士が意味的に同じでも、バイナリ表現が異なる場合は同じグループにまとめられません。例：
   ```sql
   mysql> SELECT * FROM test_jsonb;
   +------+------+
   | id   | j    |
   +------+------+
   |    1 | 123  |
   |    2 | 123  |
   +------+------+

   mysql> SELECT j, COUNT(*) FROM test_jsonb GROUP BY j;
   +------+----------+
   | j    | COUNT(*) |
   +------+----------+
   | 123  |        1 |
   | 123  |        1 |
   +------+----------+
   ```

   最初の `123` は内部で 64 ビット整数として保存され（`json_type` は `bigint` を返します）、後者の `123` はより小さい整数型として保存されます（`json_type` は `int` を返します。これは `bigint` 未満のすべての整数幅に適用されます）。そのため、バイナリ表現が異なります。次のクエリで型を確認できます。
   ```sql
   mysql> SELECT j, json_type(j, '$') FROM test_jsonb;
   +------+------------------+
   | j    | json_type(j, '$') |
   +------+------------------+
   | 123  | bigint           |
   | 123  | int              |
   +------+------------------+
   ```

   同様に、キーの順序が異なる JSON オブジェクトも同じグループにまとめられません。例：
   ```sql
   mysql> SELECT * FROM test_jsonb;
   +------+---------------+
   | id   | j             |
   +------+---------------+
   |    2 | {"b":2,"a":1} |
   |    1 | {"a":1,"b":2} |
   +------+---------------+

   mysql> SELECT j, COUNT(*) FROM test_jsonb GROUP BY j;
   +---------------+----------+
   | j             | COUNT(*) |
   +---------------+----------+
   | {"b":2,"a":1} |        1 |
   | {"a":1,"b":2} |        1 |
   +---------------+----------+
   ```

2. **数値型の統一**：数値型の違いを無視するには、`NORMALIZE_JSON_NUMBERS_TO_DOUBLE` 関数を使って JSON 内のすべての数値を `DOUBLE` 型に変換します。
   ```sql
   mysql> SELECT NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j), COUNT(*) 
          FROM test_jsonb 
          GROUP BY NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j);
   +-------------------------------------+----------+
   | NORMALIZE_JSON_NUMBERS_TO_DOUBLE(j) | COUNT(*) |
   +-------------------------------------+----------+
   | 123                                 |        2 |
   +-------------------------------------+----------+
   ```
   JSON オブジェクトをテキストの解析によって作成する場合（たとえば、CAST で文字列を JSON に変換する場合）、Doris は保存に適切な数値型を自動的に選択します。そのため、通常、数値型の不一致は問題になりません。

3. **キーの順序の統一**：
   `SORT_JSON_OBJECT_KEYS` 関数を使用してキーをソートします。
   ```sql
   mysql> SELECT SORT_JSON_OBJECT_KEYS(j), COUNT(*) 
          FROM test_jsonb 
          GROUP BY SORT_JSON_OBJECT_KEYS(j);
   +--------------------------+----------+
   | SORT_JSON_OBJECT_KEYS(j) | COUNT(*) |
   +--------------------------+----------+
   | {"a":1,"b":2}            |        2 |
   +--------------------------+----------+
   ```

   JSON オブジェクトをテキストの解析によって作成する場合（たとえば、CAST で文字列を JSON に変換する場合）、Doris はテキスト内のキーの順序を維持します。そのため、JSONB データをテキストの解析によって作成した場合、上記のグループ化の問題は発生しません。

### 推奨事項
JSON データの数値型やキーの順序を統一できない場合は、`NORMALIZE_JSON_NUMBERS_TO_DOUBLE` 関数と `SORT_JSON_OBJECT_KEYS` 関数でデータを前処理してから `GROUP BY` を実行し、期待どおりの結果を得ることを推奨します。

### 構文

**定義：**
```sql
json_column_name JSON
```

**挿入：**
- `INSERT INTO VALUES` では、値を引用符で囲んだ文字列として指定します。例：
```sql
INSERT INTO table_name(id, json_column_name) VALUES (1, '{"k1": "100"}')
```

- STREAM LOAD では、対応するカラムを追加の引用符なしの文字列として指定します。例：
```
12	{"k1":"v31", "k2": 300}
13	[]
14	[123, 456]
```

- JSON に `'\'` を含む特殊文字（`'\r'`、`'\t'` など）がある場合は、replace 関数を使用して `"\"` を `"\\"` に置き換える必要があります。たとえば、`"\n"` を `"\\n"` に置き換えます。


**クエリ：**
- JSON カラム全体を直接取得します。
```sql
SELECT json_column_name FROM table_name;
```

- JSON 関数を使用して、特定のフィールドやその他の情報を抽出します。例：
```sql
SELECT json_extract(json_column_name, '$.k1') FROM table_name;
```

- JSON 型は整数、文字列、BOOLEAN、ARRAY、MAP との間でキャストできます。例：
```sql
SELECT CAST('{"k1": "100"}' AS JSON);
SELECT CAST(json_column_name AS STRING) FROM table_name;
SELECT CAST(json_extract(json_column_name, '$.k1') AS INT) FROM table_name;
```

:::tip
JSON 型は現在、`ORDER BY` や比較演算には使用できません。
:::

## JSON の入力

CAST を使用して、JSON 構文に準拠する文字列を JSONB に変換します。

```sql
-- Simple scalar/basic values (numeric types, bool, null, string)
mysql> SELECT cast('5' as json);
+-------------------+
| cast('5' as json) |
+-------------------+
| 5                 |
+-------------------+

-- Arrays with zero or more elements (elements don't need to be the same type)
mysql> SELECT cast('[1, 2, "foo", null]' as json);
+-------------------------------------+
| cast('[1, 2, "foo", null]' as json) |
+-------------------------------------+
| [1,2,"foo",null]                    |
+-------------------------------------+

-- Objects containing key-value pairs
-- Note that object keys must always be quoted strings
mysql> SELECT cast('{"bar": "baz", "balance": 7.77, "active": false}' as json);
+------------------------------------------------------------------+
| cast('{"bar": "baz", "balance": 7.77, "active": false}' as json) |
+------------------------------------------------------------------+
| {"bar":"baz","balance":7.77,"active":false}                      |
+------------------------------------------------------------------+

-- Arrays and objects can be nested arbitrarily
mysql> SELECT cast('{"foo": [true, "bar"], "tags": {"a": 1, "b": null}}' as json);
+---------------------------------------------------------------------+
| cast('{"foo": [true, "bar"], "tags": {"a": 1, "b": null}}' as json) |
+---------------------------------------------------------------------+
| {"foo":[true,"bar"],"tags":{"a":1,"b":null}}                        |
+---------------------------------------------------------------------+
```

Doris の JSONB は、空白のような意味に影響しない細部を保持しません。

```sql
mysql> -- The input text and JSON output may not look the same
mysql> SELECT cast('[1,                 2]' as json);
+----------------------------------------+
| cast('[1,                 2]' as json) |
+----------------------------------------+
| [1,2]                                  |
+----------------------------------------+
```

### 主な違いと注意事項：
- CAST(string AS JSON)：JSON 構文に準拠する文字列を解析します。Number 型については Int8、Int16、Int32、Int64、Int128、Double のみを解析し、Decimal 型は解析しません。
- 多くの JSON 実装と異なり、Doris の JSONB 型は Int128 までの精度をサポートします。Int128 の精度を超える数値はオーバーフローする可能性があります。
- 入力数値の文字列が 12.34 の場合は Double として解析します。小数点がない場合は整数として解析します（Int128 の範囲を超えると Double に変換されますが、精度が失われます）。

## to_json を使用した Doris 内部型から JSONB 型への変換

```sql
mysql> SELECT to_json(1) , to_json(3.14) , to_json("12345");
+------------+---------------+------------------+
| to_json(1) | to_json(3.14) | to_json("12345") |
+------------+---------------+------------------+
| 1          | 3.14          | "12345"          |
+------------+---------------+------------------+

mysql> SELECT to_json(array(array(1,2,3),array(4,5,6)));
+-------------------------------------------+
| to_json(array(array(1,2,3),array(4,5,6))) |
+-------------------------------------------+
| [[1,2,3],[4,5,6]]                         |
+-------------------------------------------+

mysql> SELECT json_extract(to_json(array(array(1,2,3),array(4,5,6))), '$.[1].[2]');
+----------------------------------------------------------------------+
| json_extract(to_json(array(array(1,2,3),array(4,5,6))), '$.[1].[2]') |
+----------------------------------------------------------------------+
| 6                                                                    |
+----------------------------------------------------------------------+

mysql> SELECT to_json(struct(123,array(4,5,6),"789"));
+------------------------------------------+
| to_json(struct(123,array(4,5,6),"789"))  |
+------------------------------------------+
| {"col1":123,"col2":[4,5,6],"col3":"789"} |
+------------------------------------------+

mysql> SELECT json_extract(to_json(struct(123,array(4,5,6),"789")),"$.col2");
+----------------------------------------------------------------+
| json_extract(to_json(struct(123,array(4,5,6),"789")),"$.col2") |
+----------------------------------------------------------------+
| [4,5,6]                                                        |
+----------------------------------------------------------------+
```

to_json は、JSONB 型に対応する Doris の型からの変換のみをサポートします。
たとえば、DECIMAL は to_json で変換できます。
一方、DATE は直接変換できません。先に STRING に変換してから to_json を使用する必要があります。

## JSONB の出力

他のシステムとのやり取りのためにプレーンテキストに変換する際、Doris の JSONB 型は有効な JSON テキストを生成します。

1. null 値：
   - 引用符なしの null として出力します。
2. 真偽値：
   - true → true として出力します。
   - false → false として出力します。
3. 数値型：
   - すべての数値をそのまま出力します。
   - 例：5 → 5、3.14 → 3.14
4. 文字列：
   - ダブルクォートで囲んで出力します："<content>"
   - 特殊文字はエスケープします。
     - " → \"
     - \ → \\
     - / → \/
     - バックスペース → \b
     - 改ページ → \f
     - 改行 → \n
     - 復帰 → \r
     - タブ → \t
   - その他の制御文字（ASCII < 32）は Unicode エスケープシーケンスに変換します：\uXXXX
5. オブジェクト：
   - 形式：{<key-value pairs list>}
   - キーと値のペアの形式："<key>": <value>
   - 複数のキーと値のペアはカンマで区切ります。
6. 配列：
   - 形式：[<element list>]
   - 複数の要素はカンマで区切ります。
7. ネストした構造の処理：
   - オブジェクトと配列は、ネストの深さに制限がありません。
   - 各階層を同じ規則に従って再帰的に処理します。

## 数値精度に関する問題

to_json を使用して Doris の内部型を JSONB に変換する場合、精度は失われません。
Doris の内部 JSON 関数を使用し、戻り値も JSONB 型の場合、精度は失われません。
ただし、Doris の JSONB をプレーンテキストに変換し、再び JSONB に戻すと、精度が失われる可能性があります。

例：Doris の JSON 型オブジェクト
```
Object{
    "a": (Decimal 18446744073709551616.123)
}
```

プレーンテキストへの変換後：
```
{"a": 18446744073709551616.123}
```

プレーンテキストを Doris の JSON 型に戻した場合：
```
Object{
    "a": (Double 18446744073709552000)  // precision loss
}
```

## 設定と制限
- JSON はデフォルトで 1,048,576 バイト（1 MB）までサポートします。
- サイズの上限は BE の設定パラメーター string_type_length_soft_limit_bytes で調整できます。
- 最大 2,147,483,643 バイト（約 2 GB）まで拡張できます。
- Doris の JSON 型のオブジェクトでは、キーの長さは 255 バイトを超えられません。

## 使用例
テーブルの作成、データのロード、クエリを含む JSON データ型のチュートリアルです。

```
CREATE TABLE test_json (
  id INT,
  j JSON
)
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 10
PROPERTIES("replication_num" = "1");
```

### よくある質問

1. JSON の null と SQL の NULL（IS NULL で判定する値）には違いがありますか？

はい、違いがあります。JSON の null（例：{"key1": null}）は、キー key1 が存在し、その値が明示的に null であることを意味します。これは JSON のバイナリ形式にエンコードされる特別な型です。

一方、SQL の NULL（IS NULL で判定する値）は、JSON オブジェクトにキーがまったく存在しないことを示す場合があります。

例：

``` sql
mysql> SELECT JSON_EXTRACT_STRING('{"key1" : null}', "$.key1") IS NULL;
+----------------------------------------------------------+
| JSON_EXTRACT_STRING('{"key1" : null}', "$.key1") IS NULL |
+----------------------------------------------------------+
|                                                        0 |
+----------------------------------------------------------+
1 row in set (0.00 sec)

mysql> SELECT JSON_EXTRACT_STRING('{"key1" : null}', "$.key_not_exist") IS NULL;
+-------------------------------------------------------------------+
| JSON_EXTRACT_STRING('{"key1" : null}', "$.key_not_exist") IS NULL |
+-------------------------------------------------------------------+
|                                                                 1 |
+-------------------------------------------------------------------+
1 row in set (0.01 sec)
```

2. `GET_JSON_XXX` 関数と `JSON_EXTRACT_XXX` 関数の違いは何ですか？どちらを使うべきですか？

`GET_JSON_XXX` 関数は文字列型向けで、生の JSON 文字列から直接値を抽出します。一方、`JSON_EXTRACT_XXX` 関数は JSON データ型専用に実装され、その型に最適化されています。
