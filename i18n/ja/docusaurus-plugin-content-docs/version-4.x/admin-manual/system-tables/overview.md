# 概要

Apache Doris クラスターには、Doris システム自体のメタデータを格納する複数の組み込みシステムデータベースがあります。

### information_schema

`information_schema` データベース内のテーブルはすべて仮想テーブルであり、物理的な実体を持ちません。これらのシステムテーブルには、データベース、テーブル、カラム、権限など、Doris クラスターとそのすべてのデータベースオブジェクトに関するメタデータが含まれます。また、Workload Group や Task などの機能の状態に関する情報も含まれます。

各 Catalog には `information_schema` データベースがあり、対応する Catalog のデータベースとテーブルのメタデータのみが格納されます。

`information_schema` データベース内のテーブルはすべて読み取り専用です。ユーザーは、このデータベース内のテーブルを変更、削除、作成できません。

デフォルトでは、すべてのユーザーがこのデータベース内のすべてのテーブルを読み取れますが、クエリ結果はユーザーが実際に持つ権限によって異なります。たとえば、ユーザー A が `db1.table1` に対する権限しか持たない場合、`information_schema.tables` テーブルをクエリしても、`db1.table1` に関連する情報だけが返されます。

### mysql

`mysql` データベース内のテーブルはすべて仮想テーブルであり、物理的な実体を持ちません。これらのシステムテーブルには権限などの情報が含まれ、主に MySQL エコシステムとの互換性のために使用されます。

各 Catalog には `mysql` データベースがありますが、テーブルの内容は同一です。

`mysql` データベース内のテーブルはすべて読み取り専用です。ユーザーは、このデータベース内のテーブルを変更、削除、作成できません。

### __internal_schema

`__internal_schema` データベース内のテーブルはすべて Doris の実テーブルであり、ユーザーが作成したデータテーブルと同様に格納されます。Doris クラスターの作成時に、このデータベース内のすべてのシステムテーブルが自動的に作成されます。

デフォルトでは、一般ユーザーはこのデータベース内のテーブルに対して読み取り専用の権限を持ちます。ただし、権限が付与されると、このデータベース内のテーブルを変更、削除、作成できます。
