クエリのパフォーマンスチューニングは、データベースシステムを複数の層と観点から評価し、最適化する体系的な取り組みです。この記事では、実務者の視点から、Apache Doris のパフォーマンスチューニングの全体的な流れ、方法、ツールを紹介します。

## 作業前のチェックリスト

<!-- Knowledge type: Pre-check -->
<!-- Applicable scenario: Preparation before tuning work begins -->

具体的なチューニングに入る前に、以下を確認してください。

- 業務システムのハードウェア構成（CPU、メモリ、ディスク、ネットワーク）を把握している。
- Doris クラスターの規模（FE/BE ノード数）を確認している。
- Doris のソフトウェアバージョンと、そのバージョンで利用できる機能を確認している。
- 「業務処理が遅い」ことと「SQL が遅い」ことを区別し、問題のある SQL を特定できる。
- 利用できる診断・分析ツールを把握している。

## 1. パフォーマンスチューニングの方法

<!-- Knowledge type: Methodology -->
<!-- Applicable scenario: Build an overall understanding of tuning -->

パフォーマンスチューニングの流れを一言で表すと、**まずシステムを理解し、次に遅い SQL を特定し、ツールでボトルネックを見つけ、最後に最適化を行います。**

### 1.1 チューニングの四段階

次の表に、パフォーマンスチューニングの基本的な流れを示します。

| ステップ | 目標 | 主な作業 |
| ---- | ---- | ---- |
| 1 | システムを理解する | ハードウェア、クラスターの規模、Doris のバージョン、バージョン固有の機能を把握する |
| 2 | 問題のある SQL を特定する | 診断ツールを使い、遅い SQL を効率よく素早く見つける |
| 3 | パフォーマンスのボトルネックを分析する | Doris の組み込みツールと一般的な OS ツールを使い、実行時の情報を収集する |
| 4 | チューニングを行う | ボトルネックの分析結果に基づき、パラメーターの調整、SQL の書き換え、インデックスやマテリアライズドビューなどによる最適化を行う |

### 1.2 各ステップの説明

-   **ステップ 1: システムを理解する。** 業務ユーザーと DBA は、調査の方向を誤らないよう、使用しているデータベースシステムを十分に理解する必要があります。
-   **ステップ 2: 遅い SQL を特定する。** パフォーマンスの問題を特定するには、役立つ診断ツールが欠かせません。問題のある SQL を素早く特定して初めて、その後の作業を有効に進められます。
-   **ステップ 3: ボトルネックを分析する。** Doris 固有のツール（Profile、Explain など）と一般的な OS ツール（top、iostat など）を組み合わせ、ボトルネックの所在を判断します。
-   **ステップ 4: 最適化を行う。** 詳細な実行時情報と補足的な分析に基づき、対象を絞って設定を調整したり、SQL を書き換えたりします。

## 3. よくある質問と誤解

<!-- Knowledge type: FAQ -->
<!-- Applicable scenario: Common questions during tuning -->

**Q1: パフォーマンスチューニングは、必ず SQL の書き換えから始める必要がありますか？**

いいえ。まずシステムを理解し、遅い SQL を特定することから始めます。この二つのステップを飛ばしてすぐに SQL を書き換えると、実際のボトルネックを見逃すことがよくあります。

**Q2: Doris の組み込みツールだけで十分ですか？**

いいえ。一般的な OS ツール（top、iostat、vmstat など）も補助的に使うことで、CPU、IO、メモリのリソースに関するボトルネックを見つけやすくなります。

**Q3: チューニングは DBA だけの仕事ですか？**

いいえ。パフォーマンスチューニングには、業務ユーザー、DBA、場合によっては開発者の協力が必要です。業務ユーザーは SQL の意味を理解しており、DBA はクラスターとデータベースの特性を把握しています。
