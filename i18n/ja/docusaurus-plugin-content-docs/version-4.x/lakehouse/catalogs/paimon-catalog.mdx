Doris は、さまざまなメタデータサービスを介した Paimon テーブルのメタデータへのアクセスと、Paimon データの読み書きをサポートしています。

[Apache Doris と Apache Paimon のクイックスタート](../best-practices/doris-paimon.md)。

## 利用シナリオ {#applicable-scenarios}

| シナリオ | 説明 |
| ------------ | ------------------------------------------------------------ |
| クエリの高速化 | Doris の分散コンピューティングエンジンから Paimon データに直接アクセスし、クエリを高速化します。 |
| データ統合 | Paimon データを読み取って Doris の内部テーブルに書き込むか、Doris のコンピューティングエンジンを使用して ZeroETL 操作を実行します。 |
| データの書き戻し | Doris SQL を使用して Paimon テーブルを作成・変更し、データの追加や上書き、主キーテーブルの行単位の変更を行います。 |

## Catalog の設定 {#configuring-catalog}

### 構文 {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = '<paimon_catalog_type>',
    'warehouse' = '<paimon_warehouse>'
    {MetaStoreProperties},
    {StorageProperties},
    {PaimonProperties},
    {CommonProperties}
);
```

* `<paimon_catalog_type>`

  Paimon Catalog の種類です。以下をサポートします。

  * `filesystem`：デフォルト。ファイルシステムに保存されたメタデータに直接アクセスします。

  * `hms`：Hive Metastore をメタデータサービスとして使用します。

  * `dlf`：Alibaba Cloud DLF をメタデータサービスとして使用します。

  * `jdbc`：JDBC インターフェースを使用して、メタデータサービスとして機能するリレーショナルデータベースに接続します（バージョン 4.1.0 以降でサポート）。

* `<paimon_warehouse>`

  Paimon のウェアハウスパスです。`<paimon_catalog_type>` が `filesystem` の場合、このパラメータは必須です。

  `warehouse` パスは、`Database` パスの 1 つ上の階層を指す必要があります。たとえば、テーブルのパスが `s3://bucket/path/to/db1/table1` の場合、`warehouse` は `s3://bucket/path/to/` にします。

* `{MetaStoreProperties}`

  MetaStoreProperties セクションには、Metastore メタデータサービスへの接続情報と認証情報を設定します。詳細は[サポートされるメタデータサービス]のセクションを参照してください。

* `{StorageProperties}`

  StorageProperties セクションには、ストレージシステムに関する接続情報と認証情報を設定します。詳細は[サポートされるストレージシステム]のセクションを参照してください。

* `{PaimonProperties}`

  PaimonProperties セクションには、Paimon 関連のプロパティを設定します。

  Doris が Paimon メタデータにアクセスする際は、Paimon Java SDK の一部を使用します。そのため、一部のカスタムパラメータを Paimon Java SDK に渡す必要がある場合があります。次のプレフィックスを使用できます。

  ```
  paimon.s3.xxx
  paimon.s3a.xxx
  paimon.fs.xxx
  ```

  これらのパラメータは自動的に変換され、引き渡されます。例を以下に示します。

  | 入力パラメータ | Paimon Java SDK 向けに変換されたパラメータ |
  | --- | --- |
  | "paimon.s3.list.version" = "1" | "fs.s3a.list.version" = "1" |
  | "paimon.s3.paging.maximum" = "100" | "fs.s3a.paging.maximum" = "100" |
  | "paimon.fs.s3.read.ahead.buffer.size" = "1" | "fs.s3a.read.ahead.buffer.size" = "1" |
  | "paimon.s3a.replication.factor" = "3" | "fs.s3a.replication.factor" = "3" |

  **Paimon の読み取りオプション**

  Doris は、以下の Paimon バッチ読み取りオプションをサポートします。Catalog 全体に適用するクエリのデフォルト値は
  `paimon.table-option.<option-key>` で設定し、個々のテーブル参照では
  `table@options('<option-key>'='<value>')` で上書きできます。これらの設定は Doris による読み取りにのみ影響し、
  物理 Paimon テーブルのメタデータは更新しません。

  | Paimon オプション | Paimon のデフォルト値 | Doris が受け付ける値 | 効果 |
  | --- | --- | --- | --- |
  | `read.batch-size` | `1024` | `1`～`65536` の整数 | Paimon JNI リーダーの各バッチで要求する行数。明示的に設定した値は、Doris がリーダーを開く際にも維持されます。 |
  | `file-reader-async-threshold` | `10 MB` | `1 MB`～`1 GB` のメモリサイズ | Paimon JNI リーダーが非同期読み取りに切り替えるファイルサイズのしきい値。 |
  | `file-index.read.enabled` | `true` | 真偽値 | 読み取り時の Paimon ファイルインデックスによる絞り込みを有効にします。 |
  | `source.split.target-size` | `128 MB` | 正のメモリサイズ | Paimon がデータファイルを Doris のスキャン分割にまとめる際の目標サイズ。 |
  | `source.split.open-file-cost` | `4 MB` | 0 以上のメモリサイズ | Paimon がファイルを分割にまとめる際に使用する、ファイルを開くための推定コスト。 |
  | `scan.manifest.parallelism` | 利用可能なプロセッサ数 | `1`～`256` の整数 | 要求するマニフェスト読み取りの並列度。実行時、Doris は計画の各分岐について、この値、`256`、およびその FE または BE で利用可能なプロセッサ数のうち最小の値を上限とします。 |
  | `scan.plan-sort-partition` | `false` | 真偽値 | Paimon スキャンの計画時にパーティションを並べ替えます。 |

  たとえば、次の Catalog 設定は物理 Paimon テーブルに保存された値を上書きし、Doris のクエリに適用される
  デフォルト値になります。

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.table-option.read.batch-size" = "4096",
      "paimon.table-option.file-reader-async-threshold" = "32 MB",
      "paimon.table-option.source.split.target-size" = "64 MB",
      "paimon.table-option.scan.manifest.parallelism" = "1"
  );
  ```

  クエリでは、Catalog や Paimon テーブルのメタデータを変更せずに、これらのデフォルト値を上書きできます。

  ```sql
  SELECT *
  FROM paimon_hms.db_name.table_name@options(
      'read.batch-size' = '8192',
      'source.split.target-size' = '32 MB'
  );
  ```

  オプションの集合はテーブル参照ごとに独立しています。たとえば、同じテーブルの 2 つのエイリアスに、1 つのステートメント内で異なる
  バッチサイズを指定できます。

  ```sql
  SELECT small.id
  FROM paimon_hms.db_name.table_name@options('read.batch-size' = '1') small
  JOIN paimon_hms.db_name.table_name@options('read.batch-size' = '8192') large
    ON small.id = large.id;
  ```

  優先順位は高い順に次のとおりです。

  ```text
  relation @options > Doris Catalog property > physical Paimon table option > Paimon default
  ```

  Doris は、この優先順位を適用した後の最終的な値を検証します。そのため、物理テーブルに無効な値があっても、Catalog またはテーブル参照に設定した有効な値で
  置き換えられます。最終的な値が無効な場合、Doris は該当する計画段階またはリーダー段階に入る前にクエリを拒否します。
  マニフェストの上限も、パーティション、行数・統計情報、フォールバック分岐、およびシステムテーブルのマニフェスト計画前に適用されます。

  表の最初の 5 つのオプションはメタデータに影響せず、キャッシュされた最新のパーティション投影を再利用できます。
  `scan.manifest.parallelism` と `scan.plan-sort-partition` はメタデータの計画に影響するため、Doris は
  テーブル参照ごとの有効なテーブルハンドルを使用して計画します。クエリごとの値によって、Paimon の JVM 全体で共有するエグゼキューターのサイズは変更されません。

  Doris は、`CREATE CATALOG` および `ALTER CATALOG` の実行時に、不明または無効な `paimon.table-option.*` プロパティを拒否します。
  `ALTER CATALOG` は、設定を公開する前に候補となる設定全体を検証します。そのため、変更に失敗した場合は以前の
  Catalog 設定が有効なままです。古い Doris バージョンで永続化された Catalog も読み込めますが、
  サポート対象外または無効な旧リーダープロパティは適用されず、無視されます。それらの永続化された値は、
  イメージおよび編集ログとの互換性のために保持されます。

  スナップショットと開始位置のオプションはテーブル参照のコンテキストを選択するものであり、
  [タイムトラベル](#time-travel-with-options)で説明するように `@options` を使用する必要があります。Catalog のデフォルト値にはできません。Doris は、
  Paimon の Flink ソースエニュメレーターに属する `scan.max-splits-per-task`、`scan.fallback-branch`、およびストリーミング、
  レイアウト、書き込み、コンパクションのオプションも対象外とします。Bucket、Primary Key、Partition、Merge Engine などの物理的な
  動作は、Doris の `CREATE TABLE ... PROPERTIES` を含め、Paimon テーブルのプロパティとして設定してください。

  :::info ステートメントの一貫性
  Doris は 1 つのステートメント内で、スキーマのバインド、パーティションの読み込み、行数・統計情報の収集、システムテーブルの
  計画、およびデータスキャンに対して、同じ Paimon スナップショットとテーブル世代を使用します。
  `@options` で選択したスナップショットまたはタグには、その履歴バージョンに対応するスキーマが使用されます。ネストした `STRUCT`、`MAP`、`ARRAY`
  フィールドも対象です。準備済みステートメントの実行ごとに新しいステートメント状態が取得されるため、実行間のコミットは
  新たな実行のセレクターとキャッシュ設定に従って反映されます。
  :::

  運用上の安全性のため、Paimon スキャナーの DEBUG 設定メッセージにはバッチサイズと投影フィールド数のみが出力されます。
  Doris は、認証情報を含む可能性があるスキャナーパラメータの生のマップを出力しません。
  `PaimonJniAsyncReaderThreadCount` プロファイルゲージはスキャナー全体について 1 秒に 1 回サンプリングされるため、
  最大 1 秒古い値になる場合があります。このサンプリングはクエリの実行やスケジューリングに影響しません。リーダーと IOManager の
  クリーンアップは独立しており、クローズ処理が途中で失敗しても安全に再試行できます。

  **Paimon JNI IOManager**

  > この機能はバージョン 4.0.8 以降でサポートされます。

  Paimon の主キーテーブルでは、JNI によるマージ読み取り時に、複数ファイルのデータをソートしてマージする必要がある場合があります。
  Paimon IOManager を有効にすると、この処理の中間データを BE のローカルディスクに退避でき、
  大量のデータをマージ読み取りする際のメモリ負荷を軽減できます。

  | プロパティ | 必須 | デフォルト値 | 説明 |
  | --- | --- | --- | --- |
  | `paimon.jni.enable_jni_io_manager` | いいえ | `false` | JNI 読み取りで Paimon IOManager を有効にするかどうか。他の IOManager プロパティは、これが `true` の場合にのみ有効です。 |
  | `paimon.jni.io_manager.tmp_dir` | いいえ | `<storage_root_path>/paimon_jni_scanner_io_tmp` | Paimon IOManager が一時退避ファイルに使用するローカルディレクトリ。複数のディレクトリはコンマまたはコロンで区切れます。省略すると、Doris は各 BE ストレージパスの下にディレクトリを 1 つ作成します。 |
  | `paimon.jni.io_manager.impl_class` | いいえ | Paimon のデフォルト実装 | カスタム `org.apache.paimon.disk.IOManager` 実装の完全修飾クラス名。このクラスは、すべての BE の Paimon JNI Scanner クラスパスから利用できる必要があります。 |

  次の例では IOManager を有効にし、BE のストレージパスから一時ディレクトリを Doris に選択させます。

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.jni.enable_jni_io_manager" = "true"
  );
  ```

  IOManager を有効にしても、すべてのマージ読み取りでディスクへの退避が発生するわけではありません。Paimon は、マージリーダーの数が
  `sort-spill-threshold` を超えた場合にのみ退避します。これは Doris の動的なリーダーオプションではありません。
  退避動作を変更する必要がある場合は、物理 Paimon テーブルで設定してください。

  専用の退避用ディスクを使用するには、すべての BE に存在するか作成可能なローカルパスを設定します。

  ```sql
  "paimon.jni.io_manager.tmp_dir" = "/mnt/ssd1/paimon_io:/mnt/ssd2/paimon_io"
  ```

  Doris は JNI スキャナーごとに IOManager を作成し、スキャナーとともにクローズします。設定したディレクトリが
  書き込み可能であり、同時に実行されるクエリに対して十分な容量を持つことを確認してください。カスタム実装クラスを
  設定する場合は、`String[]` を受け取る public コンストラクター、`String` を受け取る public コンストラクター、または
  引数なしの public コンストラクターが必要です。クラスの読み込みまたはインスタンス化に失敗すると、クエリは失敗します。

  これらのプロパティは、JNI パスを使用する Paimon データテーブルの読み取りにのみ影響します。ネイティブ読み取りには影響しません。
  `paimon.table-option.file-reader-async-threshold` オプションは独立しており、Paimon ファイルの非同期読み取りの
  しきい値を制御します。IOManager を有効にしたり、退避用ディレクトリを設定したりするものではありません。

* `{CommonProperties}`

  CommonProperties セクションには共通プロパティを設定します。[Catalog の概要](../catalog-overview.md)の[共通プロパティ]セクションを参照してください。

## メタデータキャッシュ {#meta-cache}

外部データソースへのアクセス性能を向上させるため、Apache Doris は Paimon メタデータをキャッシュします。メタデータには、テーブル構造（Schema）、テーブルオブジェクト、スナップショット、パーティション投影が含まれます。

:::tip
Doris 4.1.x より前のバージョンでは、メタデータキャッシュは主に FE の設定項目で全体的に制御します。詳細は[メタデータキャッシュ](../meta-cache.md)を参照してください。
Doris 4.1.x 以降では、Paimon Catalog の外部メタデータキャッシュを統一された `meta.cache.*` キーで設定します。
:::

### キャッシュプロパティの設定（4.1.x 以降） {#meta-cache-unified-model}

各エンジンのキャッシュエントリには、統一された設定キーフォーマット `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}` を使用します。メモリ制限は、推定器を使用する `table` および `snapshot` エントリに適用されます。[外部メタデータキャッシュのメモリ管理](../external-meta-cache-memory-management)を参照してください。

| プロパティ | 例 | 意味 |
|---|---|---|
| `enable` | `true/false` | このキャッシュモジュールを有効にするかどうか。 |
| `ttl-second` | `600`, `0`, `-1` | `0` はキャッシュの無効化を意味します（即座に反映され、最新データの確認に使用できます）。`-1` は期限切れにならないことを意味します。その他の正の整数は、アクセス時刻を基準とする秒単位の TTL です。 |
| `capacity` | `10000` | 件数によるキャッシュエントリの最大数。`max-weight` が有効な場合は同時適用される件数制限にはなりませんが、`0` にするとキャッシュは無効になります。 |
| `max-weight` | `1GB` | Doris 4.1.4 以降でサポート。保持メモリの推定量に対する任意の上限です。Paimon の `table` と `snapshot` がサポートし、`0` にするとそのエントリは無効になります。 |

**有効化の条件：** `enable=true`、`ttl-second != 0`、`capacity > 0` であり、かつ `max-weight` が未指定または `0` 以外の場合に、モジュールのキャッシュが有効になります。

### キャッシュモジュール {#meta-cache-unified-modules}

Paimon Catalog には、以下のキャッシュモジュールがあります。

| モジュール（`<entry>`） | プロパティキーのプレフィックス | キャッシュする内容と影響 |
|---|---|---|
| `schema` | `meta.cache.paimon.schema.` | テーブル構造をキャッシュします。影響：テーブルのカラム情報が反映されるタイミング。無効にすると、クエリごとに最新の Schema を取得します。 |
| `table` | `meta.cache.paimon.table.` | Paimon テーブルのメタデータオブジェクトをキャッシュします。影響：クエリ計画時のメタデータ読み込み負荷を軽減します。 |
| `snapshot` | `meta.cache.paimon.snapshot.` | スナップショットのメタデータ、スキーマ世代、パーティション投影をキャッシュします。このエントリは `max-weight` をサポートします。 |

### 旧パラメータの対応関係と変換 {#meta-cache-mapping}

バージョン 4.1.x 以降では統一キーの使用を推奨します。従来の Catalog プロパティと 4.1.x 以降の統一キーの対応は次のとおりです。

| 従来のプロパティキー | 4.1.x 以降の統一キー | 説明 |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.paimon.schema.ttl-second` | テーブル構造キャッシュの有効期限 |

### ベストプラクティス {#meta-cache-best-practices}

* **最新データへのリアルタイムアクセス**：各クエリで Paimon テーブルの最新のデータ変更やスキーマ変更を確認するには、`schema` または `table` の `ttl-second` を `0` に設定できます。
  ```sql
  -- Disable table object cache to detect the latest snapshots of Paimon tables
  ALTER CATALOG paimon_ctl SET PROPERTIES ("meta.cache.paimon.table.ttl-second" = "0");
  ```
* **性能の最適化**：Doris 4.1.4 以降では、Catalog プロパティの変更が成功すると、Catalog の実行コンテキストがリセットされ、その Catalog が使用する各メタデータキャッシュエンジンの初期化済みエントリが消去されます。次回のアクセス時に、新しいコンテキストと設定を使用して再構築されます。実行中のクエリには影響しません。Doris のメモリ管理が有効な場合、Paimon SDK の `CachingCatalog` はデフォルトで無効になります。`paimon.cache-enabled` を明示的に設定した場合は、その設定が優先されます。

### 可観測性 {#meta-cache-unified-observability}

キャッシュのメトリクスは、システムテーブル `information_schema.catalog_meta_cache_statistics` で確認できます。

```sql
SELECT catalog_name, engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, load_failure_count, last_error
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'paimon_ctl' AND engine_name = 'paimon'
ORDER BY entry_name;
```

このシステムテーブルのドキュメント：[catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md)。

### サポートされる Paimon バージョン {#supported-paimon-versions}

### サポートされる Paimon フォーマット {#supported-paimon-formats}

## カラム型のマッピング {#column-type-mapping}

Doris 4.2 の完全な型のマッピング表、精度の規則、サポートされない型については、[Paimon から Doris へのデータ型マッピング](paimon-catalog/doris-type-mapping.md)を参照してください。

Doris は、Paimon JNI スキャナーの両方のパスで、引用符で囲まれたトップレベルのカラム名とネストした `STRUCT` フィールド名の
表記を正確に保持します。コンマ（`region,code`）、ハッシュ記号（`nested#value`）、コロン（`colon:name`）、
空白、Unicode 文字を含む名前も、通常の SQL 識別子の引用を超えるエスケープは不要です。読み取り時のカラム照合では
大文字と小文字を区別しないため、大文字や大文字・小文字が混在するカラム名（例：`UserId`）も通常どおりクエリできます。

:::info バージョンに関する注記

4.0.8 より前のバージョンでは、読み取り時に完全一致でカラムを特定していたため、大文字・小文字が混在するカラム名を持つ Paimon および Iceberg テーブルで、誤ったカラムを読み取ったり、クエリが失敗したりする場合がありました。この問題は 4.0.8 で修正されました。

:::

4.1.5 以降では、明示的な `REFRESH TABLE`、`REFRESH DATABASE`、`REFRESH CATALOG` コマンドによって、対応する Paimon SDK キャッシュも無効になります。外部でスキーマを変更した後や、テーブルを削除して再作成した後は、リフレッシュコマンドを使用してメタデータを再読み込みしてください。すでに開始したクエリでは、選択済みのスナップショットが維持されます。

## 書き込み操作 {#write-operations}

Doris は Paimon テーブルの作成と変更、およびテーブルへのデータ書き込みを行えます。書き込みが成功するたびに、Paimon の
スナップショットとしてコミットされます。ステートメントが失敗した場合、Doris は部分的なスナップショットを公開しません。

### 始める前に {#before-you-begin}

データを書き込む前に、以下を確認してください。

* すべての FE および BE ノードで、Paimon 書き込みをサポートする Doris ビルドが稼働している必要があります。古い BE ノードがまだ稼働している
  ローリングアップグレード中は、Paimon に書き込まないでください。
* Catalog の認証情報には、メタストアを更新し、ウェアハウス内のファイルを作成、書き込み、名前変更、削除する権限が必要です。
  必要な権限は、メタストアとストレージシステムによって異なります。
* 書き込みの対象は通常の Paimon データテーブルに限られます。Paimon システムテーブル、およびブランチ、
  タグ、スナップショット、タイムスタンプを選択するテーブル参照は読み取り専用です。

### サポートされる SQL {#supported-sql}

| 操作 | サポート内容と注記 |
| --- | --- |
| データベース DDL | `CREATE DATABASE` と `DROP DATABASE` |
| テーブル DDL | `CREATE TABLE`、`CREATE TABLE AS SELECT`、`DROP TABLE` |
| スキーマ変更 | カラムの追加、削除、名前変更、並べ替え、変更 |
| データの追加 | `INSERT INTO ... VALUES` と `INSERT INTO ... SELECT` |
| データの上書き | テーブル全体、静的パーティション、動的パーティションに対する `INSERT OVERWRITE` |
| 行単位の変更 | 以下の制約の下で、主キーテーブルに対する `DELETE`、`UPDATE`、`MERGE INTO` |

### クイックスタート {#quick-start}

次の例では、主キーテーブルを作成してデータを書き込みます。Paimon テーブルのオプションは
`PROPERTIES` で指定します。Doris の `DISTRIBUTE BY` 句は追加しないでください。

```sql
SWITCH paimon_ctl;
CREATE DATABASE IF NOT EXISTS sales;
USE sales;

CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    customer STRING NULL,
    amount DECIMAL(12, 2) NULL,
    status STRING NULL
) ENGINE=paimon
PROPERTIES (
    'primary-key' = 'order_id',
    'bucket' = '2',
    'bucket-key' = 'order_id'
);

INSERT INTO orders VALUES
    (1, 'Alice', 99.90, 'NEW'),
    (2, 'Bob', 35.00, 'NEW');

UPDATE orders
SET status = 'PAID'
WHERE order_id = 1;

DELETE FROM orders
WHERE order_id = 2;

SELECT * FROM orders ORDER BY order_id;
```

結果：

```text
+----------+----------+--------+--------+
| order_id | customer | amount | status |
+----------+----------+--------+--------+
|        1 | Alice    |  99.90 | PAID   |
+----------+----------+--------+--------+
```

Doris からテーブルのスキーマを変更し、新しいスキーマで書き込みを続けることもできます。

```sql
ALTER TABLE orders ADD COLUMN note STRING NULL;
ALTER TABLE orders RENAME COLUMN note order_note;
```

### データの挿入と上書き {#insert-and-overwrite-data}

`INSERT INTO` は、追加専用テーブルには行を追加し、主キーテーブルにはその Paimon オプションに従って行をマージします。
入力元には、`VALUES`、Doris の内部テーブル、別の外部テーブルを使用できます。

```sql
INSERT INTO paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.new_orders;
```

パーティションのないテーブルでは、`INSERT OVERWRITE` によって既存の行がすべて置き換えられます。したがって、入力が空なら
テーブルも空になります。

```sql
INSERT OVERWRITE TABLE paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.orders_snapshot;
```

パーティションテーブルでは、次のいずれかの形式を使用します。

```sql
-- Replace only the specified partition. The SELECT list omits the static partition column.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
PARTITION (order_date = '2026-10-08')
SELECT order_id, customer, amount, status
FROM internal.sales.daily_orders_stage;

-- Dynamic overwrite replaces the partitions present in the input and keeps other partitions.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
SELECT order_id, customer, amount, status, order_date
FROM internal.sales.daily_orders_stage;
```

主キーテーブルでキー以外のカラムを省略した挿入が許可されるのは、`merge-engine` が `partial-update` の場合だけです。
追加専用テーブルでは、省略したカラムにはデフォルト値、または許可されている場合は `NULL` が使用されます。

### データの削除、更新、マージ {#delete-update-and-merge-data}

行単位の変更には Paimon の主キーテーブルが必要です。デフォルトの `deduplicate` マージエンジンを使用するテーブルでは、Doris は
次の操作をサポートします。

```sql
DELETE FROM paimon_ctl.sales.orders
WHERE order_id = 10;

UPDATE paimon_ctl.sales.orders
SET amount = amount * 0.9,
    status = 'DISCOUNTED'
WHERE order_id = 20;

MERGE INTO paimon_ctl.sales.orders t
USING internal.sales.order_changes s
ON t.order_id = s.order_id
WHEN MATCHED AND s.action = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
    customer = s.customer,
    amount = s.amount,
    status = s.status
WHEN NOT MATCHED THEN INSERT (order_id, customer, amount, status)
    VALUES (s.order_id, s.customer, s.amount, s.status);
```

Paimon が行の変更を適用する仕組みにより、次の制約があります。

* `UPDATE` では、主キーカラムや `sequence.field` で設定したカラムを変更できません。
* `MERGE` 内の更新アクションを含む `UPDATE` は、`deduplicate` マージエンジンのみをサポートし、
  `changelog-producer=input` はサポートしません。
* パーティションカラムの更新には、`ignore-delete=false` を設定した動的バケットテーブル（`bucket=-1`）が必要です。
* `MERGE` 内の削除アクションを含む `DELETE` には、`ignore-delete=false` が必要です。デフォルトの `deduplicate` マージ
  エンジンでは直接サポートされます。`partial-update` テーブルでは `partial-update.remove-record-on-delete=true`、
  `aggregation` テーブルでは `aggregation.remove-record-on-delete=true` を設定する必要があります。
* `rowkind.field` を設定したテーブルでは、これらの行単位のステートメントを使用できません。
  `cross-partition-upsert.index-ttl` を設定した動的バケットテーブルでも使用できません。
* `MERGE` ステートメント内の各アクションには、対応する `UPDATE` と `DELETE` の制約が適用されます。

予測可能な結果を得るため、`MERGE` の入力側では照合キーが一意になるようにしてください。複数の入力行が
同じ対象行に一致する場合、Doris はそのステートメントを拒否します。

### 運用上の注意 {#operational-notes}

* 主キー、パーティション、バケット、マージエンジン、ファイルフォーマット、コンパクションなどの物理的な動作は、
  Paimon テーブルのプロパティとして設定してください。Doris は Paimon SDK を介してこれらのオプションを検証します。
* 現在、Doris は Paimon テーブルに対する汎用的な `ALTER TABLE ... SET TBLPROPERTIES` 操作を提供していません。
  作成後にテーブルプロパティを変更する場合は、別の Paimon エンジンを使用し、その後 Doris で `REFRESH TABLE` または `REFRESH CATALOG` を
  実行してください。
* 書き込み時のディスクへの退避に備えて各 BE に十分なローカルディスク容量を確保し、一時ファイルとコミット操作に必要な
  ウェアハウスの権限を付与してください。BE の設定 `paimon_jni_writer_memory_pool_limit_bytes` は、各
  Paimon JNI ライターが使用するメモリプールを制限します。デフォルト値は 512 MB です。
* 書き込みまたはスキーマ変更が成功した後、新しい Doris ステートメントはコミット済みの Paimon スナップショットを読み込みます。
  既存のステートメントは、開始時に選択したスナップショットを引き続き使用します。

## クエリ操作 {#query-operations}

### 基本的なクエリ {#basic-query}

Catalog を設定したら、次のように Catalog 内のテーブルデータをクエリできます。

```sql
-- 1. Switch to catalog, use database, and query
SWITCH paimon_ctl;
USE paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 2. Use Paimon database directly
USE paimon_ctl.paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 3. Use fully qualified name to query
SELECT * FROM paimon_ctl.paimon_db.paimon_tbl LIMIT 10;
```

### バッチ増分クエリ {#batch-incremental-query}

> バージョン 3.1.0 以降

Flink と同様に、Paimon の[バッチ増分](https://paimon.apache.org/docs/master/flink/sql-query/#batch-incremental)クエリをサポートします。

指定したスナップショットまたはタイムスタンプの区間内にある増分データをクエリできます。区間は左閉右開です。

```sql
-- between snapshots [0, 5)
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5');

-- between snapshots [0, 5) with specified scan mode
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5', 'incrementalBetweenScanMode'='diff');

-- read from start timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000');

-- read between timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000', 'endTimestamp'='1750944949000');
```

パラメータ：

| パラメータ | 説明 | 例 |
| --- | --- | --- |
| `startSnapshotId` | 開始スナップショット ID。0 より大きい必要があります。`endSnapshotId` とともに指定する必要があります。 | `'startSnapshotId'='3'` |
| `endSnapshotId` | 終了スナップショット ID。`startSnapshotId` より大きい必要があります。`startSnapshotId` とともに指定する必要があります。 | `'endSnapshotId'='10'` |
| `incrementalBetweenScanMode` | 増分読み取りモードを指定します。デフォルトは `auto` で、`delta`、`changelog`、`diff` をサポートします。 | `'incrementalBetweenScanMode'='delta'` |
| `startTimestamp` | 開始スナップショットのタイムスタンプ。0 以上である必要があります。単位はミリ秒です。 | `'startTimestamp'='1750844949000'` |
| `endTimestamp` | 終了スナップショットのタイムスタンプ。`startTimestamp` より大きい必要があります。省略可能で、省略すると `startTimestamp` から最新のスナップショットまでを読み取ります。単位はミリ秒です。 | `'endTimestamp'='1750944949000'` |

:::tip 注意
`startSnapshotId` と `endSnapshotId` は、Paimon パラメータ `'incremental-between'='3,10'` を構成します。

`startTimestamp` と `endTimestamp` は、Paimon パラメータ `'incremental-between-timestamp'='1750844949000,1750944949000'` を構成します。

`incrementalBetweenScanMode` は、Paimon パラメータ `incremental-between-scan-mode` に対応します。
:::

これらのパラメータの詳細は、[Paimon のドキュメント](https://paimon.apache.org/docs/master/maintenance/configurations/)を参照してください。

### タイムトラベル {#time-travel}

> バージョン 3.1.0 以降

Paimon テーブルの指定したスナップショットの読み取りをサポートします。

デフォルトでは、読み取り要求は最新バージョンのスナップショットのみを読み取ります。

`$snapshots` テーブル関数を使用すると、指定した Paimon テーブルのスナップショットをクエリできます。

```sql
Doris > SELECT snapshot_id,commit_time FROM paimon_tbl$snapshots;
+-------------+-------------------------+
| snapshot_id | commit_time             |
+-------------+-------------------------+
|           1 | 2025-08-17 06:05:52.740 |
|           2 | 2025-08-17 06:05:52.979 |
|           3 | 2025-08-17 06:05:53.240 |
|           4 | 2025-08-17 06:05:53.561 |
+-------------+-------------------------+
```

`FOR TIME AS OF` と `FOR VERSION AS OF` を使用すると、スナップショット ID またはスナップショットの作成時刻に基づいて履歴バージョンのデータを読み取れます。例：

```sql
-- Notice: Before 3.1.1, only support format like YYYY-MM-DD HH:MM:SS.SSS
-- After 3.1.2, support YYYY-MM-DD HH:MM:SS and YYYY-MM-DD
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52.740";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17";

-- Notice: The timestamp must be precise down to the millisecond.
SELECT * FROM paimon_tbl FOR TIME AS OF 1755381952740;
-- Use snapshot id
SELECT * FROM paimon_tbl FOR VERSION AS OF 1;
```

#### `@options` を使用したタイムトラベル {#time-travel-with-options}

Paimon 固有のセレクターは、クエリのテーブル参照で `@options` を使用して指定します。Doris は `scan.snapshot-id`、
`scan.tag-name`、`scan.version`、`scan.timestamp`、`scan.timestamp-millis`、`scan.watermark`、
`scan.file-creation-time-millis`、`scan.creation-time-millis`、`scan.mode` を受け付けます。選択したスナップショットまたはタグによって
対応する履歴スキーマも選択されます。Doris は履歴データに最新のスキーマをバインドしません。

```sql
-- Read snapshot 1 with the schema stored for snapshot 1.
SELECT id, old_name
FROM paimon_tbl@options('scan.snapshot-id' = '1');

-- A retained tag remains readable even after its ordinary snapshot expires.
SELECT id, old_name
FROM paimon_tbl@options('scan.tag-name' = 'tag1');
```

1 つのテーブル参照には開始位置のオプションを 1 つだけ指定できます。`scan.mode` を位置指定と組み合わせられるのは、
その組み合わせを Paimon が互換と定義している場合だけです。たとえば、`scan.mode='from-creation-timestamp'` には
`scan.creation-time-millis` が必要です。不明または期限切れのスナップショット、ブランチ、タグを指定すると、
暗黙に最新テーブルへ切り替えることなく、明示的に失敗します。`@options` 構文はクエリのテーブル参照でサポートされ、ビューの
定義にも保存できますが、CTE 参照や `SHOW` などのクエリ以外のコマンドには適用できません。

### ブランチとタグ {#branch-and-tag}

> バージョン 3.1.0 以降

指定した Paimon テーブルのブランチとタグの読み取りをサポートします。

`$branches` および `$tags` システムテーブルを使用すると、Paimon テーブルのブランチとタグを確認できます。

```
Doris > SELECT * FROM paimon_tbl$branches;
+-------------+-------------------------+
| branch_name | create_time             |
+-------------+-------------------------+
| b_1         | 2025-08-17 06:34:37.294 |
| b_2         | 2025-08-17 06:34:37.297 |
+-------------+-------------------------+

Doris > SELECT * FROM paimon_tbl$tags;
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| tag_name | snapshot_id | schema_id | commit_time             | record_count | create_time | time_retained |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| t_1      |           1 |         0 | 2025-08-17 06:05:52.740 |            3 | NULL        | NULL          |
| t_2      |           2 |         0 | 2025-08-17 06:05:52.979 |            6 | NULL        | NULL          |
| t_3      |           3 |         0 | 2025-08-17 06:05:53.240 |            9 | NULL        | NULL          |
| t_4      |           4 |         0 | 2025-08-17 06:05:53.561 |           12 | NULL        | NULL          |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
```

Spark や Trino などのシステムとの互換性のため、さまざまな構文形式をサポートします。

```sql
-- BRANCH
SELECT * FROM paimon_tbl@branch(branch1);
SELECT * FROM paimon_tbl@branch("name" = "branch1");

-- TAG
SELECT * FROM paimon_tbl@tag(tag1);
SELECT * FROM paimon_tbl@tag("name" = "tag1");
SELECT * FROM paimon_tbl FOR VERSION AS OF 'tag1';
```

`FOR VERSION AS OF` 構文では、Doris がパラメータがタイムスタンプかどうかを自動的に判定します。

## システムテーブル {#system-tables}

> バージョン 3.1.0 以降

Doris は、テーブル関連のメタデータを取得するための Paimon システムテーブルのクエリをサポートします。システムテーブルを使用すると、スナップショット履歴、マニフェストファイル、データファイル、パーティションなどの情報を確認できます。

Paimon テーブルのメタデータにアクセスするには、テーブル名の後に `$` とシステムテーブル名を追加します。

```sql
SELECT * FROM my_table$system_table_name;
```

`audit_log`、`binlog`、`manifests`、`partitions`、`ro`、`row_tracking`、`table_indexes` のシステムテーブルでは、
テーブル参照の `@options` を受け付けます。選択したスナップショットまたはタグは、システムテーブルの行に適用されます。また、
元テーブルのカラムを公開するシステムテーブルでは、対応する履歴版の元テーブルスキーマにも適用されます。

```sql
SELECT rowkind, id, old_name
FROM paimon_tbl$audit_log@options('scan.tag-name' = 'tag1');
```

その他のシステムテーブルでは、行を生成するすべての段階で選択したスナップショットが使われることを保証できないため、
`@options` を拒否します。Paimon システムテーブルは `scan.file-creation-time-millis` も拒否します。このファイル
フィルターを暗黙に無視すると、要求した範囲外の行が返される可能性があるためです。

:::info 注
Doris は、Flink でのみサポートされる Paimon のグローバルシステムテーブルの読み取りをサポートしません。
:::

## 付録 {#appendix}

### よくある質問 {#faq}

**1. `Could not find a file io implementation for scheme 's3a' in the classpath`**

3.1 より前のバージョンで、HMS をメタデータストレージとして使用し、ストレージ側で 's3a' または 's3' プロトコルを使用すると、次のエラーが発生します。

```text
java.io.UncheckedIOException: org.apache.paimon.fs.UnsupportedSchemeException: Could not find a file io implementation for scheme 's3a' in the classpath. Hadoop FileSystem also cannot access this path 's3a://`.
```

**3.1 より前のバージョン**

3.1 より前のバージョンは `s3a` プロトコルをサポートしていません。使用する必要がある場合は、一時的な回避策として `s3a` 関連のパラメータを追加できます。

**バージョン 3.1 以降**

バージョン 3.1 以降では、`s3a` パラメータを明示的に追加する必要はありません。Paimon のストレージパラメータを上書きする場合は、`paimon.fs.` プレフィックスを付けたパラメータを追加できます。Paimon は内部で HDFS API を使用するため、すべての `fs.s3a.*` パラメータがサポートされます。

例：

```sql
CREATE CATALOG `paimon_hms_on_s3a` PROPERTIES (
    "type" = "paimon",
    "paimon.catalog.type" = "hms",
    "hive.metastore.uris" = "thrift://172.20.48.119:9383",
    "warehouse" = "s3a://bucket/paimon_warehouse",
    "s3.access_key" = "<ak>",
    "s3.secret_key" = "<sk>",
    "s3.region" = "ap-east-1",
    "s3.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    -- Explicitly add s3a parameters
    "fs.s3a.access.key" = "<ak>",
    "fs.s3a.secret.key" = "<sk>",
    "fs.s3a.endpoint.region" = "ap-east-1",
    "fs.s3a.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    "fs.s3a.impl" = "org.apache.hadoop.fs.s3a.S3AFileSystem"
);
```

`s3` プロトコルを使用する場合は、Paimon の S3 関連パラメータを明示的に追加する必要があります。つまり、`paimon.` プレフィックスを追加します。例：

```sql
CREATE CATALOG test_paimon_on_hms_aws_catalog PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = 'hms',
    'warehouse' = 's3://bucket-hk/paimon_warehouse',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9383',
    's3.region' = 'ap-east-1',
    's3.endpoint' = 'https://s3.ap-east-1.amazonaws.com',
    's3.access_key' = '<ak>',
    's3.secret_key' = '<sk>',
    -- Explicitly add Paimon S3 parameters
    'paimon.s3.region' = 'ap-east-1',
    'paimon.s3.endpoint' = 'ap-east-1',
    'paimon.s3.access-key' = '<ak>',
    'paimon.s3.secret-key' = '<sk>'
);
```
