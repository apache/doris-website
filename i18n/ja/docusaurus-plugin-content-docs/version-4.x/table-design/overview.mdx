Apache Doris では、テーブル設計が書き込み性能、クエリ効率、ストレージコストを直接左右します。この章では、典型的な設計シナリオに沿って、テーブルを一から設計する方法や既存テーブルの構造を最適化する方法を説明します。

## 設計の流れ

Doris のテーブル設計は、通常、次の手順で進めます。

1. **テーブルモデルを選ぶ**: データの保存、重複排除、集約の方法を決めます。
2. **カラムとデータ型を定義する**: ビジネス上の各フィールドに適した型を選びます。
3. **パーティション分割とバケット分割を計画する**: データを均等に分散し、不要なデータの読み取りを省けるようにします。
4. **インデックスを追加する**: 特定の値の検索、範囲スキャン、全文検索を高速化します。
5. **ストレージを最適化する**: 圧縮、行・列ハイブリッドストレージ、ホットデータとコールドデータの階層化によってコストを削減します。
6. **スキーマを変更する**: ビジネスの変化に合わせてスキーマを調整したり、自動採番カラムを使用したりします。

## テーブルの作成

Doris でテーブルを作成するには、[CREATE TABLE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE) 文を使用します。既存のテーブルから新しいテーブルを作る場合は、次の方法を使用できます。

- [CREATE TABLE ... LIKE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE): 既存のテーブルの構造を再利用します。
- [CREATE TABLE ... AS SELECT (CTAS)](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE): クエリの結果に基づいてテーブルを作成します。

### テーブル名の規則

Doris のテーブル名は、デフォルトでは大文字と小文字を区別し、長さの上限は 64 バイトです。次の設定でこれらを調整できます。

| 設定 | デフォルト | 説明 |
| --- | --- | --- |
| [lower_case_table_names](../admin-manual/config/fe-config.md) | 大文字と小文字を区別 | クラスターの初期化時にのみ設定でき、その後は変更できません |
| [table_name_length_limit](../admin-manual/config/fe-config.md) | 64 バイト | 大きすぎる値の設定は推奨されません |

### 主なテーブルプロパティ

テーブルを作成するときは、PROPERTIES で一般的なプロパティを指定できます。詳細は [CREATE TABLE](../sql-manual/sql-statements/table-and-view/table/CREATE-TABLE) を参照してください。

| プロパティ | 用途 |
| --- | --- |
| `buckets` | テーブル内でのデータ分散の粒度を決めます |
| `storage_medium` | HDD、SSD、リモートの共有ストレージなど、ストレージ媒体を制御します |
| `replication_num` | 冗長性と信頼性を確保するためのデータレプリカ数を制御します |
| `storage_policy` | ホットデータとコールドデータの階層間の移行ポリシーを設定します |

:::tip
テーブルプロパティはパーティション単位で適用されます。テーブルプロパティを変更しても、その後に作成されるパーティションにのみ反映され、既存のパーティションには影響しません。詳細は [ALTER TABLE PROPERTY](../sql-manual/sql-statements/table-and-view/table/ALTER-TABLE-PROPERTY) と [ALTER TABLE DISTRIBUTION](../sql-manual/sql-statements/table-and-view/table/ALTER-TABLE-DISTRIBUTION) を参照してください。[動的パーティション分割](data-partitioning/dynamic-partitioning.md)では、これらのプロパティを個別に設定できます。
:::

## 設計時の考慮事項

{/* Knowledge type: considerations / design constraints */}

| 設計項目 | 説明 | 影響 |
| --- | --- | --- |
| データモデル | テーブル作成後は**変更できません**。適切な[データモデル](./data-model/intro.mdx)を事前に選んでください | その後の書き込みとクエリのパターンを決めます |
| バケット数 | 作成済みパーティションのバケット数は変更できませんが、[パーティションの置換](../data-operate/delete/table-temp-partition.md)によって調整できます。動的パーティション分割で今後作成されるパーティションのバケット数は変更できます | データの均衡とクエリの並列度に影響します |
| カラムの変更 | VALUE カラムの追加・削除は軽量な操作です（数秒で完了します）。KEY カラムの追加・削除やデータ型の変更は高コストな操作です | 大規模なデータセットでは、可能な限り KEY カラムの変更を避けてください |
| ストレージポリシー | [ホットデータとコールドデータの階層化](./tiered-storage/overview.md)を使い、コールドデータを HDD、S3、HDFS に移行します | ストレージコストを大幅に削減します |
