全文検索のクエリ（`MATCH_ANY`、`MATCH_ALL`、`MATCH_PHRASE` など）を実行するときは、関連性の高いレコードから返せるよう、「一致度」に基づいて結果を並べ替えることがあります。Doris の **関連性スコアリング** では、クエリ条件に基づいて各行に数値のスコアを付けます。スコアが高いほど関連性が強いことを示します。

現在、Doris は関連性スコアリングのデフォルトの実装として **BM25（Best Matching 25）** アルゴリズムを使用します。

**主な用途：**

- 検索エンジンのアプリケーション：キーワードに最も関連する文書の一覧を返す
- ログ分析：関連性の高い順に並べ、キーワードに最も一致するログをすばやく見つける
- コンテンツ推薦：テキストの類似度に基づいて、優先度の高いコンテンツを選ぶ
- ナレッジベース検索：質問との関連性に基づいて候補となる回答を順位付けして返す

## クイックスタート {#quick-start}

次の例は、クエリで関連性スコアリングを有効にし、スコア順に並べ替える方法を示します。

```sql
SELECT *,
       score() AS relevance
FROM search_demo
WHERE content MATCH_ANY 'text search test'
ORDER BY relevance DESC
LIMIT 10;
```

実行すると、Doris は BM25 アルゴリズムで各行のスコアを計算し、関連性の高い上位 10 件のレコードを返します。

```text
+------+-----------------------------------+---------+--------------+-----------+
| id   | content                           | author  | publish_date | relevance |
+------+-----------------------------------+---------+--------------+-----------+
|    1 | Full text search engine test demo | Alice   | 2024-01-01   |  2.915228 |
|    7 | Text processing techniques        | Grace   | 2024-01-07   |  1.341931 |
|    5 | Performance test framework        | Eve     | 2024-01-05   |  1.341931 |
|    3 | Advanced search algorithms        | Charlie | 2024-01-03   |  1.341931 |
+------+-----------------------------------+---------+--------------+-----------+
```

## 有効になる条件 {#activation-conditions}

スコア計算を有効にするには、クエリが次の条件をすべて満たす必要があります。

1. `SELECT` 句で `score()` 関数を明示的に呼び出す。
2. `WHERE` 句に少なくとも1つの `MATCH_*` 条件を含める。
3. Top-N クエリであり、`ORDER BY` で `score()` の結果に基づいて並べ替える。

### 対応するインデックスの種類 {#supported-index-types}

| インデックスの種類 | スコア計算への対応 | 説明 |
| ------------------ | ------------------ | ---- |
| トークン化された転置インデックス | 対応 | BM25 の関連性スコアを計算できる |
| トークン化されていない転置インデックス | 非対応 | 完全一致のみをサポートし、スコアは計算しない |

### 対応するクエリの種類 {#supported-query-types}

- `MATCH_ANY`
- `MATCH_ALL`
- `MATCH_PHRASE`
- `MATCH_PHRASE_PREFIX`
- `SEARCH`

## BM25 アルゴリズム {#bm25-algorithm}

BM25 は確率モデルに基づくテキストの関連性アルゴリズムです。**語の出現頻度（TF）**、**逆文書頻度（IDF）**、**レコードの長さ**の3つの要素を組み合わせ、一致した結果のスコアを重み付きで計算します。従来の TF-IDF モデルと比べて、BM25 は頑健性と調整のしやすさに優れ、長いテキストと短いテキストのスコア差を効果的に調整します。

### 基本式 {#core-formula}

```text
score = IDF × (tf × (k1 + 1)) / (tf + k1 × (1 - b + b × |d| / avgdl))
```

式中の変数の意味は次のとおりです。

| 変数 | 意味 |
| ---- | ---- |
| `tf` | 現在の行に検索語が出現する回数 |
| `IDF` | 語の珍しさを表す逆文書頻度 |
| `\|d\|` | 現在の行の長さ（トークン化後のトークン数） |
| `avgdl` | テーブル内の全行の平均長 |
| `k1`, `b` | アルゴリズムの調整パラメータ |

### パラメータ {#parameters}

| パラメータ | デフォルト値 | 説明 |
| ---------- | ------------ | ---- |
| `k1` | 1.2 | 語の出現頻度がスコアに与える影響の大きさを制御する |
| `b` | 0.75 | レコード長の正規化の強さを制御する |
| `boost` | 1.0 | クエリ単位の重み係数 |

### 補助統計量 {#auxiliary-statistics}

```text
IDF   = log(1 + (N - n + 0.5) / (n + 0.5))
avgdl = total_terms / total_rows
```

ここで、各変数は次を表します。

- `N`：テーブル内の総行数
- `n`：検索語を含む行数

クエリに複数の語が含まれる場合、**最終スコアは各語のスコアの合計**です。

### レコード長と `norms` プロパティ {#record-length-and-the-norms-property}

`norms` インデックスプロパティと BE 設定 `inverted_index_skip_norms_for_variant` は、Doris 4.1.5 以降でサポートされています。

`|d|` は norms から取得します。norms は、対象フィールドに値がない行も含め、インデックス対象のフィールドごとに各行で1バイトを使用します。トークン化されたインデックスはデフォルトで norms を書き込みます（`"norms" = "true"`）。トークン化されていないインデックスは書き込みません。フィルタリングにのみ使用するインデックスでは、`"norms" = "false"` に設定すると容量を節約できます。

```sql
INDEX idx_content(content) USING INVERTED PROPERTIES("parser" = "english", "norms" = "false")
```

VARIANT のサブパスはインデックスの `norms` プロパティを継承し、`行数 × パス数` バイトを使用します。BE 設定 `inverted_index_skip_norms_for_variant`（デフォルトは `false`、実行中に変更可能）を `true` にすると、インデックスプロパティよりも優先され、すべての VARIANT パスインデックスで norms が無効になります。

norms を無効にしても `MATCH_*` によるフィルタリングには影響しません。ただし、`score()` が norms のないセグメントを読み取るとエラーになります。これらの設定が影響するのは新しく書き込まれるセグメントです。既存のセグメントは compaction によって書き直されるまで変わりません。設定を変更する前に、すべての BE をこれらの設定に対応したバージョンへアップグレードしてください。

## 結果の解釈 {#interpreting-the-results}

スコアの意味を理解すると、関連性による順位付けをより正確に利用できます。

| 特性 | 説明 |
| ---- | ---- |
| スコアの範囲 | 固定の上限がない正の数。通常は絶対値より相対的な大小が重要 |
| 複数語のクエリ | 複数の語が含まれる場合、合計スコアは各語のスコアの合計になる |
| 長さの影響 | 一致する語が同じ場合、短いレコードのスコアがわずかに高くなる |
| 一致する語がない場合 | 検索語がテーブル内に現れなければ、対応するスコアは 0 になる |

## よくある質問 {#faq}

**Q1：クエリでスコアが返されないのはなぜですか？**

次の項目を順に確認してください。

1. `score()` 関数を `SELECT` で呼び出しているか。
2. `WHERE` 句に `MATCH_*` 条件が含まれているか。
3. `ORDER BY` が `score()` に基づいているか。
4. インデックスがトークン化された転置インデックスか。

**Q2：BM25 と TF-IDF の違いは何ですか？**

BM25 は TF-IDF を基礎として、**語の出現頻度の飽和**と**長さの正規化**という2つの改良を加えています。これにより、長いテキストと短いテキストのスコアのバランスが改善し、頑健性も高まります。

**Q3：異なるクエリ間でスコアを比較できますか？**

推奨しません。BM25 のスコアは、具体的な検索語とテーブル内のデータ分布に依存します。異なるクエリ間で絶対値を比較することはできません。**相対的な大小は、同じクエリの結果セット内でのみ比較してください。**
