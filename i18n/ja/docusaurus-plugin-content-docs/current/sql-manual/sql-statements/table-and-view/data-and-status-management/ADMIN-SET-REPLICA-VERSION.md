## 説明

このステートメントは、指定したレプリカのバージョン、最終成功バージョン、最終失敗バージョンを手動で設定するために使用します。主に、システムで問題が発生した際に、異常な状態になったレプリカを復旧するために使用します。

## 構文

```sql
ADMIN SET REPLICA VERSION PROPERTIES ("<key>"="<value>" [,...])
```

## 必須パラメータ

**1. `"<key>"="<value>"`**

| キー         | 値の型 | 説明                                                 |
|--------------|--------|------------------------------------------------------|
| `tablet_id`  | Int    | バージョンを変更するレプリカが属するタブレットの ID。 |
| `backend_id` | Int    | レプリカが配置されている BE ノードの ID。             |


## オプションパラメータ

**1. `"<key>"="<value>"`**

| キー                   | 値の型 | 説明                                             |
|------------------------|--------|--------------------------------------------------|
| `version`              | Int    | レプリカのバージョンを設定します。               |
| `last_success_version` | Int    | レプリカの最終成功バージョンを設定します。       |
| `last_failed_version`  | Int    | レプリカの最終失敗バージョンを設定します。       |


**注意事項**

- 指定したレプリカが存在しない場合、この操作は無視されます。

- これらの値を変更すると、その後のデータの読み書きに失敗し、データの不整合が発生する可能性があります。慎重に操作してください。

- 変更前に元の値を記録してください。変更後はテーブルの読み書きができることを確認し、失敗した場合は元の値に戻してください。ただし、元の値に戻す操作も失敗する可能性があります。

- 現在データを書き込んでいるタブレットに対して、この操作を実行しないでください。


## アクセス制御要件

この SQL コマンドを実行するユーザーには、少なくとも次の権限が必要です。

| 権限       | オブジェクト | 説明                                                                                              |
|:-----------|:-------------|:--------------------------------------------------------------------------------------------------|
| Admin_priv | データベース | テーブルやパーティションの管理、システムレベルのコマンドを含む、データベースの管理操作に必要です。 |

## 例

- BE 10001 上にあるタブレット 10003 のレプリカの失敗状態フラグをクリアする

  ```sql
  ADMIN SET REPLICA VERSION PROPERTIES("tablet_id" = "10003", "backend_id" = "10001", "last_failed_version" = "-1");
  ```

- BE 10001 上にあるタブレット 10003 のレプリカのバージョンを 1004 に設定する

  ```sql
  ADMIN SET REPLICA VERSION PROPERTIES("tablet_id" = "10003", "backend_id" = "10001", "version" = "1004");
  ```
