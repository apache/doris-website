## すぐに選ぶ

業務の状況に合わせて、次の表からデプロイ構成を選んでください。

| 状況 | 推奨構成 |
|------|----------|
| クラウド上で弾力的に拡張したい | ストレージ・コンピュート分離型 + クラウドプラットフォームへのデプロイ |
| 規模が固定されたオンプレミス環境 | ストレージ・コンピュート一体型 + 手動デプロイ |
| 大規模クラスターを自動管理したい | ストレージ・コンピュート分離型 + Kubernetes デプロイ |

---

## ストレージ・コンピュート一体型と分離型の比較

| 項目 | ストレージ・コンピュート一体型 | ストレージ・コンピュート分離型 |
|--------|----------|----------|
| アーキテクチャ | データ保存と計算が密接に結び付いており、BE ノードが両方を担当する | コンピュート層（BE）とストレージ層（Shared Storage）を分離する |
| 適した用途 | 業務規模が固定されている場合、高いクエリ性能が必要な場合、共有ストレージのない環境 | 弾力的なスケーリング、クラウドデプロイ、大規模データ分析 |
| 利点 | 構成が単純で遅延が小さく、外部の共有ストレージが不要 | コンピュート資源を独立して拡張でき、ストレージ費用を抑えやすく、資源を柔軟に分離できる |
| 注意点 | コンピュート資源だけを独立して拡張できない | コンポーネントが増え、安定した共有ストレージサービスが必要 |

## デプロイ方法

### 手動デプロイ

スクリプトと設定ファイルを使って手動でデプロイします。小規模から中規模のクラスターや初期検証に適しています。

- 適した用途：短時間での検証、最小構成のデプロイ、クラスター構成の理解
- 適さない用途：大規模クラスター、変更が頻繁な環境

詳しい手順は、[ストレージ・コンピュート一体型クラスターの手動デプロイ](./deploy-manually/integrated-storage-compute-deploy-manually)または[ストレージ・コンピュート分離型クラスターの手動デプロイ](./deploy-manually/separating-storage-compute-deploy-manually)を参照してください。

### Kubernetes デプロイ

Doris Operator を使って Kubernetes 上のクラスターを管理します。大規模な本番環境や運用の自動化に適しています。

- 適した用途：大規模クラスター、宣言的な管理が必要な環境、ハイブリッドクラウド
- 必要なもの：Kubernetes クラスター、Doris Operator

詳しい手順は [Kubernetes デプロイ](./deploy-on-kubernetes/intro)を参照してください。

### クラウドプラットフォームへのデプロイ

Alibaba Cloud や AWS などのクラウドプラットフォームに、クラウドのインフラを利用してデプロイします。

- 適した用途：クラウド上のワークロード、迅速な環境構築、環境の分離
- 対応例：Alibaba Cloud ECI、AWS EKS など

詳しい手順は [クラウドプラットフォームへのデプロイ](./deploy-on-cloud/doris-on-aws)を参照してください。

## 選択の目安

1. **初めて Doris を試す場合**：構成が単純で始めやすい、一体型 + 手動デプロイから始めます。
2. **小規模から中規模の本番環境**：一体型 + 手動デプロイ、または Kubernetes デプロイを選びます。
3. **弾力的な拡張が必要なクラウド環境**：分離型 + クラウドプラットフォーム、または Kubernetes デプロイを選びます。
4. **大規模な本番クラスター**：分離型 + Kubernetes デプロイで運用の自動化を簡単にします。

## よくある質問

### Q: ストレージ・コンピュート分離型はクエリ性能に大きく影響しますか？

分離型ではコンピュート層とストレージ層の間に追加のネットワーク通信が発生しますが、多くの環境では影響は限定的です。理由は次のとおりです。
- Shared Storage は通常、高速ネットワーク環境（25Gbps RDMA など）に配置されます。
- データキャッシュによってリモート読み取りの頻度を下げられます。
- 極めて低い遅延が必要な場合は、一体型の方が適していることがあります。

### Q: 既存の一体型クラスターを分離型に移行するには？

移行の大まかな手順は次のとおりです。
1. 新しい環境に分離型クラスターをデプロイします。
2. Broker Load または Stream Load でデータを移行します。
3. データの整合性とクエリ性能を検証します。
4. 古いクラスターを停止します。

### Q: Kubernetes デプロイには専任の運用チームが必要ですか？

クラスター規模によって異なります。
- 小規模（10 ノード以内）：Kubernetes 導入による複雑さが利点を上回る場合があります。
- 中規模から大規模（10 ノード以上）：Kubernetes の自動化機能によって運用コストを大きく削減できます。

### Q: クラウドプラットフォームと Kubernetes のどちらを選ぶべきですか？

| 項目 | クラウドプラットフォームへのデプロイ | Kubernetes デプロイ |
|--------|------------|------------------|
| 適した用途 | 迅速なデプロイ、弾力的な資源 | ハイブリッドクラウド、マルチクラウド |
| 管理の複雑さ | 低い | 中程度 |
| 柔軟性 | クラウドプラットフォームの機能に依存 | 高く、カスタマイズ可能 |
| 費用 | クラウドサービスの追加料金が発生する場合がある | 制御しやすい |
