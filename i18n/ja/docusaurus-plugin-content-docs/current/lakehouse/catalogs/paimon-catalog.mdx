Doris は、さまざまなメタデータサービスを通じた Paimon テーブルのメタデータへのアクセスと、Paimon データの読み書きをサポートします。

[Apache Doris と Apache Paimon のクイックスタート](../best-practices/doris-paimon.md)。

## 適用シナリオ {#applicable-scenarios}

| シナリオ | 説明 |
| ------------ | ------------------------------------------------------------ |
| クエリの高速化 | Doris の分散コンピューティングエンジンから Paimon データに直接アクセスし、クエリを高速化します。 |
| データ統合 | Paimon データを読み取って Doris の内部テーブルに書き込むか、Doris のコンピューティングエンジンを使用して ZeroETL 操作を実行します。 |
| データの書き戻し | Doris SQL を使用して Paimon テーブルの作成と変更、データの追加と上書き、主キーテーブルの行単位の変更を行います。 |

## Catalog の設定 {#configuring-catalog}

### 構文 {#syntax}

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = '<paimon_catalog_type>',
    'warehouse' = '<paimon_warehouse>'
    {MetaStoreProperties},
    {StorageProperties},
    {PaimonProperties},
    {CommonProperties}
);
```

* `<paimon_catalog_type>`

  Paimon Catalog の種類です。次の種類をサポートします。

  * `filesystem`: デフォルト。ファイルシステムに保存されたメタデータに直接アクセスします。

  * `hms`: Hive Metastore をメタデータサービスとして使用します。

  * `dlf`: Alibaba Cloud DLF をメタデータサービスとして使用します。

  * `jdbc`: JDBC インターフェースを使用して、メタデータサービスとなるリレーショナルデータベースに接続します（バージョン 4.1.0 以降でサポート）。

* `<paimon_warehouse>`

  Paimon のウェアハウスパスです。`<paimon_catalog_type>` が `filesystem` の場合、このパラメータは必須です。

  `warehouse` パスは、`Database` パスの1つ上の階層を指す必要があります。たとえば、テーブルのパスが `s3://bucket/path/to/db1/table1` の場合、`warehouse` は `s3://bucket/path/to/` にします。

* `{MetaStoreProperties}`

  MetaStoreProperties セクションには、Metastore メタデータサービスへの接続情報と認証情報を指定します。詳しくは[サポートされるメタデータサービス]を参照してください。

* `{StorageProperties}`

  StorageProperties セクションには、ストレージシステムへの接続情報と認証情報を指定します。詳しくは[サポートされるストレージシステム]を参照してください。

* `{PaimonProperties}`

  PaimonProperties セクションには、Paimon 関連のプロパティを指定します。

  Doris は Paimon メタデータへのアクセスに Paimon Java SDK を一部使用するため、カスタムパラメータを Paimon Java SDK に渡す必要がある場合があります。次のプレフィックスを使用できます。

  ```
  paimon.s3.xxx
  paimon.s3a.xxx
  paimon.fs.xxx
  ```

  これらのパラメータは自動的に変換されて渡されます。例を次に示します。

  | 入力パラメータ | Paimon Java SDK 向けに変換されたパラメータ |
  | --- | --- |
  | "paimon.s3.list.version" = "1" | "fs.s3a.list.version" = "1" |
  | "paimon.s3.paging.maximum" = "100" | "fs.s3a.paging.maximum" = "100" |
  | "paimon.fs.s3.read.ahead.buffer.size" = "1" | "fs.s3a.read.ahead.buffer.size" = "1" |
  | "paimon.s3a.replication.factor" = "3" | "fs.s3a.replication.factor" = "3" |

  **Paimon の読み取りオプション**

  Doris は、次の有界 Paimon バッチ読み取りオプションをサポートします。Catalog 全体のクエリのデフォルト値は
  `paimon.table-option.<option-key>` で設定し、個々のテーブル参照では
  `table@options('<option-key>'='<value>')` で上書きできます。これらの設定は Doris による読み取りにのみ影響し、物理的な
  Paimon テーブルのメタデータは更新しません。

  | Paimon オプション | Paimon のデフォルト値 | Doris が受け付ける値 | 効果 |
  | --- | --- | --- | --- |
  | `read.batch-size` | `1024` | `1` から `65536` までの整数 | Paimon JNI リーダーの各バッチで要求する行数。明示的に設定した値は、Doris がリーダーを開く際に保持されます。 |
  | `file-reader-async-threshold` | `10 MB` | `1 MB` から `1 GB` までのメモリサイズ | Paimon JNI リーダーが非同期読み取りに切り替わるファイルサイズのしきい値。 |
  | `file-index.read.enabled` | `true` | 真偽値 | 読み取り時に Paimon のファイルインデックスによる枝刈りを有効にします。 |
  | `source.split.target-size` | `128 MB` | 正のメモリサイズ | Paimon がデータファイルを Doris のスキャンスプリットにまとめる際の目標サイズ。 |
  | `source.split.open-file-cost` | `4 MB` | 負でないメモリサイズ | Paimon がファイルをスプリットにまとめる際に使用する、ファイルを開く推定コスト。 |
  | `scan.manifest.parallelism` | 使用可能なプロセッサ数 | `1` から `256` までの整数 | 要求するマニフェスト読み取りの並列度。実行時に Doris は、各計画ブランチの値を、この値、`256`、およびその FE または BE で使用可能なプロセッサ数の最小値に個別に制限します。 |
  | `scan.plan-sort-partition` | `false` | 真偽値 | Paimon のスキャン計画時にパーティションを並べ替えます。 |

  たとえば、次の Catalog 設定は物理的な Paimon テーブルに保存された値を上書きし、Doris のクエリのデフォルト値になります。

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.table-option.read.batch-size" = "4096",
      "paimon.table-option.file-reader-async-threshold" = "32 MB",
      "paimon.table-option.source.split.target-size" = "64 MB",
      "paimon.table-option.scan.manifest.parallelism" = "1"
  );
  ```

  クエリでは、Catalog や Paimon テーブルのメタデータを変更せずに、これらのデフォルト値を上書きできます。

  ```sql
  SELECT *
  FROM paimon_hms.db_name.table_name@options(
      'read.batch-size' = '8192',
      'source.split.target-size' = '32 MB'
  );
  ```

  各テーブル参照には独立したオプションセットがあります。たとえば、同じテーブルの2つのエイリアスに、1つのステートメント内で異なるバッチサイズを指定できます。

  ```sql
  SELECT small.id
  FROM paimon_hms.db_name.table_name@options('read.batch-size' = '1') small
  JOIN paimon_hms.db_name.table_name@options('read.batch-size' = '8192') large
    ON small.id = large.id;
  ```

  優先順位は高い順に次のとおりです。

  ```text
  relation @options > Doris Catalog property > physical Paimon table option > Paimon default
  ```

  Doris は、この優先順位を適用した後の最終値を検証します。そのため、Catalog またはテーブル参照に有効な値を指定すれば、物理テーブルの無効な値を置き換えられます。最終値が無効な場合、Doris は対象となる計画またはリーダーの処理が始まる前にクエリを拒否します。マニフェストの上限は、パーティション、行数と統計情報、フォールバックブランチ、およびシステムテーブルのマニフェスト計画の前にも適用されます。

  表の最初の5つのオプションはメタデータに影響しないため、キャッシュされた最新のパーティション投影を再利用できます。
  `scan.manifest.parallelism` と `scan.plan-sort-partition` はメタデータの計画に影響するため、Doris はテーブル参照ごとの有効なテーブルハンドルを使用して計画します。クエリごとの値によって Paimon の JVM 全体で共有されるエグゼキュータのサイズが変わることはありません。

  Doris は、`CREATE CATALOG` および `ALTER CATALOG` の際に、不明または無効な `paimon.table-option.*` プロパティを拒否します。
  `ALTER CATALOG` は変更を公開する前に候補となる設定全体を検証するため、変更に失敗しても以前の Catalog 設定が引き続き有効です。古いバージョンの Doris で永続化された Catalog は引き続き読み込めますが、サポートされない、または無効な従来のリーダープロパティは適用されずに無視されます。その保存値はイメージおよび編集ログとの互換性のために保持されます。

  スナップショットと開始位置のオプションはテーブル参照のコンテキストを選択するため、[Time Travel](#time-travel-with-options) で説明するように `@options` を使用する必要があり、Catalog のデフォルト値にはできません。Doris は、Paimon の Flink ソース列挙子に属する `scan.max-splits-per-task`、`scan.fallback-branch`、ストリーミング、レイアウト、書き込み、コンパクションの各オプションも対象外とします。Bucket、Primary Key、Partition、Merge Engine、およびその他の物理的な動作は、Doris の `CREATE TABLE ... PROPERTIES` を使用する場合も含め、Paimon テーブルのプロパティとして設定してください。

  :::info ステートメントの一貫性
  Doris は1つのステートメント内で、スキーマのバインド、パーティションのデータロード、行数と統計情報の収集、システムテーブルの計画、データのスキャンを、同じ Paimon スナップショットとテーブル世代に対して行います。`@options` で選択したスナップショットまたはタグには、ネストされた `STRUCT`、`MAP`、`ARRAY` フィールドも含め、その履歴バージョンに属するスキーマが使用されます。準備済みステートメントの各実行では新しいステートメント状態を取得するため、実行間のコミットは、新しい実行のセレクタとキャッシュ設定に従って参照できます。
  :::

  運用上の安全のため、Paimon スキャナーの DEBUG 設定メッセージにはバッチサイズと投影フィールド数のみが出力されます。認証情報を含む可能性があるスキャナーの生のパラメータマップは、Doris から出力しません。`PaimonJniAsyncReaderThreadCount` プロファイルゲージはスキャナー全体で1秒に1回サンプリングされるため、値が最大1秒古い場合があります。このサンプリングはクエリの実行やスケジューリングには影響しません。リーダーと IOManager のクリーンアップは独立しており、クローズが部分的に失敗した後も安全に再試行できます。

  **Paimon JNI IOManager**

  Paimon の主キーテーブルでは、JNI によるマージ読み取りで複数ファイルのデータを並べ替えてマージする必要が生じる場合があります。Paimon IOManager を有効にすると、この処理の中間データを BE のローカルディスクにスピルでき、大量のデータをマージ読み取りする際のメモリ負荷を軽減できます。

  | プロパティ | 必須 | デフォルト値 | 説明 |
  | --- | --- | --- | --- |
  | `paimon.jni.enable_jni_io_manager` | いいえ | `false` | JNI 読み取りで Paimon IOManager を有効にするかどうか。他の IOManager プロパティは、このプロパティが `true` の場合にのみ有効です。 |
  | `paimon.jni.io_manager.tmp_dir` | いいえ | `<storage_root_path>/paimon_jni_scanner_io_tmp` | Paimon IOManager が一時スピルファイルに使用するローカルディレクトリ。複数のディレクトリはカンマまたはコロンで区切れます。このプロパティを省略すると、Doris は各 BE ストレージパスの下にディレクトリを1つ作成します。 |
  | `paimon.jni.io_manager.impl_class` | いいえ | Paimon のデフォルト実装 | カスタム `org.apache.paimon.disk.IOManager` 実装の完全修飾クラス名。このクラスは、すべての BE の Paimon JNI Scanner クラスパスに存在する必要があります。 |

  次の例では IOManager を有効にし、BE のストレージパスから Doris に一時ディレクトリを選択させます。

  ```sql
  CREATE CATALOG paimon_hms PROPERTIES (
      "type" = "paimon",
      "paimon.catalog.type" = "hms",
      "hive.metastore.uris" = "thrift://127.0.0.1:9083",
      "warehouse" = "s3://bucket/paimon-warehouse",
      "paimon.jni.enable_jni_io_manager" = "true"
  );
  ```

  IOManager を有効にしても、すべてのマージ読み取りでスピルが発生するわけではありません。Paimon は、マージリーダー数が `sort-spill-threshold` を超えた場合にのみスピルします。これは Doris の動的なリーダーオプションではありません。異なるスピル動作が必要な場合は、物理的な Paimon テーブルで設定してください。

  スピル専用ディスクを使用するには、すべての BE に存在するか作成可能なローカルパスを設定します。

  ```sql
  "paimon.jni.io_manager.tmp_dir" = "/mnt/ssd1/paimon_io:/mnt/ssd2/paimon_io"
  ```

  Doris は JNI スキャナーごとに IOManager を作成し、スキャナーとともにクローズします。設定したディレクトリが書き込み可能で、同時実行クエリに十分な容量を持つことを確認してください。カスタム実装クラスを設定する場合は、`String[]` を受け取る public コンストラクタ、`String` を受け取る public コンストラクタ、または引数のない public コンストラクタが必要です。クラスのロードまたはインスタンス化に失敗すると、クエリは失敗します。

  これらのプロパティは、JNI 経路を使用する Paimon データテーブルの読み取りにのみ影響します。ネイティブ読み取りには影響しません。`paimon.table-option.file-reader-async-threshold` オプションは独立しており、Paimon の非同期ファイル読み取りのしきい値を制御します。IOManager の有効化やスピルディレクトリの設定は行いません。

* `{CommonProperties}`

  CommonProperties セクションには共通プロパティを指定します。[Catalog の概要](../catalog-overview.md)の[共通プロパティ]のセクションを参照してください。

## メタデータキャッシュ {#meta-cache}

外部データソースへのアクセス性能を向上させるため、Apache Doris は Paimon メタデータをキャッシュします。メタデータには、特定のスナップショットにおけるテーブルスキーマ、最新のスナップショット ID、派生したパーティション投影が含まれます。

:::tip
Doris 4.1.x より前のバージョンでは、メタデータキャッシュは主に FE の設定項目でグローバルに制御されます。詳しくは[メタデータキャッシュ](../meta-cache.md)を参照してください。
Doris 4.1.x 以降、Paimon Catalog の外部メタデータキャッシュは統一された `meta.cache.*` キーで設定します。以下の項目は現在のバージョンを説明しています。Doris 4.1.x と 4.2.x では異なる項目セットを使用し、このページの 4.x バージョンで説明しています。
:::

### キャッシュプロパティの設定 {#meta-cache-unified-model}

各キャッシュエントリには、統一された設定キーフォーマット `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}` を使用します。Paimon の `<engine>` は `paimon` です。`meta.cache.paimon.table.ttl-second` は、最新スナップショットキャッシュとテーブルスキーマキャッシュの TTL を制御します。

| プロパティ | 例 | 意味 |
|---|---|---|
| `enable` | `true/false` | このキャッシュエントリを有効にするかどうか。 |
| `ttl-second` | `600`, `0`, `-1` | `0` はエントリを無効にします（即座に反映され、最新データの確認に使用できます）。`-1` は無期限を意味します。その他の正の整数は、アクセス時刻を基準とする TTL（秒）を意味します。 |
| `capacity` | `10000` | 件数で指定するキャッシュエントリの最大数。`0` はエントリを無効にします。 |
| `max-weight` | `1GB` | Doris 4.1.4 以降でサポート。保持メモリの推定値に対する任意の上限です。正の値が必要で、`0` は拒否されます。以下で示す対象エントリのみで使用できます。 |

**有効化の条件:** `enable=true`、`ttl-second != 0`、`capacity > 0` の場合にエントリが有効になります。FE 全体、Catalog、またはエントリ単位のメモリ上限がある場合は、推定メモリ量による格納制限も適用されます。[外部メタデータキャッシュのメモリ管理](../external-meta-cache-memory-management)を参照してください。

### キャッシュモジュール {#meta-cache-unified-modules}

次のエントリには専用の設定キーがあり、`max-weight` を指定できます。

| エントリ（`<entry>`） | プロパティキーのプレフィックス | `ENTRY_NAME` | キャッシュする内容と効果 | デフォルトの有効化 / TTL / 容量 |
|---|---|---|---|---|
| `partition_view` | `meta.cache.paimon.partition_view.` | `paimon.partition-view` | テーブルのスナップショットから派生したパーティション投影。効果: 計画時にパーティションを繰り返しスキャンする回数を減らします。 | `true` / 86400 s / 1000 |

次のキャッシュには `<entry>` トークンがなく、Catalog と FE 全体のメモリ上限のみに従います。

| `ENTRY_NAME` | キャッシュする内容 | TTL / 容量 |
|---|---|---|
| `paimon-schema-at` | 特定のスナップショットにおけるテーブルスキーマ | 無期限 / 10000 |
| `paimon-latest-snapshot` | テーブルの最新スナップショット ID | `meta.cache.paimon.table.ttl-second` (86400 s) / 1000 |

Paimon テーブルのカラムスキーマは、共有の `default` エンジン（`meta.cache.default.schema.*`）でキャッシュされます。

### 従来のパラメータの対応関係と変換 {#meta-cache-mapping}

| 従来のプロパティキー | 統一キー | 説明 |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.default.schema.ttl-second` | テーブルスキーマキャッシュの有効期限 |

### ベストプラクティス {#meta-cache-best-practices}

* **最新データへのリアルタイムアクセス**: 各クエリで Paimon テーブルの最新スナップショットを参照するには、`meta.cache.paimon.table.ttl-second` を `0` に設定します。
  ```sql
  -- Disable the latest-snapshot cache to detect the latest snapshots of Paimon tables
  ALTER CATALOG paimon_ctl SET PROPERTIES ("meta.cache.paimon.table.ttl-second" = "0");
  ```
* **性能の最適化**: Catalog プロパティの変更が成功すると、影響を受けるメタデータキャッシュが破棄され、次回アクセス時に新しい設定で再構築されます。`meta.cache.max-weight` または `schema.cache.ttl-second` を変更すると、その Catalog のすべてのキャッシュが破棄されます。`meta.cache.<engine>.<entry>.*` を変更すると、そのエンジンのキャッシュが破棄されます。進行中のクエリには影響しません。FE 全体または Catalog のメモリ上限が適用される場合、計上されない2つ目のメタデータキャッシュを避けるため、Paimon SDK 自体の `CachingCatalog` はデフォルトで無効になります。明示的な `paimon.cache-enabled` プロパティがある場合は、そちらが優先されます。

### 可観測性 {#meta-cache-unified-observability}

キャッシュメトリクスは、`information_schema.catalog_meta_cache_statistics` システムテーブルで確認できます。`ENTRY_NAME` には上の表に記載した名前が表示され、`default` エンジンの行は共有テーブルスキーマキャッシュを表します。

```sql
SELECT engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, max_weight, estimated_weight
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'paimon_ctl'
ORDER BY engine_name, entry_name;
```

このシステムテーブルのドキュメントは、[catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md)を参照してください。

### サポートされる Paimon のバージョン {#supported-paimon-versions}

## カラム型のマッピング {#column-type-mapping}

| Paimon の型 | Doris の型 | 備考 |
| ---------------------------------- | ------------- | ----------------------------------------------------------------------- |
| boolean                            | boolean       |                                                                         |
| tinyint                            | tinyint       |                                                                         |
| smallint                           | smallint      |                                                                         |
| integer                            | int           |                                                                         |
| bigint                             | bigint        |                                                                         |
| float                              | float         |                                                                         |
| double                             | double        |                                                                         |
| decimal(P, S)                      | decimal(P, S) |                                                                         |
| varchar                            | string        |                                                                         |
| char                               | string        |                                                                         |
| binary, varbinary | VARBINARY | 4.1.5 以降、この型は常に `VARBINARY` にマッピングされます。`enable.mapping.varbinary` プロパティは互換性のために残されていますが、`false` に設定しても `STRING` へのマッピングには戻りません。それ以前のバージョンでは、このプロパティで従来のマッピングを選択できます。 |
| date                               | date          |                                                                         |
| timestamp\_without\_time\_zone     | datetime(N)   | 精度に応じてマッピングされます。精度が 6 を超える場合は最大の 6 にマッピングされます（精度が失われる可能性があります）。 |
| timestamp\_with\_local\_time\_zone | TIMESTAMPTZ(N) | 4.1.5 以降、この型は常に `TIMESTAMPTZ(N)` にマッピングされます。`enable.mapping.timestamp_tz` プロパティは互換性のために残されていますが、`false` に設定しても `DATETIME` へのマッピングには戻りません。精度は 6 が上限のため、それを超える精度は失われます。それ以前のバージョンでは、このプロパティで従来のマッピングを選択できます。 |
| array                              | array         |                                                                         |
| map                                | map           |                                                                         |
| row                                | struct        |                                                                         |
| other                              | UNSUPPORTED   |                                                                         |

Doris は、Paimon JNI スキャナーの両方の経路で、引用符で囲まれた最上位カラムとネストされた `STRUCT` フィールドの表記を正確に保持します。カンマ（`region,code`）、ハッシュ記号（`nested#value`）、コロン（`colon:name`）、空白、Unicode 文字を含む名前も、通常の SQL 識別子の引用以外にエスケープは必要ありません。読み取り時のカラム名の照合では大文字と小文字が区別されないため、大文字や混在した表記を含むカラム名（たとえば `UserId`）も通常どおりクエリできます。

:::info バージョンに関する注記

4.0 系の 4.0.8 より前のバージョンでは、読み取り時にカラムを完全一致で特定していました。そのため、大文字と小文字が混在するカラム名を持つ Paimon テーブルや Iceberg テーブルでは、誤ったカラムを読み取ったり、クエリが失敗したりする可能性がありました。この問題は 4.0.8 で修正されました。

:::

4.1.5 以降、明示的な `REFRESH TABLE`、`REFRESH DATABASE`、`REFRESH CATALOG` コマンドでも、対応する Paimon メタデータキャッシュが無効化されます。外部でスキーマを変更した後や、テーブルを削除して再作成した後は、refresh コマンドでメタデータを再読み込みしてください。すでに開始したクエリは、選択済みのスナップショットを引き続き使用します。

:::info 注
4.1.5 以降、`timestamp_without_time_zone` は `DATETIME(N)` にマッピングされ、`timestamp_with_local_time_zone` は常に `TIMESTAMPTZ(N)` にマッピングされます。後者はセッションの `time_zone` で表示される時点を表し、`enable.mapping.timestamp_tz=false` で以前のマッピングに戻すことはできません。

ソースの型にタイムゾーン情報が含まれるかどうかは、`DESCRIBE table_name` ステートメントの Extra カラムで確認できます。`WITH_TIMEZONE` と表示される場合、ソースの型がタイムゾーン対応の型であることを示します。（この機能は 3.0.8 以降でサポートされます）

バージョン 4.0.3 以降、`timestamp_with_local_time_zone` を Doris の `timestamptz` 型にマッピングできます。
:::

## 書き込み操作 {#write-operations}

Doris は Paimon テーブルを作成、変更し、データを書き込めます。成功した書き込みはそれぞれ Paimon スナップショットとしてコミットされます。ステートメントが失敗した場合、Doris は部分的なスナップショットを公開しません。

### はじめる前に {#before-you-begin}

データを書き込む前に、次の項目を確認してください。

* すべての FE ノードと BE ノードで、Paimon への書き込みをサポートする Doris ビルドを実行する必要があります。古い BE ノードがまだ動作しているローリングアップグレード中は、Paimon に書き込まないでください。
* Catalog の認証情報には、Metastore を更新し、ウェアハウス内のファイルを作成、書き込み、名前変更、削除する権限が必要です。必要な権限の詳細は、Metastore とストレージシステムによって異なります。
* 書き込みは通常の Paimon データテーブルにのみ適用されます。Paimon システムテーブル、およびブランチ、タグ、スナップショット、タイムスタンプを選択するテーブル参照は読み取り専用です。

### サポートされる SQL {#supported-sql}

| 操作 | サポート内容と注意事項 |
| --- | --- |
| データベース DDL | `CREATE DATABASE` と `DROP DATABASE` |
| テーブル DDL | `CREATE TABLE`、`CREATE TABLE AS SELECT`、`DROP TABLE` |
| スキーマ変更 | カラムの追加、削除、名前変更、並べ替え、変更 |
| データの追加 | `INSERT INTO ... VALUES` と `INSERT INTO ... SELECT` |
| データの上書き | テーブル全体、静的パーティション、動的パーティションの `INSERT OVERWRITE` |
| 行単位の変更 | 主キーテーブルに対する `DELETE`、`UPDATE`、`MERGE INTO`。以下の制約が適用されます。 |

### クイックスタート {#quick-start}

次の例では、主キーテーブルを作成してデータを書き込みます。Paimon テーブルのオプションは `PROPERTIES` で指定します。Doris の `DISTRIBUTE BY` 句は追加しないでください。

```sql
SWITCH paimon_ctl;
CREATE DATABASE IF NOT EXISTS sales;
USE sales;

CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    customer STRING NULL,
    amount DECIMAL(12, 2) NULL,
    status STRING NULL
) ENGINE=paimon
PROPERTIES (
    'primary-key' = 'order_id',
    'bucket' = '2',
    'bucket-key' = 'order_id'
);

INSERT INTO orders VALUES
    (1, 'Alice', 99.90, 'NEW'),
    (2, 'Bob', 35.00, 'NEW');

UPDATE orders
SET status = 'PAID'
WHERE order_id = 1;

DELETE FROM orders
WHERE order_id = 2;

SELECT * FROM orders ORDER BY order_id;
```

結果:

```text
+----------+----------+--------+--------+
| order_id | customer | amount | status |
+----------+----------+--------+--------+
|        1 | Alice    |  99.90 | PAID   |
+----------+----------+--------+--------+
```

Doris を通じてテーブルスキーマを変更し、新しいスキーマで書き込みを続けることができます。

```sql
ALTER TABLE orders ADD COLUMN note STRING NULL;
ALTER TABLE orders RENAME COLUMN note order_note;
```

### データの挿入と上書き {#insert-and-overwrite-data}

`INSERT INTO` は、追加専用テーブルには行を追加し、主キーテーブルにはその Paimon オプションに従って行をマージします。ソースには `VALUES`、Doris の内部テーブル、または別の外部テーブルを使用できます。

```sql
INSERT INTO paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.new_orders;
```

パーティションのないテーブルでは、`INSERT OVERWRITE` によって既存のすべての行が置き換えられます。そのため、入力が空ならテーブルも空になります。

```sql
INSERT OVERWRITE TABLE paimon_ctl.sales.orders
SELECT order_id, customer, amount, status
FROM internal.sales.orders_snapshot;
```

パーティションテーブルでは、次のいずれかの形式を使用します。

```sql
-- Replace only the specified partition. The SELECT list omits the static partition column.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
PARTITION (order_date = '2026-10-08')
SELECT order_id, customer, amount, status
FROM internal.sales.daily_orders_stage;

-- Dynamic overwrite replaces the partitions present in the input and keeps other partitions.
INSERT OVERWRITE TABLE paimon_ctl.sales.daily_orders
SELECT order_id, customer, amount, status, order_date
FROM internal.sales.daily_orders_stage;
```

主キーテーブルで非キー列を省略した挿入を受け付けるのは、`merge-engine` が `partial-update` の場合のみです。追加専用テーブルで省略したカラムには、デフォルト値、または許可されている場合は `NULL` が使用されます。

### データの削除、更新、マージ {#delete-update-and-merge-data}

行単位の変更には Paimon の主キーテーブルが必要です。デフォルトの `deduplicate` マージエンジンを使用するテーブルに対して、Doris は次の操作をサポートします。

```sql
DELETE FROM paimon_ctl.sales.orders
WHERE order_id = 10;

UPDATE paimon_ctl.sales.orders
SET amount = amount * 0.9,
    status = 'DISCOUNTED'
WHERE order_id = 20;

MERGE INTO paimon_ctl.sales.orders t
USING internal.sales.order_changes s
ON t.order_id = s.order_id
WHEN MATCHED AND s.action = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
    customer = s.customer,
    amount = s.amount,
    status = s.status
WHEN NOT MATCHED THEN INSERT (order_id, customer, amount, status)
    VALUES (s.order_id, s.customer, s.amount, s.status);
```

Paimon による行変更の適用方法により、次の制約があります。

* `UPDATE` では、主キーのカラムや `sequence.field` で設定されたカラムを変更できません。
* `MERGE` 内の更新アクションを含む `UPDATE` は、`deduplicate` マージエンジンのみをサポートし、`changelog-producer=input` はサポートしません。
* パーティションカラムを更新するには、`ignore-delete=false` を設定した動的バケットテーブル（`bucket=-1`）が必要です。
* `MERGE` 内の削除アクションを含む `DELETE` には、`ignore-delete=false` が必要です。デフォルトの `deduplicate` マージエンジンはこれを直接サポートします。`partial-update` テーブルには `partial-update.remove-record-on-delete=true`、`aggregation` テーブルには `aggregation.remove-record-on-delete=true` の設定が必要です。
* `rowkind.field` を設定したテーブルでは、これらの行単位のステートメントはサポートされません。`cross-partition-upsert.index-ttl` を設定した動的バケットテーブルでもサポートされません。
* `MERGE` ステートメントには、含まれるアクションに応じて、対応する `UPDATE` と `DELETE` の制約が適用されます。

結果を予測しやすくするため、`MERGE` のソース側では照合キーを一意にしてください。複数のソース行が同じターゲット行に一致する場合、Doris はステートメントを拒否します。

### 運用上の注意事項 {#operational-notes}

* 主キー、パーティション、バケット、マージエンジン、ファイルフォーマット、コンパクション、その他の物理的な動作は、Paimon テーブルのプロパティとして設定します。Doris は Paimon SDK を通じてこれらのオプションを検証します。
* Doris は現在、Paimon テーブルに対する汎用の `ALTER TABLE ... SET TBLPROPERTIES` 操作を提供していません。作成後にテーブルプロパティを変更するには、別の Paimon エンジンを使用し、その後 Doris で `REFRESH TABLE` または `REFRESH CATALOG` を実行してください。
* 書き込みのスピルに十分なローカルディスク容量を各 BE に確保し、一時ファイルとコミット操作に必要なウェアハウスの権限を付与してください。BE 設定の `paimon_jni_writer_memory_pool_limit_bytes` は、各 Paimon JNI ライターが使用するメモリプールを制限します。デフォルト値は 512 MB です。
* 書き込みまたはスキーマ変更が成功すると、新しい Doris ステートメントはコミットされた Paimon スナップショットをデータロードします。既存のステートメントは、開始時に選択したスナップショットを引き続き使用します。

## クエリ操作 {#query-operations}

### 基本的なクエリ {#basic-query}

Catalog の設定後、次のように Catalog 内のテーブルデータをクエリできます。

```sql
-- 1. Switch to catalog, use database, and query
SWITCH paimon_ctl;
USE paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 2. Use Paimon database directly
USE paimon_ctl.paimon_db;
SELECT * FROM paimon_tbl LIMIT 10;

-- 3. Use fully qualified name to query
SELECT * FROM paimon_ctl.paimon_db.paimon_tbl LIMIT 10;
```

### ファイルメタデータカラム {#file-metadata-columns}

> バージョン 4.2.0 以降でサポートされます。

Doris は Paimon データテーブルに対して、2つの非表示メタデータカラムを公開します。これらを使うと、各クエリ結果の元になった物理データファイルと行を特定できます。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `__paimon_file_path` | `STRING NOT NULL` | Paimon が返す、生のデータファイルの元のパス。 |
| `__paimon_row_index` | `BIGINT NOT NULL` | データファイル全体における、ゼロから始まる物理的な行位置。 |

前提条件: 前の例に従って Paimon Catalog を設定し、`id` カラムを持ち、Parquet または ORC ファイルを使用する Paimon データテーブルを作成します。次のクエリは、`paimon_tbl` に `id` の値が `1` と `2` の行がすでに存在すると仮定します。

```sql
SELECT id, `__paimon_file_path`, `__paimon_row_index`
FROM paimon_ctl.paimon_db.paimon_tbl
ORDER BY `__paimon_file_path`, `__paimon_row_index`;
```

結果の例（ファイルパスはテーブルの場所によって異なります）:

```text
+----+------------------------------------------+--------------------+
| id | __paimon_file_path                       | __paimon_row_index |
+----+------------------------------------------+--------------------+
|  1 | s3://bucket/warehouse/db/table/a.parquet |                  0 |
|  2 | s3://bucket/warehouse/db/table/a.parquet |                  1 |
+----+------------------------------------------+--------------------+
```

デフォルトでは、これらのカラムは `SELECT *` や `DESC` には表示されません。

非表示カラムを `SELECT *` と `DESC` に含めるには、セッションで `show_hidden_columns` を有効にします。

```sql
SET show_hidden_columns = true;
```

関連するセッション変数:

| 変数 | 型 | デフォルト値 | 必須 | 効果 |
| --- | --- | --- | --- | --- |
| `show_hidden_columns` | `BOOLEAN` | `false` | いいえ | `SELECT *` と `DESC` に非表示カラムを含めます。カラムを明示的に参照する場合は不要です。 |
| `enable_file_scanner_v2` | `BOOLEAN` | `true` | いいえ | クエリがこれらのメタデータカラムを参照する場合、有効のままにする必要があります。 |
| `force_jni_scanner` | `BOOLEAN` | `false` | いいえ | JNI リーダーはこれらのメタデータカラムを生成できないため、無効のままにする必要があります。 |

行位置は、物理ファイル全体を基準とします。述語によるフィルタリング、Deletion Vector の処理、スキャンの分割によって、残った行の番号が振り直されることはありません。そのため、`__paimon_file_path` と `__paimon_row_index` の組み合わせで、現在のテーブルスナップショット内の物理レコードを特定できます。データファイルの再書き込みやコンパクションによって両方の値が変わる可能性があるため、安定した論理行 ID として使用しないでください。

:::caution
これらのカラムを使用できるのは、クエリに参加するすべての Paimon スプリットを、FileScannerV2 のネイティブ Parquet または ORC リーダーで生のデータファイルとして読み取れる場合だけです。JNI またはネイティブと JNI が混在するスキャン、`enable_file_scanner_v2` が無効な場合、`force_jni_scanner` が有効な場合、または選択したデータファイルをネイティブ Parquet/ORC リーダーで読み取れない場合は、これらのカラムを参照するクエリは失敗します。

`__paimon_file_path` と `__paimon_row_index` は予約名であり、大文字と小文字を区別せずに比較されます。Paimon テーブルの物理カラム名として使用しないでください。
:::

### バッチ増分クエリ {#batch-incremental-query}

> バージョン 3.1.0 以降

Flink と同様に、Paimon の[バッチ増分](https://paimon.apache.org/docs/master/flink/sql-query/#batch-incremental)クエリをサポートします。

指定したスナップショットまたはタイムスタンプの区間内の増分データをクエリできます。区間は左端を含み、右端を含みません。

```sql
-- between snapshots [0, 5)
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5');

-- between snapshots [0, 5) with specified scan mode
SELECT * FROM paimon_table@incr('startSnapshotId'='0', 'endSnapshotId'='5', 'incrementalBetweenScanMode'='diff');

-- read from start timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000');

-- read between timestamp
SELECT * FROM paimon_table@incr('startTimestamp'='1750844949000', 'endTimestamp'='1750944949000');
```

パラメータ:

| パラメータ | 説明 | 例 |
| --- | --- | --- |
| `startSnapshotId` | 開始スナップショット ID。0 より大きい必要があります。`endSnapshotId` とともに指定する必要があります。 | `'startSnapshotId'='3'` |
| `endSnapshotId` | 終了スナップショット ID。`startSnapshotId` より大きい必要があります。`startSnapshotId` とともに指定する必要があります。 | `'endSnapshotId'='10'` |
| `incrementalBetweenScanMode` | 増分読み取りモードを指定します。デフォルトは `auto` で、`delta`、`changelog`、`diff` をサポートします。 | `'incrementalBetweenScanMode'='delta'` |
| `startTimestamp` | 開始スナップショットのタイムスタンプ。0 以上である必要があります。単位はミリ秒です。 | `'startTimestamp'='1750844949000'` |
| `endTimestamp` | 終了スナップショットのタイムスタンプ。`startTimestamp` より大きい必要があります。省略可能です。省略した場合、`startTimestamp` から最新のスナップショットまでを読み取ります。単位はミリ秒です。 | `'endTimestamp'='1750944949000'` |

:::tip 注意
`startSnapshotId` と `endSnapshotId` は、Paimon パラメータ `'incremental-between'='3,10'` を構成します。

`startTimestamp` と `endTimestamp` は、Paimon パラメータ `'incremental-between-timestamp'='1750844949000,1750944949000'` を構成します。

`incrementalBetweenScanMode` は、Paimon パラメータ `incremental-between-scan-mode` に対応します。
:::

これらのパラメータの詳細は、[Paimon のドキュメント](https://paimon.apache.org/docs/master/maintenance/configurations/)を参照してください。

### Time Travel {#time-travel}

> バージョン 3.1.0 以降

Paimon テーブルの指定したスナップショットの読み取りをサポートします。

デフォルトでは、読み取りリクエストは最新バージョンのスナップショットのみを読み取ります。

`$snapshots` テーブル関数を使用すると、指定した Paimon テーブルのスナップショットをクエリできます。

```sql
Doris > SELECT snapshot_id,commit_time FROM paimon_tbl$snapshots;
+-------------+-------------------------+
| snapshot_id | commit_time             |
+-------------+-------------------------+
|           1 | 2025-08-17 06:05:52.740 |
|           2 | 2025-08-17 06:05:52.979 |
|           3 | 2025-08-17 06:05:53.240 |
|           4 | 2025-08-17 06:05:53.561 |
+-------------+-------------------------+
```

`FOR TIME AS OF` ステートメントと `FOR VERSION AS OF` ステートメントを使用すると、スナップショット ID またはスナップショットの作成時刻に基づいて、履歴バージョンのデータを読み取れます。例:

```sql
-- Notice: Before 3.1.1, only support format like YYYY-MM-DD HH:MM:SS.SSS
-- After 3.1.2, support YYYY-MM-DD HH:MM:SS and YYYY-MM-DD
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52.740";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17 06:05:52";
SELECT * FROM paimon_tbl FOR TIME AS OF "2025-08-17";

-- Notice: The timestamp must be precise down to the millisecond.
SELECT * FROM paimon_tbl FOR TIME AS OF 1755381952740;
-- Use snapshot id
SELECT * FROM paimon_tbl FOR VERSION AS OF 1;
```

#### `@options` を使用した Time Travel {#time-travel-with-options}

Paimon 固有のセレクタには、クエリのテーブル参照で `@options` を使用します。Doris は `scan.snapshot-id`、`scan.tag-name`、`scan.version`、`scan.timestamp`、`scan.timestamp-millis`、`scan.watermark`、`scan.file-creation-time-millis`、`scan.creation-time-millis`、`scan.mode` を受け付けます。選択したスナップショットまたはタグによって履歴スキーマも選択されます。Doris が履歴データに最新のスキーマをバインドすることはありません。

```sql
-- Read snapshot 1 with the schema stored for snapshot 1.
SELECT id, old_name
FROM paimon_tbl@options('scan.snapshot-id' = '1');

-- A retained tag remains readable even after its ordinary snapshot expires.
SELECT id, old_name
FROM paimon_tbl@options('scan.tag-name' = 'tag1');
```

1つのテーブル参照に指定できる開始位置オプションは1つだけです。`scan.mode` と開始位置を組み合わせられるのは、Paimon がその組み合わせを互換と定義している場合だけです。たとえば、`scan.mode='from-creation-timestamp'` には `scan.creation-time-millis` が必要です。不明または期限切れのスナップショット、ブランチ、タグを指定すると、暗黙に最新のテーブルへフォールバックする代わりに、明示的に失敗します。`@options` 構文はクエリのテーブル参照でサポートされ、ビュー定義に保存できますが、CTE 参照や `SHOW` のようなクエリ以外のコマンドには適用できません。

### ブランチとタグ {#branch-and-tag}

> バージョン 3.1.0 以降

指定した Paimon テーブルのブランチとタグの読み取りをサポートします。

`$branches` と `$tags` システムテーブルを使用すると、Paimon テーブルのブランチとタグを確認できます。

```
Doris > SELECT * FROM paimon_tbl$branches;
+-------------+-------------------------+
| branch_name | create_time             |
+-------------+-------------------------+
| b_1         | 2025-08-17 06:34:37.294 |
| b_2         | 2025-08-17 06:34:37.297 |
+-------------+-------------------------+

Doris > SELECT * FROM paimon_tbl$tags;
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| tag_name | snapshot_id | schema_id | commit_time             | record_count | create_time | time_retained |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
| t_1      |           1 |         0 | 2025-08-17 06:05:52.740 |            3 | NULL        | NULL          |
| t_2      |           2 |         0 | 2025-08-17 06:05:52.979 |            6 | NULL        | NULL          |
| t_3      |           3 |         0 | 2025-08-17 06:05:53.240 |            9 | NULL        | NULL          |
| t_4      |           4 |         0 | 2025-08-17 06:05:53.561 |           12 | NULL        | NULL          |
+----------+-------------+-----------+-------------------------+--------------+-------------+---------------+
```

Spark や Trino などのシステムと互換性を保つため、さまざまな構文形式をサポートします。

```sql
-- BRANCH
SELECT * FROM paimon_tbl@branch(branch1);
SELECT * FROM paimon_tbl@branch("name" = "branch1");

-- TAG
SELECT * FROM paimon_tbl@tag(tag1);
SELECT * FROM paimon_tbl@tag("name" = "tag1");
SELECT * FROM paimon_tbl FOR VERSION AS OF 'tag1';
```

`FOR VERSION AS OF` 構文では、Doris がパラメータがタイムスタンプかどうかを自動的に判定します。

## システムテーブル {#system-tables}

> バージョン 3.1.0 以降

Doris は、テーブル関連のメタデータを取得するための Paimon システムテーブルのクエリをサポートします。システムテーブルを使用すると、スナップショットの履歴、マニフェストファイル、データファイル、パーティションなどの情報を確認できます。

Paimon テーブルのメタデータにアクセスするには、テーブル名の後に `$` 記号とシステムテーブル名を追加します。

```sql
SELECT * FROM my_table$system_table_name;
```

`audit_log`、`binlog`、`manifests`、`partitions`、`ro`、`row_tracking`、`table_indexes` のシステムテーブルは、テーブル参照の `@options` を受け付けます。選択したスナップショットまたはタグは、システムテーブルの行と、ソースカラムを公開するシステムテーブルでは対応する履歴ソーステーブルのスキーマに適用されます。

```sql
SELECT rowkind, id, old_name
FROM paimon_tbl$audit_log@options('scan.tag-name' = 'tag1');
```

その他のシステムテーブルでは、行を生成するすべての処理段階で選択したスナップショットが参照されることを保証できないため、`@options` は拒否されます。また、Paimon システムテーブルでは `scan.file-creation-time-millis` も拒否されます。このファイルフィルタを暗黙に破棄すると、要求した範囲外の行が返される可能性があるためです。

:::info 注
Doris は、Flink でのみサポートされる Paimon のグローバルシステムテーブルの読み取りをサポートしません。
:::

## 付録 {#appendix}

### FAQ {#faq}

**1. `Could not find a file io implementation for scheme 's3a' in the classpath`**

3.1 より前のバージョンで、HMS をメタデータストレージとして使用し、ストレージ側で 's3a' または 's3' プロトコルを使用すると、次のエラーが発生します。

```text
java.io.UncheckedIOException: org.apache.paimon.fs.UnsupportedSchemeException: Could not find a file io implementation for scheme 's3a' in the classpath. Hadoop FileSystem also cannot access this path 's3a://`.
```

**3.1 より前のバージョン**

3.1 より前のバージョンでは、`s3a` プロトコルをサポートしません。使用する必要がある場合は、回避策として `s3a` 関連のパラメータを一時的に追加できます。

**バージョン 3.1 以降**

バージョン 3.1 以降では、`s3a` パラメータを明示的に追加する必要はありません。Paimon のストレージパラメータを上書きする場合は、`paimon.fs.` プレフィックス付きのパラメータを追加できます。Paimon は内部で HDFS API を使用するため、すべての `fs.s3a.*` パラメータがサポートされます。

例:

```sql
CREATE CATALOG `paimon_hms_on_s3a` PROPERTIES (
    "type" = "paimon",
    "paimon.catalog.type" = "hms",
    "hive.metastore.uris" = "thrift://172.20.48.119:9383",
    "warehouse" = "s3a://bucket/paimon_warehouse",
    "s3.access_key" = "<ak>",
    "s3.secret_key" = "<sk>",
    "s3.region" = "ap-east-1",
    "s3.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    -- Explicitly add s3a parameters
    "fs.s3a.access.key" = "<ak>",
    "fs.s3a.secret.key" = "<sk>",
    "fs.s3a.endpoint.region" = "ap-east-1",
    "fs.s3a.endpoint" = "https://s3.ap-east-1.amazonaws.com",
    "fs.s3a.impl" = "org.apache.hadoop.fs.s3a.S3AFileSystem"
);
```

`s3` プロトコルを使用する場合は、Paimon の S3 関連パラメータを明示的に追加する必要があります。つまり、`paimon.` プレフィックスを付けます。例:

```sql
CREATE CATALOG test_paimon_on_hms_aws_catalog PROPERTIES (
    'type' = 'paimon',
    'paimon.catalog.type' = 'hms',
    'warehouse' = 's3://bucket-hk/paimon_warehouse',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9383',
    's3.region' = 'ap-east-1',
    's3.endpoint' = 'https://s3.ap-east-1.amazonaws.com',
    's3.access_key' = '<ak>',
    's3.secret_key' = '<sk>',
    -- Explicitly add Paimon S3 parameters
    'paimon.s3.region' = 'ap-east-1',
    'paimon.s3.endpoint' = 'ap-east-1',
    'paimon.s3.access-key' = '<ak>',
    'paimon.s3.secret-key' = '<sk>'
);
```
