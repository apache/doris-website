Hive Metastore または Hive Metastore と互換性のあるメタデータサービスに接続すると、Doris は Hive のデータベースとテーブルの情報を自動的に取得し、データをクエリできます。

Hive 以外にも、多くのシステムがメタデータの保存に Hive Metastore を使用します。そのため Hive Catalog を使うと、Hive テーブルだけでなく、Iceberg や Hudi など、メタデータを Hive Metastore に保存するほかのテーブル形式にもアクセスできます。

## 適用シナリオ

| シナリオ | 説明 |
|--------------|--------------------------------------------------------------|
| クエリの高速化 | Doris の分散コンピューティングエンジンから Hive データに直接アクセスし、クエリを高速化します。 |
| データ統合 | Hive データを読み取って Doris の内部テーブルに書き込むか、Doris のコンピューティングエンジンを使用して ZeroETL 処理を行います。 |
| データの書き戻し | Doris がサポートする任意のソースのデータを処理し、Hive テーブルに書き戻します。 |

## Catalog の設定

### 構文

```sql
CREATE CATALOG [IF NOT EXISTS] catalog_name PROPERTIES (
    'type'='hms', -- required
    'hive.metastore.type' = '<hive_metastore_type>', -- optional
    'hive.version' = '<hive_version>', -- optional
    'fs.defaultFS' = '<fs_defaultfs>', -- required for write, optional for read-only
    {MetaStoreProperties},
    {StorageProperties},
    {HiveProperties},
    {CommonProperties}
);
```

* `<hive_metastore_type>`

  Hive Metastore の種類を指定します。

  * `hms`: 標準の Hive Metastore サービス。
  * `glue`: Hive Metastore 互換インターフェースを使用して AWS Glue メタデータサービスにアクセスします。
  * `dlf`: Hive Metastore 互換インターフェースを使用して Alibaba Cloud DLF メタデータサービスにアクセスします。

* `<fs_defaultfs>`

  Doris からこの Hive Catalog のテーブルにデータを書き込む場合、このパラメータが必要です。例:

  `'fs.defaultFS' = 'hdfs://namenode:port'`

* `{MetaStoreProperties}`

  MetaStoreProperties セクションには、Metastore メタデータサービスへの接続情報と認証情報を指定します。詳細は「サポートされるメタデータサービス」を参照してください。

* `{StorageProperties}`

  StorageProperties セクションには、ストレージシステムに関する接続情報と認証情報を指定します。詳細は「サポートされるストレージシステム」を参照してください。

* `{HiveProperties}`

  HiveProperties セクションには、Hive Catalog に関するプロパティを指定します。

  * `get_schema_from_table`: デフォルトは false です。通常、Doris は Hive Metastore からテーブルのスキーマ情報を取得します。ただし、`Storage schema reading not supported` エラーなどの互換性の問題が発生することがあります。その場合はこのパラメータを true に設定すると、Table オブジェクトからスキーマを直接取得します。この方法では列のデフォルト値に関する情報が無視される点に注意してください。このプロパティはバージョン 2.1.10 および 3.0.6 以降でサポートされます。

  * `hive.recursive_directories`: パーティションディレクトリの一覧取得時にサブディレクトリを再帰的に検索するかどうかを指定します。このパラメータはバージョン 3.0.2 以降でサポートされます。バージョン 4.0 より前のデフォルトは `false`、それ以降のデフォルトは `true` です。一部の Hive テーブルでは、パーティションパスがテーブルスキーマのパーティション情報と一致しないことがあります。サブディレクトリ内のデータファイルを取得するには、このパラメータを true に設定する必要があります。

  * `hive.ignore_absent_partitions`: 存在しないパーティションを無視するかどうかを指定します。デフォルトは `true` です。`false` に設定すると、存在しないパーティションに遭遇したときにクエリがエラーを報告します。このパラメータはバージョン 3.0.2 以降でサポートされます。

  * `hive.staging_dir`: Hive への書き込みで使用する一時ステージングルートディレクトリを設定します。書き込み中は最初にこのディレクトリにデータを書き込み、完了後に最終的な Hive テーブルディレクトリへ移動します。パスには、Hive テーブルのルートディレクトリからの相対パスまたは絶対パスを指定できます。デフォルトは `/tmp/.doris_staging` です。`/tmp` ディレクトリとテーブルディレクトリが異なる名前空間に属するために書き込みが失敗する場合は、このパラメータを相対パスに変更すると解決できます。このパラメータはバージョン 4.0.3 以降でサポートされます。

  * `hive.parquet.time-zone`: FileScannerV2 が Hive テーブルを読み取るとき、従来の Parquet `INT96` タイムスタンプを復元するために使用する互換タイムゾーンです。デフォルトは空で、タイムゾーン変換を行わずに `INT96` に保存された日時フィールドを維持します。Catalog 内の `INT96` ファイルが、既知のタイムゾーンを使用して書き込み側で正規化された場合にのみ設定してください。Hudi テーブルは意図的にこのプロパティを無視し、既存の SQL セッションタイムゾーンに基づく動作を維持します。詳細は [Parquet INT96 タイムスタンプの互換性](#timestamp-compatibility)を参照してください。

* `{CommonProperties}`

  CommonProperties セクションには共通属性を指定します。[Catalog の概要](../catalog-overview.md)の「共通プロパティ」を参照してください。

## メタデータキャッシュ {#meta-cache}

外部データソースへのアクセス性能を向上させるため、Apache Doris は Hive メタデータをキャッシュします。対象には、テーブルオブジェクト、パーティション名、パーティションオブジェクト、列統計、ファイル一覧、派生したパーティション枝刈り構造が含まれます。

:::tip
Doris 4.1.x より前のバージョンでは、メタデータキャッシュは主に FE の設定項目によってグローバルに制御されます。詳細は[メタデータキャッシュ](../meta-cache.md)を参照してください。
Doris 4.1.x 以降、Hive Catalog の外部メタデータキャッシュは統一された `meta.cache.*` キーで設定します。以下の項目は current バージョンについて説明しています。Doris 4.1.x と 4.2.x では項目が異なるため、このページの 4.x バージョンを参照してください。
:::

### キャッシュプロパティの設定 {#meta-cache-unified-model}

各キャッシュ項目の設定キーは、統一形式 `meta.cache.<engine>.<entry>.{enable,ttl-second,capacity,max-weight}` を使用します。Hive の `<engine>` は `hive` です。Iceberg テーブルを含む Hive Metastore Catalog では、`iceberg` 項目も使用します。これらの項目については [Iceberg Catalog](./iceberg-catalog#meta-cache) を参照してください。

| プロパティ | 例 | 意味 |
|---|---|---|
| `enable` | `true/false` | このキャッシュ項目を有効にするかどうか。 |
| `ttl-second` | `600`, `0`, `-1` | `0` は項目を無効化します（即時に反映され、最新データの確認に利用可能）。`-1` は無期限を意味します。その他の正の整数は、アクセス時刻に基づく TTL の秒数です。 |
| `capacity` | `10000` | キャッシュ項目の最大件数。`0` は項目を無効化します。 |
| `max-weight` | `1GB` | Doris 4.1.4 以降でサポート。保持メモリの推定上限を指定する任意項目です。正の値が必要で、`0` は拒否されます。以下で明示した項目でのみ使用できます。 |

**有効化の条件:** `enable=true`、`ttl-second != 0`、`capacity > 0` のすべてを満たすと項目が有効になります。FE 全体、Catalog、または項目単位のメモリ上限によって、推定メモリに基づくキャッシュへの追加も制御されます。[外部メタデータキャッシュのメモリ管理](../external-meta-cache-memory-management)を参照してください。

### キャッシュモジュール {#meta-cache-unified-modules}

Hive Catalog には次のキャッシュ項目があります。すべて `max-weight` を指定できます。

| 項目 (`<entry>`) | プロパティキープレフィックス | `ENTRY_NAME` | キャッシュされる内容と効果 | デフォルトの enable / TTL / capacity |
|---|---|---|---|---|
| `table` | `meta.cache.hive.table.` | `hive-table` | Hive Metastore のテーブルオブジェクト。効果: プランニング時の Metastore へのアクセス回数を減らします。 | `true` / 86400 s / 10000 |
| `partition_names` | `meta.cache.hive.partition_names.` | `hive-partition-names` | パーティション名の一覧。効果: パーティションの列挙に影響し、無効にすると新しいパーティションが直ちに見えるようになります。 | `true` / 86400 s / 10000 |
| `partition` | `meta.cache.hive.partition.` | `hive-partition` | 場所や入力形式などのパーティションオブジェクト。 | `true` / 86400 s / 100000 |
| `column_stats` | `meta.cache.hive.column_stats.` | `hive-column-stats` | Hive Metastore の列統計。 | `true` / 86400 s / 10000 |
| `file` | `meta.cache.hive.file.` | `hive-file` | ファイル一覧。効果: リモートの LIST 操作を減らし、無効にするとファイルの変更が直ちに見えるようになります。 | `true` / 86400 s / 10000 |
| `partition_view` | `meta.cache.hive.partition_view.` | `hive-partition-view` | パーティション名から派生したパーティション枝刈り構造。 | `true` / 86400 s / 1000 |

Hive テーブルの列スキーマは、すべての外部 Catalog で使用される共通の `default` エンジン（`meta.cache.default.schema.*`）によってキャッシュされます。

### 従来のパラメータとの対応と変換 {#meta-cache-mapping}

統一されたキーの使用を推奨します。次の従来の Catalog プロパティも引き続き受け付けられ、対応するキーにマッピングされます。

| 従来のプロパティキー | 統一キー | 説明 |
|---|---|---|
| `schema.cache.ttl-second` | `meta.cache.default.schema.ttl-second` と `meta.cache.hive.table.ttl-second` | テーブルスキーマとテーブルオブジェクトのキャッシュの有効期限 |
| `partition.cache.ttl-second` | `meta.cache.hive.partition_names.ttl-second` | パーティション名一覧の有効期限 |
| `file.meta.cache.ttl-second` | `meta.cache.hive.file.ttl-second` | ファイル一覧の有効期限 |

### ベストプラクティス {#meta-cache-best-practices}

* **最新データへのリアルタイムアクセス**: 各クエリで外部データソースの最新のパーティションやファイルの変更を確認する場合は、該当する `ttl-second` を `0` に設定します。
  ```sql
  -- Disable the file listing cache to see file changes in real time
  ALTER CATALOG hive_ctl SET PROPERTIES ("meta.cache.hive.file.ttl-second" = "0");
  -- Disable the partition name cache to see new partitions in real time
  ALTER CATALOG hive_ctl SET PROPERTIES ("meta.cache.hive.partition_names.ttl-second" = "0");
  ```
* **性能の最適化**: メタデータの変更頻度が低い場合は、`capacity` と `ttl-second` を増やし、Hive Metastore やファイルシステムへのアクセス負荷を減らします。非常に大きいテーブルでは `max-weight` を使い、ファイル一覧とパーティション枝刈りのキャッシュ容量を制限します。

:::caution
Catalog プロパティの変更に成功すると、対象のメタデータキャッシュが破棄され、次回アクセス時に新しい設定で再構築されます。`meta.cache.max-weight` または `schema.cache.ttl-second` を変更すると Catalog のすべてのキャッシュが破棄され、`meta.cache.<engine>.<entry>.*` を変更するとそのエンジンのキャッシュが破棄されます。進行中のクエリには影響しません。
:::

### 監視 {#meta-cache-unified-observability}

キャッシュのメトリクスは、`information_schema.catalog_meta_cache_statistics` システムテーブルで確認できます。`ENTRY_NAME` には上の表に示した名前が表示され、`default` エンジンの行は共通のテーブルスキーマキャッシュを表します。

```sql
SELECT engine_name, entry_name,
       effective_enabled, ttl_second, capacity,
       estimated_size, hit_rate, max_weight, estimated_weight
FROM information_schema.catalog_meta_cache_statistics
WHERE catalog_name = 'hive_ctl'
ORDER BY engine_name, entry_name;
```

このシステムテーブルの詳細は [catalog_meta_cache_statistics](../../admin-manual/system-tables/information_schema/catalog_meta_cache_statistics.md)を参照してください。

## Parquet INT96 タイムスタンプの互換性 {#timestamp-compatibility}

Hive テーブルには、異なるエンジンが生成したタイムスタンプファイルが含まれる場合があります。タイムゾーン変換が必要かどうかは、物理エンコーディングと書き込み側の動作によって決まります。`INT96` にはタイムゾーンの注釈がないため、Doris は Parquet の `INT96` 値から書き込み側のタイムゾーンを推測しません。

### Parquet INT96 タイムスタンプ

FileScannerV2 は Parquet のタイムスタンプを次のように処理します。

| 物理エンコーディング | デフォルトの動作 | `hive.parquet.time-zone` の効果 |
|---|---|---|
| `INT96` を `DATETIMEV2` にマッピングしたもの | ファイルに保存された日付と時刻のフィールドを維持します。SQL セッションのタイムゾーンによって値は変わりません。 | 生の `INT96` 値を UTC の時点として扱い、設定された互換タイムゾーンに変換して、従来の書き込み側が正規化したタイムスタンプを復元します。 |
| タイムスタンプの論理型を持つ `INT64` | Parquet の論理型のセマンティクスに従います。 | 影響しません。 |

たとえば、意図したローカル時刻が `2021-01-01 10:11:00` で、タイムゾーンが `Asia/Shanghai` の場合を考えます。

* ファイルに日時フィールドが `10:11:00` として直接保存されている場合は、`hive.parquet.time-zone` を設定しないでください。Doris は `10:11:00` を返します。この動作は SQL セッションが `Asia/Shanghai` を使用していても変わりません。
* 従来の書き込み側が `INT96` に保存する前に値を UTC に正規化した場合、ファイルには `02:11:00` が含まれることがあります。`hive.parquet.time-zone` を `Asia/Shanghai` に設定すると、Doris は `10:11:00` を復元します。

Catalog の作成時に互換タイムゾーンを設定します。

```sql
CREATE CATALOG hive_legacy_int96 PROPERTIES (
    'type' = 'hms',
    'hive.metastore.uris' = 'thrift://127.0.0.1:9083',
    'hive.parquet.time-zone' = 'Asia/Shanghai'
);
```

値には `Asia/Shanghai` などの IANA タイムゾーン名、または `-12:00` から `+14:00` までの UTC オフセットを指定できます。無効な値を指定すると Catalog の作成に失敗します。

:::caution
`hive.parquet.time-zone` は、Catalog 内の Hive テーブルで `INT96` から `DATETIMEV2` にマッピングされるすべてのタイムスタンプ列に適用されます。Iceberg は独自のタイムスタンプセマンティクスを定義しているため、同じ Hive Metastore にある Iceberg テーブルには影響しません。Hudi も意図的にこのプロパティを無視します。ネイティブのベースファイルスキャンと JNI の merge-on-read スキャンは、どちらも SQL セッションのタイムゾーンでタイムスタンプを解釈する従来の動作を維持します。Parquet メタデータからは、`INT96` の書き込み側がどの規則を使用したかを確実には判別できません。SQL セッションのタイムゾーンに合わせるためだけにこのプロパティを設定しないでください。同じ Hive Metastore に異なる規則で書き込まれた `INT96` ファイルを持つ Hive テーブルがある場合は、可能であれば別々の Catalog を通して公開してください。
:::

Parquet ファイルを読み取るファイルテーブル値関数でも同じプロパティを指定できます。互換変換は FileScannerV2 での Parquet `INT96` のデコードにのみ適用されます。FileScannerV1 は意図的に変更されておらず、異なる結果を返す場合があります。FileScannerV1 への切り替えは、この変更に対する互換手段ではありません。Parquet `INT64` の論理タイムスタンプには影響しません。`INT96` 列が `TIMESTAMPTZ` にマッピングされる場合、Doris はこのプロパティを無視して UTC の時点を維持します。その値の表示は引き続き `TIMESTAMPTZ` とセッションタイムゾーンのセマンティクスに従います。

### 移行時の推奨事項

* Doris はデフォルトで Parquet `INT64` の論理タイムスタンプを書き込みます。`enable_int96_timestamps = true` は、Hive 2 や Hive 3 などの従来の読み取り側が `INT96` を必要とする場合にのみ設定してください。
* この FileScannerV2 の動作を含むバージョンへアップグレードする際は、展開前に既存の Hive テーブルを確認してください。従来の書き込み側が正規化した `INT96` ファイルを含む Catalog では、アップグレード後に返される日時の値が変わる可能性があります。代表的な値を比較し、変換が必要な場合は `hive.parquet.time-zone` を書き込み側のタイムゾーンに設定します。Hudi は既存のセッションタイムゾーンに基づく動作を維持するため、この変更に伴う移行は不要です。
* `hive.parquet.time-zone` を設定する前に代表的なファイルを調べ、既知のタイムスタンプ値と比較してください。不要な設定をすると、補正しようとするオフセットと同種のオフセットが生じます。
* `INT96` の書き込み規則が異なるファイルは別々の Catalog に分けるか、一貫した `INT64` エンコーディングに書き直してください。
* `INT96` を明示的にエクスポートするために `enable_int96_timestamps = true` を指定した場合、Doris はエクスポート時のセッションタイムゾーンでタイムスタンプを正規化します。FileScannerV2 で読み戻すには、`hive.parquet.time-zone` をそのエクスポート時のセッションタイムゾーンに設定します。[エクスポートの概要](../../data-operate/export/export-overview.md)を参照してください。

## クエリ操作

### 基本的なクエリ

Catalog の設定後、次の方法で Catalog 内のテーブルデータをクエリできます。

```sql
-- 1. switch to catalog, use database and query
SWITCH hive_ctl;
USE hive_db;
SELECT * FROM hive_tbl LIMIT 10;

-- 2. use hive database directly
USE hive_ctl.hive_db;
SELECT * FROM hive_tbl LIMIT 10;

-- 3. use full qualified name to query
SELECT * FROM hive_ctl.hive_db.hive_tbl LIMIT 10;
```

### Hive パーティションのクエリ

次の二つの方法で Hive のパーティション情報をクエリできます。

* `SHOW PARTITIONS FROM [catalog.][db.]hive_table`

  このステートメントは、指定した Hive テーブルのすべてのパーティションとその値を一覧表示します。

  ```sql
  SHOW PARTITIONS FROM hive_table;

  +--------------------------------+
  | Partition                      |
  +--------------------------------+
  | pt1=2024-10-10/pt2=beijing     |
  | pt1=2024-10-10/pt2=shanghai    |
  | pt1=2024-10-11/pt2=beijing     |
  | pt1=2024-10-11/pt2=shanghai    |
  | pt1=2024-10-12/pt2=nanjing     |
  +--------------------------------+
  ```

* `table$partitions` メタデータテーブルの使用

  バージョン 2.1.7 および 3.0.3 以降は、`table$partitions` メタデータテーブルを通じて Hive のパーティション情報をクエリできます。このテーブルはリレーショナルテーブルとして扱われ、各パーティション列がそれぞれ列として表されるため、任意の SELECT ステートメントで使用できます。

  ```sql
  SELECT * FROM hive_table$partitions;

  +------------+-------------+
  | pt1        | pt2         |
  +------------+-------------+
  | 2024-10-10 | beijing     |
  | 2024-10-10 | shanghai    |
  | 2024-10-12 | nanjing     |
  | 2024-10-11 | beijing     |
  | 2024-10-11 | shanghai    |
  +------------+-------------+
  ```

:::caution 動作の変更（4.1.4）

バージョン 4.1.4 以降、Hive のディレクトリ形式のパーティショニングで使用されるデフォルトパーティションマーカー `__HIVE_DEFAULT_PARTITION__` は、文字列 `\N` としてエンコードされず、実際の **NULL** 値として解決されます。同時に、パーティションパスに実際に保存されているリテラルの `\N` はデータとして維持されます。

4.1.4 より前は両者を区別できず、どちらもクエリ結果には `\N` と表示されていました。アップグレード後は、`WHERE <partition_col> IS NULL` が Hive のデフォルトパーティションに正しく一致します。

:::

### Hive トランザクションテーブルのクエリ

Hive トランザクションテーブルは ACID セマンティクスをサポートします。詳細は [Hive Transactions](https://cwiki.apache.org/confluence/display/Hive/Hive+Transactions)を参照してください。

* Hive トランザクションテーブルのサポート

  | テーブルの種類 | Hive でサポートされる操作 | Hive テーブルのプロパティ | サポートされる Hive バージョン |
  | ------------------------------- | ----------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------- |
  | Full-ACID トランザクションテーブル | Insert、Update、Delete をサポート | `'transactional'='true'` | 4.x、3.x、2.x（2.x では読み取りに Hive での Major Compaction が必要） |
  | Insert-Only トランザクションテーブル | Insert のみサポート | `'transactional'='true'`, `'transactional_properties'='insert_only'` | 4.x、3.x、2.x（Catalog の作成時に `hive.version` を指定） |

* 現在の制限事項

  Original Files のケースはサポートされません。テーブルをトランザクションテーブルに変換すると、新しいデータファイルには Hive トランザクションテーブルのスキーマが使用されますが、既存のデータファイルは変換されません。これらのファイルを Original Files と呼びます。
  
### Hive ビューのクエリ

Hive ビューをクエリできますが、次の制限があります。

* Hive ビューの定義（HiveQL）は、Doris がサポートする SQL ステートメントと互換性が必要です。互換性がない場合は解析エラーが発生します。

* HiveQL がサポートする関数の中には、Doris の関数と名前が同じでも動作が異なるものがあります。その場合、Hive と Doris のクエリ結果に差が生じることがあります。問題が発生した場合はコミュニティに報告してください。

### 関連パラメータ

* セッション変数

| パラメータ名 | デフォルト値 | 説明 | 導入バージョン |
| ----------| ---- | ---- | --- |
| `hive_parquet_use_column_names` | `true` | Doris が Hive テーブルの Parquet データを読み取るとき、デフォルトでは Hive テーブルの列名と同じ名前の列を Parquet ファイルから探して読み取ります。この変数を `false` に設定すると、列名に関係なく Hive テーブルでの列順に従って Parquet ファイルから読み取ります。Hive の `parquet.column.index.access` 変数と同様です。このパラメータは最上位の列名にのみ適用され、Struct 内部では無効です。 | 2.1.6 以降、3.0.3 以降 |
| `hive_orc_use_column_names` | `true` | `hive_parquet_use_column_names` と同様の動作を、Hive テーブルの ORC データに適用します。Hive の `orc.force.positional.evolution` 変数と同様です。 | 2.1.6 以降、3.0.3 以降 |

## 書き込み操作

INSERT ステートメントを使用して Hive テーブルにデータを書き込めます。Doris が作成した Hive テーブルと、互換性のある形式を持つ既存の Hive テーブルをサポートします。

パーティションテーブルでは、データに基づいて対応するパーティションに自動的に書き込むか、新しいパーティションを作成します。現在、書き込み先のパーティションを指定することはサポートされていません。

### INSERT INTO

INSERT 操作は対象テーブルにデータを追加します。

```sql
INSERT INTO hive_tbl VALUES (val1, val2, val3, val4);
INSERT INTO hive_ctl.hive_db.hive_tbl SELECT col1, col2 FROM internal.db1.tbl1;

INSERT INTO hive_tbl(col1, col2) VALUES (val1, val2);
INSERT INTO hive_tbl(col1, col2, partition_col1, partition_col2) VALUES (1, 2, "beijing", "2023-12-12");
```

バージョン 4.2.0 以降は、静的パーティション（または静的・動的混在モード）への書き込みをサポートします。

```sql
-- Full Static Partition
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
VALUES (val1, val2);
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
SELECT col1, col2 FROM source_table;

-- Hybrid Partition Mode: "partition_col1" is static, "partition_col2" comes from SELECT dynamically
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30')
VALUES (val1, val2, partition_val2);
INSERT INTO hive_tbl PARTITION (partition_col1='2026-07-30')
SELECT col1, col2, partition_col2 FROM source_table;
```

### INSERT OVERWRITE

INSERT OVERWRITE は、テーブル内の既存データを新しいデータに完全に置き換えます。

```sql
INSERT OVERWRITE TABLE hive_tbl VALUES (val1, val2, val3, val4);
INSERT OVERWRITE TABLE hive_ctl.hive_db.hive_tbl(col1, col2) SELECT col1, col2 FROM internal.db1.tbl1;
```

バージョン 4.2.0 以降は、静的パーティション（または静的・動的混在モード）への書き込みをサポートします。

```sql
-- Full Static Partition
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
VALUES (val1, val2);
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30', partition_col2='beijing')
SELECT col1, col2 FROM source_table;

-- Hybrid Partition Mode: "partition_col1" is static, "partition_col2" comes from SELECT dynamically
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30')
VALUES (val1, val2, partition_val2);
INSERT OVERWRITE TABLE hive_tbl PARTITION (partition_col1='2026-07-30')
SELECT col1, col2, partition_col2 FROM source_table;
```

INSERT OVERWRITE のセマンティクスは Hive と同じで、次のように動作します。

* 対象がパーティションテーブルで、ソーステーブルが空の場合、操作は何も行わず、対象テーブルは変更されません。

* 対象が非パーティションテーブルで、ソーステーブルが空の場合、対象テーブルは空になります。

* バージョン 4.2.0 以降は、静的パーティションを指定した書き込みと、静的・動的パーティションを組み合わせたモードをサポートします。ただし、静的パーティションを指定しても、ソースクエリの結果が空の場合は指定したパーティションは消去されません。

### CTAS

`CTAS (CREATE TABLE AS SELECT)` ステートメントを使用して、Hive テーブルの作成とデータの挿入を行えます。

```sql
CREATE TABLE hive_ctas ENGINE=hive AS SELECT * FROM other_table;
```

CTAS は、次のようにファイル形式やパーティショニング方式などの指定をサポートします。

```sql
CREATE TABLE hive_ctas ENGINE=hive
PARTITION BY LIST (pt1, pt2) ()
AS SELECT col1, pt1, pt2 FROM part_ctas_src WHERE col1 > 0;
    
CREATE TABLE hive_ctl.hive_db.hive_ctas (col1, col2, pt1) ENGINE=hive
PARTITION BY LIST (pt1) ()
PROPERTIES (
    "file_format"="parquet",
    "compression"="zstd"
)
AS SELECT col1, pt1 AS col2, pt2 AS pt1 FROM test_ctas.part_ctas_src WHERE col1 > 0;
```

### 関連パラメータ

* BE の設定

  | パラメータ名 | デフォルト値 | 説明 |
  | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------- |
  | `hive_sink_max_file_size` | 1GB | データファイルの最大サイズ。データサイズがこの上限を超えると、現在のファイルを閉じて新しいファイルへの書き込みを開始します。 |
  | `table_sink_partition_write_max_partition_nums_per_writer` | 128 | BE ノード上の各インスタンスが書き込めるパーティションの最大数。 |
  | `table_sink_non_partition_write_scaling_data_processed_threshold` | 25MB | 非パーティションテーブルで書き込みをスケールさせるためのデータ量しきい値。`table_sink_non_partition_write_scaling_data_processed_threshold` に相当するデータ量が追加されるたびに、新しいライター（インスタンス）が使用されます。この仕組みはデータ量に応じてライター数を調整し、並列書き込みのスループットを高めるとともに、データ量が少ない場合のリソース使用量とファイル数を抑えます。 |
  | `table_sink_partition_write_min_data_processed_rebalance_threshold` | 25MB | パーティションテーブルでリバランスを開始する最小データ量しきい値。`current accumulated data volume` - `data volume since last rebalancing or initial accumulation` >= `table_sink_partition_write_min_data_processed_rebalance_threshold` のときにリバランスが開始されます。最終的なファイルサイズに大きなばらつきがある場合は、このしきい値を下げて均衡を改善します。ただし、値を下げるとリバランスのコストが増え、性能に影響する可能性があります。 |
  | `table_sink_partition_write_min_partition_data_processed_rebalance_threshold` | 15MB | リバランスを開始する最小パーティションデータ量しきい値。`current partition data volume` >= `threshold` \* `number of tasks already allocated to the partition` のときにリバランスが行われます。最終的なファイルサイズに大きなばらつきがある場合は、このしきい値を下げて均衡を改善します。ただし、値を下げるとリバランスのコストが増え、性能に影響する可能性があります。 |
  

## データベースとテーブルの管理

Doris を通じて Hive Metastore のデータベースとテーブルを作成および削除できます。これらの操作で Doris が行うのは Hive Metastore API の呼び出しだけであり、Hive メタデータを Doris 自身に保存または永続化することはありません。

### データベースの作成と削除

`SWITCH` ステートメントで対象の Catalog に切り替え、`CREATE DATABASE` ステートメントを実行できます。

```sql
SWITCH hive_ctl;
CREATE DATABASE [IF NOT EXISTS] hive_db;
```

次のように、完全修飾名を使用してデータベースを作成したり、保存場所を指定したりすることもできます。

```sql
CREATE DATABASE [IF NOT EXISTS] hive_ctl.hive_db;

CREATE DATABASE [IF NOT EXISTS] hive_ctl.hive_db
PROPERTIES ('location'='hdfs://172.21.16.47:4007/path/to/db/');
```

`SHOW CREATE DATABASE` コマンドでデータベースの保存場所を確認できます。

```sql
mysql> SHOW CREATE DATABASE hive_db;
+----------+---------------------------------------------------------------------------------------------+
| Database | Create Database                                                                             |
+----------+---------------------------------------------------------------------------------------------+
| hive_db  | CREATE DATABASE hive_db LOCATION 'hdfs://172.21.16.47:4007/usr/hive/warehouse/hive_db.db'   |
+----------+---------------------------------------------------------------------------------------------+
```

データベースを削除するには、次のステートメントを使用します。

```sql
DROP DATABASE [IF EXISTS] hive_ctl.hive_db;
```

:::caution
Hive データベースを削除する前に、そのデータベース内のすべてのテーブルを削除する必要があります。残っているとエラーになります。この操作では、Hive 内の対応するデータベースも削除されます。
:::

### テーブルの作成と削除

- **テーブルの作成**

  Doris では、Hive にパーティションテーブルと非パーティションテーブルの両方を作成できます。

  ```sql
  -- Create unpartitioned hive table
  CREATE TABLE unpartitioned_table (
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3',
    `col4` CHAR(10) COMMENT 'col4',
    `col5` FLOAT COMMENT 'col5',
    `col6` DOUBLE COMMENT 'col6',
    `col7` DECIMAL(9,4) COMMENT 'col7',
    `col8` VARCHAR(11) COMMENT 'col8',
    `col9` STRING COMMENT 'col9'
  )  ENGINE=hive
  PROPERTIES (
    'file_format'='parquet'
  );
  
  -- Create partitioned hive table
  -- The partition columns must be in table's column definition list
  CREATE TABLE partition_table (
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3',
    `col4` DECIMAL(2,1) COMMENT 'col4',
    `pt1` VARCHAR COMMENT 'pt1',
    `pt2` VARCHAR COMMENT 'pt2'
  )  ENGINE=hive
  PARTITION BY LIST (pt1, pt2) ()
  PROPERTIES (
    'file_format'='orc',
    'compression'='zlib'
  );
  
  -- Create text format table(Since 2.1.7 & 3.0.3)
  CREATE TABLE text_table (
      `id` INT,
      `name` STRING
  ) PROPERTIES (
      'file_format'='text',
      'compression'='gzip',
      'field.delim'='\t',
      'line.delim'='\n',
      'collection.delim'=';',
      'mapkey.delim'=':',
      'serialization.null.format'='\\N',
      'escape.delim'='\\'
  );
  ```
  
  テーブルの作成後、`SHOW CREATE TABLE` コマンドで Hive テーブルの作成ステートメントを確認できます。

  Hive のテーブル作成構文とは異なり、Doris でパーティションテーブルを作成するときは、パーティション列をテーブルスキーマに含める必要があります。また、パーティション列はスキーマの末尾に、パーティション定義と同じ順序で配置する必要があります。

  :::tip
  デフォルトで ACID トランザクション機能が有効な Hive クラスターでは、Doris が作成したテーブルの `transactional` プロパティが `true` に設定されます。Doris がサポートする Hive トランザクションテーブルの機能は一部に限られるため、Doris が自分で作成した Hive テーブルを読み取れない場合があります。これを避けるには、テーブルプロパティに `"transactional" = "false"` を明示的に指定して、非トランザクションの Hive テーブルを作成してください。

  ```sql
  CREATE TABLE non_acid_table(
    `col1` BOOLEAN COMMENT 'col1',
    `col2` INT COMMENT 'col2',
    `col3` BIGINT COMMENT 'col3'
  ) ENGINE=hive
  PROPERTIES (
    'transactional'='false'
  );
  ```
  :::

- **テーブルの削除**

  `DROP TABLE` ステートメントを使用して Hive テーブルを削除できます。テーブルを削除すると、パーティションデータを含むすべてのデータも削除されます。

- **列の型マッピング**

  詳細は「列の型マッピング」を参照してください。次の制限事項に注意してください。

  - 列はデフォルトの NULL 許容型である必要があります。`NOT NULL` はサポートされません。
  - Hive 3.0 はデフォルト値の設定をサポートします。デフォルト値を設定するには、Catalog プロパティに `"hive.version" = "3.0.0"` を明示的に追加してください。
  - 挿入するデータ型に互換性がない場合（数値型への `'abc'` の挿入など）、値は `null` に変換されます。

- **パーティショニング**

  Hive のパーティションの種類は、Doris の List パーティションに対応します。そのため、Doris で Hive のパーティションテーブルを作成するときは List パーティション構文を使用しますが、各パーティションを明示的に列挙する必要はありません。Doris はデータ挿入時にデータ値に応じて Hive パーティションを自動的に作成します。単一列と複数列のパーティションテーブルをサポートします。

- **ファイル形式**

  - ORC（デフォルト）
  - Parquet

    DATETIME 型を Parquet ファイルに書き込むときは、物理型として INT64 ではなく INT96 が使用されます。これは Hive 4.0 より前のバージョンの動作との互換性を保つためです。

  - Text（バージョン 2.1.7 および 3.0.3 以降でサポート）

      Text 形式は次のテーブルプロパティをサポートします。

		  - `field.delim`: 列の区切り文字。デフォルトは `\1`。
		  - `line.delim`: 行の区切り文字。デフォルトは `\n`。
		  - `collection.delim`: 複合型の要素の区切り文字。デフォルトは `\2`。
		  - `mapkey.delim`: マップのキーと値の区切り文字。デフォルトは `\3`。
		  - `serialization.null.format`: `NULL` 値の保存形式。デフォルトは `\N`。
		  - `escape.delim`: エスケープ文字。デフォルトは `\`。

- **圧縮形式**

  - Parquet: snappy（デフォルト）、zstd、plain（圧縮なし）
  - ORC: snappy、zlib（デフォルト）、zstd、plain（圧縮なし）
  - Text: gzip、deflate、bzip2、zstd、lz4、lzo、snappy、plain（デフォルト、圧縮なし）

- **ストレージ媒体**

  - HDFS
  - オブジェクトストレージ

## Hive Metastore イベントの購読

FE ノードが HMS の Notification Event を定期的に読み取ることで、Doris は Hive テーブルのメタデータの変更をリアルタイムに検出し、メタデータの鮮度を高められます。現在、次のイベントをサポートします。

| イベント | 対応する動作 |
| ---------------- | ------------------------------------------------------------------------- |
| CREATE DATABASE | 対応するデータディレクトリにデータベースを作成します。 |
| DROP DATABASE | 対応するデータディレクトリからデータベースを削除します。 |
| ALTER DATABASE | 主にデータベースのプロパティ、コメント、デフォルトの保存場所の変更に関係します。これらは Doris が外部データディレクトリをクエリする機能に影響しないため、現在このイベントは無視されます。 |
| CREATE TABLE | 対応するデータベースにテーブルを作成します。 |
| DROP TABLE | 対応するデータベースからテーブルを削除し、テーブルキャッシュを無効化します。 |
| ALTER TABLE | 名前が変更された場合は古いテーブルを削除して新しい名前のテーブルを作成し、それ以外の場合はテーブルキャッシュを無効化します。 |
| ADD PARTITION | 対応するテーブルのキャッシュ済みパーティション一覧にパーティションを追加します。 |
| DROP PARTITION | キャッシュ済みパーティション一覧からパーティションを削除し、パーティションキャッシュを無効化します。 |
| ALTER PARTITION | 名前が変更された場合は古いパーティションを削除して新しい名前のパーティションを作成し、それ以外の場合はパーティションキャッシュを無効化します。 |

:::tip
1. データのインポートによってファイルが変更されると、パーティションテーブルでは `ALTER PARTITION` イベントが、非パーティションテーブルでは `ALTER TABLE` イベントが発生します。

2. HMS を経由せずファイルシステムを直接操作した場合、HMS は対応するイベントを生成せず、Doris はメタデータの変更を検出しません。
:::

この機能には、`fe.conf` の次のパラメータが関係します。

1. `enable_hms_events_incremental_sync`: メタデータの自動増分同期を有効にします。デフォルトでは無効です。

2. `hms_events_polling_interval_ms`: イベントを読み取る間隔。デフォルトは 10000 ミリ秒です。

3. `hms_events_batch_size_per_rpc`: RPC ごとに読み取るイベントの最大数。デフォルトは 500 です。

この機能を使用するには（Huawei Cloud MRS を除く）、HMS の `hive-site.xml` を変更し、HMS と HiveServer2 の両方を再起動する必要があります。

```xml
<property>
    <name>hive.metastore.event.db.notification.api.auth</name>
    <value>false</value>
</property>
<property>
    <name>hive.metastore.dml.events</name>
    <value>true</value>
</property>
<property>
    <name>hive.metastore.transactional.event.listeners</name>
    <value>org.apache.hive.hcatalog.listener.DbNotificationListener</value>
</property>
```

Huawei Cloud MRS の場合は `hivemetastore-site.xml` を変更し、HMS と HiveServer2 の両方を再起動する必要があります。

```xml
<property>
    <name>metastore.transactional.event.listeners</name>
    <value>org.apache.hive.hcatalog.listener.DbNotificationListener</value>
</property>
```

## 付録

### トランザクションの仕組み

Hive への書き込み操作は別個のトランザクションに置かれます。コミット前のデータは外部から見えません。コミット後に初めて、関連するテーブル操作がほかのユーザーから見えるようになります。

トランザクションは操作の原子性を保証します。つまり、トランザクション内のすべての操作が一緒に成功するか、一緒に失敗します。

トランザクションは操作の分離性を完全には保証できませんが、ファイルシステム操作と Hive Metastore のメタデータ操作を分離することで、不整合をできるだけ抑えます。

たとえば、Hive テーブルの複数のパーティションを変更するトランザクションで、タスクが二つのバッチに分かれている場合、後半のバッチが完了する前に前半のバッチが外部から見えることがあります。この場合、前半のバッチのパーティションは読み取れますが、後半のバッチはまだ読み取れません。

トランザクションのコミット中に例外が発生すると、HDFS ファイルと Hive Metastore メタデータの変更を含め、トランザクション全体がロールバックされます。ユーザーによる追加の操作は不要です。

### 同時書き込みの仕組み

現在、Apache Doris は複数の INSERT ステートメントによる同時書き込みをサポートします。ただし、同時書き込みで競合が発生しないよう、ユーザーが確認する必要があります。

通常の非トランザクション Hive テーブルには完全なトランザクション機構がないため、Apache Doris のトランザクション機構は不整合が生じる時間を最小限に抑えることを目指しますが、真の ACID 特性は保証できません。そのため、Apache Doris から Hive テーブルへの同時書き込みはデータの整合性の問題につながる可能性があります。

1. **同時 `INSERT` 操作**

2. `INSERT` 操作はデータを追加します。同時に実行しても競合せず、期待どおりの結果になります。

3. **同時 `INSERT OVERWRITE` 操作**

4. 同じテーブルまたはパーティションに対する同時 `INSERT OVERWRITE` 操作は、データの欠落や破損を引き起こし、結果が予測できなくなる可能性があります。

5. 一般的な対処方法は次のとおりです。

   * パーティションテーブルでは、異なるパーティションにデータを書き込みます。異なるパーティションへの同時操作は競合しません。

   * 非パーティションテーブルでは、競合を避けるために `INSERT` を使用し、`INSERT OVERWRITE` は避けてください。

   * 競合する可能性がある操作では、アプリケーション側で一度に単一の書き込み操作だけが行われるようにします。

### HDFS ファイル操作

HDFS 上の Hive テーブルデータは、通常、まず一時ディレクトリに書き込まれ、`rename` などのファイルシステム操作で確定されます。以下では、データ操作ごとの HDFS ファイル操作を詳しく説明します。

データの一時ディレクトリの形式: `/tmp/.doris_staging/<username>/<uuid>`

書き込まれるデータファイル名の形式: `<query-id>_<uuid>-<index>.<compress-type>.<file-type>`

各シナリオでのファイル操作の例を次に示します。

1. **非パーティションテーブル**

   * **追加（データの追加）**

     * 対象テーブルディレクトリ: `hdfs://ns/usr/hive/warehouse/example.db/table1`

     * 一時ファイル: `hdfs://ns/tmp/.doris_staging/root/f02247cb662846038baae272af5eeb05/b35fdbcea3a4e39-86d1f36987ef1492_7e3985bf-9de9-4fc7-b84e-adf11aa08756-0.orc`

     * コミット時に、すべての一時ファイルが対象テーブルディレクトリへ移動します。

   * **上書き（データの置き換え）**

     * 対象テーブルディレクトリ: `hdfs://ns/usr/hive/warehouse/example.db/table1`

     * 一時ファイル: `hdfs://ns/tmp/.doris_staging/root/f02247cb662846038baae272af5eeb05/b35fdbcea3a4e39-86d1f36987ef1492_7e3985bf-9de9-4fc7-b84e-adf11aa08756-0.orc`

     * コミット時の手順:

       1. 対象テーブルディレクトリを一時ディレクトリに改名します: `hdfs://ns/usr/hive/warehouse/example.db/_temp_b35fdbcea3a4e39-86d1f36987ef1492_table1`

       2. 一時ディレクトリを対象テーブルディレクトリに改名します。

       3. 一時的に退避した対象テーブルディレクトリを削除します。

2. **パーティションテーブル**

   * **追加（新しいパーティションへのデータの追加）**

     * 対象テーブルディレクトリ: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * 一時ファイル: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * コミット時に、一時ディレクトリが対象テーブルディレクトリに改名されます。

   * **追加（既存パーティションへのデータの追加）**

     * 対象テーブルディレクトリ: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * 一時ファイル: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * コミット時に、一時ディレクトリ内のファイルが対象テーブルディレクトリへ移動します。

   * **上書き（既存パーティションの置き換え）**

     * 対象テーブルディレクトリ: `hdfs://ns/usr/hive/warehouse/example.db/table2/part_col=2024-01-01`

     * 一時ファイル: `hdfs://ns/tmp/.doris_staging/root/a7eac7505d7a42fdb06cb9ef1ea3e912/par1=a/d678a74d232345e0-b659e2fb58e86ffd_549ad677-ee75-4fa1-b8a6-3e821e1dae61-0.orc`

     * コミット時の手順:

       1. 対象パーティションディレクトリを一時パーティションディレクトリに改名します: `hdfs://ns/usr/hive/warehouse/example.db/table2/_temp_d678a74d232345e0-b659e2fb58e86ffd_part_col=2024-01-01`

       2. 一時パーティションディレクトリを対象パーティションディレクトリに改名します。

       3. 一時的に退避した対象パーティションディレクトリを削除します。
