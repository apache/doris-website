# S3

このドキュメントでは、AWS S3 にアクセスするために必要なパラメータについて説明します。これらのパラメータは次の機能に適用されます。

- Catalog のプロパティ。
- テーブル値関数のプロパティ。
- Broker Load のプロパティ。
- Export のプロパティ。
- Outfile のプロパティ。

## HTTPS 用の BE CA 証明書の設定

Doris 2.1 以降では、Doris BE が HTTPS 経由で S3 にアクセスする際、`ca_cert_file_paths` を `be.conf` で明示的に設定できます。

`ca_cert_file_paths` を設定しない場合、Doris はデフォルトでオペレーティングシステムの CA 証明書を使用します。ほとんどの環境では、このパラメータを手動で設定する必要はありません。次の場合は設定してください。

- BE ノードにシステムの CA 証明書がない、またはインストールされている CA バンドルが古すぎる。
- BE ノードが、`ca-certificates` パッケージを含まない最小構成のコンテナーまたはイメージで実行されている。
- BE ノードのデフォルトの CA ファイルパスが無効、または Doris プロセスに CA ファイルの読み取り権限がない。
- 自己署名証明書、プライベート CA、または TLS トラフィックに再署名する企業のプロキシやゲートウェイを使用している。
- S3 へのアクセス時に `Problem with the SSL CA cert` や `curl 77: Problem with the SSL CA cert (path? access rights?)` などのエラーが発生する。

> **`ca_cert_file_paths` を使用できないバージョンの場合：** `ca_cert_file_paths` パラメータは Doris 2.1 以降で使用できます。Doris 2.0.x 以前を使用していて SSL CA 証明書のエラーが発生する場合は、システムの CA 証明書が正しくインストールされ、CA バンドルが `/etc/ssl/certs/ca-certificates.crt` に存在することを確認する必要があります。
>
> - **RHEL / CentOS / RockyLinux：**
>   ```bash
>   yum install -y ca-certificates
>   update-ca-trust
>   ln -s /etc/pki/ca-trust/extracted/openssl/ca-bundle.trust.crt /etc/ssl/certs/ca-certificates.crt
>   ```
> - **Debian / Ubuntu：** `apt-get install -y ca-certificates`
>
> その後、すべての BE ノードを再起動してください。証明書の問題について詳しくは、[Lakehouse FAQ - 証明書の問題](../../faq/lakehouse-faq.md#certificate-issues)を参照してください。

例：

```properties
# be.conf
ca_cert_file_paths = /etc/ssl/certs/ca-certificates.crt
```

一般的な CA バンドルのパス：

- Debian / Ubuntu：`/etc/ssl/certs/ca-certificates.crt`
- CentOS / RockyLinux：`/etc/pki/ca-trust/extracted/openssl/ca-bundle.trust.crt`

S3 にアクセスする可能性のあるすべての BE ノードでこの項目を設定し、証明書ファイルが存在し、Doris プロセスから読み取れることを確認してください。`be.conf` を更新した後、変更を適用するために対象の BE ノードを再起動してください。

## パラメータの概要

| プロパティ名                 | 旧名称                        | 説明                                                                        | デフォルト値 | 必須 |
|------------------------------|-------------------------------|-----------------------------------------------------------------------------|---------|----------|
| s3.endpoint                  |                               | S3 サービスのアクセスエンドポイント（例：`s3.us-east-1.amazonaws.com`）     | なし    | いいえ   |
| s3.access_key                |                               | 認証に使用する AWS Access Key                                                | なし    | いいえ   |
| s3.secret_key                |                               | 認証に使用する AWS Secret Key                                                | なし    | いいえ   |
| s3.region                    |                               | S3 リージョン（例：`us-east-1`）。設定を強く推奨                             | なし    | はい     |
| s3.use_path_style            |                               | パス形式のアクセスを使用するかどうか                                          | FALSE   | いいえ   |
| s3.connection.maximum        |                               | 高い同時実行数で使用する接続の最大数                                          | 50      | いいえ   |
| s3.connection.request.timeout|                               | リクエストのタイムアウト（ミリ秒）。接続取得のタイムアウトを制御              | 3000    | いいえ   |
| s3.connection.timeout        |                               | 接続確立のタイムアウト（ミリ秒）                                              | 1000    | いいえ   |
| s3.role_arn                  |                               | Assume Role モードで指定するロール ARN                                        | なし    | いいえ   |
| s3.external_id               |                               | `s3.role_arn` とともに使用する外部 ID                                        | なし    | いいえ   |
| s3.credentials_provider_type |                               | AWS 認証用の認証情報プロバイダーの種類（AK/SK を使用しない場合に使用。IAM Role モードでは STS のソース認証情報として使用） | DEFAULT | いいえ |

> バージョンに関する注記：`s3.credentials_provider_type` は **3.1.4** および **4.0.3** 以降でサポートされています。

## 認証の設定

Doris は、次の三つの方法による S3 へのアクセスをサポートしています。

### 1. Access Key と Secret Key（AK/SK）を直接指定

```properties
"s3.access_key"="your-access-key",
"s3.secret_key"="your-secret-key",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

### 2. IAM Role（Assume Role）モード

アカウント間のアクセスや、一時的な認可によるアクセスに適しています。Doris はロールによる認可を通じて一時的な認証情報を自動的に取得します。

```properties
"s3.role_arn"="arn:aws:iam::123456789012:role/demo-role",
"s3.external_id"="external-identifier",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

#### IAM Role モードでの `s3.credentials_provider_type` の設定

`s3.role_arn` を設定すると、`s3.credentials_provider_type` によって、STS の `AssumeRole` に使用するソース認証情報のプロバイダーが決まります。

1. `s3.credentials_provider_type` からソース認証情報を取得します。
2. ソース認証情報を使用して STS の `AssumeRole` を呼び出します。
3. 返された一時的な認証情報を使用して S3 にアクセスします。

#### IAM Role と `s3.credentials_provider_type` の組み合わせ例

**例 1：STS のソース認証情報に EC2 Instance Profile を使用**

```properties
"s3.role_arn"="arn:aws:iam::123456789012:role/demo-role",
"s3.external_id"="external-identifier",
"s3.credentials_provider_type"="INSTANCE_PROFILE",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

**例 2：STS のソース認証情報に Web Identity（IRSA など）を使用**

```properties
"s3.role_arn"="arn:aws:iam::123456789012:role/demo-role",
"s3.credentials_provider_type"="WEB_IDENTITY",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

**例 3：STS のソース認証情報にコンテナーのメタデータを使用**

```properties
"s3.role_arn"="arn:aws:iam::123456789012:role/demo-role",
"s3.credentials_provider_type"="CONTAINER",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

**例 4：STS のソース認証情報にデフォルトのプロバイダーチェーンを使用**

```properties
"s3.role_arn"="arn:aws:iam::123456789012:role/demo-role",
"s3.credentials_provider_type"="DEFAULT",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

### 3. `s3.credentials_provider_type` で認証情報の取得元を指定

EC2 Instance Profile、コンテナーのメタデータ、Web Identity など、AK/SK を明示的に指定しない場合に適しています。

```properties
"s3.credentials_provider_type"="INSTANCE_PROFILE",
"s3.endpoint"="https://s3.us-east-1.amazonaws.com",
"s3.region"="us-east-1"
```

### `s3.credentials_provider_type` でサポートされる値

| 値                | 説明 |
|-------------------|-------------|
| DEFAULT           | デフォルトのプロバイダーチェーンを使用 |
| ENV               | 環境変数から認証情報を読み取る |
| SYSTEM_PROPERTIES | システムプロパティから認証情報を読み取る |
| WEB_IDENTITY      | Web Identity Token の認証情報を使用 |
| CONTAINER         | コンテナーのメタデータから認証情報を取得 |
| INSTANCE_PROFILE  | EC2 Instance Profile の認証情報を使用 |
| ANONYMOUS         | 匿名アクセス（公開バケット用） |

### 複数の設定を併用した場合の適用ルール

1. `s3.access_key` と `s3.secret_key` の両方を設定した場合、AK/SK が優先して使用されます。
2. AK/SK が設定されておらず、`s3.role_arn` が設定されている場合、IAM Role が使用されます。この場合、`s3.credentials_provider_type` は STS のソース認証情報の選択に使用されます。
3. AK/SK も `s3.role_arn` も設定されていない場合、`s3.credentials_provider_type` によって S3 クライアントが使用する認証情報プロバイダーが直接決まります。

> 注：`s3.access_key` と `s3.secret_key` は必ず一緒に設定してください。

AWS の認証と認可の設定手順については、[AWS の認証と認可](../../admin-manual/auth/integrations/aws-authentication-and-authorization.md)を参照してください。

## S3 Directory Bucket へのアクセス

> この機能はバージョン 3.1.0 以降でサポートされています。

Amazon S3 Express One Zone（Directory Bucket とも呼ばれます）は高いパフォーマンスを提供しますが、エンドポイントの形式が異なります。

* 通常のバケット：s3.us-east-1.amazonaws.com
* Directory Bucket：s3express-usw2-az1.us-west-2.amazonaws.com

利用可能なその他のリージョンについては、[AWS 公式ドキュメント](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-express-Regions-and-Zones.html)を参照してください。

例：

```properties
"s3.access_key"="ak",
"s3.secret_key"="sk",
"s3.endpoint"="https://s3express-usw2-az1.us-west-2.amazonaws.com",
"s3.region"="us-west-2"
```

## 権限ポリシー

用途に応じて、権限ポリシーは**読み取り専用**と**読み書き可能**に分類できます。

### 1. 読み取り専用の権限

S3 からのオブジェクトの読み取りのみを許可します。LOAD、TVF、EXTERNAL CATALOG のクエリなどに適しています。

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
              "s3:GetObject",
              "s3:GetObjectVersion",
            ],
            "Resource": "arn:aws:s3:::<your-bucket>/your-prefix/*"
        },
        {
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket",
                "s3:GetBucketLocation"
            ],
            "Resource": "arn:aws:s3:::<your-bucket>"
        }    
    ]
}
```

### 2. 読み書き可能な権限

読み取り専用の権限に加え、オブジェクトの削除、作成、変更も許可します。EXPORT、OUTFILE、EXTERNAL CATALOG の書き戻しに適しています。

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
              "s3:PutObject",
              "s3:GetObject",
              "s3:GetObjectVersion",
              "s3:DeleteObject",
              "s3:DeleteObjectVersion",
              "s3:AbortMultipartUpload",      
              "s3:ListMultipartUploadParts"
            ],
            "Resource": "arn:aws:s3:::<your-bucket>/<your-prefix>/*"
        },
        {
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket",
                "s3:GetBucketLocation",
                "s3:GetBucketVersioning",
                "s3:GetLifecycleConfiguration"
            ],
            "Resource": "arn:aws:s3:::<your-bucket>"
        }    
    ]
}
```

### 注意事項

1. プレースホルダーの置き換え

    - `<bucket>` → S3 バケット名。
    - `<account-id>` → AWS アカウント ID（12 桁の数字）。

2. 最小権限の原則

    - クエリのみを実行する場合は、書き込み権限を付与しないでください。
