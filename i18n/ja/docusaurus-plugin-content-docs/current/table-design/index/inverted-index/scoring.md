全文検索クエリ（`MATCH_ANY`、`MATCH_ALL`、`MATCH_PHRASE` など）を実行するときは、関連度の高いレコードから返すために、結果を「一致度」で並べ替えたい場合があります。Doris の**関連度スコアリング**では、クエリ条件に基づいて各行に数値スコアを付けます。スコアが高いほど関連度が高いことを示します。

Doris は現在、関連度スコアリングのデフォルトの実装として **BM25（Best Matching 25）** アルゴリズムを使用します。

**代表的な用途：**

- 検索エンジンアプリケーション：キーワードに基づき、関連度の高いドキュメントから返す
- ログ分析：関連度で並べ替え、キーワードに最もよく一致するログをすばやく特定する
- コンテンツ推薦：テキストの類似度に基づいて優先度の高いコンテンツを絞り込む
- ナレッジベース検索：質問との関連度で順位付けした回答候補を返す

## クイックスタート

次の例は、クエリで関連度スコアリングを有効にし、スコア順に並べ替える方法を示します。

```sql
SELECT *,
       score() AS relevance
FROM search_demo
WHERE content MATCH_ANY 'text search test'
ORDER BY relevance DESC
LIMIT 10;
```

実行すると、Doris は BM25 アルゴリズムで各行のスコアを計算し、関連度の高いレコードを上位 10 件まで返します。

```text
+------+-----------------------------------+---------+--------------+-----------+
| id   | content                           | author  | publish_date | relevance |
+------+-----------------------------------+---------+--------------+-----------+
|    1 | Full text search engine test demo | Alice   | 2024-01-01   |  2.915228 |
|    7 | Text processing techniques        | Grace   | 2024-01-07   |  1.341931 |
|    5 | Performance test framework        | Eve     | 2024-01-05   |  1.341931 |
|    3 | Advanced search algorithms        | Charlie | 2024-01-03   |  1.341931 |
+------+-----------------------------------+---------+--------------+-----------+
```

## スコア計算が有効になる条件

スコア計算を有効にするには、クエリが次の三つの条件をすべて満たす必要があります。

1. `SELECT` 句で `score()` 関数を明示的に呼び出す。
2. `WHERE` 句に少なくとも一つの `MATCH_*` 条件を含める。
3. クエリが Top-N クエリであり、`ORDER BY` が `score()` の結果に基づいている。

### サポート対象のインデックスの種類

| インデックスの種類 | スコアリングのサポート | 説明 |
| ------------------ | ---------------------- | ---- |
| トークン化された転置インデックス | あり | BM25 の関連度スコアを計算できる |
| トークン化されていない転置インデックス | なし | 完全一致のみをサポートし、スコアは計算しない |

### サポート対象のクエリの種類

- `MATCH_ANY`
- `MATCH_ALL`
- `MATCH_PHRASE`
- `MATCH_PHRASE_PREFIX`
- `SEARCH`

## BM25 アルゴリズム

BM25 は確率モデルに基づくテキスト関連度アルゴリズムです。**語の出現頻度（TF）**、**逆文書頻度（IDF）**、**レコードの長さ**という三つの要素を考慮して、一致した結果に重み付けをします。従来の TF-IDF モデルに比べて、BM25 は頑健性と調整のしやすさに優れ、長いテキストと短いテキストのスコアの差を効果的に調整します。

### 基本式

```text
score = IDF × (tf × (k1 + 1)) / (tf + k1 × (1 - b + b × |d| / avgdl))
```

式の変数は次のとおりです。

| 変数 | 意味 |
| ---- | ---- |
| `tf` | 現在の行にクエリ語が出現する回数 |
| `IDF` | その語の希少性を示す逆文書頻度 |
| `\|d\|` | 現在の行の長さ（トークン化後のトークン数） |
| `avgdl` | テーブル内の全行の平均長 |
| `k1`, `b` | アルゴリズムの調整パラメーター |

### パラメーター

| パラメーター | デフォルト値 | 説明 |
| ------------ | ------------ | ---- |
| `k1` | 1.2 | 語の出現頻度がスコアに与える影響の大きさを制御する |
| `b` | 0.75 | レコード長の正規化の強さを制御する |
| `boost` | 1.0 | クエリ単位の重み係数 |

### 補助的な統計量

```text
IDF   = log(1 + (N - n + 0.5) / (n + 0.5))
avgdl = total_terms / total_rows
```

各変数の意味は次のとおりです。

- `N`：テーブル内の総行数
- `n`：クエリ語を含む行数

クエリに複数の語が含まれる場合、**最終スコアは各語のスコアの合計**です。

## 結果の解釈

スコアの意味を理解すると、関連度による順位付けをより適切に利用できます。

| 特性 | 説明 |
| ---- | ---- |
| スコアの範囲 | 固定の上限がない正の数値。通常は絶対値よりも相対的な大小関係が重要 |
| 複数語のクエリ | 複数の語が含まれる場合、合計スコアは各語のスコアの合計になる |
| 長さの影響 | 一致する語が同じであれば、短いレコードのスコアがやや高くなる |
| 一致する語がない場合 | クエリ語がテーブルに存在しなければ、対応するスコアは 0 になる |

## よくある質問

**Q1：クエリでスコアが返されないのはなぜですか？**

次の項目を順に確認してください。

1. `score()` 関数を `SELECT` で呼び出しているか。
2. `WHERE` 句に `MATCH_*` 条件が含まれているか。
3. `ORDER BY` が `score()` に基づいているか。
4. インデックスがトークン化された転置インデックスか。

**Q2：BM25 と TF-IDF の違いは何ですか？**

BM25 は TF-IDF を基礎として、**語の出現頻度の飽和**と**長さの正規化**という二つの改良を加えています。これにより、長いテキストと短いテキストのスコアのバランスが改善し、頑健性も向上します。

**Q3：異なるクエリのスコアを比較できますか？**

推奨しません。BM25 のスコアは、クエリに含まれる語とテーブル内のデータ分布に依存します。異なるクエリ間で絶対値を比較することはできません。**相対的な大小関係は、同じクエリの結果セット内だけで比較してください。**
